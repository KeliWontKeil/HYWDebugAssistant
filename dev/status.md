## 2. 当前步骤：M1-16 UI 专项

按用户方案要点打磨：视觉体系 · 模块窗口 · 端口标记 · 弹窗信息层级 · 状态反馈 · 克制动效。

**判定依据 = `docs/zh/concepts/shell.md`** —— 现行模块表面暴露的「控件错位 / 大段空白 / 意义不明」按归因处理（属 L1 缺定义、L2 声明错、还是 L3 外观值不对），**不逐条打补丁**。

**外部接入已完成所有权纠正** —— 框架托管、模块只声明标准标识的外部标准接入（串口 / TCP 客户端 / TCP 服务端 / UDP）。已落地：中性契约（声明 / 标准目录 / 模块存取面 / 状态与计量快照）、实例循环（一个“有活干”信号 + 口队列 / 会话 / 收件箱）、`src/Access`（四适配件 + 参数类型 + 内置 catalog，框架侧，只有组合根引用）、`Sdk.AccessKit`（模块共用骨架，宿主随附）、四模块接线与状态/计数发布；八模块包只含模块自有文件，宿主提供契约/UI/外部接入依赖。框架级、适配器级、模块级自动化用例已加入。**仍待**：真机 / 回环人工验收（acceptance.md 80j–80r）；本轮改动后需关闭应用重跑完整 T3（见 §6）。

**本轮（缓冲满 / 跟不上 / 丢弃机制）**：① 丢弃收口为**一个词表、三条轴**（队列轴 / 流轴 / 会话轴，同一事件两侧归属、任何合计不跨轴相加），会话快照按来源分项；② 投递循环改为**时间片回泵**（命令 / 输入 / 接收回调 / 状态发布不再被持续积压饿死）；③ 停止与暂停**先清尾再等待**（移除不再等整条积压，孤儿只可能来自"清尾之后"挤进来的单元）；④ 新增**最大滞留**过期丢弃与**外部写超时**（四个适配件统一有界）；⑤ 机制参数收进设置 `flow` 块（schema v6，旧三根键折叠并删除），设置页新增「数据面（缓冲与流控）」分组，容量/策略/写超时"对新建生效"、其余立即生效；⑥ 四个外部模块在跟不上时用**本模块文案**说一句，`drop` 读数只取会话轴有效字节；⑦ 拓扑诊断与口标记悬停显示队列压力与按原因丢弃。自动化：`SerialDeliveryResponsivenessTests` / `DataPlaneQueueLedgerTests` / `PortFlowQueryTests` / `ExternalAccessPressureStatusTests` / 拓扑与悬停用例。人眼复核见 acceptance.md A56–A64。

**本轮（串口断连、未打开发送与清空计数）**：① 串口打开期间由会话按 250 ms 探活（`IExternalAccessLiveness`），设备消失 ⇒ `DeviceLost`；故障后由实例线程释放一次句柄（故障态与原因保留），事件/泵线程不关句柄。② 未打开发送被拒计入 `RejectedUnits`，模块状态句显式提示「… · 发送已丢弃（N 次）」，不弹窗。③ 四个外部模块新增清空计数命令与 24×24 图标按钮（`ModuleButton.icon` + 12px 描边箭头）；打开/关闭端口不清零，只有清空按钮（或实例重建）清零，且不清队列数据/连接数/故障态。人眼复核见 acceptance.md A41–A45；已知边界见 G67。

**本轮（输入控件观感与退出）**：① 输入控件的绘制收成一份 `Ui/Styles/InputChrome.axaml`（宿主 / 预览 / 模块共用）：常态 1px、聚焦/报错是 2px **叠加圈**，聚焦不改边框厚度；Fluent 的聚焦黑线与下拉选中强调色不再出现；chrome 同时清掉 Fluent 的 `MinWidth=64` 与文本面内层的 `MinHeight` 外来下限，48 宽的间隔框不再裁掉末位。② 运行期只读**不换控件**：`ModuleConfigField` 与 `ModuleTextSurface` 在 `Appearance.ReadOnly` 下保持同一个输入框、同一条边框，只停止编辑；只有声明只读/显示模式才换文本叶子。③ 删除 `SurfaceTextFrameEditableBrush`（可写/只读两种边框的方案作废）。④ 退出：主窗 `ClosingBehavior=OwnerWindowOnly`（先决定、取消时子窗不动）、模块窗视图在 `Closed` 摘、`ShellExitCoordinator` 单一出口（询问/保存/记住/关模块窗/放行外壳）。人眼复核见 acceptance.md A36–A40。

**本轮（关窗时序与外部接入文本归属）**：① 关闭询问被取消后不再拆应用 —— 收尾从可取消的 `ShutdownRequested` 移到 `Exit`，用一次性闸门；关窗不再预摘视图，管理器记住窗口 `Closed`，视图可在挂回时自愈。② 外部接入只给**事实**（端点 + 结构化失败：种类 / 原始值 / 底层细节），四个模块用**自己的表**生成连接/状态/失败句子；`Access` 表只剩 `access.diag.*`；参数表单的标题/说明/分组/选项改由**声明该接入的模块**表解析（参数类型仍在框架侧）。人眼复核：关闭→取消后模块仍可用；四模块故障态显示模块文案；Issue 里是框架底层原因；参数表单标题照常（见 acceptance.md A31–A35）。

**本轮（机制收敛，已落地，待人眼复核）**：控件不再自带标题 —— `ModuleConfigField` 只做编辑器，标题是独立的 `ModuleLabel`（`Field` 取同一份配置元数据），字段标签与编辑器各占一条矩形；读数不再有标题与单位槽（单位是普通标签或值文本的一部分）；标签排印收敛成一套（`caption` / `hint` / 默认）。预览里空/透明的标签有虚线占位框，设计时上下文给样例值；预置了一份内容区几何（`ModuleSurfaceMetrics`），快照/契约用例改用真机内容区尺寸。**上一轮的 `LabelPlacement=Stacked` 方案随之撤销**（它只是把"标题在控件里"的毛病换个位置）。人眼复核：TCP 客户端「超时」、四个模块的读数、两个发送器的间隔与「已发送」、预览器里的占位框。**本轮追加**（早前已落地、仍待人眼复核）：四模块状态→按钮/字段启用绑定、状态行统一到底部、本机回环默认地址/端口、同一实例自连接拒绝；模块活动与连续发送统一到全局计时服务。

**本轮（按钮面 / 显式 SVG / 模块自有资源包）**：① 按钮面：`ButtonChrome` 的 `.icon` 与普通按钮共用面/边/hover/pressed/focus/disabled；按钮簇去掉外框、5 钮各自有面；活动栏保留导航式 + pressed；锚点 hover 统一。② 图标显式化：每个图标 `.svg` + `icons.json` 清单；框架 17 个换回 **Fluent UI MDL2**（2048 画布、旧观感），模块 4 个 `refresh.svg` 保持 **Fluent UI System Icons**（20px、与小按钮适配），两套均 MIT；`IconCatalog` 只产数据（路径/viewBox），`Sdk.Ui.Icon` 合成几何；删除 `FontIcons`；`IconButton`/`Glyph`/`ModuleButton.Icon` 全部改用 `Icon`。③ 资源包分离：8 个模块的 `i18n/`/`icons/` 搬进模块包 `resources/`；`module.json` 的 `resources` 声明；`ResourceLayout` 双根（模块 owner 只读模块包、框架 owner 只读框架根，互不回退）；新增 `Sdk` 的 `IResourceAccess`（模块自定义 kind，只读/相对/不越界）+ `IModuleContext.Resources`；审计/打包：框架只审 `resources/`，模块 `resources/` 走 ③d/`verify-module-packages`；许可 `LICENSE` + `THIRD_PARTY_NOTICES`。人眼复核见 acceptance.md A46–A55；已知边界见 G68/G69/G70。

**本轮（模块可独立开发：分层 · 对账 · 作者工具链 · 文档）**：① **分层**：外部接入面只搬原始字节（`Sdk.AccessKit` 移除类型声明与组帧，改为组合式 `ExternalAccessChannel`），数据类型与组帧由模块自己声明/实现；四个接入模块各自携带 `RawBytes`（不再由共享件代声明）。② **声明对账**：端口形状必须等于所引用类型形状；同标识两种形状报一条冲突；外部接入两种消费方式互斥；`IExternalAccess.Pump` 给活动体一个显式的会话推进入口。③ **作者工具链**：五个包（`Sdk` / `Sdk.Ui` / `Sdk.AccessKit` / `Sdk.Testing` / `Module.Build`），运行时包带 XML 文档；`Sdk.Testing` 与 `Module.Build` 属作者包（不随宿主、不进模块包，模块运行时引用即拒绝加载）；打包规则抽出 `build/module-package.targets`，仓库模块与外部作者共用。④ **样例**：`samples/DataModule`（纯数据变换）与 `samples/ExternalModule` 都只经作者包构建成薄包并能被宿主装入。⑤ **文档**：`docs/zh/module-dev/` 七页；数据类型约定、被拒原因、外部接入机制已并入对应层。⑥ **撤回**：`MaxUnitBytes` 的框架级校验（原始单元上限与端口形状的关系由模块自己的组帧决定，框架没有通用判据），结论登记在 `dev/constraints.md` 的例外说明。

**本轮（计时机制替换与 UI 热路径）**：`IActivitySource` 删除 `NextDelay`，`StepReason` 删除 `Due`；新增 `IModuleContext.Timers` / `IModuleTimer`（模块自持、框架调度、Tick 在实例线程），删除 `StepDueTimer` 与首条特殊分支；连续发送改由定时器驱动，4 ms 经验阈值与提示删除。承载增加非阻塞 posted-work 队列，定时器 Tick 与生命周期/OnStep 串行；实例禁用暂停定时器、移除统一释放。另修 UI 每帧热路径：配置 Schema 按变更号缓存、模块目录缓存、订阅最新值/曲线按 `Written` 缓存、隐藏窗口跳过表面刷新。版本升到 `0.0.0.10`，全部模块与测试桩已迁移。
