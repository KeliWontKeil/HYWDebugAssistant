# ADR-0028 模块 SDK 形态（技术架构设计 第 3 章冻结）

> 状态：**Accepted**（用户逐条裁决，议程 ③ 第 3 章）
> 关联阶段：技术架构设计（选型后 · 实现前）
> 关联主文档章节：§4.4（Definition 六项声明）、§4.6（Interface 与端口）、§4.8-B（边界契约）、§5.4/5.4.1/5.4.2（契约能力与数据面边界）、§8.4（生命周期）、§10.4（无 UI 模块）、§11.2（模块包 manifest）、§12（安全）
> 关联文档：`docs/architecture/03-module-sdk.md`（全文）、`03a-view-rendering-options.md`（C3-6 专项分析）
> 关联 ADR：**ADR-0026**（L1 零框架依赖、L6 仅引 L1）、**ADR-0027**（单一 SDK 程序集）、ADR-0008（契约能力）、ADR-0013（框架统一承载）、ADR-0023 §5（脚本留位）
> 取代：无 · 被取代：无
> 依据：顶层基线 v1.0 · ADR-0020（模块供给）· ADR-0025（工程约束）

## 问题

框架与模块之间的**唯一契约面**由什么构成：声明如何表达、模块如何被实现与调用、契约形状如何描述与判定兼容、配置如何序列化并保真、标识如何定义、视图如何表达（在 C1-3 禁止模块依赖 UI 框架的前提下）、是否引入脚本宿主。这决定了 `Sdk` 程序集的公开 API 形态，也决定模块作者的全部书写体验与框架加载/调用路径。

## 背景

- 前置裁决：ADR-0026 定 L1 契约层**零框架依赖**、L6 模块实现**仅引 L1**、**模块不得依赖 UI 框架**（C1-3）；ADR-0027 定 `Sdk` 为**单一程序集**、参考桩模块与业务模块同构。
- 基线约束：Definition 六项声明（§4.4）、契约三层能力（ADR-0008）、不自动转换（§5.4.1）、框架不附加数据单元元信息与不含单位（§5.4.2）、生命周期四正交面与框架状态机（§8.4）、模块包 = manifest + 实现绑定 + 资源（§11.2）、轻量透明安全模型（§12）。
- 用户裁决前提：Q3-1 C# 特性 + 反射；Q3-2 C# 类型即契约；Q3-3 接口实现；Q3-4 C# 类型 + 源生成；Q3-5 结构化三元组 ID；Q3-6 v1 不引入脚本；Q3-7 预置元素组合声明。

## 候选方案（要点）

| 决策点 | 候选 | 选择 |
|---|---|---|
| 声明载体 | 特性+反射 / 源生成 / 外部 manifest / 代码为源+导出 manifest | **特性 + 反射**（加载期读一次 → 不可变元数据缓存） |
| 契约表达 | C# 类型即契约 / 独立契约描述语言 / 两者并存 | **C# 类型即契约**（成员受"形状原语目录"约束） |
| 实现基元 | 接口 / 抽象基类 / 组合注册 / 接口+基类 | **接口实现** |
| 配置 Schema | C# 类型+源生成 / 独立 schema 文本 / C# 类型+宽容容器 | **C# 类型 + 源生成** |
| 标识 | 可读字符串 / GUID / 结构化三元组 / 可读+版本 | **结构化三元组**（作者命名空间 / 模块名 / 版本） |
| 脚本宿主 | 不引入 / 引入 / 预留接口 | **v1 不引入** |
| 视图 | 纯声明式 / 预置元素组合 / 含表达式声明 / 数据驱动通用渲染 / 模块自带 View | **预置元素组合声明**（档 3 完整目录） |
| 包与模块基数 | 1 包 1 模块 / 一包多模块 | **1 包 1 模块（v1 强制）** |
| 自发活动 | 可选接口+框架承载 / 模块自行发起 / 两者并存 | **可选接口 + 框架承载（L3）** |
| 未知字段保留 | 源生成+保留原始片段 / 宽容字典 / 不保留 | **源生成 + 保留原始片段** |
| 钩子集合 | 6 个 / 增加细分 / 合并 Enable-Disable | **6 个**（`OnRegistered`/`OnActivated`/`OnDisabled`/`OnEnabled`/`OnConfigurationChanged`/`OnRemoved`） |
| 形状原语目录 | 仅定长+结构组合 / 加变长 | **仅定长原语 + 结构组合** |

## 最终选择

如"候选方案"表"选择"列。要点汇总：

1. **SDK = `HYWDebugAssistant.Sdk` 单一程序集**，承载声明载体、实现基元、框架服务面；零框架依赖。
2. **声明**：C# 特性描述 Definition 六项 + manifest 附加项；**包加载期反射读取一次**，转为不可变元数据；运行期热路径零反射。
3. **实现基元**：模块入口接口 + 可选能力接口 + 六个生命周期钩子；框架只按接口调用（不继承基类）。
4. **契约**：作者定义的 C# 类型，成员限"定长形状原语"组合；三层能力落地为①传递语义标注②原语目录③组合签名；兼容判定 = **形状完全一致**〔**ADR-0051 修订**：原「接收 ⊇ 发送（定长子集）」已作废〕；判定实现在 L2/L4，不在 SDK。
5. **配置**：C# 类型 + 源生成序列化 + **未知字段片段保留并合并写回**（AC-4）。
6. **标识**：结构化三元组（作者命名空间 / 模块名 / 版本），版本参与多版本共存。
7. **视图**：模块以声明从 **18 个预置元素 + 4 个容器**（档 3 完整）中选择并组合，绑定到可暴露数据源；模块不提供 View 类型。
8. **服务面**：模块不持有框架引用，只经上下文使用上报（Issue/日志/业务状态）、配置读写、活动承载登记。
9. **无脚本**：v1 模块行为载体只有 C#；ADR-0023 §5 的脚本留位不实现。

## 选择理由

1. **特性 + 反射**：声明读取只发生在包加载期，成本一次性；避免源生成器成为模块作者构建的硬依赖（作者只需 `Sdk` + 编译器）。与 Q3-4 的源生成分工明确：**反射管声明、源生成管序列化**，热路径零反射。
2. **C# 类型即契约 + 定长原语**：契约与实现同语言，作者无需学习第二套语言；"受控"通过原语目录在加载期校验实现（§5.4.1 ②的落地）；**定长布局**使数据单元可扁平化（为第 4 章零分配投递提供前提），兼容判定退化为**定长形状的结构比较**，完全可计算〔**ADR-0051**：原「子集」已改为「完全一致」〕。
3. **接口实现**：语义最轻、与"应用层近似统一（非重量级对象系统）"一致（ADR-0006），避免继承带来的实现锁定。
4. **结构化三元组 ID**：可读 + 可治理 + 天然支持同 ID 多版本共存（§11.2），并支撑重锚（`实例ID.口名`）诊断。
5. **1 包 1 模块**：与 C2-4 一致，Registry 登记粒度 = 包粒度，加载/卸载/多版本语义最简单。
6. **自发活动 = 可选接口 + 框架承载**：这是 ADR-0013「框架统一承载活动、模块不自建线程」在 SDK 上的唯一自洽表达——若允许模块自行发起活动，AC-2 隔离性与调度可控性同时失效。
7. **未知字段片段保留**：直接达成 AC-4 无损往返，且不比宽容字典多损失类型安全。
8. **预置元素组合 + 档 3 完整**：在 C1-3 前提下，目录即表达力上限；选择完整档使串口/波形/参数调试主场景可直接表达，避免"框架一发布就缺元素"。

## 放弃方案

- **源生成器做声明载体**：模块作者构建链复杂化，且反射成本只在加载期，收益不足。
- **独立契约描述语言**：需自研语言与绑定层、双份表示映射，收益（跨语言）在 v1 无实际需求 → 未采纳（未来若需跨语言，须新 ADR）。
- **抽象基类/组合注册**：基类锁定实现方式、组合注册提高作者心智负担 → 未采纳为基元（接口为主）。
- **宽容字典配置**：失去类型安全与自动生成配置界面的能力（Q5-5/B1 依赖 Schema）→ 未采纳。
- **GUID 标识**：人工不可读，不利于组合件可读与 diff（§9.3 文本格式方向）→ 未采纳。
- **脚本宿主**：与 §12 轻量透明模型冲突，且热路径性能优先（ADR-0023 §5）→ v1 不引入。
- **变长原语（字符串/序列）**：形状比较与缓冲管理复杂化，且违反"定长布局"前提 → 未采纳（未来扩展须新 ADR）。
- **模块自带 View（路线 d）**：需推翻 C1-3，会打破 L1 零依赖与 E4 防线 → 未采纳。
- **纯声明式/含表达式声明/数据驱动渲染**：前者表达力不足以覆盖波形与表格；含表达式与"v1 不引入脚本"边界模糊；数据驱动渲染控制力弱 → 未采纳为 v1 主路线（作为未来便利层保留可能）。
- **一包多模块**：加载/卸载/版本语义复杂化，v1 无需求 → 未采纳。

## 影响

- **对第 4 章的硬约束**（四项前置）：
  1. Q4-2（数据单元物理表示）受 C3-5 约束 → 可采用**定长扁平布局**（零拷贝/池化可行）；
  2. Q4-4（UI 交接模型）受 C3-6 约束 → **必须提供抽样 + 环形缓冲 + 刷新节流**；
  3. Q4-5（模块活动承载）受 C3-2 约束 → **必须承载模块自发活动**（周期/事件驱动），模块不得自建线程；
  4. R4-5（组合件格式）受 C3-3 约束 → 须支持**未知字段片段保留与合并写回**。
- **对第 5 章**：渲染范围为 18 元素 + 4 容器；元素视觉形态属 Gate C。
- **对第 6 章**：T6 模块契约测试套件须覆盖"声明完整性 / 原语目录合法性 / 钩子实现 / 无跨模块引用"。
- **对主文档**：已将 §15.1「脚本宿主可选」收窄为 **v1 不实现**（属 Gate D 项顺延）；§10.4「模块视图自备」经本章（Q3-7/路线 d，与 ADR-0026 C1-3 同源）收窄为**"框架按声明渲染、模块不提供 View 类型"**；§4.4/§4.6/§5.4/§5.4.1/§5.4.2/§8.4/§11.2 为实现层细化（声明载体、契约原语、配置 Schema、结构化三元组 ID、生命周期钩子），结论方向不变，修订记录登记为 1.0.3。
- **对其他**：`Sdk` 的破坏性变更 = 契约变更，须 ADR（ADR-0025 §5 六类情形）。
