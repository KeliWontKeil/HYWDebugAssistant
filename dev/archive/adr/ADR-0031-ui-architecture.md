# ADR-0031 UI 架构（技术架构设计 第 5 章冻结）

> 状态：**Accepted**（用户逐条裁决，议程 ③ 第 5 章）
> 关联阶段：技术架构设计（选型后 · 实现前）
> 关联主文档章节：§10.1/10.2（视图=Instance 派生物、自由排列、无容器、几何与连接解耦）、§6.3（连线默认隐藏 + 网络标记依附于口）、§10.4（口上标记由框架渲染、无 UI 模块兜底、聚焦高亮）
> 关联文档：`docs/architecture/05-ui-architecture.md`（全文）
> 关联 ADR：ADR-0026（UI 只引契约面 + `Core.Api`）· ADR-0027（`Ui` / `FrameworkUi` 两项目）· ADR-0028（**模块不得提供 View 类型**；视图 = 预置元素组合；18 元素 + 4 容器）· ADR-0029（订阅缓冲；UI 一律经 `Core.Api`）· ADR-0030（设置界面属 `FrameworkUi`）· ADR-0018（几何与连接解耦）
> 取代：无 · 被取代：无

## 问题

第 1–4 章定了分层、项目、SDK 与机制，但 UI 侧仍缺：层如何划分、模块视图如何排布与拼接、模块视图与"叠加信息"的归属边界、连线与网络标识画在哪里、配置界面如何生成、框架自身 UI 包含什么、UI 与 Core 的接口面是什么。

## 背景

- 硬前提：C1-3（模块不得依赖 UI 框架）与 Q3-7（模块不得提供 View）⇒ **"模块自绘视图/自备编辑器"在架构上已被排除**，本章只在框架侧的做法间选择。
- 输入：C3-6（18 元素 + 4 容器）、Q4-4（订阅缓冲：最新值槽 / 环形缓冲，抽样在 UI 侧）、C4-4（UI 一律经 `Core.Api`）、基线 §10 的形态裁决。
- 用户在裁决中纠正了一处问题表述：**"模块自身的 UI"与"叠加在模块上的信息层 UI"必须分开**。

## 最终选择

1. **层模型**：**工作区层（元件层）**——始终显示、只含模块视图（含模块自身简易标记），是"基础工作区域"而非显示层（PCB 元件层类比）；**信息类层**——按功能分类、可多层、**不预设层数**、保留扩展可能性。层只承担视觉（ADR-0023 §7）。
2. **归属边界**：模块视图与模块自身标记 = 模块自身 UI（工作区层）；连线、网络标识、方向与连接状态、聚焦高亮、诊断叠加、Issue 标注 = 框架的信息类层。**模块对叠加信息无表达权（框架独占）**，只提供锚点（口的位置/尺寸）。
3. **模块区排布**：**自由画布 + 几何吸附**——【**v1.1 表述勘误**】经用户澄清，Q5-1 的"停靠"指**几何吸附**（模块间边缘拼接 + 画布边缘/参考线对齐），**不是窗口停靠（Docking UI）**；**不引入任何容器式布局**（不做布局树/停靠槽位/标签页堆叠），与主文档 §10.2「不采用画布容器概念」、§18.4「不做画布/面板容器形态」一致。**不做网格吸附**（"网格吸附有悖直觉"）。
4. **拼接 = 由位置派生的关系**：只保存位置；"是否拼为一组"由边缘贴合（容差判定）派生为**连通分量**；附带 6 条实现次序约束（拖动前冻结组、拖动后重算、传递性、快捷键独立拖动、容差唯一参数、位置变化三来源均需重算）；组**不是容器**。
5. **吸附语义**：无网络标签时 = **边缘贴合 + 端口对齐优先**；有网络标签时不做该限制（由标签块承担对齐）。快捷键可停用吸附，支持**按住/切换**两种模式且可修改（→ 应用级设置项）。
6. **几何一致性（不强制尺寸族）**：不引入框架强制的尺寸族；改为 ①内置模块的**尺寸族开发约定**（典型应用可直接拼成整块，不强制）②模块**拉伸属性**（只能拉伸长/宽/任意/不允许）③**端口锚点可拖动性属性**（固定时拉伸按比例重排；可拖动时用户自行调整；快捷键锁定/解锁）④**网络标签块可拉伸**（贴在模块边缘的小矩形块，端口对齐）⑤**排版块 = 一种常规模块**（无端口、无功能、只能改大小，与功能模块同级同机制，不引入新概念）。
7. **数据绑定**：模块**声明数据源**（名称 + 类型），框架**拉取**写入订阅缓冲，UI 按刷新节拍读取并在 UI 侧抽样。
8. **配置界面**：**按 Schema 全自动生成**；配置编辑元素（B1）**仅出现在模块视图内**（模块声明时）。
9. **框架 UI（`FrameworkUi`）**：设置界面、Issue 面板、模块清单/管理视图（无 UI 模块兜底）、诊断面板（L1/L4 + 轻量提示）、模块加载入口。
10. **层初始清单（v1）**：连线层 + 标记层 + 诊断层。
11. **端口位置归属**：与模块参数**一同管理**（同属实例级、随组合件保存）；**开发者只预设端口初始状态并指明可变更性**；锁定状态属交互态。

## 选择理由

1. **"组由位置派生"**（用户裁决）：组不是独立层级的信息，把它存起来会制造"位置与组不一致"的二义性；派生方案让组始终由当前位置唯一确定，且天然避免"拖完忘了更新组"的错误。
2. **区分工作区层与信息类层**（用户纠正）：模块视图属于模块这个功能单元；连线连接两个模块、聚焦高亮是跨模块信息——任何单个模块都表达不了，必须由框架在信息层绘制。
3. **不做网格吸附而保留非强制尺寸族约定**：网格吸附要求用户感知一张不存在的网格、违背直觉；而尺寸族约定只影响内置模块的设计，用户侧无约束感，恰好解决破洞问题。
4. **排版块做成常规模块**（用户裁决）：不引入新的内容对象类型、不新分层、不破坏"工作区层只含模块"与 P3（模块是用户可感知的功能基本单元），实现机制复用现有模块机制。
5. **配置界面全自动生成 + 只出现在模块视图内**：与 Q3-4（C# 类型 + 源生成）直接对应，零额外工作量；避免出现"模块视图 vs 管理视图"两处配置入口的状态歧义。

## 放弃方案

- **网格吸附**：需要用户感知不存在的网格，违背直觉（用户明确否决）。
- **强制尺寸族**：限制模块尺寸自由度，且用户希望"仅在需要整齐排版时"才需要整齐。
- **拼接组持久化**：引入与位置可能不一致的第二信息源。
- **模块可自绘标记 / 模块可对信息层提要求**：违反 C1-3 与"框架独占"（C5-3 ①）。
- **模块自备配置编辑器**：需引用 UI 框架，违反 C1-3。
- **配置编辑元素同时出现在管理视图**（C5-4 ②③）：会造成两处入口；无 UI 模块的配置经管理视图兜底已足够。
- **排版块作为新内容对象 / 专用"排版模块"类型**：前者破坏"工作区层只含模块"，后者引入特殊机制；用户裁决用常规模块实现。
- **仅连线层（不提供标记/诊断层）**：网络标记与诊断是调试助手的核心可见信息。

## 影响

- **第 6 章**：UI 相关测试范围（T7 UX 手工/原型、T8 UI 自动化）须与本章的层模型、拼接派生逻辑（可单测的几何谓词）、订阅缓冲（可自动化验证"UI 慢不影响数据面"）对应。
- **Gate C（UX 原型）范围**：吸附容差、拖动手感、元素视觉形态与尺寸族具体参数、层绘制次序、窗口形态、快捷键绑定默认值。
- **应用级设置新增项**：快捷键（含按住/切换模式）、吸附停用、端口锚点锁定、连线显示默认、刷新率、主题（ADR-0030 清单可增长）。
- **实现细节登记**：端口位置在组合件中的存放形态（并入配置 Schema 或并列几何段）。
- **对主文档**：已将 §10.1-5 的"尺寸族与网格对齐"具体化为**非强制开发约定**且**不含网格吸附**（§15.1 的"停靠"同时明确为**几何吸附**，不做容器式窗口停靠）；§10.1/§10.2（视图=Instance 派生物、自由排列、无容器）、§6.3（连线默认隐藏 + 标记依附于口）、§10.4（口上标记由框架渲染、无 UI 模块兜底）的层模型与归属边界属实现层细化，结论方向不变，修订记录登记为 1.0.3。
