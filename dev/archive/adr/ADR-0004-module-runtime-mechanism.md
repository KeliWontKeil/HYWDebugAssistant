# ADR-0004 模块—框架运行顶层机制（描述冻结）

> 状态：Accepted（用户裁决，批次 1c）
> 关联批次：批次 1c
> 关联主文档章节：§4.8（新增）
> 取代：无 · 被取代：无

## 问题

用户指出批次 1 在未描述"模块本身运行的顶层机制"前就进入内部结构裁决（PQ-DM-01/03/04/09），问题悬空。需先立模块被框架运行的顶层图景。审阅中用户进一步校准：不得用"Workspace 文档"等实现承载机制约束顶层；不得把模块间数据传递表述为经 Core 中转（违反 P2/E1）；P12"不直连"存在歧义。

## 背景

- Core=统一框架（仿真器）、Module Definition=可加载模型、内置=预装库文件（用户提出的仿真框架类比，批次 1 认可）。
- 已冻结：P2/E1/E2（Core 非交换机/总线）、P12（模块不依赖具体模块）、§7.1（全在线变更）、§7.2（数据直通语义，批次 1 校准）。
- Workspace 是抽象概念，持久化聚合机制不属本阶段（批次 6）。

## 决策

按"用户行为视角 / 模块运行行为视角 / 边界契约"三部分冻结模块—框架运行顶层机制（全文见主文档 §4.8，此处为要点）：

- **A1 用户行为视角**：选模块→产生实例；配置→交实例（内容模块自定）；拼接→契约校验建连接；改配置/拓扑→在线生效局部重建；保存/恢复→保存用户声明内容（机制批次 6）。
- **A2 模块运行视角**：实例被框架驱动；数据经连接**直接**流到下游（不经 Core 中转）；模块只与框架运行环境交互、不知其他模块、实现不引用另一具体模块（P12 澄清）；业务状态自管，框架管宿主级状态与绑定生命周期。
- **B 边界契约**：框架供给（生命周期/连接建立拆除/配置读写/状态错误上报/可选视图宿主/活动承载）；模块承诺（业务自负/经契约互联/错误受控上报）。
- **C 活动方式（不分类裁决）**：**不预设"被动变换/自治源"分类**——模块是否需要自发活动是模块自身属性（实现层差异），不属顶层约束；不得提前分类。具体表达随 PQ-DM-01 回审与批次 4。

## 最终选择

A1/A2/B 如上；C 采取"不分类、属性归模块自身"（用户裁决）。

## 影响

- 主文档新增 §4.8；挂起项 PQ-DM-01/03/04/09 可在本机制描述基础上回审。
- P12 表述澄清（实现不引用另一具体模块，接口互联非依赖）；§7.2 数据直通语义确立。
