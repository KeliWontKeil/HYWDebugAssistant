## 1. 背景：用户三次定性 + 一次自我检查

| 轮次 | 用户口径 |
|---|---|
| 第二十一轮 | "**多源不等于停流**；当用户配置了多源时，**可能是用户确实需要多源**"（并追问冲突/速率极限下的接收策略） |
| 第二十二轮 | "**N2 我同意动全链**。在**最初始的设计中，多源是一个重要的设计，需要实现**……当前底层通信需要**彻底的改造**……**可能需要合并两次调整为一次重大调整**" |
| 第二十三轮 | 提出"**压栈/出栈**"模型 + "**接收端不需要关心数据从哪来**" + "**输入输出任意**" + "**交换机不做仲裁**"的类比；并判断"**需要设计整个具体的结构后，才能回答部分待裁决项**" |
| 第二十四轮 | "我是否在**重新以一种复杂的方式实现某种本已完善存在的协议，比如 UDP**？……**整个底层可以重构为一个'UDP 网络'**？" |
| 第二十五轮 | "**同意你的所有推荐做法。开始进行。**" |

**核实出的现状问题**（`18` §1）：**三处互不一致** —— 冻结条款（"不建立数据流 + 保留声明"）/ 实现（`BuildLabeledNetworks` **整条网络不创建** + Issue）/ 我上一轮的措辞（"≥2 源 = 停流"，三项皆错）。**根因**：`Network.Source` 单值 ⇒ 模型无法表示多源。

## 2. 数据面语义规范化（**UDP 式数据报 + 发布订阅**）

### D1. 采用"UDP 式数据报语义"作为数据面的正式规范

| 维度 | 规范（= 现行实现的语义，本轮**正式命名**） |
|---|---|
| 连接 | **无连接**：按**声明**建立绑定后即投递（无握手/无会话） |
| 可靠性 | **best-effort**：有界队列满即丢 + 计数（**不背压**） |
| 顺序 | **同 (源,宿) 对 FIFO 强保证**；**跨源仅"按到达"**；**不提供跨源时间序** |
| 边界 | **数据报**：一个单元 = 一个定长数据报（契约尺寸） |
| 1:N / N:M | **多播**（1→N 复制）· **多发布者**（N→1）· **N:M** |
| 端点 | **口（端口）**；**无每包地址**（拓扑由声明派生） |
| 校验 | **长度校验**（`payload.Length >= SizeInBytes`） |
| 可观测 | **四档速率 + 三类丢弃 + 队列水位**（ADR-0046 D8 + 本 ADR §4） |

### D2. 术语规范化（采纳成熟词汇，停止自造）

| 本工程 | 标准术语 | 出处 |
|---|---|---|
| 数据单元 / 投递 | **数据报（datagram）** / **发布（publish）** | UDP / DDS |
| 网络（1 源 N 宿） | **topic（主题）**：**publisher / subscriber** | DDS / ROS 2 |
| 多源 | **多发布者** | DDS / ZeroMQ pub-sub |
| 停流 / 悬空 | **liveliness / deadline（活性/截止）** | DDS QoS |
| 有界队列 + 丢弃 | **best-effort reliability + history depth** | DDS QoS |
| 队列水位 | **queue depth** | 通用 |
| 契约兼容 | **type matching** | DDS |
| （不提供的）序号/源时刻 | **sequence number / source timestamp**（DDS 头内有） | DDS |

> **注意**：术语规范化**只改文档与注释用词**，**不改代码标识符**（避免大面积 churn）；新代码优先用标准词。

### D3. **不做**的两件事（以及为什么）

| 不做 | 理由 |
|---|---|
| **进程内改用真 UDP socket** | 本项目实测：完整投递 **54 ns**、三跳端到端 **1.8 µs**、≈**3.2 M 单元/秒**；走环回内核栈为 **µs 级（量级估算 1–10 µs，约 20–100× 慢）**，且引入抖动 / MTU 分片 / 系统缓冲 / 端口与防火墙因素，并失去零拷贝与对象模型 |
| **变长 / 分片** | v1 保持定长（ADR-0046 D3）；需变长另立 ADR |

**跨进程 / 跨机通信**（同一语义契约的真 UDP/TCP/共享内存）登记为**未来能力**，**不属于本轮**；**与真实设备通信由模块承担**（`ModuleCapability.Network/SerialPort` 已存在）——框架数据面是**模块之间的织物**，两者不得混淆。

## 3. 多源网络模型（**M1–M14**）

| # | 决定 | 内容 |
|---|---|---|
| **M1** | **多源 = 合法的一等组合** | 同名标签的多个发送端 ⇒ **一条多源网络**；框架**不隐式仲裁**；旧"整条拒绝"**作废** |
| **M2** | **模型 = N:M** | `Network.Sources` 改为**列表**（`Targets` 已多宿）；绑定仍按网络；**投递逐 (源,宿) 对**；保持零拷贝与字节守恒。**【落地精化 §3b】** `Sources` 只含**在场的源**，未锚定的源在 `UnresolvedSources`（宿侧对称 `Targets` / `UnresolvedMembers`） |
| **M3** | **接收策略 = 框架中立** | **按到达顺序投递**（= D1 顺序规范）；**不做**优先级 / 时刻排序 / 去重 |
| ~~M4~~ | ~~来源 sideband~~ | **撤回**：数据面**不暴露来源**；**应用需要就自带字段**（ADR-0046 D4 原裁决不变）；**观测面从绑定模型取来源**（框架不读数据即可显示多源） |
| **M4b** | **顺序保证等级** | 同 (源,宿) 对 **FIFO 强保证** · 跨源**按到达** · **不提供跨源时间序** |
| **M5** | 停流 / 悬空 | 全部源未锚定 ⇒ **停流**（保留声明）；**部分源不可用 ⇒ 其余照常投递** + 该源 Issue；无源/无宿 ⇒ 未建网（等待）。**【落地精化 §3b】** `IsStalled` = **派生量**（`⇔ Sources.Count == 0`，不单独存）；停流/悬空 Issue 由**锚定路径**报（加载全报、重锚只在源在场状态变化时报源侧） |
| **M6** | 兼容 | **逐 (源,宿) 对判定**，只排除不兼容的**那一对** |
| **M7** | 计量 / 丢弃 | **按源归属** + 细分（`队列满` / `无承载` / `载荷非法` / `停流未投递`）+ **队列水位** |
| **M8** | 建网方式 | **同名标签 ⇒ 多源网络**；**几何（接触对齐）不自动合并**（避免误连，仍按源口一条网络） |
| **M9** | **宿口多路输入 = 合法** | 取消"宿口唯一"；拓扑显示"几路输入" |
| **M10** | **不做背压** | 保持有界队列 + 丢弃 + 计数（ADR-0029 C4-1：安全 + 提示，不限额/不阻断）；只暴露水位与原因 |
| **M11** | 持久化 | `source`（单值）→ **`sources: [...]`** + `schemaVersion` 升级 + **旧文件读入迁移**（旧组合件必须可加载） |
| **M12** | 呈现 | 网络标签（端口块）**不变**；拓扑显**源列表 + 每源状态**；叠加层"**多生产者 → 一消费者**"（来源取自绑定模型） |
| **M13** | 与 ADR-0046 | D4/D5 依 **§5 薄头**处理；D1–D3/D6–D8 保持 |
| **M14** | 明确不做 | 优先级/排序/去重/限流/背压 · 变长载荷 · 模块自带 View · 几何自动合并 · 进程内真 UDP |

## 3b. 落地精化（**R2-a + R3 已实现** · 2026-09 · **不改变 M1–M14 语义**）

> 落地时暴露的三个**模型层面必须写清**的问题（推导见 `docs/architecture/18-network-semantics.md` §8；
> 主文档 §5.4.2/§9.3 已同步 → **1.0.17**）。

| # | 精化 | 内容 |
|---|---|---|
| **B1** | **源集合分两态** | `Network.Sources` = **在场（已锚定）的源**；`Network.UnresolvedSources` = **悬空的源声明**（方向 = 发送）；宿侧对称（`Targets` / `UnresolvedMembers`）；`DeclaredSources` = 两者之并（**持久化/展示的事实源**）。**根因**：源字面量与锚定后的成员**取值相同** ⇒ 单集合**无法区分"在场"与"只是声明"**，重锚无从判断"刚刚锚定成功" |
| **B2** | **`IsStalled` 是派生量** | `IsStalled ⇔ Sources.Count == 0`，**不单独存** ⇒ 不可能"标志与成员各说一套"；**部分源未锚定不是停流**；`Sources` 为空是**合法状态**，读取方必须先看 `IsStalled` |
| **B3** | **算 / 报分离** | `AnchorNetwork` = **唯一**的"字面量 → 网络"实现（**加载与重锚共用** ⇒ 重锚**不可能**再把多源网络打回单源，这是旧实现按 `network.Source` 单源重算的真实缺陷）；`NetworkAnchoring` 算而不报；`ReportNetworkAnchoring` 决定报什么（加载全报 / 重锚只报**源在场状态变化**的源侧、宿侧只在加载时报）；**停流 Issue 不再由 `RebuildBindingsCore` 报**（同一事实一个 owner） |
| **B4** | **身份键用声明的源** | `NetworkView.Key` = **声明源集合 → 宿集合** ⇒ 两条都停流的网络不会因"在场源为空"而撞成同一个键（P40 身份键必须唯一） |
| **B5** | **队列粒度每 (实例,口)**（R2-b） | **每口一条**有界 FIFO（容量按口计）+ **轮转公平调度**（`TryDequeueAny`，投递循环与主动接收共用）；`CarrierOptions.QueueCapacity` 语义改为**按口**；入队结果分类 `Accepted/QueueFull/NoCarrier/Stopped`（**"无承载"不再记成"满队"**）。**局部修订 ADR-0029 §4.2（队列粒度）**；线程模型与顺序保证不变 |
| **B6** | **薄旁路头只在多源网络**（R2-c · Q6(c) 落地） | 新增 `DatagramHeader{源实例ID, 源口名, **按源序号**, **接收时刻**}（`Stopwatch` 单调计数）`；**随单元旁路携带**（`InboundUnit.Header`，**不进 payload 字节流** ⇒ 字节守恒不变）；**单源网络传 null ⇒ 零附加**（不构造、不入队、不读取）。**消费者 = 观测面**（承载诊断 `Headered` / `LastHeaderSequence` / `LastHeaderTimestamp`）；**模块仍不通过它取来源**（M4 不变：应用需要就自带字段）。**序号语义**：按源递增（1 起）——由新增的 `BindingDiagnostics.Published`（**每个数据报一次、不受多播放大**）提供，同时它就是 ADR-0046 D8"单元速率（按源计）"的分母 |
| **B7** | **类型注册表落地**（R4 · ADR-0046 D2） | `IModuleDeclaration.DeclareDataType(DataTypeDeclaration)`：**标识 + 版本 + 定长形状（尺寸）+ 传输语义 + 计量块 + 解码器 + 语义元数据**；口用 `PortDeclaration.Type`（`init` 属性，**二进制兼容**）引用；框架持**机械镜像**（`ModuleInstance.DataTypes` + 按（标识,版本）索引）；**引用未声明类型**与**重复声明**都报 Issue 并回退 |
| **B8** | **兼容判据**（R4 · ADR-0046 D6） | 〔**ADR-0051 修订：三层 → 两层 + 形状完全一致**〕① **同标识 + 同版本 + 形状完全一致** → 兼容；② **同标识不同版本 → 不兼容**（版本升级按破坏性变更处理；原「尾部追加 = 兼容」**已作废**）；③ **不同标识** → **框架无资格判定 ⇒ 默认不兼容**（形状相同也不认）；**用户显式确认**（`ConnectNetworkOperation.AllowUnverifiedTypeMatch` / 网络上的同名标志，**随组合件持久化**）后放行，**此时仍要求形状完全一致**。**任一方未声明类型 ⇒ 只按形状完全一致判定**（原「接收 ⊇ 发送」子集判定已作废）。**形状比较必须用 `ContractShape.AreSame`**（record 默认相等对结构形状的字段集合做引用比较） |
| **B9** | **解码器随类型注册**（R4 · ADR-0046 D1 ③） | `DataTypeDeclaration.Decoder`（`SampleDecoder` 委托，在 Sdk）；数据源用 `ViewDataSource.Type` 引用类型 ⇒ 框架把**模块的解码器句柄**经 `SubscriptionSourceView.Decoder` 交给呈现层（**框架只回调、不内建**）；`Ui/Runtime/SampleCodec` **降级为参考实现**（只服务未声明类型的旧模块，登记为历史兼容路径）；Sdk 另提供 `PrimitiveSampleDecoder` 供模块直接注册 |
| **B10** | **四档速率 / 三类丢弃 / 水位落地**（R4 · ADR-0046 D8） | **四档速率由框架机械给出**（`RateMeter`，单调时基）：单元（按源 = `Published`）· **搬运字节（按宿计）** · 有效载荷字节（按源 × 类型声明的 `PayloadSizeInBytes`）· 样本/通道样本（× `SamplesPerUnit` × `ChannelCount`）；**标称速率**随视图给出（掉速 = 实测 vs 标称）。**三类丢弃分开**：`DropStalled`（合法状态）· **`DropTransport`**（= 队列满 + 无承载 + 载荷非法）· 模块内部（`SubscriptionSourceView.Overwritten/Dropped`）。**队列水位**：新增 `PortQueueDepthView`（每 (实例,口) 的深度/容量/入队/丢弃 + **按宿计**的搬运字节速率）。**记账补漏**：丢旧策略下"已入队但挤掉旧单元"改为 `CarrierEnqueueResult.QueueFullEvicted` ⇒ 新单元记投递、被挤的旧单元记**队列满丢弃**（否则投递数会把从未被消费的单元算成成功）。**UI 不再自行差分估算**（`_rateSamples` 退休，改用框架口径） |
| **B11** | **R5：参考模块重编 + 多源参考模块** | 5 个参考模块全部升级到新面（声明类型 + 口/数据源引用类型 + 模块解码器），**真实链路因此走"同标识同版本"兼容层**；**新增 `hyw/reference-fuser/1.0.0`**（包名 `fuser`）——**双源融合/仲裁范例**：两个输入口 + 一个输出口，策略 `Latest`/`Priority`/`Average`，**来源用口区分**（M4），融合结果可**再发布**（合并由模块承担，Q4）；新增 `Sdk.Contracts.CommonDataTypes`（`hyw/*` **参考类型库**，注册动作仍由模块自己做）；`ModuleContract` 增数据类型自检并修正两处既有误报。**T3 已跑通**（326 测试 / 0 失败；6 个模块包）。**本轮修掉门禁阻塞 P47**：静态/共享画刷改用 `ImmutableSolidColorBrush`（原 `SolidColorBrush` 有线程亲和性，非 UI 线程先触碰后渲染线程读它即抛跨线程异常 ⇒ 视觉测试"一起跑红、单独跑绿"） |

**状态**：R0 ✅ · R1 ✅（切片）· **R2-a ✅** · **R2-b ✅**（队列粒度每 (实例,口) + 轮转公平 + 入队结果分类）· **R2-c ✅**（多源薄旁路头，单源零附加）· **R3 ✅** · **R4 ✅**（类型注册表 + 兼容三层 + 解码器注册 + 四档速率/三类丢弃/水位）· **R5 ✅**（6 参考模块 + 多源融合器 + **T3 已跑通**）· R6 ⬜（UI 投影：P3/ADR-0048 → P4/ADR-0049）。

## 4. 结构级裁决（**Q1–Q6**）

| # | 决定 | 结论 |
|---|---|---|
| **Q1** | 顺序保证等级 | 同对 **FIFO 强保证** · 跨源**按到达** · **不提供跨源时间序**（= M4b/D1；写进 §5.4.2） |
| **Q2** | **队列粒度** | **改为每 (实例, 口) 一条 FIFO 队列**（现状"每实例一条"存在**跨口队头阻塞**：一个慢口/满口会堵住同实例其它口的数据流） |
| **Q3** | 多源 → 同一宿口 | **允许**（交织为一条流；要求**逐对契约兼容**；宿若需区分来源 ⇒ **自带字段或改用多口**） |
| **Q4** | 合并 / 仲裁由谁承担 | **模块**（框架永不仲裁） |
| **Q5** | 观测面 | **水位 + 丢弃（按源、按原因）+ 四档速率**，全部取自绑定模型（**不读数据**） |
| **Q6** | **薄框架头** | **(c) 只在多源网络带头**（单源网络**零附加**）；头为**旁路元数据**（源标识 + 序号 + 接收时刻），**可选、不进 payload 字节流**；行业惯例本就"有头"（UDP 8 B / ZeroMQ 帧头 / DDS writer GUID + 序号 + 源时刻） |

## 5. 与既有裁决的关系（**逐条标注**）

| 既有条款 | 关系 |
|---|---|

## 6. 验证计划（回归判据 → `implementation/04` 与测试）

| # | 判据 | 层 |
|---|---|---|
| 1 | **多源投递**：同名标签 N 个发送端 ⇒ 一条多源网络；每源数据都到达宿；**逐对兼容**只排除不兼容对 | T1（Core） |
| 2 | **顺序**：同 (源,宿) 对 FIFO 不乱序（含多源交织时各源自身保序） | T1 |
| 3 | **停流/悬空**：全部源未锚定 ⇒ 停流且不投递；**部分源不可用 ⇒ 其余照常** | T1 |
| 4 | **宿口多路**：两条网络指向同一宿口 ⇒ 均投递、不报错；拓扑显示路数 | T1 |
| 5 | **队列粒度**：每 (实例,口) 独立队列 ⇒ **一个口满不影响同实例其它口**（反例：现状会互相阻塞） | T1 |
| 6 | **薄头（仅多源）**：多源网络单元带旁路头（源/序/接收时刻）；**单源单元字节数不变**（零附加断言） | T1 + 字节守恒 |
| 7 | **丢弃细分**：`停流未投递` 不计入 `传输丢弃`；`队列满`/`无承载`/`载荷非法` 可分 | T1 |
| 8 | **旧组合件加载**：旧格式（单源 `source`）可加载并迁移为 `sources[]`，写回新格式 | T1 |
| 9 | **观测面来源**：拓扑/叠加层能显示多源，**全程不读 payload** | T1（视图层断言） |

## 7. 落地计划（**R0–R6**，一次冻结 + 分阶段）

| 阶段 | 内容 | 检查点 |
|---|---|---|
| **R0 设计冻结**（本 ADR） | ADR-0050 + 主文档回写（§5.4/§5.4.1/§5.4.2/§6.2/§6.3/§13.2 → **1.0.16**）+ 索引/路线图 | 文档齐；**不动代码** |

**纪律**：① 每阶段"可运行 + T0 绿 + 受影响 T1 绿"；② **禁止在同一阶段同时改模型与格式**（R2/R3 分离）；③ 只增不改优先（重载/`init` 属性/只增字段），旧单源路径保持到 R2 回归通过；④ 落地期不再改设计，变更走新 ADR。

**风险与缓解**：范围大 ⇒ 分阶段检查点（可回溯）· 格式破坏现场 ⇒ 旧文件加载用例 + 写入前备份 · SDK 变更牵连模块 ⇒ 按 **P30** 重编全部模块包 · 决策反复 ⇒ R0 先冻结。
