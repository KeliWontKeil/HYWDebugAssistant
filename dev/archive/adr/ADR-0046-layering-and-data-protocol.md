## 1. 背景：为什么需要这份顶层冻结

用户第十六～二十轮连续指出："当前的各种设计失误**不是一个简单的问题**……是**顶层设计没有对齐和细化**"。

**证据（四条顶层条款缺失，代码可查）**：

| # | 缺失的顶层条款 | 证据 | 后果 |
|---|---|---|---|
| ① | **类型身份**：端口契约只有结构（`f32`），结构被当成了类型名 | `ContractShape.Describe()` 直接充当 UI 的类型文本 | UI 只能显示 `f32`；类型色板只能占位 |
| ② | **解析边界**：框架解析到哪一层未定义 | 视图声明带原语 + **UI 侧 `SampleCodec` 自行解码** | "框架不解析"与"框架按声明渲染"冲突（§3 D1） |
| ③ | **模块数据角色**：只有资源能力 | `ModuleCapability` = 网络/串口/文件/进程 | "中心方块"没有权威来源 |
| ④ | **数据包时序与计量**：只保留"最后数据时间/丢弃计数" | §5.4.2 第三条；`_rateSamples` 差分估算 | 延迟/抖动/丢包定位不可能；速率口径含糊（6 处口径差，见 D8） |

⇒ 这四条解释了"为什么每轮 UI 都在补"：**UI 是投影，投影画不出下层没有的语义**。

## 3. 决策（冻结）

### D1. 解析三段式（**边界写死**）

| 段 | 归属 | 内容 |
|---|---|---|
| ① **声明期读取** | **框架必做** | 注册/实例化时**一次性**读取模块提供的元数据（端口、契约/类型引用、视图、能力、计量块、解码器）；销毁时注销。**运行期不重读**（热重载按既有"重扫/需重启"规则） |
| ② **传输期解析数据流** | **框架禁止** | 框架**不读数据内容**：投递按绑定 + 仅校验**长度**；（"转发与建网"用的是**声明**，不是包内标签） |
| ③ **呈现期解码** | **模块负责** | 把样本字节变成"可显示值"的解码器**由模块提供并注册**；**框架只回调**，不内建、不理解结构 |

**唯一改造点**：`Ui/Runtime/SampleCodec`（框架内建解码）→ **降级为参考实现/模块侧工具**；框架通用路径改为**调用模块注册的解码器**。

### D2. 数据类型的携带与注册

```
模块侧：类型定义 = 标识 + 版本 + 尺寸（定长）+ 传输语义 + 语义元数据（展示用） + 解码器 + 计量块
             ↓ 注册（声明期一次）
框架侧：类型注册表条目 = 标识 + 版本 + 尺寸 + 传输语义 + 兼容声明        ← 只做机械判定，不解释语义
```

- **跨模块必须引用同一标识**（可扩展性的落点）；旧模块不填标识 ⇒ **回退为"结构哈希"**（向后兼容）。
- **框架必须知道尺寸**（数据面零拷贝按偏移切片、队列按字节计数、订阅缓冲按样本开槽）⇒ **尺寸属传输层**。
- 语义元数据（单位/量程/精度/建议采样率）随类型声明，但**只透传/展示**。

### D3. 数据单元形态：**v1 只定长**

- 保留定长 + 零拷贝；**批量 = 定长数组 `T[N]`**（D7）；**v1 不引入变长**。

### D4. 数据包**不自描述**

- 数据包**不带类型标签**；框架按**声明**（端口 + 绑定）路由。
- 需要"自描述/自携带信息"的模块 ⇒ **在自己的契约里带字段**（如参考模块的 `{seq:u64, value:f32}`）。

### D5. 时序信息：**框架侧统计，不附加到数据单元**

- 框架侧记录：**投递计数**、**最后数据时间**、**间隔统计**（供速率/抖动）；"序号" = 框架侧累计计数。
- **不写入数据单元**（保持 §5.4.2 第一条的解耦意图：下游不知道数据源身份、且无每单元构造开销）。
- 模块若要"采集时刻/序号" ⇒ **自行在契约里声明**（原裁决不变）；框架可另记**接收时刻**用于自身统计。

### D6. 兼容三层判据

| 情形 | 判定 |
|---|---|
| 同标识 + 同版本 | **兼容** |
| 同标识 + 不同版本 | ~~按版本规则（**尾部增字段 = 兼容**；改类型/删字段 = 不兼容）~~ **【ADR-0051 作废】不同版本 ⇒ 不兼容**（版本升级按破坏性变更处理：请两侧同版本或插入转换模块） |
| 不同标识 + 结构相同 | 框架**无资格**判定"是否同一种量"（不懂量纲）⇒ **默认不兼容 + 用户显式确认后可强连** |

**不自动转换**（PQ-IF-05 不变）：转换 = 用户显式插入转换模块。

### D7. 批量：**由类型声明**（定长数组）

- 不做框架自动合并（会改变时序语义、难以调试）。

### D8. 计量口径（**四档速率 + 三类丢弃**）

**问题**（用户第二十轮）：自描述字段进契约后，"实际数据速率"与"框架传输速率"会不一致 —— 核实出**6 处口径差**：

| # | 口径差 | 证据 |
|---|---|---|
| ① | **多播放大**：1 单元投给 N 宿各记一次投递 ⇒ "投递单元数"实为**按宿计的投递次数** | `Deliver`：`foreach target → RecordDelivered()` |
| ② | **停流被记成"丢弃"**：`IsSuspended / IsStalled / 载荷过短 / 无承载 / 队列满` 全部 `RecordDropped()` | `ModuleRuntime.Deliver` 781–792 |
| ③ | **自描述与对齐开销**：`{seq:u64,value:f32}` = 12 B 而业务 4 B | 参考模块契约 |
| ④ | **单元 ≠ 样本**（批量/通道） | D3/D7/Q5 |
| ⑤ | **模块内部丢弃不进账**（`Publish` 口径 `Written/Overwritten/Dropped` 与网络口径不合并） | `SubscriptionSourceView` |
| ⑥ | **速率是 UI 差分估算**（无时间戳） | `ModuleViewViewModel._rateSamples` |

**做法**：类型/端口声明新增**计量块**（全可选、缺省有定义）：

| 字段 | 含义 | 缺省 |
|---|---|---|
| `PayloadSizeInBytes` | 单元中**业务数据**字节数 | = 契约尺寸 |
| `SamplesPerUnit` | 每单元样本数（批量） | 1 |
| `ChannelCount` | 通道数（与 Q5 数组语义**合并定义**） | 1 |
| `NominalRateHz` | **标称**速率（对照用） | 空 |

框架机械给出**四档速率**：**单元速率**（按源计）/ **搬运字节速率**（含自描述与填充；按宿计）/ **有效载荷字节速率**（业务）/ **样本·通道样本速率**。

**丢弃拆三类**：**停流未投递**（合法状态）/ **传输丢弃**（队列满、无承载、载荷非法）/ **模块内部丢弃**（模块上报或并入数据源口径）。

**两条纪律**：
1. **UI 只显示有定义的口径**；`_rateSamples` 之类**差分估算退休**；
2. **不做"实际 vs 框架"的单数字对比**；**是否掉速 = 实测 vs `NominalRateHz`**。

## 4. 层表（管什么 / 不管什么 / 必须携带 / 谁声明 / 谁校验 / 允许的解析）

| 层 | 管什么 | 不管什么 | 必须携带 | 谁声明 | 谁校验 | 允许的解析 |
|---|---|---|---|---|---|---|
| **传输 / 数据面** | 能不能传：尺寸完备性 + 投递 + 顺序 + 背压 + 丢弃 + 缓冲 | 数据"是什么" | **类型标识 + 版本 + 尺寸 + 传输语义 + 兼容声明** | 模块 | 框架（机械：长度/尺寸/兼容） | 仅①② |
