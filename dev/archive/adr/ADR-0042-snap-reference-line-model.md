# ADR-0042：吸附候选统一为「参照线」模型（+ Visio 式手感参数）

> **状态**：**Accepted（2026-09 · 用户裁决"通过，按 ADR 开始重构"+ "边缘对齐保留最低优先级"）· 步骤 2 已实现，步骤 3 待做**

## 1. 背景与问题

用户第十二轮连续三轮反馈同一个症状，最终收敛为一句准确的描述：

> "两个窗口靠得很近时**中线对齐才会抖**，距离远一点就不会抖。"

自检（真实窗口 + 真实 125% DPI，`architecture/15` §7）拿到的逐帧事实：

| 步骤 | 指针 | 模块 | 滞后 | 说明 |
|---|---|---|---|---|
| 20 | 308 | **315** | −7 | 吸上（跳到对齐位置） |
| 21–25 | 312→328 | **315 不动** | +1 → **+13** | 带内不跟手（指针走了 24px） |
| 26 | 332 | **332** | 0 | 出带：**一次跳 +17px** |

**根因是"硬吸附"这一模型的固有形状**：每帧 `模块位置 = f(指针位置)` 是一个**阶梯函数**

```
若 |raw − C| ≤ T（C = 某条对齐成立的坐标，T = 容差）→ 模块 = C     ← 带内不跟手
否则                                              → 模块 = raw   ← 出带跳变
```

- **带内不跟手** = 用户说的"打架"；**跨带跳变** = 用户说的"跳"；**1px 手抖在带内来回** = "抖"。
- 阶梯宽度 = `2T`（当时 T=8、释放带 16 ⇒ 宽 32px），于是"指针走 24px 不动、然后跳 17px"。
- **"靠得近才抖"** 的原因：远处没有候选 → 阶梯不存在 → 一路跟手；靠近时同一轴上**同时有多个候选挤在几像素内**（贴合 / 中心线 / 左右边对齐 / 外壳参考线），阶梯变密变矮 ⇒ 指针一动就换一级。

**结论：抖动不是某条判据写错，而是"多个候选互相抢 + 阶梯太宽"共同造成的。** 用户据此提出一个关键简化：

> "左右边对齐、外壳参考线是否构成重复判断？能否只依赖一个判据（模块外框）？网络标签吸咐应当作为锚定在外框中的一个吸附点。"

## 2. 现状核查（用户的判断成立，但要点分两半）

**① 外壳参考线与"左右边对齐"：不是两套判据，是同一判据作用在不同对象上。**

两者的数学形式相同（把模块的某条边对到某条竖线/横线上）。外壳之所以单独走 `SnapReferenceLine` 通道，是**实现限制**：零宽矩形会被 `CanvasRect.IsValid`（要求正尺寸）过滤掉（P25），所以"只暴露一条边的对象"没法用矩形表达。**它是实现补丁，不是第二套语义。**

**② 真正"重复登记"的是端口锚点与模块中心线。**

默认参考模块（发送器 1 个口、显示器 1 个口）的端口都在边正中（偏移 **0.5**），于是端口中心对齐的坐标 = 模块中心线的坐标 ⇒ **同一件事被登记了两次**（只有级别不同）。单口模块下两者同坐标、看不出问题；**多口模块或手工调过锚点后两者会分开几像素**，就进入"互相抢"的状态。

**③ 另有一处启发式隐患**：端口候选的"对齐轴"目前是靠**比较两个方向的缝隙大小**猜出来的（`horizontalGap ≤ verticalGap`）。缝隙一比大小，方向就会在 1px 抖动下翻转 ⇒ 候选在 X/Y 两轴之间跳 —— 与"靠近才抖"直接相关。

## 3. 决策

### D1. 唯一判据：一切吸附 = 把「模块外框的某个锚点」吸到「某条参照线」上

- **被拖模块提供的锚点**（纯几何，全部来自外框）：
  - X 轴锚点：`左边缘(0)` · `中心(0.5)` · `右边缘(1)` · 外加**它自己每个端口的归一化位置**（上/下边的口）；
  - Y 轴锚点：`上边缘(0)` · `中心(0.5)` · `下边缘(1)` · 外加**它自己每个端口的归一化位置**（左/右边的口）。
- **参照线**（竖线约束 X、横线约束 Y）= `(轴, 坐标, 区间, 类别, 归属矩形?)`。

### D2. 参照线只有两个来源（外壳不再是特例）

| 来源 | 提供什么 | 类别 |
|---|---|---|
| **其他模块的外框** | 4 条边（左/右/上/下）+ **1 条中心线** | `FrameEdge` / `FrameCenter` |
| **其他模块的端口** | 每个口一条线，**轴由它所在的边决定**：左/右边的口 → 横线（约束 Y）；上/下边的口 → 竖线（约束 X） | `PortAnchor` |
| **外壳** | **只有右边缘一条竖线**（ADR-0038 D5 / 用户裁决 D-2 不变） | `ShellEdge` |

> 零宽对象（外壳）只是"**只暴露一条边的对象**"，与模块进同一张线表；`SnapReferenceLine` 保留为"线的载体"，但**不再是一条特殊通道**。

### D3. 候选的级别由「线类别 + 交叉轴条件」派生（不再另写判断）

| 级别 | 成立条件 |
|---|---|
| **贴合 `Flush`（最高）** | 线是**别的对象的外框边（或外壳边）**，且**模块朝外的那条边**落在线上（即结果上两者相接），且两对象在**交叉轴上有重叠** |
| **端口锚点 `PortCenter`** | 吸到某个口的锚点（"要插上了"）；两模块在**交叉轴方向接近**（沿用 24px 接近范围） |
| **中心线 `ModuleCenter`** | 吸到对方外框中心线（只用模块的中心锚点） |
| **边缘对齐 `Edge`（最低）** | 吸到别的对象的边/外壳边，但**交叉轴无重叠**（跨屏对齐的正当用途） |

**同轴、位置相同（≤1px）的多条候选只保留级别最高的**（消除 D-2② 的重复登记；例如"端口在 0.5"与"模块中心线"）。

### D4. 端口锚点的轴由「它在外框的哪条边」确定（**取消按缝隙大小猜方向**）

- 左/右边上的口 → 只参与 **Y** 对齐（左右相邻时"插上"要看高度对齐）；
- 上/下边上的口 → 只参与 **X** 对齐。
- 接近范围（24px）也按**邻接方向的法向**判定（左右相邻看横向间隙、上下相邻看纵向间隙），不再做两轴比较。

> 用户裁决：**按所在边定轴**。这条同时删掉了"缝隙一比大小就翻方向"的隐患。

### D5. 交互模型：**保持拖动中实时吸附**（Visio 式），不做"松手吸附"

用户已否决"松手吸附"（操作不友好）。目标手感 = **Visio**：吸附半径小、离开即松、靠参考线给反馈。

### D6. A+ 参数（**在 D1–D4 重构完成后落地**）

- 新增设置项 **「吸附距离」**（`snapDistance`，默认 **4**，范围 **2–8** px）；
- **对齐类容差 = 吸附距离**；**贴合类容差 = 吸附距离 × 2**（默认 8）—— 一个旋钮，Visio 式；
- **取消额外"释放带"**：离开自己的容差带立刻跟手（最大滞后 = 一个容差）；
- **方向一致性规则**（压掉"回跳"）：换候选时，新位置在指针运动方向上**不得倒退**（`(new − old) × (raw − lastRaw) ≥ 0`）；否则保持当前候选，直到指针反向或离开容差带。该状态由**调用方（视图模型）持有**，引擎仍是纯函数。
- 已知并接受的边界：候选交接处的位置跳变**上界 = 2 × 容差**（默认 8px），由"吸附距离"设置直接控制；同坐标候选已被 D3 去重，所以"重复登记型"抖动归零。

### D7. 兼容性与影响面

| 项 | 影响 |
|---|---|
| `SnapEngine` 内部 | 候选收集与级别判定重写（D1–D4）；`Snap` 仍是**纯函数**，参数由「容差 + 接近范围」变为「吸附距离 + 贴合系数（=2） + 接近范围」 |
| `Ui` 侧 | `ModuleWindowsViewModel`：候选来源由"矩形 + 端口对 + 参照线"三路改为"**线表**"一路；方向一致性状态留在 VM |
| 端口几何来源 | 需拿到"口在哪条边"——`PortView` 已按边渲染（`PortMarkerPanel` 边感知），实现时若公开面缺该信息，按 **ADR-0035 的兼容扩展口径**（只增不改）登记 |
| 外壳 | 语义不变（仍只有右边缘），仅从"特殊通道"变成"线表里的一条线" |
| 组合件/布局格式 | **不变**（仍为绝对屏幕像素整数） |
| 测试 | `SnapEngineTests` 增补"线模型 + 去重 + 按边定轴"用例；`SnapStabilityTests` 的**上界断言收紧到 `2×吸附距离`** |

## 4. 理由

1. **重复登记是抖动的结构性来源**：把候选统一成"线"，同一坐标上的多条线自然合并成一条（取最高级别），这一类互抢从结构上消失。
2. **取消启发式**：端口对齐的轴由端口的边决定是**定义**，不是猜测；不再有"缝隙大小翻转方向"的不确定行为。
3. **外壳不该是特例**：它只是"只暴露一条边的对象"，进同一张线表后，将来要加"参考线/标尺/分组框吸附"只需产线。
4. **手感靠参数与反馈，不靠更聪明的算法**：Visio 的顺手来自"小半径 + 离开即松 + 可见参考线"；A+ 参数把阶梯宽度从 32px 收到 8px，并给出用户可调的旋钮。

## 5. 不做

- **不做"松手吸附"**（已否决，备案在 `architecture/15` §7.2 之前的实现记录里）；
- 不改**建网判定**（`DockRule` 的接触 ≤2px / 标记对齐 ≤12px 不动）；
- 不改布局/组合件**格式**；
- 不加"网格吸附"（ADR-0031 早已裁决不做）；
- 不引入第三方吸附库；
- 不改参考线的**视觉规范**（`09` 基线不变）。

### 7.5 外壳纳入「拼图图」（用户第四轮裁决）

**用户口径**："单侧吸附逻辑应当保留，但是只有完成吸附后，主窗口和模块形成了一个视觉整体，'移动它 = 整个现场一起平移'才生效。
这个逻辑在模块间似乎已经实现了，只是主窗口也要纳入类似的逻辑。"

**决策（D8）**：

| 项 | 内容 |
|---|---|
| **外壳是拼图里的一个节点** | 与模块之间**只有单侧吸附**（只提供右边缘 —— ADR-0038 D5 不变）；模块贴上去即"拼上"，二者同属一个**接触连通分量** |
| **成组谓词** | 模块↔模块沿用 `AreJoined`；**模块↔外壳只认"左边缘贴外壳右边缘 + 竖向重叠"**（不允许贴外壳的左/上/下边） |
| **移动外壳 → 平移该组** | `TranslateShellGroup(dx, dy, preMoveShell)`；**没拼上的模块留在原处**；容器锁定成员（钉住） |
| **拖动组内模块 → 外壳一起走** | 拖动组含 `ShellNodeId` 时触发 `ShellTranslationRequested`，外壳窗口随组平移；`CancelDrag` 取反还原；`OnShellMoved` 在交互期间只刷新参照（防双重位移自激） |
| **判定用移动前几何** | 分组必须用**移动前**的外壳矩形（`preMoveShell`）——否则"贴上了"被判成"没贴上"（与 P33 同类，本次由测试抓到） |
| **落盘** | 只改内存 + 180ms 防抖合并提交；`SyncModules` **跳过未落盘的成员**（否则被 60Hz 刷新拉回，表现为"模块跟不动" —— P36） |
| **作废** | 本轮中途试过的"外壳 = 应用的框架 → 所有模块无条件跟随"（不符合"拼装"直觉：没吸附上的模块不该被拖走） |
