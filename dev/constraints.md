# 代码与架构约束

> 本文件是代码风格、架构规则与架构例外的唯一清单，不对外发布。规则违反即失败；需要豁免时按文末登记。

## 工程基线

| 项 | 现行 |
|---|---|
| SDK | 版本由仓库根 `global.json` 固定；目标框架 `net10.0`；需要 PowerShell 7 及以上 |
| 语言 | 可空引用与隐式 using 开启；语言版本取最新 |
| 警告 | 警告视为错误；静态分析级别取推荐集；局部压制必须在项目文件注明原因 |
| 分析器 | 只使用内置 .NET 分析器，不引入第三方风格分析器 |
| 依赖版本 | 中央包管理，全部版本锁在 `Directory.Packages.props` |
| 风格 | `.editorconfig` 随仓库提供，不依赖全局设置 |

## 命名与文件

| 项 | 约定 |
|---|---|
| 命名 | 类型与成员用 PascalCase；私有字段用 `_camelCase`；接口加 `I` 前缀；异步方法加 `Async` 后缀；常量用 PascalCase；不使用无意义缩写 |
| 文件 | 一个文件一个公共类型，文件名等于类型名；使用文件作用域命名空间；命名空间与目录结构一致 |
| 注释 | 中文；标识符与 API 名保持英文；只写"为什么"、不变量与已知坑，不写日期、决定编号、用户原话、实测读数与当前坐标尺寸 |
| XML 注释 | `Sdk` 面向模块作者的公共 API 必须写；框架内部成员按需 |
| 禁止 | `#region`、`async void`（事件处理除外）、吞异常、热路径线程睡眠、魔法数字 |

## 架构规则

规则以 `AR-n` 编号；编号即规则项的名字，出现在测试名与报告里。规则由独立的架构测试项目执行，该项目不引用任何产品项目，只读它们的产物。缺失的目标程序集视为失败，不跳过。

| 组 | 规则 |
|---|---|
| 项目清单 | AR-0：产品项目清单必须与七层结构一致（穷举，模块前缀除外） |
| 依赖（程序集引用） | AR-1 模块只引 `Sdk` / `Sdk.Ui` / `Sdk.AccessKit` · AR-2 模块不得互引 · AR-3 数据面不得反向依赖宿主 / 核心 / 界面 · AR-4 宿主只引契约与横切 · AR-5 核心的允许集合（并加强：允许引用界面框架的程序集只有 `Ui` / `FrameworkUi` / `App`） · AR-6 公开面只引契约 · AR-7 界面两级的允许集合 · AR-8 外壳层允许集合（含 `Sdk.Ui`，但只许 `loc:` 前缀引用它） · AR-9 契约零依赖 · AR-10 横切零依赖 · AR-11 唯一白名单是组合根 · AR-12 框架不得引用模块；`Access` 只允许被 `App` 引用 |
| 命名空间与词汇 | AR-13 核心 / 宿主 / 数据面不得出现具体业务词汇 · AR-14 命名空间须与项目名加目录一致 |
| 第三方 | AR-15 排除清单（诊断支持包、加速包、商业控件、中介者与对象映射库、断言与模拟库、日志门面等一律不得引用） |
| 公开面 | AR-16 公开签名不得出现框架内部类型 |
| 用户数据 | AR-17 用户数据路径只有一处来源（文件名只允许出现在路径解析器里） |
| 模块几何 | AR-18 模块尺寸与端口位置只能来自代码声明 |
| 注释 | AR-19 源码注释只承载"为什么 / 不变量 / 坑"，不得携带日期、决定编号、用户原话、实测读数与当前坐标 / 尺寸 / 像素值 |
| 界面唯一性 | AR-20 界面描述文件禁止复活（无 `view.json` / `view.schema.json`） · AR-21 `Sdk.Ui` 只许控件 / 契约 / 主题 · AR-22 模块 XAML 的绑定键只许 `{x:Static}` 常量 · AR-27 模块输入文本面必须在 XAML 显式声明 `TextFormat` |
| 模块计时 | AR-23 模块包不得自建 Timer / Thread.Sleep / DispatcherTimer / Task.Delay / 平台专有调度 API |
| 包边界 | AR-24 模块包不得含宿主提供程序集（`Sdk*` / `Sdk.Ui*` / `Sdk.AccessKit*` / `Access*` / Avalonia / 外部接入第三方依赖） · AR-25 外部接入面只搬原始字节（`Sdk.AccessKit` 不得出现数据类型 / 组帧 / 端口概念），数据类型声明只由模块自身在 `OnRegistered` 完成 |

执行方式：

- 依赖类规则同时按两条路径检查：程序集引用（覆盖间接依赖）与项目文件的引用项（覆盖"引了但暂时没用"）。
- 源码类规则按源码扫描。
- 用到的程序集按当前构建配置定位。
- `Access` 作为框架侧外部接入实现参与 AR-0 的项目清单；它只进入组合根的允许集合，其余项目引用即判红。
- 判定口径：框架程序集引用集不变、既有测试全绿、新模块功能测试通过；不做中间语言或二进制基线比对。

## 热路径纪律

数据单元的产生、传递、解析、缓冲与绑定，每单元代码路径：

| 禁止 | 替代 |
|---|---|
| LINQ | `for` / `foreach` 配合 `Span<T>` |
| 装箱与 `params object[]` | 泛型、结构体或重载 |
| 闭包捕获与委托分配 | 缓存委托、结构体回调或静态方法 |
| 热路径字符串拼接与插值 | `Span` 或 `StringBuilder` |
| 每单元 `new` 与 `byte[]` | 池化缓冲租还 |
| 异常作控制流 | 返回值或 Try 模式 |
| 每单元 `Task` 分配 | `ValueTask` |

## 常见陷阱

### 界面与控件

- XAML 警告不受"警告视为错误"约束，需要单独查看构建日志。
- 第三方控件自带模板不会自动生效：没有模板等于什么都不画，并且不报错。控件不出现时按"有没有模板、有没有尺寸、有没有被遮挡"的顺序排查。
- 资源类型错误只在运行时暴露；视图层需要有真实资源与真实窗口的用例。
- 资源查找顺序决定覆盖是否生效；覆盖要写在会被优先读到的那一层。
- 派生自按钮的开关类控件必须从按钮模板选择器中排除，否则会拿到按钮模板。
- 布尔控件只有两种滑块：宿主界面与模块视图各一种，不要在设置页重新引入复选框。
- 模板是一个命名域，同一模板内两个分支不得使用同名元素；需要被定位的元素用样式类。
- 自绘控件必须显式声明哪些属性变化会触发重绘，每个公开属性都要有消费者。
- 静态画刷与进入资源字典的画刷按跨线程共享处理，使用不可变实例。
- 失焦要提交：输入框在回车、显式动作或失焦时交值；不允许“改了输入框、点了别处却没提交”。
- 被拒绝的动作要撤销并遗忘，不跨帧保留。
- 提示分三层：短语直接显示，一句解释挂悬停提示，多句内容进帮助入口；同一内容不重复。
- 标题不放在控件内部：标签是独立元素，与编辑器各占自己的矩形。
- 模块文字只有一套：`ModuleLabel` / `ModuleNumeric` 都是 `TextBlock` 派生；模块视图里不用裸 `TextBlock` 显示文字，裸 `TextBlock` 只留给框架内部件（图表轴、提示、页签头等）。
- 控件不自带文字：开关只画轨道与圆钮，文字是独立 `ModuleLabel`，统一放在开关右侧；勾选框例外，文字走 `Content`，方框与文字间距固定 2 DIP，宽度按内容声明。
- 预览范围框：勾选框必须覆盖“方框 + 文字”整个控件矩形；14×14 方框只表达勾选态，不表达布局/命中区。
- 两段按钮（主体 + 箭头）只能有一个状态写入者：命中区与指示区都取实际模板部件的几何，不要让父按钮和子区同时响应 `:pointerover`；点箭头不得触发主体命令。
- 文字在标签矩形内的垂直对齐由 `ModuleTextElement.TextVerticalAlignment` 负责（默认居中）；不要用 `Padding` 或控件的 `VerticalAlignment` 代替——后者只决定控件在父容器里的位置。居中基准是**与字体无关的光学基线**（内容盒中心 + 0.35×字号），不是各字体的行盒半高；不要再按 `TextLayout.Height` 各自居中。
- 预览值/初值在 XAML 声明：可输入控件写初始值，只读控件写预览值；运行期数据覆盖。视图代码不写另一套预览默认值，设计环境不调 `Refresh`。
- 预览里运行期会隐藏的控件仍全显；它们与相邻控件重叠/遮挡是有意为之，不以预览遮挡判定布局缺陷，也不为预览改成 XAML 默认隐藏。
- **控件只绑值名，不碰后端**：可编辑控件用 `Value` + `CommitMode`，只经 `IModuleViewContext.ReadValue/CommitValue/RegisterViewDefault` 取/交值；不得直接读配置、读写视图状态、调用 `SubmitInput`/`UpdateField`，也不得自己解析/校验/生成字段错误。
- **值没有配置/输入分类**：`ValueDeclaration` 只有编辑器、可选项、`Persistent`、`ResetWithModule`；初值只在 XAML。模块用 `context.Values.ReadText/AcceptText/Report`，提交时机是控件属性（`OnChange`/`OnExplicit`），失焦提交。
- **一个值只有一个默认 owner：视图 XAML**。`ValueDeclaration` 不写默认值；XAML 初值由包加载器读取并在激活前播种，重置回到该初值。配置字段的 Schema 默认仍来自配置类型。
- 用 `StyleKeyOverride` 的派生控件，样式选择器要按 `StyleKey` 写（例如 `ComboBox.module-select`）；否则样式静默不命中，默认值会变成隐藏的下限。
- 文本装不下要显式声明截断与悬停全文，不硬切。
- 单位是文本，不是控件概念；不要给控件增加单位槽。
- 坐标归视图且只有一个主人：每个元素一条矩形，坐标内联在模块的视图文件里，模块之间不共享坐标常量。
- 可取消的事件不得挂不可逆的副作用；真正的收尾只挂退出事件，并用一次性闸门保证只执行一次。
- 退出只有一个出口，主窗口只做"取消与请求"，其余收尾集中在协调器里。
- 先拆视图再关窗口会留下空壳；视图摘除只挂在窗口关闭事件上，管理器记住已关闭的窗口。
- 输入控件的框与圈只画在一处，常态一像素、聚焦与报错用叠加圈且不改变边框厚度。
- 运行期只读不换控件，只停止编辑；声明只读或显示模式才换文本叶子。
- 框架不生成面向用户的句子：跨层只传事实，句子由看到它的那一层用自己的表生成。

### 几何与自绘

- 像素只在物理边界取整一次；窗口只做整数除以缩放。只由驱动者写模型。
- 等分列之间必须留间距，相邻 1 DIP 边框不得共边；列宽只做一次除法，右侧余量要覆盖布局取整的最坏外扩，避免末列边框被窗口边缘裁掉。
- 量化边而不是分别量化位置与尺寸，避免拼接处出现像素缝。
- 判定使用事件发生前的几何，并作为显式参数传入；不要拿被移动的对象当输入基准。
- 几何函数要么全用世界坐标、要么全用局部坐标，跨窗一律经显式换算函数。
- 相对尺寸是错位之源：两端拼接的尺寸必须来自同一个变量。
- 留白是几何参数，先算最坏情况的实际长度；极窄尺寸要有退化策略。
- 贴边绘制会被裁剪吃掉；可见性判据与绘制内缩要一起改。

### 数据与模型

- 身份由框架给出；显示名可空可重复，永远不能当键。
- 高频刷新路径不抛异常，宁可少显示。
- 可由集合推导的状态一律派生，不另存。
- 用相等判断"有没有变"之前，先确认被比的对象携带了那个差异。
- 值语义类型包含集合或数组时，默认相等不可靠，需要时自己实现比较并配用例。
- 值类型从集合取出后是只读副本，改动必须写回。
- 新增公开面字段的同一笔改动里写完生产者与消费者，断言来源与一致性而不是具体值。
- 建议不能混进问题清单；自家正确样例上报警的检查先怀疑检查本身。
- 观测型指标必须可重复读，区分事件与观测。
- 查不到不等于数值为零；两套看起来都像键的标识是静默归零的高发现场。
- 指标来源唯一要落到只有一个写入点；删第二来源时检查它是否还承担刷新时机。
- 周期性刷新不要重建正在交互的集合，列表走增量同步，行模型用值语义记录。

### 契约与持久化

- 给公开构造器或记录加可选参数等于改签名，属于二进制破坏；SDK 新增可选声明用 `init` 属性。
- 改 SDK 后必须重编全部模块。
- 本地格式不做迁移：读得动就用，读不动就拒绝或取默认，不写版本分支与旧字段兼容读。
- 模块配置走序列化时显式允许命名浮点字面量与字符串枚举。
- 配置"读即登记"：首次读取登记默认值，否则保存组合件时整块配置会丢失。
- 值持久化由 `Persistent` / `ResetWithModule` 决定，不由控件或存储位置决定；视图状态只保存非值 UI 状态（页签、折叠、草稿、显示缓冲）。
- 一个成功或失败背后有性质不同的原因时，返回值用枚举而不是布尔。
- 查询路径不做文件系统访问，扫描时算一次并缓存。
- 只读的出厂内容不得住进可写根；"能不能写"是划分唯一标准。
- 投放是缺什么补什么：目标存在就不改，删了不复活靠投放记录。
- 主题是设置的子项，壁纸跟着主题走。
- 构建不往用户目录写：构建产物只有资源与模块包。

### 界面文本

- 文本是文件，不编译进 DLL；代码与界面文件里新增中文会被审计拦截。
- 键按界面区域分段命名，同一区域的键聚在一起并保持排序；占位符只用编号形式。
- 缺表要报、缺键要可见；不允许把缺表静默成空白。
- 豁免必须写理由，新增一条豁免等于增加一条待复核项。
- 两类读者两种写法：给用户看的只写"做什么、结果怎样"；给排障者看的写"动作、原因、关键值"。
- 能生成的不写死：数量、路径、当前快捷键从数据生成。
- 测试不得以文案为判据，断言键与结构。

### 流程

- 同一语义写两遍必然分叉，抽成唯一实现。
- 同类交互出现第二遍就抽公共件，抽的时候删除旧路径。
- 修一处后全仓搜索同款写法。
- 死开关比崩溃更糟：每个可交互控件都必须有真实落点。
- 捷径与缓存必须能回答"读错了会怎样"，答案是"只慢不错"才可以加。
- 设计意图只能声明，不能从结构反推；派生只适合能被结构唯一确定的东西。
- 依赖渲染引擎语义的东西先写可测量的探针；定位完删除，只有机制不变量才转正为断言。

### 资源与图标

- 图标是显式 SVG：框架图标与模块图标各有目录与清单文件，通过图标目录取用。
- 框架资源与模块资源是两套根，互不回退；模块不新增框架资源类型。
- 类型选择器是精确匹配：模块控件与外壳控件的样式必须写具体类型。

## 测试面

- 测试只做两件事：能看见处的**行为**自动化（点→生效、发送→到达、标签→建网、退出顺序）与看不见处的补充（数据面与账本、并发、生命周期、缓冲借还、几何与量化不变量、持久化与格式、契约与声明、路径、架构规则）。
- **只有共性 / 全局机制（不变量）配常驻用例**：它失败时，人能说出一句"用户会看到什么坏结果"，且这个后果不是某个控件、某次事故、某个数值的样子。
- **呈现不写断言**：布局、尺寸、颜色、文案、控件树形状、窗口位置、像素由 `artifacts\snapshots\` 截图 + 人眼验收；截图工具不是测试、不进自动化门禁，且**方法体内不留断言**（红了也不算判据）。
- **一次性缺陷不入常驻面**：判据是"能不能再复发"。与特定控件、特定事故现象、特定实测读数绑定的缺陷，修好即删；注释里的"回归网 / 被钉住的缺陷 / 当年炸过"不构成保留理由。根因是结构问题的，用设计消灭（改约束、改接口、改唯一来源），不新写用例，也不另立台账。
- **交付物式测试不写**：只验证"控件存在 / 字段被赋值 / 枚举映射 / 资源名清单 / 声明逐模块罗列"而说不出失败后果的，删；同类逐项罗列合并为一条 `[Theory]`。
- **同一事实只保留最靠外一处**：下层重复删掉；下层用例只在定位 bug 时临时加，定位完即删。模块测试不测 `Sdk` / `Sdk.Ui` 的纯函数（那是主测试的家）。
- **三类不进门禁**：`Category=Pressure`（压力）、`Category=Perf`（性能测量）、截图工具；门禁用 `-IncludePressure` / `-IncludeSnapshots` 按需打开。压力 / 性能用例是开发期临时件：功能收尾即删。
- **探针只活在截图工程**：依赖渲染引擎语义的读数先写成截图工程里的探针；定位完删除，只有机制不变量才转正为断言，且转正后必须搬出截图工程。
- **0 用例即失败**：过滤词未匹配到任何用例时，门禁与单项目入口都必须失败，不得报绿。
- **用例预算**（唯一登记处，含 `[Fact]` / `[Theory]` 行）：主测试项目 451（其中 Pressure 12 / Perf 1 不进门禁）、模块测试 165、参考测试 16；架构、包校验、资源审计属规则型检查，不受条数限制。超预算新增一条 ⇒ 先删一条，或写明它替掉了哪一条的覆盖。
- 断言对象是来源 / 一致性 / 结构 / 边界；用户可改的文案、尺寸、颜色、资源名、字体实测读数不作判据。

## 架构例外登记

本文件是架构例外的唯一登记处。代码里的 `// ARCH-EXCEPTION: <原因> · <复查条件>` 只是索引，不构成登记。

登记规则：

1. 代码注释写 `// ARCH-EXCEPTION: <原因> · <复查条件>`，并在本表追加一行。
2. 追加式：不删行。例外失效时把状态改为"已关闭（日期）"并写清关闭原因。
3. 每个里程碑收尾复查一次：过期的例外必须关闭或续期。
4. 单人项目由开发者自行登记，但必须在提交前完成。
5. "临时"不是原因。写清为什么现在必须例外、什么条件下能撤销。
