# AttitudeView 视角交互能力扩展：需求评估与实现方案

> 状态：**评估稿（待裁决，未生效）**。本稿不是现行设计的事实源；裁决通过后，结论并入
> [`channel-display-modules.md`](channel-display-modules.md) 与 `docs/zh/`，本稿删除或归档。
>
> 现行口径来源：`src/Sdk.Ui/Controls/AttitudeView.cs`、`src/Modules/Business/AttitudeDisplay/`、
> [`docs/zh/module-dev/controls.md`](../../docs/zh/module-dev/controls.md)、
> [`docs/zh/guides/modules/attitude-display.md`](../../docs/zh/guides/modules/attitude-display.md)。

## 0. 结论摘要

- **可行，且不需要引入任何第三方 3D / 图表库**：现有 `AttitudeView` 已经是纯自绘的透视投影，
  把"世界 → 屏幕"拆成"相机基向量 + 透视"即可加入轨道视角；默认视角下新公式与今天逐点等价。
- **全部能力落在控件内部**：左键拖动、左上角按钮、七视角面板、左下角地面参考轴都由 `AttitudeView`
  自己绘制与命中；模块视图 XAML、模块设置、`meta` 快照、模块事件都不改。
- **没有新增色板 token**：只新增两个画刷属性，默认值取既有主题 token；不写死色值。
- **真正的成本不在 3D 数学，而在交互口径**：空格的作用域、视角是否持久化、七视角相对世界还是相对机体、
  自绘面板的命中与退化。这些是本稿第 2 节要裁决的内容。

**需求解释**：参考图是"七个立方体图标按钮"的观感（每个图标以高亮面表示目标视角），
本方案按这个解释做 **7 个预设视角的紧凑面板**，不是 SW 中那个可拖拽旋转的单体 ViewCube 控件。
如果实际要的是后者（一个 3D 立方体上点面/点角/拖拽），方案会更大，需另立一项。

## 1. 需求拆解与现状

### 1.1 需求拆解

| 编号 | 需求 | 人可观察的完成形态 |
|---|---|---|
| R1 | 鼠标左键拖动调整视角 | 在姿态区空白处按住左键拖动，场景绕目标连续旋转；R/P/Y 读数与机体姿态不变；模块窗口不移动 |
| R2 | 左上角视角调整按钮 | 姿态区左上角有一个立方体图标按钮；悬停有反馈；点击可开合视角面板 |
| R3 | 空格或按钮弹出七种视角 | 弹出紧凑面板，含前/后/左/右/上/下/等轴测七个带立方体图标的项；选中后视角立即切换；Esc/再点按钮/点面板外可收起 |
| R4 | 控件自身能力，不做模块耦合 | 模块视图不新增按钮/事件；模块不读写相机状态；相机不进入设置与 `meta`；换一个模块用 `AttitudeView` 也自动具备同样能力 |
| R5 | 左下角地面坐标系参考轴 | 一个固定像素大小的三轴小坐标架，随当前视角旋转；颜色与机体轴一致；轴标签可读 |

### 1.2 现状核查（事实）

| 事实 | 证据 | 对方案的含义 |
|---|---|---|
| 相机是"固定的中心 + 缩放 + 机体三轴旋转" | `AttitudeView.Camera`：只有 `centerX/centerY/scale` 与 roll/pitch/yaw 的正余弦；`Project` 做 `D/(D−z)` 透视 | 视角角度没有落点；需把"视角旋转"从"机体旋转"中拆出来 |
| 控件当前完全被动 | `AttitudeView` 只实现 `IModuleViewElement.Refresh`（推进平滑）与 `Render`；没有 `Focusable`、没有指针/键盘重写 | 交互、命中、焦点都是新增面 |
| 世界网格与相机被文档定义为固定 | [`controls.md`](../../docs/zh/module-dev/controls.md) "数据显示控件"末条；[`channel-display-modules.md`](channel-display-modules.md) §6 `AttitudeView` 行 | 裁决通过后必须同步改这两处，否则文档与行为相反 |
| 模块拥有"看起来像视角"的设置 | `settings.zoom`、`grid`、`labels`、`style` 由模块 `meta` 发布，视图每帧只读 | 新相机**不能**走这条通道，否则就是 R4 明确不要的模块耦合 |
| 主题已有整套画刷，但没有浮层用色 | `Themes/Controls.axaml` 的 `ui|AttitudeView` 设了网格/三轴/机体/文字；无面板底色与高亮色 | 需要两个画刷属性；可复用 `BgChrome`、`AccentPrimary`，不加 token |
| `Sdk.Ui` 文本表没有视角文案 | `resources/i18n/HYWDebugAssistant.Sdk.Ui/zh-Hans.json` 只有面板与文本菜单键 | 七视角名、按钮提示要进这张表；不能写中文到代码/模块 |
| 没有相机数学用例 | 现有测试只覆盖模块行为与模块视图截图；`AttitudeView` 的投影无测试 | 新的相机/布局必须是可独立测试的纯几何，不能只靠人眼 |
| 模块最小尺寸足够放下紧凑面板 | 视图根 `MinWidth=360`、`MinHeight=400`（含外框），内容区约 318×350，姿态区约 310×300 | 4×2、约 168×106 的面板在最小窗口下能完整显示；仍需显式退化策略 |

### 1.3 可行性判断

- 渲染：只增加旋转矩阵与二维绘制，沿用现有 `DrawingContext` / `FormattedText`，无新依赖。
- 输入：项目已有大量自绘控件（`ChartSurface`、`RangeSelector`、`GaugeDial`）的捕获、光标、命中先例；
  `AttitudeView` 从未参与命中，需新增 `Focusable`、指针捕获与键盘处理，但机制是框架现成的。
- 布局：面板是控件内浮层，不跨窗口，不需要 `ModulePopupPanel`，也不该用平台 `Popup`（项目已明确拒绝）。
- 风险集中点：空格焦点域、面板命中与拖动的手势分离、极端视角下三轴标签退化、文档同步。

## 3. 方案

### 3.1 边界与分层

```
AttitudeView（Sdk.Ui，自绘 Control）
├─ 相机：世界→相机基→透视；机体旋转保持不变
├─ 地面参考轴：相机基的二维投影（HUD）
├─ 视角按钮 / 七视角面板：控件内绘制 + 命中
└─ 输入：Focusable + 指针捕获 + Space/Esc

模块（AttitudeDisplay）
└─ 只继续发布 Roll/Pitch/Yaw、meta、status；不新增任何视角设置或事件
```

- **不引第三方**：无 3D 引擎、无图表库。
- **不新增色板 token**：面板/按钮用两个新画刷属性指向既有 token。
- **不新建控件**：七视角面板没有第二个消费者，先作为 `AttitudeView` 的内部几何/绘制；
  若将来第二个 3D 控件也要它，再抽公共件（同类交互出现第二遍的规则）。
- **不改模块**：模块视图 XAML、设置面板、`meta` schema、测试模块行为都不用动；模块截图会变，属预期。

### 3.2 相机模型（唯一的数学新增）

把当前 `Camera` 拆成两层：

1. **机体旋转**（沿用现顺序，逐点不变）：`Rz(roll) → Rx(pitch) → Ry(yaw)`。
2. **视角旋转**：偏航 `a`（绕世界 Y）、俯仰 `e`（绕相机右轴），再用现有透视投影。

相机基（从原点指向相机）：

```
c = ( cos(e)·sin(a),  sin(e),  cos(e)·cos(a) )   // 相机方向
r = ( cos(a),          0,      -sin(a)         )   // 屏幕右
u = ( -sin(e)·sin(a),  cos(e), -sin(e)·cos(a) )   // 屏幕上
```

对任意世界点 `p`：

```
screenX = centerX + scale · (p·r) · D/(D − p·c)
screenY = centerY − scale · (p·u) · D/(D − p·c)
depth   = p·c                                      // 画家排序用，越大越靠近观察者
```

- `scale = min(W,H)·0.30·Zoom`、`D = 4`，与现实现一致。
- **默认等价**：`a = e = 0` 时 `c=(0,0,1)`、`r=(1,0,0)`、`u=(0,1,0)`，公式退化为今天的
  `centerX + x·scale·D/(D−z)`、`centerY − y·scale·D/(D−z)`。默认视角不产生任何观感漂移。
- 机体的面排序用"机体旋转后再取 `p·c`"的深度；网格与地面轴只经过视角旋转。
- 角度用度存储、弧度计算；`e` 夹在 `[−90°, 90°]`，`a` 归一化到 `(−180°, 180°]`。
  在这个参数化里 `e=±90°` 不会退化（`r` 只依赖 `a`），所以顶/底视可以精确到 90°。
- **不做垂直滚转**：屏幕上保持地平线水平；这是"看模型的视角"，不是"相机翻滚"。
- **视角状态只有一个写入点**：初始化、拖动、预设都经 `SetView(a, e, preset)`；当前预设是它的入参，
  不在绘制或刷新里另算一遍。拖动通过它清空预设，预设项通过它写入角度。

七个预设（`a, e`）：

| 预设 | 偏航 `a` | 俯仰 `e` | 屏幕结果（前视为默认） |
|---|---|---|---|
| 前视 | 0° | 0° | +X 右、+Y 上、+Z 朝屏幕外（指向观察者） |
| 后视 | 180° | 0° | +X 左、+Y 上、+Z 朝屏幕内（背离观察者） |
| 左视 | −90° | 0° | 从 −X 看，+Z 右 |
| 右视 | 90° | 0° | 从 +X 看，+Z 左 |
| 上视 | 0° | 90° | +X 右、+Z 下、+Y 朝屏幕外（指向观察者） |
| 下视 | 0° | −90° | +X 右、+Z 上、+Y 朝屏幕内（背离观察者） |
| 等轴测 | 45° | 35.264°（atan(1/√2)） | 前/上/右三个面可见；SW 等轴测方向 |

### 3.3 交互

#### 3.3.1 手势状态

| 状态 | 进入 | 移动 | 释放 | 退出 |
|---|---|---|---|---|
| 空闲 | — | 更新悬停/光标 | — | — |
| 按住按钮 | 左键在按钮命中区按下 | 按钮按下观感 | 在按钮内 → 开合面板；在外 → 取消 | 捕获丢失 |
| 按住视角项 | 左键在面板项命中区按下 | 项按下观感 | 在同一项内 → 应用视角；在外 → 取消 | 捕获丢失 |
| 拖动视角 | 左键在空白场景按下 | 按起始点快照算新角度 | 结束拖动 | 捕获丢失 / 失去焦点 |

- **拖动用起始快照 + 总位移**，不用逐帧增量：`a = a0 − dx·0.5°`、`e = clamp(e0 + dy·0.5°, −90, 90)`。
  这样不会累积误差，也不会因为坐标取整产生漂移。
- `0.5°/DIP` 是初值；360 DIP 横拖 = 180°，以实际手感复核，不在文档里钉死。
- 拖动时清空"当前预设"（变为自定义），不改变机体角度、不改变 `Zoom`。
- 拖动中光标 `SizeAll`；按钮/项上光标 `Hand`；其他为默认。
- 指针捕获：按下即捕获，释放/捕获丢失复位；拖出控件仍连续。释放时**先按释放位置结算，再释放捕获**；
  捕获丢失只复位、不结算，避免把"被别的控件抢走捕获"误当成一次点击。
- **不拦截模块窗口拖动**：模块窗口只从边框带/外框启动拖动，内容区按下本来就不移动窗口；
  控件只在自己的命中区内处理，事件不冒泡到带。
- **不接管滚轮**：缩放仍由模块的 `Zoom` 设置拥有；本次不加"滚轮缩放"。

#### 3.3.2 焦点与键盘

- 构造时 `Focusable = true`、`IsTabStop = false`、`FocusAdorner = null`（不画整块虚线焦点框）。
- 任意左键按下先 `Focus()`；`OnLostFocus` 关闭面板（点齿轮、点别的窗口、点模块外都自然收起）；
  窗口隐藏/控件摘树时也关闭，避免重新显示时残留一个开着的面板。
- `Space`（无修饰键）：开合面板；仅在控件有焦点时生效；`Handled = true`。
  文本输入框里的空格仍是空格，按钮上的空格仍激活按钮——这是 D2 选择"焦点域"的直接结果。
- `Esc`：面板打开时关闭并 `Handled`；关闭时不动，交给其他层。
- 面板打开期间不做 Tab/方向键逐项导航；七个项是绘制命中区，不是可聚焦控件。这是 v1 的明确限制
  （见第 8 节），如需要键盘逐项选择，再单独加一个可聚焦的项模型。
- 按钮的"空格"可发现性：按钮悬停时在按钮右侧画一条一行提示（文案来自 `Sdk.Ui` 文本表），
  或退化为 `ToolTip`；最终形态由截图人眼定，不改变交互。

### 3.4 视角按钮与七视角面板

#### 3.4.1 按钮

- 控件本地坐标左上角，约 24×24 DIP，距左/上各 6 DIP；图标是等轴测线框立方体（12 条棱），
  不用图标资源、不引图标表。
- 三态：常态（透明底 + 淡边框 + 正文色图标）、悬停（主题色 10% 底 + 主题色边框）、
  打开/按下（主题色 18% 底 + 主题色边框）。三种态都不改图标颜色，避免深色主题下的对比度问题。
- 按钮不进入模块 XAML，不占模块布局；它只是控件绘制的一部分。

#### 3.4.2 面板

- 锚在按钮正下方，向左夹紧在控件内；面板是本控件内的浮层，**不是** `ModulePopupPanel` 的独立窗口，
  也不是平台 `Popup`。项目"不要用 Popup 或视图内浮层"的既有结论针对的是**设置面板要超出模块窗口**；
  这个七视角选择器是控件自身的一小块 UI，必须随控件移动、被控件裁剪，因此不能做成独立窗口。
- 4 列 × 2 行，每格约 36×36 DIP，格间距约 4，四周内边距约 6；下方一行名称（约 16 DIP）。
  目标整体约 168×104 DIP；具体值由截图微调，但必须满足"最小姿态区（约 310×300）内完整显示"。
- 每个格子画一个立方体图标：
  - 每个预设用固定的"三面可见"朝向，而不是正对：前/右从 (+X,+Y,+Z) 方向看，左从 (−X,+Y,+Z) 看，
    后从 (−X,+Y,−Z) 看，上/下分别从上方/下方偏前看，等轴测用 (+X,+Y,+Z) 的等轴方向；
  - 目标面（该预设看向的那个面）用主题高亮色填充；其余面用正文色极淡填充、细边；
  - 这样"前视"看到前/右/上三面、前脸高亮，"左视"看到左/前/上三面、左脸高亮，
    "上视"看到上/前/右三面、顶面高亮；等轴测项不染单个面（它不对应某一面）；
- 名称行显示**悬停项**的名称；没有悬停时显示当前预设的名称；拖动后显示"自定义视角"。
  名称走 `Sdk.Ui` 文本表，不写中文到代码。名称行高度按当前字体的实测高度 + 2 DIP 算，
  不写死像素；默认字号下约 16 DIP，面板总高随字体一起算。
- 选中态：当前预设的格子加淡色底 + 主题色边框；拖动后无格子选中。面板保持打开（D4b）。
- 命中顺序：面板内项 > 面板背景（吃掉）> 按钮 > 场景。面板外按下 = 关闭并吃掉这次按下，
  不启动拖动。
- 按钮/面板/格子的矩形只由 `AttitudeViewCube` 的同一个布局函数给出，**绘制与命中共用**，
  不在两处各算一份；面板尺寸随字体算，不写死像素。
- 退化：控件小于约 180×150 DIP 时，面板+按钮放不下；此时**不画按钮**（避免画一个点不开的死按钮），
  场景与地面轴照常。模块声明的最小尺寸远大于该阈值，正常使用不会触发。
- 面板打开时按帧重绘性能：立方体图标的几何按预设缓存（尺寸不变），名称文字每帧最多一条；
  不做每帧重建。面板关闭时不产生这些绘制。

### 3.5 左下角地面参考轴

- 2D HUD，画在控件左下角，距左/下约 10 DIP；轴长固定（约 20 DIP），**不随 `Zoom`、不随透视缩放**。
- 三轴取世界 +X/+Y/+Z，用相机基投影（不经过透视、不经过机体旋转）：

```
tip = center + R · (axis·r, −axis·u)
depth = axis·c
```

- 颜色沿用 `AxisXBrush/AxisYBrush/AxisZBrush`；标签 X/Y/Z 用 `TextBrush`，受 `ShowLabels` 控制。
- 先按 `depth` 从远到近画轴，再画标签，保证交叉处的覆盖关系正确。
- 指向屏幕内/外的轴：二维长度小于阈值（约 3 DIP）时，画成一个小圆环/圆点（朝观察者实心点、
  朝屏幕内空心环），标签放在固定偏移处，避免"一根零长度线 + 标签叠在原点"。
- 不画负半轴；不加背景板。若截图显示网格上对比度不足，再考虑极淡的描边光晕，不预先加。
- 轴标签与机体轴标签是两套位置，但共用同一组颜色与 `ShowLabels`；文档要写清"左下是世界系，
  中心是机体轴"。

### 3.6 绘制顺序、裁剪与退化

绘制顺序（从下到上）：

1. 地面网格（`ShowGrid`）
2. 机体三轴（原点）
3. 机体（轴/方块/无人机，按面深度排序）
4. 左下地面参考轴（HUD）
5. 视角按钮
6. 视角面板（仅打开时）

- 控件设 `ClipToBounds = true`：当前 `Zoom` 放大时网格理论上可以画到控件外，靠父级裁剪是偶然的；
  这次把"绘制范围 = 控件边界"变成控件自己的事实。面板也自然被裁在控件内。
- 控件 `Render` 现有的 `width < 40 || height < 40` 早退保留。
- 网格在相机低于地面（下视）时仍在机体之前绘制，作为背景参考；不做深度遮挡。若人眼认为
  "从下面看网格盖住机体"，再单独决定是否在下视时淡出/隐藏网格（B 类观感，不在本稿冻结）。

## 6. 验证与验收

### 6.1 自动化（只判机制，不判像素）

**纯几何（下列不变量合并进 3–4 个用例）**

1. **默认等价**：`a=e=0` 时，对若干采样点的新投影与旧公式逐点一致（含透视因子）。
2. **七预设的轴向**：每个预设下，世界 +X/+Y/+Z 的屏幕方向符合 3.2 表；轴对视时投影接近零；
   预设角度 → 预设匹配可往返。
3. **拖动不变量**：起始快照 + 位移得到角度；`e` 夹紧在 ±90；`a` 跨 ±180 不跳变；
   拖动后预设为空。
4. **布局与命中**：在约 310×300 下，按钮与面板、七个格子都在控件内且互不重叠；
   每格中心命中自己；面板外命中场景；小于退化阈值时不可打开。
5. **地面轴**：三个轴端在半径内；depth 排序与预期一致；轴对观察者时进入圆点/圆环分支。

**行为（建议至多 1 条）**

- 真实窗口 + 真实焦点：控件聚焦时 `Space` 开/关、`Esc` 关；失焦自动关。
  不模拟像素，不判面板形状。

## 7. 风险与边界

| 风险 | 触发 | 处理 |
|---|---|---|
| 空格被误解为全局 | 用户没点姿态区就按空格 | D2 已明确焦点域；按钮悬停提示/模块册说明"先点姿态区"；若用户坚持全局，再单独评估窗口级处理器 |
| 自绘按钮/格子点不到 | 控件被其他层盖住、命中区算错 | 面板/按钮先于场景命中；纯几何用例钉住格子矩形；`PointerFocusRelease` 不会把可聚焦的姿态区当空白 |
| 拖动与窗口拖动混淆 | 用户从内容区拖 | 模块窗口只从边框带启动拖动；内容区按下本来就只清选中；控件捕获后事件不冒泡 |
| 极端视角标签重叠 | 上/下视、轴对视 | 轴对视画圆点/圆环；标签固定偏移；七预设逐一截图人眼复核 |
| 网格从下方遮挡机体 | 下视 | 先按"背景参考"绘制；若人眼不接受，再单独裁决下视淡出（B 类） |
| 面板在很小控件里放不下 | 自定义宿主把控件压得很小 | 显式退化：小于约 180×150 不画按钮；模块声明的最小尺寸内不会触发 |
| 深色主题对比度 | 面板/高亮/图标 | 两个画刷都取主题 token；选中/悬停只改底色透明度，不改图标色；深色截图复核 |
| 高 DPI 线条模糊 | 1px 线在 150%/200% 缩放 | 沿用现有 1px 画法，不做像素断言；必要时按 DPI 对齐（不在本次先做） |
| 每帧重建图标 | 面板打开 + 数据 50 Hz | 立方体几何按预设缓存；名称文字每帧最多一条；关闭时不绘制 |
| 视角持久化预期落空 | 用户重开/重启后期望保留 | D3 明确不持久化并写进模块册；将来要持久化就走模块显式状态，不让控件偷写 |
| 测试预算 | 主测试项目计数已高 | 进入实现前确认放宽或指定替掉的旧用例 |
| 无键盘逐项导航 | 只用键盘的用户 | v1 明确限制：只能 Space 开、Esc 关，项用鼠标点；后续可加可聚焦项模型 |
| 文档与行为相反 | 旧文档写"相机固定" | 裁决通过后同步改 `controls.md`、模块册与 `channel-display-modules.md`；本稿不先改生效文档 |
