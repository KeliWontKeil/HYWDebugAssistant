# 文档工作流（编辑 · 同步 · 归档 · 审计）

> 状态：**现行**（用户裁决：文档编辑/归档体系必须先成文，再按它一步步落文档）
> 定位：**本文件是"文档自己怎么管"的唯一落点** —— 一段内容**属于哪一类**（§0）、改文档时该同步哪些文件（§2）、失效内容搬到哪（§3）、审计门禁怎么跑（§4）、`【待裁】` 标记怎么收（§5）。
> 分工：**文档树、权威层级、按任务的阅读顺序** → 入口 `README.md`（不在此复制）；**这个系统是什么** → 主文档；**为什么这么定** → `decisions.md`；**具体怎么做** → `architecture/` 分册；**怎么写代码/怎么验** → `implementation/`；**到哪了** → `roadmap.md`；**过程材料（历史）** → `journal/`。

## 0. 内容分类协议（A–G：一段内容只允许有一个家）

> 任何一段内容，**先定类，再定落点**。同一件事实**只允许住在一个类里**；跨类搬运 = **搬家 + 原处留指针**（§1 原则 1 / 2 的操作化）。
> 判断顺序：① 这段内容回答的是"**应该是什么**"（A 类问题）还是"**已确定的东西怎么实现**"（B 类问题）——问题类型判据见 §5 末；② 它是**结论**还是**过程**？

| 类 | 回答什么 | 唯一落点 | 现行？ | 生命周期 |
|---|---|---|---|---|
| **A 生效规则** | 是什么 / 必须怎样 / 验收判据 | 主文档（基线结论）+ `architecture/` 分册（怎么做） | **现行** | 被取代 ⇒ **原地改写**，旧表述不留在现行路径 |
| **B 决策记录** | 为什么这么定 · 取代了谁 | `decisions.md`（**唯一登记处**；架构例外另见其 §3） | **现行** | 被取代的行**直接删**（用户裁决：允许删，避免记忆污染与冲突点），只保留现行条目 |
| **C 事实与数据** | 实测数值 / 取证 / 门禁基线 | 该量的**唯一**正文（视觉取值 → `architecture/07`、设置 → `architecture/08`、读数 → `roadmap.md` §6） | **现行** | 同一个量只允许**一个**现行取值；上一代取值必须带"当时"标记并只住在 E 类 |
| **D 进度与缺口** | 到哪了 / 还差什么 / 待裁项 | `roadmap.md`（状态唯一源；`【待裁】`/`【待评估】`/`【待细化】` 登记其 §3） | **现行** | 已完成项**搬出**正文（→ E 类）；正文不再保留"已完成"叙述 |
| **E 过程材料** | 改了什么 / 哪轮反馈 / 已收口条目 / 已执行流水 | `docs/journal/` | **非现行**（"历史，不作为依据"） | 只搬不删；**被取代的取值必须带"当时 / 已作废"标记**（否则与 C 类撞出"数值不唯一"，审计 §3 / §8） |
| **F 方法 / 技能** | 怎么做这件事（**可迁移**，与具体项目无关） | `.dsh/skills/`（由工具自动发现，不是给人常态阅读的参考文档） | **现行** | 不得含本项目专名（审计 §5）；项目事实一律回到 A–D 类 |
| **G 历史材料** | 被整体换版 / 退役的旧载体 | `docs/archive/` | **非现行** | **不再作为依据**；头部加 `⚠ 历史材料` + 现行锚点；**失效载体允许删除**（用户 2026-10 裁定「从宽删」）—— 删除前确认无现行引用，删除后登记 `archive/DELETED-<年-月>.md` |

**三条判据（先分类，再动手）**：

1. **一段内容只属于一类**：若同时像两类 ⇒ **拆开分放**（例：一个数值的"现行值"属 C、"当时取值"属 E；一个决定的"结论"属 A、"为什么"属 B）；
2. **现行路径只允许 A–D 与 F**：`journal/`（E）与 `archive/`（G）出现在现行文档里只能是**指针**，不能是内容副本；
3. **搬家单向**：A–D 里的失效内容往 E / G 搬（§3），**E / G 的内容永不搬回现行路径** —— 要复用就把有效部分**重写**进 A / B / C。

## 1. 三条总原则（其余条文都由它们推出）

| # | 原则 | 可执行判据 |
|---|---|---|
| 1 | **单一事实源** | 随机抽 3 条结论问"它在几处被定义？"—— 答案必须是 **1**；其余位置只留**指针** |
| 2 | **失效信息搬家，不与生效结论共存** | 被取代的写法**移出**现行路径 —— 旧设计/旧分册进 `archive/`，**过程材料进 `journal/`**；加"⚠ 历史材料 + 现行锚点"；**绝不并排留着"作对照"** |
| 3 | **绝不丢失有效信息** | 删/合并前确认内容在别处有承载；"只此一处且有指导意义"的（实测数值、边界条件、被否决方案的理由）**必须留下** |

**反模式（出现即打回）**：双份维护同一事实；为兼容旧结构新增"跳转壳"文档或空壳层；只在文档里约定的关键约束（没有可执行检查）。

## 2. 改动 → 回写落点（**一次裁决只落两处**）

> 回写的目标是**让后来者能找到生效口径**，不是把过程留档。**每批次回写一次**，在批次收尾时做；进行中不写文档、不写注释。
> 判据：问「**它替代了什么**」「**哪些下游表述必须同步改**」；只答得出前者的，通常追加一条即可，不必扩散。

| 改动类型 | 回写落点 |
|---|---|
| **一条设计决定**（口径 / 语义 / 结构变化） | ① `decisions.md` **一条**（决定了什么 + 为什么 + 取代了谁）② **受影响的唯一一个**正文（相关分册 / 模块页）—— 其余位置**只留指针**（引决定编号，不复述） |
| **一个取值 / 声明键 / 默认值** | 该取值所属的**唯一**正文（视觉 → `architecture/07`；设置 → `architecture/08`；模块声明面 → `architecture/02`） |
| **进度 / 缺口 / 待裁项** | 只在 `roadmap.md`（状态一行 + 一句引用）；**其余文档不写进度** |
| **实测读数 / 门禁基线** | 只在 `roadmap.md` §6 事实记录维护，别处引用它 |
| **新增 / 移动 / 删除文档文件** | `README.md` §1 文档树 + `docs/tools/audit-docs.ps1` 的 `$expected` 清单 |
| **改本文件的规则** | 用户裁决 + 本文件 |
| **例外豁免** | 代码注释 `// ARCH-EXCEPTION: <原因> · <复查条件>` **并**登记 `decisions.md` §3（**唯一登记处**，追加式） |

**明确不写进任何文档**（旧表把下面这些也算作"必须同步"，是回写无限膨胀的根源）：

- **过程叙述**：谁先提议、讨论了几轮、怎么被否掉的；只有"**被否决方案及其理由**"值得留，且只留一条；
- **评审对话、逐条追问、时间线、任务分解**；
- **测试读数、门禁统计、跑了哪一层**；
- **实现细节**：类名、方法名、行号、字段名 —— 正文只写"现在是什么样"，不讲"代码里怎么写的"；
- **注释不是回写目标**：代码注释只写"为什么 / 不变量 / 坑"，指向文档的指针每个文件最多一条（`.dsh/skills/human-ai-collaborative-design-review` §4.5）。

**两条附注（勿丢）**：

- **数值唯一**：字号 / 尺寸 / 容差 / 阈值在现行文档里**只允许一个取值**；两代值并存时必须**按显式取代标记取新值**，否则标 `【待裁】`。（跨册边界另见 `architecture/00-architecture-index.md` §1。）
- **状态只在一处**：进度与缺口只写在 `roadmap.md`；**分册不写进度**。

## 3. 归档规程

### 3.1 什么时候归档

| 触发 | 例 |
|---|---|
| **结论被取代** | 基线作废、口径改写（旧表述移出，不与新结论并排） |
| **里程碑收尾** | 手工验收清单冻结归档，下一里程碑**另起新文件**（不在同一文件上叠修订版） |
| **模块退役** | 模块从现役清单移出（**已发生一次**：`implementation/06` §G 的 6 个参考模块 —— **直接删除**而非归档；用户裁定与执行记录见 `journal/implementation06-g-archive.md` 与 `decisions.md` 7.36） |
| **文档体系换版** | 旧分册、ADR 原文、过程流水 |
| **过程材料积压** | 修订历史 / 逐轮反馈 / 已收口条目 / 已执行流水 —— **搬进 `journal/`**（搬家，不删除；现行结论只留指针） |
| **归档积压**（旧载体已被取代 / 无现行引用） | 评估后**删除**（不再"永不删除"），并把条目登记进 `archive/DELETED-<年-月>.md` —— 见 §3.3 第 5 条 |

### 3.2 搬到哪（**目录即语义**）

| 类别 | 位置 |
|---|---|
| ADR 原文 | `docs/archive/adr/`（**长期保留**：现行文档按编号引用它作论证原文） |
| 收敛前的旧分册 | `docs/archive/architecture/`（2026-10 已清理，见 `archive/DELETED-2026-10.md`） |
| 重写前的旧工程文档 | `docs/archive/implementation/`（2026-10 已清理） |
| 选型论证 | `docs/archive/technology-selection/`（2026-10 已清理；结论在 ADR 与现行分册） |
| **过程材料**（修订历史 · 逐轮反馈 · 已收口条目 · 已执行流水） | **`docs/journal/`**（本仓现行：`docs/journal/*.md`；历史材料，**不作为依据**；现行结论一律回到主文档 / `decisions.md` / 分册） |
| **退役模块的文档** | **`docs/archive/modules-<年-月>/`**（用户 2026-09 裁定；月份 = 归档执行月，便于按批追溯） |
| 其他过程流水 / 审计报告 | `docs/archive/<主题>-<年-月>/` |

> **2026-10 起：`archive/` 从宽清理**（用户裁定）—— 判据是"**现行文档是否按路径或编号引用它**"，不是"有没有历史价值"。保留：ADR 原文（54 份，被 `decisions.md` 按编号引用）· `adr/README.md`（ADR 一览表）· `superseded.md` · `docs-audit-2026-10-04.md` · 清理清单本身。删除：旧分册世代（22）· 旧工程文档（4）· 选型论证（6）· 收敛前根载体（6）· 过程流水与技能草稿（29）。清单见 `archive/DELETED-2026-10.md`（130 份 / 2.0 MB → 57 份 / 508 KB）。

### 3.3 归档动作清单（**搬家；无现行引用时可删**）

1. **移动**文件进上表位置（`git mv` 优先，保留历史）；
2. **加头部标记**（第一行）：
   `> ⚠ 历史材料（不作为依据）· 现行锚点：<指向现行文件的哪一节>`
3. **清理全部现行引用**：现行文档里指向它的 `docs/…` 路径要改成**指向现行锚点**——否则审计 §2「引用可达性」会报 `文件 → 路径`；
4. **两个登记处**：若它是模块 ⇒ `modules/README.md` 清单与 `roadmap.md` §5 状态同步；
5. **归档 ≠ 永久保存**：`archive/` 里的内容**永不再作为依据**；**失效载体允许删除**（用户 2026-10 裁定「从宽删」：旧分册世代 / 旧工程文档 / 选型论证 / 一次性过程流水 / 技能草稿都不保留）。删除前必须 ① 确认无现行文档按路径或编号引用；② 删除后把条目登记进 `archive/DELETED-<年-月>.md`（含 git 取回方法）；③ 重跑审计取绿。

> 归档前的**硬前置检查**（通用）：**被归档对象承载的判据/结论，是否已由新载体完全接管？** 答不上就不归档。
> （模块场景的具体清单见 `journal/implementation06-g-archive.md` 原 §G.3。）
> **`journal/` 不是审计豁免区**：`archive/`（历史材料区）不参与失效术语 / 数值唯一性 / 脆弱计数这三类检查，`journal/` 一样要过（含"引用可达 / 表格完整性"）。`journal/` 里**被取代的取值必须带"当时 / 已作废"等标记**（否则会与现行值撞出"数值不唯一"）。

## 4. 审计门禁（机械、只读、可执行）

### 4.1 命令

```powershell
pwsh -NoProfile -File .\docs\tools\audit-docs.ps1
```

### 4.2 它查八件事（任一未过会输出具体 `文件:行号`）

| # | 检查 | 失败含义 |
|---|---|---|
| 1 | **失效术语黑名单**（`快速建网` / `R0–R6` / `不建立数据流` / `形状子集` / `标题栏 24 px` 等；带"作废/历史/取代"标记的行允许） | 废止术语混进了现行正文 |
| 2 | **引用可达性**：现行文档里的 `docs/**.md` 必须存在；`ADR-00XX` 必须能在归档里找到（`ADR-0047` 按"从未产出"豁免） | 悬空引用 —— 通常 = 归档时忘了改引用（§3.3 第 3 步） |
| 3 | **数值唯一性抽查**（如遮罩不透明度）：**逐行**扫描，带"作废 / 历史 / 当时"等标记的行**跳过**并计数（与第 1 项同口径；判据修订见 §4.5） | 同一个量出现两代值 —— 通常是历史取值漏了标记 |
| 4 | **结构完整性**：分册 / `decisions` / `roadmap` / `README` / `implementation` / `modules` / `.dsh/skills` 齐备；旧文件不在现行路径 | 文件缺失或残留 |
| 5 | **skills 去事实**：`.dsh/skills/` 下的正文不得含本项目专名（索引 `README` 例外） | 可迁移技能被项目事实污染 |
| 6 | **Markdown 表格完整性**：同一张表里任何一行的**格数多于表头**（单元格里出现未转义的竖线会把整行撑错位；写成转义形式的竖线不计） | 表格错行 |
| 7 | **登记一致性**（§0 的可执行检查）：`docs/` 一级目录必须在白名单内（`architecture` / `implementation` / `journal` / `modules` / `archive` / `tools`）；`docs/` 根下的 `.md` 与 `implementation/` 下的文件必须都在脚本 `$expected` 清单里 | 出现"**三不管**"内容 —— 新目录 / 新文件没登记，读的人和审计都看不见它（2026-10 的 `docs/methodology/` 就是这样活下来的） |
| 8 | **现行正文不得携带脆弱计数**：非 `journal/` 的现行文档里出现 `约/共/合计 N 条` ⇒ 失败（带"历史 / 当时"标记的行放行；`journal/` 里的历史计数只计数不失败） | 数量 / 条目数写进了现行正文 —— 一搬家就变成假话；应改为**编号区间**或搬进 `journal/`（§0 的 C / D / E 类分工） |

> **不在此脚本内的两项检查**：① **注释卫生**（源码注释里的日期 / 决定编号 / 用户字样 / 历史叙述词）由**架构规则**负责，口径见 `.dsh/skills/human-ai-collaborative-design-review` §4.5；② **文档不写过程**（§2 的"明确不写进任何文档"清单）靠评审把关，不设机械检查。

### 4.3 何时必须跑（**用户 2026-09 裁定：已挂进完整门禁**）

| 场景 | 要求 |
|---|---|
| **改了任意 `docs/` 下的 `.md`** | **必须跑**（手工一次即可） |
| **跑完整门禁 T3** | **自动跑** —— `build.ps1` 的 **第 1/5 步**；`.\tools\dev.ps1 -Mode Gate` 走同一个 `build.ps1`，一并覆盖 |
| 确实不涉及 `docs/` | 可用 `-SkipDocAudit` 跳过（会打印 `[skip]`，不得静默） |

### 4.4 FAIL 怎么处置

1. **先假设它是真的**：绝大多数 FAIL 是"改了 A 忘了 B"（漏同步 / 漏改引用 / 留了废止术语），**照 §2 表补**；
2. **不得为了让门禁变绿而放宽规则、删规则、改白名单**（`implementation/01` §6 同口径）；
3. 确属**误报**：改 `docs/tools/audit-docs.ps1` 时必须**同时**在本文档登记"为什么原判据不成立"，并给出反例；
4. 审计脚本自身**只读**，**不得修改任何文件**。

### 4.5 判据修订登记（每改一次 `audit-docs.ps1` 的判据就在此加一行）

| 判据 | 原判据为什么不成立 | 现判据 |
|---|---|---|
| 3 数值唯一性 | 原判据对**整文件**取全部匹配，于是 `journal/` 里带"当时"标记的**历史取值**也会与现行值撞成"多值" —— 而过程材料的本分就是记录当时的取值，把历史数值涂掉等于毁掉过程材料 | **逐行**扫描；带 `作废/历史/当时` 等标记的行**跳过**并输出"历史取值跳过 N 处"（与第 1 项同一口径） |
| 7 登记一致性（**新增检查**） | 原判据只列出"应有文件"，**不检查目录本身** —— `docs/methodology/` 这类目录既不在清单里、也不在 `docs/README.md` 树里，照样能长期活着（2026-10 实际发生，靠人工发现） | **新增**：`docs/` 一级目录白名单 + `docs/` 根下 `.md` 与 `implementation/` 下文件必须都在 `$expected` 里 |
| 8 现行正文脆弱计数（**新增检查**） | 原判据不查"数量" —— 现行正文里的"7 类约 55 条"在 2026-10 搬家后立刻变成假话（同批发现 2 处，靠人工发现） | **新增**：非 `journal/` 的现行文档不得出现 `约/共/合计 N 条`；带历史标记的行放行，`journal/` 只计数不失败 |
| 归档"永不删除"（§0 G 类 · §3.3 第 5 条） | 原判据把"归档"等同于"永久保存"—— 结果 `docs/archive/` 积到 130 份 / 2.0 MB（旧分册世代、旧工程文档、选型论证、一次性流水），**读它的成本高于读代码**，且旧口径与现行结论并排造成记忆污染（用户 2026-10 裁定「从宽删」）。注意：放开的是**载体**不是**依据** | `archive/` 内容**永不再作为依据**，但**失效载体允许删除**：保留判据 = 现行文档是否按路径 / 编号引用（ADR 原文、`superseded.md`、审计报告、清理清单保留）；删除后登记 `archive/DELETED-<年-月>.md` 并重跑审计 |

## 5. 标记体系（各自的生命周期）

| 标记 | 含义 | 登记要求 | 何时清除 |
|---|---|---|---|
| **`【待裁】`** | **尚未裁定的口径** —— 语义/结构决策，**只有用户能裁** | **必须登记到 `roadmap.md` §3「未完成项」**（作为待决项），不能只躺在正文里 | 裁决后**立即**：改成生效条文，或移出正文 |
| **`【待评估】`** | **推迟到某个可判定时点再定的实现属性**（分类维度、数值校准、模板形态等） | 登记到 `roadmap.md` §3，并写明**评估时点** | 评估时点到达后清除 |
| **`【待细化】`** | 方向已定、**拆分与顺序**未定 | 登记到 `roadmap.md` §3 | 细化完成 |
| **`〔源: …〕`** | 收敛期的**可追溯标记**（指向旧分册 / 归档 ADR / 代码位置） | 无需登记 | **长期保留**（只出现在分册） |
| **`⚠ 历史材料`** | 归档文件头标记 | — | 永久 |
| **`// ARCH-EXCEPTION`** | 代码里的架构例外 | **必须**登记 `decisions.md` §3（代码注释只是索引，不构成登记） | 里程碑收尾复查：关闭或续期（**不删行**） |

**判据（先分类再标）**：问一句「**这是"应该是什么"（A 类）还是"已确定的东西怎么实现"（B 类）？**」
- A 类 ⇒ 只能是 `【待裁】`，**且必须由用户裁**；
- B 类 ⇒ `【待评估】`/`【待细化】`，实现方定，但要**登记时点**。

> 三者的**共同纪律**：**标记不是免罪符** —— 标了不等于可以不登记；也不等于可以长期挂着（每个里程碑收尾复查一次）。

## 6. 提案 → 裁决 → 回写（文档侧的固定循环）

```text
① AI 扩散/形式化 ──► 出「草案 + 编号命题清单」
② 用户逐条裁决 ────► 一次只裁一类（不打包默认）
③ 批次收尾回写 ────► 决策记录一条 + 受影响的那个正文（只落两处）+ 清掉被取代的表述 + 跑审计
④ 落地自证 ────────► 分层验证（implementation/05 §5）
⑤ 用户手工验收 ────► implementation/04 的清单（编号 ｜ 操作 ｜ 可观察预期 ｜ 结果）
```

**纪律**：

- 裁决后要问「**它替代了什么**」「**哪些下游表述必须同步改**」——答不出就还没到冻结条件；
- **不得把用户的倾向扩写为结论**：自由文本裁决必须转写为**编号命题**请其确认（`.dsh/skills/human-ai-collaborative-design-review` §3 转写校验门）；
- **失效信息搬家**（§1 原则 2），不与新结论并排；
- 文档与代码**同一次改动**（`implementation/05` §5 提交纪律）。
