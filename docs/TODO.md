# 正在做什么

> **状态的唯一来源。** 这个项目当前在开发什么、进行到哪、还差什么。
> 系统是什么样 → [`architecture/CODEX.md`](architecture/CODEX.md)；怎么验证 → [`HOWTO.md`](HOWTO.md)。

**一句话现状**：顶层设计与技术架构已冻结。**M1 框架最小闭环已实现到 M1-17**，当前处于 **M1-16「UI 专项」的调整期**；本轮已补主题壁纸/樱色 seed、全局图片裁切、模块壁纸、模块输入持久化、组合件包、工作区快照，以及窗口几何单控制器、表面不透明度与关闭策略；M1-14 手工验收顺延到最终形态上一次性执行；M2 及以后未开始。

**本轮（杂乱问题批量修复，待人工复核）**：① 资源名/布局像素不再被代码断言（主题目录名与清单 `id` 解耦、图标/几何断言改为可解析/关系判据）；② 字体选择器改为下拉内逐项预览 + 输入过滤；③ `TrExtension` 属主解析走 `IUriContext`，不再把 `Avalonia.Controls` 当文本表拥有者；④ 模块动作条高度收敛为 Canvas 单一来源；⑤ 拖动事件合并到渲染帧、参照线/端口锚点拖动期缓存、建网预览节流、拖动期暂停无关面板刷新；⑥ 位置按所在屏缩放做物理投影、组内同一物理位移，组合件布局新增可选 `scale`；⑦ 快捷键随窗口组统一挂接；⑧ 打开失败的串口不再保留"打开"意图；⑨ 同实例自回环允许，并新增纯叠加层自回环标记；⑩ 交互页"窗口"分区合并为窗口管理（全局操作 + 模块行操作 + 屏幕外召回）；⑪ 窗口层级改为固定外壳 / 浮动模块与面板 / 固定模态，模态阻塞低带。验证：**T3 全绿**（文档 / 颜色 / 资源与文本 / 注释布局审计 · 构建 0 警告 0 错误 · 模块包与资源校验 · 许可 · 全部测试：架构 21 · 模块 205 · 主测试 510 · 参考 45 · 快照 75，合计 856）；人工复核项见 ACCEPTANCE A77–A86。

**本轮（暴露问题修复，待真机复核）**：① 外壳/模块统一走“模型 DIP + 每窗物理投影”：外壳可见外框与窗口物理位置分开发布，模块组移动改**绝对物理目标**（不再逐帧 DIP→物理取整累加），外壳被系统移动时按物理外框差平移模块组；`PublishScalingFor`/启动位置/外壳外框收敛到共享 `ScreenGeometry`，尺寸落位去掉 +0.25 偏置。② 拖动目标改物理像素量化、加指针死区；`SnapEngine` 增加上一帧吸附记忆，越过释放距离才换线/松手。③ 字体选择器不再自建箭头/Popup，改为**原生可编辑 ComboBox**（`StyleKeyOverride` 复用主题模板）：下拉项做字体预览、关合态只显示名字、输入过滤 + 列表外文本；外观与设置页其他下拉框同源。④ 启动顺序改为**先落外壳尺寸/位置，再创建窗口管理器**；管理器在外壳外框就绪前挂起 `SyncAll`，自动恢复模块与手动新增模块从此走同一条建窗路径，程序性启动位置不再触发拖拽跟随。⑤ 模块窗口 `Activated` 接入整组抬升（`AppWindowGroup.RaiseFloatingGroup`），选中与焦点共用同一路径。⑥ 自回环在角色文本位于上方时自动落到方块下方。验证：**T3 全绿**（架构 21 · 模块 205 · 主测试 513 · 参考 45 · 快照 79，合计 **863**）；真机多屏/观感复核见 ACCEPTANCE A87–A91。

**本轮（窗口管理控件与模块壁纸图标，待人工复核）**：① 「全部锁定」不再用开关表达混合状态，改为「全部锁定 / 全部解锁」的一次切换按钮，和「全部置前 / 显示全部」同排；② 窗口管理行的「置顶」改为与隐藏/锁定/关闭同风格的外壳 SVG 图标；③ 模块弹窗右上角的壁纸选择图标从空心方框换成与隐藏/锁定/关闭同风格的外壳 SVG（图片 + 山景/太阳，`fill-rule=evenodd`）。验证：**T3 全绿**（架构 21 · 模块 205 · 主测试 514 · 参考 45 · 快照 82，合计 **867**）；人工复核见 ACCEPTANCE A98–A100。

**本轮（杂项事实源/观感修复，待人工复核）**：① ComboBox 模板箭头列改为自适应，并为模块配置格增加 `compact` 箭头（10px + 6px 边距）；② 模块外观事实收窄：内层编辑器高度跟随 `ModuleConfigField` 实际格子高度，模块视图根 `.axaml` 的 `MinWidth/MinHeight` 成为内容最小尺寸与**新模块初始尺寸**的来源；模块代码的 `WindowHeight` 降级为无视图兜底并逐模块写回与视图一致的值，不再把四个紧凑模块统一成同一高度；③ 发送积压（设备写后备）与发送端口队列饱和改为不同文案，后者补齐本段丢弃数；④ 窗口管理行新增屏幕外“召回”按钮；⑤ 吸附预览只点亮本次拖动组的新接触端口对，过滤已有网络和静止模块对；⑥ 模态小窗进入时强制 `Topmost` 并在浮动组抬升后重新压回顶部，释放后恢复。验证：**T3 全绿**（架构 21 · 模块 205 · 主测试 514 · 参考 45 · 快照 82，合计 **867**）；人工复核见 ACCEPTANCE A92–A97。

## 2. 当前步骤：M1-16 UI 专项

按用户方案要点打磨：视觉体系 · 模块窗口 · 端口标记 · 弹窗信息层级 · 状态反馈 · 克制动效。

**判定依据 = [`architecture/CODEX.md`](architecture/CODEX.md) §6/§7** —— 现行模块表面暴露的「控件错位 / 大段空白 / 意义不明」按归因处理（属 L1 缺定义、L2 声明错、还是 L3 外观值不对），**不逐条打补丁**。

**外部接入已完成所有权纠正** —— 框架托管、模块只声明标准标识的外部标准接入（串口 / TCP 客户端 / TCP 服务端 / UDP）。已落地：中性契约（声明 / 标准目录 / 模块存取面 / 状态与计量快照）、实例循环（一个“有活干”信号 + 口队列 / 会话 / 收件箱）、`src/Access`（四适配件 + 参数类型 + 内置 catalog，框架侧，只有组合根引用）、`Sdk.AccessKit`（模块共用骨架，宿主随附）、四模块接线与状态/计数发布；八模块包只含模块自有文件，宿主提供契约/UI/外部接入依赖。框架级、适配器级、模块级自动化用例已加入。**仍待**：真机 / 回环人工验收（ACCEPTANCE 80j–80r）；本轮改动后需关闭应用重跑完整 T3（见 §6）。

**本轮（缓冲满 / 跟不上 / 丢弃机制）**：① 丢弃收口为**一个词表、三条轴**（队列轴 / 流轴 / 会话轴，同一事件两侧归属、任何合计不跨轴相加），会话快照按来源分项；② 投递循环改为**时间片回泵**（命令 / 输入 / 接收回调 / 状态发布不再被持续积压饿死）；③ 停止与暂停**先清尾再等待**（移除不再等整条积压，孤儿只可能来自"清尾之后"挤进来的单元）；④ 新增**最大滞留**过期丢弃与**外部写超时**（四个适配件统一有界）；⑤ 机制参数收进设置 `flow` 块（schema v6，旧三根键折叠并删除），设置页新增「数据面（缓冲与流控）」分组，容量/策略/写超时"对新建生效"、其余立即生效；⑥ 四个外部模块在跟不上时用**本模块文案**说一句，`drop` 读数只取会话轴有效字节；⑦ 拓扑诊断与口标记悬停显示队列压力与按原因丢弃。自动化：`SerialDeliveryResponsivenessTests` / `DataPlaneQueueLedgerTests` / `PortFlowQueryTests` / `ExternalAccessPressureStatusTests` / 拓扑与悬停用例。人眼复核见 ACCEPTANCE A56–A64。

**本轮（串口断连、未打开发送与清空计数）**：① 串口打开期间由会话按 250 ms 探活（`IExternalAccessLiveness`），设备消失 ⇒ `DeviceLost`；故障后由实例线程释放一次句柄（故障态与原因保留），事件/泵线程不关句柄。② 未打开发送被拒计入 `RejectedUnits`，模块状态句显式提示「… · 发送已丢弃（N 次）」，不弹窗。③ 四个外部模块新增清空计数命令与 24×24 图标按钮（`ModuleButton.icon` + 12px 描边箭头）；打开/关闭端口不清零，只有清空按钮（或实例重建）清零，且不清队列数据/连接数/故障态。人眼复核见 ACCEPTANCE A41–A45；已知边界见 G67。

**本轮（输入控件观感与退出）**：① 输入控件的绘制收成一份 `Ui/Styles/InputChrome.axaml`（宿主 / 预览 / 模块共用）：常态 1px、聚焦/报错是 2px **叠加圈**，聚焦不改边框厚度；Fluent 的聚焦黑线与下拉选中强调色不再出现；chrome 同时清掉 Fluent 的 `MinWidth=64` 与文本面内层的 `MinHeight` 外来下限，48 宽的间隔框不再裁掉末位。② 运行期只读**不换控件**：`ModuleConfigField` 与 `ModuleTextSurface` 在 `Appearance.ReadOnly` 下保持同一个输入框、同一条边框，只停止编辑；只有声明只读/显示模式才换文本叶子。③ 删除 `SurfaceTextFrameEditableBrush`（可写/只读两种边框的方案作废）。④ 退出：主窗 `ClosingBehavior=OwnerWindowOnly`（先决定、取消时子窗不动）、模块窗视图在 `Closed` 摘、`ShellExitCoordinator` 单一出口（询问/保存/记住/关模块窗/放行外壳）。人眼复核见 ACCEPTANCE A36–A40。

**本轮（关窗时序与外部接入文本归属）**：① 关闭询问被取消后不再拆应用 —— 收尾从可取消的 `ShutdownRequested` 移到 `Exit`，用一次性闸门；关窗不再预摘视图，管理器记住窗口 `Closed`，视图可在挂回时自愈。② 外部接入只给**事实**（端点 + 结构化失败：种类 / 原始值 / 底层细节），四个模块用**自己的表**生成连接/状态/失败句子；`Access` 表只剩 `access.diag.*`；参数表单的标题/说明/分组/选项改由**声明该接入的模块**表解析（参数类型仍在框架侧）。人眼复核：关闭→取消后模块仍可用；四模块故障态显示模块文案；Issue 里是框架底层原因；参数表单标题照常（见 ACCEPTANCE A31–A35）。

**本轮（机制收敛，已落地，待人眼复核）**：控件不再自带标题 —— `ModuleConfigField` 只做编辑器，标题是独立的 `ModuleLabel`（`Field` 取同一份配置元数据），字段标签与编辑器各占一条矩形；读数不再有标题与单位槽（单位是普通标签或值文本的一部分）；标签排印收敛成一套（`caption` / `hint` / 默认）。预览里空/透明的标签有虚线占位框，设计时上下文给样例值；预置了一份内容区几何（`ModuleSurfaceMetrics`），快照/契约用例改用真机内容区尺寸。**上一轮的 `LabelPlacement=Stacked` 方案随之撤销**（它只是把"标题在控件里"的毛病换个位置）。人眼复核：TCP 客户端「超时」、四个模块的读数、两个发送器的间隔与「已发送」、预览器里的占位框。**本轮追加**（早前已落地、仍待人眼复核）：四模块状态→按钮/字段启用绑定、状态行统一到底部、本机回环默认地址/端口、同一实例自连接拒绝；模块活动与连续发送统一到全局计时服务。

**本轮（按钮面 / 显式 SVG / 模块自有资源包）**：① 按钮面：`ButtonChrome` 的 `.icon` 与普通按钮共用面/边/hover/pressed/focus/disabled；按钮簇去掉外框、5 钮各自有面；活动栏保留导航式 + pressed；锚点 hover 统一。② 图标显式化：每个图标 `.svg` + `icons.json` 清单；框架 17 个换回 **Fluent UI MDL2**（2048 画布、旧观感），模块 4 个 `refresh.svg` 保持 **Fluent UI System Icons**（20px、与小按钮适配），两套均 MIT；`IconCatalog` 只产数据（路径/viewBox），`Sdk.Ui.Icon` 合成几何；删除 `FontIcons`；`IconButton`/`Glyph`/`ModuleButton.Icon` 全部改用 `Icon`。③ 资源包分离：8 个模块的 `i18n/`/`icons/` 搬进模块包 `resources/`；`module.json` 的 `resources` 声明；`ResourceLayout` 双根（模块 owner 只读模块包、框架 owner 只读框架根，互不回退）；新增 `Sdk` 的 `IResourceAccess`（模块自定义 kind，只读/相对/不越界）+ `IModuleContext.Resources`；审计/打包：框架只审 `resources/`，模块 `resources/` 走 ③d/`verify-module-packages`；许可 `LICENSE` + `THIRD_PARTY_NOTICES`。人眼复核见 ACCEPTANCE A46–A55；已知边界见 G68/G69/G70。
