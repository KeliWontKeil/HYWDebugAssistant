# 发布与装载

## 构建模块包

引用 `HYWDebugAssistant.Module.Build` 后，`dotnet build -c Release` 会直接把模块包归拢到：

```
bin/module-package/Release/<模块名>/
```

包内是会被分发的那一棵目录：`module.json`、实现程序集（可含 `.pdb`）、`resources/**`、`views/**/*.axaml`（端口声明源）、模块私有依赖。宿主提供的程序集与 `*.deps.json` 自动排除；包名默认取项目名最后一个点段，可用 `<ModulePackageName>` 覆盖。

包内文件的完整规则（含平台分片与排除清单）见[项目与包布局](project-layout.md)，这里不重复。

## 装载

1. 打开主应用（产品）；
2. 活动栏「模块清单」→「导入模块…」→ 选择**包含 `module.json` 的那一层**目录；
3. 框架校验清单、入口、依赖与同标识冲突，通过后复制到 `modules/external/`；
4. 在「可用模块」里选中模块，点「加入现场」。

规则：

- **同一标识已存在**：拒绝导入并提示先移除旧包；不会覆盖、不会并存。
- **改过代码的包**：程序集不可替换，需要关闭应用重开后生效。
- 内置模块与外部模块走同一条发现与加载路径，外部包没有结构特权。
- 导入后如果模块列表没有刷新，点「重新扫描」或重启应用。

导入并加入现场只说明模块能装载；**是否与对端兼容要看建网结果**。契约不兼容时连接不会建立，原因在 Issue 面板，状态栏只显示标签设置结果。

## 迭代：改完代码怎么更新

程序集不能被替换，同一标识的包也不允许并存，所以更新外部模块要走“替换”而不是“再导入一次”：

1. 关闭应用；
2. 删除程序目录下 `modules\external\<包目录>`（框架没有“卸载包”的界面；同一标识已存在时导入会被拒）；
3. 重新 `dotnet build -c Release`；
4. 重新导入新的包目录，或直接把新包里的文件覆盖到原目录；
5. 启动应用，确认模块清单里加载的是新版本。

只改配置或资源、不改程序集时，也必须重启（或在重扫确认框里确认重启），因为资源在加载期读取。

## 导入前自查

外部作者没有仓库里的验证脚本，按这三步自查：

1. 包目录里必须有 `module.json`，且 `id` / `entryAssembly` / `entryType` 与代码一致；
2. `ModuleContract.Probe` 的 `Problems` 为空（见[测试与验证](testing.md)）；
3. 包内没有宿主程序集、没有 `*.deps.json`；`resources` 声明的目录真实存在。

这三步都不等于装载；真正的装载是上面的主应用流程。

## 被拒原因

任何一步失败都会给出**可定位**的原因，模块保持不可用，其余部分照常运行。

### 包加载

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 包目录不存在 | 选错了目录，或包被移动 | 选包含 `module.json` 的那一层目录 |
| 缺少 `module.json` | 清单没随包分发 | 确认构建输出里有清单；外部工程检查是否引用了打包规则包 |
| 清单解析失败 / 内容为空 | JSON 语法错误或空文件 | 修正 JSON；允许注释与尾随逗号 |
| 清单标识不合法 | 不是两段 `[a-z0-9-]`，或段首尾有 `-` | 改成小写两段，如 `vendor/my-module` |
| 缺少 `entryAssembly` 或 `entryType` | 清单字段缺失 | 补全实现程序集文件名与入口类型全名 |
| 资源路径非法 | `resources` 里写了绝对路径或 `..` | 改成包内相对目录 |
| 资源目录不存在 | `resources` 声明的目录在包里没有 | 让资源随包输出，或从清单去掉该条 |
| 实现程序集不存在 | 清单文件名与包内文件不一致 | 对齐 `entryAssembly` 与实际 DLL 名 |
| 实现程序集加载失败 | 目标框架不符、缺少依赖 | 按当前 SDK 重编；把第三方依赖一并放进包 |
| 引用了旧 `Access` | 旧版模块直接依赖框架内部程序集 | 改用 `Sdk` / `Sdk.AccessKit` 重编 |
| 引用了作者包 | 模块运行时引用了契约自检套件 | 把 `Sdk.Testing` 从运行时引用里去掉（它只给测试项目） |
| 宿主程序集缺失 | 应用输出不完整 | 重新构建/安装应用 |
| 入口类型不存在 | `entryType` 写错或类被改名 | 对齐全名（含命名空间） |
| 入口类型未实现模块接口 | 入口类没有实现 `IModule`，或没有公共无参构造 | 实现接口；补公共无参构造 |
| 缺少 `[ModuleDefinition]` | 入口类型没打声明特性 | 补特性；标识必须与清单一致 |
| 清单与代码标识不一致 | 两处各写了一份标识 | 统一成同一个标识（框架拒绝加载，避免同名歧义） |
| 依赖的模块不存在 | `dependsOn` 指向未安装的模块 | 先装依赖，或去掉该条 |
| 同标识已存在 | 另一个包目录已注册同一个标识 | 先移除旧包再导入；框架不覆盖、不并存 |
| 需要重启 | 同一个包目录在应用启动后被重建过 | 关闭应用重开（程序集不可热替换） |

### 实例化（声明面）

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 端口名重复 | 同一模块内两次声明同名口 | 口名在模块内唯一 |
| 口引用了未声明的类型 | `TypeId` 在本模块没有对应声明 | 先声明类型，再让口引用它 |
| 口形状与类型形状不一致 | 两处形状写法不同 | 让口形状与类型形状完全一致 |
| 数据类型重复声明 | 同一标识声明了两次 | 标识在模块内唯一 |
| 同一标识出现两种形状 | 两个模块对同一约定写法不同 | 改标识，或统一形状 |
| 角色引用了不存在的口/类型 | 角色声明与口/类型对不上 | 角色只能引用本模块已声明的口与类型 |
| 一个口属于多个角色 | 同一口被两个角色声明 | 一个口最多属于一个角色 |
| 显示源 / 输入 / 命令重名 | 同类名字重复 | 名字在模块内唯一 |
| 外部接入名重复或标准未知 | 接入名重复，或标准标识框架不认识 | 接入名唯一；标准标识取框架已提供的值 |
| 外部接入单元上限非法 | 超过框架允许的上限或 ≤ 0 | 调小 `MaxUnitBytes` |
| 配置类型不可登记 | 不是公开类、缺公共无参构造 | 按配置约束改类型 |

### 去哪里看

- 应用内：**模块清单**（加载结果与说明）、**Issue**（声明期问题，带对象路径）。
- 模块窗口：视图没起来时窗口显示一行原因（工厂缺失、构造异常等），不会静默空白。

## 版本

模块包没有自己的版本字段：包内容决定新旧，标识决定身份。主应用与作者包共用一个四段版本；升级 SDK 后重编模块，再按上面的步骤重新导入。
