# 模块结构

一个模块由七层组成。每层只回答一件事，失败时的现象各不相同；写模块就是把这七层填满，不需要的层留空即可。

## 七层

| 层 | 定义在哪 | 谁读 | 缺了或写错的现象 |
|---|---|---|---|
| 包 | `module.json` + 程序集 + `resources/` | 加载器 | 导入被拒，模块不出现在列表里 |
| 入口与元数据 | `[ModuleDefinition]`：标识、显示名、窗口尺寸、视图工厂、依赖 | 加载器、模块清单、窗口 | 清单与代码标识不一致 → 拒绝加载 |
| 声明面 | `OnRegistered` 里的 `Declare*`：类型、端口、角色、显示源、输入、命令、外部接入 | 实例化期的校验 | 自检 `Problems` 非空；加载期 Issue；建网连不上 |
| 生命周期 | `IModule` 的六个钩子 | 状态机 | 初始化时机错（在注册期假定数据已流动） |
| 活动与调度 | `IActivitySource`：`OnStep`、`ReceiveMode`、定时器 | 实例线程 | 收不到命令、周期不触发、数据没人取 |
| 视图 | 视图工厂 + 模块 XAML | 窗口与呈现层 | 窗口空白、控件无样式、读数不刷新 |
| 资源 | `resources/i18n`、`resources/icons`、自定义 kind | 文本/图标目录、模块自己 | 界面显示键名；图标缺失 |

每层的细节在对应页面：包与清单见[项目与包布局](project-layout.md)，声明规则见[声明面](contracts.md)，钩子与上下文见[实现](implementation.md)，调度见[自发活动与定时器](activity.md)，视图见[界面](ui.md)与[控件](controls.md)，资源见[资源与文本](resources.md)。

## 一次实例的生命线

```
创建实例 → OnRegistered（声明）→ 校验声明 → 进入 Active → OnActivated
        → OnStep(Start) → 之后：接收回调 / OnStep(Data|Session|Command|Input) / 定时器 Tick
        → Disabled：OnDisabled（定时器暂停）→ Enabled：OnEnabled
        → Removed：OnRemoved（释放资源）
```

这条线由框架驱动：模块只实现钩子与单步，不拥有线程、不写循环。线程与队列的完整机制见[运行期](../concepts/runtime.md)。

## 四种最小形态需要哪几层

| 形态 | 必须有 | 可以没有 |
|---|---|---|
| 纯数据变换 | 包、入口、类型+端口+角色、接收回调 | 视图、资源、定时器 |
| 带界面 | 上面 + 显示源/输入/命令 + 视图工厂 + 文本表 | 定时器 |
| 设备接入 | 包、入口、类型+端口、外部接入声明、会话读写 | 视图（可加） |
| 周期任务 | 包、入口、显示源、`IActivitySource` + 定时器 | 端口、视图 |

## 声明与读取的边界

- 声明只在 `OnRegistered` 发生一次，框架随后**只读一次**并转成不可变元数据；运行期不再重读。
- 视图与命令都按**名字**寻址：名字是模块在声明里给出的字符串常量，代码与 XAML 共用同一份（`{x:Static}`），不各写一份字面量。
- 类型与形状必须自洽：端口的形状要与它引用的类型完全一致，否则加载期报错。规则见[声明面](contracts.md)。
