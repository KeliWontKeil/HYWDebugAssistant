# 版本与兼容

本文是版本规则与兼容处置的唯一说明。产品、SDK 包、发布清单共用一个四段版本号；模块标识、数据类型、本地文件格式都没有版本。

## 版本号的构成

版本号为四段 `M.m.p.r`（主.小.修订.轮次），既是程序集版本，也是 NuGet 包版本与发布清单里的 `version`。

| 字段 | 含义 | 何时提升 | 谁决定 |
|---|---|---|---|
| 主 `M` | 兼容世代；`0` 表示开发期未定型，`1` 起承诺不破坏模块与数据契约 | 首次对外发布或明确断代 | 开发者显式 |
| 小 `m` | 能力批次；`0.x` 期间允许破坏性变更 | 一批功能交付 | 开发者显式 |
| 修订 `p` | 缺陷修复，能力集合不变 | 修完缺陷的构建 | 开发者显式 |
| 轮次 `r` | 该版本线的第几次构建，从 1 起 | 每次交付或自测构建 | 脚本自动 |

`0.x` 期间不承诺跨版本数据可读、不承诺旧模块包可加载、不承诺同标识多版本共存；破坏性变更只需显式提升版本。

## 唯一事实源

数字只写在仓库根 `version.props`，由 `tools/version.ps1` 写入。构建属性与程序集元数据都从它派生，不得单独覆盖任何版本项；门禁会拦截多出来的版本字段与代码、资源、文档里的版本字面量。

## 提升与提交

| 操作 | 效果 |
|---|---|
| `tools/version.ps1` | 显示当前版本 |
| `-Value` | 只打印版本号，供其他脚本取用 |
| `-Round` | 轮次加一 |
| `-Minor` / `-Patch` / `-Major` | 对应位加一，低位归零 |
| `-Set M.m.p.r` | 显式设置四段 |
| `-Commit "<说明>"` | 轮次加一、写入文件并提交 |

主、小、修订从不自动提升；构建、测试与门禁从不改版本。提交是推荐做法而非强制要求：手工提交、不带版本号的中间提交、跨轮次提交都允许，只要求交付构建那一刻版本正确。

## 什么有版本

| 对象 | 是否有版本 | 说明 |
|---|---|---|
| 产品构建 | 是，且唯一 | 交付、排障与回滚的指认依据 |
| SDK 包 | 是，等于产品版本 | 包是产品派生���，不是第二套编号 |
| 发布清单 | 是，`version` 字段 | 只描述这一次构建 |
| 模块标识 | 否 | 标识即身份，新旧由包内容决定 |
| 数据类型 | 否 | 改形状就是破坏性变更 |
| 设置、组合件、主题、文本表、图标表、色板 | 否 | 能解析就使用，失败即报错或丢弃，不做迁移 |
| 第三方依赖 | 是，但由中央包管理 | 与本文机制无关 |

## 兼容判据与处置

| 对象 | 兼容判据 | 不兼容时 |
|---|---|---|
| 模块到宿主 | 程序集能加载、入口实现模块接口、依赖可解析 | 拒绝该模块并报错，其余模块照常运行 |
| 同标识模块导入 | 不存在同标识的包 | 拒绝并提示移除旧包后重试 |
| 默认目录内重建 | 无判据，按内容重建 | 标记需要重启，重启后生效 |
| 端口与数据类型 | 传递语义一致、形状完全一致、两侧声明时标识相同 | 拒绝连接并说明差异，不自动转换 |
| 组合件 | 可解析且记录内标识合法 | 该记录丢弃并告警；结构损坏则整文件拒绝 |
| 设置 | JSON 可解析 | 使用默认值并告警，不静默改写原文件 |
| 主题、文本表、图标表 | 可解析且形状正确 | 跳过该项并告警 |

**禁止**：迁移函数与版本分支、兼容区间语法、旧字段兼容读取、为旧包保留的垫片、第二个版本字段。不兼容即明确拒绝，由使用者决定是否重建。
