# 代码结构

## 分层

层按运行时角色划分，不按命名空间划分。

| 层 | 名称 | 承担什么 |
|---|---|---|
| L0 | 横切支撑 | 日志、序列化、文件读写、诊断采集等中性技术能力 |
| L1 | 契约层 | 模块作者与界面共同依赖的稳定抽象面：契约、声明面、数据类型 |
| L2 | 模块托管层（`Hosting` 库，不是独立进程） | 模块包的发现、加载、校验与注册；实例世界 |
| L3 | 数据面层 | 绑定的执行与投递、有界缓冲与丢弃、模块活动的承载与调度 |
| L4 | 核心管理面 | 组合的解释与校验、变更的原子应用、增量重建、持久化、诊断中心 |
| L5 | 界面构成层 | 外壳窗口、模块窗口、视觉层、端口标记与管理视图 |
| L6 | 模块实现 | 业务功能单元，不属于框架 |

## 依赖方向

```
L6 模块实现  →  L1 契约
L2 模块托管  →  L1, L0
L3 数据面    →  L1, L0
L4 核心管理  →  L1, L2, L3, L0
L5 界面      →  L1, Core.Api
```

由此得到几条结构性事实：

- 数据面不依赖主应用组合根、核心管理与界面，因此"核心中转数据""界面参与投递"在结构上无法成立。
- 模块只依赖契约层，因此模块不能自建活动载体、不能引用其它模块、不能直接引用界面框架，也不能携带外部接入的实现。
- 界面只经 `Core.Api` 读取运行期事实，不引用核心管理面的内部类型。
- 组合根 `App` 是唯一同时可见核心与界面的位置，只做装配，不承载业务或机制逻辑。

## 项目与程序集

项目清单本身就是依赖边界：每条禁令都可以按项目引用直接检查，不需要从命名空间推断。

- 允许引用界面框架的程序集只有界面契约、模块区、外壳与组合根四个，其余项目不得出现界面框架依赖。
- 框架程序集不得引用任何模块程序集；模块之间不得互相引用。
- 业务模块只允许引用 `Sdk`、`Sdk.Ui`、`Sdk.AccessKit`。

完整的规则编号与允许集合见 `dev/constraints.md`，由架构测试强制执行。

## 仓库目录

| 目录 | 内容 |
|---|---|
| `src/` | 全部产品代码，一个程序集一个项目 |
| `tests/` | 测试项目与截图工具 |
| `tools/` | 构建、打包、审计与开发脚本 |
| `build/` | 模块打包规则（`module-package.props` / `.targets`），仓库模块与 `Module.Build` 作者包共用同一份 |
| `docs/` | 文档站工程（MkDocs），中文在 `docs/zh/` |
| `dev/` | 仓库约束、开发工作流、状态与验收，不进站点 |
| `templates/` | 模块作者模板：SDK 随附的最小可构建工程 |
| `resources/` | 框架侧资源：文本表、图标、出厂种子 |
| `artifacts/` | 构建产物，不入库 |

`src/` 的项目与层的对应：

| 项目 | 层 | 作用 |
|---|---|---|
| `Infrastructure` | L0 | 路径、存储与横切工具 |
| `Sdk` / `Sdk.Ui` / `Sdk.AccessKit` | L1 | 契约、界面契约与控件、外部接入通道 |
| `Sdk.Testing` | L1（作者包） | 契约自检与测试上下文，只给测试项目 |
| `Hosting` | L2 | 包发现、加载、校验，实例与生命周期 |
| `DataPlane` | L3 | 队列、缓冲池、承载与外部接入会话 |
| `Core` / `Core.Api` | L4 | 组合、变更、持久化、诊断；`Core.Api` 是界面读取运行期事实的唯一面 |
| `Access` | 框架侧 | 四个外部标准的适配器与参数类型，只有组合根引用 |
| `Ui` / `FrameworkUi` | L5 | 模块窗口与视觉层；外壳、面板与设置 |
| `App` | 组合根 | 依赖装配与启动 |
| `Modules/Business/*` | L6 | 八个内置模块，与外部模块走同一条加载路径 |
