# 已知问题与极端工况

本页记录**已确认但按当前设计不修复**的边界行为，避免后续把极端测试现象误当成常规缺陷。

## 串口首次打开冷启动压力

### 触发条件

- 串口首次打开（设备/驱动处于冷启动状态）；
- 1 ms 连续发送、大文本帧、高波特率；
- 设备侧实际消费速度明显低于配置波特率，或 USB 串口端点存在启动期背压。

### 现象

- 首次打开后的前几次 `SerialPort.Write` 正常，随后出现数百毫秒到 1 秒级阻塞；
- 写泵阻塞期间 `SendBacklog` 很快到达容量上限，CPU/界面出现明显峰值；
- 手动发送一次或关闭后重新打开串口后，该次冷启动瞬态通常不再出现。

### 定位结论

这是设备/驱动冷启动与极端压力叠加造成的写阻塞，不是队列死锁、线程泄漏或写泵无界等待。数据面仍按设计完成满队丢弃、错误上报与计数，不承诺该工况下的实时吞吐。

### 处理

按**已知特性**记录，不做启动预热、启动闸门或自动降速。需要稳定高频发送时，应先确认设备实际接收能力与波特率，并降低连续发送频率或缩短帧长。
