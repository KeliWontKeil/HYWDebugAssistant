# 数据文件

文件位置见[目录与发布包](layout.md)。本页只讲格式、写入规则与手工修改的边界。

## 持久化纪律

- 文本 JSON，未知字段逐层保留并合并写回，采用临时文件加重命名的方式原子写入。
- 缺失或损坏时使用内置默认值并记录一条诊断，不阻断启动；不可解析时拒绝并保护原文件，拒绝而不是猜测。
- 没有格式版本：文件不内嵌版本号，读取只接受当前形状；旧文件要么能按关键字段解析，要么被明确拒绝。不做迁移。
- 模块需要跨会话保留的参数与状态放进实例配置，随组合件保存；框架不提供模块自有设置文件或数据目录。
- 配置采用"读即登记"：模块首次读取配置时登记一份默认值，后续读写同一对象；只读未登记的模块保存组合件时会丢失整块配置。

## 组合件

- 组合件加载时按实例标识重映射冲突项，标签、网络名与位置保持不变；运行态与绑定不随件。
- 布局在窗口创建时先读取并消费已保存的布局，再处理新实例的错位摆放。
- 一个组合是一个文件夹：`composite.json`、封面与资产同住；整体复制即完成迁移。

## 工作区与退出

关闭主窗口时按设置执行"每次询问 / 保存并退出 / 不保存退出"，询问弹窗可以记住选择。保存后下次启动恢复模块、配置、用户输入、位置、壁纸与外壳位置；选择不保存只丢弃本次未保存修改。

退出只有一个出口：主窗口先决定，取消时子窗口都不关；收尾在退出事件里执行一次。

## 手工修改

文件都是文本 JSON，可以退出应用后手工编辑，改完重新启动生效。

| 文件 | 常见改动 | 注意 |
|---|---|---|
| `settings/settings.json` | 语言、刷新率、数据面参数、快捷键 | 结构不合法时整份回落默认值并记录诊断；未知字段会保留 |
| `settings/appearance/themes/<主题>/theme.json` | 主题颜色 token、壁纸引用 | 主题是一个文件夹，可整体复制搬走；改完在设置里能看到该方案 |
| `composites/<组合名>/composite.json` | 模块列表、连接、配置、位置 | 引用的模块不存在时该实例成为占位；结构损坏时整文件被拒绝 |
| `workspace/workspace.json` | 现场快照 | 启动时读取；结构损坏时从空现场开始 |

规则：

- 先备份。改坏时删除该文件即回到默认行为，诊断里会有一条记录。
- 同一事实只写一处：主题颜色写 `theme.json`，不要在 `settings.json` 里再抄一份。
- 组合件里的模块标识必须与已安装模块一致，否则该记录被丢弃并告警。
- 应用运行期间改文件可能被退出时的保存覆盖，改前先关闭应用。
