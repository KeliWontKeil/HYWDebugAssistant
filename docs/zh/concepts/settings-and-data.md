# 设置与持久化

## 三类持久化对象

| 对象 | 位置 | 内容 |
|---|---|---|
| 应用设置 | `settings/settings.json` | 语言、外观、窗口行为、存储路径、快捷键等 |
| 组合件 | `composites/<组合名>/composite.json` | 一次保存的模块组合：模块集合、连接、配置、位置、活动面 |
| 工作区 | `workspace/workspace.json` | 当前工作区快照，用于退出保存与重启恢复 |

应用设置与组合件完全分离：设置不随组合件保存，组合件也不写进设置目录。

功能根目录只在路径解析器里定义：

```
<程序目录>/modules/            内置模块包
<程序目录>/modules/external/   外部导入模块包
<程序目录>/composites/         组合件包
<程序目录>/settings/           应用设置与主题
<程序目录>/workspace/          工作区快照与资产
<程序目录>/logs/               日志
<程序目录>/resources/seeds/    出厂种子
```

## 设置分类

| 分类 | 内容 |
|---|---|
| 常规 | 语言、停止超时、输入队列容量、自动建网、界面刷新率、性能监视、日志级别、诊断提示阈值 |
| 外观 | 字体、主题方案、壁纸、色板（顺序固定） |
| 窗口与交互 | 整体置顶、叠加层开关、吸附距离、主窗口比例与尺寸固定、关闭主窗口行为、多行输入提交键 |
| 存储 | 五个功能根的只读路径与打开目录 |
| 快捷键 | 动作清单、当前绑定、修改、重置与冲突检测 |
| 关于 | 版本、构建配置、依赖许可摘要、快捷键速查 |

设置弹窗里的可编辑项都是草稿，只有应用或确认才提交，取消不改变运行时。交互页上的直接开关是另一种入口：立即生效并立即写盘。两处共享同一份设置文件，但两种语义不混用。

同一语义只保留一处状态，其他界面做委托，禁止各存一份再同步。

## 持久化纪律

- 文本 JSON，未知字段逐层保留并合并写回，采用临时文件加重命名的方式原子写入。
- 缺失或损坏时使用内置默认值并记录一条诊断，不阻断启动；不可解析时拒绝并保护原文件，拒绝而不是猜测。
- 没有格式版本：文件不内嵌版本号，读取只接受当前形状；旧文件要么能按关键字段解析，要么被明确拒绝。不做迁移。
- 模块需要跨会话保留的参数与状态放进实例配置，随组合件保存；框架不提供模块自有设置文件或数据目录。
- 配置采用"读即登记"：模块首次读取配置时登记一份默认值，后续读写同一对象；只读未登记的模块保存组合件时会丢失整块配置。
- 组合件加载时按实例标识重映射冲突项，标签、网络名与位置保持不变；运行态与绑定不随件。
- 布局在窗口创建时先读取并消费已保存的布局，再处理新实例的错位摆放。

## 出厂种子

只读的出厂内容放在 `resources/seeds/`，与目标目录同构：投放就是按相对路径合并进程序目录。

- 单文件在目标不存在时才复制；叶子目录作为一个投放单元整体复制。
- 已投放过的单元记录在设置里，用户删除后不会复活。
- 只做整单元投放，不改写已存在的内容；失败记录警告并撤掉本次半成品。
- 出厂设置基线不写入仓库：发布时由程序自身的命令从代码默认值生成。

## 工作区与退出

关闭主窗口时按设置执行"每次询问 / 保存并退出 / 不保存退出"，询问弹窗可以记住选择。保存后下次启动恢复模块、配置、用户输入、位置、壁纸与外壳位置；选择不保存只丢弃本次未保存修改。

退出只有一个出口：主窗口先决定，取消时子窗口都不关；收尾在退出事件里执行一次。
