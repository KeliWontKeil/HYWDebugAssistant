# 运行期

## 总流程

```
用户拼接与配置 → 组合声明 → 核心管理面解释与校验 → 绑定 → 数据单元直通投递
```

数据单元按序直通，核心管理面不中转数据。没有全局启停：模块加入即运行，停止由生命周期状态承担。变更以一次原子操作提交，只对受影响的局部做增量重建。

## 生命周期

```
Registered → Active ⇄ Disabled → Removed
```

| 状态 | 语义 |
|---|---|
| `Registered` | 已加入，未占用线程 |
| `Active` | 参与数据流 |
| `Disabled` | 保留实例、拓扑与配置，暂停数据流；线程与队列保留，绑定置为停流 |
| `Removed` | 已移除，资源在此回收 |

移除不可逆：重新加入会产生新实例。绑定独立于模块状态——模块停用时绑定保留并标记停流，模块移除时级联销毁。

## 线程与队列

- 每个活动实例分配一个专属线程，每条（实例，端口）一条有界输入队列与停止标志。
- 框架拥有实例循环：数据、外部会话、命令/输入、到期时间都是**唤醒原因**，合并成一次 `OnStep`；模块不拥有循环、不等待、不建定时器。
- 模块用 `NextDelay` 声明"从框架排定这一刻起，多久后需要因时间被唤醒"；普通输入/命令/数据不重排已排好的到期，只有 Start、Due 或延迟值变化才重排。框架的计时服务负责到期，模块不在计时线程上执行。
- 队列默认丢最旧保最新，不做背压、不阻塞发送方；入队结果分档计数：接受、满队挤旧、满队拒新、无承载、已停止。
- 每端口一条队列，避免跨端口队头阻塞；多端口之间轮转公平调度。
- 投递按时间片回泵，处理每个单元前检查停止信号，保证控制面与接收侧不会被长期排在后面。
- **等待是事件驱动的**：入队、会话就绪、命令与输入都在返回前唤醒实例线程；固定间隔只作"漏唤醒"的兜底，不承担数据延迟。
- 唯一的周期需求是模块自己声明的 `NextDelay` 与外部设备探活（设备拔出没有任何事件）：到期只向实例线程投一个唤醒信号，不在计时线程上执行模块或会话代码。
- 实例停用时清空该实例各端口队列并逐笔记账，恢复后不补发停用期间积压。

## 停止协议

框架置停止标志后先清尾，再有界等待线程退出。超时则记录诊断并把线程标记为孤儿线程，不强杀线程、不卸载程序集。框架不再调用 `OnStep`；模块的一步必须短小，停止总时限由承载者统一计算。停止多个实例时先全部叫停，再在一个共享总时限内逐个等待：总等待取最慢的那一个，而不是各实例超时之和。

## 变更与重建

- 单个操作原子：连接、断开、加入、移除、启用、停用，要么完整应用、要么整体回滚。
- 需要多步一起完成时，由界面或命令层组装为一次复合变更。
- 两阶段执行：Prepare 阶段整体校验，可失败且零副作用；Commit 阶段无失败点，先加后减。
- 增量重建的单位是绑定及其邻接数据面，模块实例、配置与业务状态保留。
- 配置字段的写回同样走变更路径：序列化当前配置、覆盖一个属性、反序列化为新实例后原子应用，不就地修改运行中的配置对象。

## 诊断中心

诊断条目由归属对象、类别、来源、描述与时间组成；类别覆盖配置、组合、接口、模块、通信、运行期与呈现。

- 严重度：错误表示框架故障、契约错误或持久化损坏；警告表示外部环境与对端状态；信息是生命周期与诊断事实。
- 模块业务状态不属于诊断条目，属于模块状态行。
- 呈现方式是对象标注加主从面板，默认轻量，不弹窗、不阻断其它部分运行。
- 框架不自动重试、不自动降级；恢复由用户显式操作或模块内部完成。

## 可观测性

| 层 | 内容 |
|---|---|
| 框架诊断 | 加载、注册、建网、绑定、重建等结构化日志 |
| 诊断中心 | 对象标注、主从面板、过滤与已读状态 |
| 模块状态 | 模块自产日志与状态行 |
| 数据流诊断 | 各档速率、按原因丢弃、最后数据时间、队列深度与饱和状态 |
| 性能监视 | CPU、内存、线程与 GC 计数，低频只读 |

同一份事实只在一处生成，其余位置只做格式化；界面不自行差分或相加。

## 计时纪律

模块用 `NextDelay` 声明周期需求，框架的计时服务负责到期；模块不得自建定时器、不调用线程睡眠或平台专有调度接口。框架侧只有一个进程级计时服务，界面刷新由唯一的帧时钟统一订阅，帧节拍跟随"界面刷新率"设置：用户看到的东西按这个节拍更新，数据面不因它被节拍化。呈现文本按帧预算读窗口；超预算时只重建尾部，数据与保存不受影响。

## 非功能基线

数据实时性优先于界面呈现：数据面不被界面阻塞。模块数量不设上限要求，核心不随模块数量线性膨胀。性能数值只作记录与对照，不设阈值。
