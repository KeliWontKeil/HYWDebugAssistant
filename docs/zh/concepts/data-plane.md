# 数据面

## 数据单元

一个数据单元是一个定长数据报，长度等于发送端口契约的尺寸。

- 数据包不自描述：不带类型标签，框架按声明路由。需要自描述的模块在自己的契约里带字段。
- 当前只支持定长：不提供变长载荷，也不分片。
- 批量就是定长数组 `T[N]`；框架不做自动合并，那会改变时序语义。
- 负载缓冲是池化的定长扁平缓冲，只含契约字段，不含框架元信息。
- 接收侧要求到达长度不小于本端口契约尺寸；长度不足时读取返回失败而不抛异常。
- **单元边界由发送方决定**：一次 `TrySend` 就是一个单元；框架不按内容切分、不合并，也不解释单元里装了几条业务消息。

## 解析三段式

| 阶段 | 谁做 | 内容 |
|---|---|---|
| 声明期读取 | 框架必做 | 注册与实例化时一次性读取端口、类型引用、视图声明、计量块与解码器；运行期不重读 |
| 传输期解析 | 框架禁止 | 框架不读数据内容，投递只按绑定走，外加长度校验 |
| 呈现期解码 | 模块负责 | 解码器由模块提供并随类型注册，框架只回调 |

## 端口

- 端口属于模块声明，是数据流的端点；一个端口只有一个方向：发送或接收。
- 方向严格单向；双向通信由两个端口与两条单向网络表达。
- 两个发送端口相接不会产生数据流：连接可以存在，但没有数据可投递。
- 一个接收端口可以接受多条网络的输入；若需要区分来源，模块应自带字段或改用多个端口。
- 端口是否参与自动建网只由是否带有网络标签决定，没有端口级开关。

## 类型：没有代码锚定的约定

### 它是什么

一条**类型约定**是模块之间对"一个数据单元的字节长什么样、怎么读"的共同约定，由四样东西组成：

| 组成 | 作用 | 谁给 |
|---|---|---|
| 标识 | 身份：两个模块说的是不是同一种约定 | 模块作者，一个字符串 |
| 形状 | 布局：字段、原语、长度、顺序 | 模块作者，用契约形状组合出来 |
| 传递语义 | 流 / 消息 / 事件；只参与兼容判定 | 模块作者 |
| 计量块、解码器 | 可选：怎么算速率、怎么把一个样本解成数值 | 模块作者 |

**没有代码锚定**的意思是：不存在一个所有模块都引用的 CLR 类型、SDK 常量或中央 schema。两个模块声称"我们说的是同一种类型"，依据是**两份互相独立的声明逐字相同**——标识字符串相同、形状结构相同。框架手里只有从声明抄下来的**机械镜像**（标识、尺寸、语义、兼容声明、解码器句柄）：它是这份定义的一份副本，不是定义本身，也不是各模块共享的那一份。

因此：

- 类型不放进 `Sdk`，模块之间也不互相引用（模块只依赖契约层）。
- 新增一种类型不需要改框架、不需要改 SDK，也不会产生任何"注册表"。
- 两份声明之间没有编译期检查；分叉只会在加载期对账、建网判定或模块自检时暴露。

### 为什么这样设计

模块必须能**独立编译、独立分发**：一个模块只拿到作者包，看不到其它模块的源码，更不允许引用它们。若类型做成共享程序集类型，就得发布一个"类型库"并给它版本，等于在 SDK 之外再开一条公共契约轴，而模块与数据类型都不带版本。代价是重复与分叉风险，用三处机制补偿：

1. 加载期：同一实例内重复声明、口引用未声明类型、口形状与类型形状不一致，都会报 Issue；
2. 全场对账：同标识出现两种形状时，按"标识 + 两种形状 + 两个实例"报一条冲突；
3. 模块自检：把形状的可读描述做成**指纹**写进测试，联调前比对。

### 它不是什么

- 不是共享程序集类型，也不是接口或基类；
- 不是框架的注册表项，框架不保存类型的可执行定义；
- 不是带版本的 schema：改形状就是另一种类型；
- 不是"框架能判定两个类型语义相同"的依据：框架只比较标识与结构，不判断"这两个字段是不是同一个物理量"。

## 形状与结构指纹

形状是**结构签名**：原语、定长字节块、定长数组（元素为原语）、结构组合（字段名唯一、顺序即签名顺序），全部定长、无变长载荷。上限：字节块 1–4096 字节、数组 1–256 元素、结构嵌套深度 ≤ 4。

`Describe()` 把形状渲染成紧凑文本，这就是**结构指纹**：

```
{ seq: u64, value: f32 }
{ len: u16, data: bytes[1472] }
f32[64]
```

指纹有两个用途：

- 对账：两个形状结构相等 ⇔ 指纹文字相同（框架的冲突报告与连接提示都用它）；
- 自检：模块在测试里断言 `Shape.Describe()` 等于约定的那段文字，并断言 `SizeInBytes`；任何人改了字段、顺序或长度都会立刻失败。

## 设计一条约定

设计顺序是：先决定"一个单元是什么"，再决定字节怎么排，最后决定身份与计量。

### 1 单元语义

一个单元 = 一条业务消息、一帧采样、还是一批样本？框架不合并、不分片，所以单元粒度就是发送方每次 `TrySend` 的粒度。粒度太细（逐样本发）会放大小单元开销；粒度太粗会让一条坏数据连累整批。

### 2 布局

- 字段顺序就是签名顺序，偏移等于前面所有字段尺寸之和；**没有对齐填充**。
- 所有整数与浮点都是**小端**。
- 变长内容用 `len + 尾部补零` 表达：定长字节区，`len` 写有效字节数，剩余槽补零。
- 有效性用掩码表达（一位一个通道/槽），不要用"值为 0 就无效"这类隐式约定。
- 未使用的槽、保留位必须写零：否则同一份数据的指纹相同而字节不同，排障时会误判。
- 尺寸有上限（4096 字节的字节块、256 元素的数组）；超出就换一种组合，而不是突破上限。

### 3 身份

- 标识用 **PascalCase 短名**（如 `RawBytes`、`WaveformFrame`），不带作者前缀、不带版本；模块 ID 仍用 `作者/模块名`，两者不是一套命名。跨模块同名即同一类型，所以名字要稳定、尽量不易撞名。
- **没有版本字段**：字段、类型、顺序或尺寸发生变化，就换一个新的标识；不要"加字段向后兼容"。

### 4 传递语义

| 语义 | 含义 | 选择它意味着 |
|---|---|---|
| `Stream` | 按序的连续数据 | 单元边界由发送方决定，接收方把它当连续流 |
| `Message` | 独立成帧的消息 | 每个单元自成一体 |
| `Event` | 稀疏事件 | 通常间隔大、按发生投递 |

语义只参与**兼容判定**：跨语义不判兼容。它不改变投递行为，也不保证接收方"按报文边界"收到——单元边界仍然由发送方决定。

### 5 计量块

只用于观测，不参与建网与兼容：

- `PayloadLengthField`：哪个顶层整型字段写着本单元的有效字节数（`len` 这类）；
- `PayloadSizeInBytes`：固定有效载荷字节数（不需要逐单元读时用）；
- `SamplesPerUnit` / `ChannelCount`：一个单元里几个样本、每样本几通道；
- `NominalRateHz`：标称速率，用于"实测 vs 标称"的呈现。

长度字段必须是**整型原语且是顶层字段**；否则框架只能回落到静态尺寸（自检会报出来）。

### 6 解码器

解码器把"一个样本"解成一个 `double`，用于界面显示单值。适用：单值、或能折算成一个数的样本。不适用：多通道、多字段的结构——一个 `double` 装不下，强行给解码器只会让界面显示一个错误的数。这类类型不声明解码器，界面显示字节数，由模块自己的视图读原始字节。

### 7 不写进线上的东西

单位、量程、名称、颜色、绝对时间、把序号当时钟、首帧/末帧标志、运行开始/结束、框架元数据。它们属于模块配置、呈现或模块自己的协议层；写进类型会把"约定"变成"另一个模块的业务模型"。

### 8 演进

- 改形状 = 换标识。旧标识保持原样，新标识配新形状；两侧同时改、同时发。
- 不要保留"兼容读取旧形状"的分支：框架不做迁移，类型也没有版本。
- 0.x 期间允许破坏性变更，但**所有声明同一标识的模块必须同批更新**，否则会触发全场冲突。

### 设计检查表

- [ ] 一个单元是什么、多大、为什么定长，写清楚；
- [ ] 每个字段有名字、原语、偏移、单位含义（单位写在模块文档里，不写进字节）；
- [ ] 变长内容用 `len + 补零`，未用槽写零；
- [ ] 标识用 PascalCase 短名、无版本；
- [ ] 传递语义选对，并知道它只影响兼容；
- [ ] 计量块的长度字段是顶层整型；
- [ ] 解码器要么能表达，要么明确不给；
- [ ] 字段级约束（范围、保留值、互斥）区分“发送端必须保证”的线上不变量与消费方业务策略；会让整帧丢弃的约束必须写进契约页，并列为发送端义务；
- [ ] 指纹文字与 `SizeInBytes` 已写进模块测试；
- [ ] 新形状配了新标识。

## 声明与校验的机制

一条约定从代码到投递要过五道机械检查，任何一道都只做结构比较：

```
OnRegistered 声明
  → 实例镜像（每实例一份；重复标识 / 引用未声明 / 口形状≠类型形状）
  → 全场对账（同标识多形状，报一条冲突）
  → 建网判定（逐对：语义 → 形状 → 标识）
  → 绑定布局（取源口形状）
  → 计量读取（取类型形状的长度字段偏移）
  → 呈现解码（模块解码器回调）
```

### 声明期

- 声明只在 `OnRegistered` 发生一次；框架随后只读一次，转成不可变镜像。
- 同一实例内重复声明同一标识：报 Error，后者被跳过。
- 端口引用了本模块没有声明的类型：报 Warning，该口回退为"未声明类型"，兼容判定只比形状。
- 端口的形状与它引用类型的形状不一致：报 Error（传输按口形状算布局、计量按类型形状算偏移，两者必须同一份）。

### 全场对账

实例增删时，框架把当前全场实例声明过的类型按标识聚合：同一标识如果出现了两种以上形状，就报一条 Error，带上标识、两种形状的可读描述与两个实例。同一条冲突只报一次；冲突消失后再出现会重新报。

这条对账解决的是"两个模块各写一份声明、形状分叉"的情形——没有它，用户只会看到建网时的"形状不一致"，看不出真正原因是同一个标识有两种形状。

### 建网期

逐（源，宿）对判定，规则见“兼容判定”一节。被拒绝的那一对记录原因，其余对不受影响。

### 投递期

绑定持有**源端口的布局**：字段偏移、尺寸都来自发送口声明的形状，不来自类型声明的形状（两者在加载期已被要求一致）。多播时每个宿拿一份独立缓冲。

### 计量期

框架从**源实例声明的类型**取计量块，按类型形状的布局解析长度字段：偏移在加载期算好，运行期逐单元读一个整型、夹到 `[0, 契约尺寸]`。字段不存在、原语不对、字节不够 ⇒ 回退静态尺寸，不把"声明写错"表现成"有效速率恒为 0"。

### 呈现期

界面按显示源声明取值：有解码器就用解码器，没有就按原语回退（旧模块形态），两者都没有则显示"未声明类型 + 字节数"，不猜内容。语义标签（单位、量程、精度）只用于展示。

### 失败面

| 现象 | 原因 | 在哪看 |
|---|---|---|
| 连不上，提示形状不一致 | 两侧形状不同（字段名、原语、长度或顺序不同） | Issue（网络/契约） |
| 连不上，提示标识不同 | 两侧声明了不同标识，即使形状相同也不兼容 | Issue（网络/契约） |
| 加载期报"同一标识两种形状" | 两个模块各自声明了同标识但形状分叉 | Issue（类型台账） |
| 加载期报"口形状与类型形状不一致" | 同一个模块里类型与端口写了两份不同形状 | Issue |
| 有效速率恒等于搬运字节速率 | 长度字段没声明、或声明了但字段名/原语不对 | 模块自检、拓扑诊断 |
| 界面显示字节数而不是数值 | 类型没有解码器，或显示源没声明值类型 | 端口标记悬停、模块窗口 |

建网失败的具体原因以 **Issue 面板**为准；状态栏只显示端口标签/操作结果，不承载契约差异。

## 布局与读写纪律

- **布局**只提供顶层字段的偏移；嵌套结构由模块按整体字节块自行解析。
- **写**：先把单元清零，再按字段写值（避免残留旧字节）；整数与浮点用小端；字段名拼错在开发期会抛异常，所以字段名与声明必须来自同一份常量。
- **读**：先确认到达长度不小于契约尺寸；按 `len` 夹取有效内容；**不得按 `0x00` 截断**；掩码、通道数、未用槽的归零规则由模块自己校验。
- **热路径**：不抛异常、不分配；长度与掩码这类"可能不合规"的读取用返回 `false` 的 `Try*` 形式，由调用方决定丢弃与记账。
- **发送**：载荷短于契约尺寸会被丢弃并记"载荷非法"；长于契约尺寸会被截断（框架不报错）。
- **接收**：长度不足的单元不会进回调；模块内部丢弃（解不出、校验不过）用上下文的上报口记一次，不要自己攒计数器。

## 兼容判定

判定逐（源，宿）对进行，不是整条网络：

1. 传递语义必须一致。
2. 形状必须完全一致：字段名称、原语种类、数组与字节块长度、字段顺序与数量全同。
3. 双方都声明类型时再比较标识：同标识兼容，不同标识不兼容。
4. 任一方未声明类型时只按第 2 条判定。

没有强制连接的放行路径；需要连接时把两侧声明成同一类型，或插入转换模块。框架不做自动转换。

## 在用约定：原始字节 RawBytes

`RawBytes` 是使用最广的一条约定，也是"没有代码锚定"的完整例子：没有共享常量、没有 SDK 类型，四个接入模块与三个数据模块各自在自己的代码里写同一份声明。其它约定（例如波形帧 `WaveformFrame`）采用同样的机制，由各自模块维护；波形帧的完整契约见[波形帧约定](waveform-frame.md)。

### 身份

| 项 | 值 |
|---|---|
| 标识 | `RawBytes`（PascalCase 短名，无前缀、无版本） |
| 形状 | `{ len: u16, data: bytes[1472] }` |
| 尺寸 | 1474 B |
| 传递语义 | `Stream` |
| 解码器 | 不声明（字节块不是一个数） |

### 布局

| 偏移 | 字段 | 形状 | 字节 | 语义 |
|---:|---|---|---:|---|
| 0 | `len` | u16 | 2 | 本单元有效字节数，0–1472 |
| 2 | `data` | bytes[1472] | 1472 | 有效内容；不足部分补零 |

### 规则

- `len` 是**字节数**，不是字符数；`0x00` 是合法数据，不是终止符。
- 接收方按 `len` 切片，**禁止按 NUL 截断**；`len` 超出 1472 即视为非法帧。
- 尾部补零只是定长填充；比较内容时按 `len` 比，不按整块比。
- 超过 1472 字节的内容由**模块自己拆包**（文本发送器按字符边界拆），契约不上调。
- 计量块声明 `PayloadLengthField = "len"` ⇒ 有效载荷字节速率是真实有效字节；搬运字节速率仍是每单元 1474 字节。

### 谁声明

文本发送器、HEX 发送器、数据监视器，以及串口 / TCP 客户端 / TCP 服务端 / UDP 四个接入模块。每个模块在自己的 `OnRegistered` 里声明同一标识与同一形状；四个接入模块各自带一份组帧实现。约定相同是**约定**，不是共享代码。

### 组帧与拆帧

组帧：清零整块 → 写 `len`（小端）→ 拷贝有效内容。拆帧：确认长度 ≥ 1474 → 读 `len` → 越界即失败 → 取 `data[0..len]`。

### 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把 `len` 当成字符数 | 中文内容被截断 | `len` 是 UTF-8 字节数 |
| 把 `data` 当零终止字符串 | 内容里合法的 `0x00` 之后全部丢失 | 按 `len` 切片 |
| 为了少搬字节把容量改成 1024 但仍叫 `RawBytes` | 同标识出现两种形状，全场冲突、连不上 | 容量变化就是新形状；要么保持 1472，要么换新标识 |
| 一次发超过 1472 字节 | 超出部分被截断 | 模块内部拆包 |
| 期待界面显示数值 | 界面显示字节数 | `RawBytes` 没有解码器；由模块自己的视图读字节 |
| 用 `len` 判断 TCP 报文边界 | 边界不可靠 | 流本身没有报文边界；模块自己组帧 |

## 计量块

计量块随类型声明，字段全部可选，每项都有默认语义：

| 字段 | 默认语义 |
|---|---|
| 有效载荷字节数 | 未声明即按契约尺寸计算 |
| 有效长度字段名 | 未声明即不逐单元读取，按静态尺寸计算 |
| 每单元样本数 | 未声明即按单元计，不换算样本 |
| 每样本通道数 | 未声明即不区分通道 |
| 标称速率 | 未声明即无标称值 |

速率按口径分档：单元速率按源计，搬运字节速率按宿计，有效载荷与样本速率由声明换算。计量块只用于观测与呈现，不参与建网与兼容判定。
