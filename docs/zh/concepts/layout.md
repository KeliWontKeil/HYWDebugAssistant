# 目录与发布包

本页回答“装完之后磁盘上有什么、哪些目录可以动”。

## 程序目录

程序目录就是可执行文件所在的目录。所有数据都在这一棵树下，不写系统用户目录，因此整个目录可以整体搬走。

| 路径 | 内容 | 能否删除 |
|---|---|---|
| 可执行文件与依赖 | 宿主程序、框架程序集、运行时配置 | 否 |
| `modules\` | 内置模块包，一个子目录一个模块 | 否；删掉对应模块即消失 |
| `modules\external\` | 外部导入的模块包 | 可以；该模块随之消失 |
| `resources\i18n\` | 框架文本表 | 否；缺了界面显示键名 |
| `resources\icons\` | 框架图标 | 否；缺了显示占位 |
| `resources\seeds\` | 出厂种子，只在目标缺失时投放 | 可以；不再投放 |
| `sdk\` | 作者工具链：五个作者包与四个样例源码 | 可以；程序运行不需要它 |
| `settings\` | 设置文件与外观主题 | 可以；回到内置默认值 |
| `composites\` | 组合文件 | 可以；自定义组合丢失 |
| `workspace\` | 工作区快照与资产 | 可以；下次启动从空现场开始 |
| `logs\` | 日志目录（日志能力尚未落地，路径先预留） | 可以 |

删除 `settings\` 不会损坏程序：下次启动使用内置默认值并记录一条诊断。删除前建议先备份。

发布包包含程序层、`sdk/`（作者包与样例源码）与 `resources/`，不含 `settings\`、`workspace\`、`composites\`、`logs\` 与 `modules\external\`；这些目录在首次使用时按需建立。

`sdk/` 只是给模块作者的工具链：删掉它不影响程序运行，但外部作者会失去获取作者包与样例的途径。

## 功能根

三类持久化对象与运行期目录都在程序目录下，路径只在路径解析器里定义：

| 对象 | 位置 | 内容 |
|---|---|---|
| 应用设置 | `settings/settings.json` | 语言、外观、窗口行为、数据面参数、快捷键等 |
| 组合件 | `composites/<组合名>/composite.json` | 一次保存的模块组合：模块集合、连接、配置、位置、封面与资产 |
| 工作区 | `workspace/workspace.json` | 当前工作区快照，用于退出保存与重启恢复 |

```
<程序目录>/modules/            内置模块包
<程序目录>/modules/external/   外部导入模块包
<程序目录>/composites/         组合件包
<程序目录>/settings/           应用设置与主题
<程序目录>/workspace/          工作区快照与资产
<程序目录>/logs/               日志
<程序目录>/resources/seeds/    出厂种子
```

应用设置与组合件完全分离：设置不随组合件保存，组合件也不写进设置目录。

## 出厂种子

只读的出厂内容放在 `resources/seeds/`，与目标目录同构：投放就是按相对路径合并进程序目录。

- 单文件在目标不存在时才复制；叶子目录作为一个投放单元整体复制。
- 已投放过的单元记录在设置里，用户删除后不会复活。
- 只做整单元投放，不改写已存在的内容；失败记录警告并撤掉本次半成品。
- 出厂设置基线不写入仓库：发布时由程序自身的命令从代码默认值生成。
