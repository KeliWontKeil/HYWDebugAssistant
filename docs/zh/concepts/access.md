# 外部接入

外部接入是**框架提供给模块的一套抽象接口**：模块声明"用哪个外部标准"，框架按标准创建会话、持有适配器与参数类型；数据只有**原始字节块**。

当前有四个标准实现（串口 / TCP 客户端 / TCP 服务端 / UDP），它们是这套接口的实现，不是另一种模块。

## 与模块间通信的边界

| | 框架-外部接口 | 模块-模块通信 |
|---|---|---|
| 承载物 | 一套抽象接口 + 适配器 + 会话 | 端口 + 数据类型 + 数据包 + 组帧 |
| 模块侧做什么 | 声明标准标识；请求开/关；读写**原始字节**；读快照 | 声明类型/口/角色；组帧与拆帧；参与建网 |
| 框架侧做什么 | 解析标准、建会话、参数类型、状态与计量、丢弃账本 | 只校验连接（语义 / 形状 / 标识），不持有类型 |
| 有没有数据包逻辑 | **没有**，也不得出现 | **有**，且只在这里 |

因此：模块**不为外部接入声明数据类型**，也不在接入面上组帧。把字节变成数据单元、再投给端口，是模块自己的事。

## 模块看到的接口

| 动作 | 说明 |
|---|---|
| `RequestOpen` / `RequestClose` | 只发请求；实际打开/关闭由框架在实例循环里执行，模块不直接操作连接 |
| `SetReceiveHandler` | 回调投递（`ReceiveMode.Push`），框架在实例线程上调用 |
| `TryRead` | 主动取一个字节块（`ReceiveMode.Pull`）；与回调**互斥**，同一会话只有一个消费者 |
| `Write` | 写一个字节块（有界等待；失败返回 `false` 并计入丢弃） |
| `GetSnapshot` | 状态、端点、最近失败、收发/丢弃计数——**唯一事实源**，没有事件面 |
| `ClearCounters` | 只清计数，不动队列、连接数与故障态 |
| 会话推进 | **框架负责**：实例循环推进开关/取数/探活；模块不调用泵，Pull 模式在 `OnStep(Session)` 里读 |

**块边界不承诺**：一次读到的是"一块字节"（长度不超过声明上限），它是不是一条完整报文、被切在哪里，由标准实现决定，模块**不得依赖**块边界。需要报文语义时，由模块自己的协议层在字节流上重组。

## 状态与计量

快照里的计数口径是**有效字节**；丢弃分三类且各自闭合：

- 发送侧：写失败 + 发送积压挤旧 + 发送积压过期；
- 接收侧：接入队列满 + 适配件溢出 + 超长 + 过期；
- 停止清尾**不并入**运行期丢弃（那是拆除时队列里剩下的单元）。

计数在实例生命周期内累计，重开会话不清零；唯一的归零路径是清空计数。

## 四个标准

| 标准标识 | 端点语义 | 适合 |
|---|---|---|
| `serial` | 打开一个串口，字节流双向 | 点对点设备、调试口 |
| `tcp-client` | 主动连接一个 `地址:端口`，一条连接一个会话 | 设备/服务端主动连 |
| `tcp-server` | 监听端口，多条连接合并为一路字节流，快照给出连接数 | 多客户端汇聚 |
| `udp` | 绑定本地端口，一次接收一个数据报；发送给默认收件人 | 轻量数据报 |

参数类型由框架持有（串口参数、地址端口、超时等），模块**不引用**它们；模块只在自己的配置读取里按需读字段。

## 扩展新标准

新增标准是**框架侧**的工作：在外部接入层实现适配件与参数类型、登记到标准目录，模块不改。模块声明未知标准标识时，框架报错并让该接入保持未接线状态，其余部分照常运行。
