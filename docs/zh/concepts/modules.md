# 模块机制

## 模块是什么

模块是用户可感知的功能单元。实现上一个模块只有三样东西：

- **入口接口**：框架按接口调用，模块不继承框架基类。
- **注册钩子**：在注册时通过上下文声明数据类型、角色与内部处理顺序；端口在模块视图 XAML 的 `ModuleView.Ports` 声明。
- **可选 step 接口**：声明是否需要数据/命令/会话驱动的单步（`OnStep`），框架在实例专属线程按工作原因调用；周期由模块通过 `IModuleContext.Timers` 创建定时器，模块不拥有循环、不等待、不建系统定时器。

模块不持有框架对象引用，只能通过上下文上报状态、读写自身配置、登记活动；也不能反向查询其它模块是否存在。

声明面（写什么、按什么顺序、会被拒的形态）见[声明面](../module-dev/contracts.md)。

## 模块—框架边界

框架与模块的职责按“谁拥有事实”划开：

| 事实 | 拥有者 | 模块能做什么 |
|---|---|---|
| 实例线程、队列、绑定、生命周期状态机 | 框架 | 只实现钩子与单步，不自建线程/定时器/循环 |
| 声明面（类型、角色、视图键、接入名、端口） | 模块 | 类型/角色/视图键/接入名在 `OnRegistered`；端口在视图 XAML；加载期各读一次，运行期不再改 |
| 数据的字节布局与语义 | 模块 | 用契约定长形状读写；框架不解析内容 |
| 外部设备会话、参数类型、探活 | 框架 | 声明标准、发开/关请求、读写原始字节 |
| 显示缓冲、视图状态、窗口 | 框架 | 经显示/视图/外观通道发布与读取，不直接操作控件 |
| 诊断与 Issue 的呈现 | 框架 | 报告事实；框架决定怎么展示 |

框架**不提供**：其它模块的查询或引用、跨模块直接调用、把 UI 当数据通道、绕过声明面的“强制连接”、自动重试/降级。模块之间只经端口与数据类型通信；模块与框架之间只有 `IModuleContext` 这一份接口。

线程与异常边界：`OnRegistered` 在创建方的线程（实例线程尚未启动）；其余钩子、`OnStep`、接收回调与定时器 Tick 都在该实例的专属线程，彼此不并发。钩子与回调中的异常不得逸出——框架会捕获并转 Issue，但行为已不可预期。

## 模块标识

标识是两段字面量 `作者/模块名`：各段小写、不得为空、不得以连字符开头。标识不含版本；同一个标识只有一个注册项，"新旧"由包内容决定。

## 包与加载

- 一个包一个模块，`module.json` 是包清单。
- 只扫描程序目录下的 `modules/`（内置）与 `modules/external/`（外部导入），每个根只扫直接子目录。
- 导入外部包时先校验清单与同标识冲突，再复制进 `modules/external/`；同标识已存在时拒绝导入，不静默覆盖。
- 已载入的程序集不可替换：改动模块代码的语义是重新构建并重启应用，不提供热重载。
- 内置模块是预装的包，没有任何结构特权，与外部包走同一条发现与加载路径。

## 生命周期

| 钩子 | 时机 | 语义 |
|---|---|---|
| `OnRegistered` | 实例创建、成员实例化完成 | 声明类型、角色与内部流；端口在视图 XAML；此时数据尚未流动 |
| `OnActivated` | 进入活动态 | 开始业务活动 |
| `OnDisabled` | 进入停用态 | 暂停数据流，内部处置由模块决定 |
| `OnEnabled` | 从停用恢复 | 恢复业务活动 |
| `OnConfigurationChanged` | 配置更新 | 热生效；框架不提供“请求重建”，需要重建的调整由模块自己完成 |
| `OnRemoved` | 移除前、线程停止前 | 释放模块内部资源 |

`OnRegistered` 在实例线程创建前由创建方（管理线程）调用；其余五个生命周期钩子由框架在实例专属线程调用，与 `OnStep`、接收回调同线程。异常不得逸出边界，由框架捕获并转为诊断。模块不得自建线程或系统定时器；周期用 `IModuleContext.Timers` 创建定时器，框架负责调度、暂停/恢复与释放；等待由框架承担。

## 端口与角色

- 端口是网络的端点，也是唯一的接口与建网单位；方向只有发送与接收两态。端口声明在视图 XAML 的 `ModuleView.Ports`（名称/方向/类型/边/偏移）。
- 端口名在模块内唯一且稳定，连接锚定为 `实例ID.口名`。
- 端口可以引用本模块声明的数据类型；不声明时按形状判定兼容。
- 角色是模块声明的功能分块，包含功能名、类型、输入端口集合与输出端口集合；一个角色的输入与输出承载同一种类型。
- 一个端口最多属于一个角色；内部处理顺序只表达"角色到角色"的先后，零声明即零连线。
