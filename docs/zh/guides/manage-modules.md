# 模块管理

把模块放进现场、导入外部模块包、移除实例。模块目录与每个模块的用法见[模块](modules/index.md)。

## 打开

活动栏第一项「模块清单」在侧栏打开本页，包含搜索框、分类按钮、模块列表与底部按钮行。

- 分类：全部模块 / 端口 / 数据源 / 终端 / 转换器 / 其他。分类由模块声明的标签推导；「全部模块」按这些分类分区排列。`HEX-字符串转换器` 是离线小工具、不操作数据流，归入「其他」。
- 列表：每行左侧是预览占位，右侧是名称与说明，第二行标注来源（内置 / 外部）。
- 状态行在列表下方，显示最近一次操作的结果；失败时到 Issue 面板看详情。

## 加入现场

1. 用搜索框按名称或描述过滤，或点分类按钮缩小范围。
2. 选中一行，点「加入工作区」；也可以直接双击加入。
3. 状态行显示「已加入：模块名」，桌面上出现该模块的窗口。

新窗口默认落在外壳附近，可以自由摆放并与其他模块拼接。

## 导入外部模块包

1. 点「导入模块…」。
2. 选择包含 `module.json` 的目录（选它所在的上一级目录也可以）。
3. 框架校验清单、文件与同标识冲突，通过后把包复制到程序目录的 `modules\external`。
4. 列表中出现来源为「外部」的模块；如果提示「· 需重启应用生效」，点「重新加载」。

导入失败时状态行提示「导入失败」，具体原因在 Issue 面板。常见原因：同标识的包已存在（先移除旧包）、缺少清单字段、清单声明的资源目录不存在、实现程序集缺失。

## 重新扫描与重新加载

| 操作 | 作用 | 何时用 |
|---|---|---|
| 重新扫描 | 重新扫描默认模块目录，加载新增的模块包，不重启 | 手工把包放进 `modules\external` 之后 |
| 重新加载 | 保存当前工作区并重启应用，重新加载全部模块 | 包内容变了（重新构建过），需要新程序集生效 |

程序集不能被替换：改动模块代码后必须重新加载或重启应用。

## 移除模块

- 模块窗口右上角按钮簇的「关闭」= 移除该模块实例。窗口按钮的提示写明「关闭窗口会移除该模块实例」。
- 「隐藏」不等于移除：窗口消失但模块继续运行，在「交互」页点「显示全部」恢复。
- 移除会断开该实例参与的网络，实例的配置不再随组合件保存。

## 模块缺失与替代

打开组合件时如果缺少某个模块包，现场会出现一个占位实例，标题显示「占位」。

1. 在模块清单里选中一个可用的替代模块。
2. 打开「拓扑诊断」，找到该占位实例，点「指定替代」。
3. 替代后该位置由选中的模块接替，占位实例消失。
