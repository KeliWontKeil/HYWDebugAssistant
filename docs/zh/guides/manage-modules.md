# 模块管理

把模块放进现场、导入外部模块包、移除实例。模块目录与每个模块的用法见[模块](modules/index.md)。

## 打开

活动栏第一项「模块清单」在侧栏打开本页，包含搜索框、分类按钮、模块列表与底部按钮行。

- 分类：全部模块 / 端口 / 数据源 / 终端 / 转换器 / 其他。分类由模块声明的标签推导；「全部模块」按这些分类分区排列。六个分类按钮在主窗口宽度内等分，按钮之间留 4 DIP 间隔，窗口变宽/变窄时一起伸缩；任一选中态的边框都不会被相邻按钮或窗口右缘盖住。`HEX-字符串转换器` 是离线小工具、不操作数据流，归入「其他」。
- 列表：每行左侧是预览占位，右侧是名称与说明，第二行标注来源（内置 / 外部）；选择行只显示整行底色，不再画条目边框。列表宽度跟随主窗口 B 区，不写固定宽度。
- 状态行在列表下方，显示最近一次操作的结果；失败时到 Issue 面板看详情。

## 加入现场

1. 用搜索框按名称或描述过滤，或点分类按钮缩小范围。
2. 选中一行，点「加入工作区」；也可以直接双击加入。
3. 状态行说明已加入哪个模块，桌面上出现该模块的窗口。

新窗口默认落在目标屏的中央放置区（约工作区中央 75%，左边界尽量贴外壳右侧）。放置区内按“自上而下、从左到右”铺开；第一层排满后，第二层仍在同一区域按同样方式铺开，层与层之间有坐标偏移，避免同尺寸模块恰好完全重合。层数不固定，只有几何上放不下时才兜底。不会自动排到屏幕角落；已有布局和用户手动拖动不受这个区域限制。

## 导入外部模块包

1. 点「导入模块…」。
2. 选择包含 `module.json` 的目录，或包含多个包的**外层文件夹**（向下最多 3 层；隐藏/系统/重解析点目录跳过）。
3. 框架校验清单、文件与同标识冲突，通过后把包复制到程序目录的 `modules\external`；多个包逐个导入，单个失败不中断其余。
4. 列表中出现来源为「外部」的模块；如果页面提示需要重启应用，点「重新扫描」，扫描发现需重启的包后会弹一次重启确认。

导入失败时页面底部状态说明导入失败，具体原因在状态提示与 Issue 面板。常见原因：同标识的包已存在（先移除旧包）、缺少清单字段、清单声明的资源目录不存在、实现程序集缺失。

也可以把文件夹直接拖进应用窗口：包含 `module.json` 的目录按模块包导入；包含 `composite.json` 的目录按组合导入；外层文件夹会一次导入其中 2–3 层内的多个模块包与组合包。拖入后应用会切到对应的模块清单/组合页面，并在页面底部说明已导入哪些内容或给出错误；无法识别时同样显示在页面底部，而不是应用底部状态栏。拖入只做导入，不会自动把模块放进现场。

压缩包（`.zip`）本轮不支持；需要时先解压成文件夹再导入。

## 重新扫描

| 操作 | 作用 | 何时用 |
|---|---|---|
| 重新扫描 | 重新扫描默认模块目录，加载新增的模块包，不重启；如果扫描后发现包内容变化、需要新程序集生效，会自动弹一次「保存并重启」确认 | 手工把包放进 `modules\external`，或重新构建过包之后 |

只有一个重扫入口，不再有单独的「重新加载」按钮。程序集不能被替换：改动模块代码后必须重启应用；确认框里选取消则只更新列表、不重启。

## 移除模块

- 模块窗口右上角按钮簇的「关闭」= 移除该模块实例。窗口按钮的提示写明「关闭窗口会移除该模块实例」。
- 「隐藏」不等于移除：窗口消失但模块继续运行，在「交互」页点「显示全部」恢复。
- 移除会断开该实例参与的网络，实例的配置不再随组合件保存。
- 新加模块默认落在中央放置区：正常以主窗口右侧为左边界、约占工作区 75%，四周留边；区内按“自上而下、从左到右”铺开。第一层排满后第二层仍在同一区域按行列铺开，层间有坐标偏移，不是直接叠一个点；层数不设固定上限。已有布局和手动拖动不受限制。

## 模块缺失与替代

打开组合件时如果缺少某个模块包，现场会出现一个占位实例，标题显示「占位」。

1. 在模块清单里选中一个可用的替代模块。
2. 打开「拓扑诊断」，找到该占位实例，点「指定替代」。
3. 替代后该位置由选中的模块接替，占位实例消失。
