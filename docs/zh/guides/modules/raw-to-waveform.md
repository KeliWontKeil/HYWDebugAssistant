# 文本→波形转换器

把原始字节流按所选协议解析成波形帧：接在文本发送器、串口或网络模块后面，把设备发来的文本帧 / VOFA+ 帧变成波形显示器能画的数据。

## 界面

内容宽 360、高 144（窗口 402×194，含外框），固定尺寸。顶行是协议、组号（短标签）与采样率（含 `Hz`），说明两行紧随其后；帧信息（帧头帧尾、前缀）纵向堆叠、按协议折叠；统计只有一行（通道数量 / 已转换 / 丢弃 + 清空图标），状态句单独贴底。

| 区域 | 内容 |
|---|---|
| 协议 | 自定义文本帧 / VOFA+ FireWater / VOFA+ JustFloat（设置项，选中即生效）；下方两行随协议切换 |
| 协议说明 | 第一行是该协议的抽象定义，第二行是一个帧示例；只在主应用里随选择变化，预览器显示文本帧的默认内容 |
| 输入写回 | 组号、采样率、帧头、帧尾、前缀都是**输入源**：逐键写入、模块下一拍读取并应用，不需要回车或失焦；非法值保持上一次的有效值 |
| 通道组编号 | 写入每个波形帧的组号（默认 1，必须 ≥1）；一个模块只产生一个组；0 非法，不发送，不会兜底成 1 |
| 采样率 | 写入每个波形帧的声明速率；输入框右侧显示单位 `Hz` |
| 文本帧参数 | 帧头、帧尾是**十六进制字节串**（空白分隔、每段两位，如 `61 62`），两段都不得为空，只在该协议下显示 |
| FireWater 前缀 | **前缀过滤**：留空 = 接受任意前缀（有前缀就剥掉）；填写后只解析前缀完全相同的行（区分大小写），其余行直接跳过 |
| 统计行 | 一行放三组：通道数量（只读）、已转换、丢弃；右侧 16×16 图标按钮清空统计（悬停提示"清空统计"） |
| 状态 | 最下方单独一行：就绪 / 转换中 / 帧头帧尾十六进制错误；协议不匹配或坏帧直接跳过，不计数、不报告 |

## 协议

| 协议 | 帧格式 | 说明 |
|---|---|---|
| 自定义文本帧 | `[帧头字节][空格][数据一][空格]…[帧尾字节]`，例 `61 62 1.2 4.35 3.6 63 64` 的线上形态是 `ab 1.2 4.35 3.6 cd` | 小数位数任意；帧头帧尾可含不可输入字节（如 `0A FF`）；无校验 |
| VOFA+ FireWater | `[前缀:]<值>,<值>,…\n` | 逗号分隔的文本行；`image:` 开头的图片前导帧被忽略 |
| VOFA+ JustFloat | 小端 f32 数组 + 帧尾 `00 00 80 7F` | 二进制；通道数由帧长推出 |

一帧最多 64 个通道。识别不出的字节被丢弃并计入「丢弃」，不会让模块停住。

## 状态句

| 状态句 | 意思 |
|---|---|
| 就绪 | 已登记协议，等待数据 |
| 转换中 | 正在持续出帧 |
| 帧头/帧尾必须是两位一组的十六进制（如 0A FF） | 两段没有可用的有效字节，不会解析 | 按两位一组填写 |
| 帧头/帧尾格式无效，仍使用上一次有效值 | 当前文本非法（空、位数不对、非十六进制） | 改正后自动恢复；输入框同时标红 |
| 组号必须是未占用的正整数（从 1 开始） | 组号输入为 0、非数字或越界；不解析、不发送，也不兜底成 1 | 改成 ≥1 的整数 |
| — | 协议不匹配、帧头帧尾不完整、坏数字都直接跳过：这是可预见行为，不计失败、不出状态句；后续帧照常解析 |

## 旧值迁移

旧版本把帧头/帧尾当文本保存（UTF-8 字节）。第一次激活时，模块会把旧文本按 UTF-8 转成**大写两位、空格分隔**的十六进制写入新值（`ab` → `61 62`，`cd` → `63 64`），随后清空旧值，迁移只发生一次。迁移按文本字节解释，**不会**把 `ab` 当成 `0xAB`。新模块默认 `61 62` / `63 64`。

## 典型用法

- 文本发送器 → 原始 → 波形 → 波形显示器：验证一条完整的「文本帧 → 波形」通路。
- 串口 / TCP / UDP → 原始 → 波形 → 波形显示器：把设备发来的帧直接画成曲线。
- 与「波形 → 原始」背靠背：`文本发送器 → 原始 → 波形 → 波形 → 原始 → 数据显示器`，用来核对编码与解析是否可逆。
