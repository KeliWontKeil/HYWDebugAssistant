# 原始 → 波形

把原始字节流按所选协议解析成波形帧：接在文本发送器、串口或网络模块后面，把设备发来的文本帧 / VOFA+ 帧变成波形显示器能画的数据。

## 界面

内容宽 360、固定尺寸，控件坐标固定；切换协议时只隐藏不适用的参数行，其余行不移动。

| 区域 | 内容 |
|---|---|
| 协议 | 自定义文本帧 / VOFA+ FireWater / VOFA+ JustFloat；下方两行随协议切换 |
| 协议说明 | 第一行是该协议的抽象定义，第二行是一个帧示例；只在主应用里随选择变化，预览器显示文本帧的默认内容 |
| 通道组编号 | 写入每个波形帧的组号（默认 1）；一个模块只产生一个组；0 是保留值，模块会兜底为 1 |
| 采样率 | 写入每个波形帧的声明速率，单位 Hz |
| 文本帧参数 | 帧头、帧尾（两段都不得为空），只在该协议下显示 |
| 通道数量 / 状态 | 最近一帧的通道数（只读）与状态句 |
| 计数 | 已转换帧数、丢弃单元数；右侧 16×16 图标按钮清空统计（悬停提示"清空统计"） |

## 协议

| 协议 | 帧格式 | 说明 |
|---|---|---|
| 自定义文本帧 | `[帧头][空格][数据一][空格]…[帧尾]`，例 `ab 1.2 4.35 3.6 cd` | 小数位数任意；帧头帧尾长度任意；无校验 |
| VOFA+ FireWater | `[前缀:]<值>,<值>,…\n` | 逗号分隔的文本行；`image:` 开头的图片前导帧被忽略 |
| VOFA+ JustFloat | 小端 f32 数组 + 帧尾 `00 00 80 7F` | 二进制；通道数由帧长推出 |

一帧最多 64 个通道。识别不出的字节被丢弃并计入「丢弃」，不会让模块停住。

## 状态句

| 状态句 | 意思 |
|---|---|
| 就绪 | 已登记协议，等待数据 |
| 转换中 | 正在持续出帧 |
| 帧头与帧尾不能为空 | 自定义文本帧的两段参数为空，不会解析 |
| 解析失败累计 N 帧 | 坏帧被跳过；后续帧仍会继续解析 |

## 典型用法

- 文本发送器 → 原始 → 波形 → 波形显示器：验证一条完整的「文本帧 → 波形」通路。
- 串口 / TCP / UDP → 原始 → 波形 → 波形显示器：把设备发来的帧直接画成曲线。
- 与「波形 → 原始」背靠背：`文本发送器 → 原始 → 波形 → 波形 → 原始 → 数据显示器`，用来核对编码与解析是否可逆。
