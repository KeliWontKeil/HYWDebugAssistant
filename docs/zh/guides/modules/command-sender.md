# 指令发送器

一个列表里的多组字符串发送器：每行一条逻辑指令（文本或 HEX），按勾选顺序单发、全部发送或连续发送。输出照旧是 `RawBytes`，可以直接接到串口 / TCP / UDP / 数据监视器。

窗口 400×400，只占一个发送口（下边）。列表最多 256 行；行内发送、行内删除，勾选顺序保存在实例里，重开窗口仍按原顺序发送。

## 界面

| 区域 | 内容 |
|---|---|
| ＋（新建） | 加号图标；加一行，默认标签「指令 N」、内容为空、HEX 关闭、CR/LF 都勾选、不自动勾选 |
| 全部发送 | 按勾选顺序发送全部勾选项；合并发送时一次拼成一条，不合并时按间隔逐条发送；没有勾选、或勾选项里有 HEX 非法时禁用 |
| 合并发送 | 勾选后「全部发送」把全部勾选项合并成一条；「连续发送」每个间隔合并发送一次。默认不勾选 |
| 连续发送 | 按间隔发送勾选项；不合并时每拍一条、按勾选顺序循环，合并时每拍发送全部勾选项的合并内容；需要至少一条勾选、全部合法、间隔大于 0 |
| 间隔 | 连续发送与逐条全部发送的周期（毫秒，1–86400000）；无效时字段标红。合并 + 全部发送不使用间隔 |
| 搜索框 | 占位文字「搜索指令标签...」；按标签或内容过滤行，不影响勾选和发送 |
| 导入 / 另存为 | 读写指令集 JSON |
| 列表 | 每行：序号勾选框、标签、内容、HEX、CR/LF、发送、删除 |
| 状态行 | 最近一次操作的结果或错误句；右侧是累计已发送包数 |

## 行内字段

| 控件 | 行为 |
|---|---|
| 序号勾选框 | 勾选后显示 1 基序号；序号就是发送顺序。取消后其余序号顺延 |
| 标签 | 单行文本，只用于识别和搜索 |
| 内容 | 多行文本，自动增高；文本按 C 转义解释，HEX 按每段两位解析 |
| HEX | 勾选时内容按 HEX 解析、CR/LF 禁用；切换时尝试转换内容 |
| CR / LF | 只决定按 Enter 写入什么、以及把已有真实换行归一成什么；发送时**不追加**任何结尾 |
| 发送 | 只发这一行；该行 HEX 非法时按钮禁用 |
| 垃圾桶 | 删除这一行，并清空该行的值和勾选 |

CR/LF 与文本发送器同口径：两个都勾 = `\r\n`，只勾 CR = `\r`，只勾 LF = `\n`，都不勾 = 不写换行。真实换行发出去仍是真实换行；转义写出的 `\r` / `\n` 是显式字符。

## 发送与拆包

- 全部发送严格按勾选顺序，不按列表顺序，也不按标签排序。
- **合并发送**：勾选后把全部勾选项的编码后字节按顺序拼成一条逻辑内容；超过 1472 字节仍按容量拆成多个包连续发出，命令之间没有额外间隔。
- **不合并发送**：勾选 >1 条时首条立即发，后续按「间隔」逐条发送；勾选 =1 条时立即发，不要求间隔。发送过程中主「全部发送」和行内「发送」禁用。
- 连续发送不合并时每拍发一条、按勾选顺序循环；合并时每拍把全部勾选项合并发一次。
- 空内容不发送，也不报错；整批都为空时状态行不写「已发送」。
- 单包有效内容上限 1472 字节，载荷为 `{ len: u16, data: bytes[1472] }`。
- 文本按字符边界拆包，多字节字符不会被切开；HEX 按字节每 1472 个一包。
- 一条逻辑指令可以对应多个数据包；已发送计数按**数据包**累计。
- 连续发送与全部发送互斥：连续发送运行期间「全部发送」禁用；逐条发送期间连续开关禁用。勾选/顺序/列表结构在逐条发送中变化会取消本次发送。

## HEX 与转换

- 勾上 HEX：把当前文本按 C 转义解释后以 UTF-8 编码，再写成大写、空格分隔的 HEX（例如 `Hi` → `48 69`）。
- 取消 HEX：把 HEX 解析成字节，严格按 UTF-8 解码，再把控制字符写成 `\r` / `\n` / `\t` / `\xHH`，保证再勾上 HEX 时字节不变。
- HEX 本身不合法：勾选回弹到 HEX，内容保留，状态行给原因；取消 HEX 时也会回弹。
- 字节不是合法 UTF-8（例如 `FF`）：保持 HEX，不强行转成文本。
- 导入不做转换；导入的 HEX 内容按原样进入行，非法时行标红。

## 指令集 JSON

```json
{
  "format": "hyw/command-sender",
  "version": 1,
  "intervalMs": 500,
  "commands": [
    { "label": "开机", "content": "AT+START", "hex": false, "cr": true, "lf": true },
    { "label": "查询", "content": "41 54 2B 51 3F", "hex": true, "cr": true, "lf": true }
  ]
}
```

- 最多 256 条；超过、格式/版本不对或 JSON 解析失败时整次导入失败，当前列表不变。
- `intervalMs` 可选；合法时写回间隔，缺省或非法时忽略。
- 导入会替换当前列表，并清空勾选；已保存的勾选顺序不写进文件。
- 另存为写出当前活动行；标签/内容/HEX/CR/LF 原样保存。

## 状态句

| 状态句 | 意思 | 处置 |
|---|---|---|
| 未勾选指令 | 没有勾选项，批量/连续不可用 | 勾选至少一行 |
| 第 N 条「标签」HEX 非法：… | 勾选项里有非法 HEX | 改内容或取消该行的 HEX |
| 已发送 N 个数据包（M 条指令） | 本次发送完成 | 无需处理 |
| 有 N 个数据包未送达 | 下游拒收了一部分包 | 检查连接与背压 |
| 发送间隔必须是 1~86400000 的整数（毫秒） | 间隔格式或范围不对 | 改成整数毫秒 |
| 未设置发送间隔，连续发送启动失败 | 连续发送时间隔为空 | 填写间隔 |
| 连续发送间隔必须大于 0 | 间隔为 0 | 改成大于 0 |
| 逐条发送需要 1~86400000 的发送间隔（毫秒） | 不合并 + 全部发送选了多条，但间隔为空/非法/0 | 填有效间隔，或勾选「合并发送」 |
| 逐条发送已取消 | 发送中改了勾选/顺序/列表结构 | 重新点「全部发送」 |
| 连续发送已开始（间隔 …，合并全部勾选项） | 合并模式下开启连续发送 | 无需处理 |
| 已导入 N 条指令 / 已另存为 文件名 | 文件操作完成 | 无需处理 |
| 最多 256 条指令 | 已达到列表上限 | 删掉不用的行再新建 |
| HEX 内容非法，无法转换为文本：… | 取消 HEX 时解析失败，已回弹 | 修 HEX 或保持 HEX |
| 内容包含非文本字节，保持 HEX | 字节不是合法 UTF-8 | 用 HEX 发送，或换内容 |
| 就绪 | 勾选项全部合法，可以发送 | 无需处理 |

## 典型用法

- **按脚本顺序发指令**：把多条 AT 指令写成行，按需要的顺序勾选，点「全部发送」；默认按间隔逐条发。
- **合并发送一整帧**：勾选「合并发送」，把需要拼在一起的多行按顺序勾选，点「全部发送」或开「连续发送」。
- **循环查询**：勾选几条查询指令，设 500 ms 间隔，打开「连续发送」；不合并时轮流单发，合并时每拍发全部勾选项。
- **文本与二进制混发**：一行文本、一行 HEX，各自勾选；HEX 行不会追加 CR/LF。
- **验证通路**：指令发送器 → 数据监视器，观察每条逻辑指令实际拆成了几个包。
