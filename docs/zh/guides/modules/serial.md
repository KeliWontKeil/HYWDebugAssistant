# 串口

把一路串口接入数据流：设备发来的字节成为一条发送网络，收到的数据写回串口。

## 界面

| 区域 | 内容 |
|---|---|
| 端口号 | 本机当前可用串口 |
| 波特率 / 数据位 / 停止位 / 校验位 | 串口参数；校验位可选无、奇、偶、标记、空格 |
| 打开串口 / 关闭串口 | 按当前参数打开或关闭；打开后参数不可编辑 |
| 状态灯 | 已连接、未连接与故障的颜色与形状编码 |
| 已接收 / 已发送 / 已丢弃 | 累计字节数；丢弃只计本会话轴的有效字节 |
| 状态行 | 当前状态或失败原因 |
| 清空计数 | 图标按钮；只清计数，不动连接与故障状态 |

## 打开与关闭

1. 选择端口号，确认波特率、数据位、停止位与校验位。
2. 点「打开串口」；打开期间状态行显示「正在打开… 端口」，成功后显示「串口已打开 端口」。
3. 点「关闭串口」断开；关闭不清零计数。

参数填写错误或端口被别的程序占用时，状态行给出失败原因（例如「打开串口失败」「没有选择串口」），细节在 Issue 面板。

## 收发

- 设备 → 数据流：串口收到的字节被切成数据包，从发送口发出，可接到监视器或其它模块。
- 数据流 → 设备：接到接收口的数据包按有效长度写给串口；会话未打开时这些包被拒绝并计数。

## 设备断开

打开期间框架会周期性确认端口仍在。设备被拔出或端口消失时，状态行显示「串口已断开」，该接入进入故障态；重新插好后需要再次点「打开串口」。

## 计数与清零

- 收、发、丢三类计数在实例生命周期内累计，重新打开会话不会清零。
- 唯一的归零方式是「清空计数」或移除后重新加入模块。

## 已知限制

首次打开串口时的冷启动、1 毫秒连续发送与大数据帧可能造成写阻塞与界面峰值；这是已记录的极端工况，不作为常规实时发送能力承诺。详见[已知问题与极端工况](../../project/known-issues.md)。
