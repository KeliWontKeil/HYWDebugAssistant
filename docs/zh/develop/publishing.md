# 发布与独立编译

## 构建模块包

引用 `HYWDebugAssistant.Module.Build` 后，`dotnet build -c Release` 会直接把模块包归拢到：

```
bin/module-package/Release/<模块名>/
```

包内是会被分发的那一棵目录：`module.json`、实现程序集（可含 `.pdb`）、`resources/**`、模块私有依赖。宿主提供的程序集与 `*.deps.json` 自动排除；手工打包时按[项目与包布局](project-layout.md)的清单剔除。

包名默认取项目名最后一个点段，可在项目里用 `<ModulePackageName>` 覆盖。

## 装载

1. 打开产品；
2. 工具栏「模块清单」→ 选择外部模块目录（选包目录那一层）；
3. 框架校验清单与同标识冲突，通过后复制到 `modules/external/`；
4. 在「可用模块」里把模块加入现场。

- **同一标识已存在**：拒绝导入并提示先移除旧包；不会覆盖、不会并存。
- **改过代码的包**：程序集不可替换，需要关闭应用重开后生效。
- 内置模块与外部模块走**同一条发现与加载路径**，外部包没有结构特权。

## 独立编译验证

外部作者的最小验证：只引作者包构建 → 装进产品 → 看模块清单。本仓库用 `tools/verify-standalone-module.ps1` 把同一条路径自动化：打包作者包 → 两个样例只经 `PackageReference` 构建 → 直接装载 `bin/module-package/Release/<模块名>/` 这一棵目录，断言声明期没有 Error。

## 常见失败

- 包目录选错（要选含 `module.json` 的那层）；
- 清单标识与代码声明不一致；
- 包里混进了宿主程序集（手工打包时最容易）；
- 模块运行时引用了作者包。

逐条对照见[被拒原因](../reference/rejections.md)。

## 版本

模块包没有自己的版本字段：包内容决定新旧，标识决定身份。宿主与作者包共用一个四段版本；升级 SDK 后重编模块，再按上面的步骤重新导入。
