# 模块开发

面向准备编写扩展模块的开发者。目标是：只拿得到 SDK 包、文档与产品，也能完成从建项目到装载排障的全过程。

## 先分清两条边界

| | 框架-外部接口 | 模块-模块通信 |
|---|---|---|
| 是什么 | 一套抽象接口 + 适配器 + 会话（串口 / TCP / UDP 是它的实现） | 端口 + 数据类型 + 数据包 + 组帧 |
| 模块做什么 | 声明标准标识；请求开/关；读写**原始字节**；读快照 | 声明类型与口；组帧与拆帧；参与建网 |
| 有没有数据类型 | 没有 | 有，且只在这里 |

详见 [外部接入](../concepts/external-access.md) 与 [数据类型约定](../reference/types.md)。

## 开发流程

| 步骤 | 做什么 | 判据 |
|---|---|---|
| 1 起项目 | 复制 `samples/DataModule`（纯数据变换）或 `samples/ExternalModule`（外部接入） | `dotnet build` 通过 |
| 2 声明 | 类型 → 端口 → 角色 → 显示源 / 输入 / 命令 →（可选）外部接入 | `ModuleContract.Probe` 无问题 |
| 3 自检 | 在测试项目里跑契约自检 | `Problems` 为空；`Advisories` 逐条确认 |
| 4 实现 | 收数据、发数据、更新显示源 | 用例能驱动模块的单步入口 |
| 5 打包 | `dotnet build -c Release`，取 `bin/module-package/Release/<模块名>/` | 包内只有模块自有文件 |
| 6 装载 | 产品 → 模块清单 → 选择包目录 → 重启应用 | 模块出现在可用列表并能加入现场 |
| 7 交付 | 写模块自己的使用说明与约定表 | 对端能按同一约定连上 |
