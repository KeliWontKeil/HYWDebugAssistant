> **P20–P40** 来自 M1-16（用户连续**十六**轮 UI/交互反馈）期间的返工；**P41–P44** 来自 **ADR-0050 R2-a/R3**

> （UI 开发方式 / 交互与命中 / 平台陷阱 / 流程纪律），二者互补：本文记"什么坑"，`LESSONS.md` 记"该怎么干"。

| # | 问题 | 现象 | 处理 |
|---|---|---|---|

| P3 | 模板默认引入 **AvaloniaUI.DiagnosticsSupport**（Accelerate 商业线，无许可声明 + 强制遥测） | 违反 ADR-0024 许可约束 | 已移除包引用与 `WithDeveloperTools()`；许可门禁首例拦截 |
| P4 | `dotnet_diagnostic.IDE0005=warning` 但未启用 `GenerateDocumentationFile` | 构建报 `EnableGenerateDocumentationFile` 错误 | 改为 `suggestion`（未使用 using 不阻断构建） |
| P5 | 模板代码违反严格风格（IDE0040 缺访问修饰符、IDE0011 缺大括号） | 警告即错误 → 构建失败 | 修模板代码（`internal sealed class Program`、补大括号、注释改中文） |
| P6 | **CA1707（标识符禁用下划线）与测试命名约定冲突** | 架构测试方法名（`A4_命名空间…`）构建失败 | 测试项目 `NoWarn` 豁免 CA1707/CA1859/CS1591，并在 csproj 注明原因（ADR-0025 §8 例外机制） |
| P7 | `Avalonia.Angle.Windows.Natives` 用 `<license type="file">`，`xunit.abstractions` 仅给 GitHub raw licenseUrl | 许可门禁误判 2 例 | 升级脚本：支持**许可文件文本识别** + **常见许可 URL 识别**；对无法自动识别的用**豁免清单**登记（附证据） |
| P8 | `Program` 改为 `internal` 后测试无法访问 | 测试项目 **CS0122** | App 项目加 `<InternalsVisibleTo Include="HYWDebugAssistant.Tests" />` |
| P9 | **Avalonia 编译绑定与"容器定位"DataContext 不同源**（`ItemsControl.Styles` 里 `Canvas.Left="{Binding X}"` 绑的是**条目**的数据，而 `x:DataType` 是页面视图模型） | `AVLN2000: Unable to resolve property or method of name 'X'` | 在该 `Style` 上写 `x:CompileBindings="False"`（作用域仅限这两条 Setter），并加注释说明原因 |
| P10 | `IPointer.Capture(...)` 在 Avalonia 12 返回 **void** | `CS8209: 可能无法分配类型 "void" 的值`（写法 `_ = e.Pointer.Capture(x)`） | 直接调用、不接返回值 |
| P11 | 自建 `ViewLocator` 按命名约定匹配到**不存在的视图**时会拦下显式 `DataTemplate` | 元素视图渲染成 `Not Found: …` | `Match` 只在"约定名对应的视图类型**确实存在**"时为真（带缓存），否则让显式模板生效 |
| P12 | 测试断言"写入路径零分配"时，JIT/首次调用的一次性开销会污染区间 | 断言 `allocated == 0` 偶发失败（固定 40 字节） | 断言改为**写入次数翻倍不新增分配**（与写入次数无关的噪声被抵消） |
| P13 | Avalonia 12 中 `TextBox.Watermark` 已过时（`AVLN5001`）；Avalonia 的 XAML 警告**不受** `TreatWarningsAsErrors` 约束但会出现在日志里 | 构建日志出现 2 条 AVLN5001 | 改用 `PlaceholderText`；**XAML 警告要单独看构建日志**（不阻断构建，容易漏） |
| P14 | 用 PowerShell 对源码做字符串替换时，**把"含两个元素的数组"写成了 `@(('a','b'))`** → `foreach` 迭代到的是两个**字符串**，`$pair[0]` 取到的是**首字符** | `.Replace('n','e')` 把文件里所有 `n` 换成 `e`（文件变成"二进制"、`Get-Content` 拒读） | **禁用 PowerShell 对源码做字符串手术**：改写文件一律用编辑/写入工具；确需脚本处理时先断言 `$pair -is [array]` 且长度=2 |
| P15 | 模块配置走**反射式** `JsonSerializer` 时，默认**不允许** `±Infinity`/`NaN`，枚举默认写成**数字** | ① 保存组合件时**直接抛异常**（Recorder 的期望值域用 ±∞ 表示"未设上下限"）；② 配置表单按枚举**名字**写回时反序列化失败 | `ConfigurationJson.Options` 显式设 `NumberHandling = AllowNamedFloatingPointLiterals` + `JsonStringEnumConverter`（后者默认允许整数 → 旧文件兼容）；**新增配置类型时检查其默认值是否含特殊浮点值** |
| P16 | "框架要从对象读取数据"的路径，若对象**从未被登记**，框架就取不到 | 配置只在模块**主动写**时才进快照 → 只读配置的模块保存组合件时**配置整块丢失**，且没有对象可生成 Schema 表单 | 配置面改为**读即登记**（`Read<T>` 首次调用写入默认值）；通用教训：**凡"框架按对象取数据"的接缝，都要有一条"对象从哪来"的明确登记规则** |
| P17 | UI 面板按刷新率（默认 60 Hz）刷新时，**每帧 `Clear()` + 重新 `Add`** 重建列表 | 列表项容器每秒被重建 60 次 → **鼠标悬停时所有选项乱闪**（瞬时视觉状态被反复重置），并产生大量无谓分配 | 列表统一改用**增量同步**（`CollectionSync.Sync`：结构相等则一个元素都不动，只在首个差异处替换/补删尾部）；**回归测试** `PanelRefreshStabilityTests` 断言"数据未变时行实例引用必须相同" |
| P18 | 列表行模型若是**引用语义**（`class`），增量同步无法判断"有没有变" | 只能退化为每帧重建（= P17 的闪烁） | 列表**行模型一律用 `record`**（值语义）；需要可变状态时单独用带 `ObservableProperty` 的行 VM，并在同步时显式比较内容 |
| P19 | 在**查询路径**里做文件系统访问（如"该包是否本次启动后重建过"）会被每帧调用 | 60 Hz × N 个模块 = 每秒数百次目录枚举（无谓 IO、杀软扫描、CPU 抖动） | 这类判定**在扫描时算一次并缓存**（`ModulePackageOrigin.NeedsRestart`），查询面只读缓存 |
| P20 | **资源类型写错只在运行时炸**：`CornerRadius="{DynamicResource ModuleCornerRadius}"` 而该资源是 `<x:Double>` | 点「加入现场」抛 `InvalidCastException: Unable to cast 'System.Double' to 'Avalonia.CornerRadius'`（XAML **编译期不报**） | 资源类型改对（`<CornerRadius>`）；**根因是视图层没有自动化** → 建**无头 UI 测试**（真实 `App` 资源 + 真实窗口），该类错误从此在提交前被拦 |
| P21 | **Avalonia 资源查找顺序 = 主题字典 → 自身条目 → 合并字典（后加者优先）** | 把"用户主题色覆盖"放进 `MergedDictionaries` → 永远被主题字典里的内置 token 盖住（覆盖了却读不到） | 覆盖**写进主题字典本身**，并在每次应用前按快照**还原**上一轮覆盖 |
| P22 | **无头 UI 测试的框架与并行**：`Avalonia.Headless.XUnit` 依赖 **xunit v3**（工程是 v2 → `CS0433 FactAttribute` 重复）；无头会话自带 UI 线程，与其他测试类并行会撞 `cross-thread access`；只 `RunJobs` 不推渲染帧时"单跑通过、一起跑命不中" | 三种症状都实际踩到 | 用 `Avalonia.Headless.HeadlessUnitTestSession`（不绑测试框架）+ 专用 `[CollectionDefinition(DisableParallelization = true)]` 集合 + `AvaloniaHeadlessPlatform.ForceRenderTimerTick()` 后再 `RunJobs` |
| P23 | **自绘叠加层的坐标系**：吸附/布局几何存的是**屏幕物理像素**，而 `Control.Render` 用 **DIP**；且窗口边框内缩使"模块 X/Y"≠"客户区原点" | 对齐参考线在 100% 缩放下看不出问题、**125%/150% 下整体偏移**（用户报"差几个像素"）；边框不 `ClipToBounds` 时线会画到窗口外（曾出现横贯屏幕的虚线） | 绘制前取 `TopLevel.PointToScreen(0,0)`（客户区原点）+ **÷ `RenderScaling`**；窗口根 `ClipToBounds="True"` |
| P24 | **装饰窗口的 `Position` 是外框、`Bounds` 是客户区** | 用 `Position + Bounds` 拼出外壳矩形 → 右边界少一个窗口边框宽 → "模块吸附到外壳右侧差几像素" | 用 `PointToScreen(0,0)` + `ClientSize`（两者同源，均为客户区） |
| P25 | **"零尺寸矩形"会被几何校验过滤**：`CanvasRect.IsValid` 要求正尺寸 | 想把"外壳右边缘"表示为零宽矩形参与吸附 → 恒被过滤 → 该参照永不命中（表现为"无法吸附到外壳"） | 线不是矩形：`SnapEngine` 增加 **`referenceLines`** 通道（`(IsVertical, Position)`）单独评估 |
| P26 | **Avalonia 12 已移除 `SymbolIcon`**；第三方图标包（`Projektanker.Icons.Avalonia`）最新版仍依赖 **Avalonia 11.2.8** | 图标方案不能用"内置 SymbolIcon"，也不能盲引图标包（大版本落后 = 运行时不兼容风险） | 用**系统图标字体**（`Segoe Fluent Icons / Segoe MDL2 Assets` + `Glyph*` 码位资源），零依赖、Windows 原生观感；引入图标包需单独评估并做回归 |
| P27 | **"死开关"比崩溃更糟**：设置项/开关可改、可持久化，但**没有任何绑定消费它** | 用户以为功能坏了（"这个开关没效果"），也不会有报错 | 规则：**每个可交互控件都必须有真实落点**；新增开关时要能指出"谁读它"（本例 `showPortMarkers` → 改为 `showInfoOverlay` 并真正接到叠加层可见性） |
| P28 | **命中优先级决定可用性**：拖动带/缩放手柄在内容之上，而端口标记（唯一建网入口）又在内容层 → 手柄"垂直居中"与标记"垂直居中"重叠 | 双击标记中心被手柄吃掉 → **表现为"改不了网络标签"**；同时控件不可见（对比度≈1.02）让人以为没有标记 | 层级固定为 内容 → 交互带/手柄 → **口标记层** → 叠加层 → 按钮簇；**手柄仅在选中时可命中**；标记贴外框 + 强边框 + 字号 11 保证"一眼可见" |
| P29 | **`Refresh` 写盘时机与"代码算布局"耦合**：新模块按"元素类型 → 高度表"算窗口尺寸并立即写回布局 | 布局里存的是代码算出的尺寸而非真实窗口尺寸；用户无法在 XAML 里调 | 尺寸默认值归 **XAML**；新模块**只分配位置**，窗口打开后用 `PublishActualSize` 把**实际尺寸**读回再落盘 |
| P30 | **给 SDK 构造器/记录加"可选参数"是二进制破坏**：`ViewDeclaration(elements, dataSources, commands, preferredWidth = 0, preferredHeight = 0)` 语义上是"只增不改"，但**方法签名变了** | 已编译的第三方模块（各自带一份 SDK 副本）加载时抛 `MissingMethodException`；本项目 5 个参考模块中**未重编的 3 个立即失败**（Tests.Reference 10 项红） | SDK 新增"可选声明"一律用 **`init` 属性**（如 `PreferredWidth`），**不改构造器签名**；改 SDK 后**必须重编全部模块**并把这一步纳入验收前检查（模块包与 SDK 版本耦合） |
| P31 | **"硬吸附"把模块位置变成指针位置的阶梯函数**：每帧 `位置 = f(指针)`，带内吸住（不跟手）、出带跳变；再叠加**多路候选**（贴合/中心线/左右边对齐/外壳参照线各一套通道）与"按缝隙大小猜邻接方向"的启发式 | 实测（真实窗口 + 125% DPI）"指针走 **24px** 模块一动不动、然后**跳 +17px**"；靠近时多个候选挤在几像素内 ⇒ 阶梯变密 = 用户说的"**靠近才抖**"；另有两处**重复登记**（端口在 0.5 时与模块中心线同坐标；外壳参照线本可并入"边对齐"） | **ADR-0042**：候选统一为**参照线模型**（模块外框 4 边 + 中心线、端口锚点按所在边定轴、外壳 = 只暴露一条边的对象），级别由「线来源 + 交叉轴条件」派生，**同坐标去重**，删除"按缝隙猜方向"；手感按 Visio（**吸附距离进设置项**、离开即松、方向一致性规则压回跳） |
