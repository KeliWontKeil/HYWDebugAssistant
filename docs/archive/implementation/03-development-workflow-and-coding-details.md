## 2. 标准流程

### 2.1 任务确认（动手前）

1. 明确**任务属性**：改代码 / 仅设计 / 暂缓；
2. 定位**影响层级**：改哪一层（`Sdk`/`Infrastructure`/`Hosting`/`DataPlane`/`Core`/`Core.Api`/`Ui`/`FrameworkUi`/`App`/模块）——跨层改动先查 `01` 依赖禁令；
3. 判断是否触发 **ADR**（`implementation/01` §5 六种情形）：影响 v1.0 结论 / 新核心概念 / 新依赖 / 改模块契约 / 性能策略变更 / 例外豁免；
4. 判断是否触发**文档回写**：发现"应该是什么"未定（残余 A 类）→ 停止实现 → Architecture Issue → 人工决策 → 回写主文档 + ADR（主文档 §16.2/§16.4）；
5. **评估回滚点**：本次改动能否单独回退（提交粒度）。

### 2.2 实施

1. **默认直提 `main`**（开关 S4）；提交前门禁全绿；
2. **分层约束优先于便利**：不得为了让代码跑通而新增反向依赖（`01` §1.3 依赖链是穷举的）；
3. **参数先入设置模型再使用**：框架行为的可调参数 → 应用级设置（`04b`）的字段 + 默认值，不在代码里写魔法数字；
4. **热路径代码先想分配**：数据面路径（产生/传递/解析/缓冲/绑定）按 `implementation/01` §3 写，改完给出分配数据；
5. **模块相关改动**：先看 `03-module-sdk.md`（SDK 面）——模块作者只引 `Sdk`，不得依赖 UI 框架、不得引用其他模块；
6. **UI 相关改动**：模块视图只能由**声明**表达（18 元素 + 4 容器），模块不提供 View；UI 一律经 `Core.Api` 读写；
7. **一次改动一个主题**：重构与功能不混在同一提交。

### 2.3 验证（三级）

| 级 | 内容 | 何时 |
|---|---|---|
| **① 门禁** | `build.ps1` 全绿：还原 → 构建（0 error、**0 warning**）→ 许可审计 → 测试 → **AR-1~AR-16 架构规则** | 每次提交前 |
| **② 机制验证** | 该机制有对应验证：契约矩阵 / ChangeSet 原子性 / 增量重建 / 持久化 round-trip / 故障注入（`06` T2–T5） | 改动机制时 |
| **③ 组合级验证** | 涉及框架机制的行为变化 → **参考组合**（桩模块）级验证；核心判据看 AC-1~6 | 机制改动必须 |
| **④ 手工验证** | UI 应用层面由用户按**手工验收清单**执行（`08` §4） | 里程碑收尾 |

**注意**：不做框架级"MCU 式"单元测试；**不设覆盖率百分比**；以"机制改动必须有组合级验证"为准（`06` §6.6）。

## 3. 质量门禁

### 3.1 必须满足（通过条件）

1. `build.ps1` 全绿：**0 error、0 warning**（`TreatWarningsAsErrors=true`；局部 `NoWarn` 须注明原因）；
2. **AR-1~AR-16 全绿**（依赖类走程序集元数据 + 源码类走源码扫描；**目标程序集缺失即失败**）；
3. 依赖许可 ∈ {MIT, Apache-2.0, BSD}，含传递依赖（许可审计门禁）；
4. 热路径改动**给出分配数据**（`GC.GetAllocatedBytesForCurrentThread()` 或基准）；
5. 机制改动有**组合级验证**；
6. 关键约束可映射到**可执行检查**（检索 / 构建 / 测试 / 架构规则），而非只写在文档里；
7. 文档与代码**同次同步**。

### 3.2 拒收条件（出现即打回）

1. 同一结构事实在多个文档并行维护（双份漂移）；
2. 为兼容旧结构新增"跳转壳"文档或空壳层；
3. 新增反向依赖或绕过 AR 规则的"临时通道"；
4. 关键路径出现无收益的重复拷贝/转换/绕路中转（违背"数据直通"）；
5. 引入降低可读性的冗余中间抽象（"为了模式而模式"）；
6. 静默吞异常、静默降级、静默丢数据（必须转为 Issue 或诊断计数）；
7. 未登记的架构例外（`// ARCH-EXCEPTION` 写了但未进 `docs/decisions.md`）。

## 5. 编码细节风格

> 原则层见 `implementation/01` §1；以下是**具体到写法的细节**。

### 5.1 类型与成员

| 项 | 约定 |
|---|---|
| 默认封闭 | 类型默认 `sealed`；**例外**：`Sdk` 中面向模块作者的抽象接口（抽象基类一律不用） |
| 不可变优先 | 框架内部元数据（Definition/契约形状/设置快照）一律**不可变**（`readonly`/`init`/`record`）；运行期只读共享 |
| 可见性最小 | 默认 `internal`；仅 `Sdk`/`Core.Api` 的公开面用 `public`；跨程序集内部可见用 `InternalsVisibleTo`（并登记原因） |
| 值与引用 | 数据单元用**结构体**；跨层传递的描述/元数据用不可变 `record`；**热路径不 new 类** |
| 集合 | 对外暴露 `IReadOnlyList<T>`/`ReadOnlySpan<T>`；内部用数组/池化；不用 `List<T>` 作长期容器 |
| 常量 | 魔法数字入具名常量或设置项；枚举显式编号（序列化稳定性） |

### 5.2 异步与并发（**本项目最重要的一节**）

| 项 | 约定 |
|---|---|
| 数据面不用 async | 投递路径**同步**（线程已专属）；`async` 只用于 UI/IO 等待，禁出现在热路径 |
| 线程归属 | **框架为每个 `Active` 实例分配专属线程**（`04` §4.1）；模块可阻塞；**任何代码不得自建 `Thread`/`Timer`**（除 `DataPlane` 的承载设施） |
| 共享状态 | 跨线程共享只经：①**不可变快照 + 原子替换**（绑定集合、设置快照）②**有界队列**（投递）③**订阅缓冲**（UI 读取）——**不引入 `lock` 保护热路径** |
| UI 线程 | UI 只碰 UI 对象；经订阅缓冲/`Core.Api` 与后台交互；**不阻塞 UI 线程**，也不用 `Task.Run` 把框架逻辑丢到池上 |
| 停止协作 | 长循环必须检查**停止信号**（`04` §4.1）；模块活动体入口由框架包裹异常边界 |

### 5.3 异常与错误

| 场景 | 约定 |
|---|---|
| 模块异常 | **不逸出边界**：由框架在活动体入口捕获 → Issue（归属实例）+ 该模块活动停止 |
| 框架内部 | 不做防御性 `catch` 掩盖；框架缺陷必须暴露给开发者（`04` §4.1） |
| 可预期失败 | 用返回值/Try 模式（解析失败、契约不匹配、口不存在），**不用异常作控制流** |
| 上报 API | 内部**不抛**：上报失败只记诊断计数 |
| 错误分类 | 一律映射到 Issue 七类（`08` 主文档 §8.2）+ 归属对象；**不用自定义错误码体系**（v1 明确不做） |
| 禁止 | `catch (Exception) { }`、`catch` 后仅 `Debug.WriteLine`、静默降级 |

### 5.4 可空与契约

`<Nullable>enable</Nullable>` 全程开启；`!`（null-forgiving）仅用于已证明非空处并加注释；公开 API 的参数校验用 `ArgumentNullException.ThrowIfNull`（非热路径）。

### 5.5 日志与上报

| 层 | 方式 |
|---|---|
| 框架（L2/L3/L4） | 内置极简日志 sink（自研，ADR-0024）；结构化字段：时间/层级/对象/事件 |
| 模块 | **只经 `Sdk` 上下文**上报（Issue/日志/业务状态）；**不直接引用日志库** |
| 级别 | `Trace/Debug/Info/Warn/Error`；`Info` 及以上进日志文件，`Trace/Debug` 只在诊断开关打开时 |
| 禁止 | 热路径逐单元打日志（改为**计数 + 定时汇总**）；日志里拼字符串（用结构化参数） |

### 5.6 DI 与生命周期

- 容器：`Microsoft.Extensions.DependencyInjection`；**注册集中在 `App`（组合根）**，各层不自行 `ServiceLocator`；
- 框架内部对象由构造注入；**不用静态可变单例**（除 `ArrayPool<T>.Shared` 这类 BCL 池）；
- `Core.Api` 的实现随 Core 生命周期；UI 侧不持有 Core 内部对象（只持接口）。

### 5.7 热路径写法（数据面）

```text
✅ 结构体 + Span/ReadOnlySpan + ArrayPool 租还 + 生成的字段访问器
✅ 批量处理（一次搬 N 个单元）+ 固定容量环形缓冲
✅ 返回值表达失败（Try 模式）
❌ LINQ / 装箱 / 闭包 / 每单元 new / 字符串插值 / 异常控制流 / async
```

**缓冲归还**：池化缓冲的所有权必须明确（谁租谁还）；跨线程移交时**由接收方归还**；调试构建下断言双重归还。

### 5.8 UI 层写法（Avalonia）

| 项 | 约定 |
|---|---|
| 模式 | MVVM + `CommunityToolkit.Mvvm`（源生成 `[ObservableProperty]`/`[RelayCommand]`）——**仅 `Ui`/`FrameworkUi` 内部约定**，模块作者不涉及 |
| 模块视图 | 由框架按**声明**渲染；元素实现按 `03` §3.6 的目录，参数化而非派生 |
| 数据读取 | 从订阅缓冲取（最新值槽/环形缓冲），**UI 侧抽样**；节拍 = 刷新率设置项（默认 60 Hz） |
| 渲染性能 | 曲线用批量点写入（不逐点触发属性通知）；表格用虚拟化 |
| 视觉取值 | 颜色/字体/尺寸一律引 `09` 的 token，不写死色值 |
| 线程 | UI 对象只在 UI 线程访问；后台数据到手后用调度器切回，**不在后台线程碰控件** |

### 5.9 测试写法

| 项 | 约定 |
|---|---|
| 命名 | `Method_Scenario_ExpectedResult`（中文场景可读，如 `ChangeSet_契约不兼容_整体拒绝且零副作用`） |
| 风格 | 优先**表驱动**（`[Theory]` + `[InlineData]`/`MemberData`）覆盖矩阵（契约兼容、R0–R6） |
| 断言 | Shouldly（`ShouldBe`）；避免断言实现细节 |
| 替身 | NSubstitute；框架内部优先用真实实现 + 桩模块，避免过度 mock |
| 分类 | 按 `06` 的 T1–T8 归档到对应项目；**T8 UI 自动化 v1 不做** |
| 例外 | 测试专用 `NoWarn`（如 `CA1707`）须注明原因 |

### 5.10 注释与文档

- **中文注释**（开关 S5）；标识符与 API 名英文；
- `Sdk` 面向模块作者的公开成员**必须** XML 注释（含用法与约束），其余按需；
- 注释写"**为什么**"（尤其非显然的分支/约束），不复述代码；
- 引用设计：`// 见 docs/architecture/04 §4.2（有界缓冲与丢弃）`——**只写文档路径 + 章节号**。

### 5.11 文件与目录组织

- 一文件一公共类型；文件名 = 类型名；**文件作用域命名空间**；命名空间与目录一致（AR-14）；
- 目录按**角色**分（如 `DataPlane/Binding/`、`Core/Composition/`），不按"类型种类"分（不设 `Interfaces/`、`Helpers/`）；
- 不建 `Utils`/`Common`/`Misc` 这类无归属命名空间——**归不到某层就说明设计有问题**。

## 6. 构建与调试经验

### 6.1 构建命令

```powershell
cd "D:\project\c# project\HYWDebugAssistant"
.\build.ps1                    # 全量门禁：还原 → 构建 → 许可审计 → 测试
.\build.ps1 -SkipTests         # 只构建（快速迭代）
.\build.ps1 -RunBenchmarks     # 额外跑基准（不进常规门禁）
.\build.ps1 -StopDesignerHost  # 构建前停掉 VS 的 Avalonia 设计器宿主机
```

### 6.2 常见错误与解决方案

| 症状 | 根因 | 解决 |
|---|---|---|
| `MSB4126` 解决方案配置 `Debug\|<路径>` 无效 | 系统环境变量 `Platform` 被污染 | `build.ps1` 已自动清除；建议系统级删除该变量 |
| `MSB3026/3027/3021` 文件被 `.NET Host` 锁定 | VS 的 Avalonia 设计器宿主机占用输出 | `build.ps1 -StopDesignerHost`，或关闭预览器 |
| `error EnableGenerateDocumentationFile` + `IDE0005=warning` | 规则冲突 | `IDE0005` 设为 `suggestion`（已配置） |
| `IDE0040` / `IDE0011` 报错 | 缺访问修饰符 / 缺大括号 | 均已设为 `warning` 且警告即错误 → 补上（勿关规则） |
| 许可审计门禁失败 | 依赖许可不在白名单 | 查 `tools/license-allowlist.json`；**不得**为过门禁而放宽规则（须换依赖或走 ADR） |
| Avalonia Accelerate 遥测提示 | 无 Accelerate 许可密钥 | 不影响构建；`AVALONIA_TELEMETRY_OPTOUT=1` 抑制上报 |

### 6.3 调试要点

1. **数据面问题先看 L4 诊断**（投递数/丢弃数/最后数据时间/队列深度），不要一上来打断点——多线程下断点会改变时序；
2. **模块卡住** → 看是否 `Removed` 后线程超时（Issue + 孤儿标记，`04` §4.1）；
3. **UI 卡顿** ≠ 数据面卡顿：看订阅缓冲丢弃计数；数据面**不应**受 UI 影响（若受影响即违反 §13.1，属架构级缺陷）；
4. **架构规则报错** → 先确认是真违规（不是误报）；确属误报走 `docs/decisions.md` 登记，**不擅自改规则**；
5. 会话上下文被压缩或切换后，继续改动前**重读关键文档**（尤其 `01`/`04`）。
