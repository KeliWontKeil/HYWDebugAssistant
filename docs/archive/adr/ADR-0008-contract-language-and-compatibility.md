# ADR-0008 契约语言能力与兼容规则（PQ-IF-03~07）

> 状态：Accepted（用户裁决，批次 2）
> 关联批次：批次 2
> 关联主文档章节：§5
> 取代：无
> 被取代：第 5 条（多路承载的视觉表述）被 ADR-0018 取代

## 问题

批次 2 兼容组裁决：契约语言能力结构（PQ-IF-03）、兼容判定（PQ-IF-04）、转换处理（PQ-IF-05）、"合法但无意义"组合（PQ-IF-06）、多路承载（PQ-IF-07）。

## 决策

1. **契约语言三层能力（PQ-IF-03，方案 A）**：① 传递语义标注（流/消息/事件）；② **受控基础形状原语目录**（平台提供、可扩展；作者只能组合不能自造）；③ **组合与签名**（组合编码数据流签名 = 兼容判据锚点）。语法与实现 Gate。
2. **兼容判定（PQ-IF-04，方案 A）**：Core 只算可计算的契约关系、不解释内容——① 传递语义可匹配（**跨语义如流→消息不判兼容**，由模块内部组帧处理）；② 形状兼容 = 接收契约接受集 ⊇ 发送契约提供集（子集/派生，可计算）；契约可为**具名可引用发布物**（契约目录）或内联形状。
3. **转换处理（PQ-IF-05，方案 A）**：平台**不自动转换**；不可连 + UI 明示差异；转换由用户显式插入的**转换模块**承担（内容模块职责，非框架机制）。
4. **"合法但无意义"组合（PQ-IF-06，方案 A）**：允许连接存在（拓扑合法），UI 标注"无数据流"；运行期"无数据/无输入"为合法状态（§8.2 类 a）。
5. **多路承载（PQ-IF-07）**：1:N 分发 = 连接机制原生多播（无需运行时转发模块）；N:1 汇入允许、合并/同步语义由接收模块承担；**拓扑关系的用户视觉由"结构块"承载**——模块视觉保持单口外观，分支视觉/交互由结构块元素呈现（多播路由策略）；结构块从"功能模块"向"**拓扑视觉承载**"演进，P5/P6 相关修订列入批次 3 前结构块专题（暂缓项解冻线索）。

## 影响

- §5.4 增补、PQ-IF-03~07 关闭；结构块专题登记（批次 3 前）。
- 契约目录/具名契约概念出现（与 Registry 平行，可后续并入 Registry 或独立契约库，批次 2 收尾定）。
