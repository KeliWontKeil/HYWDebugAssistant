# ADR-0035：M1-15 实现期的契约补充（配置 Schema 通道 · 配置读即登记 · 设置项更名）

> **状态**：Accepted（2026-09；M1-15 实施中作出并回写）
> **修订对象**：主文档 §9.2（配置随组合件保存）· §9.5（应用级设置清单）· `architecture/03`（模块 SDK 面）· `architecture/05` §5.6/§5.7 · `architecture/11` §4.2/§10
> **关联**：ADR-0034（表现形态修订）、ADR-0030（应用级设置）、M1-15（界面澄清与修正）
> **被取代**：**ADR-0040**（D6-1「B2 命令 / B5 文本输入通道」已关闭 —— 该 SDK 面由 ADR-0040 落地）；其余条款（D1–D5、D6-2）仍生效

---

## 0. 为什么要开这份 ADR

ADR-0034 冻结的 M1-15 要求"**配置编辑回到模块视图内**，由框架按**配置 Schema 自动生成表单"，并要求**删除 JSON 编辑**。
实施时发现三处**冻结基线没有覆盖**的契约缺口；另有两处**实现期才暴露的表示层语义**问题。它们都不是"实现细节"，
而是会写进组合件文件、或影响模块作者的契约，故按治理规则以 ADR 记录。

---

## 1. 决定

### D1. 配置 Schema 通道（`Core.Api` 新增只读 Schema + 按字段写回）

| 项 | 内容 |
|---|---|
| 新增查询 | `IRuntimeQuery.TryGetConfigurationSchema(instanceId, out ConfigurationSchemaView?)` |
| 新增命令 | `IRuntimeCommand.UpdateConfigurationField(instanceId, fieldName, value)` |
| Schema 内容 | 字段**名 / 标题 / 分组 / 控件类型（布尔·整数·实数·文本·枚举）/ 当前值文本 / 取值范围 / 步长 / 单位 / 说明 / 枚举可选项**；不可编辑时给出 `Notice` 原因（无配置类型、占位实例等） |
| **不含** | 配置类型完整名（**界面不得出现代码化标识** —— 主文档 §10.4 / 意见 3） |
| 写回路径 | 按字段解析文本 → **JSON 中转**（序列化当前配置 → 覆盖一个属性 → 反序列化为**新实例**）→ 经 L4 变更入口 `UpdateConfigurationsOperation`（一次 ChangeSet、原子应用或整体拒绝、触发一次配置变更通知） |
| 零副作用 | 绝不就地修改运行中的配置对象（变更入口要求 Prepare 阶段零副作用）；拒绝时原配置不变 |

> **为什么用 JSON 中转而非反射写属性**：反射写属性需要"先改再提交"，一旦提交失败就留下了已改的对象；
> JSON 中转天然产出**新实例**，与"整体应用或整体拒绝"的机制要求一致。

### D2. SDK 新增可选的字段元数据 `ConfigurationFieldAttribute`

- 位置：`HYWDebugAssistant.Sdk.Configuration`；**只增不改**（新特性，既有无标注的模块照常工作）。
- 作用：补足**标题 / 分组 / 范围 / 步长 / 单位 / 说明**；不标注时由**字段名生成标题**（`PeriodMs` → "Period Ms"）、由**属性类型**判定控件。
- 范围与步长**仅约束编辑界面**：框架**不据此裁剪**配置值（语义归模块）。
- 特性参数只能是常量，故"未设置"用 `double.NaN` 表达（构建 Schema 时归一为 `null`）。

### D3. 配置"**读即登记**"（`IConfigurationAccess.Read<T>` 语义补充）

| 项 | 内容 |
|---|---|
| 原语义 | 读当前配置（不可变快照）——但实现为"没有就返回 `new T()`"且**不登记** |
| 新语义 | **首次读时登记默认值**（`new T()` 写入该实例的配置集合）；后续读返回同一对象；`Write<T>` 覆盖 |
| 理由 | ① 模块通常**只读不改**配置：不登记则"随组合件保存的实例参数"在保存时**整块丢失**，AC-4 无损往返形同虚设；② 没有配置对象就**无法生成配置表单**（M1-15 的核心交付物之一）；③ 组合件加载时 `RestoreConfiguration` 会覆盖默认值，顺序不变 |
| 并发 | 配置字典由**模块线程**（首次读）与**管理线程**（保存/恢复）共同访问 → 访问点全部纳入同一把锁；`ConfigurationSnapshot` 改为**加锁复制** |

> **这一条修正了一个真实缺陷**：M1-8 的"配置随组合件保存"此前只在"模块自己写过配置"时才成立。

### D4. 配置 JSON 的数值与枚举表示

| 项 | 内容 |
|---|---|
| 命名浮点字面量 | 允许 `±Infinity` / `NaN`（`JsonNumberHandling.AllowNamedFloatingPointLiterals`）：模块合法使用 ±∞ 表示"未设上下限"（如 Recorder 的期望值域），此前**保存组合件会直接抛异常** |
| 枚举 | 按**名字**读写（`JsonStringEnumConverter`）；转换器默认允许整数 → M1 早期写下的**数字枚举仍能加载**（向后兼容） |
| 理由 | 组合件是**给人看的文本**（§9.3），枚举名字比序号可读；表单写回的字面量也是名字 |

### D5. 设置项更名：`ShowLinkLines` → `ShowPortMarkers`

| 项 | 内容 |
|---|---|
| 原因 | "跨窗口长连线"在 v1 **不做**（`11` §2.3），"连线层默认显示"这一设置随之失去对象；而口上标记是**唯一建网入口**，必须有可见性开关 |
| 做法 | 属性更名 `ShowPortMarkers`（默认 **true**）；JSON 键写 `showPortMarkers`，读取时**优先新键、回退旧键** `showLinkLines` |
| 兼容 | 无需设置 Schema 版本升级：读取容忍未知/缺失键，旧文件照常加载（旧值沿用为新语义的初值） |

### D6. 两项**未完成**的设计项（明确记录，不静默降级）

| 编号 | 项 | 状态与处置 |
|---|---|---|
| **D6-1** | **B2 命令按钮 / B5 文本输入**通道（`11` §5 中"手动数据发送器"的原始交互设想） | **未做**：元素目录里早有这两个**元素类型**，但"命令/输入"缺少**执行通道**（模块声明命令 → 框架投递 → 在模块线程上执行；文本输入的写入面）——属**新增 SDK 面**，须单独设计并批准。M1-15 以**配置写入**作为可戳通道落地（单次模式：每次配置写入发一个数据单元），**人工验收不受阻**；该通道列入 **M1-15 之后的开放项**（登记于 `11` §10、`roadmap.md`） |
| **D6-2** | 信息显示模块的"**日志条数**"配置 | **改为"日志密度（LogEvery）"**：订阅环容量是**框架常量**（`SubscriptionBuffer.DefaultRingCapacity` = 512，暂不可按实例配置），故"条数"无法由模块配置；改为"每 N 个单元记一条日志"更贴合模块能决定的事。若将来要按实例配置环容量，属新的设置/契约项 |

> **已失效：D6-1 已由 ADR-0040 取代**（ADR-0040 落地了"SDK 视图元素执行通道"：命令通道 `ViewCommand` + `IModule.OnCommand`（投递到模块线程、命令合并、失败转 Issue）与文本输入写入面（回车/失焦一次提交），"命令/输入缺少执行通道"这一缺口不复存在）⇒ B2/B5 不再是未完成设计项。D6-2（日志密度）仍生效。

## 2. 影响面

| 层 | 变更 | 说明 |
|---|---|---|
| `Sdk` | **新增** `ConfigurationFieldAttribute` | 只增不改；无标注模块照常工作 |
| `Core.Api` | **新增** `ConfigurationSchemaView` / `ConfigurationFieldView` / `ConfigurationFieldKind` / `ConfigurationFieldChoice`；`IRuntimeQuery` + `IRuntimeCommand` 各加一个方法 | 公开面**不出现**框架内部类型（AR-16 保持） |
| `Core` | 新增 `ConfigurationSchemaBuilder`（读 Schema + 按字段写回）；`ConfigurationJson` 参数补充 | 反射**只发生在模块自有配置类型**上（与既有取舍一致） |
| `Hosting` | `Read<T>` 读即登记；配置集合加锁 | 语义补充 + 并发修正 |
| `Ui` / `FrameworkUi` | 模块窗口内渲染 Schema 表单；无 UI 模块的兜底同样用表单 | 删除 JSON 编辑（意见 3） |
| 文档 | 主文档 §9.2/§9.5、`architecture/03`（SDK 面）、`architecture/05` §5.6/§5.7、`architecture/11` §4.2/§10、`architecture/08` M1-15 | 本次回写 |

## 3. 未采纳的方案（备查）

| 方案 | 未采纳原因 |
|---|---|
| 用**源生成器**产出配置 Schema（Q3-4 的完整形态） | 需要独立的生成器工程与模块作者约定；M1 的配置类型已走反射式 JSON（同一取舍），单独为 Schema 引入生成器会让"配置"出现两条技术路线。留待需要"编译期零反射"时统一替换 |
| 配置表单**就地修改运行中的对象** | 违反变更入口的"Prepare 零副作用"；失败后无法回滚 |
| 把**日志条数**做成框架级设置（每个实例的环容量） | 会让"每个数据源的缓冲容量"成为可配置项，牵动内存预算与数据面契约；M1 不做，登记为后续项 |
| 为 B2/B5 **临时**加一个"仅参考模块可用"的后门通道 | 会形成"参考模块特权"，与"参考模块与第三方模块同构同路径"（AR-1/AR-2）冲突 |
