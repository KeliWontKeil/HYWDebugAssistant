# ADR-0020 模块供给：包模型 / 发现加载 / Manifest / 隔离目标（批次 8）

> 状态：Accepted（用户裁决，批次 8）
> 关联批次：批次 8
> 关联主文档章节：§11
> 取代：无（落实 ADR-0002 同形原则） · 被取代：无

## 决策

1. **B1 模块包模型**：确立"**模块包**"为模块唯一供给单位 = `manifest（Definition 声明）+ 实现绑定 + 可选资源`；**内置 = 预装的包**（无结构特权），外部 = 用户加载的包；Registry 只登记包注册后的 Definition。物理形式（目录/压缩包/单文件）→ Gate。
2. **B2 发现/加载/更新/移除**：
   - **发现**：以**用户显式加载模块包**为主；可选"来源目录"由用户配置并扫描（**不自动扫描任意位置**——安全与可控）；
   - **加载**：校验（manifest 完整性 / 框架兼容范围 / 依赖）→ 注册 Registry → 可实例化；失败 → Issue，**不影响既有模块与运行**；
   - **更新**：同 Definition ID + 新 Version **共存注册**（不覆盖）；实例按声明版本加载，缺失/不兼容走缺失态（ADR-0017）；
   - **移除**：从 Registry 注销；已实例化者进入缺失态（占位+Issue）；**不强制卸载**正在使用的模块（提示 + 可强制）。
3. **B3 Manifest 最小内容**：Definition 六项声明（身份版本/元数据/接口/配置 Schema/视图/生命周期能力，ADR-0005）**+ 供给与实现绑定**：实现入口（脚本/原生/组合件引用）、依赖（模块包/契约）、**框架兼容范围**、可选资源引用。
4. **B4 隔离与崩溃边界目标（技术无关）**：① 模块异常**不逸出边界**（框架捕获转 Issue，ADR-0015）；② 模块间不因共享状态互相破坏（框架不暴露跨模块直接引用，P12）；③ 加载/卸载失败不损害框架与既有运行；④ 恶意防护与信任模型 → 批次 9。实现层（进程内/外、沙箱）→ **Gate**。

## 影响

- §11 新增冻结节；PQ-PL-01~04 关闭；PQ-PL-05（Assembly/DLL/进程模型）与 PQ-PL-06（Security）保持 Gate（后者衔接批次 9）。
- 具体内置模块清单归属"具体模块阶段"（不属顶层）。
