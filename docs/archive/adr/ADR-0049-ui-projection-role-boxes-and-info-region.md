## 1. 为什么现在做 P4（用户裁定）

- 用户第十九轮："**连线是"角色 → 角色"而非"端口 → 端口"** ⇒ 同意重构为「角色方块 → 对端角色方块 + 角色对级聚合」"；
- P3 已把"角色/角色对"在 **Core** 里算好并经 `Core.Api` 暴露（`GetDataRoles` / `GetRolePairs` / `PortView.TypeKey`），
  ⇒ P4 只是**把已有模型画出来**，不再涉及建网/兼容/投递的任何改动；
- 用户第三十一轮：同意起草本 ADR（先设计、后代码）。

## 3. 设计（**D1–D12**）

### D1. 方块 = **角色**（方向 × 类型身份），数量与 P3 一致

- 一个模块的方块数 = `GetDataRoles(instanceId).Count`（**同类型的发送角色与接收角色各一个方块**）；
- **不再**按 `TypeText` 去重 ⇒ "不同标识但同形状"的两种类型**各一个方块**（ADR-0051：二者不是同一种量）；
- 方块总数与"口数"无关：8 通道记录器 = **1 个接收角色方块**（其下挂 8 个口标记）——这正是"角色"要表达的东西。

### D2. 方块画什么（内容固定三段，尺寸不随内容变）

```
┌──────────┐
│ → {seq:u64, value:f32} │     ← 方向小箭头（方向色）+ 类型文本（省略号截断）
│   2 口 · 2 连           │     ← 口数 / 已建立的口级连接数
└──────────┘
```

| 元素 | 取值 | 依据 |
|---|---|---|
| **填充** | 类型色（`PacketTypePalette.For(role.TypeKey)`） | 同一类型 = 同一色，跨模块一致 |
| **边框 + 小箭头** | **方向色**（`DirectionSend` / `DirectionReceive`） | 与端口标记"箭头 + 边框"**同构**（用户不必学第二套颜色语言） |
| **类型文本** | `role.TypeText`（`{seq:u64, value:f32}` 之类），过长**居中省略** | 呈现给人看；**身份**用 `TypeKey`（D6） |
| **口数 / 连接数** | `role.Ports.Count` / `role.ConnectionCount` | 一眼看出"这个角色下有 8 个口、连了 3 条" |
| ~~状态色~~ | **不画**（停流/悬空只在端口标记与线上；同一事实只在一处表达） | ADR-0048 R5 |

### D3. 方块**分侧摆放**（发送靠右、接收靠左）——本 ADR 的主要观感变化

现状是"所有方块在模块中心成组"，线要**横穿整个模块**才能到边界。角色带方向后可以更省：

| 侧 | 内容 | 排布 |
|---|---|---|
| **右内侧** | 全部**发送角色** | 单列**竖直居中**堆叠，间距 `RoleBoxGap`；放不下 ⇒ 第二列（再放不下按 D11 降级） |
| **左内侧** | 全部**接收角色** | 同上 |

- 收益：① 线**不再横穿模块**（起点离边界更近、更少交叉）；② "左边进、右边出"与端口标记的左右分侧**一致**，读图顺序自然；
- 代价：与上一版观感差别明显（这正是"整体替换"的含义）；
- **备选（不推荐）**：仍居中成组 —— 好处是与上一版连续、坏处是线长且易交叉。

### D4. 线 = **角色对**（一条线 + `×N`）——**两点一线 + 一裁**（用户第三十三轮简化）

- 线数 = `GetRolePairs(instanceId).Count`（**同一角色对的多条口级连接/多条网络已聚合**）；
- **几何只有两个点**：① **本端角色方块中心**；② **对端窗口中心**（`RoleLinkViewModel.Target`，本窗局部坐标）；
  两点连线被**本窗矩形**一裁 ⇒ **长度与角度全部由此得出**。用户原话："**通过核心的坐标和是否连接即可计算连线的长度和角度**"；
- **起点** = 该连线与角色方块边界的交点（不压住方块里的文字）；**终点** = 与本窗边界的交点；
- **删掉的东西**（上一版把简单事情做复杂了）：`BoundaryOffset`（"该角色各口的平均位置"）、
  `PeerSide`（上下左右的方位分类 + 回退）、按方位特判的端点计算 —— 这些都不再存在；
- **箭头朝向**由这条线自己给出：**发送 = 数据离开模块**（箭头沿"起点→终点"朝窗外）、**接收 = 数据进入模块**（反向）——
  任意角度都自然正确；
- **`×N` 徽标**：`Count > 1` 时把 `×N` 附在线的标签行（`网络名 ×N`），`Count == 1` **不显示**（不加噪）；
- **多源网络**：不同模块的源 = **不同的对端角色** ⇒ **各自一条线**（ADR-0050/0048 R6 的既定语义，不在 UI 上合并）；
- 颜色/虚线/箭头/淡出/对端标注规则 **逐条沿用** ADR-0045（D4 中点色相接等）；对端不在现场（未装入/隐藏）⇒ 瞄准点取
  "**本端角色外侧方向上的一点**" ⇒ 线朝模块外侧走到边界。

### D5. 未连接的角色

- 该角色下**所有口都未入网** ⇒ 画**短虚线残段 + `未连`**（沿用现规则，方向色不透明、按边朝外、窗口内钳制）；
- 部分口连、部分未连 ⇒ **有线就画线**；未连的**口**仍在端口标记上（灯灭）与信息区计数里体现，**不**为它单独画第二条残段（避免线数与角色对数不一致）；
- 信息区给出 `未连 k` 计数（k = 完全未连接的**角色**数）。

### D6. 类型色板按**类型身份键**映射

- `PacketTypePalette.For(string typeKey)`：键 = `TypeKey`（`hyw/analog-sample@v1`；未声明类型 ⇒ 结构描述）；
- 迁移：**现在**接口就已经收字符串，只需把调用点从 `port.TypeText` 改成 `role.TypeKey`，**映射表仍是空的**（中性占位色）；
- **为什么必须是 TypeKey**：`TypeText` 会把"不同标识同形状"（ADR-0051 明确不是同一种量）涂成同一色，**与 P3 的角色合并规则自相矛盾**；
- 映射表（谁给颜色）见 **P4-Q4**。

### D7. 信息区（**分区域 × 字号分层**）

> 用户第三十三轮重申："**分区域和根据字号大小显示不同的信息**"（原始口径见 ADR-0045 **D9**：一眼级 12 / 11 / 10 px）。
> 上一版把所有内容拼成**一行 10px** 贴在右下角 —— 既没分区、也没分层，等于把这些信息重新"藏"了起来。本版改为：

| 区域 | 内容 | 字号 / 颜色 | 依据 |
|---|---|---|---|
| **左上·第一行** | `实例 · 模块名`（身份） | **12px** · 主色 | 一眼认出"这是谁" |
| **左上·第二行** | **结构事实**：`角色 2（收 1 发 1）· 口 2 · 连 2 [· 未连 1]`；零口 ⇒ **`无数据口`** | **10px** · 次要色 | 结构不常变、不必抢注意力；紧贴身份便于对照 |
| **右下·第一行** | **主要指标**：`投递 1,234 · 丢弃 2`；无连接 ⇒ `无连接` | **11px** · 主色 | 调试时**最该先看到**的两个数 |
| **右下·第二行** | **模块级速率**（各角色对速率之和；无流量 ⇒ **不占位**） | **10px** · 次要色 | 补充信息，放第二档 |
| **方块自带两行** | 类型文本 + `N 口 · M 连` | 11px / 10px | 每个方块自己说清"我是哪种数据、几个口、连了几条" |
| **线上标签** | `网络名 [×N]` + 该线的速率；未拼接时再标对端实例 | 11px / 10px | 只在有线的位置出现 |

**为什么结构不在左下**（渲染自检发现）：**左下角是模块自己的运行指示**（ADR-0039 D1），叠上去当场糊成一团 ⇒
身份与结构都放左上（两块同列、不同字号），右下只放指标（该角无模块自有元素，且留 `Gutter` 即可避开 20px 端口标记带）。

**现状核查**（`ConnectionOverlay.Render` ③ / `Summary`）：

- 旧实现 = **左上标题 + 右下 `投递/丢弃`** 两处；本 ADR 把它扩成上表六块，**每块一种信息、三档字号**；
- 修改点集中在 `ConnectionOverlay.Render` 的信息段与 `RoleProjectionSummary.Build`（**纯函数，可单独断言**）。

### D13. **内部角色 → 角色线**（模块自身的数据流；与网络拓扑无关）【用户第三十一轮追加】

> 用户原话："**同模块内的角色之间可能也有关联**（同模块可能多端口/多角色，特别是对于复杂模块，
> 该关联与底层通信网络拓扑无关，**属于模块自身配置/属性的一部分**，需要考虑简单的可扩展性），
> **这里的连线也需要**，不过逻辑应该较为简单。"

| 项 | 决定 |
|---|---|
| **是什么** | "数据从本模块的哪个**接收角色**流到哪个**发送角色**"——表达模块**内部处理关系**（如融合器：`in1 → out`、`in2 → out`）。**与任何具体网络/实例无关**（同一模块的多个实例画法相同） |
| **为什么不能纯派生** | 该关系是**设计信息**（融合器"两路合一"这件事推不出来）：同类型收发口之间**没有**必然关系；若按"接收角色 → 发送角色全连"猜，会画出大量**不存在的线 ⇒ 虚假信息**。⇒ **声明式**：**模块声明，框架只投影**；**零声明 ⇒ 不画**（不猜） |
| **声明面（SDK，只增）** | `IModuleDeclaration.DeclareFlow(FlowDeclaration)`；`FlowDeclaration(string FromPort, string ToPort, string? Label = null)`。框架**只存不解释**（与端口/视图元素同级），随模块定义加载，**不进组合件**（派生自负，无需持久化） |
| **自检** | `FromPort` 必须是**本模块的接收口**、`ToPort` 必须是**本模块的发送口**（"进入 → 输出"是唯一有意义的方向；其他组合在 `ModuleContract` 自检里报 Issue 并忽略该条）· 两端必须存在（否则报 Issue）· 同（From,To）重复 ⇒ 去重（保留首条 + 提示） |
| **映射到角色** | **口 → 角色是唯一的**（一个口只有**一个方向**与**一个类型身份**）⇒ 内部流天然是"**角色 → 角色**"；同一（角色→角色）有多条 ⇒ **一条 + `×N`**（与对外角色对同一套聚合规则） |
| **画法（必须与对外线区分）** | **细实线 + 中性低对比色 + 小箭头示向**，端点落在**角色方块边缘**（不压文字）；**不走方向色渐变、不参与 20Hz 流动相位**——否则用户会误以为"这里有数据在流"。对外线保持"方向色渐变 + 粗虚线 + 流动" |
| **红线** | 不参与建网 / 兼容 / 停流 / 投递 / 计量（ADR-0046 §4/D3、ADR-0048 R9）；**停流/未连不影响它**（它是**结构**，不是流量）；不参与命中（`IsHitTestVisible=false` 不变） |
| **可扩展性** | v1 只做"接收口 → 发送口"的**静态结构线**（`Label` 目前不用，留作将来注记）；**不做**内部流的速率/延迟指标（那需要模块自己在数据源层面给，**不是**框架功能）；不做接收→接收、发送→发送（无意义） |
| **参考模块落点** | **融合器**（`in1 → out`、`in2 → out`）是本轮唯一的自然范例；Monitor/Recorder/Asserter 无发送口、DataGenerator/ManualSender 无接收口 ⇒ **无内部流**（零声明零线，正好验证"不猜"） |

**与 ADR-0048 R3 的关系**：R3 的"**纯派生**"说的是**角色身份**（角色不声明）；本 D13 声明的是**内部处理关系（边）**，
**不是角色声明** ⇒ §6.2"不引入业务分类"的裁决**不变**（框架仍不理解业务语义，只画模块自己声明的结构）。

> **〔ADR-0052 修订（已落地）〕**：D13 的声明面**改为「角色 → 角色」**：
> `FlowDeclaration(string FromRoleId, string ToRoleId, string? Label = null)`；自检改为"两端角色必须已声明 · 不得自环 · 同（起点,终点）不重复"。
> 理由：角色已经把"口"收进了**功能分块**里（一块 = 一类型 + 它的入/出口），于是"块内部的 in→out"**不需要再声明**；
> 剩下真正需要表达的只有"**块与块之间的处理顺序**"（多分块模块，如"融合 → 限幅 → 输出"）。
> 参考模块都是**单块** ⇒ **零声明零线**（`RoleOrder` 为空），这也正好验证"不猜"。
> 另：对外线**不再标网络名与 `×N`**（网络标签属接口层，ADR-0052 §4）；`PortPairCount` 只作内部量，不给用户看条数。

### D8. 多源网络的呈现（源侧 / 宿侧各一条线）

- **宿侧**：一条多源网络 → 对端有 N 个不同实例 ⇒ **N 条线**（各自标对端实例；同实例多口 ⇒ 一条 + `×N`）；
- **源侧**：源角色 → 该来源所服务的所有宿（多播）⇒ 按"对端实例 + 对端角色"**各一条线**；
- 线上不再需要"来源"字样（P3 的 `NetworkKeys` 已能表达"几条网络"，且 M4 规定**来源不进数据面**）。

### D9. 层级、命中、遮罩、开关**全不变**

- 遮罩 `OverlayScrim`（浓度 = token，不进设置项）· `IsHitTestVisible=false` · 叠加层在**端口标记之下、连线跨过标记** ·
  默认关闭 + 快捷键 `L`；**不自绘任何文字控件**（全部 `DrawingContext`，与现实现一致）。

### D10. 数据从哪来（`Ui` 不新增对 Core 的引用）

- `ModuleWindowViewModel` 已持有运行时查询面（`IRuntimeQuery`）⇒ 刷新时对**本实例**取 `GetDataRoles` / `GetRolePairs`；
- 新增**只读 VM**：`RoleBoxViewModel`（Key/IsSend/TypeKey/TypeText/Ports/ConnectionCount/X/Y/W/H/Fill/Border）与
  `RoleLinkViewModel`（LocalRoleKey/PeerInstanceId/PeerRoleKey/Count/NetworkKeys/端点/线色/标签/`PeerAdjacent`）；
- **投影规则全部在 Ui 侧**（Core 不画图、不排版）；`Core.Api` **本轮零改动**（P3 已备好）。

### D11. 小窗降级（角色数比类型数多，必须明确）

| 情形 | 策略 |
|---|---|
| 一侧放得下 | 单列竖直居中 |
| 单列放不下 | **第二列**（同侧内），列间距 `RoleBoxGap` |
| 两列仍放不下 | 方块边长 `RoleBoxSize → RoleBoxSizeSmall`（14 → 10），文字保留 |
| 仍放不下 | 同侧只画前 `N` 个 + **`+K` 徽标**（`K = 未画出的角色数`）；**线照画**（线多但方块少时，仍以线为准） |
| 宽度不足（类型文本被压） | 文本**居中省略**；`TypeText` 的完整内容仍在**端口标记的悬停提示**里（已有路径） |

- 阈值与尺寸**全部写成 `ConnectionOverlay` 的常量 + XAML token**（沿用"改观感只改一处"的既有做法）；
- **不做**自动滚动、不做缩放方块（叠加层是观测层，不是编辑器）。

### D12. 明确**不做**的事（防止范围膨胀）

- **不做**跨窗口的"整条角色→角色线"（仍只是各窗画自己那半段，公共边颜色相接 —— ADR-0034/0045 不变）；
- **不做**角色方块的拖拽/双击（角色是**派生只读**视图；建网入口仍是端口标记）；
- **不做**角色的显式命名/分组（P3-Q3：v1 纯派生）；
- **不做**"按角色过滤/筛选"、"点击角色高亮链路"（需要交互状态与持久化，留待未来，且应先问用户）；
- **不做**叠加层内的指标图表（速率曲线属于模块自己的 UI）；
- **不做**内部流的速率/延迟（D13：内部流是**结构**；要指标得模块在数据源层面自己给）；
- **不做**"数据包类型表"的**实现**（见 §8：本轮只留接口，单独一轮做）。

## 8. 后续项评估：**数据包类型表（侧边栏）**（用户第三十一轮要求评估）

> 用户原话："这里不能简单下结论，因为涉及到另一个功能：**映射表**，但是这个映射表不只是映射颜色，
> **更是观察状态的手段**。可以使用哈希配色+覆盖表，同时在**侧边栏**交互中显式加入**数据包类型表**的位置
> （下面很大一块空着的，刚好放），允许用户**手动配置颜色**，但是该实现项**需要评估，涉及到很多耦合项**；
> 如果你认为非常复杂，就仍然**保留接口**，做完 UI 下一轮去做。"

**我的评估结论**：**不是"非常复杂"，但是一个独立功能**，且**有 4 个真实耦合项**——混进 P4 会让
"叠加层整体替换"（本身已是全量几何重写）额外承担"新查询面 + 设置迁移 + 跨主题可读性"的风险。
⇒ **建议：P4 只留接口，下一轮单独做（并单独出一份 ADR）**。耦合项如下：

| # | 耦合项 | 为什么绕不过去 | 工作量 |
|---|---|---|---|
| 1 | **"全场类型清单"查询面缺失** | 侧边栏要列"本场出现过哪些数据类型"，而现在的类型信息只在**每实例**内（`ModuleInstance.DataTypes` / `PortView`）。需要 `Core.Api` 新增只读查询（如 `GetDataTypes()` → 键/呈现文本/尺寸/计量块/**声明者列表**），并跨模块去重 | 小（只增一个查询 + 视图），但**是新的公开面** |
| 2 | **用户配置要持久化** | 颜色是**用户决定** ⇒ 进 `ApplicationSettings`（按 **`TypeKey`** 为键），涉及设置 schema **只增字段** + 旧文件兼容 + "改了颜色立刻重绘所有窗口"的通知路径（现设置变更已有广播，需接上） | 中 |
| 3 | **渲染入口必须唯一** | 颜色至少影响**两处**（叠加层角色方块、端口标记窄色条），将来还可能影响拓扑/图例 ⇒ 必须让 `PacketTypePalette` 成为**唯一映射入口**并支持**运行时覆盖 + 变更通知**（现在它是静态占位） | 小（P4-c 已铺路） |
| 4 | **浅色/深色主题下的可读性** | 用户选的是**绝对颜色**：深色主题选的颜色到浅色主题可能不可读（方块上的文字对比度不足）。需要策略：**每主题一套** 或 **自动对比度**（取色时保证与文字/背景的对比度）；这是**产品决策**，不该由实现者默认 | 中（含决策） |
| 5 | （附）**"观察手段"的含义需要定义** | 用户说它"不只是映射颜色，更是观察状态的手段" ⇒ 这张表可能还要显示**该类型的实时速率/计数/丢弃**（那就同时是"图例 + 指标面板"）。**范围需要先定**，否则实现会漂移 | 待用户澄清 |

**P4 本轮保留的接口**（下一轮直接用）：
① `PacketTypePalette.For(TypeKey)` 作为**唯一入口**（哈希配色 + 覆盖表，覆盖表**可注入**）；
② `Ui` 侧不缓存颜色（每次经 `PacketTypePalette` 取），换映射即全量生效；
③ 端口标记窄色条与角色方块**共用**同一入口（颜色天然一致，不会两处不一致）。

**下一轮开工前需要你定的两件事**（届时我会单独出 ADR）：
(a) 这张表**只是图例（颜色 + 类型信息）**，还是**兼作指标面板**（带速率/计数）？
(b) 颜色**按主题各一套**，还是**一套色 + 自动保证对比度**？

   `PacketTypePalette.For(null)` 恒为占位色。由"窄色条颜色"用例抓出（期望 `For(TypeKey)` 与实际不同）⇒
   在 `RuntimeServices.ToView` 里用 **`DescribePortTypeKey`（与角色键同一来源）** 补齐。**教训**：新增公开面字段时，
   **同一次改动里就要有生产者与消费者**（与 `LESSONS` 45"旁路元数据必须有消费者"同源）。
2. **方块贴边导致线退化成残段**：第一版把方块放在"外侧留 `Gutter(24)`"处 ⇒ 默认窗口（320 宽）下线长仅 **24 px**
   （与 20 px 标记带同量级，视觉上又"像坏了"）。改为 `RoleColumnInset = 46`（并保证**不越过窗口中线**），
   默认窗口下线长 ≈ **46 px**；几何用例把"线长必须显著大于标记带"钉住，防止以后再退化。

> 用户反馈（原话）："**1. 连线能看出趋势，但是仍然看起来连不上**，用户可以看到'因窗口未拼接产生的一根看起来缺少一部分的线'，
> 但是**不应该看到'两根错位的线'**。**2. 缺少信息，同时左上角信息多余**，有几个口/几个角色不需要用文字表达，
> 这通过图像可以很清晰看出；反而缺少一些重要的信息（这些信息常态下被隐藏或是不清晰），**如速率等**。
> 我给你画了一张草图。这张草图仅作示意大致观感，从配色到绘制全部不精确甚至有误，**需要你详细设计**。先出设计方案。"

### 10.1 诊断（先给根因，避免"看起来像调参问题"）

| # | 现象 | 根因（几何定义层面） |
|---|---|---|
| 1 | **两根错位的线** | 现在**两端各自定义自己的线**：A 窗画"从 **A 的方块中心**朝 **B 的窗口中心**"的射线在 A 窗内的部分；B 窗画"从 **B 的方块中心**朝 **A 的窗口中心**"的射线在 B 窗内的部分。两条射线**起点不同、方向也不同**（指向的是对方的**窗口中心**而不是对方的方块），除极特殊情况外**不共线** ⇒ 两窗之间出现**两根错位**的线。**这不是参数问题**：只要"各端各自定向"，就一定会在窗口尺寸不同/位置偏移/重叠时错位。 |
| 2 | 左上信息多余 | `角色 a（收 b 发 c）· 口 m · 连 n` 把**图上已经能看见的事实**又用文字说了一遍（方块数 = 角色数；方块上的口数刻度 = 口数；线数 = 连接数）⇒ 占位却不增量。 |
| 3 | 缺少重要信息 | 真正"常态看不到"的量（**速率 · 投递 · 丢弃 · 最后数据时间 · 类型语义 · 标称速率/掉速 · 队列水位**）目前只在**悬停提示**或**拓扑诊断**里，叠加层里只给了一个模块级总数。 |

### 10.2 设计（**D14–D20**）

#### D14. **线是"一条线"，各窗只画自己窗内的那一段**（修"两根错位线"）

- **先定义线，再各自裁剪**：一条角色对线 = **本端角色方块中心 ↔ 对端角色方块中心** 的线段（**唯一一条**）；
  每个窗口只画**这条线段与自己窗口矩形的交集**。
  - 起点（本窗内） = 该线段与**角色方块边界**的交点（不压方块文字）；
  - 终点（本窗内） = 该线段与**本窗边界**的交点。
- **为什么这样就不会错位**：两段是**同一条直线**的两部分 ⇒ **严格共线**。
  - **相邻/拼接** ⇒ 两段在公共边**正好接上**，看起来是**一根连续的线**（无缝）；
  - **未拼接（有间距）** ⇒ 各自被自己的边界裁断，中间恰好空出"两窗之间那一段" ⇒ 正是你说的"**看起来缺了一部分**"（可接受）；
  - **窗口重叠** ⇒ 两段仍在同一条线上（各画各窗内部分），**不会再出现两根错位的线**。
- **对端角色方块中心怎么算**：`ModuleWindowsViewModel` 已经持有**全部模块**，用与自身**同一套** `LayoutRoles`
  （对端角色清单 + 对端窗口宽高）算出对端方块中心，再把屏幕坐标换算到本窗局部坐标 ⇒ 与对端自己画的位置**必然一致**。
- **回退链**（对端不可用时逐级降级，绝不猜）：① 对端角色方块中心 →（未装入 / 对端没有该角色 / 占位实例）② **对端窗口中心**
  →（对端不在现场）③ 沿**本端角色外侧**方向出窗（现状行为）。

> **〔ADR-0052 修订（已落地）〕**：线的两端由"**方块中心 ↔ 方块中心**"改为"**发送角色方块的输出侧中点 ↔ 接收角色方块的输入侧中点**"。
> 仍然只定义**一条线段**、各窗只画自己窗内那一段（共线原理不变）；端点落在接口侧中点是"左入右出的功能块"的自然结果
> （方块中心在块内，线会压住块里的文字）。回退链保留：对端角色不可用 ⇒ 对端窗口中心 ⇒ 本窗信息区（见下）。

#### D15. 末端处理：**未拼接不淡出**，改为"断口"表达

- 现状：未拼接时末端 14px 淡出 —— 实机上"淡出"让"缺一段"更像"线坏了"。
- 改为：**实线画到边界**（保持线的完整性）；**未拼接**时在终点画一个**小断口标记**（贴边的一段 3px 竖线 + 对端名），
  明确表达"**线在这里被窗口裁断，另一端在窗外**"；**拼接**时**不加任何标记**（无缝）。
- **待裁决 Q13**：断口标记用哪种（a 竖杠 · b 小箭头 · c 什么都不加，只保留对端名）。

#### D16. 角色方块**去文字**（按草图意图）

- 方块 = **类型色填充**（同类型跨模块同色）+ **方向色边框** + **方向小箭头**；**不再写**类型文本、**不再写** `N 口 · M 连`。
- **口数用图形表达**（"几个口不需要用文字"）：方块**靠模块内侧**一列 **口数刻度**（每口 1 条 2px 短竖线；
  ≤6 口精确显示，>6 口显示 6 条 + 一个点，精确值进悬停）。
- **类型识别**：**颜色**（一眼辨"是不是同一种数据"）+ **悬停**给出完整信息（类型标识/版本/尺寸/语义/口列表/连接数/速率）。
- **功能图标**：草图提到"可用图标表示角色的大致功能，或**无文字/图标、只有类型色**"。
  **v1 建议：不做业务图标** —— 框架不知道业务语义（主文档 §6.2"不引入业务分类"），凭空配图标等于框架替模块定义业务。
  方向已由**边框色 + 小箭头**表达（进/出）。若将来要图标，应由**类型声明的语义标签**驱动（模块自己声明，框架只映射）。
- **待裁决 Q14**：口数表达方式（a **刻度**（推荐）· b 角标 `×N`（很小）· c 只进悬停）。

> **〔ADR-0052 修订（已落地）〕**：方块**不是"无文字"**——按用户第三十三轮 Q14 口径，方块内**两行** =
> **功能名**（无则类型短名）+ **`m/n`**（输入/输出侧连接的**对端角色数**）。"几个口"继续用**刻痕**表达，
> 但只在**该侧口数 &gt; 1** 时画（1 个口是常态，不加噪）；**类型长文本不进方块**（靠颜色 + 悬停）。
> 填充/接口边的取色规则不变（填充 = 类型色，左 = 接收方向色、右 = 发送方向色）。
> 另：方块摆放定为**单列竖直堆叠、居中**（原 §3 的"发送靠右、接收靠左"随新模型作废——一个块同时有两侧）。

#### D17. 线信息卡（**补"缺少的信息"**）〔**已被 ADR-0053 取代：改为角色方块上方的纯文字**〕

> **⚠️ ADR-0053 修订（第三十四轮）**：用户："这些信息表达的**不是「数据通路信息」，而是「角色本身速率信息」**……
> **每一个角色块显示其自身的信息**" ⇒ **卡片整体删除**（连同 `OverlayCard` 令牌），改为画在**角色方块上方/周围**的**纯文字**，
> 数据取**角色的自身聚合**（产出侧优先）；**线上一律不写文字**。下面这张表的内容与字号分档**继续有效**，落点见 **ADR-0053 D4**。

- **位置**：线的**中点**附近（`Lerp 0.45–0.55` 之间取第一个不与方块/标记带冲突的位置），卡片**贴着线的一侧**（上方 6px）。
- **只画一次**：一条角色对**只由发送端窗口绘制**（避免两窗各画一张、信息重复）。
- **内容（三行，字号分档）**：

| 行 | 内容 | 字号 / 颜色 | 数据来源（框架口径，UI 不自算） |
|---|---|---|---|
| ① **速率** | `123 B/s`（用户草图的 `123b/s`） | **11px · 主色**（最重要） | `BindingDiagnosticView.BusByteRate`（**搬运字节速率**，含自描述/填充，按宿合计）；无流量 ⇒ `---` |
| ② **投递 / 丢弃** | `↑1,234 ⊗2`（`↑` = 投递，`⊗` = **传输丢弃**） | 10px · 次要 | `Delivered` / `DropTransport`（**停流未投递**另计，不与传输丢弃混算 —— ADR-0046 D8） |
| ③ **类型语义 · 标称** | `normal · 100 Hz`（无声明则省略） | 10px · 次要 | `SemanticTags` / `MeteringBlock.NominalRateHz`；有了标称才能看"**掉速**" |

- **样式**：新增 token `OverlayCard`（半透明深底 + 1px 边框 + 圆角 2）——压在模块内容/线上都可读。
- **待裁决 Q15**：第 ② 行的口径 —— (a) **投递/丢弃**（推荐，与框架三类丢弃一致）· (b) 你草图里的 **输入/输出**
  （若指"**发布 ↔ 投递**"这对量，我可以改成 `发出 1,234 → 收到 1,234`，它能直接暴露"多播放大"与"丢在哪"）。
- **待裁决 Q16**：卡片是否**可悬停展开**（四档速率 / 三类丢弃 / 队列水位 / 最后数据时间）。展开需要**参与命中**（现在是全层不命中的），
  会与"双击标记改网络名"的命中纪律耦合 ⇒ 我倾向 **v1 不展开**（卡片已给最重要的三项），把细节留给悬停**端口标记**与拓扑诊断。

#### D18. 左上角**只留身份**

- 保留：`实例 · 模块名`（12px）——"这是谁"必须常显。
- **删除**：`角色 a（收 b 发 c）· 口 m · 连 n`（图上可见的事实，不再用文字重复）。
- **保留一句例外**：**零数据口** ⇒ 左上第二行写 `无数据口`（图上"没有方块"与"画失败/没画"无法区分，必须有一句事实；ADR-0048 R4）。

#### D19. 模块级汇总：**倾向删除**（同一事实只在一处表达）

- 每张卡片已经给出该条流线的速率/投递/丢弃 ⇒ 右下角的 `投递 … · 丢弃 …` 是**同一事实的第二个出处**
  （与"数据指标来源唯一"同一纪律）。
- 建议：**删掉模块级汇总**；仅当**没有任何连线**时显示一句 `无连接`（与 `无数据口` 同级的"状态事实"）。
- **待裁决 Q17**：是否同意删除（我推荐删；若你想保留一个"模块总量"，我建议改为**极小字号**的 `Σ` 行）。

#### D20. 避让与冲突规则（把"看起来乱"钉死）

1. 所有叠层文字/卡片**一律留在 `Gutter` 以内**（不进入 20px 端口标记带；标记带是标记自己的地盘）；
2. 卡片与角色方块冲突 ⇒ 沿线向中点靠拢重试（最多 3 个候选位置，取第一个不冲突的；都不行 ⇒ 贴中点）；
3. 对端名标签：**仅未拼接**时显示，位置放在**终点内侧**、并避开左上信息块与右下卡片；
4. 同一窗口内多条卡片重叠 ⇒ 沿**垂直方向**错开（每条 12px），仍不越界。
