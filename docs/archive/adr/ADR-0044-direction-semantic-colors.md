# ADR-0044：方向语义色（发送/接收）与主题色解耦 + 设置项

> **状态**：**Accepted（2026-09 · 用户逐条裁决 D1–D7，已实现，待复验）**
> **关联**：ADR-0038 D4（主题/背景设置）· ADR-0039 D3/D5（标记方向箭头、叠加信息层）· ADR-0043（标记内容重排）· `09` §2/§7/§8 · `05` §5.18/§5.23 · 主文档 §9.5 · `implementation/02` P39
> **修订对象**：`09` §2.1/§2.2（新增两个颜色角色）· `05`（新增消费者表）· 主文档 §9.5（新增两个设置键 → **1.0.13**）· `implementation/04`（新增验收项）

---

## 1. 背景与问题（现状核查：不是"没一致化"，而是一致化错了对象）

用户第十四轮提出："一致化全局带有**发送/接收**语义的颜色，并在设置中添加颜色设置"。核查现状后发现三个结构性问题：

| # | 现状 | 问题 |
|---|---|---|
| ① | 标记箭头：发送 = `AccentPrimary`、接收 = `AccentSecondary` | "方向"这种**稳定语义**被绑在"主题色"这种**全局偏好**上：用户改一次主题色 = 同时改了一堆语义色 |
| ② | `AccentSecondary` 由 `ThemeApplier.Secondary(accent)` **公式派生**，而 `AccentColor` 默认值 `#2563EB` **永远能解析成功** | `Tokens.axaml` 里内置的 `AccentSecondary`（浅 `#0891B2` / 深 `#22D3EE`）**从没生效过 = 死值**；且"接收色"永远只是主题色的一个邻近色，用户无法单独指定 |
| ③ | "即将建网"描边 = `AccentPrimary`，与"选中边框""活动项"**同色**；叠加层流向箭头 = `AccentPrimary`（且见下） | 多个语义共用一个色 ⇒ 用户无法通过颜色区分"这是发送端"还是"这是被选中的" |
| ④ | **实施期发现（本轮一并修掉）**：`ConnectionOverlay.DrawArrow` 建好几何后**从未调用 `DrawGeometry`**，且 `ArrowBrush` 属性**无任何消费者** | 叠加层的**流向箭头从来没画出来过**（"死属性 + 死绘制路径"）——与用户"叠加层太潦草"的观察一致 |

**核心判断**：所谓"一致化"的正确对象是**语义**（发送 = 一个语义、接收 = 一个语义），而不是"某几个元素"；语义一旦抽出来，颜色就必须可被**单独**指定，且不再由主题色派生。

## 2. 决策（用户逐条裁决）

| # | 裁决 | 内容 |
|---|---|---|
| **D1a** | **方向色完全独立于主题色** | 用户原话："**完全独立，这正是为何要做这一次调整**"。方向色有**自己的内置默认值**（深浅两套各一份），**不再从主题色派生**；主题色只表达"选中/聚焦/活动"等**框架性交互**语义 |
| **D2c** | **一致化范围 = 箭头 + 标记框 + 叠加层流向箭头** | 用户：**"标记框相同效果着色，我认为这样更清晰"**（原 D2 选项 c） |
| **D3b** | **"即将建网"描边用同一方向色** | 用户："边框也使用箭头色，建网时也表达'这是接收/发送端'的语义，**这与即将建网提示并不冲突**" |
| **D4** | **叠加层连线是否按方向分色：保留问题** | 用户："之后会有一轮**叠加层专项**调整，当前叠加层太潦草，我之后将详细对其进行设计" ⇒ 本轮**连线保持单色**，只做箭头取色 |
| **D5** | **命名与落点同意** | token `DirectionSend`/`DirectionReceive`；设置键 `directionSendColor`/`directionReceiveColor`；设置页"外观"区、色片 + Flyout（预设 + 十六进制）+ 一处实时预览 |
| **D6** | **不做任何提示** | 用户："完全尊重用户选择，个性化内容不应干预用户立场，用户决定不好看会自己改回去" ⇒ 不校验、不警告两色相同/低对比 |
| **D7** | **主题色只影响"模块共有元素/框架性颜色"** | 用户原话类比 Windows："主题影响各个窗口的共有元素的视觉效果……但并不妨碍每个应用程序有自己完全不同的风格；具体内部每个不同模块特有的绘图细节/文本颜色等**模块自己决定**" |
| **追加边界** | **数据-颜色绑定不属本轮** | 用户："数据-颜色绑定与后面我会做的一轮**协议相关专项**评估调整有关，现在它们的颜色**仍然只做预留**" |

### D7 的连带影响（本轮只登记，不实现）

- `ModuleContentView.axaml` 的曲线 `Stroke="{DynamicResource AccentSecondary}"` = **框架色泄漏进模块私有绘图**，与 D7 冲突；
- 但"数据-颜色"依赖将来的协议专项（模块如何声明颜色）⇒ 本轮**不改代码**，只在本文与 `05` 登记为**已知偏差 + 待办**（届时由"数据-颜色专项"落地：曲线颜色改由模块声明/自定，与主题色无关）。

## 3. 落地（代码事实）

| 项 | 落点 |
|---|---|
| **颜色角色** | `Tokens.axaml` 深浅两套各新增 `DirectionSend` / `DirectionReceive`：浅 `#EA580C`（暖橙）/ `#0891B2`（冷青）；深 `#F59E0B` / `#22D3EE`。**默认刻意避开"红/绿"对**（色盲友好） |
| **设置模型** | `ApplicationSettings.DirectionSendColor` / `DirectionReceiveColor`：**默认空串 = 跟随主题默认值**（这样深浅两套内置值都有效；`Clone()` 同步）；`SettingsService` 读写 `directionSendColor`/`directionReceiveColor`（**只增不改**、不做值域校验，见 D6） |
| **主题应用** | `ThemeApplier.BuildOverrides`：**仅在用户显式填色时**覆盖 `DirectionSend`/`DirectionReceive`；空串 ⇒ 不覆盖 ⇒ 跟随内置 token。同时给 `Secondary()` 补注释：方向语义**已不再使用**该派生色 |
| **设置界面** | 「外观」区新增**发送色 / 接收色**两行（色片按钮 + Flyout：8 个预设 + 十六进制输入，清空 = 跟随主题默认值；右侧显示 `跟随主题` 或色值）+ **实时预览**（`↑发送` / `↓接收` 两个色块）。`SettingsPanelViewModel` 新增两个可观察属性、两个预设命令、`DirectionSendBrush/ReceiveBrush`（未自定义时**读当前主题的有效值**）、`DirectionSendText/ReceiveText` |
| **标记视图** | `ModuleWindow.axaml`：标记 `Border.portMarker` **去掉内联边框色**，改由 `Window.Styles` 的 `Border.portMarker`（默认接收色）/ `Border.portMarker.send`（`Classes.send="{Binding IsSend}"`）着色；**建网预览描边**同一个方向色（`Border.dockHighlight` / `.send`，仅以 **线宽 2 vs 1** 区分）；**箭头 4 处** `Foreground` 改为方向 token |
| **叠加层** | `ConnectionOverlay`：`ArrowBrush`（**死属性**）→ 替换为 `SendArrowBrush` / `ReceiveArrowBrush`；`Render` 按 `port.IsSend` 取色；`DrawArrow` 增加画刷参数并**真正调用 `DrawGeometry`**（修掉"箭头从未绘制"）；补 `static ctor → AffectsRender(...)`（此前**缺失**：改画刷不会重绘，设置里改色后线条要等别的失效才刷新）。连线仍为单色（D4） |

**槽位/尺寸**：本 ADR **不改**标记尺寸与内部排版（ADR-0043 结论不动）。

## 4. 明确不做（边界）

| 项 | 理由 |
|---|---|
| 叠加层**连线**按方向分色 | D4：保留问题，归"叠加层专项"重设计 |
| **状态色**（ok/warn/error/idle）可配置 | 健康语义；改坏会削弱警示力（09 §7 要求"颜色 + 形状双重编码"兜底） |
| **交互强调色**（选中/悬停/聚焦/活动/参考线）跟随方向色 | 二者语义不同；混用正是本轮要消除的病根 |
| 两色相同 / 低对比时的提示或校验 | D6：完全尊重用户选择，不干预 |
| 数据-颜色绑定（曲线/日志等模块私有绘图配色） | 归"协议相关专项"；本轮**只做预留**（D7 登记为待办） |
| 网络身份色 / 类型色板设置 | 分属后续档位（类型色板等用户给映射；网络色缺展示面） |

**"做到什么程度为好"的判据（写入 `05`，作为以后开颜色设置的准入条件）**：
① 该语义是否在**多处**出现；② 用户改色后是否仍能靠**形状/位置**读懂（双重编码）；③ 两个颜色是否**同屏同时出现且需要区分**。
三条全"是"才开设置项；**用户可调颜色总数上限建议 ≤ 6**（主题色 · 背景 · 发送 · 接收 · [类型色板] · [网络色]）。

| 层 | 结果 |

| **新增断言**（`端口标记_方向色应来自方向语义色且与主题色无关`） | 发送口标记**边框**与**箭头** = 发送色；接收口 = 接收色；**建网预览描边** = 同一方向色；主题色故意设成第三个颜色（`#16A34A`）而方向色不变 ⇒ 证明**与主题色解耦**；清空设置后回到 `Tokens.axaml` 的内置值 ⇒ 证明"空 = 跟随主题"且**深色默认值不是死值** |
