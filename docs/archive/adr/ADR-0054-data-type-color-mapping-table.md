# ADR-0054：**数据结构（类型身份）→ 颜色映射表**（侧边栏「交互」页）

> **状态**：**Accepted + 已落地**（用户第三十四轮："**添加数据结构-颜色映射表**，添加应该很简单，之前应该预留了很多接口。
> 这个表放在**右侧边栏的「交互」下**，那下面空出来很大一片地方，刚好用来放映射表。"）
>
> **关联**：落地 **ADR-0049 D6 / P4-Q4** 预留的覆盖表接口（`PacketTypePalette.SetOverride` 等）与 **§8** 的"数据包类型表"评估；
> 颜色键 = **类型身份**（ADR-0048 R2 / ADR-0051：不得用呈现文本）· 只呈现（ADR-0048 R9）。
>
> **性质**：**新增一处只读呈现 + 一个用户偏好**（不改任何判定、不进组合件）。

---

## 1. 这张表是什么（一次说清）

| 项 | 定稿 |
|---|---|
| **一行** | **一种数据类型身份**（`标识@v版本`；未声明类型的旧模块 ⇒ 结构描述）——与色板键、角色键、端口 `TypeKey` **同一个键** |
| **列** | ① **色块**（可点开取色）② **类型身份**（等宽字体，超长省略，悬停给全文）③ **形状文本**（`{seq:u64, value:f32}` 之类，次要色）④ **用在**（`N 个口 · M 个角色`） |
| **颜色从哪来** | ① 用户在表里指定的**覆盖色**；② 否则 **稳定哈希自动色**（FNV-1a → HSL，饱和度/亮度固定）⇒ **不配置也能分辨类型**，且**跨模块、跨进程、跨重启同色** |
| **改色的影响面** | **只影响呈现**：端口标记的窄色条与叠加层角色方块的填充**共用同一个色板** ⇒ 改一处，两处同步；**不参与**建网/兼容/停流/投递/计量，**不进组合件** |
| **表里列哪些类型** | **当前现场真出现过的**（来自各实例的**端口类型身份** + 角色类型身份）——与用户看到的东西对得上；"声明了但没用上"的类型不列 |
| **空态** | 一句事实：`现场还没有数据类型` |

## 2. 交互与持久化

| 项 | 定稿 |
|---|---|
| **改色** | 点色块 ⇒ 打开**调色板窗口**（见 §2.1）：**任选颜色**（色板 / 色相条 / 十六进制 / 分量滑块）+ 一排推荐色 + 「恢复自动色」 |
| **恢复自动** | 移除该类型的覆盖 ⇒ 回落稳定哈希色（"恢复自动色"由调色板窗口的"恢复"按钮承担；无覆盖时点了也只是保持自动，结果等价） |
| **持久化** | 写进**应用设置**新增的 `typeColors`（键 = 类型身份，值 = `#RRGGBB`）；启动时灌入色板 ⇒ 重启仍生效。**缺省不写任何条目**（不配置 = 自动配色，不产生死数据） |
| **落盘入口唯一** | 表 → `ShellViewModel.ApplyDataTypeColor(typeKey, hex)` ⇒ ① `PacketTypePalette.SetOverride/RemoveOverride`（色板）② 设置落盘 ③ 让界面重画（标记重读类型画刷；叠加层在 `Render` 里当场取色，可见时由共享时钟持续重绘） |
| **重画范围** | 端口标记的窄色条走**绑定** ⇒ 显式通知（`PortMarkerViewModel.RefreshTypeBrush`）；角色方块在绘制期取色 ⇒ 下一次重绘即生效 |
| **刷新不重建集合** | 表按刷新节奏（0.5 s）**就地改值**（`DataTypeColorRowViewModel.Update`），只有类型集合增删才动 `Rows`。**根因记录**：早期实现每次刷新重建整张表 ⇒ 正在打开的弹窗/悬停目标被销毁 ⇒ 用户实测"鼠标指到色块上时**不停闪烁**" |

### 2.1 调色板窗口（所有取色位置复用）

用户原话："我希望内置一个**调色板窗口**，可以从中选择**任意颜色**，而不是像现在这样只能输 RGB 值或是使用内置颜色，调色板窗口将可以**被所有颜色选择相关位置复用**……建议做精简。"

| 项 | 定稿 |
|---|---|
| **实现** | `ColorPickerDialog`（`FrameworkUi/Views`）—— Avalonia 官方 `Avalonia.Controls.ColorPicker`（**MIT**，12.1.2）的 `ColorView`：**色板方块 + 色相条 + 十六进制 + 分量滑块 + 分量输入** |
| **精简** | 只留**右侧常驻的 8 个推荐色**；**不做**"自定义颜色"格；**关掉**控件自带的"色板"页签与强调色增减块；**不带透明度**（本工程取色均为不透明色） |
| **推荐色与主题同一套** | 色板 = `ThemeApplier.Presets`（与设置页"主题色"同源 8 档）——用户裁定："**一套颜色，由用户自己改，不与主题一套色，不过调色板中的推荐颜色与主题一套色**" |
| **统一入口** | `ColorPickerDialog.ShowAsync(owner, initial, title, resetText, hint)` ⇒ `ColorPickerResult(Confirmed, Color, Reset)`；**调用方自己解释 Reset**（类型色 = 移除覆盖；方向色 = 置空跟随主题） |
| **已接入点（5/5）** | ① 交互页「数据结构 · 颜色」每行色块 ② 设置页**主题色** ③ 设置页**自定义背景色** ④ 设置页**发送色** ⑤ 设置页**接收色**。原先这 4 处各自内联"预设色片 + 十六进制输入框"的 `Flyout` **全部删除**（连同只服务它们的 `AccentPresetList` / `SelectAccent` / `SelectDirectionSend` / `SelectDirectionReceive` 命令），全应用只剩**一种选色交互** |
| **不做的事** | 不做**指标面板**（用户裁定："现在的叠加层已经非常清晰了"）；不做主题联动校验（用户第十四轮 D6：完全尊重用户选择，不做合法性/对比度提示） |
| **模板必须显式挂载** | `ColorView` **自带模板但不会自动生效** —— `FluentTheme` **不含**它的样式，必须在 `App.axaml`（以及快照项目的 `SnapshotApp`）里加一行 `<StyleInclude Source="avares://Avalonia.Controls.ColorPicker/Themes/Fluent/Fluent.xaml" />`。**不挂的后果不是报错，而是"什么都不画"**（第三十四轮实测：窗口只剩标题 + 提示 + 按钮，用户看到的是"一个**复位提示**，不仅没法选，字还是错位的"） |
| **布局（一屏全见）** | 用户裁定："改成一屏全见：**左取色器 + 右侧常驻推荐色**" ⇒ 左 = `ColorView`（两页签：**光谱** / **分量**＝RGB·HSV 滑块 + **十六进制输入**，另有当前色预览条）；右 = **常驻 8 个推荐色**（不必切页签就能点）。**关掉控件自带的"色板"页签**（`IsColorPaletteVisible=False`）与**强调色增减压块**（`IsAccentColorsVisible=False`）⇒ 推荐色**只有一个来源**、界面**只留我们确实要的东西**（"精简"的落地） |
| **布局纪律** | 标题**只由窗口标题栏给**（窗口内不再重复写一遍，否则看着像提示框）；**提示文字整行独占 + 自动换行**、**按钮单独一行右对齐**（挤在一行会被窗宽裁掉）；窗口 `SizeToContent="WidthAndHeight"`（不留死白） |

**颜色体系口径（本轮明确）**：类型颜色 = **一套全局颜色**（跨窗口、跨模块同一身份同色），**由用户自己改**、**与主题色解耦**（换主题不改用户已选的类型颜色）；只有**调色板里的推荐色**才与主题同一套。

**渲染冒烟（新增，`implementation/02` P65）**：`ColorPickerDialogSnapshotTests` 在**真实 Skia 渲染栈**下把窗口画成 PNG（`%TEMP%\hyw-overlay-snapshot\color-picker.png`），判据 = ① 窗口高度 > 240 DIP（只有文字/按钮时矮得多）② 渲染结果**不同颜色数 > 64**（色相条一个人就给出上百种色；空白窗口只有个位数）③ 留下 PNG 供眼睛复核。**这类缺陷只有"真的出像素"才看得见**（同 P39）。


## 3. 为什么放在「交互」页（用户指定）

- 用户："那下面空出来**很大一片地方**，刚好用来放映射表" ⇒ 交互页底部新增**「数据结构 · 颜色」**分区（带帮助问号 + 空态 + 列表）；
- 该页其余分区（显示 / 交互 / 窗口 / 快捷键）都是**会话内的视图与操作偏好**，本表也是"看与调"的东西 ⇒ 归在同类，不挤设置弹窗。

## 4. 与既有纪律的一致性

| 纪律 | 本表的遵守方式 |
|---|---|
| **颜色来源唯一** | 色板 `PacketTypePalette` 是**唯一**色彩来源；表只**改它**、不自己存颜色。端口标记与角色方块因此永不漂移 |
| **键 = 类型身份** | 表里的键与 `PortView.TypeKey`/`RoleView.TypeKey` 同源（`标识@v`）；**不用呈现文本**（ADR-0051：不同标识即使形状相同也是不同的量） |
| **只呈现 / 不进组合件** | 颜色是**应用级显示偏好**，写在应用设置里，**不写进组合件**；改色不影响任何判定 |
| **不发明类型** | 表里的行来自**现场实际用到的类型身份**，不凭空造条目；解析不出身份的旧模块按结构描述成行（与标记/方块同处理） |
| **不静默** | 十六进制非法 ⇒ 输入框不生效（保持原样）；未配置 ⇒ 明示"自动"（而不是假装用户配过） |
