# ADR-0000 模板与编号规则

> 状态：Accepted（本文件为 ADR 库自身的使用规则，随批次 0 审核）
>
> 说明：本文件定义 ADR 库的组织规则。**ADR-0001 起**用于记录架构决策；每条 ADR 一个文件，命名 `ADR-XXXX-<短横线英文短名>.md`。

---

## 1. 为什么需要 ADR

- 顶层与后续每个架构决策都需要可追溯（谁、何时、基于什么理由、放弃了什么）。
- 主文档《上位机架构设计.md》**只存放冻结结论**；结论背后的论证存放在 ADR，主文档冻结项以 `ADR-XXXX` 编号链接。
- 未来若推翻已冻结决策，不得静默修改主文档，必须新开一条 Superseded/Deprecated 记录。

## 2. 编号与文件规则

- 编号连续递增：`ADR-0001`、`ADR-0002`…
- 文件名：`ADR-0001-<短名>.md`，短名用英文 kebab-case，如 `ADR-0001-core-shell-assembly.md`。
- `ADR-0000` 保留给本规则文件。
- 主文档引用格式：`见 ADR-0001` 或 `（ADR-0001）`。

## 3. ADR 状态机

```text
Proposed ──→ Accepted ──→ Deprecated
    │            │              
    └──→ Rejected         (或被) Superseded（由新 ADR 取代）
```

| 状态 | 含义 |
|---|---|
| Proposed | 已提出，等待人工评审 |
| Accepted | 评审通过，成为冻结决策（须同步回写主文档） |
| Rejected | 被否决（保留记录，说明否决理由） |
| Deprecated | 曾接受，现已弃用（说明替代） |
| Superseded | 被后续 ADR 取代（注明取代者编号） |

## 4. 模板

```markdown
# ADR-XXXX <标题>

> 状态：Proposed / Accepted / Rejected / Deprecated / Superseded
> 关联批次：批次 N
> 关联主文档章节：§ x.y
> 取代：无 / ADR-XXXX
> 被取代：无 / ADR-XXXX

## 问题
（本决策要解决什么问题？引用相关 PQ 编号：PQ-<域>-<nn>）

## 背景
（为什么现在必须决策？上层约束、冲突点、场景依据）

## 候选方案
### 方案 A：<名称>
（描述 + 优点 + 缺点）
### 方案 B：<名称>
（描述 + 优点 + 缺点）
### 方案 C：<名称>
（…）

## 最终选择
（方案 X）

## 选择理由
（为什么选它；逐条对应约束/判据）

## 放弃方案
（各放弃方案的否决理由）

## 影响
（对主文档哪些章节的修订；对后续批次的约束；对判据的影响）

## 修订记录
（状态变化时间线）
```

## 5. 纪律

1. 只有 **人工（用户）评审通过** 的决策才可标 Accepted 并回写主文档。
2. 实现 Agent / 设计 Agent 不得自行将 Proposed 提升为 Accepted。
3. 主文档中每个"已冻结"表述必须可追溯到：原顶层基线（批次 0 前内容，原样保留即视为基线冻结）或一条 Accepted ADR 或一次批次评审记录。
4. 若某决策仅涉及措辞/排版（非语义），无需 ADR，直接走主文档修订记录。
