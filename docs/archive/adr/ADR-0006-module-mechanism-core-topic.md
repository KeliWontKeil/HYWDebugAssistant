# ADR-0006 模块机制核心专题（三分模型 / 成员统一路径 / 专题定位）

> 状态：Accepted（用户裁决，批次 2 前导）
> 关联批次：批次 2（核心专题，横跨领域模型/生命周期/通信）
> 关联主文档章节：§4.10（新增）、§4.8
> 取代：无（为后续 Interface/生命周期/运行时裁决提供支点） · 被取代：第 4 条"口方向三态（发送/接收/双向）"由 **ADR-0022** 修订为"两态：发送 / 接收（双向 = 两个口）"
> **收窄/修订说明**：仅第 4 条（口 = 成员机制首个实例，口方向三态）被 **ADR-0022** 修订；第 1–3 条（运行时三分模型 / 成员统一路径 / 核心专题定位）结论不变。

## 问题

为"口"设计三层模型时触发"底层决定顶层"越层信号：口是模块的子对象，其机制设计依赖更高的"模块对象结构"支点。用户进一步指出：模块对象结构、生命周期、通信机制是本项目**最重要的顶层设计**，并决定技术栈；成员机制应是"应用层近似统一"（参考 WinForms Window/Control 关系：机制同路径、实现各异），而非重量级框架对象系统。不可拘泥于既有文档章节/路线图切分。

## 决策

1. **模块运行时三分模型（骨架）**：
   - **声明世界（作者）**：模块模型 = 身份/元数据 + **成员声明集**（口/配置项/视图…）+ 行为绑定（脚本/原语，实现域）；
   - **实例世界（框架运行）**：Instance = 声明实例化 + 运行上下文（生命周期状态机[批次5]、成员实例表、通信端点、配置存储、上报通道、可选视图）；
   - **用户世界（表现）**：配置输入/视图开关/拼接口/看状态。
2. **成员统一路径（应用层近似）**：所有成员走同一"声明→实例化→存取/连接→表现"四入口；实现各异（口=通信端点、配置项=值槽、视图=渲染宿主）。不建成员基类/属性系统级重框架。
3. **专题定位**："模块机制（模块结构/生命周期/通信）"立为**横切核心专题**；口（Interface）设计、生命周期、通信机制均视为其子问题。
4. **口 = 成员机制的首个实例**：口是带方向类型（发送/接收/双向）与契约形状的通信成员；其类型目录由平台提供（受控）。

## 影响

- 主文档新增 §4.10；批次 2 范围以本专题为轴（数据语义/口成员类型/契约语言/兼容/分发归属皆为其子问题）。
- Definition"6 项声明"中 口/配置/视图 声明可理解为**成员声明集**的特例（后续批次可收敛表述，不推翻 ADR-0005）。
- 行为载体（脚本/原语）决定技术栈 → 仍属实现域（Gate 技术选型），顶层只冻结"模块=可加载的数据化声明+行为"边界。
