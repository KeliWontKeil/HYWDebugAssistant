# ADR-0038：外壳形态修订（工具条 → 侧边栏 + 侧边界面）

> **状态**：**Accepted（2026-09 · 依据用户第六轮反馈的逐项裁决 D-1/D-2/D-6/D-7）· 待实现（`08` M1-16 批次 B4/B5）**
> **关联**：ADR-0034（拼图式多窗口 · 外壳归属）· ADR-0036（窗口层级统一 · 设置分类）· `architecture/14-ui-rework-m1-16.md`（设计全文与裁决记录）
> **修订对象**：主文档 §10.1-3（外壳形态）· §9.5（应用级设置清单）· `05` §5.7/§5.14 · `09` 视觉基线 · `08` M1-16

---

## 1. 背景：ADR-0034 的"工具条外壳"被用户否决

ADR-0034 R-1/R-2 把外壳定型为 **"一条工具条"**（`SizeToContent=Height`、`CanResize=false`、**没有主体区域**、四个功能一律弹窗），理由是"模块即窗口、背景即桌面，外壳不得暗示存在工作区"。

用户第六轮反馈给出**相反的目标形态**：**VSCode 式侧边栏**——左侧活动栏（竖向图标入口）+ 右侧侧边界面（竖向内容区），**模块清单与交互常驻侧边界面**，设置/诊断/帮助仍为弹窗，**顶部菜单删除**。并指出当前观感"简陋、不够现代"，且设置弹窗尺寸与内容不匹配、左分类字号偏大。

**判定**：这不是"再调样式"，而是**外壳形态的基线变更** → 必须修订 ADR-0034 的结论。

## 2. 决策

### D1. 外壳 = **主窗口（侧边栏 + 侧边界面）**
- 结构：**A 区活动栏**（竖向图标按钮，约 44 px，按钮**图标化**、选中态用**可变色滑块**）· **B 区侧边界面**（竖向排列的常驻页面）· **底部状态栏**（保留 Issue 计数可点）。
- **顶部菜单撤销**：文件/视图/窗口/帮助 的全部动作改由 A 区入口 + B 区页面 + 弹窗承担。
- **模块清单 / 交互 = B 区常驻页面**（不再是弹窗）；**设置 / 拓扑诊断 / Issue / 帮助与关于 = 弹窗**（`DialogWindow`）。
- 外壳**仍是"拼图起始点"**（ADR-0034 的定位不变）：模块窗口 `Owner=外壳`、层级规则与"全体置顶"照旧（ADR-0036 D5）。

### D2. 屏幕尺寸与比例（设置驱动）
- 新增应用级设置 **`shellAspect`**（默认 `9:19.5`；档位 `9:19.5 / 9:16 / 16:9 / 自定义宽高`）与 **`shellFixedSize`**（默认 **true**）。
- `shellFixedSize=true` → 窗口**不可缩放**、尺寸由比例与档位推导（默认 **396×858**，最小 360×640）；`false` → 可自由缩放，比例仅作初值。
- 常量集中在 `Ui/Geometry/ShellLayout.cs`（等价物），**换比例只改一处**。

### D3. 设置弹窗按内容自适应
- `DialogWindow` 不再固定 `460×420`：改为 `SizeToContent` + `MaxWidth/MaxHeight` 上限 + 内容区 `ScrollViewer`；四个弹窗统一。
- 设置页改 **VSCode 风**：左分类固定宽 132 px、条目高 28、字号 12；右页面留白 12、分组标题 11 半粗、**字段行高 27**。

### D4. 主题色与背景（新设置）
- 应用级设置新增 **`theme`**（`Light` / `Dark` / `System`）· **`accentColor`**（8 预设 + 自定义取色）· **`backgroundColor`**（纯色 4 档：跟随主题 / 浅灰 / 深灰 / 自定义）。
- 机制：仍走既有 **角色 token**（`Ui/Styles/Tokens.axaml` 的 Light/Dark 主题字典）——**只替换 token 值**，不改任何视图的取色方式；模块窗口、弹窗、叠加层**一并跟随**（`DynamicResource` 自动刷新）。
- **v1 不做图片背景**。

### D5. 吸附参照收敛（D-2 裁决）
- **删除屏幕工作区**作为吸附候选（`WorkArea` 仍用于默认摆放与"不出屏"钳制）。
- **外壳只提供一条吸附参照 = 其右边缘**（模块左边贴合外壳右边缘，拼图向右展开）；外壳的上/下/左边缘**不作为**吸附参照。
- **模块↔模块吸附不变**（左右/上下贴合均保留，现状正确）。
- **缺陷单**：用户实测"模块无法吸附到外壳"——引擎侧候选已含 `ShellRect`，须在 B4 批定位唯一原因（候选：外壳太薄无参照感 / 拖动只能靠 6 px 带故未真正拖动 / `ShellRect` 在 `Show()` 前发布为 0 且此后未刷新）并加**可断言的无头测试**（见 `14` §9.1）。

### D6. 模块清单的**缩略图预览**（模块呈现信息的一部分）
- 每行 = 缩略图占位（约 96×54，先占位、后由用户截图替换）+ 名称 + 版本 + 来源 + 「加入现场」。
- 模块包清单 `module.json` 增加**可选**字段（预览图相对路径）+ `Core.Api` 目录视图增加对应字段（**兼容扩展**：缺字段即无图，不影响既有模块）。

## 3. 理由

1. **用户明确否决**"工具条外壳"的观感与信息密度：常驻侧边界面让"模块清单/交互"始终可见，符合"工程调试助手"的使用方式（反复加入/停止/交互），而弹窗式入口需要反复开关。
2. **形态修订不动机制**：外壳归属、窗口层级、置顶语义、模块窗口形态均沿用 ADR-0034/0036，只改外壳自身的布局与入口 → 风险可控。
3. **比例/固定/主题都做成设置项**：用户明示"可能改比例"，故以设置而非硬编码承载。
4. **缩略图先行占位**：数据结构先落地，图片后补，避免二次改结构。

## 4. 影响面

| 层/项目 | 影响 |
|---|---|
| `FrameworkUi` | `MainWindow.axaml(.cs)` 重写为侧边栏 + 侧边界面 + 状态栏；`ShellViewModel` 增加"当前页面/活动栏选中"状态；`ModuleCatalogView` 改为页面形态（含缩略图列）；`SettingsView` 重排 + 新增外观与显示项；`DialogWindow` 改为内容自适应 |
| `Core.Api` | `ApplicationSettings` 新增 `shellAspect`/`shellFixedSize`/`theme`/`accentColor`/`backgroundColor`（**已知字段增加 = 兼容扩展**，旧文件缺项即用默认）；模块目录视图新增缩略图字段 |
| `Core` | `SettingsService` 读写上述字段；`module.json` 清单解析增加可选预览图字段 |
| `Ui` | `SnapEngine`/`ModuleWindowsViewModel` 吸附候选收敛（D5）；`Tokens.axaml` 增加主题色/背景覆盖入口与 `ControlHeight=27` 等尺寸 token |
| 文档 | 主文档 §10.1-3（**作废**"外壳是一条工具条、不存在主体区域"）· §9.5（新增设置项）· `05` §5.7/§5.14 · `09` 视觉基线 · `08` M1-16 |

## 5. 不做（本 ADR 范围外）

- 跨窗口覆盖窗/长连线（ADR-0034 结论不变）；
- 图片背景、皮肤包、插件化主题；
- 外壳自身的多标签/可拖动布局（B 区页面固定纵向排列）。
