# ADR-0014 生命周期模型（批次 5 首批：LC-01~04）

> 状态：Accepted（用户裁决，批次 5）
> 关联批次：批次 5

> 取代：无 · 被取代：无
> **例外登记（技术架构层）**：ADR-0029 §4.1 为「移除」引入一处例外——**停止超时后可能残留孤儿线程**（框架放弃等待并记 Issue，不再管理该线程）；此时"`Removed` = 资源已释放"对此线程不成立。属有意接受的边界（.NET 无安全线程中止）；资源处置规则见 `docs/architecture/04` §4.1。

## 问题

PQ-LC-01~04：框架层状态机与状态归属、Enable/Disable 语义、移除语义、Binding 与生命周期关系。

## 决策

1. **图景：四个正交面**——存在性（框架权威）、活动面（框架权威）、业务状态（模块自报，框架只登记/呈现、不解释，延续 §8.3）、异常报告（模块产生、框架受控收集）。
2. **LC-01 框架层状态机**：**Registered → Active ⇄ Disabled → Removed**（框架权威判定）；`Registered`=已加入（基线 Created/Initialized 为转换过程）、`Active`=参与数据流（加入即运行）、`Disabled`=保留实例/拓扑/配置并暂停数据流、`Removed`=已移除（Stopped/Disposed 为过程）。**基线 Faulted/Recovering 不设为框架状态**（软件异常走"异常报告"，见 ER 批）。
3. **LC-02 Enable/Disable**：Disable = 保留实例与全部拓扑/配置、暂停数据流（绑定保留停流）、**通知模块**（内部处置自决：停采样/断连/保持）；Enable = 反向恢复。框架不替模块决定"禁用时是否断硬件"。
4. **LC-03 移除**：ChangeSet 原子操作（ADR-0011）→ 级联清连接/绑定 → 框架释放成员实例资源 → 模块钩子释放内部资源（ADR-0013）；移除**不可逆**（重新加入=新实例；配置复制属 UI 便利；撤销由 UI 撤销栈承担）。
5. **LC-04 Binding 关系**：绑定**独立于模块状态**、随连接存在——`Disabled`→绑定保留停流（UI 标注）；`Removed`→级联销毁；业务状态变化（离线等）不触碰绑定（表现为无数据，§8.2 类 a）；绑定建立不要求特定业务状态。

## 影响

- §8 新增冻结节；PQ-LC-01~04 关闭；批次 5 后半处理 PQ-ER-01~03（错误模型定稿）。
