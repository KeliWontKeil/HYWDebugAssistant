# ADR-0037：建网重写（标签命名网络 + "接触且对齐"对齐建网）

> **状态**：**Accepted（用户第五轮反馈与裁决）· 已实现（门禁全绿）**
> **修订对象**：主文档 §6.2/§6.3（快速建网 R0–R6 → 建网两条机制）· §9.5（设置项语义变更）· `05` §5.5/§5.14（端口标记形态与信息）· `09` §5（标记尺寸基准）· `08`（本批实现落点）
> **关联**：ADR-0018（网络统一模型）· ADR-0034（拼图式多窗口）· ADR-0036（窗口层级统一）

---

## 0. 用户裁决（本 ADR 的依据）

| # | 裁决 |
|---|---|
| 1 | **移除"加入模块即连"**（原快速建网 R0 的触发时机）："过于反直觉，不利于用户学习和探索功能" |
| 2 | 建网 = **两条机制**：① **网络标签同名即连**；② **"接触且对齐"即连**（比"对齐"更严格，防误建） |
| 3 | **吸附对齐（UI 行为）与对齐建网（网络行为）必须分开**：吸附只让用户容易对上；建网只按几何事实判定，二者**共用同一条判定规则**但**触发时机不同** |
| 4 | 拖动中新增**"即将自动建网"预览高亮**（还没松手就能感受到），松手后由网络行为落地 |
| 5 | 对齐网络**拖开即自动断开**（几何派生） |
| 6 | 端口标记：**所有标记占地统一**（左右边缘 20×76 竖排、上下边缘 76×20 横排）；内容 = **网络名 + 彩色方向箭头 + 速率 + 状态指示灯** |
| 7 | 交互增强：**中心对齐**候选 · **尺寸吸附**（Visio 式）· **窗内虚线参考线**（不跨窗口）· 缩放时**边缘高亮** |

---

## 1. 决定

### D1. 删除旧的"快速建网 R0–R6"

- `AutoNetworkBuilder`、`ModuleRuntime.NamedNetworks`、`ApplyAutoNetwork`、构造参数 `autoNetwork`、类型 `AutoNetworkOptions` **全部删除**；19 处调用点同步清理。
- 主文档 §6.2/§6.3 的 **R0–R6 规则表整体作废**（其"候选选择/最近加入者/抢占"等语义只对"加入即连"有意义）。

### D2. 建网 = **单一权威推导**（`ReconcileNetworks`）

| 机制 | 规则 | 名字 |
|---|---|---|
| **命名网络** | 端口**网络标签同名即连**：唯一发送端为源、契约兼容的接收端为宿；0 发送端/多发送端/不兼容 → 提示或 Issue（不猜） | 标签本身即网络名 |
| **对齐网络** | **未打标签**的口，两模块**接触且标记对齐**时自动连上（判定见 D3） | **匿名**（直连） |

- **派生 vs 显式**：派生网络标记 `IsAutoGenerated = true`，每次重算**先全部移除再重建**；组合件加载/用户显式建立的网络**一律不动**（用户意图优先）。
- **触发时机**：每次变更提交（布局提交＝拖动/缩放结束 · 模块增删启停 · 标签变更）+ 组合件加载 + 占位解析。**不做增量**——以现场为准重算，无隐藏状态。
- **生命周期**：对齐网络由几何**派生** → 模块拖开即自动消失。
- **提示**：新建/消失的连接都生成面向用户的提示（"已连接：A.out → B.in"），经 `CommandResult.Notices` 到状态栏。

### D3. "**接触且对齐**"判定（严格以防误建）——`Core/Composition/DockRule`

| 条件 | 值 |
|---|---|
| **接触** | 相邻边间隙 ≤ **2 px**（吸附贴合后为 0，正常拖动即满足） |
| **接触面重叠** | 沿接触边的投影必须真正重叠（排除"边缘数值巧合"） |
| **标记对齐** | 两端口**标记中心**沿接触面距离 ≤ **12 px** |
| **方向** | 发送口（左/上模块的右/下面）↔ 接收口（右/下模块的左/上面） |
| **契约** | **形状完全一致**〔**ADR-0051 修订**：原「接收 ⊇ 发送」已作废〕（不兼容即忽略，不自动转换） |
| **标签** | 双方**均未打标签**（打标签的口只参与命名网络，两种机制不混用） |

**只有一份实现**：网络行为（L4 推导）与 UI 预览（拖动中高亮）**共用 `DockRule`** → 预览与结果必然一致。

### D4. 预览查询（UI 只问、不复制规则）

`Core.Api` 新增 `IRuntimeQuery.PreviewConnections(provisionalLayouts)`：
UI 在**拖动中**用临时布局问 L4"现在松手会连上什么" → 高亮相关端口标记 + 状态栏提示；
**实际建网只发生在布局提交之后**（"吸附是 UI 行为、建网是网络行为"的落地）。

### D5. 端口标记（标准件）

- **占地统一**：左右边缘 **20（宽）× 76（高）竖排**（内容旋转 90°）；上下边缘 **76×20 横排**。所有标记一致 → 便于对齐与"接口标准化"。
- **内容**：网络名（未连="无网络" · 匿名已连="（直连）"）+ **彩色方向箭头**（发送=主色 / 接收=次色）+ **速率**（两次采样增量，`xxx/s`，无流量为 `---`）+ **状态指示灯**。
- **位置**：标记落在窗口边缘的**预留带**内（20 px），与内容**永不重叠**；两窗口相邻时标记视觉上正好相接 → "接触且对齐"看得出来。
- 速率/投递量为**网络粒度**（框架诊断按网络统计；字节 = 投递单元数 × 发送方契约尺寸的估算），界面以工具提示注明。

### D6. 交互增强

- **中心对齐**候选加入吸附引擎（原来只有左右/上下边对齐 + 贴合）。
- **尺寸吸附**（Visio 式）：缩放时若结果宽/高接近其他模块的宽/高（容差内）→ 吸附到该尺寸（"把几个模块调成一样大"很容易）。
- **窗内虚线参考线** + **缩放边缘高亮**：由 `GuideOverlay` 在**模块窗口内部**绘制（虚线为对齐参考线、2 px 实线标出正在缩放/被对齐的边）——**不跨窗口绘制**（跨窗口覆盖窗仍为推迟项）。

### D7. 设置项语义变更

`AutoNetworkEnabled` → **`AlignAutoNetworkEnabled`**（键 `alignAutoNetwork`，旧键 `autoNetworkEnabled` 兼容读取）：语义由"加入即连"变为"**对齐自动建网**"（开 = 接触且对齐的未打标签口自动连；关 = 只做命名网络）。

## 2. 影响面

| 层 | 变更 |
|---|---|
| `Core` | 新增 `Composition/DockRule.cs`（判定唯一实现）· `Runtime/ModuleRuntime.Networking.cs`（推导）；删除 `AutoNetworkBuilder`/`NamedNetworks`/`ApplyAutoNetwork`；`Commit` 末尾统一推导；加载/占位解析后推导 |

| `Ui` | 标记标准尺寸与内容（`PortMarkerViewModel`/`ModuleContentView`/`PortMarkerPanel`）· 拖动预览高亮 · `GuideOverlay`（窗内虚线 + 边缘高亮）· 尺寸吸附 · 中心对齐（`SnapEngine`） |
| 测试 | 删除过时的 R0–R6 与"命名口从匿名网络摘出"用例；新增对齐建网 6 项（接触且对齐才连 / 不接触·不对齐不连 / 拖开自动断开 / 打标签口不参与 / 契约不兼容不连 / 显式网络不被误删）；门禁 **221 项通过** |

## 3. 未采纳

| 方案 | 原因 |
|---|---|
| 保留"加入即连"作为可选开关 | 用户裁决移除：反直觉、不利学习与探索；两种建网机制已足够 |
| 以"对齐"（不要求接触）作为建网条件 | 用户裁决要求**接触且对齐**：严防误建（并对标记 UI 形成约束——标记紧贴边缘，相邻即相接） |
| 跨窗口虚线参考线 | 需全屏透明点击穿透覆盖窗（穿透/z-order/DPI/失活四件事）；用户裁决**窗内画线即可** |
| 预览由 UI 自行实现判定 | 会造成"预览与结果不一致"的经典缺陷；改为 UI 经 `Core.Api` 询问 L4 |
