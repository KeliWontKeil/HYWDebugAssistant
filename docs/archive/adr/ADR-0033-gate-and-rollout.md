# ADR-0033 Gate 处置与开发推进（技术架构设计 第 7 章冻结 · 收尾）

> 状态：**Accepted**（设计方推荐 + 用户审核，议程 ③ 第 7 章）
> 关联阶段：技术架构设计收尾 → 实现阶段启动
> 关联主文档章节：§18.5（Gate 清单）· §16.4（设计—实现推进阈值）· §14.3（产品验收场景）
> 关联文档：`docs/architecture/07-gate-and-rollout.md`（全文）
> 关联 ADR：ADR-0023/0024（选型 Gate 已关闭）· ADR-0026~0032（第 1–6 章）
> 取代：无 · 被取代：无
> 推荐与裁决：第 7 章 Gate B/C/D/E 处置表（含 §7.1 逐条处置）由**设计方推荐**（承第 6 章用户授权），已由用户审核追认（见 ADR 修订记录）

## 问题

Gate A 已关闭（选型完成）。剩余 Gate B（实现机制）、Gate C（UX 原型）、Gate D（后续阶段）、Gate E（顶层之后）需逐条处置，并确定进入开发的推进方式、首个里程碑与数值指标的实测时点。

## 背景

- §16.4 的推进阈值：**只有当剩余未知以 B 类（怎样实现）为主时，才应进入实际开发**。
- 第 1–6 章已冻结（ADR-0026~0032），剩余项经核对**全部为 B 类**（参数取值、视觉形态、实测数值、排期）。
- 用户在第 6 章明确授权：测试与流程类事项由设计方推荐供审核（"不要求全方位全覆盖，只希望自动化完成主要问题"）。

## 最终选择

1. **Gate B**（口径：以 `architecture/07` §7.1 处置表逐行统计，共 **18 项**）：**11 项关闭**（含 1 项**部分关闭**——「View/ViewModel 模式」：模块侧无 View 已关闭，`Ui`/`FrameworkUi` 内部 MVVM 用法转 R 项；其余 10 项为线程/调度/队列、零拷贝、ID 格式、契约语言、配置 Schema、组合件格式、脚本、UI 自动化、表现层解耦、风暴护栏）；**4 项转 R 项**（批量优化、契约提示性标注、模块包物理形式、`Ui` 内部 MVVM 约定）；**2 项实测回写**（数值指标；停止超时 / 队列容量默认值）；**2 项留 Gate D**（进程/隔离模型与 IPC、L5 性能监视）。（逐行合计 18 项；「View/ViewModel 模式」一行同时计入"关闭（部分）"与"转 R"，故各口径项数之和为 19。）
2. **Gate C 时点**：**M1（框架最小闭环）之后、M2（UI 完整化）之前**做一次 UX 原型——数据面风险先闭环，原型站在真实数据上做。
3. **Gate D**：**预留**会话快照与模块版本迁移（低成本、影响接口形态）；**明确不预留**组合件递归嵌套、录波回放、进程沙箱、跨平台硬性要求、L5 性能监视。预留原则：只预留成本极低且改变接口形态的项。
4. **Gate E**：具体模块清单与 v1 产品验收场景由用户在产品阶段定义（只做业务正确性验收，不做架构验收）；建议方向供参考。
5. **推进方式**：**垂直切片**——先打通"模块包 → 实例 → 网络 → 投递 → 显示"一条最小完整链路，而非按层横向做完。
6. **M1 里程碑**（9 步）：项目骨架 → `Sdk` 最小面 → `Hosting` → `DataPlane` → `Core`/`Core.Api` → `Ui` 最小 → `FrameworkUi` 最小 → 参考桩模块 + T1 判据测试 → `Benchmarks` 首轮实测。
7. **M1 验收**：门禁全绿 + AC-1~6 自动化通过 + **用户手工验证**（加载/拼接/建网/看到数据与曲线/保存重载）+ 性能数值回写。
8. **冻结声明**：本章冻结后**技术架构设计整体冻结**，进入实际开发；实现中暴露的残余 A 类问题必须回写主文档（§16.4）。

## 选择理由

1. **垂直切片**：最早暴露端到端风险（装配链/加载/建网/投递/显示），符合纪律 C2「只有最小可验证形态才算可验证」；每完成一片都有可运行系统，便于用户持续手工验证。
2. **Gate C 后置到 M1 之后**：视觉细节不改变数据面设计，且 M1 后原型可基于真实数据，避免原型与实现脱节。
3. **预留只给"便宜且影响接口"的项**：避免为想象的未来付费；会话快照与版本迁移成本极低而用户价值明确，故预留。
4. **M1 覆盖 AC 实证**：AC-1~6 的纸面路径在第 1–6 章已给出，M1 用参考组合完成实证，使"架构验收"闭环。

## 放弃方案

- **按层横向开发**（先做全 Registry/生命周期再连数据）：端到端风险暴露晚，早期无可运行系统。
- **Gate C 前置到开发前**：原型缺乏真实数据与真实机制支撑，易与实现脱节；且推迟了最大风险（数据面）的验证。
- **全面预留 Gate D**：为不确定的未来增加当前复杂度。
- **v1 即做进程隔离/沙箱**：与 §12 轻量透明模型冲突，且非 v1 需求。
- **架构验收覆盖业务场景**：违反 §14.3（业务只做正确性验收，防架构对具体业务过拟合）。

## 影响

- **进入实现阶段**：M1 按 §7.5 九步推进；工程落地（第 2 章项目骨架、第 6 章规则集重构）自此开始执行。
- **数值指标**：M1-9 首轮实测 → 回写主文档 §13.2 与 `04a` §5；M2 后第二轮。
- **交付物**：实现期须产出**用户手工验收清单**（ADR-0032）。
- **议程 ③ 完成**：技术架构设计整体冻结，`docs/roadmap.md` 记录为 v1.11。
