## 1. 决定

### D1. 模块发现 = **声明根列表**（有序、显式、可诊断、可重扫）

| 项 | 决定 |
|---|---|
| 设置项 | `moduleSourceDirectories: string[]`（**有序**）；替代原单值 `moduleSourceDirectory`（旧键**兼容读取**：存在则作为列表首项） |
| 默认值 | `[<应用目录>\modules]`（内置包目录；随构建产出） |
| 扫描规则 | 按顺序逐根扫描；每根只扫**直接子目录**中含 `module.json` 者；**不递归、不猜、不扫任意位置**（守 §11.2 原意："用户可见的声明根"取代"任意位置"） |
| 重复 | 同 ID 同版本：**先到者胜**，后者记 **Info**（"已由更早的来源装入"）；同 ID 不同版本：**都注册**，目录按模块名聚合、默认取**最新版本** |
| 重扫 | 新增 `Core.Api` 命令 `RescanModuleSources()`：作用域 = 声明根；**只发现新增包**；已载入程序集不可替换（见 D4） |
| 诊断 | 新增查询 `GetModuleSources()`：每根的路径 · 扫到/跳过/失败计数 · 逐包结果（成功/失败原因）· 以及"该包在本次启动后被重新构建"的提示 |
| 界面 | 「模块清单」弹窗展示上述诊断，并提供「立即重扫」「打开目录」；设置页提供根的增删排序与「填入工程默认值」 |

### D2. 包产出 = **构建即归拢**（消除"脚本里的硬编码模块清单"）

| 项 | 决定 |
|---|---|
| 模块侧 | 新增 `src/Modules/Directory.Build.targets`：项目构建后把 `module.json` + 输出程序集 + 依赖复制到 `artifacts\modules\<包名>\`（**先清空该包目录**再复制，避免新旧 DLL 混放）；包名由项目属性推导（默认取项目名后缀），**新增模块项目零改动** |
| 应用侧 | `App` 项目构建后把 `artifacts\modules\*` 镜像到 `$(OutDir)modules\` → **内置包目录始终与构建一致** |
| 脚本 | `tools/stage-reference-modules.ps1` 改为**发布打包用**（不再硬编码模块清单，改为遍历 `artifacts\modules`）；`build.ps1` 的"归拢"步骤降级为**校验**（检查每个包目录是否齐全） |
| 仓库卫生 | `artifacts/` 已在 `.gitignore`（构建产物不入库）；包物理形式**不变**（1 包 = 1 目录，ADR-0020） |

### D3. 发现的边界（**明确不做**）

- 不做磁盘递归/全盘搜索；不做"扫描 `obj/` 或 `bin/` 任意深度"；不做隐式仓库探测（用户裁决 O-1）。
- 不引入第二套包形式（zip/单文件）。

### D4. 热重载：**不做**（固定语义 = 重启），仅保留一条提示

- **决定（用户二次裁决）**：**不实现热重载**——不做可卸载 `AssemblyLoadContext`，**不列入 M2，也不留待办**（理由：通常没有这样的需求，且会引入高复杂度）。语义固定为：**改模块代码 → 重新构建 → 重启应用**。
- **唯一保留的便利**：重扫时若包目录/文件的写入时间**晚于本进程启动时间** → 记一条 Info 并在模块清单中标出"该包在本次启动后重新构建，**重启应用才生效**"（成本 = 一次时间比较，不引入任何重载机制）。

### D5. 窗口层级 = **应用内从属 + 应用整体统一**（用户 O-5 的核心要求）

**D5-1 应用内（自上而下）**：**弹窗 > 模块窗口 > 外壳**
- 模块窗口 `Owner = 外壳窗口`：外壳永远在模块窗口**之下**，点外壳不再把模块"压下去"；最小化外壳时模块窗口随之最小化，恢复时一并恢复；
- 弹窗 `Owner = 外壳窗口`（现状保持），打开即激活（位于最前）。

**D5-2 应用整体（相对其他应用）——只有两种**统一**状态，由**应用级开关**切换**：

| 状态 | 语义 | 实现 |
|---|---|---|
| **普通（默认）** | 本应用整体"一起进出"：任一本应用窗口被激活 → **把本应用其余窗口一并抬到最前**（不抢焦点、保持内部次序）；其他应用被激活 → 本应用整体下沉 | 监听任一本应用窗口的激活事件 → 对同应用的其余顶层窗口调用 Win32 `SetWindowPos(HWND_TOP, SWP_NOACTIVATE|SWP_NOMOVE|SWP_NOSIZE)` |
| **应用置顶** | 本应用**全部**窗口一起置顶（含外壳、模块窗口、**以及之后新开的窗口与弹窗**） | 统一设置 `Topmost=true`；新窗口创建时按当前应用状态套用 |

- **撤销**：原方案稿的"每个窗口各自置顶（per-window Topmost）"——它正是"一部分置顶、一部分被覆盖"的来源；
- **最小化/任务栏**：任务栏与 Alt+Tab **只出现外壳一项**（模块窗口 `ShowInTaskbar=false`，**写死、不设开关** —— 用户二次裁决：不加设置项，避免提高复杂度）；
- **平台代价（如实登记）**：D5-2 的"组抬升"需要**少量 Win32 互操作**（`user32.dll`：`SetWindowPos`；通过 Avalonia `TryGetPlatformHandle()` 取 HWND）。属**表现层平台适配**，只落在 `Ui`/`FrameworkUi`，不进入 L1–L4；非 Windows 平台降级为"不做组抬升"（其余行为不受影响）。

### D6. 设置 = **分类化**（七类，仿成熟软件）

```text
设置（左分类 · 右页面，即时生效）
├─ 常规            启动行为（会话恢复 = 后续）· 便携目录说明
├─ 模块与来源  ★   根列表（增/删/排序/「填入工程默认值」/「立即重扫」）+ 每根诊断 + 包清单（内置/第三方）
├─ 窗口与交互  ★   吸附开关与容差 · 整组拖动修饰键 · 临时停用吸附修饰键 · 锁定语义说明 · **应用整体置顶开关**
├─ 外观与显示      刷新率 · 口上标记 ·（主题 = 后续）
├─ 快捷键     ★   动作清单 + 当前绑定 + 修改/重置/冲突检测
├─ 日志与诊断      日志级别 · 诊断提示阈值 · Issue 上限与保留
└─ 关于            版本 · 构建配置 · 依赖许可摘要 · 用法/快捷键速查
```

### D7. 快捷键 = **应用内、可见、可改、可重置**

| 项 | 决定 |
|---|---|
| 作用域 | **应用内**：本应用**任一窗口**（外壳或任一模块窗口）聚焦时生效（现在只有外壳聚焦才生效 → 修正） |
| 模型 | `hotkeys: { "<动作>": "<键+修饰键>" }`；动作 = 固定枚举：打开模块清单/Issue/设置/拓扑诊断 · 切换口上标记 · 切换吸附 · 全部锁定 · **应用整体置顶** · 全部置前 · 显示全部窗口 · 取消拖动 |
| 编辑 | 设置页「快捷键」类：逐行动作 + 当前绑定 + 捕获新键（含修饰键）+ **冲突即时提示** + 单项/全部重置；空 = 不绑定 |
| 持久化 | 进 `settings.json`；**已知字段增加属兼容扩展**（旧文件缺该项即用默认），无需版本迁移 |
| 不做（v1） | 系统级全局热键（未聚焦也响应）——需 Win32 `RegisterHotKey` 与全局占用语义，另立 ADR |
| 清单归属 | 快捷键清单**以设置页为准**（`10` §5 的既有规定，本次补做） |

### D8. 契约与兼容

| 项 | 影响 |
|---|---|
| `Core.Api` 新增 | `GetModuleSources()`（查询）· `RescanModuleSources()`（命令）——只增量，不破坏既有面（AR-16 保持） |
| `ApplicationSettings` 变更 | 新增 `moduleSourceDirectories`（列表）· `hotkeys`（映射）· `appTopmost`（布尔）；**旧键 `moduleSourceDirectory` 兼容读取**；已知字段增加 = 兼容扩展（**不新增任务栏相关设置项** —— 模块窗口不进任务栏是固定行为） |
| 既有行为不变 | 包物理形式、注册表多版本共存、显式「选择…加载」、快速建网、"不自动扫任意位置"的**精神**（改为"只扫声明根"） |

## 2. 实施计划（**批准本 ADR 后开始编码**）

| 段 | 内容 | 交付判据 |
|---|---|---|
| **① 构建归拢（D2）** | `src/Modules/Directory.Build.targets` + `App` 镜像 target；脚本改发布用；`build.ps1` 改校验 | `dotnet build` 后 `artifacts\modules\` 与 `<应用>\modules\` 自动齐全；新增一个模块项目**无需改任何脚本/targets** |
| **② 多根发现与诊断（D1/D3/D4）** | `ApplicationSettings` 根列表 + `Core` 多根扫描（顺序/去重/结果）+ `Core.Api` 查询与重扫命令 + 模块清单弹窗诊断区 + "需重启"提示 | 新增模块项目 → 构建 → 「立即重扫」→ 出现可用模块，**无需重启**；改代码后重建 → 明确提示需重启 |
| **③ 窗口层级统一（D5）** | `Owner=外壳` · 激活组抬升（Win32 `SetWindowPos`）· 应用整体置顶开关（含新窗口/弹窗继承）| 点外壳不盖住模块；切换其他应用再切回，**整个应用一起回来**；置顶开关打开后**所有**窗口一起在最前（无混合状态） |
| **④ 设置分类 + 快捷键（D6/D7）** | 设置弹窗改左右分栏七类；`HotkeyService` 挂到所有本应用窗口；快捷键编辑器（捕获/冲突/重置） | 模块窗口聚焦时按 `I` 也能开 Issue；设置里能看/改/重置每一个快捷键 |
| **⑤ 验收与回写** | 更新验收清单（新增：自动发现、重扫、需重启提示、组抬升、置顶统一、设置分类、快捷键可改）→ 回到 **M1-14 手工验收** | 用户按清单通过 |

**预估规模**：① 小 · ② 中 · ③ 中（含平台适配）· ④ 中 · ⑤ 小。**顺序按用户裁决：三项一起做完再验收**（M1-17 作为一个整体步骤）。

## 3. 未采纳的方案（备查）

| 方案 | 未采纳原因 |
|---|---|
| 递归/全盘搜索模块包 | 与 §11.2 冲突；会扫到 `obj/`、旧版本、他人构建产物；用户无法回答"包从哪来"（用户裁决 O-1 排除） |
| 隐式探测仓库根并自动加根 | 同一 exe 在不同目录启动行为不同（隐式）；改为设置里一键「填入工程默认值」（显式） |
| 包改成单文件（zip） | 破坏 ADR-0020 的物理形式与既有加载路径，且与"自动发现"无因果关系 |
| **每个窗口各自置顶** | **会被坏应用整体层级的一致性**（用户 O-5 明确排除）：出现"一部分置顶、一部分被覆盖" |
| 可卸载 ALC 热重载 | **用户裁决不做**：通常无此需求，且需独立设计（默认上下文类型标识、静态状态/线程/缓冲回收），复杂度与风险都高；**不列入 M2、不留待办** |
| 系统级全局热键 | 需 Win32 `RegisterHotKey`，会抢占全局按键、可能与其他软件冲突 → 另立 ADR |
