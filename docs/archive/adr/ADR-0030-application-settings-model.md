# ADR-0030 应用级设置模型（Settings）

> 状态：**Accepted**（用户逐条裁决，议程 ③ 第 4 章补遗）
> 关联阶段：技术架构设计（选型后 · 实现前）
> 关联主文档章节：**§9.5（本次回写新增）** · §9.1/§9.2（抽象工作区与组合件）· §6.2 R0（快速建网设置项）· §11.2（模块来源目录）
> 关联文档：`docs/architecture/04b-application-settings.md`（全文）、`04-key-mechanisms.md` §4.12（缺口来源）
> 关联 ADR：ADR-0029（第 4 章机制；C4-2/C4-3 的参数归属）、ADR-0016（持久化模型）、ADR-0017（持久化细节）
> 取代：无 · 被取代：无

## 问题

基线只定义了两类持久化内容：**Configuration**（实例参数、随组合件保存）与 **Layout**（布置数据、随组合件保存）。但两处独立引用指向了第三类——**"不随组合件、属于应用/用户级偏好"的设置**：

1. §6.2 R0「**设置项**开启（默认开）」（批次 3 冻结结论，已隐含其存在）；
2. 技术架构设计第 4 章新出现的"停止超时""输入队列容量默认值"（C4-2/C4-3 裁决为"可配置且带默认值"）。

这类数据**从未定义**谁拥有、存哪里、何时生效、如何呈现——属真实设计缺口，非过度设计。

## 背景

- 用户裁决：S-1 **现在补设计**；S-2 **仅应用级设置**；S-3 **回写主文档（补一节）**；S-4 **与组合件完全分离**（"设置与模块本身组合应完全分离，且设置可独立保存（可以是一个简单的 .json 文件）。他们是完全不同的两种东西，特别是不存在广义的'工作空间'时。"）
- 约束：§9.1 明确"不存在广义工作空间容器"；§9.2 的组合件随件边界已冻结；§7.1"全在线变更"要求设置在线生效；§16.2 要求任何新核心概念经人工决策 + ADR。

## 候选方案

### 归属
- **A1 Core 管理 + 独立用户级文件**；A2 UI 管理（FrameworkUi 自持）；A3 作为特殊模块（配置模块）。

### 范围
- **B1 仅应用级**；B2 应用级 + 按模块类型的默认设置；B3 仅框架内部参数（不暴露）。

### 与组合件的关系
- **C1 完全分离**；C2 组合件可携带"设置快照"；C3 随组合件保存（与 Configuration 合并）。

### 是否回写主文档
- **D1 回写（补 §9.5）**；D2 仅在架构层定义。

## 最终选择

**A1 + B1 + C1 + D1**：

1. **定位**：应用级/用户级行为偏好，独立于组合件，不属"工作现场内容"。
2. **归属**：Core（L4）管理与持久化；**单一 JSON 文件**，原子写 + `schemaVersion` + 未知字段片段保留（沿 C3-3）；缺失/损坏 → 内置默认值 + Issue，**不阻断启动**。
3. **范围**：仅应用级；**不提供按模块类型的默认设置**；模块默认值由模块实现提供。
4. **生效**：在线即时生效；变更经 **L4 变更入口**（与 ChangeSet 同一入口串行化），但不走 ChangeSet 组合语义、不触发增量重建。
5. **呈现**：`FrameworkUi` 设置界面；读取一律经 `Core.Api`。
6. **与模块**：设置**不下发**给模块（模块只接收自身 Configuration）。
7. **主文档回写**：新增 §9.5，并把持久化内容全集收敛为三类——**组合件 / 应用级设置 / 会话快照（Gate D）**；主文档修订记录登记 1.0.2（既有结论未变更）。

## 选择理由

1. **A1**：设置是框架自身行为的参数（停止超时、队列容量、R0 开关），必须由语义内核持有并作用于机制；交给 UI 会让"框架行为"依赖表现层。
2. **B1**：作用域越少越清晰；"按模块类型默认值"会引入第二层作用域与优先级规则（应用级 > 类型级 > 模块默认？），而 v1 无此需求；模块默认值留在模块实现内即可。
3. **C1**：与用户判断一致——**组合件是"内容"，设置是"应用偏好"，两者是完全不同的东西**；在"不存在广义工作空间"的前提下（§9.1），设置天然属于应用级而非现场级。也避免了"加载组合件时是否要改用户设置"这类隐式副作用。
4. **D1**：主文档是**验收唯一事实源**；持久化对象的全集属于顶层应描述的范围。缺了它，主文档对"什么东西会被持久化"的描述不完整。

## 放弃方案

- **A2（UI 管理）**：框架行为参数由表现层持有，破坏"运行不依赖 UI"（§10.1）。
- **A3（作为模块）**：内置模块无结构特权（ADR-0020），但设置作用于框架机制本身，做成模块会造成机制依赖内容模块的反向耦合。
- **B2（加模块类型默认值）**：引入第二作用域与优先级规则，v1 无需求。
- **B3（仅内部参数）**：与 §6.2 R0 已冻结的"用户可见设置项"矛盾。
- **C2（组合件携带设置快照）**：表面上提高重现性，实则制造"加载组合件是否覆盖用户设置"的歧义；与 S-4 的用户判断相悖。
- **C3（随组合件保存）**：直接违反 §9.2 已冻结的随件内容边界（Configuration/网络/Layout/活动面）。
- **D2（不回写主文档）**：会使"验收唯一事实源"缺一类持久化内容。

## 影响

- **主文档**：新增 §9.5；修订记录 1.0.2；**既有冻结结论无一变更**。
- **第 4 章**：C4-2（停止超时）、C4-3（队列容量）两参数的归属落定；参数生效语义见 `04b` §6。
- **第 5 章**：设置界面纳入 `FrameworkUi` 范围；设置读取经 `Core.Api`。
- **第 6 章**：测试需覆盖——设置缺失/损坏不阻断启动、未知字段保留、原子写、在线生效。
- **第 7 章（Gate 处置）**：设置文件的默认位置（C4b-1）与写盘时机（C4b-3）作为待细项。
