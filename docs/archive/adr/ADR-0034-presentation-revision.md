## 问题

M1 手工验收准备期，用户在界面上发现 7 个问题（工作区呈现、框架面板归属、冗余与"代码化"信息、开关混放、面板形态、建网交互、缺手动测试模块），并给出对表现形态的明确意图：**拼图式**（每模块一个无边框窗口、背景即桌面、主窗口为拼图起点）。其中若干条与既有冻结结论冲突或属基线留白，必须正式裁决后才能实现。

## 背景

- 主文档 §9.1/§10.2：工作区**无容器、无生命周期**；"画布容器"概念明确不采用。用户意图与之同向（连背景都不要），**不冲突且更彻底**。
- 主文档 §10.1-2：**"Module ≠ Window"**——与"每模块一个窗口"**直接冲突**；该条原意是防止"模块=窗口"的反模式（EC-4/E4），但未禁止"框架把模块表现成可拼接窗口"。
- 主文档 §6.3 / `05` §5.5：**连线层**（默认隐藏、热键切换、有向流动样式）——多窗口形态下"一层画布画所有线"不再成立。
- `05` §5.1：`Ui` 与 `FrameworkUi` 为并列构成，**未规定谁持有主窗口**。
- `05` §5.6/§5.7 + 主文档 §10.4（C5-4）：**配置编辑元素在模块视图内**，管理视图**仅作无 UI 模块兜底**——实现中违反了该条（给全部实例列清单、暴露 JSON 与类型名）。
- 工程纪律 C3：禁止把简易原型并入工程；确需原型须独立搭建（不参与主构建）——本 ADR 后续的"手感小样"据此执行。

## 最终选择

1. **表现形态 = 拼图式多窗口**：每个模块 = **一个无边框顶层窗口**（`SystemDecorations=None`、`ShowInTaskbar=false`）；**无任何"工作区"背景**（背景即用户桌面）；外壳主窗口为拼图"起始点"且可被贴靠。**正式修订 §10.1-2** 为："模块**不强制**等于窗口；**默认形态 = 每模块一个可拼接的无边框窗口**（框架渲染、模块不提供 View 类型不变）。"
2. **窗口交互 = Office 直觉**：完全无边框；**边框 6 px 为交互带**（边中点/角点缩放、其余拖动）；**锁定/隐藏/关闭**按钮同处（建议右下、悬停/选中出现）；**锁定后禁止拖动与选中**（仍显示数据）。`09` §5 的"模块标题栏 24 px"随之修订：模块名与状态改为**内容区顶部一行轻量文本**。
3. **主窗口归属 = `FrameworkUi`**：`FrameworkUi` 持有 `Window`（菜单/工具栏/状态栏 + 全部弹窗）；`Ui` 只提供**模块区控件**；依赖方向仍 `FrameworkUi → Ui`（AR-8 不变）。旧的 `IFrameworkPanels` 宿主契约**撤销**（方向反转）。
4. **弹窗化**：模块清单/加载、Issue、设置、**拓扑诊断** 一律按钮打开的弹窗；主窗口不再常驻 TabControl 侧栏。工具栏开关**分类**为「显示 / 交互 / 窗口」。
5. **建网交互 = 口上网络标签同名即连**：
   - **唯一建网机制**：口标记上就地填写网络名，同名即自动建立/加入同一网络；清除名字即退出；**删除"连接管理"操作界面**（一次性自创 UX，作废）；
   - 匿名直连仍由**快速建网 R0**产生（加入模块时自动匹配）；
   - **端口唯一 ID 与连接关系**作为**调试信息**保留：新增**只读拓扑诊断弹窗**（形态与 Issue 同级）——**这是"像 ISSUE 那样存在"的落地**；
   - **正式修订 §6.3 的连线呈现**：多窗口下 v1 **不做跨窗口长连线**，改以"**口上标记（网络名+方向+状态）+ 选中/悬停高亮同网络成员 + 拓扑诊断**"表达；跨窗口覆盖窗列为**后续可选增强**（需 Win32 互操作 + 全局 z-order + 跨显示器 DPI 三事同办；届时建议**全屏**覆盖而非跟随包围盒动态改大小）。
6. **配置编辑回到模块视图内**：由框架按**配置 Schema 自动生成表单**（数值/文本/布尔/枚举/文件路径）；无 UI 模块的管理视图兜底改为**同样的表单**（**不再展示 JSON、配置类型全名、`ModuleId` 字面量**）；**删除"已实例化"清单**（画布上可见即已实例化）。为此 `Core.Api` 新增"配置 Schema 只读 + 按字段写回"通道（写回仍走 L4 变更入口保全原子性）。
7. **新增两个开发/测试用参考模块**（与既有三个同构同路径、只引 `Sdk`）：**手动数据发送器**（输入值 → 发送一次/连续发送）与**信息显示模块**（最后值/计数/曲线/带时间戳的最近 N 条日志）；两者**同时并入自动化 T1/T6 覆盖**。
8. **推进**：新增实现步骤 **M1-15（界面澄清与修正）**，三段式 = 设计冻结（本 ADR + 文档回写）→ 实现（含两个测试模块 + 重写验收清单）→ 用户验收；**M1-14 手工验收顺延至该步之后**。
9. **记录一项后续专项**：M1-15 完成后需进行一次 **UI 专项开发**（目标：从"简陋"到"**简洁美观**"；范围=视觉体系/模块窗口视觉/弹窗布局/交互反馈与克制动效；**具体方案由用户提出**）。**时点由设计方定：置于 M1-15 之后、下一里程碑功能开发之前**（即把 ADR-0033 §7.2 的 Gate C"UX 原型"正式化为该专项），理由是结构（多窗口/弹窗/无边框）在 M1-15 定型后再做视觉与交互打磨可避免返工。**【已顺移 · 见修订记录第 2 行】** 实际时点 = **M1-17 之后、M1-14 验收之前**（中间插入 M1-17），推进方式 = 用户出要点 → 设计方扩散成草案 → 用户定稿 → 实现 + 回写。

## 后果

- **正面**：表现形态更贴合用户直觉（拼图、桌面即背景、Office 式边框操作）；建网机制唯一（标签）且与设计语义（网络标签依附于口）一致；界面不再向嵌入式开发者暴露代码化标识；M1 手工验收具备"可戳"的测试模块。
- **代价**：`Ui` 需从"单窗口内画布"改为**多窗口宿主**（窗口管理、屏幕坐标吸附、整组移动、锁定）；`FrameworkUi` 升级为外层主窗口；跨窗口连线在 v1 缺席（以标记/高亮/诊断替代）；`Core.Api` 增加"配置 Schema"通道。
- **风险与缓解**：多窗口拖动/吸附手感、多显示器不同 DPI 的坐标换算、口标记就地编辑与"内容区不抢事件"的边界——按 C3 允许的方式，**先独立搭建手感小样**（不参与主构建）验证后再铺开实现。
- **不动的部分**：L0–L4 机制（数据面/宿主/Core/持久化/设置）**零改动**；`Sdk` 仅**新增**（既有口/视图/配置声明与 18 元素目录不变）。
