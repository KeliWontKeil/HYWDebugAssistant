# ADR-0016 持久化模型重构：抽象工作区 + 组合件载体（Supersede ADR-0001/0003/0005 相关表述）

> 状态：Accepted（用户裁决，批次 6）
> 关联批次：批次 6
> 关联主文档章节：§9（重写）、§2.5、§3.1、§3.3、§3.4、§4.1、§4.2、§4.5、§4.9、§6.1、术语表
> 取代：ADR-0001/0003/0005 中"Workspace 作为保存单元/内容容器"的表述（部分条目）
> 被取代：无

## 问题

批次 6 首轮我提出"Workspace 定义与生命周期、多工作区并行"，被用户否决：**工作区只是抽象概念**——由模块拼接自然而然的整体，不存在"工作区空间"，因此不存在"多工作区""工作区生命周期"这类裁决点；可以并存多条互不相关的链路（如同时监控多个串口），但不是多个工作区。根源是文档长期残留"Workspace = 保存单元"的实体化表述，诱导出容器/文件/多开推理。

## 决策

1. **抽象工作区（唯一）**：由 Core 与全部已拼接模块自然形成的**运行整体（当前现场）**；无容器对象、无"新建/打开/关闭"生命周期、**无多工作区并行或切换**（撤销此类裁决点）；不存在"工作区文档/文件"；工作区内可并存任意多条互不相关链路。术语保留"Workspace/工作区"但**仅指该抽象整体**，一切实体化用法视为表述错误。
2. **组合件（Composite）= 持久化与复用的唯一载体**：**保存** = 选择"一组模块实例 + 连接（含拓扑构造）+ 配置 + 布局"物化为组合件；**1 文件 = 1 组合件**；**加载** = 实例化进当前工作区；可复用/参与拼接（递归嵌套 Gate）。**"保存全部内容" = 一个覆盖当前全部实例与连接的根组合件**（概念上仍是蓝图，不是"工程容器"）。
3. **随件保存的内容边界**（沿用批次 6 裁决）：Configuration ✅ / 组合拓扑 ✅ / Layout ✅（加载可"忽略布局"）/ 实例活动面（启用·禁用）✅；**Runtime State 与绑定 ❌**（重建）。
4. **会话快照（可选能力）**：退出/崩溃后自动恢复"上次现场"，独立于组合件的自动化行为（实现 Gate）。
5. **保存机制**：显式保存为主 + 脏标记；**原子写**（临时文件替换）防半写损坏；自动保存/崩溃恢复属 UX/后续。
