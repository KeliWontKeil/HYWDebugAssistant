# ADR-0039：模块窗口视觉规范重置 + 端口标记 → 叠加信息层

> **状态**：**Accepted（2026-09 · 依据用户第六轮反馈的逐项裁决 D-3/D-4/D-8）· 待实现（`08` M1-16 批次 B1/B2/B3）**
> **关联**：ADR-0034（拼图式多窗口）· ADR-0037（建网重写 · 端口标记标准件）· ADR-0038（外壳形态）· `architecture/14-ui-rework-m1-16.md`
> **修订对象**：主文档 §10.1-4（连线表达）· §9.5（设置项语义）· §5.2（公开面：端口类型信息）· `05` §5.5/§5.14/§5.17 · `09` §5/§6 · `08` M1-16

---

## 1. 背景

用户第六轮反馈（需求 2）逐条指出模块与端口标记的表现问题，并给出目标形态。其中三项**推翻既有结论**：

1. **"无标题栏但保留顶部身份行"** → 用户否决："**边框应覆盖整个窗口，不应留出一个标题栏**，以表现它是一个**模块**而不是**窗口**"；模块名**不显示**（现位于左上）。
2. **连线表达**：ADR-0034 裁决"多窗口下 v1 不做跨窗口长连线，改为口上标记 + 高亮 + 只读拓扑诊断"。用户给出**新的可行形态**：把「口上标记」开关改为「**叠加信息层**」——开启后在**模块窗口内**绘制指向其连接模块的线并指示数据流向；**模块拼接后线自然相连**，无需特殊操作；层上可给出更详细信息。→ **结论可保留（仍不做跨窗口覆盖窗），但表达方式升级为"窗内叠加层 + 拼接连通"**。
3. **接口信息类型**：用户"完全不知道接口的信息类型"，并追问是机制缺失还是仅 UI 未表现。**经核实：机制已实现、公开面未暴露**（`Core.Api.PortView` 只有 `ContractSizeInBytes`，而 `Sdk` 的 `ContractShape` 一等事实包含原语/结构/定长数组与兼容性判定）→ 需**扩展公开面**。

## 2. 决策

### D1. 模块窗口 = 整块"模块"，无标题栏
- **删除身份行**：模块名不显示；整块窗口矩形**即模块矩形** → 与 `DockRule.MarkerCenter` 的几何基准**完全一致**（顺带消掉一处"UI 基准 vs Core 基准"的潜在偏移）。
- **边框覆盖整个窗口周界**：1 px 常规 / 选中态主色加粗；不预留任何"标题栏"区域。
- **运行指示移左下角**：状态点 + 状态文本（10 px 弱化色）。
- **按钮簇移右上角、纯图标**：锁定/解锁 · 隐藏/显示 · 停止/运行 · 关闭（悬停或选中时淡入，命中区 12×12）。
- **取消选中**：点外壳/本应用其他窗口 → 清除选中（现存缺陷：无法取消选中）。

### D2. 缩放手柄
- 角点/边中点手柄 **12×12 → 6×6**。
- **仅在被选中或悬停时可命中**（`IsHitTestVisible` 随选中态切换）→ "手柄置顶"与"端口标记可点"不再互斥（这是 2026-09 缺陷"双击标记无反应"的根因之一）。

### D3. 端口标记（标准件）规格变更
| 项 | 原（ADR-0037） | 新（本 ADR） |
|---|---|---|
| 尺寸 | 20×76（竖排）/ 76×20（横排） | **20×114 / 114×20**（**长度 +50%**） |
| 贴边 | `EdgeInset = 1`（离外沿 1 px） | **与外边框完全重合**（`EdgeInset = 0`） |
| 内容 | 网络名 + 方向箭头 + 速率 + 状态灯 | 增 **信息类型**；四段**固定宽度槽位**（名称 / 类型 / 箭头 / 速率+灯），数值右对齐、固定小数位、空值 `---` → **信息变化不再引起排版抖动** |
| 箭头方向 | 按角色 `→`/`←` | **按边取向外/向内**：发送口（右边缘）= 向外；接收口（左边缘）= 向内（竖排随旋转变换） |
| 字号 | 10 px（速率 9） | **11 px**（速率 10） |

### D4. 公开面扩展：端口**信息类型**
- `Core.Api.PortView` 新增 **`ContractText`**（如 `f32` / `u64` / `f32[8]` / `enum(Foo)` / `struct{seq:u64, value:f32}`）。
- 由 `Sdk/Contracts/ContractShape` 新增 **`Describe()`** 渲染（**只增不改**：既有成员与语义不变）。
- 兼容性：新增可选参数（默认 `null`）= **兼容扩展**；旧 UI 代码不受影响。

### D5. 「口上标记」→「**叠加信息层**」（开关真正生效）
- **端口标记常显**（模块标准件，不再有开关）；**开关改为控制叠加信息层**，并**改名换语义**：`showPortMarkers` → **`showInfoOverlay`**（旧键兼容读取；旧文案「口上标记」改为「叠加信息层」）。
  > 现状缺陷：`showPortMarkers` 在设置/工具栏可改、可持久化，但**没有任何 XAML 绑定到标记可见性**（死开关）——本 ADR 一并修正。
- **叠加层内容**（绘制在内容之上、按钮簇之下，`IsHitTestVisible=false`）：
  1. **连接线**：从每个已连接端口标记出发，朝**对端模块方向**画线；模块**拼接（接触）后线在公共边处自然相连**（不需要跨窗口覆盖窗，也不需要跨窗口长连线）；
  2. **流向**：箭头 + 沿流向的克制动效（0.8 s 周期，可关）；
  3. **详细信息**：线端小标签 = 对端 `模块名.口名` + 速率 + 累计量；**未拼接**时线只画到本窗口边缘并标注"→ 对端名（未拼接）"（D-4 裁决）。
- 分层（自下而上）：内容 → 交互带/手柄 → 口标记层 → **叠加信息层** → 按钮簇。

### D6. 颜色与主题跟随
- 保持工程工具风，**加入层级色阶**（活动栏/工具区/内容底三档），语义色只用于状态、不铺面积；模块窗口底色可混入主色极轻比例，避免"一片灰"。
- 模块窗口、标记、叠加层、弹窗**全部走同一套 token** → 设置里改主题/主题色/背景时**一并跟随**（ADR-0038 D4）。

### D7. 图标（D-8 裁决）
- **允许引用图标包**（用户裁决），前提：**许可在白名单内**（MIT/ISC/CC0 等）且**实测观感确实更好**。
- 选型：Lucide（MIT）的 Avalonia 封装 或 `Projektanker.Icons.Avalonia` + MaterialDesign（MIT）；**先过许可审计 + 观感对比**，若不如 Fluent 内置符号字形则退回内置（**不加依赖也是合法结论**）。

## 3. 理由

1. 用户对"像窗口而非模块"的观感有明确诉求 → 无标题栏 + 边框覆盖全窗是**结构级**修正，不是配色微调。
2. 标记"看得见、不抖动、贴边、方向可读"是**建网唯一入口**的可用性前提（此前缺陷正源于标记不可见/被压住）。
3. 叠加载荷"拼接即连通"这一物理直觉，避免引入跨窗口覆盖窗（后者需要 layered/click-through/多 DPI 处理，成本与风险都高）。
4. 信息类型必须来自**公开面**而非 UI 反射运行时内部（AR-16）：故扩 `PortView` 而非让 UI 直连 `Core`。
5. 死开关是"看起来能用、实际没有效果"的典型，必须在本次一并消除（并列为"开关必须有真实落点"的检查项）。

## 4. 影响面

| 项目 | 影响 |
|---|---|
| `Core.Api` | `PortView` 增 `ContractText`；`ApplicationSettings`：`showPortMarkers` → `showInfoOverlay`（旧键兼容） |
| `Sdk` | `ContractShape.Describe()`（只增不改） |
| `Core` | `RuntimeServices.ToView` 填 `ContractText`；`SettingsService` 读写新键 + 旧键回退 |
| `Ui` | `ModuleWindow.axaml(.cs)`（删身份行、边框、按钮簇右上图标化、运行指示左下、手柄 6×6 且按选中态可命中）· `PortMarkerViewModel`/`PortMarkerPanel`（尺寸/贴边/固定槽位/箭头）· **新增 `ConnectionOverlay.cs`** · `Tokens.axaml` |
| `FrameworkUi` | 开关文案与绑点改为「叠加信息层」 |
| 测试 | `ModuleWindowUsabilityTests` 扩展（槽位宽度稳定、箭头方向、类型文本）；B7 加无头布局/命中/可见性断言 |
| 文档 | 主文档 §10.1-4 · §9.5 · §5.2 · `05` §5.5/§5.14/§5.17 · `09` §5/§6 |

## 5. 不做

- 跨窗口覆盖窗与跨窗口长连线（**不变**）；
- 标记的自由拖拽/多列排布（口位置仍由端口几何 `AnchorOffset` 决定）；
- 叠加层的交互（不可点选；点击穿透到内容）。
