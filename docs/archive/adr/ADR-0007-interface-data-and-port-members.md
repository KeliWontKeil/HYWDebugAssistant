# ADR-0007 Interface 数据面与口成员裁决（PQ-IF-01/02 等）

> 状态：Accepted（用户裁决，批次 2）
> 关联批次：批次 2
> 关联主文档章节：§5
> 取代：无
> 被取代：第 1 条（口方向三态）由 **ADR-0022** 修订为**两态（发送/接收）**（双向=两个口）；网络严格单向

## 问题

批次 2 前导（ADR-0006）确立"模块机制"为轴后，Interface 域首批概念裁决：连接方向语义、口的数据面本质（PQ-IF-01）、口身份与能力目录（PQ-IF-02）。

## 决策

1. **连接无强制方向（IF-A）**：端口声明"发送/接收/双向"；连接不强制 In→Out，任意两口可连；"能否传数据"由端口方向能力在建立/运行期判定并给 UI 提示。
2. **数据语义（PQ-IF-01）**：统一 **数据单元流（Unit Stream）** 载体——模块间传递一串按序到达的"数据单元"，绑定只保证按序交付、不解释单元内部（Core 不中转，§7.2）；**流/消息/事件是契约层的传递语义标注**，不是机制三分。**"组合编码/签名/掩码"登记为契约表达语言的候选机制（PQ-IF-03 细化）**：口的数据流可由基本单元组合编码描述，签名兼容构成兼容判据。
3. **口身份与能力目录（PQ-IF-02）**：口名 = 模块内唯一稳定名（作者在成员声明中命名，多同型用名+序号）；连接锚定 `实例ID.口名`。平台提供**元能力目录**（受控）：可实例化口、可被连接、方向三态；**业务形状由作者在契约中描述，不入平台目录**（P16）。
4. 分发（1:N 多接收端）归连接机制（IF-B 原理）；结构块文档重构暂缓（用户裁决"暂缓结构块"）。

## 影响

- §5 新增冻结裁决节；PQ-IF-01/02 关闭。
- 后续 PQ-IF-03（契约表达语言，含组合编码）、PQ-IF-04~06（兼容规则）、PQ-IF-07（多播承载落定）、PQ-IF-08~11（收尾/Gate）。
