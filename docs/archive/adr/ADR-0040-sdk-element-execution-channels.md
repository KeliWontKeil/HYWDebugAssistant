# ADR-0040：SDK 视图元素执行通道（B2 命令按钮 · B5 文本输入 · A10 开关）+ 参考发送模块重写

> **状态**：**Accepted（2026-09 · 依据用户第六轮需求 3 与 D-5/D-7 裁决）· 待实现（`08` M1-16 批次 B6）**
> **关联**：ADR-0028（模块 SDK 形态）· ADR-0031（UI 架构）· ADR-0035 D6-1（**本 ADR 关闭该登记项**）· `architecture/11` §10.3 · `architecture/14-ui-rework-m1-16.md` §3/§9.2
> **修订对象**：主文档 §5.2（SDK 公开面）· §10.4（渲染子集）· `03` §3.6（视图声明）· `04` §4.1（线程归属）· `05` §5.6（表单与输入渲染）· `08` M1-16

## 1. 背景：已登记的设计缺口

SDK 的元素目录里**早就声明**了 `CommandButton = 9`、`ToggleSlider = 10`、`TextInput = 12`（`Sdk/Views/ViewDeclaration.cs`），但**没有执行通道**：

- 框架不渲染它们（渲染子集只有 A1 数值 / A3 曲线 / A5 文本日志 / B1 配置表单），其余按"未渲染"占位；
- 即使渲染，**值往哪里写、按钮点了执行什么**都没有面：模块是**被动**的，框架无法把"人的一次操作"投递到**模块线程**上执行。

M1-15 的权宜做法是**用配置写入充当"戳一下"**（参考发送器：改配置 = 发一个数据单元）。用户第六轮反馈明确指出这**反直觉**（"当前数据发送器有些过于反直觉"），并给出目标排版：

```
① 必要信息（紧凑）
② 文本输入框 + 发送按钮 / 自动发送滑块 + 时间输入框
```

并要求"**如果有必要，可能要重写整个发送模块，删除不必要的机制**"。→ **本 ADR 正式设计执行通道，并重写发送器。**

## 2. 决策

### D1. 命令通道（**B2 命令按钮**）
- 模块在 `ViewDeclaration` 中声明命令：`new ViewCommand("send", "发送", ViewCommandIcon.Play, ViewElementKind.CommandButton)`；
- 模块实现 **`IModule.OnCommand(string name)`**（在**模块线程**执行；与生命周期钩子同一线程约束，`04` §4.1）；
- 框架渲染按钮 → 点击 → `Core` 经变更入口**投递命令** → 在模块线程调用 `OnCommand`；**不阻塞 UI、不跨线程直接调模块**；
- 未知命令 / 未实现 `OnCommand` / 执行抛异常 → 转 **Issue（`ModuleError`）**，**不逸出**；
- 重复点击不排队堆积：命令**合并**（同命令在待执行队列中存在则不再追加，语义 = "至少执行一次"）。

### D2. 文本输入通道（**B5 文本输入**）
- 模块声明输入元素：`new ViewElement(ViewElementKind.TextInput, source: "input", title: "发送值")`，其 `ViewDataSource` 的 `kind = ViewDataSourceKind.Text`（或 `Value` + `valueType`）；
- **写入面**：框架把输入值**按声明写入**——`IModule.OnInput(string source, ReadOnlySpan<byte> value)`（模块线程执行），或（对既有 `Value` 数据源）走既有"按字段写回"通道；
- **写入时机（D-5 裁决）**：**回车 / 失焦**提交（不做逐字符写入），并在 UI 上给出"未提交"与"已写入"的可辨识状态；
- 写入失败（类型/范围不合法）→ **就地报错 + 不静默**（沿用端口标签编辑的反馈口径）。

### D3. 开关/数值写入（**A10 开关滑块**）
- `ToggleSlider` 声明为布尔或数值输入；写入面与 B5 相同（一次提交一个值）；
- v1 不引入"连续拖动即连续写入"（避免刷爆运行时）；拖动只在**松手**时写入。

### D4. 渲染与尺寸
- 渲染子集扩充为：**A1 数值 · A3 曲线 · A5 文本日志 · B1 配置表单 · B2 命令按钮 · B5 文本输入 · A10 开关 · A11 枚举选择**（后者已具备）；
- **统一控件高度 `ControlHeight = 27`**（字号 12、圆角 3、行距 4），由 `Tokens.axaml` 定义并全局应用（禁止逐处写死）；
- 布局：同一行内的元素**横向紧凑排列**（信息两列 / 输入+按钮一行），不再一律纵向堆叠。

### D5. 参考发送模块**重写**（删除权宜机制）
| 删除 | 理由 |
|---|---|
| `ManualSendMode` 枚举 与 `OnApply`（"写配置即发一个"） | B2/B5 到位的权宜通道 → **本 ADR 关闭该缺口后不再需要** |
| 配置项 `发送值` / `模式` / `周期` | 改由**视图元素**承担（输入框 / 开关 / 数值输入），配置只留"非交互"参数 |
| 配置项 `写入显示缓冲` | 诊断细节不占用户界面（诊断统一去 Issue / 拓扑 / 叠加信息层） |

| 新视图（自上而下） | 元素 |
|---|---|
| ① 必要信息（紧凑两列） | `Numeric 待发送值` · `Numeric 已发送` · `Numeric 被丢弃` |
| ② 输入与发送（一行） | `TextInput 待发送值` + `CommandButton 发送` |
| ③ 自动发送 | `ToggleSlider 自动发送` + `Numeric 周期(ms)` |
| ④ 其余配置（折叠） | `ConfigurationEditor`（仅保留非交互参数；无则整块消失） |

- 单次/连续两种行为改由**开关**表达（开关开 = 按周期连续发送），**不再用枚举**；
- 模块对外契约（`out` 口形状 `{seq: u64, value: f32}`）**不变** → 与记录器/断言器/显示模块的互通不受影响（AC-1~6 与 T1 参考组合照常）。
- 顺带：**信息显示模块**只做"统一控件高度 + 行距 + 与主题 token 对齐"，**不重写**（用户口径：删除「不必要的机制」，显示模块没有权宜机制）。

### D6. 兼容性
- SDK **只增不改**：新枚举值（`ViewCommand` 等）为新增类型/成员；`ViewElementKind` 的既有值语义不变；
- 未使用新面的既有模块**照常工作**（不渲染的元素继续以"未渲染"占位，不假装支持）；
- 框架兼容范围（F1 版本区间）需按 SDK 面变更**登记**（`Sdk` 版本号 + 兼容范围回写 `03` §3.7）。

## 3. 理由

1. **人的操作必须有正规通道**：用"改配置"充当点击，是把自己实现的机制当成 UI 事件总线——反直觉、且把"配置"原本的语义（随组合件保存的参数）搅浑。
2. **线程约束不可破**：模块是单线程活动体，UI 直接在 UI 线程调模块会破坏数据面假设 → 必须"投递到模块线程执行"。
3. **一次一个值的写入**（回车/失焦、松手）与既有"两阶段 ChangeSet"成本模型相称；逐字符写入会在管理面上产生海量变更。
4. **重写而非补丁**：权宜机制一旦保留，会长期误导模块作者（"发送器就该这么写"）→ 删除并把模式固化为 SDK 通道。

## 4. 影响面

| 项目 | 影响 |
|---|---|
| `Sdk` | 新增 `ViewCommand`/`ViewCommandIcon`；`ViewElementKind` 语义文档化；`IModule.OnCommand`/`OnInput`（可选接口或默认实现）；`ContractShape.Describe()`（ADR-0039 共用） |
| `Hosting`/`Core` | 命令与输入的**投递队列 + 模块线程执行**（复用数据面/生命周期既有线程归属）；失败转 Issue；命令合并策略 |
| `Core.Api` | 视图命令的只读描述（供框架渲染）、输入写入命令（`SubmitInput(instanceId, source, text)`） |
| `Ui` | `ModuleContentView.axaml`（模板新增 TextInput/CommandButton/ToggleSlider 渲染）· `ConfigurationFormView`（控件高度 27）· `Tokens.axaml`（`ControlHeight`） |
| `Modules.Reference.ManualSender` | **重写**（D5 清单） |
| 测试 | Tests：命令投递与合并、输入写入（合法/非法）、线程归属断言、失败转 Issue；Tests.Reference：`ManualChainTests` 改为经命令/输入驱动（**保持 AC 判据不变**） |
| 文档 | 主文档 §5.2/§10.4 · `03` §3.6 · `04` §4.1 · `05` §5.6 · `11` §10.3（关闭登记项）· `08` M1-16 |

## 5. 不做

- 模块自定义任意 WPF/Avalonia 控件（模块只声明元素，渲染由框架负责，ADR-0031 不变）；
- 双向"实时同步"输入（输入值是**一次提交**，不持续回读）；
- 模块命令的快捷键绑定（D-7 裁决：v1 只在窗口内点击）；
- 输入的历史/脚本/批量导入（后续里程碑另议）。
