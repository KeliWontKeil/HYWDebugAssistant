# ADR-0032 测试架构映射（技术架构设计 第 6 章冻结）

> 状态：**Accepted**（Q6-1~Q6-4 用户裁决；C6-1~C6-4 经用户授权由设计方推荐并记录）
> 关联阶段：技术架构设计（选型后 · 实现前）
> 关联主文档章节：§14.1（AC-1~6）、§14.2（参考组合）、§14.4（T1–T8）、§13.2（可观测性）
> 关联文档：`docs/architecture/06-test-architecture.md`（全文）
> 关联 ADR：ADR-0025（测试纪律与 5 开关）· ADR-0026（七层禁令 → AR 规则集）· ADR-0027（三测试项目 + `App` 白名单）· ADR-0028（T6）· ADR-0029（T1 覆盖项）· ADR-0031（UI 范围）
> 取代：**A1–A6 架构测试骨架**（工程基线阶段；语义并入 AR-1~AR-16） · 被取代：无
> 推荐与裁决：C6-1~C6-4 由**设计方推荐**（经用户授权，见 `architecture/06` §6.7），已随本 ADR 的 Accepted 裁决追认（见 ADR 修订记录）

## 问题

AC-1~6 与 T1–T8 需要落到具体项目、工具与判定方式；工程基线阶段的架构测试骨架（A1–A6）基于旧命名后缀推断，须按 ADR-0026 的七层重写；"Core 零改动"（AC-1/AC-6）需要可执行的判定口径。

## 背景

- 用户裁决：Q6-1 **依赖图断言 + 回归**；Q6-2 **程序集引用/IL 检查**；Q6-3 **v1 不做 UI 自动化**；Q6-4 **T6 提供且推荐**。
- 用户对测试领域的明确要求（授权设计方推荐其余项）：**"测试流程能够简单快捷地验证，不要求全方位全覆盖，只希望自动化完成主要问题的验证/测试；做不到可以跳过。我只能完成最终 UI 应用层面的测试。"**
- 约束：ADR-0025（不设覆盖率、不自研第三方架构框架、例外机制）、ADR-0027（`App` 组合根白名单）。

## 最终选择

1. **测试项目**：`Tests`（T2–T5）· `Tests.Reference`（T1，参考组合三桩模块）· `ArchitectureTests`（AR 规则集，**不引用产品项目**）· 新增 `Benchmarks`（BenchmarkDotNet，**不进常规门禁**，`build.ps1 -RunBenchmarks` 按需运行）。
2. **架构规则集 AR-1~AR-16**（取代 A1–A6）：
   - **依赖类 AR-1~AR-12**（`MetadataLoadContext`/`System.Reflection.Metadata` 读程序集 `AssemblyRef`）：模块只引 `Sdk`；模块互引禁止；`DataPlane`/`Hosting`/`Core`/`Core.Api`/`Ui`/`FrameworkUi`/`Sdk`/`Infrastructure` 各自的允许集合；模块不得被框架编译期引用；**唯一白名单 = `App` 组合根**。
   - **源码类 AR-13~AR-16**（源码扫描）：业务词汇禁令（`Core`/`Hosting`/`DataPlane`）、命名空间与目录一致、ADR-0024 排除清单、`Core.Api` 公开签名不得含内部类型。
   - **"跳过 vs 失败"语义**：目标程序集缺失即**失败**（禁止规则静默失效）——工程基线阶段的"无对象则跳过"逻辑必须移除。
3. **AC-1 判定口径**：框架程序集**引用集不变** + 既有测试全绿 + 新模块功能测试通过；不做 IL/二进制基线比对。
4. **T1–T8 映射**：T1 ✅ · T2–T5 ✅（表驱动优先）· T6 ✅ 提供且推荐 · T7 用户手工（须交付**手工验收清单**）· T8 ❌ v1 不做。
5. **简单快捷原则**：基准不进常规门禁；优先表驱动；自动化聚焦六项判据与四类机制（ChangeSet / 增量重建 / 持久化 / 丢弃与停止），不追求边界穷举。
6. **资源释放验证**：计数断言为主（活动线程/队列/池计数归零）+ 少量关键点弱引用断言。
7. **参考组合桩模块**：只声明少量视图（数值 + 曲线）；其余元素由 Gate C 原型与手工验收覆盖。

## 选择理由

1. **程序集引用检查**能覆盖**间接依赖**（源码扫描只能看直接 `using`/`ProjectReference`）——依赖禁令是分层的核心护栏，值得用可靠判据；而命名空间一致性、业务词汇这类规则**程序集元数据无法表达**，故两类规则分走两套手段。
2. **失败而非跳过**：规则静默失效比规则误报危险得多（分层项目一旦改名，规则可能整体失效而无人察觉）。
3. **基准项目独立且不进常规门禁**：直接落实"简单快捷"——日常构建不受拖累，Gate B 数值仍有明确承载。
4. **计数断言为主**：弱引用断言受 GC 时机影响易 flaky，与"快捷、稳定"的目标冲突；只在关键路径保留。
5. **桩模块少量视图**：v1 无 UI 自动化时，把 18 元素塞进参考组合会稀释 T1 的判据焦点。

## 放弃方案

- **纯源码扫描**（原 A1–A6 方式）：查不到间接依赖。
- **IL/二进制基线比对**：成本高、误报多（编译器版本/时间戳等），且依赖图断言已能覆盖 AC-1 的实质。
- **全部改为程序集检查**：会丢掉业务词汇与命名空间一致性两条规则。
- **T8 UI 自动化进 v1**：`Avalonia.Headless` 全套 UI 测试成本高、易碎，与"简单快捷"冲突（用户裁决 v1 不做）。
- **T6 强制**：v1 无第三方生态，强制只会阻碍作者（用户裁决：提供且推荐）。
- **基准测试放进 `Tests`**：会拖慢常规门禁。

## 影响

- **架构测试项目须重构**：移除工程基线阶段的 A1–A6 与"分层未落地则跳过"逻辑，改为 AR-1~AR-16；`App` 白名单生效。
- **`build.ps1`**：新增可选 `-RunBenchmarks` 步骤（默认不跑）。
- **第 7 章**：Gate B 中"UI 自动化测试"项据此关闭（v1 不做）；"数值指标"由 `Benchmarks` 承载。
- **交付物**：实现阶段须产出**用户手工验收清单**（T7），覆盖模块加载、拼接、建网/连线、配置修改、保存/加载、持续运行观察。
- **对主文档**：已将 §14.4 的 AC-1 判定改为**依赖图断言 + 回归**、T5 移除风暴护栏项（该项由 ADR-0029 处置）、**T8 UI 自动化 v1 不做**；§13.2 数值指标改为**实测回写、仅记录不设阈值**（由 `Benchmarks` 承载）；§14.1/§14.2 属实现层映射细化；修订记录登记为 1.0.3。
