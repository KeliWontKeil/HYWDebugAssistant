# ADR-0023 技术栈选型（数据面 C#/.NET + UI Avalonia · MIT 约束）

> 状态：**Accepted**（用户确认，技术选型阶段）
> 关联阶段：技术选型（Gate A）
> 关联文档：《上位机架构设计.md》v1.0 §15（选型约束来源）、§18.5-A（Gate 清单）
> 前置裁决（用户）：性能余量优先 · 允许混合架构 · 跨平台"有一定可能" · **闭源商用自由分发且禁止采购**（许可基线 **MIT**）
> 取代：无 · 被取代：无（§5 脚本宿主留位、§7 多视觉层被收窄/具体化，见下）
> **收窄/修订说明**：§5 脚本宿主留位在 v1 不实现（**ADR-0028** §9）；§7 多视觉层已由 **ADR-0031** 具体化为"工作区层 + 信息类层"。

## 问题

在 v1.0 顶层基线约束下确定实现技术栈：运行时/语言、数据面形态、UI 技术、模块行为载体、许可与依赖策略、性能上限的可扩展路径。

## 决策

1. **运行时与语言**：**.NET（最新 LTS）× C#**；**不使用 Native AOT**（其会限制运行期动态加载与脚本，与 ADR-0020 模块供给冲突），保留 JIT 运行时。
2. **数据面 = C#（严格零分配设计）**：`struct`/`Span<T>`/`Memory<T>`/`ArrayPool<T>`、批量传递、避免装箱与委托分配；GC 配置 = Server GC + 低延迟模式（并按需 DATAS）。**工程量级**（待实测）：结构体消息 ~10⁶–10⁷ 单元/秒/核；`Span` 解析 ~0.1–1 GB/s+。
3. **性能上限可扩展路径（冻结为备案）**：若出现极端热点（超高速采集解析/滤波），**将该热点下沉为原生库**（Rust/C++ 编译动态库，经 `LibraryImport`/P/Invoke 调用），其余保持 C#；不整体换栈。
4. **UI = Avalonia（MIT）**：理由——跨平台"有一定可能"（避免未来 UI 层重写）、单栈单进程（UI↔数据面同进程、可零拷贝共享缓冲）、XAML 知识与 WPF 互通、原生窗口契合"模块视图自由排列"、Skia 自绘能力满足波形需求；波形可先用 **ScottPlot.Avalonia（MIT）** 起步，性能不足时下沉自绘。
5. **模块行为载体（ADR-0006 的"行为层"）**：**C# 为主路径**（预编译程序集 / Roslyn 动态编译）；**脚本宿主为可选**（非热路径：编排/胶水/第三方轻量扩展），**具体脚本语言留后续 ADR**，且必须满足第 6 条许可约束。
6. **许可约束（用户裁决，硬约束）**：依赖仅允许 **MIT / Apache-2.0 / BSD 等宽松许可**；**禁止 GPL/LGPL 与任何需采购的商业授权**；实现阶段须做**依赖许可审计**（逐项核实，含传递依赖）。
7. **UI 架构方案（不冻结，仅登记）**：允许多**视觉层**（如：模块视图层 + 叠加层：连线/网络标识/状态监控），**层只承担视觉体验、不承担业务逻辑**（类比 PCB 层级概念，但不同于走线承载电气功能）。
8. **跨平台**：由 Avalonia + .NET 天然提供，但**不为跨平台牺牲性能**（Windows 为首要目标，跨平台能力作为保留选项）。

## 影响

- 解除 Gate A 中"UI 框架/运行时"两项；其余库级选择（DI/序列化/日志/配置/测试/串口·网络库等）在**技术架构设计**阶段逐项裁决（同受第 6 条约束）。
- 主文档 §15 在选型结束、用户确认后更新（记录结论与 ADR 引用）。
- 技术选型的评估材料见 `docs/technology-selection/01–04`。
