# ADR-0015 错误模型定稿（Issue / 隔离恢复 / 通知日志分层）

> 状态：Accepted（用户裁决，批次 5）
> 关联批次：批次 5
> 关联主文档章节：§8.2、§8.3、§8.5
> 取代：无（在 §8.2/§8.3 两类故障语义上定稿） · 被取代：无

## 问题

PQ-ER-01~03：错误/异常模型、Fault Isolation 传播规则、用户通知与日志/诊断层级职责。

## 决策

1. **ER-01 Issue（问题标注）统一模型**：框架把一切可呈现问题统一为 **Issue**：`归属对象`（实例/口/连接/配置项）+ `类别`（配置/组合/接口/模块/通信/运行时/呈现，沿用 §8.2 分类）+ `来源`（框架判定 / 模块报告）+ 描述与时间。语义分两类：**设计/变更问题**（可判定、用户可修）与**运行报告**（运行期产生）。**模块业务状态不入 Issue**（属状态面，§8.4）。呈现=对象标注 + 汇总列表；**不阻止其他部分运行**。
2. **ER-02 隔离与恢复**：**天然隔离 + 显式恢复**——框架**不自动重试、不自动降级、不阻断上下游**（延续 §8.3）；隔离的实现保障 = **模块异常不逸出边界**（框架在边界捕获并转为 Issue，ADR-0004 边界契约）；恢复 = 用户显式操作或模块自身内部恢复。可选标准动作：**"重建实例"**（Remove + Add 的复合 ChangeSet，UI/命令层组装，框架只执行 ChangeSet）。
3. **ER-03 通知与日志分层**：**框架层**=Issue 列表（对象标注+汇总）+ 机制层诊断日志；**模块层**=模块自产日志/诊断经框架汇集呈现（接口细节→批次 9 可观测性）；**通知强度**=默认轻量呈现（标注/计数），**不弹窗打扰**；允许模块声明"需要用户注意"级别，默认不打断（呈现形态→批次 7）。

## 影响

- §8.2/§8.3 由"批次 0 草案"转为**定稿**（两类语义 + Issue 模型）；PQ-ER-01~03 关闭 → 批次 5 全部裁决完成并冻结。
- 为批次 9（可观测性细节）与批次 7（呈现形态）留接口。
