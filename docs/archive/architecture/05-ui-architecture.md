## 5.1 UI 构成总览

> **【修订 · ADR-0034（拼图式多窗口）】** 原表述把 `Ui` 放在外层、`FrameworkUi` 作为其中一块，并按"层"组织；
> 现修订为：**`FrameworkUi` 是外层主窗口（持有 Window）**，`Ui` 只提供**模块区控件**（模块各自是无边框顶层窗口）；
> 详见 `11-presentation-revision.md`。

```text
Application
├─ FrameworkUi（**外层主窗口**：持有 Window / 菜单 / 工具栏 / 状态栏；§3.2：不作为普通 Module）
│   ├─ 模块清单 / 加载（弹窗；含**无 UI 模块**的状态与配置兜底表单，§10.4）
│   ├─ Issue（弹窗：汇总 + 四项过滤，§8.5）
│   ├─ 设置（弹窗：应用级设置，ADR-0030）
│   └─ 拓扑诊断（弹窗，只读：网络 / 成员 ID / 方向 / 状态 / 投递与丢弃计数）
└─ Ui（**模块区控制器**，术语 Shell 收窄为"模块表现"）
    └─ 模块窗口群（**每个模块一个无边框顶层窗口**，边缘吸附拼接、整组拖动、可锁定）
        · 模块视图 = 框架按模块声明渲染（§5.3）
        · 口上标记 + 选中/悬停高亮 = **信息表达**（不再是"叠在画布上的层"）
```

- 所有读取与命令**一律经 `Core.Api`**（C4-4/Q1-4）：UI 不引用 `Core`/`Hosting`/`DataPlane`/`Infrastructure`，也不引用任何模块实现程序集。
- UI 侧不持有任何机制实现；运行由 Core 承载（§10.4）。
- 依赖方向仍为 **`FrameworkUi` → `Ui`**（AR-8 不变）：原先"`Ui` 声明宿主契约、`FrameworkUi` 实现"的接缝**撤销**，改为 `Ui` 暴露模块区控制器、由 `FrameworkUi` 主动调用。

## 5.2 层模型（Q5-2 裁决落地）

| 分类 | 性质 | 内容 | 可见性 |
|---|---|---|---|
| **模块窗口群（元件）** | **不是"显示层"**，而是用户拼出来的**基础工作单元**（每个模块一个无边框窗口） | 仅模块视图；**始终显示** | 不可关闭（可隐藏/锁定单个模块） |
| **信息表达**（按功能分类，可开关） | 依附于模块窗口的信息呈现，**不再是"叠在一张画布上的层"** | 口上标记（网络名/方向/状态）、选中与悬停高亮、Issue 标注 | 可开关；**不预设项数，保留扩展可能性** |
| **诊断视图**（独立弹窗） | 跨模块的只读信息 | 拓扑诊断（网络/成员 ID/方向/状态/投递与丢弃）、Issue 汇总 | 按需打开 |

> **【修订 · ADR-0034】** 原"工作区层（元件层）+ 信息类层（多层叠加）"的**层模型**在多窗口形态下不再成立：
> 没有承载一切模块的画布，故不存在"下层/上层"；"信息类"保留为**功能分类**（连线表达/标记/诊断），不是"层"。
> 原"绘制次序：工作区层在下、信息类层依次在上"随之失效。

**归属原则（回应"模块自身 UI vs 框架信息表达"的区分）**：

| UI 内容 | 归属 | 理由 |
|---|---|---|
| 模块视图（18 元素 + 4 容器） | **模块自身 UI**（框架渲染） | 是模块这个功能单元面向用户的表现（§10.1） |
| 模块自己的**简易标记**（受模块视图空间限制） | **模块自身 UI 的一部分**，绘于**模块窗口内** | 标记属于模块自己的一部分，因此随模块视图走 |
| 网络标识、方向标识、连接状态（口上标记） | **框架信息表达** | 连接连接的是**两个模块**，任何单个模块都表达不了 |
| 选中/悬停高亮（同网络成员）、流量/丢弃指示 | **框架信息表达** | 跨模块或框架级信息 |
| 完整的连接关系（网络与成员唯一 ID） | **诊断视图（弹窗）** | 用户裁决：这是**调试信息**，形态与 Issue 同级；不作为操作界面 |
| Issue 标注 | **信息表达 + `FrameworkUi` 汇总** | §8.5：对象标注 + 汇总列表 |

- **信息表达只承担视觉、不承担逻辑**（ADR-0023 §7）：其开关/绘制不影响数据面与模块运行（§10.1）。
- 具体视觉形态与开关分组（显示 / 交互 / 窗口）属 Gate C。

## 5.3 模块视图与视图声明（承 Q3-7 / C3-6）

- 模块视图 = **Instance 的派生物**（§10.1），随实例创建/销毁，可独立开关/重排（不影响运行）。
- 渲染内容 = 模块**声明**的元素组合（18 元素 + 4 容器，C3-6）：数值显示、状态灯、曲线、表格、日志窗口、十六进制视图、仪表、图像；配置编辑、命令按钮、开关/滑块、枚举选择、文本输入、文件选择；分组/分栏、标签页、折叠、滚动。
- **模块不提供 View 类型**（C1-3）：框架按声明渲染；元素**类型**属架构（已定），元素**视觉形态**属 Gate C（UX 原型）。
- **模块自身简易标记**（Q5-2 裁决）：受模块视图空间限制的轻量标记（如状态点、方向提示），属于模块自身 UI，绘于工作区层。

### 数据绑定（Q5-3 ①）

```text
模块声明「可暴露数据源」：名称 + 类型（值 / 序列 / 行集 / 字节块 / 文本 / 帧）
      ↓ 框架按声明拉取（节拍 = UI 刷新率，来自应用级设置）
订阅缓冲（Q4-4）：单值/状态 = 最新值槽；流数据 = 环形缓冲（满则丢旧）
      ↓ UI 线程读取 + 抽样/降采样（抽在 UI 侧）
渲染
```

- 模块**不知道**自己的数据被谁展示、怎么展示；只声明"哪些数据可暴露"。
- **无 UI 模块合法**（§10.4）：不声明视图的模块照常运行，其状态与配置经管理视图访问。

## 5.4 模块区排布与拼接（Q5-1 / C5-1 / C5-2 裁决落地）

### 排布

- **自由画布**：模块视图绝对定位，用户可自由分散放置。
- **不做网格吸附**（用户裁决原话要点："并不存在可被看到的'网格画布'，网格吸附有悖直觉"）——吸附仅发生在**模块之间**与**画布边缘/参考线**。
- **不做容器式窗口停靠**：经用户澄清，Q5-1 的"停靠"指**几何吸附**（模块间拼接 + 参考对齐），**不是**窗口停靠（Docking UI）——不引入布局树/停靠槽位/标签页堆叠这类**容器形态**（与 §10.2「不采用画布容器概念」、§18.4「不做画布/面板容器形态」一致）。ADR-0024 遗留的"停靠面板 v1 自研（预留评估位）"**经评估不采用**。

### 拼接 = 由位置派生的关系（C5-1）

**核心裁决**：**"是否拼为一组"由位置决定，不作为独立信息存储**（用户原话要点："模块位置的拼接不是一个层级的信息……只保存位置是更好的决定"）。

```text
判定：两个模块的边缘在容差内贴合 → 视为拼接（几何谓词）
组：  贴合关系的「连通分量」（并查集）
存储：Layout 只保存各模块位置；加载后由位置重新推导组关系
```

**派生组带来的实现次序约束（必须在实现中遵守）**：

| # | 约束 | 原因 |
|---|---|---|
| 1 | 拖动**开始时**先计算所属分量并**冻结**，拖动期间整组移动，**结束后重算** | 否则拖动过程中会不断吸入新模块，产生"越拖越大"的怪行为 |
| 2 | 组具有**传递性**（A-B、B-C 贴合 ⇒ A/B/C 同组） | 链条式排列必须整体移动，否则拖动会留下破洞 |
| 3 | 传递性的代价用**快捷键独立拖动**抵消（Q5-1 已裁：快捷键可单独拖动已拼接组中的一个模块） | 用户想只动中间那个模块时可用 |
| 4 | **容差**是贴合判定的唯一参数；容差过小则"看着贴着其实没拼上"，过大则误吸 | 具体数值属 Gate C（视觉/手感） |
| 5 | 位置变化来源有三处：拖动、加载组合件、模块尺寸/端口锚点调整——**每处结束后都要重算** | 组关系必须始终由当前位置唯一确定 |
| 6 | 组**不是容器**：不含语义、不承载归属、不影响运行（§9.1/§10.1） | 防止 E6 型退化 |

**已知代价（接受）**：只存位置时，若模块尺寸族变化导致原本贴合的两个模块不再贴合，组关系会静默改变——这是"组不是独立信息"的必然结果。

### 吸附语义（C5-2）

| 场景 | 规则 |
|---|---|
| **无网络标签** | **边缘贴合 + 端口对齐优先**：优先让两模块的端口位置对齐（"插上"的手感），无端口参与时退化为普通边缘贴合 |
| **有网络标签** | **不做该限制**：由网络标签块（§5.5）承担对齐职责，模块边缘贴合不再强制端口对齐 |
| 吸附对象 | 模块边缘 / 网络标签块边缘（二者对齐规则见 §5.5） |
| 禁用吸附 | **快捷键**可临时停止吸附（精细摆放），支持**按住 / 切换**两种模式且可修改（→ 应用级设置项） |

### 几何一致性：不强制尺寸族，用"属性 + 约定"解决破洞（C5-6 / C5-7 / C5-8 裁决）

**不引入框架强制的尺寸族/模数基准**（用户裁决）。取而代之的是三项机制：

| 机制 | 内容 |
|---|---|
| **内置模块的尺寸族约定**（开发约定，**不强制**） | 内置模块使用特殊设计的长宽比与特殊设计的端口位置，使**默认的几种典型应用与典型简单功能组可直接拼成一整块**；这是开发中的约定，非框架约束 |
| **模块的拉伸属性**（模块属性之一） | `只能拉伸长` / `只能拉伸宽` / `任意拉伸` / `不允许拉伸`；用户可据此判断哪些模块适合参与整齐排版 |
| **端口锚点属性**（C5-7） | **是否可拖动**作为属性：**固定**时模块拉伸则**按比例重排**；**可拖动**时用户可自行调整端口在边缘的位置。可通过**快捷键/操作锁定与解锁** |
| **网络标签块可拉伸**（C5-8） | 标签块随模块边缘长度适配（拉伸），与"端口对齐优先"共同承担对齐职责 |
| **排版块**（无功能占位块，C5-9） | **一种常规模块**：没有端口、没有功能、只能随意改变大小；与各功能模块处于**同一级别、实现机制完全相同**（内置预装包，无结构特权，§11.2）；用于不强调视觉排版的模块（如数据处理类）之间的占位与整齐布局 |

**不强制尺寸族的后果（接受）**：由于尺寸自由，任意两个模块的边缘长度可能不同；破洞问题由"网络标签块可拉伸 + 端口对齐优先 + 可拖动锚点 + 排版块"共同缓解，而非由框架强制尺寸。

**与基线 §10.1-5 的关系**：基线原文"模块视图遵循**尺寸族与网格对齐**、接口靠边缘布局"——本次裁决将其**具体化并降级为开发约定**（不强制）；同时 Q5-1 已排除**网格吸附交互**（可见网格）。**"尺寸族"（排版约定）与"网格吸附"（交互）不是同一件事**，前者保留为非强制约定，后者排除。

## 5.5 连线与网络标识的呈现（信息类层）——**【修订 · ADR-0034】多窗口形态下无"层"，v1 不做跨窗口长线**

> **【修订 · ADR-0034 / `11` §2.3】** 多窗口形态下"叠在一张画布上的层"不存在：下表**连线**一行**v1 不做**（改为"口上标记 + 选中高亮同网络成员 + 只读拓扑诊断"），"绘制位置"一行随之失效。**网络标签块（口上标记）保留**。

| 项 | 设计（承 §6.3/§10.4） |
|---|---|
| ~~连线~~ | 【**修订 · ADR-0034**】**v1 不做跨窗口长连线**（点击穿透需 Win32 互操作 + 全局 z-order + 跨显示器 DPI 三事同办）；替代表达见 `11` §2.3 |
| **网络标签块（口上标记）** | 依附于**口**、贴在**模块边缘**的**小矩形块**（C5-2）；网络名弱化显示于其上 + 方向标识 + 连接状态；**双击就地编辑网络名 = 唯一建网入口** |
| 端口对齐 | 网络标签块**需要端口对齐**（有标签时由标签承担对齐职责，模块边缘贴合不再强制端口对齐） |
| 多链路区分 | 同色/同符号区分链路；**聚焦/高亮**（选中即高亮相关者）——**高亮的完整表达属 M1-16** |
| ~~绘制位置~~ | 【**修订 · ADR-0034**】无层可依：口上标记画在**模块窗口内部**（`PortMarkerPanel`），其余由拓扑诊断弹窗承担 |
| 分线器 | 无（已撤销，ADR-0018）：1:N 由绑定原生多播（§5.4.1） |

- 网络标签块的**数据来源**：`Core.Api` 查询（网络成员 + 口状态），**不由模块提供**（C5-3 ①：框架独占，模块只提供锚点）。
- **模块自身简易标记**（Q5-2 裁决）与**网络标签块**是两回事：前者属于模块自身 UI（在工作区层，随模块视图走），后者是框架的信息呈现（在信息类层）。
- 状态语义：停流（上游无输入/Disabled）、悬空（口消失，§9.3）、无数据流（方向不匹配，§5.4）——均为**状态呈现**，非错误弹窗。

## 5.6 配置界面（Q5-5 ①）

- **按配置 Schema 全自动生成**（与 Q3-4 的 C# 类型 + 源生成直接对应）：数值/文本/布尔/枚举控件按字段类型生成，分组按字段顺序/分类。
- 呈现位置：**模块自己的窗口内**（配置编辑元素 B1，模块声明时可选）。**【修订 · M1-15】**模块**未声明 B1 元素**时由**框架补上一个**——"配置编辑在模块视图内"（C5-4）对**所有**模块成立；"无 UI 模块经管理视图兜底"的旧口径作废（不声明视图的模块同样有窗口）。
- 配置写入路径：UI → `Core.Api`（`UpdateConfigurationField`，按字段）→ L4 变更入口 → `OnConfigurationChanged` 通知模块（§3.3/§4.5）。
- 配置随组合件保存（§9.2）；**应用级设置**独立（ADR-0030）——两者在界面上须明确区分（"该模块的配置" vs "应用设置"）。

## 5.7 框架自身 UI（`FrameworkUi`）——**【修订 · ADR-0034】外层主窗口 + 全部弹窗**

| 界面 | 形态 | 内容 | 依据 |
|---|---|---|---|
| **外壳窗口** | **一条工具条**（菜单/工具栏/状态栏）；**【修订 · M1-15 用户裁决】高度 = 内容高度（`SizeToContent=Height`）、不可缩放、不存在主体区域** | 模块清单 · Issue · 设置 · 拓扑诊断 · 显示/交互/窗口三组开关 | ADR-0034；`11` §3/§10.4 |
| 设置 | **弹窗** | 应用级设置全部项（框架行为 / UI 偏好 / 模块来源目录 / 日志），含快捷键与吸附模式配置 | ADR-0030；C4b-2 |
| Issue | **弹窗** | 汇总列表 + 四项过滤（归属对象/类别/**来源**/严重度）；默认轻量不打扰 | §8.5/§13.2 |
| 模块清单 / 加载 | **弹窗** | 模块目录（可用模块，**内置模块启动即已装入**）· 加入现场 · **占位实例**的替代指定；**不列实例清单**（每个实例都有自己的窗口） | §10.4；C5-4；`11` §10.4 |
| 拓扑诊断 | **弹窗（只读）** | 网络 → 成员唯一 ID（`实例ID.口名`）· 类型（匿名/命名/自动）· 方向 · 状态 · 投递/丢弃计数 · 最后数据时间 | ADR-0034（用户裁决：调试信息，形态与 Issue 同级） |
| 诊断面板（L1/L4，轻量提示） | 后续 | 同前（"缓冲持续为满""处理速度跟不上"） | §4.7/§4.11 |

**不属 `FrameworkUi`**：口上标记、选中/悬停高亮（这些属 `Ui` 的**信息表达**）。
**不再存在**：常驻侧栏 TabControl（原模块/Issue/设置三页形式，ADR-0034 废止）；**外壳主体区域**（不留任何"隐式工作区"观感）；**实例清单与"无界面模块"概念**（每个实例都有自己的窗口）。

### 5.16 M1-17：窗口层级统一 · 设置分类 · 快捷键（ADR-0036）

**窗口层级（D5）**：

| 关系 | 规则 |
|---|---|
| **应用内**（自上而下） | **弹窗 > 模块窗口 > 外壳**：模块窗口 `Owner = 外壳`（外壳永在其下；最小化/恢复随外壳）；弹窗 `Owner = 外壳`，打开即激活 |
| **应用整体（相对其他应用）** | **只有两种统一状态**：**普通**（默认）——任一本应用窗口被激活 → 其余本应用窗口**一并抬升**（不抢焦点、保持内部次序）；其他应用激活 → 整体下沉。**全体置顶**——应用级开关，外壳 + 模块窗口 + 弹窗**一起**最前；新开窗口与弹窗按当前状态继承 |
| **禁止** | "一部分被外部应用覆盖、一部分置顶"的**混合状态**（原"每窗口各自置顶"的设计已撤销） |
| **任务栏 / Alt+Tab** | 只出现**外壳**一项（模块窗口 `ShowInTaskbar=false`，**固定行为、不加设置项**） |
| **平台代价** | "组抬升"需少量 Win32 互操作（`SetWindowPos`，经 Avalonia `TryGetPlatformHandle()` 取 HWND）——只落在 `Ui`/`FrameworkUi`（表现层平台适配），不进 L1–L4；非 Windows 降级为不做组抬升 |

**设置弹窗结构（D6，七类）**：常规 · **模块与来源** · **窗口与交互** · 外观与显示 · **快捷键** · 日志与诊断 · 关于（左分类 + 右页面，即时生效；`★` 为本次新增/改动）。

**快捷键（D7）**：作用域 = **应用内**（外壳或任一模块窗口聚焦都生效）；动作固定枚举，绑定存 `settings.json`；设置页可**查看/修改/重置**并做**冲突即时提示**；系统级全局热键 v1 不做。

**模块来源诊断（D1）**：「模块清单」弹窗显示每个根的路径、扫到/跳过/失败计数与逐包结果，并提供「立即重扫」「打开目录」；对"本次启动后被重新构建"的包给出**需重启**提示。

| **锁定 = 钉住** | 锁定模块不入组、不随整体移动（第十一轮口径）；组内含外壳时同样排除锁定成员 |
| **平移的落盘** | 只改内存 + 记待提交（`_pendingSceneCommits`），180ms 防抖后 `CommitSceneTranslation()` 合并成一次变更；保存组合件前也先冲一次。**未落盘期间 `SyncModules`（60Hz）必须跳过这些模块**，否则会被旧布局一帧帧拉回（表现为"模块跟不动"） |

**回归网**：`SnapEngineTests`（真接触才算贴合 · 交叉轴无重叠只能算边缘 · 中心线优先于边缘 · 端口锚点优先于中心线 · 端口锚点超范围不参与 · **同坐标重复候选只保留最高级别** · 贴合容差宽于对齐 · 外壳边两向 · **外壳与模块外框同表** · 纯函数性 · 未命中 · 拼接谓词）· `SnapStabilityTests` 3 项（跳变/回跳**上界断言**，待步骤 3 收紧到 `2×吸附距离`）· `ModuleWindowsTests` 2 项（整数物理像素含 125% 下 412.5px · 整组平移组内相对偏移恒定）。

**第二轮反馈补充（"还是振荡、只左右抖" · `architecture/15` §7）**：
① **决策层已用矩阵扫描排除** —— 判据改为"**跳走又跳回**（A→B→A 且 &gt; 1px）"，扫 **1446 组 X 轴配置**（宽度差 −8…+8px、含贴壳与反向对齐、逐 1px 推进 + ±1px 抖动）**全部通过** → 转正为 `SnapStabilityTests`（3 项）；
② **真因是指针坐标的取法**（`ModuleWindow.ScreenPoint`）：原 `Position + 局部坐标 × 缩放` 的两个来源**不是同一次采样**（窗口位置是我们自己刚设进去的、局部坐标来自系统消息生成时刻），拖动中窗口每帧都在动（吸附命中还整块跳）⇒ 指针读数带上"等于窗口位移量"的误差 ⇒ **正回授**；只在拖动方向（通常左右）出现，故"上下不抖"，也与网络标签无关；
③ **修复**：新增 `Ui/Views/NativeCursor.cs`（`GetCursorPos` 取**系统光标**，屏幕物理像素，与本窗口自身位置无关），鼠标拖动/缩放**优先用它**，非 Windows / 非鼠标（触摸、笔）/ 调用失败时回退到原换算。

### 5.27 第三十四轮：**两个信息维度**与线的端点/流向（**ADR-0053** · 更新 §5.26 的信息/线/方块三行）

> 用户："**连线从角色方块中心出发**" · "**中心块太大了**……用**文本自适应宽度**" · "**不显式绘制文本框**……每一个角色块显示**其自身的信息**" ·
> "**网络标签上缺少速率显示**，这才是'**数据通路速率**'" · "**仍然没有区分两个不同的信息维度**，网络标签**不高亮**也没有做"。
> **口径**：**角色维度**（这块功能自己跑多快）⇒ **角色方块上方/周围的纯文字**（速率 / 投递·丢弃 / 类型语义，**不画文本框**）；
> **通路维度**（这条网络跑多快）⇒ **端口标记**（叠加层里显示通路速率，且标记**降权不高亮**）。
> 对 §5.26 三行的更新：**布局**（宽度随文本自适应、删除"缩方块"档）· **线**（端点 = 两个方块**中心**、绘制裁掉本端方块内部、**不写任何文字**）·
> **信息**（角色信息文字替代原信息卡）。**二次修正（用户手工实测后）**：① "网络标签不高亮" = **做减法**（标记层排到遮罩**之前**，被灰玻璃压暗），
> **删除**标记的降权样式；② **通路速率常驻**标记（"它不属于叠加层"），角色速率 = 角色自己的发送/接收（产出侧优先），
> 角色信息**左对齐 + 大字速率 + `输入 m / 输出 n` + 短类型标签**；③ **坐标系唯一事实源** = `ModuleViewViewModel.Width/Height`
> （叠加层经 `CanvasWidth/CanvasHeight` 接收），修掉"`Bounds` 比窗口小 2 DIP ⇒ 两端布局尺寸不同 ⇒ 连线错位"。
> **③ 续（单位口径，第三十四轮实测修正）**：模型几何 `X/Y/Width/Height` 是**物理像素**（`PixelPoint`，拖拽/命中都用它），
> 叠加层是 **DIP**；转换**只**发生在 `CanvasWidth/CanvasHeight`（= 尺寸 ÷ `Scale`）与 `ToDip(...)` 两处，**别处一律不做换算**。
> ④ **虚线"平滑后突然跳一下"**：相位原先按 `dash+gap`（DIP）取模，而 `DashStyle.Offset` 的单位是**笔宽倍数** ⇒ 真实周期 =
> `(6+4) × 线宽 = 25 DIP`；改按真实周期取模 + **60 Hz 时间相位**（`OverlayAnimationClock`，`Phase = f(秒)`）后消失
> （像素级判据：走满一个周期的画面与零相位**逐像素相同**）。
> ⑤ **虚线衔接处颜色反了**：渐变原先跟着**绘制方向**走 ⇒ 改为 `GradientEnds(start, end, localIsSend)` 把**本端方向色锚在方块那一端**
> （与绘制顺序无关），两端公共边颜色因此**恰好相接**（ADR-0045 D4 的本意）。
> 详见 **ADR-0053**（含 §5 二次修正）与 `architecture/18` §8.14/§8.15。
