## 7.1 Gate B（实现机制）逐条处置

| Gate B 项 | 处置 | 依据 |
|---|---|---|
| 线程·调度·队列实现（**背压 v1 不做**） | ✅ **关闭**：每模块线程 + 有界输入队列 + 丢旧默认；**背压不做**（与"绝不阻塞上游"互斥，ADR-0029 C4-1） | ADR-0029 |
| 复制共享 / 零拷贝 | ✅ **关闭**：扁平定长缓冲 + 池化 + 所有权移交；访问层加载期特化 | ADR-0029 Q4-2 |
| 批量优化 | ➡️ **转 R 项**（实现期按实测决定，含批量投递） | `04` §4.2 |
| ID 格式 | ✅ **关闭**：结构化三元组（作者命名空间 / 模块名 / 版本） | ADR-0028 Q3-5 |
| 契约语言语法 | ✅ **关闭**：C# 类型即契约，成员限定长原语 + 结构组合 | ADR-0028 Q3-2/C3-5 |
| 契约提示性标注（PQ-IF-11） | ➡️ **转 R 项**：作为契约声明的可选标注（传递语义之外的提示性信息），实现期细化，不影响兼容判定 | `03` §3.4 |
| 配置 Schema 语言 | ✅ **关闭**：C# 类型 + 源生成 + 未知字段片段保留 | ADR-0028 Q3-4/C3-3 |
| 组合件文件具体格式 | ✅ **关闭**：文本 JSON + `schemaVersion` + 原子写 | ADR-0029 R4-5/R4-6 |
| 模块包物理形式（§11.2） | ➡️ **转 R 项**：包 = manifest + 实现绑定 + 可选资源（结构已定）；**物理容器（目录/压缩包）实现期定** | ADR-0028/ADR-0020 |
| 进程·隔离模型 / Assembly·DLL / IPC | ⏸️ **留 Gate D**：v1 同进程 + `AssemblyLoadContext` 加载；进程级隔离不在 v1 | ADR-0026/0029 |
| 脚本引擎与执行权 | ✅ **关闭**：v1 不引入脚本 | ADR-0028 Q3-6 |
| View/ViewModel 模式 | ➡️ **部分关闭**：模块侧无 View（框架按声明渲染）；**`Ui`/`FrameworkUi` 内部的 MVVM 用法属实现约定**（转 R 项） | ADR-0031 |
| UI 自动化测试 | ✅ **关闭**：v1 不做（留 Gate） | ADR-0032 Q6-3 |
| L5 性能监视 | ⏸️ **留 Gate D** | §13.2 |
| 表现层解耦机制细节 | ✅ **关闭**：`Ui` 只引 `Sdk` + `Core.Api`；UI 不调用模块代码 | ADR-0026/0031 |
| 风暴护栏实现 | ✅ **关闭**：不做限流/环检测；护栏 = 安全（静默）+ 提示（轻量） | ADR-0029 C4-1 |
| 数值指标（刷新率/延迟/内存/吞吐/连续运行） | ✅ **已实测回写（M1-13）**：19 项基准实测完成，数值落在 `04a` **§5.1**，量级小结见主文档 §13.2；**只记录、不设阈值** | ADR-0029 裁决 |
| 停止超时 / 队列容量默认值 | ✅ **已实测回写（M1-13 + M1-7）**：归属已定（应用级设置）；数值保持设计默认（停止超时 5 s、队列容量 1024）——实测显示二者都不是瓶颈（持续 10⁶ 单元下单元耗时 49–50 ns、最长 GC 暂停 ≤0.9 ms），故**不改默认值** | ADR-0030；`04a` §5.1 |
| **实测暴露的两项偏差**（M1-13 新增） | ✅ **已裁决（M1-13 收尾）**：① 空闲唤醒粒度 → **参考模块改用被动接收（已实施）+ `WaitForData` 列入后续里程碑的 SDK 兼容扩展**；② 每单元 40 B 分配 → **池化包装对象列入后续里程碑首项**（不动 SDK 面）。两项推导见 `04a` §5.2 | `04a` §5.2 |

## 7.2 Gate C（UX 原型）处置与时点

| 项 | 处置 |
|---|---|
| 时点（推荐） | **M1（框架最小闭环）完成之后、M2（UI 完整化）之前**做一次 UX 原型 |
| 理由 | ①数据面机制是最大技术与性能风险，应先闭环验证；②Gate C 的形态细节不改变数据面设计；③M1 之后已有可运行系统，原型可直接站在真实数据上做，避免"原型与实现两张皮" |
| 原型范围 | 模块视图视觉形态与尺寸族具体参数 · 吸附容差与拖动手感 · 拼接/整体拖动/快捷键交互 · 网络标签块形态 · 信息类层（连线/标记/诊断）呈现 · 窗口与整体布局 · 配置界面形态（按 Schema 生成的具体样式） · 分组框/多页面等可选 UX 元素 |
| 不属 Gate C | 层分类与职责、模块视图与信息层的归属、拼接语义、快捷键可配置性（均已在第 5 章冻结） |

## 7.3 Gate D（后续阶段）逐项处置

| Gate D 项 | 处置（推荐） | 理由 |
|---|---|---|
| **会话快照**（崩溃/退出恢复现场） | **预留**（低成本接口位：与组合件并列的独立机制） | 用户价值明确（调试现场易丢），预留成本极低 |
| **模块版本迁移路径**（旧版本实例 → 新 Definition） | **预留**（ID 三元组已含版本；加载期保留"迁移钩子"位置） | 多版本共存已冻结（§11.2），迁移是自然延伸 |
| 组合件递归嵌套（组合含组合） | **明确不预留**（v1 不做；未来若做属增量特性） | 会显著复杂化组合件格式与加载流程，且 v1 无需求 |
| 录波 / 回放 | **明确不预留**（可由普通内容模块实现） | 属模块能力，框架无需预留 |
| 沙箱（进程级隔离） | **明确不预留**（保留 Gate） | 与 §12 轻量透明模型一致；未来若需要属架构级变更 |
| 跨平台是否为硬性要求 | **明确不预留**（Windows 优先；Avalonia 天然跨平台但不为它牺牲性能） | ADR-0023 §8 |
| L5 性能监视 | **明确不预留**（未来按需加信息层/面板） | 已有 L1–L4 覆盖排障主力 |

**预留原则**：只预留**成本极低且会改变接口形态**的项；其余明确不做，避免"为想象的未来付费"。

## 7.5 v1 首个里程碑（M1）与开发推进方式

### 推进方式（推荐）：**垂直切片**

先打通**一条最小完整链路**，而不是按层横向做完（先把 Registry 做全、再做数据面……）。

理由：①最早暴露端到端风险（装配链、加载、建网、投递、显示）；②符合纪律 C2「只有最小可验证形态才算可验证」；③每完成一片都有可运行系统，便于用户随时手工验证。

### M1 = 最小可运行闭环

```text
M1 目标：一条链路从"模块包 → 实例 → 网络 → 数据投递 → 界面显示"完整跑通
```

| 步 | 内容 | 产出 |
|---|---|---|
| M1-1 | 建立项目骨架（第 2 章 9 项目 + 模块目录 + 测试项目） | 可构建的空骨架；架构规则集生效 |
| M1-2 | `Sdk` 最小面：声明特性 + 模块接口 + 六个钩子 + 上报 API + 契约与配置声明 | 可写模块 |
| M1-3 | `Hosting`：模块包加载（显式路径）→ 注册 → 实例化 → 生命周期状态机 | 能"加入并运行"一个模块 |
| M1-4 | `DataPlane`：每模块线程 + 输入队列 + 绑定对象 + 扁平缓冲投递 + 丢旧 | 模块间能收数据 |
| M1-5 | `Core` + `Core.Api`：ChangeSet（Prepare/Commit）+ 手工建网 + 保存/加载（原子写 + 片段保留） | 可建网、可保存加载 |
| M1-6 | `Ui` 最小：工作区层 + 模块视图（数值 + 曲线元素）+ 连线层（显示/隐藏） | 用户能看到数据 |
| M1-7 | `FrameworkUi` 最小：模块清单 + Issue 面板 | 能看到加载与问题 |
| M1-8 | 参考桩模块三个（DataGenerator / Recorder / Asserter）+ T1 判据测试 | **AC-1/2/3/4/5/6 自动化通过**（纸面 → 实证） |
| M1-9 | `Benchmarks` 首轮实测（`04a` §5 清单） | 数值指标回写 |

**M1 验收标准**：① 门禁全绿（构建 + 许可 + 测试 + 架构规则）；② T1 的 AC-1~6 全通过；③ **用户手工验证**：能加载模块、拼接、建网、看到数据流动与曲线、保存并重新加载组合件；④ 首轮性能数值回写文档。

### 后续里程碑（概要）

| 里程碑 | 内容 |
|---|---|
| M2 | Gate C UX 原型 → 18 元素 + 4 容器完整渲染 · 拼接/拖动/快捷键 · 网络标签块 · 三层信息类层 · 配置界面按 Schema 生成 · 设置界面 · 诊断面板 |
| M3 | 首批真实业务模块（Gate E）+ v1 产品验收场景 |
| M4 | 打磨与稳定性：连续运行观察、诊断提示调优、文档与手工验收清单定稿 |
