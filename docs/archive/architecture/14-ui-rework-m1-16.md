## 0. 先说三条事实（含代码证据）

| # | 结论 | 证据 |

## 1. 需求 → 设计：外层主窗口（用户需求 1）

### 1.1 形态：**工具条 → VSCode 式侧边栏**
| 项 | 现状（事实） | 目标 |
|---|---|---|
| 外壳 | `FrameworkUi/MainWindow.axaml`：`Menu` + 一条工具栏 + 状态栏，`SizeToContent=Height`、`CanResize=False`、**没有主体区域** | **主窗口有真实主体**：左侧**活动栏 A**（竖向图标按钮，约 44 px）+ 右侧**侧边界面 B**（竖向排列的内容区）；状态栏保留在最底 |
| 顶部菜单 | 文件/视图/窗口/帮助 四条 `Menu` | **删除**；全部改为 A 区图标入口 + B 区页面，或弹窗 |
| 模块清单 / 交互 | 弹窗（`ModuleCatalogView`） | **改为 B 区常驻页面**（竖向列表 + 缩略图预览位） |
| 设置 / 诊断 / 帮助 | 弹窗 | **保持弹窗**（`DialogWindow`） |
| 窗口比例 | 980 × 自适应高 | **手机竖屏常用比例**：`9:19.5` → 默认 **396 × 858**（可缩放，最小 360×640）；**比例本身做成可改的常量**，将来换比例只改一处 |
| 观感 | 平面、单色 | VSCode 风：A 区深一档底色、B 区页面留白与分组标题、选中项用**可变色滑块**（Fluent `ListBoxItem`/`ToggleButton` 定制）；按钮用系统风（Fluent 默认 + 统一高度） |

**A 区图标入口（拟）**：模块清单 · 现场（组合件）· 交互（吸附/对齐开关）· 拓扑 · Issue（带计数徽标）· 设置 · 帮助 · 关于。（图标族见 §4.3；先用 Fluent 内置符号字体，不引第三方图标包以免触碰许可白名单。）

### 1.2 模块清单：缩略图预览
- 每行 = **缩略图占位**（约 96×54，`Border` + 图标 + "预览待补"字样）+ 名称 + 版本 + 来源 + 「加入现场」。
- **缩略图 = 模块呈现的一部分**（用户口径）：本批只留**占位符**与数据位置（`ModuleCatalogEntryView.ThumbnailPath`），你后续截图后放进包内 `preview.png` 即可自动显示（模块包清单 `module.json` 增加可选字段）。
- 影响：`Core.Api` 模块目录视图 + `module.json` 清单（**兼容扩展**，缺字段即无图）。

### 1.3 设置弹窗（贴合内容 + VSCode 风）
- 现状问题：弹窗固定 `460×420`、内容溢出；左分类字体偏大（`FontSize=12` + `TabItem` 默认字号）。
- 目标：**按内容测量尺寸**（`SizeToContent=WidthAndHeight` + `MaxWidth/MaxHeight` 上限 + 内容区滚动）；左分类宽度固定 132 px、字号 12、条目高 28；右页面留白 12、分组标题 11 半粗、字段行高 27。
- `SettingsView.axaml` 是 `UserControl`，尺寸由宿主 `DialogWindow` 决定 → 改为按宿主内容自适应（每个弹窗给 `Width/Height` 缺省值，仍可手动拉）。**弹窗尺寸不匹配问题**对所有四个弹窗统一处理。

### 1.4 主题色与背景（新设置项）
- 现状：`Ui/Styles/Tokens.axaml` 已有 **Light/Dark 两套角色 token**（`BgModule`/`BgChrome`/`AccentPrimary`…），主题切换机制已具备（V2），但**没有设置入口**。
- 目标（设置 → 外观与显示）：**主题（浅色/深色/跟随系统）· 主题色（8 个预设 + 自定义取色）· 背景（纯色 4 档 / 跟随主题）**。
- 机制：应用级设置新增 `theme` / `accentColor` / `backgroundColor`（**兼容扩展**）；启动与变更时**替换 token 值**（`Resources` 覆盖 `AccentPrimary`/`BgWorkspace` 等），**模块窗口与弹窗一并跟随**（§2.7）。

### 1.5 吸附参照：**只允许吸附到右侧边**
- 现状：吸附候选 = 其他模块窗口 + **屏幕工作区（四边）** + 外壳矩形（左右上下皆可）。
- 目标：**只保留"贴到右侧"**——即模块的**左边**吸附到**外壳/其他模块的右边缘**（拼图向右展开）；屏幕工作区左/上/下边与"中心对齐"是否保留**待裁决（D-2）**。

## 2. 需求 → 设计：模块总体风格（用户需求 2）

### 2.1 窗口结构：**边框覆盖整个窗口，无标题栏**
| 项 | 目标 |
|---|---|
| 身份行 | **删除**（模块名不显示）；由此**整块窗口矩形 = 模块矩形**，与 `DockRule.MarkerCenter` 的几何基准**完全一致**（顺带消掉一处潜在偏移） |
| 运行指示 | 移到**左下角**（状态点 + 状态文本，10 px 弱化色） |
| 按钮簇 | 移到**右上角**、**仅图标**（锁定/解锁 · 隐藏/显示 · 停止/运行 · 关闭），悬停或选中时淡入；命中区仍为 12×12 热区 |
| 选中/取消选中 | 点模块边框带 → 选中；**点外壳或桌面（本应用其他窗口）→ 取消选中**（现状：无法取消）；锁定态不可选中 |
| 边框 | 1 px 主题色边框贯穿整个窗口周界；选中态主色加粗（1→2 px 或加外发光，取值见 §4.3） |

### 2.2 网络标签（端口标记）：加长 50% + 显示信息类型 + 固定槽位
| 项 | 目标（取值） |
|---|---|
| 尺寸 | 左右边缘 **20×114**（原 20×76，**长度 +50%**）；上下边缘 **114×20** |
| **贴边** | 标记与外边框**完全重合**：去掉 `EdgeInset=1`，标记外沿 = 窗口边框 |
| 槽位 | **四段固定宽度**（名称 / 类型 / 方向箭头 / 速率+状态灯），每段预留固定宽度、**数值右对齐并固定小数位**，无数据时显示 `---` → **信息变化不再引起排版抖动** |
| **信息类型** | **新增**：`Core.Api.PortView` 增加 `ContractText`（如 `f32`、`u64`、`struct{seq:u64, value:f32}`、`f32[8]`、`enum`），由 `ContractShape` 渲染（新增 `ContractShape.Describe()`）；标记上以 10 px 显示，过长省略中间 |
| 箭头 | **按边取向外/向内**：发送口（右边缘）= **向外**（→ 指向模块外）；接收口（左边缘）= **向内**（→ 指向模块内）；竖排时随旋转变换 |
| 字体 | 名称/类型/速率 **10 → 11 px**（你反馈"小了"） |
| 颜色 | 保持语义色，但增加**层次**：标记底 `BgChrome`，类型用 `TextSecondary`，速率 `TextMuted`，方向箭头 发送=主色、接收=次色，状态灯语义色 |

### 2.3 「口上标记」→「**叠加信息层**」
- **标记本身常显**（它是模块标准件，不再有开关）；**开关改为控制叠加信息层**（设置 + A 区/工具栏）。
- 叠加层内容（绘制在模块窗口**内容之上、按钮簇之下**）：
  1. **连接线**：从每个已连接端口标记出发，向**对端模块所在方向**画线 → 若模块已拼接（接触），线在公共边处**自然相连**，无需跨窗口覆盖层（沿用 ADR-0034 的"不做跨窗口长连线"结论，且**不需要新的透明覆盖窗**）；
  2. **流向**：线上带箭头 + 沿方向的高亮移动（克制动效，0.8 s 周期，可关）；
  3. **详细信息**：线端小标签（对端 `模块名.口名` + 速率 + 累计量）；未拼接时线只画到本窗口边缘并给出"→ 对端名（未拼接）"提示。
- 分层：`ConnectionOverlay`（新控件，`src/Ui/Controls/`），`IsHitTestVisible=False`，`ShowInfoOverlay` 为应用级设置（**替代** `showPortMarkers` 的语义；旧键兼容读取）。
- **"口上标记"在设置中的旧文案与开关保留兼容**（旧键读取），新文案为「叠加信息层」。

### 2.4 缩放手柄
- 角点/边中点手柄 **12×12 → 6×6**（缩小 50%）。
- **与标记的冲突处置（重要）**：手柄仅要求"置顶"会重新盖住标记中点（就是 F2 的缺陷）→ 设计为：**手柄只在窗口被选中（或悬停）时可命中**（未选中时 `IsHitTestVisible=False`），选中时置顶、以 6×6 小方块显示。这样"置顶"与"标记可点"不再互斥。

### 2.5 颜色
- 保持工程工具风，增加**层级色阶**（Fluent 已有）：A 区最深 → 标题/工具区次之 → 内容底最浅（或反之，深色主题镜像）；语义色只用于状态，不铺面积。
- 模块窗口底色可随主题色**极轻**偏移（如主色的 3% 混入），避免"一片灰"。

### 2.6 模块视图渲染（与需求 3 共用）
- 现有渲染子集：A1 数值 · A3 曲线 · A5 文本日志 · B1 配置表单；其余为"未渲染"占位。
- 本批**新增渲染**：**B2 命令按钮** · **B5 文本输入** · **A11 枚举选择**（已有实现）→ 见 §3。
- 控件统一高度 token：**`ControlHeight = 27`**（§4.3），字号 12，行距 4。

### 2.7 主题跟随
- 模块窗口、弹窗、叠加层**全部走同一套 token**（`Ui/Styles/Tokens.axaml`）；设置变更 → 立刻生效（`Resources` 覆盖 + `DynamicResource` 自动刷新）。

## 3. 需求 → 设计：模块功能精修（用户需求 3）

### 3.1 发送器视图重排（自上而下）
```
① 必要信息（紧凑，两列：待发送值 / 已发送 · 被丢弃）
② 文本输入框 [ 值 ]  +  [ 发送 ] 按钮
③ [ 自动发送 ] 开关滑块  +  周期 [ 200 ] ms 输入框
④ （可选）发送设置（其余配置项，折叠）
```

### 3.2 这需要**新增 SDK 面**（这就是已登记的开放项）
| 通道 | 现状 | 需要的 SDK 面 |
|---|---|---|
| **B5 文本输入** | `ViewElementKind.TextInput`（=12）**已声明但无执行通道**；框架不渲染、值无处可写 | `ViewElement` 增加"输入元素"承载：框架把输入值**按声明的写入路径**交给模块（模块线程）；配 `ViewDataSourceKind.Text` 的**双向**写入面（`IModuleContext` 或视图回调） |
| **B2 命令按钮** | `CommandButton`（=9）已声明但无执行通道 | 模块声明**命令**（名字 + 标题 + 图标 + 快捷键）→ 框架渲染按钮 → 触发时**投递到模块线程**执行（不阻塞 UI、不跨线程直接调模块） |
| **A10 开关滑块** | `ToggleSlider`（=10）已声明但无执行通道 | 与 B5 同一写入面（布尔/数值写入），或先由**配置写入**承担（一次性） |

> **命名与语义**（草案）：
> - `ViewElementKind.TextInput`：`ViewElement(TextInput, source: "input", title: "发送值")`，框架渲染 `TextBox`，**输入即写入**（去抖 150 ms）或**回车/失焦写入**（D-5）；
> - 命令：`ViewDeclaration.Commands = [ new ViewCommand("send", "发送", ViewCommandIcon.Play) ]`，模块实现 `IModule.OnCommand(string name)`；
> - 两者**都在模块线程上执行**（沿用既有"命令/输入必须在模块线程"约束，`04` §4.1），失败转 Issue。
> - **发送器改造**：`Value` 从配置改为**文本输入**（一次性写入 `_pendingValue`），`发送` = 命令，`自动发送` = 布尔 + `周期` = 数值。

### 3.3 控件高度
- 所有输入类控件统一 **高 27 px**、字号 12、圆角 3（`TextBox`/`ComboBox`/`Button`），由 `Tokens.axaml` 定义并在 `ModuleWindow`/`ConfigurationFormView`/`MainWindow` 统一应用（样式选择器 `TextBox { Height }` 之类，**用控件主题样式**，不在每处写死）。

## 4. 需要你裁决的点（**已裁决 · 结果见 §9**；此处保留原始提问以便追溯）

| # | 问题 | 我的建议 |
|---|---|---|
| **D-1** | 手机比例的**具体值**与是否可缩放 | 取 **9:19.5**，默认 **396×858**，允许缩放（最小 360×640）；常量集中在 `ShellLayout` 一处，将来换比例只改一行 |

| **D-3** | 缩放手柄"置顶"与"标记可点"的冲突 | 建议：**手柄仅在选中/悬停时可命中**（未选中时透明不可点），选中时置于最上、6×6；这样两者不互斥 |
| **D-4** | 叠加信息层：未拼接时怎么画 | 建议：线只画到本窗口边缘 + 标注"→ 对端名（未拼接）"；**不做跨窗口覆盖窗**（沿用 ADR-0034） |
| **D-5** | 文本输入的写入时机 | 建议：**回车/失焦写入**（可控、不刷爆运行时）；不做逐字符写入 |
| **D-6** | 主题色的形式 | 建议：**8 个预设色 + 取色器**；背景 = 纯色 4 档（跟随主题/浅灰/深灰/自定义）；**不引入图片背景**（v1） |
| **D-7** | 命令按钮是否要快捷键 | 建议：模块命令**不进**应用级快捷键系统（v1），只在窗口内点击；若你要，我按 `HotkeyCatalog` 扩展（成本小） |
| **D-8** | 侧边栏 A 区的图标来源 | 建议：**Fluent 内置符号字形**（`SymbolIcon`/`PathIcon`，无新依赖）；若你要统一风格图标集，需要引入图标包（**触碰许可白名单，须单独立项**） |
| **D-9** | 是否加入无头 UI 自动化兜底（你已原则同意"容易就加"） | **加最小集**：布局与命中测试**不需要模拟输入**——断言①标记被排布在窗口内且可见、②标记是自身中心点的**最上层命中目标**、③「叠加信息层」开关真的改变可见性。**输入模拟**（双击→弹窗→提交）也可做，但成本更高，**建议本批先不做**，看本批是否再出同类缺陷 |

### 9.1 新增缺陷单（D-2 派生）：**模块无法吸附到外壳**

- **现象**（用户实测）：模块之间吸附正常，**但无法吸附到主窗口**（拼图起始点）。
- **代码事实**：吸附候选**已包含**外壳矩形（`ModuleWindowsViewModel.CollectSnapTargets`：`ShellRect` + `WorkArea`），`ModuleWindowManager.PublishShellRect()` 在管理线程启动、外壳 `PositionChanged`/`SizeChanged` 时发布 → **引擎侧具备能力**。
- **待核实的候选原因（B4 批必须定位到唯一原因，不许"改到看起来能吸"就收）**：
  1. **外壳形状**：现外壳是"一条工具条"（高 ~90 px），模块要吸它的右边缘必须与它**同一高度带**才看得见参照 —— 新形态（侧边栏主窗口）会显著改变这一点；
  2. **拖动发现性**：拖动只能靠 **6 px 边框带**（内容区不响应）→ 用户可能根本没成功拖动过（与"标记看不见"同一类问题）；B1 的"边框覆盖整个窗口"会一并改善；
  3. **`ShellRect` 时序**：`PublishShellRect` 在 `Show()` 之前可能发布 `Bounds=(0,0)` 的矩形，若此后没有 `PositionChanged`/`SizeChanged`（窗口尺寸不变）→ 一直用 0 尺寸矩形（`IsValid` 为假或退化）→ 吸附永不命中。
- **处置**：B4 先加**可断言的无头测试**（给定 `ShellRect` 与拖动轨迹 → 断言吸附命中外壳右边缘），再修。
- **附带**：`WorkArea` 随 D-2 **退出吸附候选**（仍用于默认摆放位置的钳制与"打开时不出屏"）。

| 1 | **同一个开关出现两处，且两处不联动**（设置页与主界面各有一个"显示叠加信息/窗口置顶"，改一个另一个不动——**死开关**的变种：开关在但没接线） | `SettingsPanelViewModel` 增加 **`Owner`（= `ShellViewModel`）**，`ShowInfoOverlay`/`AppTopmost` 改为**委托外壳的实时属性**（不再各自持有字段）；任一入口切换即调用 `PersistLiveSwitches()` 落盘 → 两处**同一状态源**，永远同步 |
| 2 | **颜色选择太原始**（只有一行预设按钮，无法自由取色） | 强调色/背景色改为**色片按钮 + `Flyout` 取色面板**：上排预设色块（`WrapPanel`），下排 **十六进制输入框**（可填 `#RRGGBB`）；选色立即写主题字典并落盘 |
| 3 | **锁定应有两层含义**：① 锁定后不允许用户拖动；② **锁定 = 不再跟随壳体移动**（现行实现里锁定的模块仍被"随壳移动"拖走） | `ModuleWindowsViewModel.BeginDrag` 把锁定成员**排除出 `_dragGroup`**（拖一个锁定模块不再带动别人，别人也不带动它）；新增 **`FollowShellMove(dx,dy)`**：以"**锚定**"判定（`|模块.Left − 壳体.Right| ≤ 2` 且竖向有重叠）找出贴壳的模块，整体平移**平铺组**（同样排除锁定），最后经 `UpdateModuleLayouts` 落盘 |

| 5 | **模块应有自己的默认尺寸**，不该总用 320×220 | SDK `ViewDeclaration` 新增 **`PreferredWidth`/`PreferredHeight`（`init` 属性）**；`ModuleViewViewModel.PreferredWidth/Height` + `HasPreferredSize`（声明了用声明值，否则回退 `DefaultWidth/Height` 320×220）；参考模块给出**声明值**：`ManualSender` **330×330**、`Monitor` **360×460** |

### 15.1 一处必须记下的技术教训（**已登记为 P30 / LESSONS 17**）

第 5 条我最初把 `PreferredWidth/PreferredHeight` 做成**构造器可选参数**，语义上"只增不改"，实则**方法签名变了**：已编译的模块各自带一份 SDK 副本，加载时抛
`MissingMethodException: Method not found: 'Void ViewDeclaration..ctor(IReadOnlyList<ViewElement>, IReadOnlyList<ViewDataSource>, IReadOnlyList<ViewCommand>)'`，
5 个参考模块中**未重编的 3 个当场失败**（`Tests.Reference` 10 项红）。**改为 `init` 属性后重编全部 5 个模块 → 30/30 绿**。
结论：**SDK 的"只增不改"要看签名，不看语义**；新增可选声明一律用 `init` 属性，改 SDK 后必须重编全部模块。

### 15.2 另一处（**P16 同源**）

`ModuleContext.ResetConfiguration()` 最初实现为 `Clear()`，结果"按登记对象生成"的配置表单**变成空表单**（`Sequence contains no matching element`）。
正确语义：**还原 = 替换为同类型的新默认实例**，而不是清空。（"清空 ≠ 还原"，已登记为 LESSONS 18。）
