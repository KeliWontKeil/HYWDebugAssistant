## 0. 先回答"我想到的实现方式"（三处"解析"，逐一对照）

用户第十九轮问："我认为这并不违反规定，**除非你想到的实现方式不是如此**。" —— **如实回答：有一处确实不是。**

| # | "解析"发生在哪 | 是否允许（按你的规则） | **现状** | 需要的改动 |
|---|---|---|---|---|
| ① | **声明期读取**：注册/销毁时读模块提供的元数据（端口、契约、类型、视图、能力） | **允许且必须** —— 转发/建网/兼容判定全靠它 | ✅ 符合：`TryRegister(definition)` 一次登记；实例化时 `OnRegistered → DeclarePort` 读一次；运行期不重读 | 无 |
| ② | **传输期解析数据流**：为了转发/建网去读包里的内容 | **不允许** | ✅ **符合，而且比你想的更强**：`ModuleRuntime.Deliver` 按**绑定**（声明派生）投递**裸字节**，**只校验长度**（`payload.Length < binding.Layout.SizeInBytes`）；数据包**不带标签、不自描述** ⇒ **框架连"包里是什么"都不读** | 无 |
| ③ | **呈现期解码**：把样本字节变成"可显示的值"（数值/曲线/日志） | **应归模块** | ❌ **不符合**：框架侧 `Core/Views/SubscriptionBuffer` 保存最近样本，`RuntimeSubscriptionSourceView` 暴露 `ValueType`（`ContractPrimitive`）+ `SampleSizeInBytes`，**UI 侧 `Ui/Runtime/SampleCodec` 按原语自行解码** ⇒ **框架在运行期解析了数据流**（虽只用于显示） | **一处改造**：**解码器随类型注册由模块提供，框架只回调**（见 §3.3） |

> **结论**：你的规则本身**成立且自洽**，② 处框架做得比你要求的还干净（转发与建网**不需要**读数据包标签：它们用的是**声明**）。
> 唯一不合规的是 ③：**"谁的数据谁解析"** —— 把解码器从框架内建改为**模块注册**，规则就完全成立，且不影响"框架按声明渲染视图"这条已冻结结论（ADR-0026/0028）。

**顺带回答"不解析标签就无法转发/建网？"**：在当前模型里**不成立** ——
转发 = 按**绑定**投递；建网 = 按**端口契约 + 几何**判定；两者都只用**声明**。
**若你希望数据包自描述**（异构流、运行期类型校验），那是一个**独立选择**（有每包开销或旁路标签的代价），且更符合分层的做法是：**让模块在自己的契约里自描述**（现有参考模块的 `{seq:u64, value:f32}` 就是这个模式）—— 框架仍然零解析。→ 决策 **D4**。

## 1. 层表（管什么 / 不管什么 / 必须携带 / 谁声明 / 谁校验 / 允许的解析）

| 层 | 管什么 | **不管什么** | **必须携带** | 谁声明 | 谁校验 | 允许的"解析" |
|---|---|---|---|---|---|---|
| **传输 / 数据面** | 能不能传：**尺寸完备性** + 投递 + 顺序 + 背压 + 丢弃计数 + 缓冲 | 数据"是什么"（单位/量程/精度/语义/解析方式） | **类型标识 + 版本 + 尺寸（定长或上限）+ 传输语义（`Stream/Message/Event`，已有）+ 兼容声明** | 模块（端口引用类型） | 框架**机械校验**：长度/尺寸合法、兼容关系成立 | **只有 ①②**（声明期读取 + 长度校验）；**不解析内容** |
| **应用 / 模块语义** | 数据是什么、怎么解析、单位、量程、精度、建议采样率、阈值、显示格式 | 传输细节（队列/背压/时序实现） | **语义元数据 + 解码器** | 模块 | **模块自己**（框架不解释） | 由模块执行（框架只回调，**不内建**） |
| **呈现 / 框架 UI** | 通用信息：拓扑 · 连接 · **数据角色** · 传输级指标（投递/丢弃/速率/延迟/队列） · 错误 | 应用语义（不解释单位含义、不做业务解析） | —— | 框架（由传输面 + 拓扑派生） | 框架 | 只读**框架自己拥有的**数据（计数、绑定、几何） |
| **模块自身 UI**（按声明渲染） | 该模块要让用户看的业务内容（数值/曲线/日志 + 单位） | —— | 视图声明（元素 + 数据源 + 原语/类型 + **单位**） | 模块 | 框架"照声明画"，值由**模块解码器**产出 | 调用模块注册的解码器（**框架不理解结构**） |

**两条纪律**（建议写进主文档）：
1. **框架永不内建业务解析器**；需要解析时一律"**模块注册解码器、框架回调**"。
2. **声明只在注册/实例化时读一次**（注册 = 登记；销毁 = 注销）；运行期不重读（热重载除外，按既有"重扫/需重启"规则）。

## 3. 数据类型的携带、注册与解析

### 3.1 由谁携带：**模块声明并注册，框架只持机械镜像**（已同意）

```
模块侧：类型定义 = 标识 + 版本 + 尺寸（定长或上限）+ 传输语义 + 语义元数据 + 解码器
             ↓ 注册（声明期一次）
框架侧：类型注册表条目 = 标识 + 版本 + 尺寸 + 传输语义 + 兼容声明      ← 只做机械判定，不解释语义
```

**可扩展性**（你要的）：模块 A 定义 `hyw.encoder.pulse`，模块 B 要用 → **引用同一标识**（从注册表解析），而不是各写一份结构。这正是现在缺的（端口只内联结构 ⇒ 没有跨模块类型身份 ⇒ UI 色板/图例/检索都无从谈起）。

### 3.2 为什么框架**必须**知道"尺寸"（对你方案的必要修正）

数据面是**零拷贝按偏移切片**、队列按字节计数、订阅缓冲按样本大小开槽、UI 显示"估算字节"。
⇒ **不知道尺寸就传不了**。所以：**尺寸属传输层，语义不属传输层**。

### 3.3 解析边界（本文件的核心条款）

| 事项 | 归属 | 说明 |
|---|---|---|
| 长度校验 | 框架（传输层） | `payload.Length >= layout.SizeInBytes` |
| 字段偏移 | **模块**（或其 SDK 读取助手） | `PayloadBuffer` 由模块在自己的线程上使用 |
| 解码成"可显示值" | **模块**（注册的解码器） | 框架把样本字节交给解码器，取回显示值/序列；**框架不知道结构** |
| 曲线/数值/日志的绘制 | 框架（呈现层） | 只画解码器给的**通用值**（标量/序列）+ 模块声明的**单位/标签** |

**唯一改造点**：`Ui/Runtime/SampleCodec`（框架内建解码）→ **降级为"参考实现/模块侧工具"**；框架通用路径改为"**调用模块注册的解码器**"。

### 3.4 兼容判据升级为三层（并把"框架无资格判语义兼容"写死）

| 情形 | 判定 |
|---|---|
| 同标识 + 同版本 | **兼容** |
| 同标识 + 不同版本 | **不兼容**（版本升级按破坏性变更处理）〔**ADR-0051 作废**原「尾部增字段 = 兼容」〕 |
| **不同标识 + 结构相同** | 框架**无资格**判定"是否同一种量"（不懂单位量纲）⇒ **默认不兼容 + 用户显式确认后可强连** |

### 3.5 计量口径（速率与计数）——【用户第二十轮提出，新增】

**问题**（用户）：自描述字段放在模块自己的契约里之后，**"实际数据传输速率"会不会不等于"框架传输速率"？是否需要显式计算？**

**回答：需要，而且现状不止"速率不一致"，还有两处记账口径歧义。**（代码证据见下表"现状"列）

| # | 口径差 | 说明 | 现状 |
|---|---|---|---|
| ① | **多播放大** | 一个单元投递给 N 个宿会**各记一次投递** ⇒ "投递单元数"其实是"**按宿计的投递次数**"，不是模块的发送次数 | `ModuleRuntime.Deliver`：`foreach target → RecordDelivered()` |
| ② | **停流被记成"丢弃"** | `IsSuspended / IsStalled / 载荷过短 / 无承载 / 队列满` **全部**走 `RecordDropped()` ⇒ 三种性质完全不同的事混在一个数里（正常停流未投递 / 传输丢弃 / 非法载荷），界面上看起来像故障 | 同上（`Deliver` 第 781–792 行） |
| ③ | **自描述与对齐开销** | 契约尺寸含 `seq:u64` 这类**自描述字段**与对齐填充 ⇒ `单元数 × 契约尺寸` = **搬运字节**，大于**业务字节** | 参考模块契约 `{seq:u64, value:f32}` = 12 B（业务 4 B） |
| ④ | **单元 ≠ 样本** | 批量投递 / 多通道（D7、`16` Q5）下，单元速率 × 尺寸 ≠ 样本速率 | 未支持批量 ⇒ 现在恰好相等，一旦支持就不等 |
| ⑤ | **模块内部丢弃不进账** | 模块自己的降采样/覆盖（如显示器"覆盖旧值"）属**另一套计数**（`Publish` 数据源口径 `Written/Overwritten/Dropped`），与网络口径不合并 | `SubscriptionSourceView`（两套计数并存，UI 只用了网络那套） |
| ⑥ | **速率是差分估算** | UI 用"两次刷新之间的字节差 ÷ 间隔"估算（`_rateSamples`），**没有时间戳** ⇒ 精度受刷新节奏影响，且不是"测量" | `ModuleWindowsViewModel.RefreshMarkerStatus` |

**做法（补充设计）：分量 + 明确口径，全部"声明驱动、框架机械计算、零解析"**

类型/端口声明新增**计量块**（全部可选，且都有**明确定义的缺省**）：

| 字段 | 含义 | 缺省 |
|---|---|---|
| `PayloadSizeInBytes` | 该单元中"业务数据"的字节数（不含自描述字段与对齐填充） | = 契约尺寸 |
| `SamplesPerUnit` | 一个单元含几个样本（批量） | 1 |
| `ChannelCount` | 通道数（与 `16` Q5 的数组语义合并，避免两处定义） | 1 |
| `NominalRateHz` | **标称**速率（用于"是否掉速"的对照） | 空（不显示对照） |

框架据此机械给出**四档速率**（每档都有"实测 = 计数 ÷ 时间"与可选的"标称对照"）：

| 档 | 定义 | 谁提供 |
|---|---|---|
| **单元速率** | 单元/秒（**按源计**：模块发送次数；另可显示"按宿计"） | 框架计数 + 时间戳（D5） |
| **搬运字节速率** | 单元数 × **契约尺寸**（含自描述与填充；按宿计会乘上多播份数） | 框架 |
| **有效载荷字节速率** | 单元数 × `PayloadSizeInBytes`（业务数据） | 框架（用模块声明的系数） |
| **样本速率 / 通道样本速率** | 单元速率 × `SamplesPerUnit`（× `ChannelCount`） | 框架（用模块声明的系数） |

**丢弃必须分成三类**（不再混一个数）：

| 类别 | 含义 | 来源 |
|---|---|---|
| **停流未投递** | 网络停流/挂起期间的发送（**不是故障**，属合法状态） | 框架（现被并入"丢弃"，须拆出） |
| **传输丢弃** | 队列满、无承载、载荷非法等真正"传丢了" | 框架 |
| **模块内部丢弃** | 模块自己的覆盖/降采样（如显示器覆盖旧值） | **模块上报**（或合并 `Publish` 数据源口径） |

**两条纪律**：
1. **UI 只显示"有定义的口径"**；**不得**再由 UI 自己差分估算速率（`_rateSamples` 这类实现应退休）。
2. **"实际速率 vs 框架速率"不做一个对比数字**，而是**并列显示多档口径 + 明确标注**（工业惯例：link rate / payload rate / sample rate / goodput）。**是否掉速**由"实测 vs `NominalRateHz`"回答，而不是靠两个数字相减。

> 这条同时解释了现状：叠加层里的"速率/约字节"= `投递单元数 × 契约尺寸 ÷ 间隔` —— 既含自描述开销（③），又把多播按宿放大（①），所以**看起来总是对不上**。



| 类别 | 是什么 | 谁声明 | 给谁看 | **显示在哪** |
|---|---|---|---|---|
| **功能角色** | 这个模块**是什么、干什么、怎么用**（用户语义） | 模块（现有 `DisplayName/Description/Tags` 已是雏形） | 用户（选型/使用） | **模块清单页 · 模块自己的窗口说明 · 帮助** |
| **数据角色** | 这个模块**怎么处理数据**：几种数据、进出关系、从哪来到哪去 | 端口 + 类型**派生**（协议专项可加显式声明） | 用户（观测/调试） | **叠加层**（中心方块 + 数据流线）· 拓扑诊断 |

**【ADR-0048 落地（P3）· 数据角色的精确定义】** 上表第二行细化如下（用户第三十轮"全部按推荐"）〔**第三十三轮已由 ADR-0052 修订：角色改「模块声明的功能分块」，见下方 §4.1**〕：

| 项 | 定稿 |
|---|---|
| **定义** | **角色 =（方向 × 类型身份）**，在**模块内聚合**（同方向 + 同类型身份的口 = 一个角色；一个角色可有**多个口**，如 8 通道记录器 = 1 个接收角色 + 8 个口） |
| **类型身份** | 已声明类型 ⇒ **`标识@版本`**；未声明（旧模块）⇒ **结构描述** `ContractShape.Describe()`。**不得**用呈现文本一律代替——那会把"不同标识但同形状"错误合并（ADR-0051 明确二者**不是同一种量**） |
| **派生 vs 声明** | **v1 纯派生**（不引入角色声明/业务分类；主文档 §6.2 的裁决不变） |
| **零口回退** | 没有数据口 ⇒ **角色集合为空**，**不画任何方块**（信息区写"无数据口"；这不是错误状态） |
| **状态色** | 角色方块**不带状态色**（停流/悬空只在**端口标记与线**上表达 —— 同一事实只在一处表达） |
| **角色对** | 聚合键 =（本端角色, **对端实例**, 对端角色）⇒ **一条线 + 条数**（跨网络也聚合）；**多源网络**下不同模块的源 = 不同对端 ⇒ **各自一条线**；同一模块的多个同类型口 ⇒ 一条 + `×N` |
| **线的几何** | **沿用 ADR-0045**（本窗只画到自己那侧边界，不做跨窗口覆盖窗）；角色只改**起点与聚合粒度** |
| **红线** | **只呈现**：不参与建网 / 兼容判定 / 停流 / 投递 / 计量，且**不进组合件**（持久化里不得出现角色字段） |
| **算在哪** | **Core 算 + `Core.Api` 暴露**（`IRuntimeQuery.GetDataRoles` / `GetRolePairs`；`PortView.TypeKey`），**UI 只画** —— 与兼容判定**同一入口**（`CheckCompatibility`），否则 UI 会复制一套并漂移 |

⇒ **叠加层只显示"数据角色 + 拓扑 + 传输级指标"；应用语义（单位/量程/业务含义）显示在模块自己的 UI。**

### 4.1 【ADR-0052（第三十三轮 · 已落地）】角色 = **模块声明的「功能分块」**

| 项 | 定稿 |
|---|---|
| **定义** | **角色 = 模块声明的功能分块** = 一个 `Id` + **一种数据类型**（`DataTypeRef`）+ **输入口**/**输出口**（通常各 1；**融合块 = 2 入 1 出**；**口数不设上限**，&gt;2 口时 **SDK 自检**给一条**可忽略的建议**）⇒ 上表"定义/派生 vs 声明/零口回退"三条已被本行取代 |
| **谁定义** | **模块自身声明**（`IModuleDeclaration.DeclareRole`）。**框架不派生、不发明角色** —— 功能分解是**设计信息**，"方向 × 类型"的机械组合推不出来（会把融合器画成"一收一发两块"） |
| **仍然有效** | 类型身份不得用呈现文本（上文第 2 行）· 零数据口 ⇒ 不画方块 · 角色**不带状态色** · 角色级聚合（聚合键 =（本端角色, 方向, 对端实例, 对端角色））· **只呈现**红线（不参与建网/兼容/停流/投递/计量、不进组合件）· **Core 算 + `Core.Api` 暴露、UI 只画** |
| **`m/n`（方块第二行）** | 输入/输出侧连接的**对端角色数**（去重键 =（对端实例, 对端角色））；**无该侧口 ⇒ `--`**、**有口未连 ⇒ `0`**；**由框架从网络成员关系派生**（`RoleModel.PeersOf`），**模块不得自报** |
| **算在哪（现行接口）** | `IRuntimeQuery.GetRoles` / `GetRoleFlows` / `GetRoleOrder`（视图 `RoleView` / `RoleFlowView` / `RoleOrderView`）；`RoleFlowView.NetworkKeys` **只用于取指标**，**网络标签属接口层、不进叠加层** |
| **新增红线** | **框架不发明角色**：未声明角色 ⇒ 不画方块 + 一句可执行的事实（`未声明角色（N 个数据口）`）；**不做兼容回退**（避免"两套角色模型并存"） |
| **已知局限** | **声明 ≠ 证明**：框架只校验"口存在且归一、类型可解析"，**校验不了语义** |
