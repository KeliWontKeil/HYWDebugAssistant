## 3.1 SDK 的定位

- SDK = **`HYWDebugAssistant.Sdk` 单一程序集**（Q2-2），是模块作者**唯一**可引用的框架程序集（Q1-2/ADR-0026）。
- **零框架依赖**：`Sdk` 不引用 `Infrastructure`（L0 仅 L2/L3/L4 可见，C1-4）、不引用任何 UI 框架（C1-3）、不引用其他框架项目。
- SDK 承载三件事：**① 声明载体**（特性与声明类型）· **② 实现基元**（模块接口与生命周期钩子）· **③ 框架服务面**（上下文、上报、配置读写）。
- **不含**：机制实现、契约兼容判定的实现（只在 L4/L2 侧）、数据面投递类型、UI 类型。
- 边界纪律：SDK 的公开 API 必须有 XML 注释（ADR-0025 §5）；SDK 的破坏性变更等同契约变更，须走 ADR。

## 3.2 声明载体：C# 特性 + 反射（Q3-1）

模块 Definition 的**六项声明**（§4.4）与 manifest 附加项（§11.2）在技术上的映射：

| # | Definition 六项（§4.4） | SDK 载体 | 说明 |
|---|---|---|---|
| ① | 身份与版本标识 | 模块特性上的**结构化三元组**（作者命名空间 / 模块名 / 版本）（Q3-5） | 版本参与多版本共存（§11.2）与重锚诊断 |
| ② | 目录/用户元数据 | 特性属性：显示名、描述、可选标签 | 仅供 UI 目录展示；**不构成框架业务分类**（§4.3/P16） |
| ③ | 对外契约声明 | **契约类型**（C# 类型即契约，Q3-2）+ 口成员声明（名称、方向两态、契约类型） | 见 §3.4 |
| ④ | 可配置项声明 | **配置类型**（C# 类型 + 源生成，Q3-4） | 见 §3.5 |
| ⑤ | 可选视图声明 | **视图声明**（预置元素组合，Q3-7） | 见 §3.6；模块不提供 View 类型 |
| ⑥ | 宿主/生命周期能力声明 | 特性属性：模块是否参与数据活动、是否需要配置变更通知、活动承载需求 | 供 L2/L3 决定承载方式（不构成框架分类） |
| — | 实现入口（§11.2） | 模块实现类型（实现 `IModule`，Q3-3） | 包加载时定位 |
| — | 依赖（§11.2） | 特性声明其他模块 ID 三元组的依赖 | 缺失依赖 → Issue、不静默降级（§12） |
| — | 框架兼容范围（§11.2） | 特性声明兼容的框架主版本区间 | 加载校验（§11.2） |
| — | 可选资源引用（§11.2） | 资源清单（图标等） | 物理形式 Gate |

**反射策略**：声明**仅在模块包加载/注册期读取一次**，读取后转为**不可变元数据**缓存；运行期热路径**零反射**（契约元数据在注册期解析成形）。

### 3.2.1 口成员声明的附加约定（补 §5.4 PQ-IF-02 的落点）

| 项 | 约定 |
|---|---|
| **口名唯一性** | 口名 = **模块内唯一稳定名**（作者命名；多同型用「名 + 序号」）；**由加载期校验**（重复即拒绝注册 + Issue，**不静默改名**） |
| **口级自动建网开关** | 口声明含 **`参与自动建网`（bool，默认 true）**——落地基线 §2.5「'是否参与自动建网'为口级开关」；全局 R0 开关关闭时该属性无效 |
| 元能力目录 | 平台提供**受控元能力目录**（可实例化口 / 可被连接 / **方向两态**），业务形状由作者契约描述、**不入目录**（P16）；目录由 `Sdk` 声明 + L2 校验 |
| **契约引用形态** | **契约一律具名引用**（随模块包/Definition）；**v1 不支持内联契约**——即把 §9.3 的「具名或内联」落地为「具名」 |

## 3.3 实现基元：接口实现（Q3-3）

模块作者实现一组**接口**（不继承框架基类，Q3-3）；框架只按接口调用。

- **必需接口**：模块入口接口（提供 ID/元数据读取与生命周期钩子的入口）。
- **可选接口**（按声明能力实现）：配置变更通知、活动承载回调（若模块需要自发活动）、上报扩展。
- **生命周期钩子**（对齐 §8.4 框架状态机 `Registered → Active ⇄ Disabled → Removed`）：

| 钩子 | 触发时机（框架侧） | 模块应做 |
|---|---|---|
| `OnRegistered` | 实例创建、成员实例化完成后 | 建立内部结构；**不得**假定数据已在流动 |
| `OnActivated` | 进入 `Active`（加入即运行，§8.1） | 开始业务活动（若需要） |
| `OnDisabled` | 进入 `Disabled`（保留实例/拓扑/配置、暂停数据流） | 内部处置**自决**（框架不替模块决定"是否断硬件"，§8.4） |
| `OnEnabled` | `Disabled → Active` | 恢复业务活动 |
| `OnConfigurationChanged` | 配置更新（框架通知模块，热生效或请求重建由模块自决，§7.3） | 应用新配置 |
| `OnRemoved` | `Removed` 前 | **释放模块内部资源**（框架已先清连接/绑定与成员实例资源，§7.3/PQ-RT-08） |

- **不进钩子集的**：数据到达（属数据面调用路径，第 4 章）、业务状态上报（属服务面即时 API，§3.8）。
- **异常纪律**：钩子与投递回调中的异常不得逸出边界——框架受控捕获并转 Issue（§8.5/AC-2）；捕获形态由第 4 章定（与 Q4-1 执行模型一并）。

## 3.4 契约：C# 类型即契约（Q3-2）

契约 = **模块作者定义的 C# 类型**，但其**构成受限**——只能由平台提供的**形状原语目录**组合而成（§5.4.1 ②），框架在加载期校验（反射检查成员类型）。

**契约三层能力（ADR-0008）的落地**：

| 层 | 内容 | 本方案载体 |
|---|---|---|
| ① 传递语义标注 | 流 / 消息 / 事件 | 契约类型上的标注（作者声明）；跨语义**不判兼容**，需模块内部自行组帧（§5.4.1） |
| ② 受控基础形状原语目录 | 平台提供、可扩展、作者只能组合 | **v1 原语目录已定（C3-5）**：定宽有符号整数 `i8/i16/i32/i64` · 定宽无符号整数 `u8/u16/u32/u64` · `f32/f64` · `bool` · **定长字节块**（长度 1–256）· **定长数组**（元素为上列原语，长度 1–256）· 上述的**结构组合**（嵌套深度 ≤ 4）；**无变长**（字符串/序列由定长数组 + 长度字段自行表达） |
| ③ 组合与签名 | 组合编码签名 = 兼容判据锚点 | 契约的成员序列（名称 + 原语类型 + 顺序）= 签名；兼容判定 = **形状完全一致**（结构比较，可计算）〔**ADR-0051 修订**：原「接收 ⊇ 发送」已作废〕 |

**边界（承 §5.4.2，不得违反）**：
- 框架**不附加任何数据单元元信息**（时间戳/序号/来源）——需要者由模块在自己的契约中声明字段；
- 契约**不含单位/量纲语义**——单位属模块配置/显示层；
- **不自动转换**（§5.4.1 ⑤）：不兼容即不可连 + UI 明示差异，转换由用户显式插入转换模块。

**兼容判定的执行位置**：判定在 L2/L4 侧实现（不在 SDK）；SDK 只提供契约的**声明类型与元数据描述**。吸附仅几何对齐、兼容判定发生在建立网络时（§5.3/ADR-0018）。

## 3.5 配置：C# 类型 + 源生成（Q3-4）

- 配置类型 = 作者定义的 C# 类型，由**源生成器**产出序列化代码（Q3-4）：热路径无反射、可预测。
- **未知字段保留（AC-4 无损往返）**：加载时未被当前配置类型识别的字段**必须保留**并在再次保存时原样写回——实现路线**已定（C3-3）**：源生成序列化 + **保留原始片段 + 合并写回**。
- 配置的归属（§4.5）：**Instance 持有、随组合件保存**；Schema 在 Definition。
- 配置界面由框架按 Schema 生成（承 Q5-5；形态属 Gate C）。

**【实现落定 · M1-15 / ADR-0035】配置 Schema 与字段元数据**

| 项 | 落定值 |
|---|---|
| Schema 来源 | 框架**反射配置类型的公有可读写属性**生成字段（v1 无源生成器：配置序列化本身已是反射式，见下条）；不支持的属性类型（复杂对象等）**不生成字段**而非假装支持 |
| 可选标注 | **`[ConfigurationField("标题", Group=…, Minimum=…, Maximum=…, Step=…, Unit=…, Description=…)]`**（`Sdk.Configuration`，**只增不改**）；不标注时标题由属性名生成（`PeriodMs` → "Period Ms"）、控件由属性类型判定（布尔→开关 / 枚举→下拉 / 整型·实数→数值输入 / 字符串→文本） |
| 范围语义 | 范围与步长**只约束编辑界面**：框架**不据此裁剪**配置值（语义归模块）；特性参数只能是常量，故"未设置"用 `double.NaN` 表达 |
| 读即登记 | `IConfigurationAccess.Read<T>` **首次读即登记默认配置**（否则只读配置的模块在保存时会整块丢失配置，且无对象可生成表单）；配置集合的所有访问点**统一加锁** |
| 写回路径 | UI → `Core.Api.UpdateConfigurationField` → **JSON 中转产出新实例** → L4 变更入口（原子应用或整体拒绝、触发一次配置变更通知）；**不就地修改运行中的对象** |
| 序列化取舍（v1 明确） | **组合件信封零反射**（手工 JsonNode 映射）；**模块自有配置对象走反射式序列化**（`ConfigurationJson.Options`）；配置 JSON 允许 `±Infinity/NaN` 命名浮点字面量、**枚举按名字**读写（旧数字枚举仍可读） |

> **与 Q3-4"源生成"的差异已登记**：v1 未引入源生成器（模块作者无需提供序列化上下文）；将来需要"编译期零反射"时统一替换，届时 Schema 与序列化一并迁移（ADR-0035 §3）。

**反射与源生成的分工（消解潜在张力）**：声明（六项/成员/契约形状）→ **反射**读取一次并缓存为不可变元数据（Q3-1）；配置序列化与反序列化 → v1 **反射**（原定源生成，Q3-4；差异见上表注）。两者不冲突：反射只发生在包加载期与配置读写路径（非数据面热路径）。

## 3.6 视图：预置元素组合声明（Q3-7 + C3-6）

**约束（C1-3，不可协商）**：模块**不得提供任何 View 类型**，不得依赖 Avalonia；视图全部由框架渲染。

- 模块以**声明**描述视图：从**框架预置元素目录**中选取元素、组合、绑定到模块可暴露的数据源与配置项。
- 视图元素绑定到的数据来自模块的**可暴露数据源声明**（不暴露内部对象引用，避免 P12 与实现耦合）。
- **不声明视图的模块**：**合法**——但**【修订 · M1-15 用户裁决】它仍然拥有自己的窗口**：窗口内至少显示模块名与状态，并由框架补上**配置表单**（无配置则说明原因）。"无 UI 模块经管理视图兜底"的旧口径作废：不存在"没有窗口的模块"这一形态；模块的运行/停用、锁定、隐藏、移除与配置编辑都在**它自己的窗口**上完成。

**v1 预置元素目录（档 3 完整 · C3-6）**：

| 类 | 编号 | 元素 | 需要的框架设施 | 牵扯数据面 |
|---|---|---|---|---|
| 数据呈现 | A1 | 数值显示（单/多值 + 格式单位） | 单值订阅 + 刷新节流 | 轻 |
| 数据呈现 | A2 | 状态灯/指示器 | 状态值订阅 | 轻 |
| 数据呈现 | A3 | 曲线/波形（多通道、时间轴） | **抽样 + 环形缓冲 + 刷新节流** | **重** |
| 数据呈现 | A4 | 表格（行集） | 行式数据订阅 + 更新策略 | **重** |
| 数据呈现 | A5 | 文本日志窗口 | 文本流 + 限流 + 滚动策略 | **重** |
| 数据呈现 | A6 | 十六进制/字节视图 | 字节块数据 + 格式切换 | 中 |

| 数据呈现 | A8 | 图像/位图帧 | 大块数据 + 帧率控制 | **重** |
| 交互控制 | B1 | 配置项编辑（按 Schema 自动生成） | 配置 Schema（Q3-4）+ 写回 | 无 |

- **D 类（框架渲染类）不在模块声明范围**：Issue 标注与列表、口上标记与网络标识、流量/丢弃计数、模块状态徽标由框架渲染（§10.4）。
- **扩展性（承 C1-3 后果 2）**：第三方无法贡献 UI 元素；目录增长只能由框架版本升级提供。**新增元素属兼容扩展**，删除或改语义属破坏性变更（须 ADR）。
- **元素类型 vs 视觉形态**：元素**类型**属本章（SDK 声明类型）；元素**视觉形态**（尺寸族/网格/样式）属 Gate C（UX 原型，第 5 章衔接）。
- 视觉层划分与渲染实现（含口上标记、连线层）属第 5 章。

## 3.7 模块包与模块的基数

- 承 C2-4（三个桩模块各自独立项目）：**1 个模块包 = 1 个 Module Definition = 1 个模块实现**（**已定 · C3-1**：v1 强制，不允许一包多模块）。

### 3.7.1 模块包生命周期（补 §11.2 PQ-PL-03 的落点）

| 操作 | 约定 |
|---|---|
| **发现 / 加载** | **显式加载为主**（用户选择路径或来源目录）；加载经校验（完整性 / 框架兼容范围 / 依赖）→ 注册 Registry；失败 = Issue 且**不影响既有运行** |
| **版本维度** | 同 ID **多版本共存注册**（版本字段是 ID 三元组的独立维度）；实例引用**创建时所选版本** |
| **更新** | 新版本作为**新增注册项**（不覆盖旧版本）；既有实例**保持**原版本继续运行；用户可手动把实例切到新版本（**版本迁移路径**属 Gate D，见 `07` §7.3） |
| **移除** | 注销注册项；**已实例化的在用实例不强制卸载** → 进入**缺失态**（占位保留配置与网络成员 + Issue，§9.3）；**程序集不主动卸载**（避免在用代码被卸载） |
| **重锚** | 组合件记录实例的 ID 三元组（含版本）→ 加载时按版本重锚；版本不兼容 → 缺失态 + Issue（可手动指定替代版本） |

### 3.7.2 包产出与发现（**模块作者视角** · M1-17 / ADR-0036 D1/D2）

| 项 | 约定 |
|---|---|
| 包从哪来 | **构建即产出**：模块项目构建后自动归拢到 `artifacts\modules\<包名>\`，框架 `App` 构建后再镜像到 `<应用输出>\modules\` —— **作者不需要手工拷贝，也不需要改任何脚本**（新增模块项目零改动） |
| 应用从哪找 | **声明的根列表**（设置项 `moduleSourceDirectories`，有序；默认只含 `<应用目录>\modules`）：按顺序逐根扫描，每根只扫**直接子目录**中含 `module.json` 者；**不递归、不扫任意位置** |
| 重复时怎么办 | 同 ID 同版本：**先到者胜**（后者记 Info）；同 ID 不同版本：共存（目录按模块名聚合，默认取最新版本） |
| 何时重扫 | 启动自动扫描 + 界面「立即重扫」（只发现**新增**包）；**改过代码的包必须重启应用**（程序集不可卸载）——重扫会对"本次启动后重新构建过"的包给出**需重启**提示 |
| 作者调试建议 | 改模块 → `dotnet build`（包自动归拢）→ **重启应用**。**框架不实现热重载**（用户裁决：无此需求，且复杂度高）；重扫只发现新增包，改过代码的包给出"需重启"提示 |

## 3.8 框架服务面（模块如何与框架交互）

模块**不持有框架对象引用**，只通过框架在实例化时提供的**上下文**使用服务：

| 服务 | 用途 | 约束 |
|---|---|---|
| 上报：Issue | 模块发现的可呈现问题（归属对象 + 类别 + 描述，§8.5） | **模块业务状态不入 Issue**（§8.5） |
| 上报：日志 | 模块诊断经框架汇集（可观测性 L3，§13.2） | 分级 + 来源；默认轻量不打扰 |
| 上报：业务状态 | 模块自报业务状态（框架只登记/呈现、不解释，§8.4） | 框架**不解释业务语义**（P2） |
| 配置读写 | 读当前配置、写回配置 | 写回触发 §3.3 的配置变更通知路径 |
| 活动承载登记 | 声明模块需要被承载的活动（若需要自发活动） | 承载与调度在 L3（C1-2/ADR-0013） |

**方向纪律**：模块 → 框架为"上报/请求"；框架 → 模块为"生命周期钩子 + 投递回调"。模块**不得**反向查询其他模块是否存在、不得持有其他模块实例（P12）。

**关于"连接建立/拆除服务"（§4.8-B 的落点）**：连接（网络）的建立/拆除**由用户在 UI 声明、由 L4 执行**，**模块不参与、也不可见**——模块无法请求"把我和某个模块连起来"。§4.8-B 中"框架供给模块：连接的建立/拆除服务"应理解为：**数据通路由框架建立并保证直通，模块侧只需实现接收回调与发送 API**。

## 3.9 与安全模型的一致性（§12）

- **v1 不引入脚本宿主**（Q3-6）：模块行为载体只有 C#（预编译/动态编译）。ADR-0023 §5 的"脚本宿主可选"在 v1 **不实现**；未来引入须新 ADR，并重新评估执行权（§12 表"脚本模块逃逸"一行）。
- 模块包的能力声明（网络/串口/文件）由 manifest 承载，加载时**透明提示**（不拦截，§12）。
- **组合件永不自动执行代码**（§12）：加载组合件只重建声明结构，不触发任何模块代码以外的机制。

## 3.10 与 AC 判据的对应

| 判据 | 本章如何支撑 |

### 3.10.1 成员统一路径四阶段 → SDK 载体（补 §4.10.2 的落点）

| 阶段（§4.10.2） | SDK 载体 | 框架侧动作 |
|---|---|---|
| ① 声明 | 特性 + 口/配置/视图声明类型 | 加载期反射读一次 → 不可变元数据 |
| ② 实例化 | 框架调用模块入口（构造 + 注册成员） | L2 创建实例与成员实例表（口实例 / 值槽 / 视图宿主） |
| ③ 存取·连接 | 上下文服务：配置读写、发送 API、订阅写入、上报 | L4 建网与绑定；L3 投递；UI 经订阅缓冲读取 |
| ④ 表现 | 视图声明（元素组合 + 数据源） | L5 按声明渲染；**口上标记与网络标签由框架绘制** |

### 3.10.2 模块实现来源（补 §4.2「原生代码 / 脚本 / Composite」的落点）

| 来源 | v1 | 说明 |
|---|---|---|
| **原生代码（C#）** | ✅ | **唯一实现来源**（`Sdk` 接口实现 + manifest） |
| 脚本 | ❌ | v1 不引入（Q3-6 / ADR-0028 §9） |
| **Composite（组合件作为模块实现来源）** | ❌ | **v1 不支持**：组合件是**持久化/复用载体**（§9.2），**不是**模块实现来源；登记为 Gate D（未来若支持需新 ADR + 定义"组合件发布为模块"的装载语义） |

| 编号 | 问题 | 裁决结果 | 连带影响（后续章节必须遵守） |
|---|---|---|---|
| **C3-1** | 模块包与模块基数 | **1 包 = 1 模块（v1 强制）** | Registry 登记粒度 = 包粒度；与 C2-4（三独立桩模块项目）一致；manifest 不含"包内多模块"结构 |

| **C3-5** | 契约形状原语目录 | **仅定长原语 + 结构组合**（定宽整数/浮点、布尔、定长字节块、定长数组、结构组合；**无变长**） | 第 4 章 Q4-2 数据单元物理表示可据此采用**定长布局**（扁平缓冲/零拷贝可行）；兼容判定 = 定长形状的**结构比较**，可完全计算〔**ADR-0051**〕 |
