# 第 4 章补遗：应用级设置（Settings）模型

> 状态：**已冻结**（议程 ③ 第 4 章补遗；S-1~S-4 与 C4b-1~C4b-3 已逐条裁决，见 ADR-0030）
> 来源：C4-2 裁决暴露的缺口（`04-key-mechanisms.md` §4.12）；基线 §6.2 R0 已隐含应用级设置的存在
> 裁决前提：**S-1 现在补** · **S-2 仅应用级设置** · **S-3 回写主文档**（已完成：主文档 §9.5 + 修订记录 1.0.2）· **S-4 与组合件完全分离**（用户原话要点："在仅使用应用级设置下，设置与模块本身组合应完全分离，且设置可独立保存（可以是一个简单的 .json 文件）。他们是完全不同的两种东西，特别是不存在广义的'工作空间'时。"）
> 关联：ADR-0030 · 主文档 §9.5 · `02-project-structure.md`（`FrameworkUi` 承载设置界面）

---

## 1. 定位

**应用级设置 = 应用/用户级的行为偏好**，独立于组合件，不属于"工作现场内容"（§9.1）。

三类持久化内容自此边界清晰、互不重叠：

| 内容 | 层级 | 载体 | 随组合件 | 谁改 |
|---|---|---|---|---|
| **组合件** | 内容 | 1 文件 1 件（§9.2） | —（它自己就是载体） | 用户（保存时） |
| **Configuration** | 实例参数 | 组合件内 | ✅ | 用户（配置界面） |
| **Layout** | 视图布置 | 组合件内 | ✅（加载可忽略） | 用户（拖动） |
| **Settings** | 应用偏好 | **独立用户级文件** | ❌ 完全分离 | 用户（设置界面） |
| 会话快照 | 现场自动恢复 | Gate D（不在 v1） | — | 框架 |

---

## 2. 归属与生命周期

| 面 | 结论 |
|---|---|
| 归属 | **Core（L4）** 管理与持久化（不是模块、不是 UI） |
| 创建 | 首次启动时以**内置默认值**生成（或纯内存默认，首次修改才落盘） |
| 生效 | **在线即时生效**（与"全在线变更"一致，§7.1）：变更经 L4 变更入口应用，相关组件被通知 |
| 呈现 | `FrameworkUi` 的设置界面（第 5 章）；读取一律经 `Core.Api`（C4-4） |
| 与模块的关系 | **设置不下发给模块**：模块只接收自己的 Configuration；设置仅供框架自身使用（模块不感知全局偏好） |
| 与组合件的关系 | 完全分离：不随组合件保存/加载；组合件不携带设置快照（S-4） |

---

## 3. 存储

| 项 | 方案 |
|---|---|
| 形式 | **单一 JSON 文件**（用户原话：可以是一个简单的 `.json` 文件）；`System.Text.Json` 源生成 |
| 位置 | **应用所在目录（便携式）**：`settings.json` 与应用同目录（C4b-1）——拷贝整个应用目录即可搬走配置 |
| 版本 | 文件内嵌 `schemaVersion`；能迁移则自动迁移，不能则用默认值 + Issue（**不阻断启动**） |
| 缺失/损坏 | 使用内置默认值 + Issue（归属 = 应用级设置），不阻断启动（§9.5） |
| 写回 | **原子写**（临时文件 → `File.Replace`，机制同 §9.2 与 R4-6） |
| 未知字段保留 | **沿用 C3-3 策略**：未知字段片段保留 + 合并写回（版本前进/回退皆无损） |
| 并发 | 读写在 L4 管理线程；UI/其他读取经 `Core.Api` 快照 |
| 写盘时机 | **每次变更立即原子写**（C4b-3）——设置变更本就不频繁，行为最直观 |

### 3.1 应用目录不可写时的行为（便携模式的边界）

便携模式要求应用目录可写；若应用被安装在受保护位置（如 `Program Files`）且当前用户无写权限：

| 方案 | 说明 |
|---|---|
| **① 明确提示 + 本次运行设置仅存内存**（建议方案） | 启动时探测目录可写性 → 不可写则：状态栏/Issue 提示"设置无法保存（应用目录不可写）"，设置改动在本次运行内生效但不落盘。**不做静默回退**——保持"便携"语义可预测（用户知道文件在哪） |
| ② 静默回退到用户级目录 | 使用方便，但"设置文件在哪"变得不可预测，与便携语义冲突 |
| ③ 拒绝启动 | 过于强硬 |

**此项由本节提出方案（①）供审核**，属 B 类实现细节（`04b` §7 不再单列）。

## 4. v1 设置项清单（初版）

| 类 | 项 | 说明 |
|---|---|---|
| 框架行为 | **快速建网默认开关**（R0） | §6.2 R0 的"设置项开启（默认开）"落点 |
| 框架行为 | **停止超时**（默认值 + 可配置） | C4-2 裁决的参数归属 |
| 框架行为 | **输入队列容量默认值** | C4-3 裁决的参数归属 |
| 框架行为 | 诊断提示阈值（如"缓冲持续为满"的判定阈值） | §4.11 轻量提示的触发参数 |
| UI 偏好 | 刷新率（UI 渲染节拍） | 与 Q4-4 的 UI 读取节拍一致 |
| UI 偏好 | **吸附距离**（ADR-0042 D6） | 拖动磁吸半径：对齐类容差 = 本值（默认 **4**，2–8）；贴合类 = 2×；离开容差带立即松手 |
| UI 偏好 | 主题 | 外观 |
| UI 偏好 | 连线/网络标记的显示默认 | §6.3 连线默认隐藏 + 热键切换的初始状态 |
| 模块供给 | 模块来源目录（可选扫描目录） | §11.2「可选来源目录」 |
| 日志 | 日志级别、日志文件位置 | ADR-0024 极简日志 |

**明确不做**（S-2）：按模块类型的默认设置（模块默认值由模块实现提供）；任何"隐藏的全局行为开关"（设置项必须可在设置界面看到）。

## 5. 变更路径（与机制的一致性）

```text
设置界面（FrameworkUi）→ Core.Api 提交设置变更 → L4 变更入口（与 ChangeSet 同一入口串行化）
   → 校验（类型/范围）→ 应用（内存中的设置快照原子替换）→ 通知相关组件
   → 原子写盘（失败 → Issue，内存态保留并提示未持久化）
```

- 设置变更**不走 ChangeSet 的组合语义**（它不涉及实例/网络/绑定），但**共用同一变更入口**以保证"没有两条并发的状态修改路径"。
- 设置变更**不触发增量重建**（§7.3 的重建单位是绑定及邻接数据面）。

## 6. 与本章机制参数的衔接

第 4 章中"可配置"的参数自此有了明确归属：

| 参数 | 归属 | 生效方式 |
|---|---|---|
| 停止超时（C4-2） | 应用级设置 | 修改后对**后续**停止操作生效（进行中的等待不追溯） |
| 输入队列容量默认值（C4-3） | 应用级设置 | **数值 = 每 (实例, 口) 的容量**【ADR-0050 Q2】；修改后对**新建**队列生效；既有队列保持创建时容量（避免运行中改容量导致数据丢失） |
| 诊断提示阈值 | 应用级设置 | 即时生效 |
