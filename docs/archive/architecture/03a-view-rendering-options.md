# 第 3 章支撑分析：模块视图的渲染路线与元素目录（C3-6 专项）

> 状态：**已裁决**（C3-6 已关闭：路线 **(a) 预置元素组合声明** + 目录规模 **档 3 完整**，见 ADR-0028）
> 关联：`03-module-sdk.md` §3.6 · 第 1 章 C1-3（契约层不分面，模块不得依赖 UI 框架）· 第 3 章 Q3-7（预置元素组合声明）· ADR-0026 · ADR-0023 §7（多视觉层）
> 目的：说明"框架预置元素目录"到底是什么、它决定什么、在已冻结前提下一共有几条可行路线，供裁决。

---

## 1. 这个问题从哪里来（推导链）

```text
C1-3（已裁）  契约层不分面 ⇒ 模块实现不得依赖任何 UI 框架
      ↓
Q3-7（已裁）  模块不得提供 View 类型 ⇒ 视图必须由「框架按声明渲染」
      ↓
C3-6（已裁决）  那么"声明"能表达什么？⇒ 取决于框架提供哪些「预置元素」
```

也就是说：**C3-6 不是"要不要好看"，而是"模块作者能用哪些词汇描述自己的界面"**。在 C1-3 前提下，模块没有别的表达途径。

---

## 2. C1-3 带来的三条硬后果（必须一起考虑）

1. **没有"自定义视图"逃生口**：模块作者若需要目录里没有的呈现形式，无法自己写——只能等框架升级或走 ADR 推翻 C1-3。
2. **UI 表达力的增长路径只有框架版本升级**：第三方无法贡献 UI 元素（贡献 UI 元素必然要引用 Avalonia，违反 C1-3）。因此**初始目录的完整度比一般框架更关键**。
3. **SDK 定型后改动昂贵**：元素类型是 SDK 的公开声明类型。**新增元素是兼容扩展**（旧模块不受影响），但**删除或改语义是破坏性变更**（需 ADR + 迁移）。

---

## 3. 四条可选路线（都在既定裁决框架内或明确标注需推翻）

| 路线 | 内容 | 优点 | 代价 / 风险 |
|---|---|---|---|
| **(a) 预置元素组合声明**（Q3-7 当前裁决） | 模块从框架元素目录中选元素、组合、绑定到可暴露数据源 | 控制力与表达力可预期；框架渲染负担可控；模块零 UI 依赖 | 目录不足时模块无路可走（见后果 1）；需要定义元素目录 + 绑定声明 |
| **(b) 数据驱动的通用渲染** | 模块只声明"暴露哪些数据"，框架按数据形状自动选呈现（标量→数值、序列→曲线、行集→表格） | 模块几乎不用写视图声明；作者门槛最低 | 控制力弱（同一数据可能想用不同呈现）；自动选择易猜错；仍需要一个元素集合来实现（不是省掉问题，而是把它藏到框架内部） |
| **(c) 声明式 UI 语言** | 框架提供的声明语言（元素 + 布局 + 条件/表达式 + 绑定），模块写声明描述界面 | 表达力最强（可表达条件显示、换算、布局嵌套）；仍是纯声明、不引入脚本 | 需自研声明语言与校验器（工作量最大）；与 Q3-6「v1 不引入脚本」的边界需划清（表达式算不算脚本）；调试与错误提示困难 |
| **(d) 允许模块自带 View** | 推翻 C1-3：契约层分面，模块可依赖 UI 框架 | 表达力无上限；成熟生态（Avalonia 原生） | 打破 L1 零框架依赖 → Q1-2「模块仅见契约面」失效；E4（Module=Window）防线削弱；框架与 UI 框架版本强耦合 |

**说明**：(b) 与 (a) 不互斥（(b) 可作为 (a) 之上的便利层）；(c) 是 (a) 的超集；(d) 需要新 ADR 推翻 ADR-0026 的 C1-3 条目。

---

## 4. 若走 (a)/(c)：目录里可以有什么（分类与依赖）

下表按"元素 → 用途 → 需要的框架设施 → 是否牵扯数据面"列出候选。**"牵扯数据面"一列是关键**：它决定该元素是否会把第 4 章的 UI 交接模型（Q4-4）一并拖进来。

### A. 数据呈现类（只读）

| 元素 | 用途 | 需要的框架设施 | 牵扯数据面 | 备注 |
|---|---|---|---|---|
| A1 数值显示（单/多值 + 格式单位） | 实时参数、测量值 | 单值订阅 + 刷新节流 | 轻 | 最基础 |
| A2 状态灯/指示器 | 枚举状态（在线/离线/告警） | 状态值订阅 | 轻 | |
| A3 曲线/波形（多通道、时间轴） | 波形、趋势、FFT 结果 | **抽样 + 环形缓冲 + 刷新节流** | **重** | 需先定 Q4-4 |
| A4 表格（行集） | 参数表、报文列表 | 行式数据订阅 + 更新策略（追加/重绘） | **重** | 需先定 Q4-4 |
| A5 文本日志窗口 | 串口原始输出、模块日志 | 文本流 + 限流 + 滚动策略 | **重** | 与可观测性 L3 有重叠 |
| A6 十六进制/字节视图 | 报文二进制查看 | 字节块数据 + 格式切换 | 中 | 调试助手场景常见 |
| A7 仪表/进度条 | 占用率、百分比 | 单值订阅 | 轻 | A1 的变体 |
| A8 图像/位图帧 | 相机、热力图 | 大块数据 + 帧率控制 | **重** | 成本最高 |

### B. 交互控制类（写回配置或触发命令）

| 元素 | 用途 | 需要的框架设施 | 牵扯数据面 | 备注 |
|---|---|---|---|---|
| B1 配置项编辑（按 Schema 自动生成） | 参数设置 | 配置 Schema（Q3-4）+ 配置写回 | 无 | 即 Q5-5「配置界面生成」的落点 |
| B2 命令按钮 | 触发模块定义的动作 | 命令声明 + 调用路径 | 无 | |
| B3 开关/滑块 | 快速调节 | 配置写回（连续值需节流） | 无 | |
| B4 枚举/下拉选择 | 模式选择 | 配置 Schema 枚举 | 无 | |
| B5 文本输入（如 AT 指令） | 命令式输入 | 命令 + 文本输入 | 无 | |
| B6 文件/路径选择 | 日志落盘、固件文件 | 文件对话框（§12 限定用户选择路径） | 无 | 安全模型已定 |

### C. 结构容器类（编排）

| 元素 | 用途 | 备注 |
|---|---|---|
| C1 分组/分栏 | 把元素排成布局 | 无容器语义（§10.1），仅视图内部编排 |
| C2 标签页 | 多页切换 | 与 §10.2「面板/分组框/多页面为可选 UX 元素（Gate）」呼应 |
| C3 折叠面板 | 节省空间 | 同上 |
| C4 滚动容器 | 内容超长 | 基础能力 |

### D. 框架渲染类（不经模块声明）

Issue 标注与列表、口上标记与网络标识、流量/丢弃计数、模块状态徽标——**由框架渲染**（§10.4），模块不声明，不属于 C3-6 范围。

## 5. 目录规模的三档后果

| 档 | 内容 | 直接后果 |
|---|---|---|
| **档 1 最小** | A1/A2 + B1/B2 + C1 | UI 交接只需"单值快照 + 命令调用"，**Q4-4 可极简化**；串口/波形类模块基本无法呈现核心数据 |
| **档 2 调试标配** | 档 1 + A3/A4/A5 + B3/B4 | 覆盖串口/波形/参数调试主场景；**必须先定 Q4-4（抽样·环形缓冲·限流）**，第 5 章渲染工作量显著增加 |
| **档 3 完整** | 档 2 + A6/A7/A8 + B5/B6 + C2/C3/C4 | 表达力最强；工作量与第 5 章规模最大；A8（图像）成本最高，v1 可能只登记不实现 |

---

## 6. 与其他未决问题的耦合（裁决前需一并考虑）

| 耦合点 | 关系 |
|---|---|
| **Q4-4（UI 与数据面交接模型）** | 只要目录含 A3/A4/A5/A8（高频数据呈现），就必须先定抽样/缓冲/限流模型；档 1 则可以用最简单的快照模型 |
| **Q5-2（多视觉层划分）** | 元素越多，层间职责（内容层/连线层/标记层）越需要清晰划分，尤其曲线与连线层的绘制次序 |
| **Q5-5（配置界面生成）** | B1 与 Q3-4（配置 Schema）是同一件事的两面；目录里是否含 B1 决定"配置界面"是框架能力还是模块自备 |
| **Gate C（UX 原型）** | 元素**类型**属架构（SDK 声明类型）；元素**视觉形态**（尺寸/样式/网格）属 Gate C |
| **Q3-6（v1 不引入脚本）** | 路线 (c) 的"表达式"需明确是否越界；建议若走 (c) 则表达式限于"格式化/单位换算/条件显示"等纯函数子集 |

---

## 7. 若不裁决会阻塞什么

1. **SDK 的声明类型无法定型** → 第 3 章无法冻结，`Sdk` 程序集无法开始编写；
2. **第 4 章 Q4-4 无法定**（是否必须做抽样/环形缓冲/限流）→ 数据面设计方向不确定；
3. **第 5 章无法开展**（渲染什么元素是第 5 章的全部内容）；
4. **参考组合桩模块的视图无法设计** → T1 判据测试的"可视化验收"部分无法落地。

---

## 8. 裁决结论

**C3-6 已裁决：路线 (a) 预置元素组合声明 + 档 3 完整目录，见 ADR-0028。**

- **路线**：**(a) 预置元素组合声明**（模块从框架预置元素目录中选元素、组合、绑定到可暴露数据源）；
- **目录规模**：**档 3 完整**（A1–A8 + B1–B6 + C1–C4；即 **18 个元素 + 4 个容器**）。

> 落地位置：`03-module-sdk.md` §3.6；连带确定对第 4 章 Q4-4 的约束（抽样 + 环形缓冲 + 刷新节流）与第 5 章的渲染范围。
