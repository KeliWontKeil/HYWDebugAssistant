## 1.1 分层依据与层清单

按**运行时角色**切分为六个框架/应用层 + 一类非框架实现：

| 层 | 名称 | 运行时角色 | 是否框架 |
|---|---|---|---|
| L1 | **契约层**（Contracts / SDK） | 模块作者与 UI 共同依赖的稳定抽象面；承载"模块世界"的声明与上报契约 | 框架 |
| L2 | **模块宿主层**（Hosting） | 模块包的发现/加载/校验/注册/实例化、实例世界（成员实例表）、框架侧生命周期状态机 | 框架 |
| L3 | **数据面层**（DataPlane） | 绑定执行、数据单元投递、有界缓冲与丢弃、模块活动的承载与调度、流量诊断计数 | 框架 |
| L4 | **核心管理面**（Core） | Composition 解释与校验、ChangeSet 原子应用、增量重建、持久化（组合件）、Issue 中心、公开查询 API | 框架 |
| L5 | **UI 构成层**（Shell / App） | 主窗口、全局命令、模块视图宿主（模块区）、视觉层、口上标记渲染、管理视图 | 应用 |
| L6 | **模块实现**（业务模块） | 用户功能单元的实现体（非框架组成部分） | 非框架 |
| L0 | **横切支撑**（基础设施） | 日志 sink、序列化、配置读写、时间/诊断等中性技术能力 | 框架附属 |

**命名说明**：本表的 L1–L5 是**逻辑层**，与物理程序集的对应关系（一个层 = 一个还是多个程序集）由第 2 章裁决；文中"层"一律指逻辑层。

**已裁决（C1-5）**：L4 对外提供**独立 `Core.Api` 程序集**作为公开查询/命令面——UI 只引用它，L4 的内部实现类型对 UI 完全不可见；L6（模块实现）**不得**引用 `Core.Api`（Q1-2：模块仅见契约面）。

## 1.2 各层职责与内容边界

### L1 契约层

**职责**：定义模块作者与框架之间、以及 UI 与框架之间的**稳定抽象**——模块基元（模块声明入口与生命周期钩子签名）、成员声明（口/配置/视图）、数据单元与契约形状的抽象、上报 API（Issue/日志/业务状态）、框架**公开查询 API** 的抽象（Q1-4）。

**可以放**：抽象类型/接口、纯数据描述类型、枚举与常量、契约形状原语目录（§5.4.1 ②）、兼容判定所需的**元数据描述**（不含判定实现）。

**禁止放**：任何机制实现（加载、绑定、缓冲、调度、持久化）、任何依赖具体传输/业务的知识（P2/E7）、任何 UI 框架类型（若模块视图需 UI 类型，见 §1.6 待确认 C1-3）、对上层（L2–L5）的引用。

**依赖**：仅 BCL（可含 `System.*` 数据与诊断原语）；**零框架内部依赖**——这是"模块实现仅见契约面"（Q1-2）成立的前提。

### L2 模块宿主层

**职责**：模块包的发现/加载/校验/注册；实例化（按 Definition 创建实例世界与成员实例表）；框架侧生命周期状态机 `Registered → Active ⇄ Disabled → Removed`（§8.4）；模块清单数据；把模块包 manifest 与实现绑定对应起来（§11.2）。

**可以放**：加载器、包校验、注册表（Registry）、实例工厂、成员实例表、生命周期驱动。

**禁止放**：数据投递与缓冲（属 L3）、Composition 解释与原子变更（属 L4）、UI 类型（P1/A1 禁令）、具体业务知识（P2）。

**依赖**：仅 L1（+ L0）。

### L3 数据面层

**职责**：绑定的执行与拆除；数据单元从发送口到接收口的**直接投递**（不经管理面中转）；**每 (实例, 口) 的有界输入队列**与丢弃策略（§7.3；**【ADR-0050 Q2】** 按口独立 = 无跨口队头阻塞）；**模块活动的承载与调度**（ADR-0013/ADR-0029：框架为每个 Active 实例分配专属线程，模块不自建线程）；流量速率/丢弃计数/最后数据时间等 L4 诊断采集（§13.2）。

**可以放**：投递路径、绑定结构、缓冲与丢弃、调度与承载、护栏（**安全 + 提示**，ADR-0029 C4-1）、数据流诊断计数。

**禁止放**：UI 类型与任何 UI 等待/同步原语进入投递路径（保障 §13.1「数据面绝不被 UI 阻塞」）、模块加载与注册、持久化、任何业务知识。

**依赖**：L1（+ L0）。**不得反向依赖 L2/L4/L5**——数据面不查宿主、不问管理面，这是"管理/UI 不阻塞数据面"的结构保障。

### L4 核心管理面

**职责**：Composition 的表示、校验与解释（§6）；快速建网 R0–R6 规则执行（§6.2）；ChangeSet 的原子应用与失败整体拒绝（§6.2/ADR-0011）；增量重建（§7.3）；网络成员关系与命名（§6.3）；持久化：组合件序列化/反序列化/原子写/加载重锚（§9.2/9.3）；Issue 中心与可观测性 L1/L2 汇集（§8.5/§13.2）；对外**公开查询 API** 的实现（Q1-4）。

**可以放**：变更事务、差异计算、建网规则、持久化、Issue 管理、查询与命令面、对 L2/L3 的编排调用。

**禁止放**：数据投递路径的实现（只调用 L3 原语）、UI 类型（A1 禁令）、具体业务知识（P1/P2/P13）。

**依赖**：L1 + L2 + L3（+ L0）。

### L5 UI 构成层

**职责**：主窗口与全局命令；模块视图宿主（模块区，§10.1）；多视觉层（第 5 章细化）；**口上标记与连线的框架渲染**（§10.4）；配置界面容器与管理视图（无 UI 模块兜底）。

**可以放**：Avalonia 视图/ViewModel、UI 命令、视图宿主与视觉层、对公开查询 API 的调用、对契约面类型的展示适配。

**禁止放**：任何机制实现、直接引用模块实现程序集（A3 禁令）、修改 Core 内部状态（一切变更经变更入口）。

**依赖**：L1 + **`Core.Api`**（L4 的公开查询/命令面程序集，Q1-4/C1-5）。**不得引用 L2/L3 实现类型、不得引用 L4 内部实现程序集**；L5 亦**不得引用 L0**（C1-4）。

### L6 模块实现

**职责**：业务功能（含带逻辑的结构操作模块，如缓冲/聚合/条件路由，§6.3）。

**依赖**：**仅 L1**（Q1-2）。不得引用 L2/L3/L4（含 `Core.Api`）与 L5，不得引用 L0（C1-4），不得引用另一个模块（P12/A2），**不得依赖任何 UI 框架**（C1-3：模块视图由框架按声明渲染）。

### L0 横切支撑

**职责**：日志 sink、序列化、配置读写、诊断等中性技术能力（ADR-0024：日志极简自研）。

**依赖**：仅 BCL。**不得引用 L1–L5**（保持纯净，避免形成事实上的上层漏斗）。**仅 L2/L3/L4 可引用 L0**（C1-4）；L1 契约层、L5 UI 层、L6 模块实现均不得引用——契约层由此保持零框架依赖。

## 1.3 依赖方向（唯一允许的箭头）

```text
依赖链（唯一允许方向；"─►" = 依赖 = "可引用"）

  L6 模块实现   ─► L1 契约层
  L2 模块宿主   ─► L1 契约层、L0 横切支撑
  L3 数据面     ─► L1 契约层、L0 横切支撑
  L4 核心管理面 ─► L1 契约层、L2 模块宿主、L3 数据面、L0 横切支撑
  Core.Api      ─► L1 契约层                      （L4 的公开面程序集）
  L5 UI 构成    ─► L1 契约层、Core.Api            （L5 不引 L0）

结构要点：**L3 数据面没有任何指向 L2/L4/L5 的依赖** ⇒ 管理面与 UI 在结构上无法进入数据投递路径。
```

**允许的依赖（穷举）**

| 从 | 可依赖 |
|---|---|
| L1 契约层 | 无（**不得引 L0**，保持零框架依赖） |
| L2 模块宿主 | L1、L0 |
| L3 数据面 | L1、L0 |
| L4 核心管理面 | L1、L2、L3、L0 |
| `Core.Api`（L4 公开面） | L1 |
| L5 UI 构成 | L1、`Core.Api`（**不得引 L0**） |
| L6 模块实现 | **仅 L1** |

**禁止的依赖（核心禁令）**

- L1 不得依赖 L2/L3/L4/L5 与 `Core.Api`，也不得依赖 L0（契约层必须零机制、零框架依赖）；
- L3 不得依赖 L2/L4/L5（**数据面不被管理面与 UI 反向拖累**）；
- L2 不得依赖 L3/L4/L5；
- L5 不得依赖 L2/L3 实现类型、不得依赖 L4 内部实现程序集与 L0，不得引用模块实现程序集；
- L6 不得依赖 L1 以外的任何框架层（含 `Core.Api`、L0）、不得依赖任何 UI 框架、不得引用另一模块；
- L4 不得让数据投递经过自身（**只调用 L3 原语，不承接数据**）；L4 内部实现类型不得出现在 `Core.Api` 的公开签名中（只允许 L1 契约类型与 Api 自有 DTO）。

## 1.4 关键不变式的结构保障（逆例自检）

| 基线约束 | 本层图如何保障 |
|---|---|
| **P2 / E1 / E2**（Core 不是交换机/路由器，不中转业务数据） | 投递路径位于 L3，且 L3 不依赖 L4；L4 无任何数据面转发实现的位置。若有人把投递写成"经 Core 转发"，必然产生 L3→L4 依赖，被禁令直接拦截 |
| **§13.1 数据面绝不被 UI 阻塞** | L3 不依赖 L5；L5 只能通过 `Core.Api` 与框架交互，UI 的任何等待都不能进入 L3 调用栈 |
| **ADR-0013 框架统一承载活动** | 模块活动的承载与调度**独占于 L3**，L6 只能引用 L1，物理上无法创建框架外活动载体（模块不得自建线程） |
| **P12 / A2**（模块不依赖具体模块） | L6 只依赖 L1；模块间连接只能是 L1 契约的组合 |
| **P1 / A1**（Core 是 Host/Runtime，不是 Module） | L2/L3/L4 均不得引用 UI 类型；框架自身 UI（§3.2）位于 L5，与语义内核分离 |
| **P16 / §5.4.2**（具体数据类型不过早冻结、框架不加元信息） | 数据单元的类型语义只存在于 L1 的契约描述中；L3 只搬运不解释（是否需要元信息由契约自带，框架侧无字段） |
| **AC-1 / AC-5**（新增模块 Core 零改动） | 新增 L6 只引 L1，不触碰 L2/L3/L4；"Core 零改动"在依赖图上可判定（第 6 章给出判定方式） |
| **§3.2.1 表现/语义分离** | L5（表现）→ L4 公开面（语义）为唯一跨面通道；L6 不感知 L5 |

**反模式对照（E 系列）**：E1/E2 见上；E3（Core=God Object）由 L2/L3/L4 的职责三分与 L1 的抽象面限制；E4（Module=Window）由 L6 不依赖 L5、且不得依赖任何 UI 框架保障（C1-3）；E5（Plugin=DLL）不影响层图（模块包物理形式是 Gate）；E6（Workspace=数据流图）由 L4 的 Composition 表示限制；E7（Interface=每业务一类型）由 L1 的受控原语目录（§5.4.1）限制；E8（Composition=任意连接）由 L4 的校验与建网规则限制。

## 1.6 本章裁决记录（已确认 · 冻结依据）

| 编号 | 问题 | 裁决结果 | 连带影响（后续章节必须遵守） |
|---|---|---|---|
| **C1-1** | 层清单 | **即为此七类**：L1 契约 / L2 模块宿主 / L3 数据面 / L4 核心管理 / L5 UI 构成 / L6 模块实现 / L0 横切支撑 | 第 2 章按此七类划项目；第 6 章按此七类建规则集 |
| **C1-2** | 调度与承载归属 | **L3 数据面**（模块活动的承载与调度在数据面层） | 第 4 章 Q4-1/Q4-5 的执行模型必须在 L3 内实现；L2 只管"实例存在与状态"，不驱动活动 |
| **C1-3** | 契约层是否分面 / L6 能否依赖 UI 框架 | **不分面；L6 不得依赖任何 UI 框架** | **Q3-7 被收窄**：模块视图只能由框架按声明渲染（模块不得提供 View 类型）；**Q5-3 被收窄**：模块视图的数据绑定方式不得要求模块引用 Avalonia；第 5 章须给出"声明式视图"的落地形态 |
| **C1-4** | L0 横切支撑可见性 | **仅 L2/L3/L4 可引用 L0** | L1 契约层保持零框架依赖（也是 Q1-2 的前提）；L5 UI 与 L6 模块实现不得引用 L0 —— 框架的诊断/日志能力对 UI 与模块只能经 L1 契约面暴露 |
| **C1-5** | 公开查询/命令面归属 | **独立 `Core.Api` 程序集** | 第 2 章需为它单列项目；`Core.Api` 只依赖 L1；L4 内部类型不得出现在其公开签名中；L6 不得引用它（Q1-2） |
