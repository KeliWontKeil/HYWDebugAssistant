# 第 6 章 测试架构映射（全文）

## 6.1 定位

把 AC-1~6（§14.1）与 T1–T8（§14.4）落到**具体项目、工具与判定方式**，并按 ADR-0026 的七层重写架构测试规则集（取代工程基线阶段的 A1–A6 骨架）。

**继承的纪律**（ADR-0025 / 纪律 C1–C4）：验证以**模块级 + 组合级**为准，不做框架级"MCU 式"单元测试；**不设覆盖率百分比**；机制改动必须有组合级验证。

## 6.2 测试项目与职责

| 项目 | 职责 | 引用 |
|---|---|---|
| `HYWDebugAssistant.Tests` | **T2–T5**：契约兼容矩阵、建网规则 R0–R6、ChangeSet 原子性、增量重建、资源释放、持久化 round-trip、故障注入 | 引用 `Core`/`Hosting`/`DataPlane`/`Sdk`/`Infrastructure`（测试可跨层） |
| `HYWDebugAssistant.Tests.Reference` | **T1**：参考组合（**五个**桩模块：三个判据桩 + M1-15 新增的手动发送器与信息显示模块）+ AC-1~6 判据测试 | 引用框架 + `Modules.Reference.*` |
| `HYWDebugAssistant.ArchitectureTests` | **架构规则集（AR 系列）**：依赖方向禁令 + 源码级规则 | **不引用产品项目**；通过程序集元数据与源码读取分析（见 §6.3） |
| `HYWDebugAssistant.Benchmarks` | Gate B 数值实测（第 4 章 `04a` §5 清单）；**不进常规门禁**（`build.ps1 -RunBenchmarks` 按需运行） | 见 C6-2（ADR-0032） |

**为什么架构测试不引用产品项目**：它以"被分析对象"身份读取产品程序集（元数据 + 源码），若引用则会被编译期依赖关系绑住，且无法表达"禁止引用"这类规则。

## 6.3 架构测试规则集（按七层重写 · 取代 A1–A6）

### 两类规则与判定机制（Q6-2 裁决）

| 类 | 判定手段 | 原因 |
|---|---|---|
| **依赖类规则**（AR-1~AR-12） | **程序集引用检查**：用 `MetadataLoadContext` / `System.Reflection.Metadata` 读取已编译程序集的 `AssemblyRef` 表 | 能覆盖**间接依赖**（源码扫描只能看直接 `using`/`ProjectReference`），是依赖禁令的可靠判据 |
| **源码类规则**（AR-13~AR-16） | 保留**源码扫描**（现有方式） | 命名空间一致性、业务词汇、第三方命名空间这类规则本质上属源码层，程序集元数据无法表达 |

**前提**：依赖类规则要求产品程序集**已构建**（架构测试在构建之后运行；`build.ps1` 的顺序已满足）。
**"跳过 vs 失败"语义（重要）**：目标程序集不存在时**报失败而非跳过**——避免规则在重构中静默失效（工程基线阶段的"无对象则跳过"逻辑在分层落地后必须移除）。

### 规则清单

**依赖类**（程序集 → 允许引用集合）

| 编号 | 规则 |
|---|---|
| AR-1 | 模块程序集（`Modules.*`）**只允许**引用 `Sdk` |
| AR-2 | 模块程序集之间**不得互相引用**（P12） |
| AR-3 | `DataPlane` 不得引用 `Hosting`/`Core`/`Core.Api`/`Ui`/`FrameworkUi`（数据面不反向依赖） |
| AR-4 | `Hosting` 不得引用 `DataPlane`/`Core`/`Core.Api`/`Ui`/`FrameworkUi` |
| AR-5 | `Core` 不得引用 `Ui`/`FrameworkUi`（框架不得依赖 UI）；**允许引用 `Core.Api`**（实现 L4 公开面，见 `02` §2.1 修订说明） |
| AR-6 | `Core.Api` **只允许**引用 `Sdk` |
| AR-7 | `Ui` **只允许**引用 `Sdk` + `Core.Api` |
| AR-8 | `FrameworkUi` **只允许**引用 `Sdk` + `Core.Api` + `Ui` |
| AR-9 | `Sdk` **不得引用任何框架程序集**，也不得引用任何 UI 框架（零依赖，ADR-0026 C1-4） |
| AR-10 | `Infrastructure` 不得引用任何框架程序集；**只允许**被 `Hosting`/`DataPlane`/`Core` 引用（**测试项目豁免**：AR 规则只约束 `src/` 下的产品程序集，`tests/` 可跨层引用） |
| AR-11 | **唯一白名单**：`App`（组合根）可引用 `Core`/`Core.Api`/`Ui`/`FrameworkUi`（ADR-0027 登记例外） |
| AR-12 | 任何框架程序集**不得引用模块程序集**（反向依赖禁止；模块由包加载，不在编译期依赖） |

**源码类**

| 编号 | 规则 | 依据 |
|---|---|---|
| AR-13 | `Core`/`Hosting`/`DataPlane` 内不得出现具体业务词汇（UART/FOC/Plotter/串口/Modbus/CAN 等） | P1/P2/P13、ADR-0003 |
| AR-14 | 命名空间应与目录结构一致 | 工程约定（原 A4） |
| AR-15 | 不得引用 ADR-0024 排除清单中的第三方组件（MediatR/AutoMapper/FluentAssertions 8+/Moq/商业控件等） | 许可合规 |
| AR-16 | `Core.Api` 的公开成员签名中不得出现 `Core`/`Hosting`/`DataPlane` 的内部类型（只允许 `Sdk` 契约类型与 Api 自有 DTO） | ADR-0026 C1-5 |

- **例外机制**（ADR-0025 §8）：确需违反时用 `// ARCH-EXCEPTION: <原因> · <复查条件>` + **登记到 `docs/decisions.md`**；架构测试对**已登记的例外按显式白名单放行**；禁止静默绕过。
- 规则集**取代**工程基线阶段的 A1–A6（A1/A3/A5 语义并入 AR-1~AR-13；A2 并入 AR-2；A4 并入 AR-14；A6 并入 AR-15）。

## 6.4 判据落地（AC-1~6 → T1 参考组合）

参考组合 = `Modules.Reference.DataGenerator`（可编程数据发生器）+ `.Recorder`（记录/断言）+ `.Asserter`（断言器）；三者与第三方模块**同构同路径**（ADR-0027 Q2-3），保证实证保真度。

| 判据 | 测试方式（T1） | 通过标准 |
|---|---|---|
| **AC-1** 新增模块 Core 零改动 | 新增 `DataGenerator` 模块 → 跑架构规则集 + 功能回归 | AR-12 通过 + **框架程序集的引用集与构建产物未变**（依赖图断言）+ 模块可加载、可建网、可运行 |
| **AC-2** 隔离与异常不逸出 | 故障注入：模块抛异常 / 慢消费 / 上游断流 | 异常不逸出边界且转 Issue；无关模块继续运行；下游"无输入"为合法状态（§8.2 类 a） |
| **AC-3** 在线变更 | 五类变更（建网/断网/加模块/删模块/配置改）在常驻运行中应用 | 无需重启；受影响局部重建；**模块实例与业务状态保留**（§7.3） |
| **AC-4** 保存/加载无损往返 | 组合件 round-trip（保存 → 加载 → 运行 → 再保存） | 内容逐字段等价，**含未知字段保真**（C3-3 片段保留） |
| **AC-5** 无隐藏耦合 | 多模块批量接入回归 | 新增模块不要求修改既有模块；既有模块测试全绿 |
| **AC-6** 对未知类型开放 | 接入**新契约形状**（新的定长原语组合）模块 | 框架零改动即可承载；兼容判定正确 |

**AC-1 的判定口径（Q6-1 ①）**：**依赖图断言 + 回归**
- 依赖图断言：`Core`/`Hosting`/`DataPlane`/`Core.Api`/`Sdk` 的**引用集**与基线一致（新增模块不得引入新引用，更不得被反向引用）；
- 回归：既有测试全绿 + 新模块功能测试通过；
- **不采用** IL/二进制级基线比对（成本高、误报多），也不依赖人工改动面检查。

## 6.6 纪律与边界

- **不做**框架级 MCU 式单元测试（纪律 C1）；框架机制以**组合级**（参考组合）验证为准。
- **不设覆盖率百分比**（ADR-0025 §6）：以"机制改动必须有组合级验证"为判据。
- **警告即错误**（`TreatWarningsAsErrors=true`）在测试项目同样生效；测试专用豁免（如 `CA1707`）以 `NoWarn` + 理由登记。
- **不做一次性原型**（纪律 C3）：测试代码属常备基础设施（参考组合/桩模块），不是原型。
- **许可门禁**（`tools/audit-licenses.ps1`）覆盖测试依赖（含 xUnit/Shouldly/NSubstitute/BenchmarkDotNet）。

### 6.6.1 简单快捷原则（用户要求的具体落实）

| 原则 | 落实方式 |
|---|---|
| 快 | 常规门禁只跑 `Tests` + `Tests.Reference` + `ArchitectureTests`；**基准测试不进常规门禁**（按需运行，§6.7 推荐 ①） |
| 简 | 优先**表驱动**测试（契约矩阵、建网规则 R0–R6），避免为每个组合写一个测试方法 |
| 只验主要问题 | 自动化聚焦六项判据（AC-1~6）与四类机制（ChangeSet/增量重建/持久化/丢弃与停止）；**不追求边界穷举** |
| 做不到就跳过 | UI 自动化（T8）v1 不做；视觉形态（Gate C）由原型与手工验证 |
| **用户侧验收** | **UI 应用层面由用户手工验证**：实现阶段须交付**可执行的手工验收清单**（步骤 + 预期结果 + 判据映射），覆盖模块加载、拼接、建网/连线、配置修改、保存/加载、持续运行观察。**【修订 · ADR-0034】**清单须包含**可"戳"的测试模块**（手动数据发送器 + 信息显示模块），否则用户无法独立验证链路 |

### 设计方推荐项（C6-1~C6-4，用户授权推荐 · 见 ADR-0032）

| 编号 | 问题 | 推荐 | 理由 |
|---|---|---|---|
| **C6-1** | 源码类规则是否保留 | **保留（两类规则分走两套手段）** | 依赖类规则（AR-1~12）用程序集元数据，能查间接依赖；源码类规则（AR-13~16：业务词汇、命名空间一致、排除清单、公开 API 签名）**程序集元数据无法表达**，而实现成本极低（数十行扫描）。**全部改成程序集检查会直接丢掉两条有价值规则** |
| **C6-2** | 基准测试项目 | **新增 `HYWDebugAssistant.Benchmarks`，但不进常规门禁**（`build.ps1 -RunBenchmarks` 按需运行） | 满足"简单快捷"：日常构建不受基准拖累；Gate B 数值实测（`04a` §5）有明确承载 |
| **C6-3** | 资源释放无泄漏验证 | **计数断言为主 + 少量关键点弱引用断言** | 计数断言（活动线程/队列/池计数归零）稳定、不 flaky；弱引用断言只在关键路径（实例移除后缓冲/绑定回收）使用，避免 GC 不确定性导致测试不稳定 |
| **C6-4** | 桩模块是否声明视图 | **只声明少量（数值 + 曲线）** | v1 无 UI 自动化时，把 18 元素全塞进参考组合只会稀释 T1 的判据焦点；其余元素的验证交给 Gate C 原型与用户手工验收 |
