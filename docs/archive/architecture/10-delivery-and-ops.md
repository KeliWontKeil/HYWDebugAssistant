## 1. 分发形态

| 项 | 约定 |
|---|---|
| 形态 | **便携包**（zip）：解压即用；**不做 MSI、不做安装程序、不做卸载程序** |
| 目标平台 | Windows（x64）；其他平台不作为 v1 交付目标 |
| 目录布局 | `App\`（`HYWDebugAssistant.App.exe` 与依赖）· `modules\`（随包内置模块）· `logs\`（运行时生成）· `settings.json`（首次运行生成）· `THIRD_PARTY_NOTICES.md` |
| 运行时 | **依赖 .NET 10 桌面运行时**（不发布 self-contained，避免包体过大；若目标机器无运行时 → 启动时给出明确提示与下载指引） |
| 首次运行 | 无向导（明确不做首次引导）：直接进主界面；`settings.json` 与 `logs\` 按默认值生成 |
| 版本标识 | 程序集版本 + 关于界面；模块包各自携带版本三元组 |

## 2. 日志文件策略

| 项 | 约定 |
|---|---|
| 位置 | 应用目录下 `logs\`（便携语义，与设置同目录） |
| 文件名 | `app-YYYYMMDD.log`（**按日期滚动**） |
| 保留 | 最多保留 **最近 7 个文件**；超出自动删除最旧 |
| 格式 | 文本单行：`时间 \| 级别 \| 层 \| 对象 \| 事件 \| 详情`（便于人工 tail 与 grep） |
| 写入 | 框架内置极简 sink（ADR-0024）；追加写；单文件超 **32 MB** 立即滚动 |
| 级别 | 由应用级设置控制（默认 `Info`）；`Trace/Debug` 仅诊断开关打开时写入 |
| 热路径 | **不逐单元写日志**：用计数 + 定时汇总（`04` §4.7 L4） |
| **未处理异常兜底** | AppDomain 未处理异常 / 任务未观察异常 → ①写日志（含堆栈）②转 Issue（归属"框架"）③**不静默崩溃**：给出提示并保留现场日志 |
| 崩溃转储 | **不做**（v1 明确不做 dump） |
| 多实例 | 多实例同时运行时各自写同一日志文件会交错——**允许**（单行原子追加，不影响可读性）；文件名不做 PID 区分 |

## 3. 错误呈现规范

### 3.1 呈现渠道

| 渠道 | 内容 |
|---|---|
| **对象标注** | 出问题的对象（实例/口/网络/配置项）上显示角标或状态色（`09` §7 状态语义） |
| **Issue 面板**（`FrameworkUi`） | 汇总列表 + 过滤（按归属对象/类别/来源）；默认**轻量不打扰** |
| **轻量提示** | "该缓冲持续为满""处理速度跟不上输入"等事实陈述（`04` §4.11）：低饱和、可忽略 |
| **日志** | 全量细节（不弹窗） |

### 3.2 文案规范

**结构 = 事实 + 影响 + 建议动作**，例如：

```text
✗ 差：Error 0x1F
✓ 好：模块「串口 #1」未在期限内停止（已超时 5 s）· 该模块线程已放弃等待，其资源已释放
      建议：检查该模块是否有阻塞的硬件调用；可在设置中调大「停止超时」
```

| 规则 | 说明 |
|---|---|
| 不出现错误码 | v1 **不做错误码体系**（主文档 §18.4）——用可读描述 |
| 说清归属 | 指出是哪个模块/口/网络/配置项 |
| 说清影响 | 是否影响其他部分（大多数情况：**不影响**） |
| 给可执行建议 | 能做什么（重试/重建实例/改配置/查看日志） |
| 不判断用户意图 | 描述事实，不替用户决定（`04` §4.11） |

### 3.3 分级与打扰度

| 级别 | 打扰度 | 示例 |
|---|---|---|
| 信息 | 无（仅日志/诊断层） | 模块加载成功、网络建立 |
| 注意 | 轻提示（诊断层/角标） | 缓冲持续为满、上游无数据 |
| 错误 | Issue 面板 + 对象标注（**不弹模态框**） | 模块异常停机、组合件加载失败 |

**禁止**：模态弹窗打断数据监视；把"上游无输入"报成错误（§8.2 类 a 是合法状态）。

## 4. 第三方许可声明（NOTICE）

| 项 | 约定 |
|---|---|
| 产物 | `THIRD_PARTY_NOTICES.md`（随包根目录）——**这是 MIT/Apache-2.0/BSD 的合规要求，不是可选项**（与"不做隐私声明"不同：隐私声明是产品承诺，NOTICE 是法律要求） |
| 生成 | 由 `tools/audit-licenses.ps1` 的同一数据源导出（包名 / 版本 / 许可 / 版权行）；**不手工维护**（避免漂移） |
| 界面 | 「关于」入口显示同名精简列表（名称 + 许可 + 链接） |
| 时机 | 每次依赖变更后由门禁重新生成；发版前校验非空 |

| 交互 | 默认绑定 | 状态 |
|---|---|---|
| 打开模块清单 / Issue / 设置 / 拓扑诊断 | `M` / `I` / `S` / `T` | **M1-17 落地**（实现值；Gate C 可微调） |

| 全部置前 / 显示全部窗口 | 待定 | M1-17 新增动作 |
| 独立拖动已拼接组中的一个模块 | `Ctrl`（按住） | 已实现（修饰键，不做绑定项） |

| ~~切换连线显示/隐藏~~ | — | **随多窗口形态撤销**（ADR-0034：v1 不做跨窗口长连线） |

## 6. 多实例与残留

| 项 | 约定 |
|---|---|
| 多实例 | **允许**（不做单实例限制）；各实例共享同一 `settings.json` → **直接覆写，最后写入获胜**（可能丢失另一实例的修改，已接受） |
| 设置冲突提示 | **不做**（用户裁决：直接覆写） |
| 注册表 | **不写**（便携语义） |
| 用户目录 | **不写 AppData**（除 .NET 运行时自身行为） |
| 卸载 | 删除应用目录即完成；**无残留**（无注册表项、无 AppData 目录、无服务） |
| 内置模块 | 随包在 `modules\`；用户删除某模块目录 → 该模块进入**缺失态** + Issue（不崩） |

## 7. 与主文档 §18.4 的对应

本文件**不新增"做"的范围**，只把已裁决的"不做"与必要的合规/可诊断能力落成约定：

| 主文档 §18.4「明确不做」 | 本文件对应 |
|---|---|
| 安装包（MSI）与卸载程序 | §1（便携包）、§6（删除即卸载） |
| 自动更新通道 | §1（手动替换便携包） |
| 诊断包导出 | §2（日志文件即可，用户自行提供） |
| 隐私/遥测声明 | 无（产品自身不上报；**但 §4 的 NOTICE 仍必须做**，属第三方许可合规） |
| 单实例限制 | §6（允许多开） |
| 首次运行引导 | §1（无向导） |
| i18n / 无障碍 | 无（v1 不做） |

## 8. 裁决记录（已确认）

| 编号 | 问题 | 裁决结果 |
|---|---|---|
| **C10-1** | 运行时依赖 / 分发形态 | **两者都发**：framework-dependent（精简包，需目标机器有 .NET 10 桌面运行时）+ self-contained（自包含，开箱即用）。**关键事实**：两者共用**同一份代码与工程文件**，差异仅在发布参数（`--self-contained true/false` + RID），**不影响开发**——因此在开发稳定后于**发布阶段**一次性处理。用户裁决原话要点："如果只是发布时以不同设置发布两份，那么两者都发布"；"该问题可能是在开发完全稳定之后才需考虑，不过可以先写入文档" |
| **C10-2** | 日志保留策略 | 按 §2：**最多 7 个文件 / 单文件 32 MB 滚动**（设计方推荐；实现期可调） |
| **C10-3** | NOTICE 呈现位置 | **随包文件 + 「关于」界面**（§4） |

> 说明：C10-1 的两种发布形态在 §1 的目录布局与启动提示上需各自处理（精简包需检测运行时不存在的提示；自包含包无此需求）。
