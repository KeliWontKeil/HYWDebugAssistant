## 1. 已裁决的四项（用户 2026-09 裁决）

| 编号 | 裁决 |
|---|---|
| **R-1 表现形态** | **拼图式**：每个模块 = **一个无边框顶层窗口**；**没有任何"工作区"背景**，背景就是用户桌面；主窗口（框架外壳）是拼图的"起始点"，也是可被贴靠的一块 |
| **R-2 主窗口归属** | **`FrameworkUi` 作为外层主窗口**（持有 `Window`、菜单/工具栏/状态栏、各弹窗）；`Ui` 只提供**模块区控件**（依赖方向仍 `FrameworkUi → Ui`，符合 AR-8） |
| **R-3 弹窗化** | **Issue / 设置 / 模块清单（加载与管理）/ 拓扑诊断** 一律为**按钮打开的弹窗**；主窗口不再常驻 TabControl 侧栏 |
| **R-4 建网交互** | **唯一建网机制 = 口上的网络标签同名即连**；**删除"连接管理"操作界面**；"端口唯一 ID 与连接关系"作为**调试信息**保留，形态**与 Issue 同级**（只读诊断视图）。快速建网 R0 仍作为"加入模块时自动连好"的便利默认 |

**授权**：用户已**明确授权修订**主文档 §10.1-2「Module ≠ Window」（拼图形态必需）→ 由 ADR-0034 正式修订。

## 2. 形态规格（R-1/R-2 落地）

### 2.1 窗口与拼接

| 项 | 规格 |
|---|---|
| 模块窗口 | `SystemDecorations=None`、`ShowInTaskbar=false`、`CanResize=false`、无标题栏（**完全无边框**） |
| 拖动 | 按住**边框区域**拖动即移动该窗口（自定义拖动：跟踪指针 → 设 `Position`，**拖动过程内实时吸附**） |
| 缩放 | 边框的**边中点/角点**为缩放热区（Office 直觉） |
| 吸附 | 复用现有几何吸附引擎，坐标由"画布坐标"改为**屏幕坐标**；贴合容差仍 8 px（Gate C 可调） |
| 整组拖动 | 拖动开始时按贴合关系求连通分量并冻结 → 整组窗口同步位移 → 结束后重算（C5-1 六条约束不变） |
| 锁定 | 每个窗口提供 **锁定/解锁** 按钮；锁定后**禁止拖动与边框选中**（可继续显示数据） |
| 按钮簇 | **锁定/解锁 · 隐藏 · 关闭** 三个小按钮置于同一处（建议右下角，悬停/选中时出现；Gate C 定位置与图形） |
| 主窗口 | 外壳窗口同样可被模块贴靠（拼图"起始点"）；其自身可移动/缩放（系统边框保留，因为它是外壳不是元件） |

### 2.2 边框交互细节（待你确认的两个数值）

| 项 | 建议值 | 说明 |
|---|---|---|
| 边框热区宽度 | **6 px**（Gate C 可调） | 边框内 6 px 为交互带：边中点/角点 12×12 为缩放手柄，其余为拖动带 |
| 选中态 | 点击边框带 → 显示手柄与按钮簇（主色 1 px 边框 + `overlay.selection`） | 内容区点击**不触发选中**，避免与模块内交互元素（按钮/滑块/输入）抢事件 |

> **与 `09` §5 的冲突**：原基线规定"模块标题栏高 24 px"。拼图形态下无标题栏 → **模块名与状态改为**：默认在内容区顶部以一行轻量文本呈现（12 px、弱化色），可在模块声明中省略；状态点并入该行右侧。`09` §5 需相应修订。

### 2.3 连线与标记（R-1 的直接后果）

| 项 | 规格 |
|---|---|
| 口上标记 | **保留**（§6.3"网络表现依附于口"）：模块窗口边缘的小块 = 口名/网络名（弱化）+ 方向箭头 + 连接状态点 |
| 跨窗口长连线 | **不做**（v1）。原因：点击穿透透明覆盖窗需 Win32 互操作（`WS_EX_TRANSPARENT|LAYERED`，Avalonia 未提供），且需处理全局 z-order（必须位于模块窗之上、弹窗之下，并在应用失活时随之下沉）、动态改大小的闪烁、以及跨显示器不同 DPI 的坐标/缩放一致性 |
| 替代表达 | ① **选中/悬停高亮**同网络成员（§10.4 的聚焦高亮）；② **拓扑诊断视图**（R-4）列出每条网络与其成员（`实例ID.口名`） |
| 覆盖窗（后续可选增强） | 若将来仍要跨窗口长线：**建议全屏覆盖窗**（而非跟随包围盒动态改大小），并把 z-order/DPI/失活下沉三件事一并设计；记为 Gate D 候选 |

> **与 §6.3/`05` §5.5 的冲突**：原基线有"连线层（默认隐藏、热键切换、有向流动样式）"。多窗口形态下 v1 以"口上标记 + 高亮 + 拓扑诊断"替代 → 需一并修订该条。

## 3. 界面结构（R-2/R-3 落地）

```text
FrameworkUi（外层主窗口：持有 Window）
├─ 菜单/工具栏：模块清单 · Issue · 设置 · 拓扑诊断 · 显示开关（分类见下）· 锁定全部
├─ 主体：**无背景**（= 桌面可见；模块各自是独立窗口，不画在这里）
└─ 状态栏：模块数 · 运行状态摘要 · Issue 计数（可点击打开 Issue 弹窗）

弹窗（按钮打开；非模态优先）
├─ 模块清单/加载（可用模块 · 加入现场 · 移除 · 启停）
├─ Issue（汇总 + 四项过滤）
├─ 设置（应用级设置全项）
└─ 拓扑诊断（**只读**：网络 → 成员（实例ID.口名）、方向、状态、投递/丢弃计数）
```

**开关分类（意见 4 的修正）**：

| 分组 | 内容 | 位置 |
|---|---|---|
| 显示 | 连线/标记的表达开关（v1 = 口上标记显示、聚焦高亮） | 工具栏「显示」组 |
| 交互 | 几何吸附（开/关 + 按住 Alt 临时停用） | 工具栏「交互」组（或并入设置，Gate C 定） |
| 窗口 | 锁定全部 / 解锁全部 | 工具栏「窗口」组 |

> `Ui` 不再持有主窗口 → `MainWindow.axaml` 从 `Ui` 移到 `FrameworkUi`；`Ui` 对外只暴露模块区相关控件与服务（`IFrameworkPanels` 宿主契约可撤销或改名，因为方向反过来了）。

## 4. 建网与配置（R-4 + 意见 3 落地）

### 4.1 建网

| 项 | 规格 |
|---|---|
| 唯一机制 | **网络标签同名即连**：在口标记上（双击/就地编辑）填写网络名；两个口的网络名相同 → 框架按"发送口为源、接收口为宿"**自动建立/加入同一网络**；名字不同 → 不连 |
| 匿名直连 | 由**快速建网 R0**产生（加入模块时自动匹配未连接口），不提供手写"匿名"的入口 |
| 撤销 | 清除口上的网络名即退出该网络；网络无成员时自动消失 |
| 诊断 | 拓扑诊断弹窗（只读）显示网络与成员唯一 ID（`实例ID.口名`）——**这就是你要的"调试信息"，形态与 Issue 同级** |
| 删除 | 「连接管理」界面（源口/宿口下拉 + 建立网络 + 断开）**整体删除** |
| 短路数据模块 | 仍作为**普通内容模块**可选提供（§6.3"带逻辑的结构操作 = 普通内容模块"）；v1 暂不提供，列入后续清单 |

### 4.2 配置编辑（意见 3）

| 项 | 规格 |
|---|---|
| 有 UI 的模块 | 配置编辑**在模块视图内**（C5-4）：由框架按 **配置 Schema 自动生成表单**（数值/文本/布尔/枚举/文件路径），模块声明中可选放置 `ConfigurationEditor` 元素 |
| 无 UI 的模块 | 管理视图兜底：显示**同样由 Schema 生成的表单**（不再是 JSON + 类型全名） |
| 需要的能力 | `Core.Api` 暴露"实例配置的 **Schema + 当前值**"（字段名/类型/取值范围/可选项/分组标题）与"按字段写回"；实现走 L4 变更入口（保持原子性） |
| 不再展示 | `ModuleId` 字面量、配置类型完整名、口字面量（除**拓扑诊断**这一处调试视图外，界面不出现代码化标识） |
| 实例清单 | **删除**"已实例化"清单（K-3：画布上看得见模块即已实例化）；管理视图只列**无 UI 模块**（兜底入口） |

> **说明**：Schema 表单需要"配置 Schema"这一概念落地——设计上 Q3-4 早已冻结"配置 = C# 类型 + 源生成"，但**尚未把 Schema 暴露给 UI**。本步要补的就是这条通道（`Core.Api` 新增只读 Schema + 按字段写回）。

## 5. 开发/测试用模块（意见 7）

新增两个参考桩模块（与既有三个同构同路径，只引 `Sdk`）：

| 模块 | 口 | 视图 | 配置 | 用途 |
|---|---|---|---|---|
| **手动数据发送器**<br>`hyw/reference-manual-sender/1.0.0` | `out`：`{seq:u64, value:f32}`（与发生器同形状，便于与任何接收端互通） | A1 数值（当前值/已发送数）+ B5 文本输入（值）+ B2 命令按钮「发送一次」+ B2「开始/停止连续发送」 | 值、发送周期、是否连续 | **人来戳**：输入一个值 → 点一下 → 看下游反应 |

## 10. 实施结果（M1-15 · 代码已落地，待用户验收）

### 10.2 实现期的**有意偏离**与取舍（均已在代码注释与 ADR-0035 记录）

| # | 设计原文 | 实现 | 原因 |
|---|---|---|---|
| A | §5：手动发送器视图含 **B5 文本输入 + B2 命令按钮** | 视图为 **A1 数值 + B1 配置表单**；"发一次"= 单次模式下写一次配置 | B2/B5 需要**新增 SDK 面**（命令与输入通道），须单独设计批准 → 登记为开放项（§10.3-①）。配置写入通道已能满足"人来戳"的验收目标 |
| B | §5：信息显示模块配置含 **日志条数** | 配置为 **日志密度（LogEvery）+ 是否发布曲线 + 总开关**；日志行按**定长 48 字节**发布 | 订阅环容量是**框架常量**（512）而非实例配置项；"条数"不是模块能决定的事（§10.3-②）。定长是框架要求（同一数据源样本长度一致） |
| C | §2.1 组拖动 + 吸附以"屏幕坐标" | 几何**存物理像素**；窗口宽高（DIP）按各自 `RenderScaling` 换算 | 窗口位置本身是 `PixelPoint`：同一单位空间里比较才自洽；跨显示器不同 DPI 的**尺寸**换算按各窗口缩放，风险点 ② 仍属 Gate D 复核项 |
| D | §2.1 "拖动过程内实时吸附" | 拖动中吸附 + 辅助线；**不再有"画布边界钳制"**（原实现有），改为**屏幕工作区与外壳窗口参与吸附** | 无画布即为桌面：越界不该被"钳"（多显示器下更是合法位置）；"贴住外壳/不跑出工作区"由吸附表达 |
| E | §2.1 锁定 | 锁定为**会话内交互状态，不持久化**（不进组合件） | 设计只定义"锁定后禁止拖动与边框选中"；把锁存进组合件会让"文件携带 UI 会话状态"，属新增持久化语义 → 需要时再立 ADR |
| F | §3 外壳"主体无背景 = 桌面可见" | 外壳窗口 `TransparencyLevelHint=Transparent` + 主体透明 Border（工具栏/状态栏为不透明 chrome）；**保留系统边框** | 直译 R-1/R-2 与 O-6：外壳是拼图起点、不是容器；透明主体同时保证"点得到、能拖动（系统标题栏）" |
| G | §3 快捷键（`10` §5 清单） | Shell 窗口内绑定：`M/I/S/T` 开四个弹窗 · `L` 口标记 · `G` 吸附 · `Ctrl+L` 全部锁定 | Gate C 前的临时取值，已写入"帮助 → 快捷键"与验收清单 |
| H | §4.2 "配置编辑需要的能力：`Core.Api` 暴露 Schema + 当前值与按字段写回" | 已实现（ADR-0035 D1）；**附加**：`Read<T>` 首次读登记默认配置、配置 JSON 允许 ±Infinity/NaN、枚举按名字 | 实施中发现原实现的**真实缺陷**：只读配置的模块在保存时会丢配置，且无对象可生成表单（ADR-0035 D3/D4） |

### 10.4 用户第二轮评审的三项修正（**已实现并回写**）

> 用户在拿到 M1-15 实现后实测，提出三条意见；**三条全部成立，其中两条属我的理解错误**。下表为判定与处置。

| # | 用户意见 | 判定 | 处置（已落地） |
|---|---|---|---|
| 1 | 无法加载模块：选 `src\Modules\Reference\Monitor` 报"实现程序集不存在"；且"内置模块应启动时自动加载" | **我实现错了（两处）**：① 提示只说程序集名，**不给查找路径**，也不提示"源码目录不是模块包"；② 参考模块**没有内置**——来源目录默认为空，用户必须先自己找路径 | ① 载入失败信息改为给出**解析后的绝对路径** + 明确提示（"模块包目录必须同时含 module.json 与实现程序集；源码目录请改选 `bin\<配置>\net10.0`"）；② 新增**内置模块包目录**（应用目录 `modules\`，由 `build.ps1` 的归拢步骤产出、`CompositionRoot` 启动默认扫描）→ **五个参考模块开箱可用**；③ 模块清单弹窗加"包目录提示"；④ 新增自动化：`组合根_应默认装入应用目录下的内置模块包`（把包目录模拟成发布形态后断言装入 5 个） |
| 2 | "无界面模块"是什么？所有模块都应有一个"界面"（可以没有可操作对象，但起码要有一个空窗口） | **我理解错了**：把"未声明视图"当成了"没有窗口"，并据此造出"无界面模块"这一**例外概念**与一个管理清单 | ① **撤销"无界面模块"概念**：每个实例**一律开窗**；② 未声明视图 → 窗口显示模块名行，并由**框架补上配置表单**（无配置则说明原因）；③ 声明了视图但**没有 B1 元素**的模块（如参考数据发生器）也由框架补上表单 → "配置编辑在模块视图内"对**所有**模块成立；④ 窗口按钮簇增加「**停/启**」（运行/停用）→ 运行、锁定、隐藏、移除、配置**全部在模块自己的窗口**上完成；⑤ 模块清单弹窗删掉整个"无界面模块"区（只留 可用模块 + 占位实例） |
| 3 | 外壳那块"奇怪的透明部分"仍然像某种"工作区" | **我理解错了**：为直译"主体无背景"而留了一个**大块透明主体区域**，结果制造出一个"隐式工作区"的观感，正是用户最初要消除的东西 | 外壳改为**一条工具条**：`SizeToContent="Height"` + `CanResize="False"`，窗口高度 = 菜单 + 工具栏 + 状态栏，**不存在主体区域**（原透明主体与其提示文本删除，提示移入「帮助 → 快捷键」）；外壳仍保留系统边框、仍可被模块贴靠（O-6） |
