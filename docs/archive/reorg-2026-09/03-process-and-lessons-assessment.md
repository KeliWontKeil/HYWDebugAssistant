### 2.2 通用工程纪律（抽象、可复用）——**应移出本文件**

下面每一条都可以脱离本项目使用。**括号内 P 号为来源**。

**A. 构建与工具链**
1. 外部环境变量会污染构建配置解析；门禁脚本应**启动即清理/固定**，并把"建议在系统层删除"写进提示。（P1）
2. 运行中的宿主进程（设计器/预览器/应用实例）会**锁定构建输出**；工具应**先检测、快速失败并给可操作提示**，而不是让构建重试十次后失败。（P2、P36 的"内存领先于落盘"是同一族的运行时侧版本）
3. 脚手架/模板的默认依赖**必须过许可审计**——模板作者的选择不是你的选择。（P3）
4. 严格风格开启后，**模板生成的代码也必须一并修**，否则门禁第一次就红。（P5）
5. 规则与既有约定冲突时，用**局部豁免 + 注明原因**，不要关掉规则本身。（P4、P6）
6. 某些子系统的警告**不受"警告即错误"约束**（如标记语言），必须**单独看日志**，否则永久漏掉。（P13）
7. **禁止用脚本对源码做字符串手术**（数组/正则语义陷阱会静默损坏文件）；改写源码一律用编辑器或结构化工具。（P14）

**B. 依赖与契约面**
8. 给公开构造器**加可选参数 = 改方法签名 = 二进制破坏**；新增"可选声明"用属性；**改公开面后必须重编全部消费方**，并把这一步纳入验收前检查。（P30）
9. 引第三方包前**核对它依赖的框架大版本**；落后一个大版本 = 运行时不兼容风险；框架大版本移除的 API 要靠编译错误清单清理。（P26、P10）
10. 约定优先的自动装配（按命名约定找实现）**必须只在"约定目标确实存在"时生效**，否则会拦下显式声明。（P11）
11. 许可自动识别必然有漏（许可文件型、仅有 URL 型）——需要**豁免清单 + 证据**机制。（P7）
12. 缩小可见性会破坏测试访问；用显式的"对测试可见"声明并登记原因。（P8）

**C. 数据与状态建模**
13. 序列化默认值会**拒绝特殊值/把枚举写成数字**；显式配置 + 兼容旧文件的读取策略是必需的。（P15）
14. 凡"框架/上层按对象取数据"的接缝，都要有明确的**"对象从哪来"的登记规则**（否则整块数据静默丢失）。（P16）
15. **可推导的状态一律派生，不要另存**——否则标志与成员各说一套。（P41）
16. **"同一个值"≠"同一个事实"**：用相等判断"状态有没有变化"前，先确认被比较的对象**携带了那个差异**；携带不了就把差异**显式建模**（对称性检查：一侧有、另一侧没有的结构，通常就是缺的那半）。（P42）
17. **同一语义写两遍必然分叉**——抽成唯一实现；"看起来正常"的静默数据损失是最贵的一类缺陷。（P43）
18. **格式迁移 = 读旧写新 + 清旧字段 + 升版号**；迁移前先写"旧文件加载"用例；两字段并存时以新字段为准并报警，不猜测。（P44）
19. 一个"成功/失败"背后有**性质不同的原因**时，返回值用**枚举**；"成功但丢了点什么"的返回值必须带出那份损失。（P45）
20. 捷径/缓存状态必须能回答"**读错了会怎样**"，且答案是"**只慢不错**"；答不上来就别加。（P46）
21. **观测型指标必须可重复读（幂等）**：区分"事件"（消费一次就没了）与"观测"（可被任意多个消费者读）；凡"读的时候才算"的指标都要问"同一次刷新读两次会怎样"。（P61）
22. **身份必须由框架/模型给出**；显示名（可空、可重复）永远不能当键；高频刷新路径**一律不抛**（宁可少显示）；修一处后**全仓搜同款写法**。（P40）
23. 一个"成功/失败"别挤布尔（同 19）；"还没有基准"的度量宁可返回 0/未知，**不要估算**。（P45、P61 同源）
24. 泛型容器里的值语义类型（结构/元组/记录结构）**取出后是副本**，改动必须写回；"半引用半值"的复合类型最危险——**部分生效会掩盖部分失效**，判据必须断言那个会静默失效的字段。（P49）
25. **新增字段的同一笔改动里必须写完生产者与消费者**；测试断言"**来源/一致性**"而不是"某个具体值"；没有消费者的数据、没有生产者的字段都是死代码。（P50）
26. **值语义类型里含集合/数组/字典时，默认相等不可靠**——需要值语义就自己写比较，并为它写一条专门用例（否则它一直靠巧合通过）。（P48）

**D. 刷新、集合与命中**
27. 周期性刷新**重建集合**会拆掉用户正在交互的控件（悬停/弹窗状态归零）——区分"刷新数据（改属性）"与"重建视图（动集合）"。（P63、P17）
28. 列表行模型用**值语义**（否则无法判断"有没有变"，只能退化为重建）；列表用**增量同步**，并断言"数据未变时行实例引用必须相同"。（P18、P17）
29. **查询路径不做 IO**（会被每帧调用）；这类判定**扫描时算一次并缓存**。（P19）
30. **每个可交互控件都必须有真实落点**；新增开关要能指出"谁读它"——"死开关"比崩溃更糟（用户以为功能坏了，且不报错）。（P27）
31. **命中优先级决定可用性**：层级固定，手柄类只在选中时可命中，"唯一入口"类控件必须在最上层；同时**"看得见"是功能的一部分**（对比度/字号/被压掉几个像素都会让用户以为功能不存在）。（P28）

**E. 几何、坐标与交互**
32. 自绘要换算坐标系：物理像素 ÷ 缩放；原点取客户区；根容器裁剪。（P23）
33. "外框矩形"与"客户区矩形"是**两个矩形**；要客户区就用"客户区原点 + 客户区尺寸"（同源取值）。（P24）
34. **零尺寸的几何会被校验过滤**——"边缘/线"要用**专门通道**表达，不要用零宽矩形。（P25）
35. 参照基准要取**用户看到的那条边**（可见外框），而不是内部可计算的那条边（客户区）。（P35）
36. **像素几何只有一个量化口径**；并且**只由驱动者写模型**（交互中被指针带着走的成员不要被刷新回写）。（P32）
37. **判定必须用"事件发生前"的几何**——用移动后的坐标判"谁贴着谁"，会把条件悄悄改成"位移足够小才成立"；**把'移动前的值'做成显式参数**传进去，才不会在第二处再犯。（P33）
38. **别拿"被自己移动的对象"当输入基准**（自反馈 ⇒ 正回授振荡）；"只在一个方向出现"的抖动往往就是线索——那个方向正是我们自己动过的方向。（P34）
39. "内存领先于落盘"的成员，**刷新一律让路**。（P36）
40. **吸附要有粘滞 + 双向阈值**；候选要**分级且跨级不比较**；**同坐标去重**；删除"按缝隙大小猜方向"这类启发式。（P31）
41. 贴边绘制会被自己的裁剪吃掉——**"没画"与"画了看不见"要分开**：可见性判据要容忍贴边超出，绘制时按"线宽/2"内缩，**两条一起改**。（P37）
42. **留白是几何参数**：先算最坏情况下"从 X 画到 Y"的实际长度再定留白，并写进几何用例；极窄尺寸要有明确退化策略。（P51）
43. **连线 = "两点 + 一裁"**：需要"方位分类 + 特判"通常说明几何选错了；一条规则若要用两套推断才能讲清，它就不是简单规则。（P52）
44. 几何函数**要么全用世界坐标、要么全用局部坐标**；跨窗/跨层一律经**显式换算函数**；几何用例失败时**先怀疑输入坐标的口径**。（P55）
45. **尺寸/坐标只能有一个来源**：凡"两端各算一半、拼起来要对得上"的几何，必须取同一个变量；布局结果尺寸与意图尺寸不是一回事。（P62）

**F. 视图框架与渲染**
46. 标记语言里的**资源类型错误只在运行时炸**（编译期不报）⇒ 视图层必须有自动化。（P20）
47. **资源查找顺序决定覆盖是否生效**；覆盖要写在会被优先读到的那一层，并在每次应用前还原上一轮覆盖。（P21）
48. 无头/UI 测试有**框架绑定与并行约束**（依赖的测试框架版本、专属线程、需要显式推进渲染节拍）；"只跑任务不推帧"会让"单跑通过、一起跑命不中"。（P22）
49. **模板是一个命名域**：同一模板内两套分支不得用同名 `Name`（不可见的那套也算）；需要用 `Classes`/样式类而非 `Name`。（P38）
50. **自绘路径必须有断言证明"真的画出来了"**；每个公开属性都要有消费者；会画东西的控件必须显式声明"哪些属性变化要重绘"。（P39）
51. **无头测试默认是空绘制**——忘了调用绘制、画到窗外、两块叠字，**断言一律看不见**；必须另有一条"真实渲染成图片"的路径，且这类会话要**按进程隔离**（框架的渲染配置是进程级的）。（P54）
52. 依赖渲染引擎语义的东西（虚线相位与其单位、渐变端点、字体度量、像素对齐）**先写能测量的探针**；量**单调可测的量**，并把探针留在测试里当文档。（P58）
53. **静态 / 单例 / 进资源字典的对象要当作跨线程共享**（线程亲和性）；"**单独跑绿、一起跑红**"先怀疑**共享可变状态**，而不是测试本身。（P47）
54. **第三方控件的"自带模板"不会自动生效**；"控件不出现"按"**有没有模板 → 有没有尺寸 → 有没有被裁/被盖**"排查；每个自绘/第三方控件都要一条"出像素"判据。（P65）
55. 同类交互出现**第二遍就抽公共件**，抽的时候**顺手删旧路径**；"精简"是公共件的准入条件；用户说"建议做精简"是在批准**删**，不是批准**加**。（P64）

**G. 诊断与契约语义**
56. **"建议"不能混进"问题清单"**——诊断分级必须与消费方语义一致；凡是会在**自家正确样例**上报警的检查，先怀疑检查本身。（P56）
57. **"设计意图"只能声明，不能从结构反推**：派生只适合"确实是结构属性"的东西（判据 = **能否被结构唯一确定**）。（P57）
58. 信息**归属于它所描述的对象**：决定"这行字写在哪"之前先问"它在说谁"；两个维度的数字挤进同一个控件，用户必然读成同一个意思。（P59）
59. **两套"看起来都像键"的标识是静默归零的高发现场**：先用一条端到端断言把数值钉住；"**查不到 ≠ 数值为 0**"必须分开表达。（P60）
60. **指标来源唯一要落到"只有一个写入点"**；删第二来源时，顺手检查"它是不是还承担了刷新时机 / 口径统一"。（P53）

## 4. 专项：`implementation/04` 的形态结论

### 4.1 它应该保留成什么形态

**结论：保留为"用户手工验收清单"这一独立文档类型，但必须满足四条形态约束。**

| 约束 | 具体要求 | 理由 |
|---|---|---|
| ① 只承载"人眼可判"的内容 | 每条 = **编号 ｜ 操作 ｜ 可观察预期 ｜ 结果☐**。预期必须是"用户能看到/能做到的现象"。 | 它的存在理由就是"自动化覆盖不到的应用层行为"（L5）；写实现细节会让它变成第二份设计文档 |
| ② 与实现/历史解耦 | 删除 ADR 编号、类名、字段名、轮次编号、"以前是这样现在是那样"、修订版沿革段 | 验收人不需要知道实现；旧做法与现行预期并排正是 §6.4 禁止的形态 |
| ③ 显式生命周期 | 里程碑收尾 → 冻结归档为"**Mx 验收记录**"；下一里程碑**另起新文件** | 现在它靠"修订版 N"在同一文件上叠加（已到修订版 9 / 111 条），这是膨胀的根因 |
| ④ 与自动化挂钩 | 每条形如"**已由自动化覆盖（保留人工复看）**"或"**仅人工可判**" | 能算出"手工验证净工作量"，也能看出自动化该往哪补（例：#62 列表不闪、#100 渲染快照已有自动化兜底） |

### 4.2 保留价值最高的部分（不要一起精简掉）

- **§0 准备步骤**（先跑完整门禁 → 再启动应用，且提示"需先关闭应用"，L27–34）——**把环境前置写进验收步骤**，很实用。
- **"标 ⭐ / 🆕 表示新增或改写"的标记约定**（L11）——只要清单还有增量维护，这个约定就该留。
- **§4 验收结论表**（L229–241）：验收人 / 日期 / **门禁基线（并注明"实际数字以该次为准"）** / 未通过条目（逐条列 # 号与现象） / 意见与待办 / 通过·有条件通过·不通过三选一。
- **J/K/L 三组**（多源与格式迁移、多源链路与类型身份、叠加层角色投影）中的**边界语义判据**：如"1 源 → N 宿 = 广播，每宿一份独立拷贝"、"N 源 → 同 1 个宿口 = 按到达交织，不排序/不去重/不仲裁/不告知来源"、"形状不同 ⇒ 不建立投递"、"版本不同 ⇒ 拒绝"、"schemaVersion 过新 ⇒ 拒绝加载并保护原文件"。
  这些是**用户级语义契约**，虽然写得很细，但**恰是"自动化覆盖不到"的部分**，且是产品语义。**建议保留，但把措辞从"实现口径"改写成"用户可观察行为"**（例如："同一宿口上不会出现两种长度的数据"而不是"尺寸/字段/顺序必须全同（ADR-0051）"）。
