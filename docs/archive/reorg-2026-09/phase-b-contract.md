## 2. 写作纪律（违反任何一条都会被退回）

1. **只搬现行值**。来源里凡是"当时怎么想 / 第一版是 / 后来发现 / 本轮改成"这类过程叙述，**一律不写**（历史已归档）。
2. **不得发明、不得"顺手优化"、不得外推**。你只能整理与压缩来源里**已经存在的结论**。来源没说的事，不许补。
3. **可追溯**：每个二级标题后面加来源标记，形如
   `## 建网两机制 〔源: architecture/18 §2.3 + ADR-0037 D1〕`。
   表格/关键数值行如需，可在行尾加 `〔源: …〕`。来源标记**保留**在正式文件里（便于审计与追溯）。
4. **一处事实只写一次**。同一数值/规则在你的文件里出现两次就是缺陷。
5. **发现冲突不拍板**：来源之间（或同一来源前后）口径不一致时：
   - 在正文该处写 `【待裁·N】口径 A：… / 口径 B：…（依据分别是 …）`；
   - 同时把该冲突追加到 `D:\project\上位机开发\.reorg\conflicts.md`（Markdown，一条一节：位置 / 两种口径 / 各自依据 / 为什么需要人裁）。
   - **判定"哪个更新"的唯一合法依据** = 来源里**显式**的取代标记（"已被 XXX 取代/作废/更新"、修订记录、`【修订】` 标注）或 ADR 编号/修订版本先后。**不许凭印象判断**。
6. **不丢信息**：若你判断某段内容"不该留在现行分册，但也没有别处承载"，**不要删，把它原样搬进** `D:\project\上位机开发\.reorg\orphans\<你的目标文件名>.md`，并在报告里点出。
   判据：**只此一处 + 对后续开发或验收仍有指导意义** ⇒ 搬 orphans；纯历史 ⇒ 归档（在报告里说明）。
7. **读者任务优先**：默认读者是"接下来要做模块开发 / 修为 bug / 调 UI 的人"。写的时候先问：他要做这件事，需要知道哪些**现行约束与数值**？据此组织章节，而不是照抄来源的章节结构。
8. **风格**：中文；Markdown；标题层级从 `##` 起（`#` 留给文件名标题）；能用表格就用表格；**不写套话与口号**；每句话都要有信息量。
9. **顶部必须有状态行**（三行，固定格式）：

```
> 状态：**现行**（本轮收敛重写；来源见各节标记）
> 适用范围：<一句话，这份文件管什么>
> 与主文档的关系：主文档 `上位机架构设计.md` 是验收唯一事实源；本文件是其实现层分册，冲突时以主文档为准。
```

10. **篇幅**：不设硬上限，但要求"密度优先"。判据 = 删掉任何一段，读者会不会因此做出错误实现？不会 ⇒ 删。
