## 【待裁·4】`Disabled` 状态是否保留线程（由 `04-runtime-mechanisms.md` 提出）

- **位置**：`.reorg/new-architecture/04-runtime-mechanisms.md` §「生命周期状态机」状态表 `Disabled` 行 + §「线程、队列与停止协议」。
- **口径 A：保留线程** —— `Disabled` 的实例**保留**其专属线程，仅"停流"（投递暂停、绑定保留），线程空闲等待、不参与数据流。
  依据：`ADR-0029` 第 1 条："`Registered` 不占线程，`Disabled` 保留线程并停流，`Removed` 请求退出→有界等待→回收"；`architecture/04` §4.1 状态表（`Disabled` → 线程 **保留**、队列 **停流**）。
- **口径 B：不占线程** —— 线程**按活跃实例计**，`Disabled` 的实例**不占线程**，只有 `Active` 才分配线程。
  依据：`architecture/04a` §6"由 Q4-1 直接确定的事项"："线程数策略：**按活跃实例计**（`Disabled` 的实例不占线程；`Removed` 释放线程）"；`上位机架构设计.md` §7.3："为每个 `Active` 实例提供**专属线程 + 每 (实例, 口) 一条有界输入队列**…"（照字面，非 `Active` 即无线程）。
  同向的第三处：`architecture/04` §4.10 裁决记录 Q4-1 行"连带影响"列写作"线程按实例分配、**随 `Disabled`/`Removed` 回收**"，与其 §4.1 状态表**自相矛盾**。
- **实现现状（供裁定参考，非判定依据）**：已实现代码**禁用不回收承载者**——`ModuleRuntime` 的 Enable/Disable 路径只置生命周期状态并把相关绑定置停流（`SetSuspended`），**不调用** `Carriers.TryDeactivate`（该方法只在 Remove 路径与应用退出时调用）⇒ **行为同口径 A**；但 `src/DataPlane/Carriers/CarrierHost.cs` 的 XML 注释写的是"`Disabled` 的实例不占线程"（同口径 B）——**注释与行为不一致**。
- **为什么需要人裁**：这不是措辞差异，而是**资源语义**差异——禁用大量模块时是否释放数百个线程、重新启用是否要重新分配线程与队列。ADR-0029 与 `04` §4.1 同向（A），主文档 §7.3 与 `04a` §6 同向（B）；`04a` 虽自述"结论以 `04` 与 ADR-0029 为准"，但**未点名此条**，ADR 侧也无"已被取代"标记，故不满足契约 §2.5 的自动判新条件，不拍板。

## 05 网络语义（Network Semantics）· 文档内部集合口径

> 作者：`05-network-semantics.md` 分册作者。编号前缀 `05-` 以避免与他人编号冲突。

### 【待裁·05-1】"源集合为空"指哪个集合：未建网 还是 停流？

- **位置**：`.reorg/new-architecture/05-network-semantics.md` §10 第 1 行 / §【待裁·05-1】。冲突来源 = `docs/architecture/18-network-semantics.md` §2 M5 与 §8.1/§8.2；`docs/adr/ADR-0050-multi-source-network-and-datagram-semantics.md` §3 M5 与 §3b B1/B2。
- **口径 A：按"声明源"判 ⇒ 未建网** —— `DeclaredSources`（声明源）== 0 ⇒ **未建网**（**保留标签** + 提示"等发送端"，**网络不创建**、不占身份键、拓扑不出现该行）。
  依据：`architecture/18` §2 M5 第 1 行"源集合为空（只有宿）⇒ **未建网**（保留标签 + 提示'等发送端'）——现状语义保留"；ADR-0050 §3 M5"无源/无宿 ⇒ 未建网（等待）"。
- **口径 B：按"在场源"判 ⇒ 停流** —— `Sources`（**在场、已锚定**的源）== 0 ⇒ **停流**（网络**已存在**、`IsStalled == true`，保留声明、不投递、每源 Issue）。
  依据：ADR-0050 §3b **B2**"`IsStalled` ⇔ `Sources.Count == 0`，**不单独存**；`Sources` 为空是**合法状态**，读取方必须先看 `IsStalled`"；`architecture/18` §8.2 同款表述；`architecture/18` §8.1 又明确"`Sources` = **在场（已锚定）的源**，悬空源在 `UnresolvedSources`"。
- **冲突点**：当"**有源声明、但全部源都未锚定**"时两种口径给出**不同结果**（网络创建与否）。两份来源都只写"源集合为空"，**都没写清是 `Sources` 还是 `DeclaredSources`**。
- **为什么无法用"取代标记"机械收口**：ADR-0050 §3b 的 B1/B2 是 M5 的"**落地精化**（**不改变 M1–M14 语义**）"——它改的是 `IsStalled` 的**存储方式**（改派生量、不单独存），**并未改写 M5 第 1 行的判定集合**；B1 新增 `DeclaredSources` 时也没有回头修订 M5 的措辞。两者不构成"作废 / 修订"关系，属同一来源前后**用词同形、所指集合不同**，故不拍板。
- **为什么需要人裁**：它决定"有源声明但一个都没锚定"的网络**是否出现在拓扑 / 是否占用 `NetworkView.Key` / 是否报停流 Issue**；两种实现是两条不同路径，选错会表现为"拓扑里少一行"或"多了一行永远没有数据的网络"。

### 【待裁·10-2】依赖可复现性：是否采用 `packages.lock.json`

- **口径 A：用依赖锁文件** —— `docs/adr/ADR-0024-library-selection.md` §6（许可审计门禁·工程要求）："依赖锁文件（`packages.lock.json`）**保证可复现**"。
- **口径 B：不用锁文件，只靠中央包管理（CPM）** —— 现行工程 `Directory.Build.props` 显式设 **`RestorePackagesWithLockFile=false`**，且全仓（含各项目、`tests/`）**不存在任何 `packages.lock.json`**；版本锁定的落点是 `Directory.Packages.props`（`ManagePackageVersionsCentrally=true`），其注释自称"ADR-0024 要求**锁定版本**"。
- **依据**：文档 = ADR-0024 §6；代码 = `Directory.Build.props` L17 + `Directory.Packages.props` L4–L6 + 仓库内 `packages.lock.json` 检索无命中。
- **为什么需要人裁**：这是**显式取值冲突**（`false` 是一个决定，不是遗漏），且不能靠"取代标记"收口——ADR-0024 无修订记录触及此条，CPM 注释只声称满足"锁定版本"而非"锁文件"。它决定构建可复现性的**承担者**：若保留 A 则需打开 `RestorePackagesWithLockFile` 并把 lock 文件入库（并接受其更新流程）；若保留 B 则应改写 ADR-0024 §6 的措辞为"以 CPM 锁定版本"。
