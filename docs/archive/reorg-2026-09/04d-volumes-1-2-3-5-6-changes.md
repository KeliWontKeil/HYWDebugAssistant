## 4. `05-network-semantics.md` —— 源集合两态 + 多对多

### 4.1 §10 行 249–255（替换原 `【待裁·05-1】` 段）——**按代码收口**

- **代码核对事实**〔源: 代码 `src/Core/Composition/Network.cs`、`src/Core/Services/RuntimeServices.cs`〕：

  | 事实 | 代码 |
  |---|---|
  | `Sources` = **在场（已锚定）**的源 | `Network.Sources`（成员注释："在场是这里的定义"） |
  | `DeclaredSources` = `Sources ∪ UnresolvedSources`（在场在前、悬空在后），**持久化与展示的事实源** | `Network.DeclaredSources` |
  | `IsStalled` ⇔ `Sources.Count == 0`，**派生量、不单独存** | `Network.IsStalled => Sources.Count == 0` |
  | **不变量：声明的源（在场 + 悬空）至少一个**，否则构造抛 `ArgumentException` | `Network` 构造器（`Sources.Count == 0 && UnresolvedSources.Count == 0` ⇒ throw） |
  | 口是否入网 = **网络成员关系**（含停流网络）；未入网 ⇒ `null` | `RuntimeServices.FindPortNetwork` / `IsPortConnected` |
  | 口是否停流 = `FindPortNetwork(...)?.IsStalled ?? false` | `RuntimeServices.IsPortStalled` |
  | 停流时不建绑定、不投递；提示与 Issue 由**锚定路径**负责 | `ModuleRuntime.RebuildBindingsCore`（`if (network.IsStalled) return;`）、`ReportSourceAnchoring` |

- **改后要点（两态模型）**：
  - **未建网** = **该口不在任何网络的成员里**（`FindPortNetwork` 返回 `null`）⇔ **没有网络对象** ⇒ 这才是 §10 第 1/2 行"保留标签 + 提示等发送端/等接收端"的情形；**不占**网络身份键（`NetworkView.Key`）、**不出现在拓扑行**。
  - **停流** = **网络存在、但 `Sources.Count == 0`**（`IsStalled == true`）⇒ 网络**已创建**、**占用** `Key`（键含**全部声明源**）、**出现在拓扑里**（状态 = 停流），声明保留、不投递、每源报 Issue。
  - **"源集合为空"所指 = `Sources`（在场源），不是 `DeclaredSources`** —— 由构造器不变量推出：**"声明源为 0 的网络"在代码里不可能存在**。
  - **判据归属（两态各管一段）**：`DeclaredSources` 只用于持久化/展示/身份键；`Sources` 用于停流判定。⇒ 原口径 A（按 `DeclaredSources == 0` 判未建网）**不成立**。
  - **"有源声明但全部未锚定"的唯一结果 = 停流**（网络已存在），不是"未建网"。
- **依据**：用户裁定（按代码给出准确表述）+ 上表代码文件。
- **是否可能丢信息**：**否**。两方来源（`architecture/18` §2 M5 / ADR-0050 §M5 与 §3b B2）仍然成立，只是**判据集合被代码钉死**；§10 上表五行的判定**不变**。
