# hyw/hex-sender（HEX 发送器）

> 状态：**开发中**（阶段进度见 `../journal/modules-rulings-and-progress.md`）
> 版本：`1.0.0` ｜ 包 ID：`hyw/hex-sender/1.0.0`
> **功能角色（层①）**：**十六进制发送器**
> 一句话职责：把一串十六进制文本解析成字节发出去；单次点击 + 连续发送（开关 + 间隔）

> 填写规范：`implementation/06-module-standard-and-development-process.md`（§A 四层视角 · §B 判据 · §C 结构 · §D 大小 · §E 七阶段）。

## 1. 声明面

### 1.1 功能角色与数据角色构成（四层视角的 ①② —— `implementation/06` §A.1）

| 层 | 内容 |
|---|---|
| **① 功能角色** | **十六进制发送器**（用户能一句话叫出来的名字；一个模块只有一个） |
| **② 数据角色** | **`hex-send`**（**唯一一个**）：类型 **`RawBytes`@v1** · 入口 **无**（纯源） · 出口 **`out`** |

- [x] **α**：本角色**只有输出口**（纯源）⇒ 输入/输出同型**天然满足**；**无类型转换** ⇒ **不拆角色**
- 角色顺序：**不声明**（单角色模块无需 `DeclareFlow`）

> **为什么不与 `text-sender` 共用一个角色名**：角色 Id 只在本模块内唯一（`02-module-sdk`），且**类型标识相同已足以让两者默认互通**（ADR-0051）；角色名保留各自的语义（「这次流动的是谁」）便于叠加层阅读。

### 1.2 声明表

| 项 | 内容 | 依据 |
|---|---|---|
| **数据类型** | **`RawBytes`@v1**（**本模块自己声明**，与 `hyw/text-sender` 的标识**逐字相同**）：形状 = `StructShape(("len", u16), ("data", BytesShape(1472)))` ⇒ 契约尺寸 **1474 字节**（定长） | `03-data-protocol-and-typing`（形状即契约）· `decisions.md` **7.26**（D1 标识中性化） |
| **`len` 的语义** | **有效字节数**（0–1472），**唯一的「到哪结束」判据**；尾部**补零**只是填充，**`0x00` 是合法数据**（T10）⇒ 收方必须按 `len` 切片、禁止 NUL 截断 | `modules/hyw-text-sender.md` §1.2（同一形状、同一纪律） |
| **数据角色（层②）** | `hex-send`：一种数据类型 + 输出口 `out`（**无输入口** ⇒ 纯源角色） | `02-module-sdk`「角色声明」 |
| **端口** | `输出`：`out`（角色 `hex-send`，方向 `Send`，契约 = `RawBytes`@v1，**默认边 = 下边** —— 见 §1.3） | `02-module-sdk`「口声明」 |
| **兼容要求** | 与 `hyw/text-sender` **默认互通**（同标识 + 同形状）；与 `hyw/data-monitor` **默认互通**（同理） | `decisions.md` 4.5 · **7.26** |

**两条必过的自检**（`implementation/06` §B.1-b）：

- [x] **一个角色只有一种数据类型** ⇒ 只有一种类型在流动（`RawBytes`）⇒ 恰好一个角色
- [x] **角色的输入口与输出口同型（α）** ⇒ 纯源 ⇒ 天然满足

### 1.3 口的默认边 = **下边**（【待裁 H5】）

用户原始需求（含草图）：「**由于宽 > 高，因此网络标签横置在下边处**」。

- 端口边**没有框架惯例**（**2026-09 复裁**，`decisions.md` 7.61）：`edge` **必填**、`.json` 写什么就是什么 ⇒ 本模块**必须显式声明**，否则整份声明按硬伤忽略。
- ⇒ 本模块在包内 `view.json` 的 `frame.ports` 里**显式声明** `edge: "bottom"`（它只定**网络标签的落点**，用户仍可拖动覆盖 —— 载体见 `decisions.md` 7.60）；配套的 `hyw/data-monitor` 声明 **`"top"`** ⇒ **两个口朝向同一接触面**，四个模块才能上下叠起来连（`05` §2 的七条判定第 ② 条要求「端口挂在朝向接触面的那条边上」）。
- **同一结论适用于 `hyw/text-sender`**（其口也必须**显式声明** `edge`，当前声明为 `"bottom"`；`Auto` 已不是声明面的合法取值）：**属同一处漏项，见 `roadmap.md` §3 第 22 项（E2）**。

## 8. 已知限制

- **输入必须是十六进制**：非法字符**根本不进框**（框架隧道阶段吞掉）；**奇数个半字节**是无法表达的 ⇒ 模块**明确回报失败**（红框），不猜测、不补零（用户的「每字节两位」口径）。
- **空白只是排版**：输入里的空格/换行会被**忽略**（用户裁定「HEX 的换行不作为字符」）⇒ 想发 `0D 0A` 必须**显式写出来**。
- **单条长度 = 1472 字节**（定长契约的硬约束，同 `text-sender`）；超出由模块拆包，**接收侧表现为多条**（T14a）。
- **「间隔」的实际粒度 ≈ 20 ms**（活动周期 + 定时器分辨率）。
- **不落盘**：所有可调项都是运行期状态，重启回默认（T8 取向）。
- **【待裁 E1】多条消息未落地**（见 §3）· **【待裁 H5】口默认边**（见 §1.3）。
