# hyw/data-monitor（数据显示器）

> 状态：**开发中**（阶段进度见 `../journal/modules-rulings-and-progress.md`）
> 版本：`1.0.0` ｜ 包 ID：`hyw/data-monitor/1.0.0`
> **功能角色（层①）**：**数据显示器**
> 一句话职责：把收到的字节**显示出来**（文本 / 十六进制），可暂停、按包换行、加时间戳、清空、保存为 `.txt`

> 填写规范：`implementation/06-module-standard-and-development-process.md`（§A 四层视角 · §B 判据 · §C 结构 · §D 大小 · §E 七阶段）。
> **用户原始需求（含草图）**：「接收模块的大致布局如图二所示，我特别提示**暂停接收：当勾选后，直接丢弃接收到的数据，而不是一种在内存里存着**，当勾选了**接收换行**后，将**每一个数据包的字符串换行显示**，其他选择框顾名思义非常清楚，**按下保存后将框内文本保存为 `.txt` 文件**。只有一个角色，一个接收端口；允许拉伸模块长宽比。」

## 1. 声明面

### 1.1 功能角色与数据角色构成（四层视角的 ①② —— `implementation/06` §A.1）

| 层 | 内容 |
|---|---|
| **① 功能角色** | **数据显示器**（用户能一句话叫出来的名字；一个模块只有一个） |
| **② 数据角色** | **`monitor`**（**唯一一个**）：类型 **`RawBytes`@v1** · 入口 **`in`** · 出口 **无**（纯汇） |

- [x] **α**：本角色**只有输入口**（纯汇）⇒ 输入/输出同型**天然满足**；**无类型转换** ⇒ **不拆角色**
- 角色顺序：**不声明**（单角色模块无需 `DeclareFlow`）

### 1.2 声明表

| 项 | 内容 | 依据 |
|---|---|---|
| **数据类型** | **`RawBytes`@v1**（**本模块自己声明**，标识与两个发送器**逐字相同**）：形状 = `StructShape(("len", u16), ("data", BytesShape(1472)))` ⇒ 契约尺寸 **1474 字节**（定长） | `03-data-protocol-and-typing` · `decisions.md` **7.26**（D1） |
| **`len` 的语义** | **有效字节数**，**唯一的「到哪结束」判据** ⇒ **按 `len` 切片**、**禁止 NUL 截断**（`data` 里 `0x00` 是合法数据 —— T10）；**不静默改写**：非法/被截断的 UTF-8 序列在**字符串方向明确标出**（不静默替换成 `�`），十六进制方向永不丢 | `../journal/modules-rulings-and-progress.md`（text-sender 部分）§9.5/§9.6 · `decisions.md` 7.25 |
| **数据角色（层②）** | `monitor`：一种数据类型 + 输入口 `in`（**无输出口** ⇒ 纯汇角色） | `02-module-sdk`「角色声明」 |
| **端口** | `输入`：`in`（角色 `monitor`，方向 `Receive`，契约 = `RawBytes`@v1，**默认边 = 上边** —— 见 §1.3） | `02-module-sdk`「口声明」 |
| **兼容要求** | 与两个发送器**默认互通**（同标识 + 同形状）；**不自动转换**任何其它形状 | `decisions.md` 4.5 · **7.26** |

**两条必过的自检**（`implementation/06` §B.1-b）：

- [x] **一个角色只有一种数据类型** ⇒ 只有一种类型在流动（`RawBytes`）⇒ 恰好一个角色
- [x] **角色的输入口与输出口同型（α）** ⇒ 纯汇 ⇒ 天然满足

### 1.3 口的默认边 = **上边**

- 端口边**没有框架惯例**（**2026-09 复裁**，`decisions.md` 7.61）：`edge` **必填**、`.json` 写什么就是什么 —— 本模块若不声明，接收口就无法定位（整份声明按硬伤忽略）；声明成左边（竖排）则与两个发送器（**下边**）**朝向不同的接触面**，叠起来也连不上（`05` §2 七条判定第 ② 条）。
- ⇒ 本模块在包内 `view.json` 的 `frame.ports` 里**显式声明** `edge: "top"`（只定**网络标签的落点**，用户仍可拖动覆盖 —— 载体见 `decisions.md` 7.60）；配套 `text-sender` / `hex-sender` 声明 **`"bottom"`** ⇒ **上下叠放即可连**（「整体测试单元」的默认摆法）。

## 3.1 显示与保存的数据流（**已裁**）

```
数据口 ──► 模块（按 len 切片 + 格式化）──► 显示源（定长样本追加）
                                              │
                        ┌─────────────────────┘
                        ▼
              框架的「显示缓冲」（视图状态存储；**不清空就一直在**，容量上限见 `../journal/modules-rulings-and-progress.md` §9 M6 / roadmap 第 25 项）
                        │                                    ▲
        界面渲染（滚动回看 + 自动滚到底）          模块**回读**（保存 / 其它用途）
                                                                 │
                     框架 B6 弹保存对话框 ──► 路径 ──► 模块写 .txt
```

### 3.2 声明（包内 `view.json` · `decisions.md` **7.60**）

- **载体**：**包内 `view.json`** —— 框架级那几行（窗口尺寸 / 网络标签默认位置）在 **`frame`** 段，控件树与数据源在 **`sources` + `views`** 段；由构建规则「**存在就拷进包**」送进包。写法与键位见 `implementation/06` §C.1′ 与 `../architecture/02-module-sdk.md` 的「视图：模块只声明，框架渲染」。
- **内容**：根节点 `kind: "container"` + `layout: "grid"` + `columns ["*","*","*"]` + `rows ["*","auto","auto"]` + `columnSpacing 8` / `rowSpacing 6`；第 ① 个（显示区）= `column 0` / `row 0` / `columnSpan 3` / **`"width": { "fill": true }`** / **`"height": { "fill": true }`** / **`feedbackSource: "savePath"`**；②…⑦ 各 **`"width": { "pixels": 128 }` / `"height": { "pixels": 30 }`**（尺寸**每轴一个对象**，`pixels` / `fill` / `adaptive` 选一种，`min`/`max` 可空 —— `decisions.md` 7.58 定下的这套写法由 7.60 沿用），其中保存那个另加 **`showInlineResult: false`**。
- **视觉结果**：第一行 = **暂停显示 | 十六进制显示 | 清空**；第二行 = **数据包换行 | 添加时间戳 | 保存**；三列等宽、列内左对齐、**第一列左边缘 = 显示框左边缘**；六个交互控件**同尺寸 128×30**（清空/保存不再是一大一小 —— 根因是两处模板各自决定宽度，已按 `decisions.md` 7.58 改成「尺寸只由声明决定」）；显示区跨满三列并随窗口变高（行高 `*`）。
- **保存结果的位置**：保存按钮的就地结果行**关掉**（否则会把那一格撑高）⇒ 结果改由 `feedbackSource: "savePath"` 送到**显示区左下角**（成功显示「已保存 …（N 行）」，失败显示原因；**该控件的红框仍然照旧**）。
- **守护（两条，改坏即红）**：一条契约测试断言**声明面逐项**（元素与数据源齐全、口与角色一一对上 —— 顺序 = `children` 数组序，**只有这一处来源**，不需要第二份清单同步）；一条布局测试钉住**像素**（见 §7 ⑨）。

## 8. 已知限制

- **显示行是定宽的**（框架要求同一数据源样本长度一致，上限 **1024 字节/行**）⇒ 超过一行宽度的数据包要**拆成多行显示**（见 `../journal/modules-rulings-and-progress.md` §9 M5）；**超长文本会被截断或分行**，不是无限长的一行。
- **只在活动体跑的时候刷新**（**1 ms 轮询**）⇒ 显示有约一个定时器刻度的延迟；**高频大流量下会丢显示**（框架显示通道有界，丢最旧）。
- **暂停 = 丢弃**（用户明确要求）：暂停期间的数据**永久丢失**，不会在恢复后补显示。
- **不落盘**：4 个开关是运行期状态，重启回默认；**保存的文件是显示文本的快照**，不是「接收日志文件」（不自动滚动写文件）。
- **`HexView`(A6) 未渲染**：十六进制以**文本形式**显示（等宽观感靠文本行实现，没有地址列/网格）。
- **不是协议解析器**：只按 `len` 切片的**原始字节**显示；不做分片重组（上游拆包 ⇒ 显示 K 条，T14a）。
- **显示缓冲「不清空就一直在」**（**用户裁定 · 对齐 WinForms 的 `TextBox` 语义**）：显示文本由**框架的显示缓冲**持有，**只会被「清空」命令清掉**；界面只显示放得下的部分，**更早的内容用滚动条回看**。**边界**：缓冲**容量 20 000 行、到顶丢最旧并提示「已丢弃 N 行」**（`decisions.md` 7.31；防长跑 OOM）；**通道**侧在 ≈ **3 万行/秒**以内不丢（订阅环 512 样本 × UI 60 Hz 全量取），超出由框架丢最旧并计数（`04`）。⇒ **保存**读的是**该缓冲的全部内容**（所见即所存的完整版）；要「整场会话无损落盘」是**另一个功能**（持续记录到文件，属记录器类模块），不是本模块的「保存」。
- **主类行数超过 `implementation/06` §D.1 的约定**（**实测 569 行** > 主类上限 **450**、同时 > 单文件上限 **500**；口径含 XML 注释）：按 §D.2 登记理由 —— ① **不是「两个模块」**（B.1-a 判据不成立：一个角色、一个口、一种类型）；② 已抽出一个辅助文件（106 行，只做字节→文本）；主类里剩下的是「声明面常量 + 四段结构 + 1 kHz 主动接收（排空 + 收件箱）+ 暂停收下即弃 + 保存/回读 + 清空请求」；③ **下一步可抽的候选**（估算，本次**未做** —— 试点只动声明顺序与布局，不动业务结构）：把「保存 / 回读 / 写盘文案」整段单独成文件，即可回到上限内。⇒ 作为**下一次复盘输入**。
