## 1. 声明面

### 1.1 功能角色与数据角色构成（四层视角的 ①② —— `implementation/06` §A.1）

| 层 | 内容 |
|---|---|
| **① 功能角色** | **数据显示器**（用户能一句话叫出来的名字；一个模块只有一个） |
| **② 数据角色** | **`monitor`**（**唯一一个**）：类型 **`RawBytes`@v1** · 入口 **`in`** · 出口 **无**（纯汇） |

- [x] **α**：本角色**只有输入口**（纯汇）⇒ 输入/输出同型**天然满足**；**无类型转换** ⇒ **不拆角色**
- 角色顺序：**不声明**（单角色模块无需 `DeclareFlow`）

### 1.2 声明表

| 项 | 内容 | 依据 |
|---|---|---|
| **数据类型** | **`RawBytes`@v1**（**本模块自己声明**，标识与两个发送器**逐字相同**）：形状 = `StructShape(("len", u16), ("data", BytesShape(1472)))` ⇒ 契约尺寸 **1474 字节**（定长） | `03-data-protocol-and-typing` · `decisions.md` **7.26**（D1） |
| **`len` 的语义** | **有效字节数**，**唯一的"到哪结束"判据** ⇒ **按 `len` 切片**、**禁止 NUL 截断**（`data` 里 `0x00` 是合法数据 —— T10）；**不静默改写**：非法/被截断的 UTF-8 序列在**字符串方向明确标出**（不静默替换成 `�`），十六进制方向永不丢 | `modules/hyw-text-sender.md` §9.5/§9.6 · `decisions.md` 7.25 |
| **数据角色（层②）** | `monitor`：一种数据类型 + 输入口 `in`（**无输出口** ⇒ 纯汇角色） | `02-module-sdk`「角色声明」 |
| **端口** | `输入`：`in`（角色 `monitor`，方向 `Receive`，契约 = `RawBytes`@v1，**默认边 = 上边** —— 见 §1.3） | `02-module-sdk`「口声明」 |
| **兼容要求** | 与两个发送器**默认互通**（同标识 + 同形状）；**不自动转换**任何其它形状 | `decisions.md` 4.5 · **7.26** |

**两条必过的自检**（`implementation/06` §B.1-b）：

- [x] **一个角色只有一种数据类型** ⇒ 只有一种类型在流动（`RawBytes`）⇒ 恰好一个角色
- [x] **角色的输入口与输出口同型（α）** ⇒ 纯汇 ⇒ 天然满足

### 1.3 口的默认边 = **上边**

- 惯例（`PortEdgeResolution.Resolve`）是"**发送口在右、接收口在左**"⇒ **不声明**则本模块的接收口会挂在**左边**（竖排），与两个发送器（**下边**）**朝向不同的接触面**，叠起来也连不上（`05` §2 七条判定第 ② 条）。
- ⇒ 本模块**显式声明** `PortDeclaration.Edge = Top`；配套 `text-sender` / `hex-sender` 声明 **`Bottom`** ⇒ **上下叠放即可连**（"整体测试单元"的默认摆法）。

## 8. 已知限制

- **显示行是定宽的**（框架要求同一数据源样本长度一致，上限 **1024 字节/行**）⇒ 超过一行宽度的数据包要**拆成多行显示**（见 §9 M5）；**超长文本会被截断或分行**，不是无限长的一行。
- **只在收到数据时刷新**（20 ms 轮询）⇒ 显示有约一个定时器刻度的延迟；**高频大流量下会丢显示**（框架显示通道有界，丢最旧）。
- **暂停 = 丢弃**（用户明确要求）：暂停期间的数据**永久丢失**，不会在恢复后补显示。
- **不落盘**：4 个开关是运行期状态，重启回默认；**保存的文件是显示文本的快照**，不是"接收日志文件"（不自动滚动写文件）。
- **`HexView`(A6) 未渲染**：十六进制以**文本形式**显示（等宽观感靠文本行实现，没有地址列/网格）。
- **不是协议解析器**：只按 `len` 切片的**原始字节**显示；不做分片重组（上游拆包 ⇒ 显示 K 条，T14a）。
- **显示缓冲"不清空就一直在"**（**用户 2026-09 裁定 · 对齐 WinForms 的 `TextBox` 语义**）：显示文本由**框架的显示缓冲**持有，**只会被「清空」命令清掉**；界面只显示放得下的部分，**更早的内容用滚动条回看**。**边界**：缓冲**容量 20 000 行、到顶丢最旧并提示"已丢弃 N 行"**（`decisions.md` 7.31；防长跑 OOM）；**通道**侧在 ≈ **3 万行/秒**以内不丢（订阅环 512 样本 × UI 60 Hz 全量取），超出由框架丢最旧并计数（`04`）。⇒ **保存**读的是**该缓冲的全部内容**（所见即所存的完整版）；要"整场会话无损落盘"是**另一个功能**（持续记录到文件，属记录器类模块），不是本模块的"保存"。
