# hyw/hex-string-converter（HEX ↔ 字符串转换器）

> 状态：**开发中**（阶段进度见 `../journal/modules-rulings-and-progress.md`）
> 版本：`1.0.0` ｜ 包 ID：`hyw/hex-string-converter/1.0.0`
> **功能角色（层①）**：**十六进制/字符串转换器**
> 一句话职责：一个**离线小工具** —— 把十六进制文本转成字符串、把字符串转成十六进制文本；**没有任何端口、不参与组网**

> 填写规范：`implementation/06-module-standard-and-development-process.md`（§A 四层视角 · §B 判据 · §C 结构 · §D 大小 · §E 七阶段）。
> **用户原始需求（含草图）**：「字符串转换工具**不存在任何端口**，它只是一个应用小工具……输入 hex 转字符/字符串，输入字符串转 hex，**如果转换失败，将文本框边框显著标红**，同样可拉伸长宽，**左侧输入框有多个标签，可以储存多条不同消息，也不持久化，重启即丢**。」
> **D4 裁定（用户 · `decisions.md` 7.28）**：① **char 组与 hex 组各自一个 `TabPages`**，每个 tabpage 提供**多组文本输入区**，**不持久化，关闭模块就清空**；② **两个方向各一按钮**；③ **点按钮或敲回车**（回车走 `multilineSubmitKey`，模块不做声明）。

## 3. 视图

**结构（按 D4 裁定）**：

```
container（根）
  ├ tabs「字符」stateKey: "char-pages"（5 页；每页一个 group 作页包装 + 一个多行 textInput：char1…char5）
  ├ commandButton「转成 HEX」command: "to-hex"
  ├ tabs「十六进制」stateKey: "hex-pages"（5 页；每页一个 group 作页包装 + 一个多行 textInput：hex1…hex5，inputKind: "hex"）
  ├ commandButton「转成字符」command: "to-text"
  └ textLog「HEX 结果」data: "hexResult" · textLog「字符结果」data: "charResult"
```

> 上面是声明树（`view.json` 的 `views[].root`）；`kind` 取 schema 小驼峰键名，`input` / `command` / `data` 是**角色键**（载体见 `decisions.md` 7.60）。页签标题取页包装 `group` 的 `title`。**页内只有一个 `textInput`** —— 两个方向按钮都在**各自标签组之后**（见下表与 §9 C1）。

| 项 | 内容 |
|---|---|
| 元素 | `tabs`×2（各含 5 个页；**页内只有 `textInput`**）+ `commandButton`(B2)×2（**每组标签之后各一个方向按钮**）+ `textLog`(A5)×2（结果区） |
| 数据源 | `char1…charN`（`kind = Text`）· `hex1…hexN`（`kind = Text`）· `charResult` / `hexResult`（`kind = Text`，追加显示） |
| 写入通道 | ① 输入文本 ⇒ `SubmitInput` ② 方向按钮 ⇒ `SendCommand`（**点按钮如何拿到当前页文本，见 `../journal/modules-rulings-and-progress.md` §9 C1**）③ 回车提交 ⇒ 多行输入的提交键（**应用级设置** `multilineSubmitKey`）⇒ 同样是 `SubmitInput` ④ 结果 ⇒ `Publish`（追加）⑤ 失败 ⇒ **G3 就地反馈（红框）**打回**该页输入** |
| 渲染可行性 | `TabPages`(C2，G1 已渲染) · `TextInput`(B5，含多行) · `CommandButton`(B2) · `TextLog`(A5) **均在现行渲染子集内**（`implementation/06` §H.1） |
| 默认尺寸 | **声明 `frame.window` = 520×600**（现行声明文件的值，与 `architecture/07`「模块窗口视觉规范」一致；两组标签页 + 双结果区，属「工具类」中等偏大）。**内容下限推算**（M12 实测口径）：内容最小布局高 **432** + 上/下预留带 **46** ⇒ **485**；现行声明按余量取 **600**（早期文档写成 485，属只按内容下限落笔，已被声明文件取代）。**算式**：每组 ≈ 标签条 28 + 输入框最小高 60 + 按钮行 28 + 结果区 80 + 间距 ≈ 200 ⇒ 两组 ≈ 400 + 内边距 40 ≈ 440 ⇒ 取 420 并留余量；宽取 520 以容下「一行十六进制 ≈ 40 字符」的等宽显示。**阶段 3 后按实测微调** |
| **页面数与大小约定** | **每组 5 页**（用户裁定「tabpages 的标签数量增加为 5 个」）—— `implementation/06` §D.1 原有的「视图元素 ≤12 / 数据源 ≤12」约定已按用户裁定**取消数量上限**（「12 个太少了…无意义的约束不符合逻辑」）⇒ 页数不再受元素计数约束 |
| **「方向按钮」的落位** | **每组标签之后各一个**（char 组后 → 「转成 HEX」；hex 组后 → 「转成字符」）⇒ **每组一个方向按钮、页内不重复控件**；代价是框架要能回答「**当前是哪一页**」⇒ 只读**视图状态回读**面（`../journal/modules-rulings-and-progress.md` §9 **C1 = 已裁 ③**，依据 `decisions.md` 7.28）。原先「每页内各一个（①）」的候选**已不再采用**（7.27 已撤回） |

## 8. 已知限制

- **零口**：不参与组网、不进拓扑；它**不能**被连到任何模块上（这是设计意图 —— 纯工具）。
- **不持久化**：多页内容与结果都是运行期状态；**关闭模块（移除实例）即全部清空**（用户明确要求）。
- **结果行是定宽的**（框架硬约束：同一数据源样本长度一致，上限 1024 字节/行）⇒ 长 hex 串会**折成多行**显示（见 `../journal/modules-rulings-and-progress.md` §9 C6）。
- **只支持 UTF-8 文本**（与文本发送器同一口径，`decisions.md` 7.25）：**非法/被截断的字节序列明确报错**（红框），**不静默替换**；十六进制方向**永不丢**（它显示/接收的就是原始字节）。
- **按钮路径依赖「视图状态回读」面**：在该面落地前，「点按钮转换」拿不到**当前**输入（只能用最后一次提交的值）—— 本模块与四模块**同批**落地，故不阻塞。
- **不做**：字符集选择（GBK 等）· 文件导入导出 · 正则/转义处理 —— 需要时另立模块或扩展页。
