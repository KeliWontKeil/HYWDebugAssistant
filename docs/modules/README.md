# 模块文档（一模块一页）

> 状态：**现行**（2026-09 随双轨工作流建立；规定见 `implementation/05-two-track-development-workflow.md` §4）
> 用途：**这个模块是什么**。做到哪了看 `docs/roadmap.md`（状态唯一源）；框架契约看 `docs/architecture/` 各分册（**不在此复制**）。
> **模块的定义、粒度判据、模块族、组织结构、大小约定与七阶段开发流程**见 `implementation/06-module-standard-and-development-process.md`（**草案 · 待裁**）。

## 1. 登记纪律

1. 一个模块一页：`docs/modules/<模块标识>.md`（模块标识 = 模块包 ID，如 `hyw/text-sender`）。
2. 新模块从 `_模板.md` 复制起页；**与模块代码同一次改动**更新。
3. 页内**只写模块自己的事**；凡属框架契约（类型系统、端口/角色语义、投递与计量、视图元素目录）一律**引用分册**。
4. 模块状态（**未开始 / 开发中 / 待验收 / 已交付 / 暂停**）以本页清单与 `roadmap.md` 为准，两处必须一致。
5. 用到的**契约扩展**必须登记（页内"契约扩展"列 + `roadmap.md` 的请求条目）。
6. **清单只登记"要做的模块"**；每个模块的开发过程见 `implementation/06` §E 七阶段，**阶段 0 的产出 = 本页对应模块页起草到"八问可答"**。
7. **模块页必须写清两层角色**（`implementation/06` §A.1 的四层视角）：**功能角色**（层①，一个名字 = 本清单的"一句话职责"）与**数据角色**（层②，每个角色**一种数据类型**、**输入口/输出口同型** —— 有类型变化就拆成两个角色）。

### 2.2 参考模块（**判据载体，不是业务模块**）

这 6 个模块承载 AC-1~6 与手工验收清单（`implementation/04`），**冻结为"判据载体"**：只做必要修复、不再长功能。

> **两条约束**（`implementation/06` §G，**用户 2026-09 已裁**）：
> ① 它们**不再是新模块的模板来源** —— 其写法优先服务**判据覆盖面**（主动/被动接收、多源、命令通道等各条路径），**不代表推荐写法**；新模块的样板 = **第一批正式模块**。
> ② **处置 = 验收后归档**（不是立即归档）—— 归档前置 = AC-1~AC-6 判据已由新模块接管；现在不删是因为会打断 5 个 AC/契约测试文件与手工验收清单。

| 模块 | 定位 | 说明 |
|---|---|---|
| `DataGenerator` | 纯源（可编程数据发生，含周期活动） | 判据桩 |
| `ManualSender` | 纯源（手动发送） | 手工操作通道的载体 |
| `Recorder` | 纯汇（记录 + 断言） | 判据桩 |
| `Asserter` | 纯汇（契约/形状断言） | 判据桩 |
| `Monitor` | 纯汇（信息显示） | 视图元素与呈现的载体 |
| `Fuser` | 多入一出（多对多 + 合并策略 Latest/Priority/Average） | 多对多网络的范例 |
