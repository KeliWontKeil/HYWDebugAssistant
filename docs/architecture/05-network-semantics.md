## 1. 口与网络的基本口径 〔源: ADR-0022 §G3 + ADR-0018 §Q1/Q2/N1/N3/N4 + ADR-0010 + 主文档 §5.4/§6.3〕

| 项 | 现行口径 | 依据 |
|---|---|---|
| **口方向** | 只有**两态：发送 / 接收**；**无"双向"口**；双向通信 = 模块声明**两个口 + 两条单向网络**（UART 的 TX/RX 直觉） | ADR-0022 G3 |
| **网络方向** | **严格单向**：源 = 发送口，宿 = 接收口 | ADR-0022 G3 |
| **连接 = 网络** | 只有"网络"一种声明：**直连 = 匿名网络，标签 = 命名网络**；文档层 / 持久化 / 重锚 / Issue 归属一律按网络 | ADR-0018 Q1 |
| **网络标记** | 网络表现**依附于口**（模块边缘内部）：网络名（默认弱化）+ 方向标识 + 连接状态；**端口标记是唯一建网入口**；分线器视觉件**已撤销** | ADR-0018 Q2/Q4 + ADR-0052 §1 |
| **几何与连接** | 几何只负责**排列与对齐**（吸附、拼接不承担连接语义）；连接的建立/断开完全由网络承担 | ADR-0018 N1 |
| **任意两口可连** | 连接**不强制几何方向**、任意两口可连；"能否传数据"由口方向在建立/运行期判定并给 UI 提示 | 主文档 §5.4 |
| **两个发送口相接** | **连接存在但无数据流**（合法无意义组合）——UI 标注"无数据流"，**不是错误** | 主文档 §5.4.1 PQ-IF-06 |
| **数据通路** | 网络展开为**绑定**；数据在两端模块的接口之间**直接流动**——**Core 不中转、不转发业务数据** | 主文档 §7.2 |
| **口身份** | 口名 = 模块内唯一稳定名（多同型用"名 + 序号"）；连接锚定 `实例ID.口名` | 主文档 §5.4 PQ-IF-02 |
| **元能力目录** | 平台提供受控元能力目录：可实例化口 / 可被连接 / **方向两态**；业务形状由作者契约描述、**不入目录** | 主文档 §5.4 + `architecture/03` |
| **不引入业务分类** | 源 / 过程 / 汇由**口的方向**体现，不由框架分类 | ADR-0046 §2-8 |

## 2. 建网：两种自动派生机制 + 显式网络 〔源: ADR-0037 §D1–D4/D7 + ADR-0050 §M1/M8 + ADR-0051 §D1 + 主文档 §6.2/§6.3〕

**唯一实现 = 单一权威推导 `ReconcileNetworks`**（`Core/Runtime/ModuleRuntime.Networking`）：每次变更提交后**先移除全部派生网络再重建**；**显式网络与组合件加载的网络一律不动**（用户意图优先）。派生网络标 `IsAutoGenerated = true`。

**自动派生只有两条机制**（另有一条独立来源：用户显式建网 / 组合件加载，不受重算影响）：

| # | 机制 | 输入 | 名字 | 现行判定 |
|---|---|---|---|---|
| ① | **命名网络** | 端口**网络标签同名** | **标签本身即网络名** | **契约兼容的接收端**为宿；**打标签的口只参与命名网络**（两机制不混用）；**多发送端 ⇒ 建一条多对多网络**（N 个发送端同属一条网络，见下） |
| ② | **对齐网络** | 两模块**接触且标记对齐**的**未打标签**口 | **匿名（直连）** | 判定见下表，严格以防误建 |

**命名网络遇"多发送端"：建一条多对多网络（已裁定）**〔源: 用户裁定 + ADR-0050 §M1/M8〕

- **网络允许多对多**：同名标签的 **N 个发送端 ⇒ 一条网络**（源集合 = 全部发送端，宿集合 = 与**任一**源兼容的接收端之并集）。旧口径"**唯一发送端为源；多发送端 ⇒ 提示 / Issue、整条拒绝**"（ADR-0037 D2）**已不适用**（历史见归档）。
- **不再区分"多源 / 多个发送端"**：多对多（N:M）是**网络的常态形态**，不另立"多源特例"这一说法；本文件统称**多对多网络**。
- 其余无争议部分照写：**0 源声明 / 0 宿声明 ⇒ 未建网 + 提示**（见 §10）；**不兼容 ⇒ 逐对排除 + Issue**（见 §4）。

**"接触且对齐"判定**（`Core/Composition/DockRule`，**七条同时满足才连**）：

| 条件 | 值 |
|---|---|
| **接触** | 相邻边间隙 ≤ **2 px**（吸附贴合后为 0，正常拖动即满足） |
| **接触面重叠** | 沿接触边的投影**必须真正重叠**（排除"边缘数值巧合"） |
| **端口在接触面上** | **两个口必须各自挂在朝向接触面的那条边上**（左右相邻 ⇒ 发送口在**右**、接收口在**左**；上下相邻 ⇒ 发送口在**下**、接收口在**上**）。边取**有效边**（用户拖动覆盖 &gt; 模块声明 `PortDeclaration.Edge` &gt; 惯例；解析见 `PortEdgeResolution`）。**缺这一条会误报**：上下相邻的两模块，若拿"右边缘的发送口"与"左边缘的接收口"沿接触面（X 轴）比中心，宽度相近时正好落进 12px 对齐容差内 ⇒ 明明不在一面却报"即将建网"（用户实测："明明对齐的下侧却导致左右两侧的吸附"）；这两个口**永远不会真的接触**。**2026-09 增补** |
| **标记对齐** | 两端口**标记中心**沿接触面的距离 ≤ **12 px** |
| **方向** | 由**端口自己**（发送 / 接收）+ **接触几何**（谁朝谁）共同决定：**发送口朝外、接收口朝内**，两侧谁在左/上**无关**（2026-09 修正，见下条） |
| **契约** | **形状完全一致**（见 §4；不兼容即忽略，**不自动转换**） |
| **标签** | 双方**均未打标签**（打标签的口只参与命名网络） |

- **方向判定的 2026-09 修正（用户实测缺陷）**：用户原话："**网络标签解锁并换边拖动后，网络标签吸附无效了，只有在默认边才能吸附**"。**真因**：`DockRule.ComputeDockPairs` 把"**左/上那个模块**"直接当成发送端（`var sender = aIsLeftOrTop ? a : b;`）⇒ 只要发送端不在左/上（恰恰是"把标签拖到另一边 + 反着摆"的情形），候选**恒为空** ⇒ 建网与"连接对齐"吸附**同时静默失效**。**修法**：由接触几何算出"两侧各自朝向接触面的那条边"（`lowFacing`/`highFacing`），再**双向各试一次**（发送口在左/上侧，或发送口在右/下侧）⇒ **四种摆法都成立**（左右并排 × 发送在左/右 · 上下叠放 × 发送在上/下）。**物理事实不变**：两个口仍必须各自冲着对方（"端口在接触面上"那条判据照旧生效）。回归网 = `tests/HYWDebugAssistant.Tests/DockRuleTests.cs`（表驱动四种摆法 + "口不朝接触面不得建网"的护栏）。

- **只有一份判定实现**：网络行为（推导）与 UI 拖动预览**共用 `DockRule`** ⇒ 预览与结果必然一致。
- **预览查询**：`Core.Api` 的 `IRuntimeQuery.PreviewConnections(provisionalLayouts)` 返回 `ConnectionCandidateView`；UI 在**拖动中**问"现在松手会连上什么"并高亮；**实际建网只发生在布局提交之后**（吸附是 UI 行为、建网是网络行为）。
- **拖动网络标签时的"连接对齐"吸附（2026-09 追加）**：`IRuntimeQuery.SuggestAnchorDock(实例, 口, 边, 偏移)` —— 模块**已拼在一起**、两个口只差对齐（因而还没连上）时，UI 把标记吸到"中心对齐"的偏移并**高亮两侧标记**，松手即连上。判定同样**复用 `DockRule`**（与建网同源）⇒ "能吸上" ⟺ "松手真的连上"。
- **触发时机**：每次变更提交（布局提交 = 拖动/缩放结束 · 模块增删启停 · 标签变更）+ 组合件加载 + 占位解析。**不做增量**——以现场为准重算，无隐藏状态。
- **拆网**：对齐网络由几何**派生** ⇒ **拖开即自动断开**（并生成面向用户的提示）。
- **提示**：新建/消失的连接都生成面向用户的提示（"已连接：A.out → B.in"），经 `CommandResult.Notices` 到状态栏。
- **设置项**：`alignAutoNetwork`（开 = 接触且对齐的未打标签口自动连；**关 = 只做命名网络**）；旧键 `autoNetworkEnabled` 兼容读取。
- **已整体作废**："加入模块即连"与快速建网 **R0–R6**（`AutoNetworkBuilder` / `NamedNetworks` / `ApplyAutoNetwork` / `AutoNetworkOptions` 全部删除）；其"候选选择 / 最近加入者 / 抢占"语义只对"加入即连"有意义。

## 3. 多对多 N:M：模型与成员 〔源: ADR-0050 §M1/M2/M5/M8/M9/M11/M12 + §3b B1–B4 + `architecture/18` §8.1/§8.4〕

**定性**：**网络即多对多（N:M）**——多对多是**常态形态**，不是特例；框架**不隐式仲裁**（不猜优先级、不做语义合并），只提供中立的"多源 → 多宿"投递；语义级合并/仲裁由**模块**承担。

```
Network {
  Name                                  // 命名网络名（匿名对齐网络为空）
  Sources      : [NetworkMember]        // 在场（已锚定）的源；"声明源"另见 DeclaredSources
  Targets      : [NetworkMember]        // 在场（已锚定）的宿
  UnresolvedSources / UnresolvedMembers // 悬空的源/宿声明（方向仍为发送/接收）
  DeclaredSources                       // = 在场 ∪ 悬空（持久化与展示的事实源）
  MergePolicy  : ArrivalOrder           // v1 唯一策略
  IsAutoGenerated · IsStalled
}
```

| 项 | 现行口径 |
|---|---|
| **绑定** | 仍按**网络**建立；**绑定对象** = 源 / 目标列表 / 契约引用 / 诊断计数 / 状态 |
| **投递** | **逐 (源,宿) 对**：每个源独立投递到每个宿（1:N × M 由"每 (源,宿) 对一条投递关系"表达）；**保持零拷贝与字节守恒**；投递全程在 **L3**（L4 只增删绑定：不可变快照 + 原子替换）；**1:N = 写多个目标队列** |
| **成员两态** | `Sources` = **在场（已锚定）**；`UnresolvedSources` = **悬空的源声明**（保留待重锚）；宿侧对称（`Targets` / `UnresolvedMembers`）；`DeclaredSources` = 两者之并，是**持久化与展示的事实源** |
| **`IsStalled`** | **派生量**：`⇔ Sources.Count == 0`，**不单独存** ⇒ 不可能出现"标志说停流、成员却在场"；**读取方必须先看 `IsStalled`**——`Sources` 为空是**合法状态**，不是错误 |
| **身份键** | `NetworkView.Key` / `BindingDiagnosticView.Key` = **声明源集合 → 宿集合**（`DeclaredSources` ⇒ 两条**都停流**的网络不会因"在场源为空"撞同一个键）；**视图层一律按 `Key` 配对，禁用 `Name`**（匿名网络名为空串） |
| **宿口多路输入** | **合法**：**取消"宿口唯一"**；两条（含两条几何）网络指向同一宿口是正常形态；拓扑/诊断要能表达"某宿口当前几路输入" |
| **几何不自动合并** | 接触且对齐**不**把多个源并成**一条**网络（避免误连）——仍**按源口一条网络** |
| **锚定** | `AnchorNetwork` = **唯一**的"字面量 → 网络"实现，**加载与重锚共用**（⇒ 重锚不可能把多对多网络打回单源）；`NetworkAnchoring` **算而不报**；`ReportNetworkAnchoring` 决定报什么：**加载全报**（源侧 + 宿侧）、**重锚只在"源在场状态变化"时报源侧**、宿侧只在加载时报；**停流 Issue 不再由 `RebuildBindingsCore` 报**（同一事实只有一个 owner） |
| **持久化** | 网络记录 **`sources: [...]`（有序）** + **`schemaVersion` 升到 2**；v1 的单值 `source` **解析期归一**为单元素列表、**写回清旧字段**（同一事实绝不留两个字段）；**旧组合件必须可加载、可运行** |
| **呈现** | 网络标签（端口标记）**形态不变**；**拓扑页显示源列表 + 宿列表 + 每源状态**（来源取自绑定模型，不读数据） |

## 4. 逐对兼容：谁能连谁 〔源: ADR-0051 §D1–D3/§6 + ADR-0050 §M6/B8 + 主文档 §5.4.1〕

**判定单位 = 逐 (源,宿) 对**：某源与某宿不兼容 ⇒ **仅该对不建立投递 + Issue**，其余源照常，**网络不整条拒绝**。

| 情形 | 判定 |
|---|---|
| 双方都声明类型：**同标识 + 同版本 + 形状完全一致** | ✅ **兼容** |
| **同标识 + 不同版本** | ❌ **不兼容**（版本升级按**破坏性变更**处理；请两侧升到同版本，或**插入转换模块**）——原"尾部追加 = 兼容"**已作废** |
| **不同标识** | ❌ **默认不兼容**（框架**无资格**判定"是否同一种量"，形状相同也不认）；用户**显式确认**后放行，**此时仍要求形状完全一致** |
| **任一方未声明类型**（旧模块） | 只按**形状完全一致**判定（原"接收 ⊇ 发送"子集判定**已作废**） |
| **传递语义不同** | ❌ 不判兼容（跨语义不判；组帧由模块内部完成） |

- **"形状完全一致"的定义**：字段**名称** / **原语种类** / **数组与字节块长度** / **字段顺序** / **字段数量** 全同（⇒ 尺寸必然相同）。
- **比较实现**：必须用 **`ContractShape.AreSame`**（**逐字段结构比较**）。形状是 record，但结构形状的字段集合在 record 默认相等里做的是**引用比较** ⇒ 写 `left == right` 会把"两个模块各自构造的同一形状"判成不同（只有引用同一静态实例才连得上）。
- **显式确认的载体**：`ConnectNetworkOperation.AllowUnverifiedTypeMatch` → 存到 `Network.AllowUnverifiedTypeMatch`（**用户决定，不是派生事实**）⇒ 随组合件持久化（`allowUnverifiedTypeMatch`，**新增可选字段**：只在该值为 true 时写出、缺省 = false），否则重载后连接会莫名失效。
- **不自动转换**（PQ-IF-05 不变）：转换 = 用户**显式插入转换模块**。
- **读取纪律（防御，不因上条而删）**：**到达的数据报长度 = 发送方的契约尺寸**（框架**不投影、不补零、不截断**）；形状一致后这**恒等于本口契约尺寸**（即不变量），但接收方仍应**按到达长度读**——SDK 提供 `PayloadReader.TryCreate(payload, layout, out reader)`（长度不足返回 `false` 不抛）；用**自己的**契约硬构造 `PayloadReader` 在长度不足时会抛。
- **异常边界政策不变**（ADR-0029）：投递期**不做异常隔离**。新规则下"短数据报"从源头消失，剩下的回调异常**全是模块自身的代码错**（确定性）⇒ "**报 Issue + 停止该实例活动**"是正确的。**已知文案缺陷**：这类退出只留下一条写着"活动体异常"的 Issue，**文案与真实原因不符**，现场表现为"模块莫名不再收数"。
- **推论（同口长度唯一）**：形状不一致的源被**逐对排除** ⇒ **同一宿口永远只出现一种长度**；被排除的那一路**保留声明 + Issue**（不是整条网络拒绝，也不是静默丢弃）。

## 5. 来源不进数据面 〔源: ADR-0050 §M4/D1 + ADR-0022 §G1/G2 + ADR-0046 §D4/D5 + 主文档 §5.4.2〕

| 面 | 是否携带/暴露来源 | 现行依据 |
|---|---|---|
| **数据面**（投递到宿） | **不暴露**——框架零附加：不写 payload，也不给 sideband 参数 | M4（原 sideband 方案**已撤回**） |
| **应用层** | **需要来源就自己带**（在模块契约里声明来源/序号字段，如 `{seq,t,value}`） | ADR-0022 G1 / ADR-0046 D4 |
| **观测面**（拓扑 / 叠加层 / 诊断） | **可以显示来源**——框架**从网络成员关系（绑定模型）即可知道**，**无需读数据** | 来源是**声明/拓扑事实**，不是数据事实 |

- **框架不往数据单元附加任何元数据**：**投递字节 == 模块产出字节**（字节守恒）；**数据包不自描述**（不带类型标签，框架按**声明**路由）。
- **框架侧只做统计**：投递计数 · 最后数据时间 · 间隔统计；"序号" = 框架侧累计计数，**不写入单元**。
- **契约不含单位/量纲语义**：单位属**模块配置 / 显示层**；语义元数据（单位/量程/精度/建议采样率）可随类型声明供**展示**，但**禁止参与任何框架判定**（"可声明 ≠ 可判定"）。
- **解析三段式**：① 声明期读取（框架必做，注册/实例化时一次性读声明）② **传输期零解析**（框架不读数据内容，投递只按绑定 + 校验长度）③ **呈现期解码由模块负责**（解码器随类型注册、框架只回调）。
- **多对多网络上的唯一例外**：**薄旁路头**（见 §8）——传输层旁路，**不进 payload 字节流**，字节守恒不变。

## 6. 数据报语义与顺序等级 〔源: ADR-0050 §D1/D2/D3 + §Q1/Q3/Q4 + `architecture/18` §5.1/§5.2/§6.2〕

数据面的正式规范 = **「UDP 式数据报 + 发布订阅」**：

| 维度 | 现行规范 |
|---|---|
| 连接 | **无连接**：按**声明**建立绑定后即投递（无握手 / 无会话） |
| 可靠性 | **best-effort**：有界队列满即丢 + 计数（**不背压**） |
| 边界 | **数据报**：一个单元 = 一个**定长**数据报（契约尺寸） |
| 1:N / N:M | **多播**（1→N 复制）· **多发布者**（N→1）· **N:M** |
| 端点 | **口（端口）**；**无每包地址**（拓扑由声明派生） |
| 校验 | **长度校验**；**无内容校验和** |
| 接收策略 | **框架中立：按到达顺序投递**（v1 唯一 `MergePolicy`）——**不做**优先级 / 时刻排序 / 去重 |
| 可观测 | **四档速率 + 三类丢弃 + 队列水位**（见 §9） |

**"哑交换"结构**（声明驱动转发表 + 每宿 FIFO 队列 + 观测面）：

| 组件 | 职责 |
|---|---|
| **转发表（绑定）** | 由**声明**派生：网络成员关系（标签同名 / 接触且对齐）；**不学习地址**——"输入输出任意"的准确含义 = **口数/方向组合不受限，但连接需显式建立（标签或几何）** |
| **投递** | 对每个 (源,宿) 对**复制入队**；1:N 复制 N 份；N:M 逐对；**不合并、不排序** |
| **宿队列** | **每 (实例,口) 一条**有界 FIFO；满即丢弃并计数 |
| **出队** | 模块取用（拉 `TryReceive` 或接收回调） |
| **观测面** | 水位 / 丢弃（按源、按原因）/ 速率（四档）；**全部取自绑定模型，不读数据** |

**顺序保证等级**：

| 范围 | 保证 |
|---|---|
| **同一 (源,宿) 对** | **FIFO 强保证**：不得乱序、不得重复、不得丢（除非**明确丢弃并计数**） |
| **不同源之间** | **无顺序保证**（只保证每源各自 FIFO）；多源到同一宿口 = **按到达顺序交织** |
| **跨源时间序** | **框架不提供**（不附加时刻）⇒ 需要时间序的应用**自带时刻字段** |

- **术语澄清（避免误导）**："压栈/出栈"在语义上要的是 **FIFO，不是 LIFO**（LIFO 会反转数据顺序）。在本工程里对应两个既有动作：**发送侧入队**（`Deliver → InboundBuffer.TryEnqueue`）与**接收侧取用**（`TryReceive` / 接收回调）。文档与注释统一写 **"入队 / 出队（FIFO）"**，不用"压栈"。
- **术语规范**（**只改文档与注释用词，不改代码标识符**；新代码优先用标准词）：数据单元 / 投递 → **数据报（datagram）/ 发布（publish）**；网络 → **topic**（成员 = **publisher / subscriber**）；多源 → **多发布者**；停流 / 悬空 → **liveliness / deadline**；有界队列 + 丢弃 → **best-effort reliability + history depth**；队列水位 → **queue depth**；契约兼容 → **type matching**。
- **与 UDP 的关键差异（都是本工程独有的必要增量）**：**转发表声明驱动**（不是"每包带地址"，更像静态 VLAN / 订阅关系）· **无地址**（网络名/绑定即身份）· **强类型定长契约 + 兼容判定** · **可观测性更强**（四档速率 + 三类丢弃 + 水位）；**顺序比 UDP 略强**（同对 FIFO 是合理的工程加强）。
- **明确不做**：**进程内不换真 UDP socket**（实测完整投递 **54 ns**、三跳端到端 **1.8 µs**、≈**3.2 M 单元/秒**；走环回内核栈为 **µs 级（量级估算 1–10 µs，约 20–100× 慢）**，并引入抖动 / MTU 分片 / 系统缓冲 / 端口与防火墙因素，且失去零拷贝与对象模型）· **不变长 / 不分片**（v1 只定长；批量 = 定长数组 `T[N]`，由类型声明，不做框架自动合并）· **模块远程化不属本轮**（跨进程 / 跨机用真 UDP/TCP/共享内存登记为**未来能力**，**同一语义契约**）· **与真实设备通信由模块承担**（`ModuleCapability.Network / SerialPort` 已存在）——框架数据面是**模块之间的织物**，两者不得混淆。
- **框架不仲裁**：合并 / 仲裁语义一律由**模块**承担（框架永不仲裁）；需要"每源一个值 / 取最新 / 取平均 / 按源区分"时由模块实现。

## 7. 队列、投递与背压 〔源: ADR-0050 §Q2/B5 + ADR-0029 §Q4-1/§4.2/C4-1 + 主文档 §7.3 + `architecture/04b`〕

| 项 | 现行口径 |
|---|---|
| **队列粒度** | **每 (实例,口) 一条**有界 FIFO 队列（消除"每实例一条"的**跨口队头阻塞**：一个慢口/满口会堵住同实例其它口） |
| **容量** | **按口计**；默认 **1024 单元/口**（应用级设置项可配）〔源: `architecture/04` §4.2 + `architecture/07` §7.1〕；**改动只对新建队列生效**，既有队列保持创建时的容量（避免运行中改容量导致数据丢失） |
| **线程模型** | 每 `Active` 实例 **1 个框架分配的专属线程**；模块**不自建、不直接管理线程**，可在自己线程上同步阻塞。**`Disabled`（禁用）= 保留线程与资源**（已裁定）：**停用不释放** —— 实例、承载者、专属线程、队列与订阅缓冲**全部保留**，只把相关绑定置为**停流**（不投递）；**重新启用即继续**（同一实例、同一线程、队列与缓冲不重建）。线程与队列的**回收只发生在 `Removed`**（有界等待超时则记 Issue + 孤儿线程）〔源: 用户裁定（口径 A）+ 代码 `src/Core/Runtime/ModuleRuntime.cs`（`ApplyEnabled` → `SetSuspended`；`TryDeactivate`/承载停止**只在移除路径**调用）+ `src/Hosting/Lifecycle/ModuleLifecycleController.cs`（`Disable` = 状态转换 + `OnDisabled` 钩子）〕。**注**：`src/DataPlane/Carriers/CarrierHost.cs` 的类注释写"`Disabled` 的实例不占线程"，与上述**实际行为不一致（过期注释）**，需在后续 bug 修复轮改正 |
| **阻塞与背压** | 投递**绝不阻塞发送方**；**v1 不做背压**（背压按定义需阻塞或反向通知上游，与"绝不阻塞"互斥） |
| **丢弃方式** | 按口声明：**默认丢旧**（丢最旧保最新）或**丢新** |
| **公平调度** | `TryDequeueAny`（**轮转**：连续调用在非空口之间轮换）；投递循环与主动接收（`IPortAccess.TryReceive`）**共用**它 ⇒ 任一口都不会被饿死（二者互斥：有活动体则不跑投递循环） |
| **空口探测** | 用**提示位图**（"该口有数据"）跳过空口探测（≤ **64** 口；更多口退化为逐口探测，正确性不变）。**正确性不依赖位图**：入队必 `Release` 信号量、消费侧 `Wait` 为 Acquire 栅栏 |
| **入队结果分类** | `CarrierEnqueueResult{ Accepted, QueueFull, NoCarrier, Stopped }`：**"口不存在/无承载"与"队列满"分开**（前者入队即失败、立即丢弃；后者是 best-effort 丢弃）——Core 侧映射 `DropReason.NoCarrier` / `QueueFull`，**不再把"无承载"记成"满队"** |
| **记账补漏** | 丢旧策略下"已入队但挤掉旧单元" ⇒ `CarrierEnqueueResult.QueueFullEvicted`：**新单元记投递，被挤的旧单元记"队列满丢弃"**（否则"投递数"会把从未被消费的单元算成成功） |
| **停止协议** | 停止与孤儿缓冲处置不变（改为清空**全部口**的队列） |
| **护栏边界** | 安全护栏（静默）+ 轻量提示（可见），**不做限流、不做环/自连检测、不做阻断**（不改变"自连/环允许"的裁决） |
| **单源/单口回归** | 单源 / 单口路径**行为与性能不变**（1 口时每轮恰好 1 次探测） |

**两种连线形态的现行语义**：

| 形态 | 框架实际行为 |
|---|---|
| **1 源 → N 宿** | **多播**：每条数据报**每个宿各一份独立拷贝**；宿之间互不影响；每个宿看到的都是该源**完整、有序**的流。**不存在"融合"**。注意：**同一模块的两个口打同一标签 = 两次订阅 = 收到两份**（合法语义，但常出乎意料） |
| **N 源 → 同一宿口** | 框架**只做一件事**：把每个被接受的数据报按**到达顺序**写进该口的**同一条 FIFO 队列** = **匿名多路复用**；**不排序 · 不去重 · 不仲裁 · 不告知来源**，每个源自身顺序仍保证。**推荐形态是一源一口**（现行范例 = 判据项目内测试桩 `FusionStubModule`（`test/fusion-stub/1.0.0`）：两个输入口 + 一个输出口，策略 `Latest` / `Priority` / `Average`，来源用**口**区分，融合结果可**再发布**；原参考模块 `hyw/reference-fuser/1.0.0` **已于 2026-09 按用户裁定删除**）；或应用**自带来源字段**。**不同尺寸的源不可能连到同一宿口**（见 §4） |

## 8. 薄旁路头：仅多对多（N>1）网络 〔源: ADR-0050 §Q6(c)/B6 + `architecture/18` §8.7 + 主文档 §5.4.2〕

| 项 | 现行口径 |
|---|---|
| **结构** | `DatagramHeader{ SourceInstanceId, SourcePortName, Sequence, ReceivedTimestamp }`（`DataPlane.Queues`）——**传输层**类型（L3 持有），**不是契约的一部分** |
| **携带方式** | `InboundUnit.Header`（**旁路**）⇒ **不进 payload 字节流**（**字节守恒不变**）；`ModuleCarrier.TryEnqueue(port, buffer, header)` 新增可选参重载，**旧两参重载 = 单源零附加** |
| **附加条件** | **仅在 `binding.Network.Sources.Count > 1` 时构造**；**单源网络：不构造、不入队、不读取**（`Header` 为 `null`） |
| **序号语义** | **按源递增（1 起）**——来源 = `BindingDiagnostics.Published`（**每个数据报一次，多播不放大**）；它同时就是"**单元速率（按源计）**"的分母 |
| **接收时刻** | `Stopwatch.GetTimestamp()`（**单调高频计数、非墙钟**）⇒ 只用于"差"（延迟 / 抖动 / 跨源交织观测），**不可当墙钟时间** |
| **消费者（必须有，否则是死数据）** | **观测面**：`CarrierDiagnostics.Headered`（带头发起数）/ `LastHeaderSequence` / `LastHeaderTimestamp` ⇒ 单源网络 `Headered == 0` **就是"零附加"的可断言证据** |
| **仍然不做** | 模块**不**通过头取来源（应用需要就**自带字段**）；**不做**跨源排序/去重；头**不进契约**（兼容判定仍只看形状） |
| **选型依据** | 行业惯例本就"有头"（UDP 头 8 B · ZeroMQ 帧头 · DDS 头含 writer GUID + 序号 + 源时间戳）；**(c) 只在多对多网络（N>1）带头** = 单源零开销、多源才付代价（每单元 +8–16 B） |

## 9. 计量与丢弃 〔源: ADR-0046 §D8 + ADR-0050 §M7/B10 + `architecture/18` §8.8/§8.15 + 主文档 §5.4.2/§13.2〕

**四档速率**（框架用**模块声明的计量块**机械给出，**零解析**）：

| 档 | 定义 | 归属 |
|---|---|---|
| **单元速率** | 数据报个数 | **按源计**（= `BindingDiagnostics.Published`） |
| **搬运字节速率** | 含自描述与对齐填充的传输字节 | **按宿计** |
| **有效载荷字节速率** | **真实业务数据字节**：声明了 `PayloadLengthField` ⇒ **逐单元读该字段**（夹到 `[0, 契约尺寸]`）后累计；未声明 ⇒ `PayloadSizeInBytes`（缺省 = 契约尺寸） | **按源计** |
| **样本 / 通道样本速率** | × `SamplesPerUnit` × `ChannelCount` | 来源未标注聚合口径 |

三种聚合（**按源 · 按网络 · 按宿**）**都可查**（UI 择一显示）。

**界面显示哪一档（2026-09 用户裁定）**：用户原话——"**速率只要有效数据，截断的不应该算在有效数据里面，整个数据包大小速率是底层协议，用户想知道的肯定是有效速率**" ⇒ **网络标签（通路维度）与角色方块（角色维度）显示的都是第 3 档**（`PortMetricsView.PayloadBytesPerSecond` / `RoleView.PayloadRateBytesPerSecond`），**累计流量同口径**（`PayloadBytesDelivered`）。搬运口径（`BytesPerSecond`/`BytesDelivered`/`BusByteRate`）**保留为 API 事实**，但界面不再显示它（否则同一块标签上"速率"与"流量"会各说一套）。

**计量块字段**（随类型声明，全可选、缺省有定义）：

| 字段 | 含义 | 缺省 |
|---|---|---|
| `PayloadSizeInBytes` | 单元中**业务数据**字节数（**静态**：每个单元都一样时用它） | = 契约尺寸 |
| **`PayloadLengthField`** | **写着"这一个单元有多少有效字节"的顶层字段名**（**2026-09 只增**）——变长载荷用它：框架逐单元读该字段（整型原语、小端、夹到契约尺寸内） | 空 = 不逐单元读 |
| `SamplesPerUnit` | 每单元样本数（批量） | 1 |
| `ChannelCount` | 通道数 | 1 |
| `NominalRateHz` | **标称**速率（对照用） | 空 |

**为什么需要 `PayloadLengthField`**：定长契约里的**变长载荷**（典型 `{ len:u16, data:bytes[1472] }`，尾部补零）用一个静态尺寸表达不出"这一个单元真正有多少业务字节" ⇒ 有效速率只能退化成搬运速率（用户看到的"整帧大小"，正是他要排除的）。声明字段名之后框架**逐单元读它**（读法与不变量见 `07`）；**声明写错**（字段不存在 / 不是整型）由契约自检在**加载期**报出 —— 否则表现为"有效速率恒等于搬运速率"，无人察觉。

**丢弃三类**（统计与呈现都不得混算）：

| 类 | 含义 |
|---|---|
| **停流未投递**（`DropStalled`） | 合法状态，**不是故障** |
| **传输丢弃**（`DropTransport`） | = **队列满 + 无承载 + 载荷非法**（三个子原因**可分**） |
| **模块内部丢弃** | `SubscriptionSourceView.Overwritten/Dropped`——**模块自己的口径，不并入**网络口径 |

⇒ 细分原因共四个：**队列满 / 无承载 / 载荷非法 / 停流未投递**；**丢弃按源归属**（每网络/绑定独立诊断）。

**队列水位**：`IRuntimeServices.GetQueueDepths()` → `PortQueueDepthView{ 深度 · 容量 · 入队 · 丢弃 · 填充率 · 按宿计的搬运字节速率 }`——只有"每 (实例,口) 一条队列"才给得出"按宿计"这一档。

**速率计**：`RateMeter`（**单调时基**；**首次观察只建基准**；**计数回退归零**；**口径 = 整秒桶**〔**2026-09 用户裁定**："算一秒的积累量"〕：`WindowSeconds = 1.0` ⇒ 速率 = **上一个 ≥1 秒窗口的增量 ÷ 该窗口真实秒数**，窗口锚定在首次观察、与 UI 刷新节拍**解耦**；窗口未满（含"同一次刷新里的多个消费者"）返回上一次的值 ⇒ 不会有人读成 0）。**界面只格式化**：`---` **只表示"无连接"**；有连接但这一秒无数据 ⇒ **`0.00 B/s`**（**不再拿 `---` 冒充 0**，也不做"速率过低"之类的模糊化）。

**采集点**：L1–L4 的诊断采集点包含**每绑定 / 每队列**的投递数、丢弃数、最后数据时间、队列深度〔源: ADR-0029 §4.2 第 11 条〕。

**两条纪律**：① UI **只显示有定义的口径**（`_rateSamples` 之类**差分估算已退休**，一律用框架口径）；② **不做"实际 vs 框架"的单数字对比**——**是否掉速 = 实测 vs `NominalRateHz`**。

## 10. 停流 / 悬空 / 未建网（判定速查） 〔源: ADR-0050 §M5/B2/B3 + `architecture/18` §8.2/§8.3/§8.12〕

| 情形 | 处理 |
|---|---|
| 只有宿、无任何**源声明** | **未建网**（**保留标签** + 提示"等发送端"） |
| 只有源、无任何**宿声明** | **未建网**（**保留标签** + 提示"等接收端"） |
| 有源声明但**全部源未锚定**（口/实例缺失） | **停流**（网络存在，`IsStalled == true`；**保留声明、不投递**、每源标注 Issue） |
| **部分源**不可用 / 不兼容 | **其余源照常投递**；不可用者**保留声明 + 该源 Issue**（**不是停流**） |
| 多源同名标签 | **合法**（不拒绝） |
| 不兼容的 (源,宿) 对 | 只排除**该对** + Issue；网络与其他成员不变 |

- **连接 / 停流状态的唯一来源 = 网络成员关系**（`FindPortNetwork` 从网络成员派生，**不看绑定**）⇒ 停流网络的成员关系照样呈现（用户仍需要看到"本来连给谁"）；UI 连接状态由刷新路径按**网络**口径统一生产。
- **`IsStalled` 是派生量**、**不是错误**；停流/悬空的 Issue **只由锚定路径报一次**。
- **"源集合为空"的两态模型（已裁定，按代码收口）**〔源: 用户裁定 + **代码** `src/Core/Composition/Network.cs`（`Sources` / `DeclaredSources` / `IsStalled` 的不变量与派生）+ `src/Core/Services/RuntimeServices.cs`（`FindPortNetwork` / `IsPortStalled`）〕：
  - **判据只有两个，且分居两态**：
    - **未建网** = **该口不在任何网络的成员里**（`FindPortNetwork` 返回 `null`）⇔ **没有网络对象**。这才是 §10 第 1/2 行"保留标签 + 提示等发送端 / 等接收端"的情形——**网络不存在**，因而不占**网络身份键**（`NetworkView.Key`）、不出现在拓扑行。
    - **停流** = **网络存在、但 `Sources.Count == 0`** ⇔ `Network.IsStalled == true`（**派生量、不单独存**）。网络**已创建**、**占用** `NetworkView.Key`（键含**全部声明源**）、**出现在拓扑里**（状态 = 停流），声明保留、不投递、每源报 Issue。
  - **"源集合为空"所指 = `Sources`（在场/已锚定的源），不是 `DeclaredSources`** —— **代码不变量**：`Network` 构造器要求"声明的源至少有一个（在场或悬空）"，`Sources.Count == 0 && UnresolvedSources.Count == 0` **直接抛 `ArgumentException`** ⇒ **"声明源为 0 的网络"在代码里不可能存在**。故"源集合为空"只可能是**在场源为空**（`Sources`）⇒ **停流**。
  - **判据归属（两态各管一段）**：`DeclaredSources`（= `Sources ∪ UnresolvedSources`）**只用于持久化与展示**（"本来连给谁"、身份键、拓扑归属），**不用于判定建网与否**；`Sources` 用于**停流**判定。⇒ 原口径 A 的"按 `DeclaredSources` == 0 判未建网"**不成立**（该情形由"没有网络对象"表达）。
  - **"有源声明但全部未锚定"的唯一结果**：网络**已存在**且 `IsStalled == true`（停流）——不是"未建网"。

## 11. 明确不做（本域边界） 〔源: ADR-0050 §M14/D3 + ADR-0029 §C4-1 + ADR-0022 §G1/G2 + ADR-0052 §R3′〕

- 框架**不**做优先级 / 时刻排序 / 去重 / 限流 / 背压；**不**做合并与仲裁（由模块承担）。
- **不**引入变长载荷、**不**做分片；批量由类型声明（定长数组）。
- **不**自动把几何相邻的多个源合并成**一条**网络（避免误连）。
- **不**在进程内改用真 UDP socket；**不**在本轮做模块远程化 / 跨机。
- **不**往数据单元附加任何元数据（除多对多网络的**旁路薄头**）；**不**在契约里放单位 / 量纲语义。
- **不**做每口发送速率上限、环 / 自连检测、阻断式护栏。
- **数据角色**（模块声明的功能分块）**只用于呈现**：**不参与**建网 / 兼容判定 / 停流 / 投递 / 计量，且**不进组合件**（角色的定义与画法不在本文件范围）。

## 12. 网络语义的回归判据（现行） 〔源: ADR-0037 §2 + ADR-0050 §6 + ADR-0051 §6/§7 + `architecture/18` §8.6–8.8〕

| 域 | 判据 |
|---|---|
| **建网 / 拆网** | 接触且对齐才连 · 不接触或不对齐不连 · 拖开自动断开 · 打标签口不参与对齐建网 · 契约不兼容不连 · 显式网络不被重算误删 |
| **多源投递** | 同名标签 N 个发送端 ⇒ **一条**网络；每源数据都到达宿；逐对兼容只排除不兼容对 |
| **顺序** | 同 (源,宿) 对 FIFO 不乱序（含多源交织时各源自身保序） |
| **停流 / 悬空** | 全部源未锚定 ⇒ 停流且不投递；**部分源不可用 ⇒ 其余照常**；补齐后**逐源重新锚定**（重锚不得把多源打回单源） |
| **宿口多路** | 两条网络指向同一宿口 ⇒ 均投递、不报错；拓扑可显示路数 |
| **队列粒度** | 一个口满**不影响**同实例其它口；按口名分别入队/出队；**无承载的口入队被拒并立即计丢弃**（与"口存在但无处理"分开） |
| **薄头** | 多源单元带旁路头且**序号按源递增**；**单源单元零附加**（`Headered == 0`、`Published == 1`）；单源单元**字节数不变** |
| **丢弃细分** | `停流未投递` **不计入**传输丢弃；队列满 / 无承载 / 载荷非法可分；水位按口可查 |
| **兼容** | 形状完全一致（含**各自独立构造的同一形状**）⇒ 兼容；尾部追加 / 缺字段 / 改类型 / **改顺序** / 同尺寸不同字段名 ⇒ 拒绝且原因可读；同标识**不同版本** ⇒ 拒绝且原因点明"版本不同"；不同标识 ⇒ 默认拒绝、显式确认后放行（仍要求形状一致）；未声明类型 ⇒ 仅按形状一致判定；**混形状多源 ⇒ 只排除该 (源,宿) 对 + Issue，同一宿口只出现一种长度** |
| **读取纪律** | 硬构造 `PayloadReader` 在长度不足时抛；`TryCreate` 安全失败返回 `false`；够长可读。参考模块（Monitor / Recorder / Asserter / Fuser，**该载体已于 2026-09 按用户裁定删除**）**防御式读取**：长度不足 ⇒ **丢弃 + 计数 + 首次一条 Issue**（不静默、不崩） |
| **计量** | 四档速率的定义可断言（单元 / 搬运 / 有效载荷 / 样本）；停流期间的发送**只计停流未投递**；`RateMeter` 显式时基、同一刷新重复读数同值；`多对多网络`下角色/口速率 > 0（键空间按 `NetworkKey` 聚合，不用逐源 `Key`） |
| **旧格式** | v1 单源 `source` 可加载并迁移为 `sources[]`，写回新格式且清旧字段 |
| **观测面来源** | 拓扑 / 叠加层能显示多源，**全程不读 payload** |
| **反向断言** | 角色声明（增 / 删 / 改）⇒ 网络与投递结果**逐字段不变**；网络身份键唯一且一一对应 |
