# 07 · 叠加层与视觉基线

> 状态：**现行**（本轮收敛重写；来源见各节标记）
> 适用范围：模块窗口与端口标记的视觉规范、叠加信息层（角色方块 / 连线 / 信息区）、方向与类型配色、视觉 token 基线（颜色 / 字号 / 尺寸）、坐标系与单位口径、几何吸附与坐标量化。
> 与主文档的关系：主文档 `上位机架构设计.md` 是验收唯一事实源；本文件是其实现层分册，冲突时以主文档为准。
> 附录：**附录 A = 为什么这么定 —— 吸附与像素对齐的实测证据**（三类根因的证据链 + 一次性测量/诊断手段设计），几何吸附与坐标系两节的约束均由它解释。

## 取值纪律（改视觉只改这几处） 〔源: 09 §5 实现落点 + 05 §5.18 控件尺寸〕

- 尺寸与配色 token 集中在 **`src/Ui/Styles/Tokens.axaml`** 与 **`src/Ui/Styles/Controls.axaml`**；**叠加层的几何常量在 `ConnectionOverlay` 顶部**。
- **控件尺寸只从 token 取**（禁逐处写死）：输入类控件统一高 **27 px**（token `ControlHeight`）、圆角 **3**；`Button`/`ToggleButton` 最小高 **27**；图标按钮 `Button.icon` **20×20**。
- token 类型必须与消费者的属性类型一致（`ModuleCornerRadius` 必须是 `<CornerRadius>` 而非 `<x:Double>`，否则运行时才抛 `InvalidCastException`），同类错误由无头测试拦住。
- 设置键名与默认值以 `08-application-settings.md` 为唯一来源；本文件只写与视觉/手感直接相关的取值。

## 设计原则 〔源: 09 §1〕

| 原则 | 含义 |
|---|---|
| 工程工具风 | 高信息密度、紧凑间距、清晰边框；一屏看更多数据 |
| 数据优先 | 视觉服务于数据可读性：波形、数值、表格的对比度优先于装饰 |
| 克制 | 无阴影 / 渐变 / 装饰性动效（除非表达状态）；颜色只用于**语义**与**选中** |
| 层级靠明度 | 用背景明度差与边框区分层级，而非投影（深色主题下投影不可见） |
| 状态可见 | 模块 / 网络 / 口的运行状态必须一眼可见：**颜色 + 形状双重编码**，不只靠颜色 |

## 坐标系与单位口径 〔源: 05 §5.22 + ADR-0042 §7.2 + ADR-0053 §5/§5.1 + 18 §8.13/§8.15〕

**这是最容易出错的地方，两套单位不得混用。**

| 面 | 单位 | 口径 |
|---|---|---|
| 模型几何（`ModuleLayoutView` / `ModuleViewViewModel` 的 `X/Y/Width/Height`） | **整数物理像素** | 由唯一量化点 `Ui.Geometry.ScreenPixels`（`Round` = `MidpointRounding.AwayFromZero`、`ToPixel`）产出；在**构造（含 `PreferredWidth × 缩放`）/ 读布局 / 拖动 / 缩放 / 跟随外壳 / 还原**处一律取整 |
| 窗口落位 | DIP | `ModuleWindowManager.ApplyGeometry` 位置**直接用整数模型值**（不再各自 `Math.Round`）、尺寸 = **整数 ÷ `scaling`**；`PublishActualSize` / `PublishShellRect` 一并量化 |
| 叠加层（`ConnectionOverlay`，Avalonia 自绘控件） | **DIP** | 换算**只允许发生在两处**：`CanvasWidth/CanvasHeight`（= 尺寸 ÷ `Scale`）与 `ToDip(...)`；**别处一律不乘除缩放** |
| 画布尺寸的唯一事实源 | —— | `ModuleViewViewModel.Width/Height`（叠加层经同名 `CanvasWidth/CanvasHeight` 绑定接收，`Bounds` **只兜底**）；对端锚点用同一对数字算 ⇒ 两端得到同一布局 |
| 画布贴边 | —— | 叠加层 `Margin="-1"` 抵消外层 `Frame` 的 1 px 边框 ⇒ 画布**正好等于窗口客户区**，拼接线才在窗口真正外沿相接 |
| 裁剪坐标系 | —— | 每窗画布原点恒为 `(0,0)`；`ClipSegment(window, from, to)` 的 `window` 必须是**本窗局部矩形**，世界原点只用于把对端锚点换算进本窗（`ToLocal(point, fromOrigin, toOrigin)`） |
| 指针取法 | 屏幕物理像素 | 拖动 / 缩放**优先取系统光标**（`Ui/Views/NativeCursor.cs` → `GetCursorPos`）；非 Windows / 非鼠标（触摸、笔）/ 调用失败时回退到"窗口位置 + 局部坐标 × 缩放"换算。**禁止**用后者作为主路径：它与窗口位移不是同一次采样，拖动中形成正回授（抖动） |

> 已知取整边界：模型整数化 + 窗口只做"整数 ÷ 缩放"后，屏幕上"相邻模块的边"与模型里的边是同一个整数 ⇒ 缝与像素级错位结构性消失（125% 缩放下不再出现 `412.5 px` 这类小数尺寸）。
> 本表每一条的**故障现象与实测证据**（含 125% 缩放下的具体数值、指针回授的推导）见 **附录 A**。

## 模块窗口视觉规范 〔源: 05 §5.14/§5.17/§5.18 + ADR-0034 + ADR-0039 D1/D2 + ADR-0041 D1 + 主文档 §10.4〕

| 项 | 规范 |
|---|---|
| 结构 | **无标题栏、无身份行**；**边框覆盖整个窗口周界**；**整块窗口矩形 = 模块矩形**（与建网判定 `DockRule.MarkerCenter` 的几何基准一致）；**模块名不在窗口上显示** |
| 窗口样式 | 无边框顶层窗口（`WindowDecorations=None`、`CanResize=false`、`ShowInTaskbar=false`；任务栏 / Alt+Tab 只出现外壳一项） |
| 边框 | 1 px 常规；选中 / 悬停 / 锁定态差异化（反馈见「交互视觉反馈」节）；圆角 **2 px** |
| 运行指示 | **左下角**：状态点 **7 px** + 状态文本 **10 px** 弱化色 |
| 按钮簇 | **右上角 · 纯图标**：**还原 · 锁定/解锁 · 隐藏 · 关闭**（原"运行/停用"已删除——模块没有"暂停"语义）；图标按钮 **20×20**、图标为 **12×12 填充几何**（token `GlyphReset`/`IconLock`/`IconUnlock`/`IconHide`/`IconClose`；换图标包**只改 token**）；悬停或选中时淡入 |
| 「还原」语义 | 弹确认框三选一：**只还原默认尺寸 / 尺寸和配置都还原 / 取消** |
| 缩放手柄 | **6×6**（原 12×12），**仅在选中或悬停时可命中** —— 防抢端口标记的点击 |
| 窗口交互带 | **6 px** 边框热区：边中点 / 角点为缩放；其余为拖动；锁定 / 隐藏 / 关闭按钮簇同处（右上角） |
| 取消选中 | 点内容区 / 点外壳 / 点本应用其他窗口 → `ClearSelection()`；**内容区点击不选中**（避免与模块内控件抢事件） |
| 默认尺寸 | 未声明 `PreferredWidth/PreferredHeight` 时回退 **320×220 DIP**；参考模块声明值：手动发送器 **330×330**、信息显示模块 **360×460** |
| 最小尺寸 | **180×120 DIP**〔源: 代码 `src/Ui/Views/ModuleWindow.axaml`（`MinWidth="180"` / `MinHeight="120"`）+ `src/Ui/ViewModels/ModuleViewViewModel.cs`（`MinWidth = 180` / `MinHeight = 120`，注释声明与 axaml 一致）〕——`09` §5 的 M1-15 小尺寸取值（150×70）**已被 ADR-0039 定稿段取代**，现行值以代码为准 |

### C2 标签页的标签条（G1 · 2026-09）〔源: 用户裁决"框架全做完再出模块页"· `roadmap.md` §3 第 12 项 · 代码 `Ui/Views/ModuleContentView.axaml`〕

| 项 | 规范 |
|---|---|
| 位置 | **当前页内容之上**、按声明顺序（`TabPages` 与其他元素同列，`Margin="0,2,0,4"`） |
| 排布 | 页签**横向**排列、间距 **4 px**、**不换行**（页数多时按容器裁剪，不做滚动条与 ◀▶ 箭头） |
| 页签 | 复用框架按钮外观；**最小高 24 px**、内边距 `10,2`、字号 **11** |
| **选中态** | **下边框 2 px + 前景 = `AccentPrimary`**（"做减法"：只靠**一处**对比表达当前页，不加底色、不加图标、不加粗体） |
| 未选中态 | 常规按钮外观（不改样式），标题为 `TextSecondary`/默认前景 |
| 页签文字 | 页节点 `Title`；空 ⇒ 页序号（`1`、`2`…） |
| 不画什么 | **不画页签条背景、不画分隔线、不画"当前页/共 N 页"文字**（页数由页签本身表达） |

**回归网**（`.dsh/skills/ui-rendering-and-third-party-control-discipline` §7）：① 真实窗口无头用例断言"页签出现 / 可见 / 非零尺寸 / 真指针点击后切换"（`tests/HYWDebugAssistant.Tests` 的 `ModuleWindowVisualTests.标签页_*` 与 `标签条_*`）；② **真出像素**用例断言"切页前后两帧必须有差异"并留下 PNG（`tests/HYWDebugAssistant.VisualSnapshots/TabStripSnapshotTests`，产物在 `%TEMP%\hyw-tab-snapshot\`）。

> **注意：快照产物目录为何独立** —— `OverlaySnapshotTests` 开头会 `Directory.Delete` 清空 `%TEMP%\hyw-overlay-snapshot\`，同一 collection 内执行顺序不定 ⇒ 共用目录会让本类的 PNG **被静默删掉**（断言全过、却没人能"看一眼"）。故标签条快照**自持一个目录**。

**窗口内层级（自下而上）**：`内容 → 交互带/手柄 → 端口标记 → 遮罩 → 连线/角色层 → 运行指示/按钮簇`。
端口标记**压在交互带之上**（层与内容层同处 `Row=1`）；叠加层的遮罩与角色/连线层**都不参与命中**（`IsHitTestVisible=false`），因此叠加层开启时标记**照样可双击建网**。

**已知取舍**：标记压在交互带之上 ⇒ **左右边缘中点手柄被标记覆盖处不可缩放**（角点与无标记的边段照常）。这是"标记是唯一建网入口"优先于"边中点缩放"的必然结果。

**模块自身简易标记**（如状态点、方向提示）属模块自身 UI，绘于模块窗口内，随模块视图走——与端口标记（框架的信息表达）是两回事。

## 端口标记（网络标签）= 数据接口的标准件 〔源: 05 §5.12/§5.17/§5.18/§5.23 + ADR-0039 D3 + ADR-0043 + ADR-0044 D2c + ADR-0053 D5/§5〕

端口标记是**模块标准件、常显**（没有开关），也是**唯一建网入口**。

| 项 | 规范 |
|---|---|
| 尺寸 | 竖排 **20×114** / 横排 **114×20**（长度 +50%）；与模块**外边框完全重合**（`PortMarkerPanel.EdgeInset = 0`） |
| 挂载边 | **有效边 = 用户覆盖 > 模块声明的默认边 > 数据流惯例**（发送右 / 接收左）。模块用 `PortDeclaration.Edge` 声明默认边（`Auto` = 沿用惯例 ⇒ 老模块零改动）；用户可把标记**拖到任意边**（C5-7 · G5），结果随组合件保存 |
| 锚点位置 | 沿边缘**按端口数等分**（`(i+1)/(n+1)`）；用户在组合件里调整过的端口用其偏移；固定锚点在模块拉伸时**按比例重排**（`Offset` 归一化，天然如此） |
| 锚点「固定」 | **三态**：用户设置 > 模块声明 `PortDeclaration.AnchorDraggable`（默认 `false` = 固定）（`decisions.md` 7.19）。**入口**：① 标记**同一条边的预留带里、标记长度之外**浮出的**图标按钮**（`GlyphUnlock` E785 / `GlyphLock` E72E，平时 `Opacity=0`、**悬停该标记时 120ms 淡入**，**点击 = 固定/解锁该口**）② 全局快捷键 **Ctrl+P**（一次切换全部模块的所有口） |
| 「固定」按钮的落位 | **带内、标记长度之外**（`PortMarkerPanel` 的 `AnchorButton` 层排布；**与标记共用同一份定位算法** `AlongEdgeSpan`）：优先放标记**之后**（沿边正方向）→ 否则放**之前** → 两端都不够（窗口接近最小尺寸）⇒ 贴**色条端**并允许压住色条，**永不压指示灯端**【待裁：该退化规则】。**为什么不能放"内侧"**：预留带与内容区的 20px 内边距**是同一块地方**（实测内容区右缘 298、标记带 [299,319]）⇒ 内侧没有空白，放那儿就是压内容（用户实测报过"落在了内侧遮挡 UI"） |
| 悬停反馈 | **只改鼠标指针**：可拖 = `SizeAll`、已固定 = 默认箭头（**不做悬停放大** —— 用户 2026-09 裁定，`decisions.md` 7.18）。「固定」按钮的显隐另由**标记悬停**驱动（`IsMarkerHovered`，视图在 `PointerEntered/Exited` 写回模型；按钮自身 `:pointerover` 保底 ⇒ 鼠标从标记滑到按钮上不会闪掉） |
| 槽位 | **四段固定槽位**（信息变化不引起排版抖动）：① **类型窄色条** `PortMarkerStripWidth = 6` ② **网络名**（`*` 吃剩余宽度、`CharacterEllipsis`）③ **方向箭头**（槽 20、`PortMarkerArrowFontSize = 16`）④ **连接状态灯**（`PortMarkerLampSize = 8`）。**「固定」按钮不在槽位里**（浮在标记之外 ⇒ 不占长度、不挤名称） |
| 名称字号 | **11 px**（超长省略） |
| 读数顺序 | 竖排分支整体旋转 **−90°**（`(x,y) → (y,−x)`）⇒ 内容 `x` 小的一端落到屏幕**下方**（文字自下而上读）⇒ **灯在上端、色条在下端**。由无头测试 `ModuleWindowVisualTests` 钉住 |
| 箭头语义 | **按边取向外 / 向内**：数据流向恒为"左→右"，发送口（右边缘）**向外**、接收口（左边缘）**向内**；屏幕上都表现为指向右侧 |
| 灯的位置 | 8×8；**离端部留 5 px**（不再贴到端部）；竖排箭头 `Margin = 0,0,0,4`（字形墨迹回中线） |
| 边框着色 | 标记边框 = **方向色**（`Border.portMarker` 默认接收色 / `.send` 发送色），与箭头同色 |
| 显示文本 | **只有网络名**：`NetworkText` = **标签名** / 已连但无标签 **`（直连）`** / 无标签未连 **`无网络`**。后两者是**网络名占位**，不是状态提示 |
| 不显示 | **不写连接状态文本**（删"（未连）"，状态只由灯表达）；**不写数据包类型文本**（标签名通常很长，放不下） |
| 类型表达 | ① 标记上 = **窄色条**（颜色 = 类型色板，见"类型 → 颜色"节）② 悬停提示里显式给出 **`类型：X`** |
| **通路速率（常驻）** | 标记上有速率槽：`PortMarkerViewModel.RateText`，字号 **10**（token `PortMarkerRateFontSize`，比名称小一号）；**未入网 / 无流量 = `---`**（不显示上一段旧值）。**速率常驻，与叠加层开关解耦**——"它不属于叠加层" |
| 悬停提示 | `口名（方向）` · `状态` · `类型：X` · 网络名 / 网络 / 对端 / 投递 / 丢弃 / 流量 · `双击填写/清除网络名`；**剔除"上次操作"**（`EditResult` 字段整体删除，提交结果仍送状态栏 = 反馈闭环不丢） |
| 编辑弹窗 | 宽度 **188**；**行内多句提示移除** → 标题右侧 **`?` 帮助按钮 + Flyout**（`Button.helpIcon`，与外壳各页同规则：点击弹窗、点外部关闭、不占版面）；失败原因**就地显示且保持弹窗打开**、输入不清空；**失焦不提交**；Enter = 确定、Esc = 取消，另有「确定 / 清除 / 取消」按钮 |
| 建网 | **双击标记就地编辑网络名 = 唯一建网入口**；同名即连，清空即退出 |
| 模板标识纪律 | 模板内需要被测试定位的元素用 **`Classes`**（`typeStrip` / `markerLamp`），**不用 `Name`** —— 竖排/横排两分支在**同一命名域**，同名会在首次布局时抛 `already registered`（编译期看不到） |

## 叠加信息层：语义、开关、层级 〔源: ADR-0045 D1 + ADR-0052 + ADR-0053 §5 + 05 §5.26/§5.27 + 09 §5〕

| 项 | 规范 |
|---|---|
| 语义 | **调试 / 观测层**（附加的信息显示层），不是常驻层 |
| 默认 | **关闭**（`showInfoOverlay` 默认 `false`；快捷键 **L**）；**旧配置里显式写过的值保留**（含更旧键 `showPortMarkers` / `showLinkLines` 的兼容读取） |
| 视觉 | **半透明深色遮罩（"灰玻璃"，token `OverlayScrim`）** 压暗模块自身内容 + 其上浅色信息（`OverlayInk` / `OverlayInkMuted`）。**不做模糊、不进设置项** |
| 遮罩浓度 | **不透明度 0.60**（浅 / 深两套一致）；浓度下调的原因：标记已改为沉到遮罩之下，过高会把它压得读不出通路速率 |
| 层级 | 层级顺序见「模块窗口视觉规范」节：**端口标记排在遮罩之前 ⇒ 被灰玻璃压暗**——用户口径："网络标签不高亮 = **做减法**，把它埋入灰色玻璃下方"。连线 / 角色层保持满强度；**不给标记加任何降权样式**（"做加法"的降权样式已删除） |
| 命中 | **遮罩与角色/连线层都不参与命中**（`IsHitTestVisible=false`） |
| 内容（现行） | **角色功能块 + 角色间数据线 + 角色自身信息文字 + 模块内部顺序线**（结构 ≠ 流量）|
| 信息区 | 左上 **`实例 · 模块名` 12 px** + **必要的一句事实 10 px**（`无数据口` / `未声明角色（N 个数据口）`）；**只在需要说明时**第二行才非空 |
| 删掉的东西 | 中心类型方块（按类型一个）· 每口一条线 · 「未连」文字 · 线上的网络名与 `×N` · 模块级汇总 · 结构行 · 线上的信息卡与 `OverlayCard` 令牌 · 标记的 `overlay` 降权样式 |
| 跨窗口长连线 | **v1 不做**（需 Win32 互操作 + 全局 z-order + 跨显示器 DPI 三事同办）——叠加层**只画"本窗内那半段"**，拼接处在公共边自然相接 |
| 动画纪律 | 叠加层关闭 ⇒ **退订**共享时钟；无订阅者 ⇒ **停表**；窗口不可见 ⇒ tick 内跳过重绘 |

## 两个信息维度（角色维度 vs 通路维度） 〔源: ADR-0053 §1/§2 D4/D5 + 18 §8.14/§8.15〕

**这是叠加层的信息设计主线，两个维度必须一眼可分。**

| 维度 | 回答的问题 | 落在哪 | 数据来源（框架算、UI 只格式化） |
|---|---|---|---|
| **角色维度** | "这块功能自己在跑多快" | **角色方块**上的纯文字（不画文本框；位置规则见下节） | `RoleView.RateBytesPerSecond` / `Delivered` / `Dropped`，= 该角色**产出侧**承载网络的 `BusByteRate` / `Delivered` / `DropTransport` 之和（**有输出口 ⇒ 输出网络；纯汇分块 ⇒ 输入网络；不相加入/出两侧**） |
| **通路维度** | "这条网络在跑多快" | **端口标记**的速率槽（见「端口标记」节） | 该口队列的按宿计速率；取不到时用本条连接的**搬运字节速率**（绑定诊断） |

> 二者读同一份框架诊断，但**表达对象不同**——不能因为底层同源就当作一个维度。
> **两处曾导致速率恒为 `---`/`0` 的键与读数问题（已修，勿复发）**：① 角色的**承载网络必须按 `NetworkKey` 聚合**——`BindingDiagnosticView.Key` 是**逐源键**（`源 → 宿子集`），按它建表再用网络键查会永远查不到；② **速率计必须可重复读**：`RateMeter.Observe` 每次重算"自上次观察以来"的增量，而一次 UI 刷新会对每个模块各读一遍诊断 ⇒ 除第一个消费者外全读 0；`RateMeter.MinIntervalSeconds = 0.1`（间隔过短的重复观察返回上次速率）。

## 角色方块（角色维度） 〔源: ADR-0052 §3/§4/§12.5 + ADR-0053 D3/D4/§5 + 05 §5.26/§5.27 + 18 §8.13〕

**角色 = 模块声明的「功能分块」**（不是框架派生量）。

| 项 | 规范 |
|---|---|
| 声明面 | SDK 只增：`RoleDeclaration(Id, Type, Inputs, Outputs, DisplayName)` + 静态 `Input/Output/Both`；`IModuleDeclaration.DeclareRole`。**一个角色只有一种数据类型**；**一个口最多属于一个角色**；**口数不设上限**；**声明几个画几个**（与方向、类型数量无关） |
| 校验（两处同规则） | `ModuleInstanceFactory.BuildRoles`（运行期：非法 ⇒ **报 Issue 并忽略该条**）与 `ModuleContract.CheckRoles`（SDK 自检）：`Id` 唯一 · 类型可在本模块解析 · 口存在且方向相符 · 一口最多一角色 · 至少一个口。**口数 > 2 只在 SDK 自检的独立建议通道 `Advisories` 给建议**（不进 `Problems`、运行期不报） |
| 布局 | **单列竖直堆叠、居中**；宽度 = `RoleTextMetrics` **确定性纯函数**估算（CJK 一字宽 ≈ 字号、拉丁 ≈ 0.6 字号、留 5% 余量），夹在 **[64, 176]**；块高 **34**；放不下 ⇒ **只画得下的 + 底部 `+K`**（如实报出未画数量）；**不分左右侧** |
| 方块内容 | 第一行 = **功能名**（无则**类型短名**，11 px）· 第二行 = **`m/n`**（10 px） |
| `m/n` 口径 | `m` = 输入侧连接的**对端角色数**、`n` = 输出侧同理；去重键 =（对端实例, 对端角色）⇒ 同一对端角色的多个口仍算 **1**；**无该侧口 ⇒ `--`**（界面显示，内部 `null`）；**有口未连 ⇒ `0`**（两者含义不同，必须区分）。唯一来源 = `RoleModel.PeersOf`（从**网络成员关系**派生）；**模块无法自报这个数** |
| 方块配色 | 填充 = **类型色**（`PacketTypePalette` 按 `TypeKey`，跨模块一致）· **左边缘 = 接收方向色（有输入口才画）· 右边缘 = 发送方向色（有输出口才画）** · **口数 > 1 才在该边画刻痕** · **不带状态色**（停流/悬空只在端口标记与线上表达） |
| 角色自身信息文字 | **纯文字、不画文本框**；**左对齐**（三行同一起点 = 方块左边缘）；默认在方块**上方**（**间隙 5**），上方放不下（会压到左上身份/出窗）⇒ 改到**下方**；一律留在 `Gutter` 以内。三行：① **速率大字 15 px**（`RoleTextMetrics.RateFontSize`，无流量 `---`）② **`输入 m / 输出 n`**（**口数**，10 px）③ **`类型：<第一个语义标签>`**（10 px，**截断 8 字**，未声明不占位；**禁止外显过长描述**） |
| 零口 / 未声明角色 | **零数据口 ⇒ 角色集合为空 ⇒ 不画方块**（信息区写 `无数据口`，**不是错误状态**）；**模块有数据口但未声明角色 ⇒ 不画方块、不画线**，信息区写 `未声明角色（N 个数据口）`（**框架不发明角色**，也不做兼容回退——避免"两套角色模型并存"） |
| 命中 | **方块 v1 不参与命中**（详情仍在端口标记悬停与拓扑诊断里） |
| 红线 | 角色 **不参与**建网 / 兼容判定 / 停流 / 投递 / 计量，且**不进组合件**（持久化里不得出现任何角色字段）；**框架不内置任何角色类型枚举 / 图标 / 业务词**（只有"标识 + 名字 + 类型 + 口集合"） |

参考模块的声明面（各 1 个角色）：数据发生器 / 手动数据发送器 = 纯源（`--/n`）· 信息显示模块 / 记录器 / 断言器 = 纯汇（`m/--`）· 多源融合器 = **一块两入一出**（`fuse`，输入 `in1`+`in2` / 输出 `out`，`m/n` 的 m 可为 2）。

## 连线：端点、绘制、流向、相位 〔源: ADR-0053 D1/D2/§5 + ADR-0052 §5 + 18 §8.13/§8.14〕

| 项 | 规范 |
|---|---|
| 一条线 = | 一次"角色 → 角色"的数据流（角色对：同一 **(本端角色, 方向, 对端实例, 对端角色)** 聚合为一条；多源网络下不同模块的源 = 不同对端 ⇒ **各自一条线**） |
| 端点 | **两个角色方块的中心**（`ConnectionOverlay.LinkSegment`，纯函数） |
| 画出来的那段 | **本窗内 ∩ 本端方块之外**（起止落在方块边界朝对端那一点）⇒ 视觉上从方块中心出发、**不横穿方块**、不在方块里留淡线；发送段朝外、接收段朝内 |
| 两侧共线 | 两端都用**同一套** `LayoutRoles` + `LinkSegment` 算，各窗只画自己窗内那一段（`ClipSegment`，Liang–Barsky）⇒ **严格共线**：相邻无缝 · 未拼接恰好缺两窗之间那段 · 重叠也不错位。对端锚点由 `ModuleWindowsViewModel.ResolvePeerAnchor` 用**与对端同一套** `LayoutRoles` 算 |
| 线宽 / 线型 | 粗 **2.5 DIP**；虚线 **dash 6 / gap 4** |
| 颜色 | **本端方向色 → 中点色**（发送色与接收色的 50% 混合）渐变；`GradientEnds(start, end, localIsSend)` 把**本端方向色锚在方块那一端**（与绘制顺序无关）⇒ 两端公共边颜色**恰好相接** |
| 箭头 | 端部 **6 px 实心三角**，色 = **该口方向色**；画在**指向本模块的那一端**（发送 ⇒ 朝窗外；接收 ⇒ 朝本端方块） |
| 未拼接 | 在**窗口边界那一端**画**竖杠断口 + 对端名** |
| 线上文字 | **线上不写任何文字**（不写网络名、不写 `×N`、不写速率/投递/丢弃）——网络标签属**接口层**（端口标记的地盘） |
| 角色对之间的口对条数 | `RoleFlowView.PortPairCount` 如实报出"这一对角色之间有几条口对投递"，**不上图**；`NetworkKeys` **只用于取指标**（速率/投递/丢弃）。"看哪条线动了"（同网络内 A→B 与 A→C 都亮）是已登记的已知局限 |

**对端角色不可用（未装入 / 该模块未声明角色 / 占位）⇒ 不画这条线**（**裁定**）——与"未拼接就在窗口边界画断口 + 对端名"的现行行为一致：**避免让人误以为"线还在"**；此时信息区按「角色方块」节给一句事实（`未声明角色（N 个数据口）` / `无数据口`）。〔源: ADR-0052 §6 兼容表 + 红线③"不发明角色"；ADR-0052 §5 末条的"回退画到对端窗口中心"**不采用**〕

### 虚线相位与 `DashStyle.Offset` 的单位/符号约定 〔源: ADR-0053 D2/§5 + 18 §8.14 + 09 §5〕

- **实测约定**：`DashStyle.Offset` **单位是笔宽倍数**（不是 DIP）——笔宽 2、偏移 +2 ⇒ 位移 **4 DIP**；且**偏移增大 ⇒ 图案整体朝几何起点移动**。
- **绘制方向恒按数据流方向** ⇒ 两侧取**同一个偏移量** = **`-相位 ÷ 线宽`**（`OverlayAnimationClock.DashOffset`）：取负 = 图案沿绘制方向从起点向终点前进；除以线宽 = 速度不随线宽变化。
- **相位是时间相位**（`Phase = f(秒)`，**60 Hz**）——**不是**帧计数。
- **取模周期必须用真实周期** = `(6+4) × 线宽 = 25 DIP`：若按 `dash+gap`（10 DIP）取模，会出现"平滑一段后突然跳一下"。
- **像素级判据**：走满一个周期的画面与零相位**逐像素相同**。
- 结果：**发送向外 / 接收向内**（沿数据流方向流动）。

## 模块内部顺序线（结构，不是流量） 〔源: ADR-0052 §4/Q7 + 18 §8.13 + 09 §5〕

- 声明面：`FlowDeclaration(FromRoleId, ToRoleId, Label)`（**角色 → 角色**——角色自身已含 in/out，只表达**块与块之间**的顺序）；经 `ModuleInstanceFactory` 校验（必须"存在的接收角色 → 存在的发送角色"，重复去重，**非法报 Issue 并忽略该条**）。
- 画法：**细实线 + 中性低对比色 token `OverlayFlow` + 不参与流动**；**零声明 ⇒ 不画**（框架不猜）。
- 参考模块都是单块 ⇒ 零声明零线；范例 = 融合器的 `in1→out` / `in2→out`。
- 它**只呈现**，不参与建网 / 兼容 / 停流 / 投递 / 计量，也不进组合件。

## 方向语义色（发送 / 接收） 〔源: ADR-0044 D1a/D2c/D3b/D5/D6 + 05 §5.24 + 09 §2.1〕

**方向色与主题色完全解耦**：主题色只表达框架性交互语义（选中 / 聚焦 / 活动 / 参考线），方向色驱动"发送 / 接收"这一稳定语义。

| token | 浅色 | 深色 | 语义 |
|---|---|---|---|
| `DirectionSend` | `#EA580C` | `#F59E0B` | **发送**方向 |
| `DirectionReceive` | `#0891B2` | `#22D3EE` | **接收**方向 |

默认刻意**避开"红 / 绿"对**（色盲友好）；**不再从主题色派生**。

**消费者表（新增消费者必须在此登记）** 〔源: 05 §5.24〕

| 语义 | token | 消费者 |
|---|---|---|
| 发送方向 | `DirectionSend` | 端口标记**箭头**（发送口）· 端口标记**边框**（`Border.portMarker.send`）· **建网预览描边** · 叠加层**流向箭头** · 角色方块**右边缘**（有输出口才画）· 连线段（发送侧端） |
| 接收方向 | `DirectionReceive` | 同上（接收侧；**默认类即接收**，无需额外类）· 角色方块**左边缘**（有输入口才画） |
| 连线段 | `DirectionSend` / `DirectionReceive` | 叠加层连线（两端独立按同一规则渐变 ⇒ 公共边颜色相接） |
| 连接 / 运行状态 | `SemanticOk/Idle/Warn/Error` | 状态灯（**不开放自定义**） |
| 交互强调 | `AccentPrimary` | 选中边框 · 对齐参考线 · 活动栏活动项 · 按钮 active/悬停 · 弹窗边框 |
| 模块私有绘图（**待改**） | `AccentSecondary`（曲线 `Stroke`） | 与 D7 冲突：应由**模块自己**决定 —— 归"数据-颜色专项"（当前只做预留） |

**设置**：`directionSendColor` / `directionReceiveColor` —— **空 = 跟随主题默认值**；**不校验、不提示**（裁决 D6：完全尊重用户选择）；设置页「外观」区两行（色片 + 色值文本，或显示 `跟随主题`）+ **实时预览**（`↑发送` / `↓接收`）。

**开颜色设置的准入判据（以后新增语义色按此办）**：① 该语义在**多处**出现；② 用户改色后仍能靠**形状 / 位置**读懂（双重编码）；③ 两色**同屏同时出现且需区分**。三条全"是"才开设置项；**用户可调颜色总数上限建议 ≤ 6**（主题色 · 背景 · 发送 · 接收 · [类型色板] · [网络色]）。

## 类型 → 颜色：色板、覆盖、调色板窗口 〔源: ADR-0054 + 05 §5.28 + ADR-0049 D6 + 18 §8.13〕

| 项 | 规范 |
|---|---|
| 唯一色彩来源 | 色板 **`PacketTypePalette`**（`Ui/ViewModels`）——**端口标记窄色条**与**叠加层角色方块填充**共用同一入口 ⇒ 改一处、两处同步，永不漂移 |
| 键 | **类型身份**（`标识@v版本`；未声明类型的旧模块 ⇒ `ContractShape.Describe()`），与 `PortView.TypeKey` / 色板键 / 角色键 **同源**；**不得**用呈现文本代替（不同标识即使形状相同也是不同的量） |
| 颜色从哪来 | ① 用户在表里指定的**覆盖色**；② 否则 **FNV-1a 稳定哈希自动色**（→ HSL，饱和度 / 亮度固定）⇒ **不配置也能分辨类型**，且**跨模块 / 跨进程 / 跨重启同色**（`string.GetHashCode` 每进程变，不可用） |
| 覆盖表接口 | `SetOverride` / `RemoveOverride` / `OverriddenKeys`；持久化为应用设置 `typeColors`（键 = 类型身份，值 = `#RRGGBB`），**缺省不写任何条目** |
| 改色入口（唯一） | 表 → **`ShellViewModel.ApplyDataTypeColor(typeKey, hex)`** ⇒ ① 色板 ② 设置落盘 ③ 界面重画（`PortMarkerViewModel.RefreshTypeBrush` 显式通知；角色方块在绘制期取色，下一次重绘即生效） |
| 影响面 | **只影响呈现**：不参与建网 / 兼容 / 停流 / 投递 / 计量，**不进组合件**（应用级显示偏好） |
| 颜色体系 | 类型颜色 = **一套全局颜色**、由用户自己改、**与主题色解耦**（换主题不改已选类型色）；仅**调色板里的推荐色**与主题同一套 |

**表的位置与结构**（侧边栏「交互」页底部新增分区「**数据结构 · 颜色**」，带帮助问号 + 空态 + 列表）：

- **一行 = 一种数据类型身份**（键同上）；**列** = ① **色块**（点开取色）② **类型身份**（等宽、超长省略、悬停给全文）③ **形状文本**（次要色）④ **用在**（`N 个口 · M 个角色`）。
- 只列**当前现场真出现过的**类型（来自各实例的端口类型身份 + 角色类型身份）——"声明了但没用上"的不列；**不发明类型**。空态 = 一句事实 `现场还没有数据类型`。
- **刷新纪律**：按 **0.5 s** 节奏**就地改值**（`DataTypeColorRowViewModel.Update`），**只有类型集合增删才动 `Rows`**——早期"每次刷新重建整张表"会销毁正在打开的弹窗/悬停目标（表现为"鼠标指到色块上不停闪烁"）。
- 「恢复自动色」= 移除该类型的覆盖 ⇒ 回落稳定哈希色（无覆盖时点击结果等价）。

**调色板窗口 `ColorPickerDialog`（所有取色位置复用）**：

| 项 | 规范 |
|---|---|
| 实现 | Avalonia 官方 `Avalonia.Controls.ColorPicker`（**MIT**，12.1.2）的 `ColorView` |
| 布局（一屏全见） | **左 = 取色器**（两页签：**光谱** / **分量**＝RGB·HSV 滑块 + **十六进制输入**；底部当前色预览条）+ **右 = 常驻 8 个推荐色**（= `ThemeApplier.Presets`，与设置页"主题色"同一套，不必切页签就能点） |
| 精简 | **关掉**控件自带的"色板"页签（`IsColorPaletteVisible=False` ⇒ 推荐色**唯一来源**）与强调色增减压块（`IsAccentColorsVisible=False`）；**不做**自定义色格；**不带透明度**（本工程取色均为不透明色） |
| 按钮与语义 | `ColorPickerDialog.ShowAsync(owner, initial, title, resetText, hint)` ⇒ `ColorPickerResult(Confirmed, Color, Reset)`；**调用方自己解释 Reset**（类型色 = 移除覆盖；方向色 = 置空跟随主题） |

| 不做 | 不做**指标面板**（颜色表**只做图例**，不加速率/流量列）；不做主题联动校验（不提示两色相同/低对比） |
| 布局纪律 | 标题**只由窗口标题栏给**（窗口内不重复写）；提示文字**整行独占 + 自动换行**；按钮**单独一行右对齐**；窗口 `SizeToContent="WidthAndHeight"` |
| 模板（必做） | `ColorView` 的模板在**它自己的程序集**里、`FluentTheme` **不含** ⇒ 必须在 `App.axaml`（及快照项目 `SnapshotApp`）显式挂 `avares://Avalonia.Controls.ColorPicker/Themes/Fluent/Fluent.xaml`。**不挂不报错，只是什么都不画**（窗口只剩标题 + 提示 + 按钮）；回归网 = `ColorPickerDialogSnapshotTests`（真实 Skia 出像素 + 数"不同颜色数"） |

## 状态语义映射（颜色 + 形状双重编码） 〔源: 09 §7 + ADR-0052 §3 + 18 §8.11/§8.12〕

| 状态 | 颜色 | 形状 / 图标 | 含义 |
|---|---|---|---|
| 正常 / Active | `semantic.ok` | 实心点 | 参与数据流 |
| Disabled | `semantic.idle` | 空心点 | 保留拓扑、暂停数据流 |
| 停流（上游无输入） | `semantic.idle` | 空心点 + 灰线 | **合法状态**，非错误 |
| 无数据流（方向不匹配） | `semantic.warn` | 三角 | 连接存在但无数据 |
| 悬空（口消失） | `semantic.warn` | 断续边框 | 保留声明 + Issue |
| 异常停机 | `semantic.error` | 叉 / 惊叹 | 模块活动体异常退出 |
| Issue 标注 | `semantic.error` / `warn` | 角标 | 归属对象 + 汇总列表 |

| 交互 | 反馈 |
|---|---|

| 聚焦 / 高亮相关者 | 相关模块与连线提升不透明度；其余降透明度（**不隐藏**） |
| 拖动 | 被拖对象半透明；**吸附命中时显示对齐辅助线** |

| 端口锚点可拖动 | 悬停时锚点放大 + 光标变化；锁定状态显示锁图标 |
| 禁用吸附（快捷键） | 状态栏 / 光标提示"吸附已关闭" |
| **输入处理失败**（G3 · 2026-09） | 该输入框边框 → **`SemanticError`**、**线宽 2**（常态 1）——"**显著标红**"（用户草图原文）。**做减法**：不叠背景色、不加图标、不弹提示；原因文本仍走该输入框右侧的**就地提示**位。**只在模块回报失败时出现**；**下一次提交即刷新**（框架在投递入队时清旧结果） |
| 诊断提示（轻量） | 图标 + 短文本，**低饱和度**（不打扰）；位于模块窗口内或诊断弹窗 |

## 几何吸附：参照线模型 〔源: ADR-0042 D1–D6/§7.2/§7.6 + 05 §5.22 + 主文档 §10.1-5〕

**唯一判据：一切吸附 = 把「模块外框的某个锚点」吸到「某条参照线上」。** 没有第二套判据，也没有"按缝隙大小猜邻接方向"这类启发式。

| 项 | 规范 |
|---|---|
| 类型 | `SnapLine(AlignsX, Coordinate, Start, End, Source, Owner, IsOwnerLow)`；`SnapLineSource` = `FrameEdge` / `FrameCenter` / `PortAnchor` / `ShellEdge` |
| 线来源 | ① **其他模块的外框**：`SnapEngine.LinesOf(rect)` = 4 条边 + 1 条中心线 ② **端口锚点**：`PortAnchorPair` ③ **外壳**：`SnapEngine.LineOf(SnapReferenceLine)` = **只有右边缘一条竖线**，与模块**进同一张线表**（不再是特殊通道） |
| 允许的锚点由线来源决定 | 外框边 → `{0,1}`；中心线 → `{0.5}`；外壳边 → `{0,1}`；端口锚点 → **只用被拖模块自己的那个口**（偏移随配对传入） |
| 级别派生 | 外框边：`contact = (anchor == 1) == IsOwnerLow` 且**交叉轴重叠 > 4 px** → **贴合**，否则**边缘对齐**；中心线 → **模块中心线**；端口锚点 → **端口锚点**（交叉轴间隙 **≤ 24 px** 才参与）；外壳边 → 沿线重叠 > 4 px ? **贴合** : **边缘对齐** |
| 级别顺序 | **贴合 > 端口锚点 > 模块中心线 > 边缘对齐**（**跨级不比较**；同级取偏移更小者）。**边缘对齐保留**在最低优先级（跨屏对齐的正当用途） |
| 同坐标去重 | 位置相差 **≤1 px** 的候选**只保留级别最高者**（消除"端口在 0.5"与"模块中心线"这类重复登记；同坐标 ⇒ 同偏移 ⇒ 不影响落位） |
| 端口定轴 | **左 / 右边的口 → 约束 Y；上 / 下边的口 → 约束 X**（当前模型里口只在左 / 右边 ⇒ **恒为 Y**）；接近范围 24 px 也按**邻接方向的法向**判定 |
| **容差（两档）** | **对齐类 = 吸附距离**、**贴合类 = 吸附距离 × 2**；默认吸附距离 **4 px**、范围 **2–8 px**、越界拒绝（写设置时拒绝且不改当前值）。**无额外释放带**：离开自己的容差带立即跟手 |
| 设置项 | `SnapDistance`（JSON `snapDistance`），设置「外观与显示」页一行（与刷新率同段，ToolTip 说明"越小越跟手、越大越容易吸上；贴合用它的 2 倍"）；**在线即时生效**（VM 每次 `Refresh` 从设置同步） |
| 交互模型 | **拖动中实时吸附**（Visio 式：小半径 + 离开即松 + 参考线给反馈）；**不做"松手吸附"**（已否决）；**不做网格吸附** |
| 引擎性质 | `Snap` 仍是**纯函数**（无跨帧状态）；策略由调用方（`ModuleWindowsViewModel`）持有 |
| 已知边界（接受） | 候选交接处的位置跳变**上界 = 2 × 容差**（默认 8 px），由"吸附距离"设置直接控制；**"方向一致性规则"已砍掉**（跨帧状态，无额外收益的复杂度） |
| 旧通道 | `CollectSnapTargets`（矩形列表）与 `CollectReferenceLines`（外壳特例）**已删除**，合并为 `CollectLines(draggingId)` + `BuildPortAnchors(draggingId)` |
| 候选通道 | **端口对齐恒开**（不再与"是否显示叠加信息层"绑定） |

**回归判据（纯几何）**：1 px 步进扫过容差边界时**模块位移 ≤ 1 px**、方向不反转；离开容差带后不再被吸住；**交叉轴无重叠不得算贴合**且不产生参考线；任意输入（含 125% 缩放下的小数尺寸/参照）⇒ 吸附结果与模型几何均为整数物理像素。

> 本节约束**为什么写成这样**（吸附振荡 / 拉脱 / 缝与像素级错位的完整代码证据链与实测数值）见 **附录 A**。

## 拼图组、外壳跟随与平移落盘 〔源: ADR-0042 D8/§7.2 + 15 §8.3/§8.4 + 05 §5.22 + 主文档 §10.1-3〕

| 项 | 规范 |
|---|---|
| 外壳的角色 | **拼图里的一个节点**（拼图起点）；与模块之间**只有单侧吸附**（只提供**右边缘**一条参照线） |
| 成组谓词 | 模块 ↔ 模块沿用 `AreJoined`；**模块 ↔ 外壳只认"左边缘贴右边缘 + 竖向重叠"**（不允许贴外壳的左/上/下边）；组 = **接触连通分量** |
| 组关系的存储 | **由位置派生，不作为独立信息存储**：拖动**开始**算分量并**冻结** → 期间整组平移 → **结束**重算；组具**传递性**；`Ctrl` 可**独立拖动**组内单个模块；位置变化的三个来源（拖动 / 加载组合件 / 模块尺寸或端口锚点调整）**每处结束后都要重算** |
| 移动外壳 | `TranslateShellGroup(dx, dy, preMoveShell)`：**只平移与外壳相连的那一组**（**没拼上的模块留在原处**）；容器**锁定成员**（钉住）不入组、不随整体移动 |
| 拖动组内模块 | 拖动组包含 `ShellNodeId` 时 → `ShellTranslationRequested` → **外壳窗口一起走**；`CancelDrag` 按累计位移取反还原；`OnShellMoved` 在交互期间**只刷新参照、不再联动平移**（防双重位移自激） |
| **判定必须用移动前几何** | `preMoveShell` 必须是**移动前**的外壳矩形——用移动后的位置判"谁与外壳相连"会把"贴上了"判成"没贴上" ⇒ 模块不跟随 |
| 外壳参照基准 | `PublishShellRect` 取**可见外框**（`Ui/Views/WindowFrameProbe`：优先 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`（物理像素）→ 回退 `GetWindowRect` → 再回退客户区）。取客户区会与用户看到的窗口边缘差一个可见边框宽 ⇒ **模块贴上去总有 1px 缝** |
| 锚定 / 跟随 | 跟随按**锚定集**（拖动结束时把贴壳模块集合记为锚定集，内存态、可由几何重算兜底）+ 组传播，**不再逐帧重新判定**；释放 = 用户把模块拖离外壳（间隙 > 释放阈值）或改动外壳位置使重叠消失 |
| 拖动期间的驱动权 | **整组**成员都标记 `IsInteracting` ⇒ 窗口回写 `OnWindowMoved` 不会改写组内成员的位置（消除"拖动中组内被逐个取整"的像素级错位） |
| 平移落盘 | 只改内存 + 记待提交（`_pendingSceneCommits`），**180 ms 防抖**后 `CommitSceneTranslation()` 合并成**一次**变更；保存组合件前也先冲一次。**未落盘期间 `SyncModules`（60 Hz）必须跳过这些模块**，否则会被旧布局一帧帧拉回（表现为"移动主窗口时模块跟不动"） |
| 交互结束 | `EndDrag` / `EndResize` 结束时**统一取整并落盘**（只在结束，拖动中不引入新的写入） |
| 吸附参照收敛 | **屏幕工作区退出吸附候选**（仍用于默认摆放与不出屏钳制）；**不做边界钳制**；模块 ↔ 模块吸附不变（左右/上下贴合 + 中心线对齐） |

## 对齐参考线（辅助线）的绘制 〔源: 15 §8.6〕

| 项 | 规范 |
|---|---|
| 绘制位置 | 对齐线画在**被拖窗口内部**（ADR-0034：**不做跨窗口覆盖窗**） |
| 可见性判据 | `GuideOverlay.IsDrawable(position, extent, tolerance)`：**容忍"贴边超出"**（容差 = 边框内缩量级 **3 DIP**）——窗口边框 `BorderThickness=1` 会让叠加层内缩，坐标却按客户区原点算 ⇒ 上/左对齐的线落在 `0`（可见），**下/右**会落到 `范围 + 2` 而被朴素判据直接排除（根本不画）；同时仍排除"离得远"的线（那属于对方窗口） |
| 收进量 | `GuideOverlay.InsetForDrawing`：贴边时把线**收进半个线宽**（位移 ≤ **0.5 px**），否则一半线宽被裁剪、虚线不可见；两个窗口收进量相同 ⇒ 仍在同一条直线上 |

## 附录 A：为什么这么定 —— 吸附与像素对齐的实测证据 〔源: architecture/15-snap-and-anchor-remediation.md §2 / §3.4 / §3.5 / §6.3 / §7.1–§7.3 / §8.4〕

> 归位说明：以下内容**不是现行口径**（现行值见本册正文），但它们是"现行约束为什么写成这样"的**唯一记录**，或是一次性验证手段的设计。删掉它们，后来者会重犯同一类错误。**原样保留，未作改写（数值未作概括）。**

### A.1 三类根因的完整证据链（`15` §2）

#### A.1.1 吸附振荡：同一轴上多个候选同时落在容差内，且没有粘滞（`15` §2.1）

**代码证据**

- `SnapEngine.Snap` → `FindBest`：每个轴一次性生成 5 类候选（左右贴合 ×2、左/右/中心对齐 ×3，`SnapEngine.cs:302-324`），选出唯一的赢家，规则只有两条：**贴合优先于对齐**、**同级取 |Δ| 最小**（`SnapEngine.cs:258-267`）；**没有进入/释放两个阈值，也不记住上一次命中谁**。
- 容差 `DefaultTolerance = 8`（`SnapEngine.cs:38`），而指针在屏幕上是**整数像素**——1px 的抖动即可改变"谁 |Δ| 更小"。

**数值实验（临时测试，已跑过并删除；几何：邻居 320×200 @ (1000,400)，被拖模块 330×220，X 已贴合）**

| 指针 rawY | 386 | 387 | … | 394 | **395** | 396 | … | 408 | 409 |
|---|---|---|---|---|---|---|---|---|---|
| 模块 snappedY | 390 | 390 | … | 390 | **400** | 400 | … | 400 | 409 |
| Δ（模块 − 指针） | +4 | +3 | … | −4 | **+5** | +4 | … | −8 | 0 |

- 在 `rawY 394 → 395`（指针**只动 1px**）时，模块从 390 **跳到 400（+10px）**；反向移动时同样 10px 回跳。
- 在 `[386,408]` 这 23px 区间内，模块**始终处于吸附态**（Δ≠0），只在 380/390/400 三个位置之间台阶式跳——**它不跟随指针**。
- **10px 这个数** = 两个模块尺寸差的一半（220−200=20 → 中心对齐与边缘对齐相差 10px）。**这正对应"标签接近中心线时"**：两模块中心线接近时，"中心对齐"与"边缘对齐"两个候选只差几个像素，同时落入 8px 容差，赢家随 1px 抖动来回切换 ⇒ **振荡**。

**次生缺陷（同一根因，须一并修）**

- `SnapEngine.Snap` 的贴合候选**不要求交叉轴重叠**：`XCandidates` 无条件产出"右边缘贴左边缘"候选（`SnapEngine.cs:304`），而"是否拼成一组"用的 `AreJoined` **要求重叠**（`SnapEngine.cs:146-153`）——两处口径不一致。
- 实测：两模块竖直相距 **1400px**（完全无重叠）仍被 X 吸附走 3px，并生成一条 **1844px 长的参考线**（388..2232）。这既"莫名其妙被吸走"，又"线画得离谱"。

> **现行对应约束**：贴合必须"交叉轴重叠 > 4px"，否则降级为边缘对齐（见本册"几何吸附"节）。

#### A.1.2 "拉脱"：锚定判定**用的是移动之后的外壳矩形**（`15` §2.2）

**代码证据（三步推导，可复核）**

1. `ModuleWindowManager.OnShellMoved()`（`ModuleWindowManager.cs:267-279`）：先记 `previous = ShellRect` → **`PublishShellRect()` 把 `ShellRect` 更新为新位置** → 再调 `FollowShellMove(dx, dy)`。
2. `ModuleWindowsViewModel.FollowShellMove`（`ModuleWindowsViewModel.cs:421-428`）的锚定条件是 `Math.Abs(m.Rect.Left - shell.Right) <= 2` —— 此处 `shell` 已是**新的** ShellRect，而模块 `m` **还在旧位置**（还没被移动）。
3. 设模块原本严丝合缝贴着外壳：`m.Left == 旧 shell.Right`，于是 **gap = |m.Left − 新 shell.Right| = |dx|** ⇒ 判定退化为 **"本次外壳位移 ≤ 2px 才跟随"**。

**推论（与用户描述完全吻合）**

- 慢速拖动：每个 `PositionChanged` 的位移 1–2px ⇒ 跟随正常；
- **快速拖动**：单个事件位移 10–40px ⇒ gap > 2 ⇒ **不跟随**；下一次事件里模块与外壳的差距更大 ⇒ **永远不会重新锚定** ⇒ 表现为"**被拉脱**"（且是永久性的，直到用户手动拖回去）。

**放大器**：`FollowShellMove` 末尾**每个事件都提交一次 `UpdateModuleLayouts`**（`ModuleWindowsViewModel.cs:457`）→ 拖动中每秒几十次变更提交 → 外壳拖动本身卡顿 → OS 合并鼠标消息 → **单次位移更大** ⇒ 更容易触发脱开。即"加速度越大越容易拉脱"存在**自增强**链路。

> **现行对应约束**：锚定 / 分组判定必须传**移动前**的几何（`preMoveShell`）；跟随按锚定集、不再逐帧重判；平移 180ms 防抖合并落盘（见本册"拼图组"节）。

#### A.1.3 缝与像素级错位：模型存小数物理像素，窗口只能落在整数物理像素（`15` §2.3）

**代码证据**

- 模型几何是**物理像素的小数**：`Width = PreferredWidth * _scale`（`ModuleViewViewModel.cs:99`）、拖动目标 `targetX = pointerX - _dragPointerOffsetX`（`ModuleWindowsViewModel.cs:471`）都是 double。
- 窗口落位 / 落尺寸时才取整：`position = new PixelPoint((int)Math.Round(geometry.X), …)`、`window.Width = geometry.Width / scaling`（`ModuleWindowManager.cs:224-247`）。**位置与尺寸各自独立取整**，没有任何"回写对齐"。
- 本机实测 DPI：`HKCU\Control Panel\Desktop\LogPixels = 120` ⇒ **缩放 125%**。于是
  - 参考模块"手动数据发送器"声明 330×330 DIP ⇒ **模型 412.5 × 412.5 px（小数）**；外壳 858 DIP 高 ⇒ 1072.5 px（小数）；
  - 320×220 → 400×275 px（整数，恰好没问题）——**所以只有部分模块 / 部分方向会"有时"错位**。
- 相邻两模块的贴合关系是在**模型坐标**里成立的（`A.Right == B.Left`，小数），但**屏幕上**两个窗口各自取整 ⇒ 视觉上可能是 0px、1px 缝或 1px 叠——这正是"经常有缝或是错位""有时像素级错位"。
- **U-4 的"再拖动时"额外一击**：拖动中只有**被拖模块**被标记 `IsInteracting`（`ModuleWindowsViewModel.cs:383`），**同组其他成员没有**；而 `OnWindowMoved`（`ModuleWindowManager.cs:192-208`）对 `IsInteracting == false` 的模块会把**窗口取整后的位置写回模型**（`module.X = window.Position.X`）⇒ 组内成员在拖动过程中被逐个取整、被拖模块保持小数 ⇒ **组内相对位置被破坏**；`EndDrag` 再把这份"半整数"布局落盘（`ModuleWindowsViewModel.cs:570-600`）⇒ 下次拖动的起点就带着 ≤0.5px 的错位。
- **待确认的一面（不猜）**：U-3 里"外壳与模块的缝"还可能来自**参照基准取的是外壳客户区右边缘**（`PublishShellRect` 用 `PointToScreen(0,0)` + `ClientSize`，`ModuleWindowManager.cs:290-300`），而用户视觉上的"窗口边缘"是**可见外框**（Win 的窗口矩形还含不可见缩放边与 1px 可见边框）。这一步需要**一次性测量**才能定论。

> **现行对应处置**：① 单一量化点（整数物理像素）② 窗口只做"整数 ÷ 缩放" ③ 拖动期间整组标记 `IsInteracting` ④ 结束一次性回收 ⑤ 参照改用**可见外框**（`DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`；实测"缝"= 可见边框约 1px）。
> **另一次实测排除**（`15` §7.5）：模型几何 vs 窗口实际几何**差全为 0**（413×413 / 位置一致 / 缩放 1.25）⇒ **"尺寸不匹配"不存在**；指针换算差值 `err=0`。

#### A.1.4 指针坐标回授（第二轮反馈的真因，`15` §7.2）

原实现：`屏幕点 = Position（窗口位置） + GetPosition(this)（窗口内局部坐标） × 缩放`。

**两个来源不是同一次采样**：窗口位置是我们**自己刚设进去的**（拖动中每帧都改，吸附命中时还会整块跳几像素），而局部坐标来自**系统在消息生成时刻**算出的"光标 − 当时的窗口矩形"。两者一旦差一帧：

> 指针读数误差 = 窗口位移量 → 原始位置抖 → 模块位置抖 → 窗口再动 …（**正回授**）

**与现象逐条吻合**：只有左右抖、上下不抖（拖动通常是水平的）；与网络标签无关；吸附命中时更明显（吸附会让窗口整块跳）。

> **现行对应约束**：拖动 / 缩放**优先取系统光标**（`GetCursorPos`，与本窗口自身位置无关），非 Windows / 非鼠标 / 调用失败时回退。

#### A.1.5 第三轮："阶梯函数"实测（`15` §7.5）

拖动中硬吸附使"模块位置"成了指针位置的**阶梯函数**——带内不跟手（指针走 **24px**、模块不动）、出带猛跳（**+17px**）。"靠得近才抖"是因为靠近时同一轴上**多个候选挤在几像素内**，阶梯变密 ⇒ 指针一动就换一级。

**同批实测排除两项**：模型几何 vs 窗口实际几何差全为 0；指针换算差值 `err=0`。

### A.2 一次性测量 / 诊断手段的设计（如需重新定位手感问题，可复用）

#### A.2.1 外壳参照基准的测量口径（`15` §3.4，D-4 裁决后改为"直接落地"，故未走此步骤）

- 现状参照 = 外壳**客户区**右边缘；用户看到的是**可见外框**右边缘。两者相差"不可见缩放边 + 可见边框"。
- 方案：用**已有的 P/Invoke 通道**（`AppWindowGroup` 已用 `SetWindowPos`）加 `GetWindowRect` + `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`，得到**可见外框矩形**作为唯一参照；取不到时回退客户区（并记录一次 Issue/日志，不静默）。
- **先测量再定论**：实施第一步先加一个**临时诊断**（状态栏显示：客户区矩形 / 可见外框矩形 / 当前吸附参照线），复现一次并截图/口述——**如果两者相差 0，则本项不做**。
- **已落地的量测场景**（`15` §8.4）：`DragSelfTest.MeasureShellEdge` —— 把外壳放到确定位置 → 把模块吸到其右边缘 → 记录"参照右边缘（可见外框）/ 客户区右边缘 / 两者之差（= 修复前的缝）/ 模块左边缘与参照之差（应为 0）"，落盘到 `%TEMP%\hyw-drag-diag.log`。

#### A.2.2 临时拖动诊断日志的字段表（`15` §7.3 · 定位完成后该文件整体删除）

`Ui/Diagnostics/DragDiagnostics.cs`：**每次拖动都把每一帧完整追加**到 `%TEMP%\hyw-drag-diag.log`（不再只记异常帧），拖动结束时状态栏给出路径。每帧记录：

| 字段 | 用途 |
|---|---|
| `cursor` / `derived` / `err` | 系统光标 vs "窗口位置 + 局部坐标换算"及其差值 → **验证回授** |
| `ptrΔ` | 指针位移 → 区分"输入在抖"与"吸附在跳" |
| `raw` / `→` / `Δ` | 吸附前的原始目标 / 吸附后的位置 / 实际施加的位移 → **复算决策函数** |
| `model` / `win` | 模型几何 vs 窗口实际位置与客户区（×缩放）→ **验证"尺寸不匹配"** |
| `sticky` | 当前粘滞候选（轴 + 类别 + 参照坐标）→ 看它是否来回换 |
| `group` / `neighbours` | 本次拖动组与参与吸附的模块数 → 区分"整组拖动"与"单模块拖动" |
| `!!邻居被回写` | 拖动期间**其他模块**被 `SyncModules` 回写位置（帧间移动的邻居会把贴着它的模块带抖） |

#### A.2.3 吸附稳定性的矩阵扫描设计（`15` §7.1）

把判据写成"**跳走又跳回**"（A→B→A 且跳变 > 1px；自由的 1px 跟手不算），按矩阵扫：

- 尺寸取 125% 缩放下的常见值（400 / 413 / 450 宽，275 高）、**宽度差 −8…+8px**、逐 1px 推进 + ±1px 抖动、x ∈ [930,1010]（**共 1446 组 X 轴配置**），外加"外壳参照线 + 贴壳邻居 + 反向对齐"组合 ⇒ 已转正为回归网 **`SnapStabilityTests`**（3 项）；
- **端口候选通道**（`PortAlignReach = 24px` 是唯一"随距离才出现"的候选）在"两窗口靠得很近"的 2D 区域（x 逐 1px × y 逐 3px）、端口偏移 0.5/0.33/0.67、宽 400/413/450 的组合下逐点做 ±1px 抖动检测 ⇒ **`SnapPortProximityScanTests`**。

#### A.2.4 回归网用例表（`15` §3.5，纯几何 + 视图模型）

| 用例 | 断言 |
|---|---|
| 吸附单调性 | 指针 1px 步进扫过容差边界：模块位移 ≤ 1px、方向不反转 |
| 粘滞与释放 | 进入 8px 内吸附；离开 16px 前保持；离开后释放 〔**该行随"粘滞"被 ADR-0042 取代**：现行 = 无额外释放带〕 |
| 无重叠不贴合 | 交叉轴无重叠 ⇒ `SnappedX/Y == false`，且不产生参考线 |
| 整数化 | 任意输入（含 125% 缩放下的小数尺寸/参照）⇒ 吸附结果与模型几何均为整数物理像素 |
| 组内稳定 | 组拖动过程中组内相对偏移恒定；`EndDrag` 后组内边严丝合缝 |
| 外壳跟随 | `dx = 1 / 8 / 40px` 三种位移，贴壳模块**都必须跟着走** |

#### A.2.5 已知未被自动化覆盖的点（`15` §6.3）

- `ModuleWindowManager.OnWindowMoved` 与真实窗口取整的联动属窗口层行为，无头环境**不构造** `ModuleWindowManager`（需要真实 shell 屏幕信息）→ 该路径由"整组标记驱动 + 单一量化点"从源头消除，**登记为该批唯一未被自动化覆盖的点**。
- 视图层接线（谁在什么时机把控制器给谁）属 **T8 UI 自动化 v1 不做**（ADR-0032）的范围，需人工复验。若"接线静默失效"再出现，应考虑引入最小无头 UI 测试夹具（`Avalonia.Headless`）。
- 无头环境的渲染缩放恒为 1 ⇒ **无法在测试里复现缩放 ≠100% 的场景**，该类结论由用户手动复验。
