# 06 · 外壳与窗口

> 状态：**现行**（来源见各节标记）
> 适用范围：外壳（主窗口）形态与侧边栏结构 · 拼图式多窗口与模块窗口交互 · 窗口层级与置顶 · 人机操作三通道（命令/输入/配置）· 快捷键 · 设置页分区 · 本域明确不做的事。
> 与主文档的关系：主文档 `上位机架构设计.md` 是验收唯一事实源；本文件是其实现层分册，冲突时以主文档为准。

## 1. 拼图式多窗口：现行口径 〔源: architecture/11 §1 R-1/R-2/§3 + ADR-0034 最终选择 1–4 + 05 §5.14〕

| 项 | 现行结论 |
|---|---|
| 形态 | **拼图式**：每个模块实例 = **一个无边框顶层窗口**；**没有任何"工作区"背景**（背景就是用户桌面）；不采用画布/工作区容器 |
| `Module ≠ Window` | **已正式修订**为："模块**不强制**等于窗口；**默认形态 = 每模块一个可拼接的无边框窗口**（框架渲染；模块仍不提供 View 类型）" |
| 外壳 | 主窗口 = 拼图**起始点**，本身也是可被贴靠的一块；外壳**保留系统边框**（它是外壳，不是元件），自身可移动/缩放 |
| 归属 | `FrameworkUi` 持有 `Window`（主窗口 + 全部弹窗）；`Ui` 只提供**模块区控件**；依赖方向仍 `FrameworkUi → Ui`；旧 `IFrameworkPanels` 宿主契约**撤销**（方向反转） |
| 接缝 | `Ui` 暴露 `ModuleWindowsViewModel`（几何/交互/标签提交）+ `ModuleWindowManager`（模块↔窗口映射、外壳矩形回写、实际尺寸回写）；`FrameworkUi.ShellViewModel` 持有并调用 |
| 实例开窗 | **每个实例一律开窗**：撤销"无界面模块"概念；未声明视图（或视图无 B1 元素）→ 由**框架补配置表单**（无配置则说明原因），窗口本身仍**不显示模块名**（身份行已删，见 §5） |

**模块窗口的窗口属性**：无系统装饰（`SystemDecorations=None` / `WindowDecorations=None`）、`ShowInTaskbar=false`（后果见 §6）。〔源: architecture/11 §2.1 + ADR-0036 D5/O-6〕

## 2. 外壳（主窗口）：侧边栏形态 〔源: architecture/14 §1.1/§10 B4 + ADR-0038 D1/D2/D3 + 05 §5.19 + MainWindow.axaml〕

```text
主窗口（VSCode 式侧边栏；顶部菜单已撤销）
├─ A 区 活动栏（左，44 px，竖向图标入口）
├─ B 区 侧边界面（右）：模块清单页 / 交互页（常驻竖向页面）
└─ 状态栏（最底，固定高 28）
弹窗（DialogWindow，非模态）：设置 · 拓扑诊断 · Issue · 帮助与关于
```

| 部件 | 现行值 |
|---|---|
| A 区活动栏 | 宽 **44 px**；6 个入口，自上而下：**模块清单 · 交互** ｜（分隔线）**拓扑诊断 · Issue（有错误时显示计数徽标）· 设置 · 帮助**；按钮 40×36、间距 2；选中态 = **最左 3 px 主色滑块（独占一列，与图标分列不重合）+ 浅底**；图标用**系统图标字体**（`FontIcons` = Segoe Fluent Icons / Segoe MDL2 Assets + `Glyph*` 码位表） |
| B 区侧边界面 | **模块清单**与**交互**为**常驻竖向页面**（不是弹窗）；其余入口一律开 `DialogWindow` 弹窗 |
| 顶部菜单 | **撤销**（文件/视图/窗口/帮助）：动作全部改由 A 区入口 + B 区页面 + 弹窗承担 |
| 状态栏 | 固定高 **28**；左 = 状态文本（11 px、次要色、超长省略；内容 = `模块 N · 叠加层开/关 · 吸附开/关 · 刷新 N Hz [· 已锁定] · Issue N[（错误 M）]`），**右 = 临时提示**（独占一列、`TextBlock.notice`（错误态 `.error`），最长 240、超长自己省略，**8 秒自动过期**）；内边距左 10 / 右 10。〔**2026-09 用户实测修复**〕① **删掉尾部那个「Issue N」按钮** —— 活动栏已有 Issue 图标 + 错误计数 ⇒ 那是**重复入口**、标签又与摘要里的 `· Issue N` 重复（用户："建议直接删掉最尾部的 ISSUE 入口点"）；② **提示不再拼进摘要**：主窗口只有 396 宽，摘要占满后提示被截成"拖动…"（用户："似乎是未完成显示的信息"）⇒ 摘要先省略、提示优先完整；③ 提示原先**永不过期**（只有下一条提示才替换它）⇒ 现在到点由外壳刷新节拍清 |
| 窗口尺寸 | 默认 **396×858**（= 9:19.5），默认值**写在 `MainWindow.axaml`**；**现行最小尺寸 = 360×360**（`MainWindow.axaml` 的 `MinWidth=360` / `MinHeight=360`）；设置 `shellAspect`（9:19.5 / 9:16 / 16:9 / 自定义）与 `shellFixedSize`（默认 **true** = 不可缩放）**只在用户显式改过时**覆盖；换算集中一处（`ShellLayout`），换比例只改一处 〔源: 代码 `src/FrameworkUi/Views/MainWindow.axaml`（`Width=396 Height=858 MinWidth=360 MinHeight=360`）+ `MainWindow.axaml.cs` `ApplyShellSizeFromSettings`〕 |
| 弹窗宿主 | 外层尺寸**固定 780×620**、可手动缩放（Min 560×320 / Max 1080×880）、**不按内容撑高**；每个弹窗根都有 `ScrollViewer` ⇒ **外层固定 + 子区滚动**（取代 ADR-0038 D3 的"按内容自适应"）。**四个种类（模块清单 / Issue / 设置 / 拓扑诊断）尺寸一致**〔**2026-09 用户实测修复**：原先按种类覆盖尺寸，与 XAML 里"尺寸固定"的声明**直接矛盾** ⇒ 覆盖已删除，**尺寸只有 XAML 一处来源**，`ShellChromeTests.弹窗_四个种类的默认尺寸必须一致` 把它钉住〕 |
| 主题跟随 | 外壳、模块窗口、弹窗、叠加层走**同一套角色 token**（`Ui/Styles/Tokens.axaml`）；设置里改主题/主题色/背景**即时生效**（机制 = 改写主题字典 + 快照还原；放进合并字典会被内置 token 盖住） |
| 调色板窗口 | `ColorPickerDialog` **可复用**：主题色 · 自定义背景色 · 发送色 · 接收色 4 个设置色块 + 「数据结构 · 颜色」表内色块，**5 个取色点全走它**；设置页内联取色 `Flyout` 已删除 ⇒ 全应用一种选色交互 |

## 3. B 区「模块清单」页：六段显式布局 〔源: architecture/14 §10/§12-6/§12-7 + implementation/04 #4/#4b〕

自上而下固定六段（**区域尺寸固定**：切换分类/搜索不移动任何其它控件）：

| # | 段落 | 现行值 |
|---|---|---|
| ① | 搜索框 | 按**名称与描述**过滤 |
| ② | 横向分类标签 | 固定宽 **64**（图标 + 数量，悬停显示名称）；分类 = **全部 / 数据源 / 显示与接收 / 记录与断言 / 其他**（未声明标签 → 其他）；筛选经增量同步，不闪 |
| ③ | 可用模块列表 | 放在 `Border.pane` 的 **`*` 行**（固定区域 + **内部滚动**）；一行 = **缩略图占位 72×40** + 名称 + 版本/来源/「需重启」提示；底行左「加入现场」、右下角帮助问号。**双击一行 = 直接加入现场**（只双击到项上才生效，空白处不动作） |
| ④ | 目录操作行 | 添加目录… / 删除选中 / 重新加载 |
| ⑤ | 模块来源目录 | 固定高 **120**、一行一个、**路径中间省略**（全路径在悬停提示）、行尾小按钮"在资源管理器中打开"（内置包目录始终生效、不在此列表） |
| ⑥ | 加载模块包 | 输入框 + 选择… + 加载（显式加载第三方构建产物目录） |

**页面级约定**〔源: architecture/14 §10-3/§12-2/§12-3/§12-4〕：说明性文字**一律不占版面**—走悬停提示或**问号按钮 + `Flyout` 弹窗**（弹窗式、右对齐、右边距统一 4 px、内容只有文字）；各分区**一律带边框**（`Border.pane`）并有分区标题；布局紧凑（内边距 10、行距 6）。

「占位实例」（未能锚定/无实现的实例）**不在本页**：归**拓扑诊断弹窗**（属诊断；经 `TopologyViewModel.Catalog` 复用同一份数据，不复制状态）。〔源: architecture/14 §11-4〕

**拓扑诊断的刷新**〔**2026-09 缺陷修复**〕：弹窗是**非模态**的，内容必须由**外壳刷新节拍**驱动 —— `ShellViewModel.Refresh()` 里依次刷 `Windows` / `Catalog` / `Issues` / **`Topology`**。**`Topology` 那一行原先漏了** ⇒ 拓扑视图模型从来没被刷新过（只有设计时样例与测试里手工调用）⇒ 打开弹窗后**表恒为空、摘要恒"网络 0"**，且**与是否建网无关**（用户："网络拓扑诊断器没有任何作用，无论是否建网，都没有东西"）。回归网 = `ShellStatusAndSettingsTests.拓扑诊断_外壳刷新后必须真的有内容`（真建网 → 刷一次外壳 → 表必须有行）。

## 4. B 区「交互」页 与 设置弹窗分区 〔源: InteractionView.axaml/SettingsView.axaml + ADR-0036 D6 + ADR-0041 D4 + architecture/12 §3.2 + architecture/15 §8.5 + ADR-0054〕

### 4.1 交互页（常驻页面）〔源: InteractionView.axaml + architecture/14 §10 B4 + 05 §5.28 + ADR-0054〕

分区自上而下（每区：左标题 + 右侧问号帮助，帮助一律 `Flyout` 弹窗）：

| 分区 | 内容 |
|---|---|
| 显示 | 「叠加信息层」开关（端口标记**常显**，不由开关控制） |
| 交互 | 「几何吸附」开关（拖动中按住 `Alt` 临时停用） |
| 窗口 | 「全部锁定」·「应用置顶」两个开关 + 「全部置前」「显示全部」两个按钮 |
| 快捷键 | 当前默认键位的**速查**（键位清单以设置页为准，见 §8） |
| 数据结构 · 颜色 | 图例表：一行 = 一种**数据类型身份**（`标识@v版本`），列为 色块 / 身份 / 形状文本 / 用在（`N 个口 · M 个角色`）；空态 = 一句话事实（`现场还没有数据类型`）；点色块开**调色板窗口**；改色**唯一入口** = `ShellViewModel.ApplyDataTypeColor`；**只呈现**（不进组合件、不参与建网/兼容/判定）；颜色语义见《叠加层与视觉基线》 |

**开关同名同源（硬要求）**：设置页与交互页的 `ShowInfoOverlay` / `AppTopmost` **委托外壳的实时属性**（单一状态源），任一入口切换即 `PersistLiveSwitches()` 落盘 ⇒ 两处永远一致；此后凡"同一设置出现在多个界面"的开关，**一律只保留一处状态**，其余做委托，禁止各存字段再"同步"。〔源: ADR-0041 D4 + 05 §5.21〕

### 4.2 设置弹窗：七类 〔源: ADR-0036 D6 + architecture/12 §3.2 + SettingsView.axaml + implementation/04 #46–#51 + architecture/15 §8.5〕

左分类 + 右页面，**即时生效**；左分类 **12 px / 条目高 28 / 宽 132**，字段行高 **27**，标签列统一 140。七个分类与顺序：

| 分类 | 页面内容（UI 层） |
|---|---|
| 常规 | 框架行为项（停止超时 / 队列容量 / 对齐自动建网）+ 启动行为、便携目录说明 |
| 模块与来源 | 来源根列表（增/删/排序/「立即重扫」/「打开目录」）+ 每根扫描结果与逐包失败原因 + "本次启动后重建过 → 需重启"提示 + 加载模块包（供给与发现规则见《模块 SDK》） |
| 窗口与交互 | 窗口层级说明（应用内：弹窗 > 模块窗口 > 外壳）+ 拖动与吸附（修饰键为**固定行为**）+ 叠加信息层 / 吸附 / 全部锁定 / 应用置顶 / 全部置前 |
| 外观与显示 | 刷新率 · **吸附距离（px）** · 主题 · 主题色 · 背景 · 发送色 · 接收色 · 主窗口比例与尺寸固定 |
| 快捷键 | 动作清单 + 当前绑定 + 捕获修改 + **冲突即时提示** + 单项/全部重置（空 = 不绑定） |
| 日志与诊断 | 日志级别 · 诊断提示阈值 · Issue 上限 · Issue 保留策略 |
| 关于 | 版本 · 构建配置 · 依赖许可摘要 · 帮助（快捷键 / 用法速查） |

> 设置**键名、取值范围与生效规则**不在本文件维护 —— 以《应用设置》分册为**唯一来源**；几何吸附的容差语义（大小、贴合 = 2 倍等）见《叠加层与视觉基线》。

## 5. 模块窗口：形态与交互 〔源: ADR-0039 D1/D2 + ADR-0041 D1/D2/D3/D6 + 05 §5.18/§5.21 + architecture/14 §13.2/§15 + ADR-0053〕

| 项 | 现行值 |
|---|---|
| 窗口结构 | **无标题栏、无身份行**（模块名不在窗口上显示）⇒ **整块窗口矩形 = 模块矩形**（与 `DockRule.MarkerCenter` 的几何基准一致）；边框 1 px 贯穿整个窗口周界，**选中态主色边框加粗到 2 px** |
| 运行指示 | **左下角**：状态点 7 px + 状态文本 10 px（弱化色） |
| 按钮簇 | **右上角、纯图标**（20×20 图标按钮，悬停或选中时淡入），四个：**[还原] [锁定/解锁] [隐藏] [关闭]** |
| 选中 / 取消选中 | 点**边框带**选中；点内容区、点外壳或本应用其他窗口 → **取消选中**；锁定态不可选中 |
| 边框交互带 | **6 px**：边中点/角点 = 缩放，其余 = 拖动；**内容区点击不选中**（不与模块内控件抢事件） |
| 缩放手柄 | **6×6**；**仅选中或悬停时可命中**（未选中时 `IsHitTestVisible=false`）⇒ 不再压住端口标记 |
| 默认/最小尺寸 | **尺寸字面量的唯一来源 = 包声明 schema**（`view.schema.json` 的 `window.width`/`height` 缺省 **320×220**、`window.minWidth`/`minHeight` 缺省 **180×160**）：模块在**包内 `view.json`** 的 `frame.window`（`width`/`height`/`minWidth`/`minHeight`/`maxWidth`/`maxHeight`）里声明自己的默认尺寸与约束，**省略即取上述缺省**。**最小尺寸 = 框架地板**（**2026-09：最小高由 120 抬到 160** —— 端口标记沿边长度加到 150 后，窗口比它短会把标记裁掉一截；几何依据 = `PortMarkerMetrics.MinWindowExtent`）：声明的下限**只能抬高地板**，写小了由读取器**夹到地板并记 warning**，渲染侧不再夹、也不自带字面量（`decisions.md` 7.63）。`ModuleWindow.axaml` 里**没有** `MinWidth`/`MinHeight`（原先那对字面量已删；且因 `CanResize="False"` 它们对用户本就毫无约束作用 —— 真实约束走模型的 `EffectiveMin*` → `ModuleWindowManager.Fit`）。**四个正式模块的现行声明值见 `07`「模块窗口视觉规范」的默认尺寸行**（不在本表复述数值，避免第二份事实源） |
| 尺寸归属 | **尺寸归 XAML**：`ApplyContentDrivenSize` 与"元素→高度表"已删除——**信息量不得改变外层容器尺寸**，排不下由内容区滚动条处理；未摆放模块只分配**位置**，窗口按 XAML 尺寸打开后由 `PublishActualSize` 把实际尺寸读回落盘 |
| 默认摆放 | 起点 = **外壳右边缘 + 12 px**，与已有模块逐个相交检查，**一列到底自动换右列**（上限 256 次兜底）⇒ 新窗口不压住主窗口、不互相堆叠 |
| 隐藏 / 关闭 | 隐藏 = 窗口不可见、**模块继续运行**并写回布局（恢复入口 = 交互页「显示全部」）；关闭 = **移除该实例**（要回来从模块清单重新加入） |
| 窗口内层序（下→上） | 内容 → 端口标记 → 遮罩 → 连线/角色层 → **运行指示与按钮簇**（遮罩与图形层不参与命中；端口标记被灰玻璃压暗 = "做减法"）〔源: ADR-0053 + 05 §5.27 二次修正〕 |
| 口标记的交互（**G5 · C5-7**） | ① **双击 = 填写/清除网络名**（唯一建网机制）② **拖动 = 移动锚点**（沿边改偏移 / 拖到任意边）：按下后**越过 4 px 阈值**才启动，**阈值内仍是双击**（否则双击改网名会被拖动吃掉）；拖动期间**冻结刷新节拍**，松手经 `UpdatePortGeometry` 一次写全、失败就地回滚 ③ **标记带内、标记长度之外**（悬停该标记时淡入）的**图标按钮 = 固定/解锁该口**（`GlyphUnlock`/`GlyphLock`，见 `07` 端口标记表） |
| 锚点层的构成 | **两层**：`PortMarkers`（标记块）+ `PortAnchors`（「固定」按钮），两层都用 `PortMarkerPanel`（`Layer` 属性切排布分支 ⇒ **落位规则只有一份实现**）；两层都排在 `OverlayScrim` **之前** ⇒ 叠加层开启时与标记一起"沉下去"；遮罩不参与命中 ⇒ 按钮始终可点 |
| 锚点的悬停反馈 | **只改鼠标指针**：可拖动 = `SizeAll`、已固定 = 默认箭头（**不做悬停放大** —— 用户 2026-09 裁定） |
| 拖动手势的命中优先级 | 口标记层**压在** 6 px 拖动带与缩放手柄之上（否则双击标记会被边缘中点手柄吃掉）；锚点拖动与窗口拖动/缩放**互斥**（后两者只由边框带/手柄按下置位） |

### 5.1 按钮簇语义

**「还原」（取代早期的"运行/停用"）**〔源: ADR-0041 D1/D2 + 05 §5.21〕：模块没有"暂停"这件事——模块生命周期由框架权威判定（`Registered → Active ⇄ Disabled → Removed`），窗口不提供停/启。点「还原」弹**范围确认对话框**，三选一：

1. **只还原默认尺寸**（几何回模块声明的默认尺寸，位置保持）；
2. **尺寸和配置都还原**（几何回默认 + 配置回默认值）；
3. **取消**（什么都不做）。

**配置还原的实现语义（硬要求）**：`IModuleContext.ResetConfiguration()` = **用同类型的新默认实例替换**每个已登记配置，**不得**用 `Clear()`（清空会让按登记对象生成的 Schema 表单失去来源，表现为空表单 + `Sequence contains no matching element`）。走 `ResetModuleConfigurationOperation` → `IRuntimeServices.ResetModuleConfiguration`，Prepare 校验 + Commit 应用 + `NotifyConfigurationChanged` + Notice（**不静默**）；**不扩 SDK 面**（还原是框架对自己持有的配置与几何的处置）。

**「锁定」两层含义**〔源: ADR-0041 D3 + architecture/11 §10.2 E〕：

- ① 不可拖动 / 不可缩放 / 不可选中（**仍刷新数据**）；
- ② **不参与拖动组、不随壳体移动**：组织拖动组时**排除锁定成员**（拖相邻模块不带走它、拖它也不带走他人），`FollowShellMove` 取"贴壳平铺组"整体平移时同样排除锁定；
- 锁定是**会话内交互状态，不持久化**（不进组合件）；锁定**不改变**布局坐标的存储格式（仍是绝对屏幕像素，"跟随"只是贴壳时的行为）。

### 5.2 拖动、成组与拆分 〔源: architecture/15 §8.3 + implementation/04 #65/#66/#66b + 05 §5.14〕

- **整组拖动**：拖动前按贴合关系求连通分量并冻结 → 整组同步位移 → 结束后重算；拖动中**不逐帧落盘**，停下后合并为一次变更。
- **拖动贴壳模块**：拖动组包含外壳时 → 外壳窗口**一起走**（"视觉整体"）；`Ctrl` 独立拖动时只动该模块、外壳不动。
- **拖动中按 Ctrl = 当场拆分**（等价"拖动前按住 Ctrl"）：其余成员与外壳**立刻回到本次拖动的起点**，只有被拖模块继续跟指针；松开 `Ctrl` **不会**重新合组（单向、幂等）。
- **移动外壳**：只平移与外壳相连的那一组（没拼上的模块留在原处），锁定成员不跟随。
- 拖动只能靠 **6 px 边框带**（内容区不响应）——这是"窗口看起来拖不动"的常见原因。

> 吸附参照（候选、容差、参照线、坐标量化）不在本文件：见《叠加层与视觉基线》。

## 6. 窗口层级与置顶（两态）〔源: ADR-0036 D5/O-6 + 05 §5.16 + architecture/12 §2〕

| 关系 | 规则 |
|---|---|
| **应用内**（自上而下） | **弹窗 > 模块窗口 > 外壳**：模块窗口 `Owner = 外壳`（外壳永在其下；最小化/恢复随外壳）；弹窗 `Owner = 外壳`，打开即激活 |
| **应用整体**（相对其他应用） | **只有两种统一状态**：**普通**（默认）——任一本应用窗口被激活 → 其余本应用窗口**一并抬升**（不抢焦点、保持内部次序）；其他应用激活 → 整体下沉。**全体置顶**——应用级开关（「应用置顶」），外壳 + 模块窗口 + 弹窗**一起**最前；新开窗口与弹窗按当前状态继承 |
| **禁止** | "一部分被外部应用覆盖、一部分置顶"的**混合状态**（原"每窗口各自置顶"的设计已撤销，**不提供单窗口置顶**） |
| 任务栏 / Alt+Tab | 只出现**外壳**一项（模块窗口 `ShowInTaskbar=false`，**固定行为、不加设置项**） |
| 平台代价 | "组抬升"需少量 Win32 互操作（`SetWindowPos`，经 `TryGetPlatformHandle()` 取 HWND）——只落在 `Ui`/`FrameworkUi`（表现层平台适配），不进 L1–L4；非 Windows 降级为不做组抬升 |
| 操作入口 | 「全部置前」「显示全部」「全部锁定」「应用置顶」在**交互页「窗口」分区**（并同源出现在设置页「窗口与交互」） |

## 7. 人机操作三通道：命令 / 输入 / 配置 〔源: ADR-0040 D1–D5 + 05 §5.20 + architecture/11 §4.2/§10.2 H〕

| 通道 | 声明面 | 写入面（公开面） | 提交时机 | 失败处理 |
|---|---|---|---|---|
| **命令**（B2 命令按钮） | 按钮节点自带 **`command` 角色键**（`title` 缺省时取命令名；**没有独立的命令表**） | `IRuntimeCommand.SendCommand(instanceId, commandName)` → `SendCommandOperation`（Prepare 校验"该命令是否已声明"） | 点击按钮 | **未声明即拒绝、不静默**；执行失败/未知命令转 **Issue（`ModuleError`）**，不逸出 |
| **输入**（B5 文本输入） | `ViewElementKind.TextInput` + 视图数据源（**多行** = schema 键 `multiline`，缺省 `false`） | `IRuntimeCommand.SubmitInput(instanceId, source, text)` → `SubmitInputOperation`（同样 Prepare 校验） | **单行**：回车 / 失焦一次提交（**不逐字符写入**）；**多行**：提交键由**应用级设置** `multilineSubmitKey` 决定（`CtrlEnter` 默认 = 回车换行 / Ctrl+Enter 提交 / **失焦不提交**；`Enter` = 回车提交 / Shift+Enter 换行；`None` = 只用按钮）——见 `08` §2〔**G2 · 2026-09**〕。UI 给"未提交 / 已写入"可辨识状态 | 类型/范围不合法 → **就地报错 + 保留输入**，不静默丢值 |

**多行输入框「不自动折行」= 特性**（用户 2026-09 裁决）：输入框里**画面上的换行 ⟺ 文本里真的有一个换行符**（长行横向滚动）⇒ **所见即所发**，发送内容完整，用户不必猜"这是自动折行还是换行符"。
**框架对提交的文本不做任何规范化**（不折 CRLF/LF、不去尾、不追加）；行尾用 `CR`/`LF`/`CRLF` **属模块语义**（模块自己的配置项）。
**与只读显示的分工**：只读的 A5 文本日志**可以为便于阅读而折行**；输入框不行 —— 两者语义不同，不得互相类推。完整约定见 `02`「多行输入框不自动折行是特性」。
| **开关**（B3 开关/滑块，枚举序号 10） | `ViewElementKind.ToggleSlider` + 视图数据源 | 同上通道 | 拨动即提交一次 `true/false`；拖动只在**松手**时写入（v1 不做"连续拖动即连续写入"） | 同输入 |
| **配置**（B1 配置表单） | 配置的 Schema（`Core.Api` 只读 Schema + 按字段写回） | 框架按 Schema **自动生成表单**（数值/文本/布尔/枚举/文件路径）；写回仍走 L4 变更入口（保持原子性） | 字段提交（两阶段 ChangeSet） | 失败就地报错 + Issue |

**投递与线程纪律**〔源: 05 §5.20 + `ModuleContext.BoundedInbox`〕：

- 命令/输入**一律入队** `IModuleContext.Inbox`（`IModuleInbox.TryDequeueCommand` / `TryDequeueInput`），由模块**在自己的活动体内（模块线程）**消费 —— **框架不跨线程直接调模块**、不阻塞 UI。
- 队列**有界 64**：满则**丢最旧并计数**（`DroppedCount`）；投递方 = 管理线程，消费方 = 模块线程，以锁保护。
- 投递结果一律进 `CommandResult`（Notice / Failures）→ 界面就地显示 + 状态栏提示。
- **B6 文件选择器（G4 · 2026-09；**2026-09 改单按钮**）走同一条输入通道**：用户选/存后，**路径字符串**经 `SubmitInput` 投递；
  弹系统对话框在**视图层**（`ModuleContentView.axaml.cs` 的 `OnBrowseClick`，用 `TopLevel.StorageProvider`），
  **模块不接触文件对话框 API**。渲染 = **一个按钮**（文案 = 声明标题）+ 其下一行**就地结果**；保存模式把声明里的
  `SuggestedFileName` 交给对话框预填，路径改挂按钮的悬停提示（用户："更好的方案为**只提供一个保存按钮**，
  点击后弹出窗口选择位置 → **选择完成自动保存在此处**"）。
  **结果行归模块回报**（写盘成没成功只有模块知道，视图层自己写"已保存"就是预览骗人）：成功也显示（"已保存 …（N 行）"）、
  失败 = 按钮红框 + 红字原因。
  **只有人工能验的部分**：无头环境没有真实对话框 ⇒ "点按钮真的弹窗"归人工验收。
- **已登记限制**：**无活动循环的模块不消费收件箱**（投递入队但框架不代执行 —— 模块线程纪律不允许）；v1 的四个正式模块均为活动模块，后续如需支持应在数据面投递循环增加收件箱消费点（**不是静默降级**）。

**渲染子集（现行）**〔源: ADR-0040 D4 + 05 §5.20；**元素编号以 SDK 声明面为准** = A/B/C 三类前缀 + 枚举序号〕：**A1 数值 · A3 曲线 · A5 文本日志 · B1 配置表单 · B2 命令按钮 · B5 文本输入 · B3 开关/滑块（序号 10）· B6 文件选择器（序号 13，2026-09 G4 补齐）· C2 标签页（序号 15，2026-09 G1 补齐）**；其余元素按"**未渲染**"占位（不假装支持）。**代码核对补充**〔源: 代码 `src/Ui/ViewModels/ModuleViewViewModel.cs` 元素工厂〕：`EnumSelector`（**B4**，序号 11）当前**未接渲染分支**，落入"未渲染"占位 ⇒ v1 实际渲染子集**不含 B4**（旧文中的"A10/A11"是 ADR-0040 的连续编号记法）。控件统一高 `ControlHeight = 27`（字号 12、圆角 3、行距 4），尺寸**只从 token 取**，禁止逐处写死。

**C2 标签页的交互（G1 · 2026-09）**〔源: 用户裁决"框架全做完再出模块页"· `roadmap.md` §3 第 12 项〕：

| 项 | 现行 |
|---|---|
| 声明结构 | `TabPages.children` = **页节点序列**；**页节点的 `children` 才是该页内容**（页节点自身无子元素时把**它自己**当内容）；页签标题 = 页节点 `Title`（空 ⇒ 页序号） |
| 渲染 | **标签条**（横向、页签按钮）+ **只渲染当前页**；未声明的页不出现；**零页 ⇒ 什么都不画**（不假装支持） |
| 切换 | 点页签即切（框架内部命令）；**切页是纯 UI 状态** —— 不进组合件、不下发模块、**模块不感知当前在第几页** |
| 与容器的关系 | 与 `Group`/`Collapsible`/`Scroll` 同一约定：**容器自身不画、由框架渲染**；标签页展开为「标签条 + 当前页子元素」⇒ 不需要嵌套模板 |
| **已知代价** | 切页**重建元素表** ⇒ 其他元素的**焦点/滚动位置重置**（v1 接受；要保留需改成"独立宿主 + 只换内容"，那时要把元素模板抽成共享资源字典） |
| 视觉取值 | 见 `07`「模块窗口视觉规范」 |

**配置通道的边界**〔源: 11 §4.2 + §10.2 H〕：配置 = **随组合件保存的参数**（编辑在**模块视图内**；无视图或视图无 B1 元素者由框架补表单 ⇒ "配置编辑在模块视图内"对**所有**模块成立）；**命令/输入 = 瞬时操作**，不写配置、不进组合件。实现细节：`Read<T>` 首次读取会登记默认配置；配置 JSON 允许 `±Infinity/NaN`；枚举按**名字**表示。界面**不展示** `ModuleId` 字面量、配置类型全名、口字面量（唯一例外 = 只读的拓扑诊断调试视图）。

**参考发送器（现值）**〔源: ADR-0040 D5 + 05 §5.20 + implementation/04 #39–#45〕：视图自上而下 = ① 必要信息（待发送值 / 已发送 / 被丢弃，紧凑）② **值输入框 + 发送按钮** ③ **自动发送开关 + 周期(ms) 输入框** ④ 其余配置（可折叠）；命令 `send` 在模块线程消费；**删除**"改配置即发送"权宜通道与 `ManualSendMode`、`发送值/模式/周期/写入显示缓冲` 配置项；**激活不再自动发送**；对外契约 `{seq:u64, value:f32}` **不变**。

## 8. 快捷键 〔源: ADR-0036 D7 + architecture/12 §3.3 + architecture/10 §5 + implementation/04 #66b〕

| 项 | 现行值 |
|---|---|
| **作用域** | **应用内**：本应用**任一无边框模块窗口或外壳窗口聚焦**时都生效（`HotkeyService` 挂在所有本应用窗口上）；**不做**系统级全局热键（需 Win32 `RegisterHotKey`，v1 不做） |
| **模型** | `hotkeys: { "<动作>": "<键+修饰键>" }`；动作 = **固定枚举**：打开模块清单 / Issue / 设置 / 拓扑诊断 · 切换叠加信息层 · 切换吸附 · 全部锁定 · 应用整体置顶 · 全部置前 · 显示全部窗口 · 取消拖动 |
| **编辑** | 设置页「快捷键」逐行：动作 + 当前绑定 + **捕获新键（含修饰键）** + **冲突即时提示** + 单项/全部重置；**空值 = 不绑定** |
| **持久化** | 进 `settings.json`（**已知字段增加 = 兼容扩展**：旧文件缺该项即用默认，无需迁移） |
| **清单归属** | **以设置页为准**；本文件与其它文档**不重复维护键位表**（避免双份漂移）。交互页「快捷键」分区给一份速查提示，最终以设置页为准 |
| **固定修饰键**（不是可编辑热键） | 模块窗口内：`Ctrl` **独立拖动**（拖动过程中按下 = **当场拆分**）、`Alt` **临时停用吸附** |
| **不做** | 模块命令按钮 **v1 不进**应用级快捷键系统（只在窗口内点击） |

## 9. UI 开发方式与调参地图（本域硬规则）〔源: architecture/14 §13.1/§13.2/§10/§7 + 05 §5.19 + 已收敛的仓库根 `UI-ADJUST.md`〕

### 9.1 约定（六条原则 · 两条硬规则 · 三处例外）

| 原则 | 具体含义 |
|---|---|
| **① 尺寸默认值写在 XAML** | 窗口/控件的默认尺寸、最小尺寸、内边距、间距**全部写在 axaml 里**（如 `ModuleWindow.axaml` 的 `Width/Height/MinWidth/MinHeight`、`DialogWindow.axaml` 的 `Width/Height`）。代码里**没有**"按内容估算尺寸"的逻辑。 |
| **② 外层容器尺寸固定** | 外层窗口尺寸**不随信息量变化**。内容排不下 → **子容器的 ScrollViewer 出滚动条**（不是把窗口撑大）。 |
| **③ 按钮排版固定** | 按钮行/工具栏的位置与排列是静态布局，不因内容增删而移动。 |
| **④ 设计时可预览** | 每个视图都有 `d:DataContext`（设计时样例数据）→ **VS 设计器里能看到有内容的界面**并直接调样式。 |
| **⑤ 代码只管"事实"，不管"外观"** | 代码只做三件事：把**用户拖过的**几何从组合件恢复、把**设置里选的**比例/主题应用上、把**领域标准件**（端口标记/连线/参考线）画出来。其余一切外观都在 XAML。 |
| **⑥ 帮助一律弹窗、区域一律有边框**（第十轮） | 帮助 = 小号**带边框**问号按钮（`Button.helpIcon`，16×16）+ `Flyout` 文本弹窗——**不展开、不改变布局**，各分区**右侧/右下角且 X 对齐**；列表/分区用 `Border.pane` / `ListBox` 的 1 px 边框表达边界。 |

**由此得到的两条硬规则（改代码时也要守）**：
1. 想改"某个屏幕上的尺寸" → 改 **XAML 里的字面值**，不要在 C# 里算；
2. 数据多到放不下 → 加 `ScrollViewer`，不要把外层改大。

> 例外（**必须**留在代码里的三处，已在文档登记）：① 用户拖动/缩放过的几何（随组合件保存）；② 外壳比例设置（你要求做成设置项）；③ 端口标记/叠加连线/参考线的自绘（贴在预留带内的领域标准件）。

> 原 §9 硬规则里只此两处的交叉引用，随本节保留：模块窗口的尺寸与约束一律由包内 `view.json` 的 `frame.window` 声明、缺省与地板由 schema 给出（`ModuleWindow.axaml` 只剩 `Width`/`Height`/`d:DesignWidth`/`d:DesignHeight` 供设计器预览，**不再有 `MinWidth`/`MinHeight`**，`../decisions.md` 7.63）；**地板数值也不在代码里** —— 它是 schema 的 `window.min*` 缺省，`PortMarkerMetrics.MinWindowExtent` 只是它的几何依据。
### 9.2 文件 → 界面部位对照（改哪里 = 改哪个文件）

### 9.3 界面文本的三种写法

| 场景 | 写法 | 示例 |
|---|---|---|
| 一句短语（≤ 12 字） | 直接显示 | `<CheckBox Content="几何吸附" .../>` |
| 一句解释（一句话说清） | **悬停提示**，不占版面 | `<CheckBox Content="几何吸附" ToolTip.Tip="拖动时…" />` |
| 长说明（多句 / 教程） | **问号按钮 + 弹窗**（第十轮起：不再就地展开） | `Button.helpIcon` + `Button.Flyout` |

**问号按钮 + 弹窗文本**（纯 XAML，**不需要改视图模型**，且关闭后不留痕）：

```xml
<Grid ColumnDefinitions="*,Auto">
    <TextBlock Grid.Column="0" Classes="paneTitle" VerticalAlignment="Center" Text="分区标题" />
    <Button Grid.Column="1" Classes="helpIcon" ToolTip.Tip="说明">
        <Button.Flyout>
            <Flyout Placement="TopEdgeAlignedRight">
                <TextBlock MaxWidth="320" TextWrapping="Wrap" FontSize="11" Text="这里是说明文本……" />
            </Flyout>
        </Button.Flyout>
    </Button>
</Grid>
```

要点：
- `Classes="helpIcon"`（`Controls.axaml`）：16×16、圆角、**1 px 边框**、内容自动是 `?`、悬停变主色；
- 放在分区的**右侧/右下角**，右边距保持 4 px → 各按钮 **X 坐标一致**；
- 弹窗内容**只放文字**（不放控件、不放会改变布局的东西）。
- `Classes="note"` = 10 px 弱化色 + 自动换行的说明文本样式。

### 9.5 弹窗尺寸与换行

- `DialogWindow.axaml`：**宽度固定 780** + `SizeToContent="Height"`（高度随内容），`MaxHeight=880`（超出时内容区滚动）。
- **为什么不能都自适应**：`SizeToContent="WidthAndHeight"` 会让带 `TextWrapping` 的文本拿到"无限可用宽度"→ **永不换行**（只有手动缩小窗口才换行）。若你希望某个弹窗更宽/更窄，改这里的 `Width` 即可。

### 9.6 想加一个"设置项"或"图标入口"

1. **字段**：`src/Core.Api/ApplicationSettings.cs` 加属性（**只增不改 = 兼容扩展**）；
2. **读写**：`src/Core/Settings/SettingsService.cs` 的 `FromJson` / `MergeInto` 各加一行（新键优先、旧键可回退）；
3. **面板**：`src/FrameworkUi/ViewModels/SettingsPanelViewModel.cs` 加 `[ObservableProperty]` + 在 `Load()`/`Apply()`/回读处各一行；
4. **界面**：`SettingsView.axaml` 对应分类里加控件；
5. **生效**：若要在界面即时生效，参考 `SettingsPanelViewModel.ApplyAppearance()` 的写法。

## 10. 本域明确不做 〔源: ADR-0034/0036/0038/0039/0040/0041/0054 + architecture/11 §10.3 + architecture/14 §8 + architecture/15 §9〕

| **模块自定义任意 Avalonia/WPF 控件** | 模块只声明元素，渲染由框架负责 |
| **输入的双向实时同步 · 逐字符写入 · 连续拖动连续写入** | 输入是"一次提交"，不持续回读 |

## 11. 本域已裁定事项（本轮收口；原「待裁事项」）〔源: 用户裁定 + 代码核对〕

- **人机操作通道 = 收件箱拉取式（已裁定）**：模块从 `IModuleContext.Inbox`（`IModuleInbox.TryDequeueCommand` / `TryDequeueInput`）自己取，**框架不跨线程调模块**；**推送式 `IModule.OnCommand` / `OnInput` 作废**，**ADR-0040 的推送式条款（D1/D2）已不适用**（历史见归档）。本文件 §7 即按此写。仍有效的语义：**失败转 Issue、输入一次提交、开关松手写入**〔源: 用户裁定 + 05 §5.20 + `ModuleContext.BoundedInbox`〕。
