# 应用设置（Settings）

> 状态：**现行**（来源见各节标记）
> 适用范围：应用级设置（`settings.json`）的**键清单、类型、默认值、取值范围、生效时机**，以及它与组合件 / Configuration 的边界
> 与主文档的关系：主文档 `上位机架构设计.md` 是验收唯一事实源；本文件是其实现层分册，冲突时以主文档为准。

## 0. 定位与边界 〔源: 主文档 §9.5 + architecture/04b §1–§2 + ADR-0030〕

**应用级设置 = 应用/用户级的行为偏好**，独立于组合件，**不属「工作现场内容」**（主文档 §9.1）。

| 内容 | 层级 | 载体 | 随组合件 | 谁改 |
|---|---|---|---|---|
| **组合件** | 内容（实例 + 网络 + 配置 + 布局） | 1 文件 1 件（主文档 §9.2） | —（它自己就是载体） | 用户（保存时） |
| **Configuration** | 实例参数 | 组合件内 | ✅ | 用户（模块窗口内配置表单） |
| **Layout** | 视图布置 | 组合件内 | ✅（加载可忽略） | 用户（拖动） |
| **Settings** | 应用偏好 | **独立用户级文件** `settings.json` | ❌ 完全分离 | 用户（设置界面） |
| 会话快照 | 现场自动恢复 | Gate D（**不在 v1**） | — | 框架 |

持久化内容的**全集**即上表的组合件 / 应用级设置 / 会话快照三类〔源: 主文档 §9.5〕。

| 面 | 结论 |
|---|---|
| 归属 | **Core（L4）** 管理与持久化（不是模块、不是 UI） |
| 读取 / 提交 | 一律经 `Core.Api`：`IRuntimeQuery.GetSettings()`（返回 `Clone()` 快照）/ `IRuntimeCommand.UpdateSettings(settings)` |
| 呈现 | `FrameworkUi` 的设置界面（设置/拓扑诊断/Issue/帮助均为**弹窗**，主文档 §10.1-3） |
| 与模块 | **设置不下发给模块** —— 模块只接收自己的 Configuration，不感知全局偏好 |
| 与组合件 | 完全分离：不随组合件保存/加载，组合件**不携带设置快照** |
| 范围（v1） | **仅应用级**；不提供「按模块类型的默认设置」（模块默认值由模块实现提供） |
| 变更语义 | 与 ChangeSet **组合语义无关**（不涉及实例/网络/绑定），**不触发增量重建** |
| 清单可增长 | 新增设置项 = **兼容扩展**（旧文件缺该项即用默认）；**删除项或改语义 = 破坏性变更，须 ADR** |

## 1. 存储与生命周期 〔源: architecture/04b §3〕

| 项 | 现行方案 |
|---|---|
| 形式 | **单一 JSON 文件** `settings.json`；文件可读可 diff（不转义中文，允许注释与尾逗号） |
| 位置 | **应用所在目录下的用户数据目录（便携式）**：`<程序目录>\data\settings.json` —— 拷贝整个应用目录即可搬走配置。**路径口径唯一来源 = 统一的路径解析器**（`decisions.md` 7.55 · P5/P6）；用户数据统一收进 `data\`（目录布局见 `10-delivery-and-ops.md` §1）。**旧的 exe 级 `settings.json` 不搬家、不提示**。**未落地**：`data\composites\` 的对话框初值（入口属已知 G14）、`data\logs\`（日志能力本身未落地）—— 见 `roadmap.md` 第 54 项 |
| 写入 | **原子写**：同目录 `.tmp` → `File.Replace`（文件不存在时 `File.Move`）；失败清理临时文件 |
| 写盘时机 | **每次变更立即原子写**（无需「退出前刷新」，崩溃丢失窗口 = 0） |
| 读回策略 | 以 `JsonObject` 为底稿，**只更新已知字段** ⇒ **未知字段原样保留 + 合并写回**（版本前进/回退皆无损） |
| 缺失 | 文件不存在 → 内置默认值，`DefaultsCreated`（首次运行，正常，不报 Issue）；**首次运行不生成文件**，直到首次变更才落盘 |
| 损坏 / 不可读 | 内置默认值 + **Warning Issue**，`DefaultsAfterFailure`，**不阻断启动**；**原文件保持不变** |
| 应用目录不可写 | 启动/运行期不做静默回退：改动**本次运行内生效但不落盘**，写失败 → Issue（「设置已生效但未能写入文件……重启后丢失」）并回执提示「应用目录可能不可写」 |
| 多实例 | 直接覆写（**最后写入获胜**），不做冲突检测（用户裁决） |
| 版本字段 | `schemaVersion`（当前 **1**），随文件写入 |
| 并发 | Core 持有唯一实例；UI/其他读取经 `Core.Api` 取**快照副本** |

**共 21 个键**（上表逐行；`schemaVersion` 是文件版本字段，含在内）。**`appTopmost` 不在本清单内** —— 它属**运行期状态（不持久化）**，见下。

> **`multilineSubmitKey` 为什么是应用级设置而不是模块声明**（G2 · 用户 2026-09 裁决）：用户原话 ——
> **「换行是一个极其常见的行为，且不同用户习惯不一样」** ⇒ 由**用户**在设置里选；**模块只声明「我要多行」**
> （schema 键 `multiline`，缺省 `false`）。**单行输入不受本项影响**：仍是「回车 / 失焦一次提交」（ADR-0040 D-5）。
> 三档语义：`CtrlEnter`（默认）= 回车换行 · Ctrl+Enter 提交 · **失焦不提交**（否则「点模块按钮 ⇒ 先失焦提交 ⇒ 按钮又发」会**双发**）；
> `Enter` = 回车提交 · Shift+Enter 换行 · 失焦提交；`None` = 键盘都不提交，只用模块的按钮。

**运行期状态（不持久化，不进设置键清单）**：

| 项 | 现行事实 |
|---|---|
| **`appTopmost` 应用整体置顶** | **运行期状态**：属性存在（默认 `false`）、界面可切换且即时生效，但设置文件的 JSON 映射**既不读也不写** ⇒ **不落盘**，重启后回到 `false`。按 §4 纪律，它**不属于需要持久化的设置项**——置顶是**运行期状态切换**（这也正是它放在交互面板而不是设置里的原因）：**只在会话内生效**。 |

### 2.1 校验与非法值处理

- **生效机制 = 常规三键「确认 / 取消 / 应用」**（**用户裁定**，原话见 `decisions.md` 7.38）：设置页里**任何**改动（含主题/主题色/背景/方向色/字体）都只是「**待生效**」；**只有**点「应用」（校验 → 生效 → 落盘，弹窗保留）或「确认」（同上 + 关闭弹窗）才真正生效并写盘；「取消」= 回到已生效值并关闭。**校验失败 ⇒ 「确认」不关闭**（原因显示在面板左下角的状态行）。**旧口径「外观改动即时生效（ADR-0038 D4）」已撤销**。
- **值域校验失败 ⇒ 整批拒绝，零副作用**（不落盘、不生效），回执逐条原因。受校验的只有 5 项：`inputQueueCapacity` 1–65536 · `stopTimeoutSeconds` 0.1–300 · `uiRefreshRateHz` 1–240 · `diagnosticHintThreshold` ≥1 · `snapDistance` 2–8。
- **全局一键还原**（**用户裁定**，原话见 `decisions.md` 7.38）：设置页底部按钮行（**与「取消 / 应用 / 确认」同一行**）左侧有「**恢复全部默认设置**」。**范围** = 本页全部可配置项（应用行为 / 外观 / 字体 / 快捷键 / 模块来源根 / 日志级别 / 置顶），取值直接来自 `ApplicationSettings` 的**缺省对象**（不另写一份「默认值清单」）；**不落盘**：与三键机制一致，它只把字段填成默认值并提示「点「应用」或「确认」后生效」（还能用「取消」反悔）。**不在范围内**：数据结构 → 颜色表（那是另一处入口的映射表）。
- **外观类不做校验**：`theme` 非 `Dark`/`Light` 的值 → 走 `ThemeVariant.Default`（跟随系统）；`accentColor`/`backgroundColor` 无法解析 → **不覆盖 token**（回落主题内置值）；两个方向色同理（空/非法 = 跟随主题默认）。
- **类型不符/缺失的字段** → 回落默认值（`ReadInt/ReadDouble/ReadBool/ReadString` 容错读）。

### 2.2 旧键兼容与迁移 〔源: 主文档 §9.5〕

| 旧键 | 新键 | 读 | 写回 |
|---|---|---|---|
| `autoNetworkEnabled`（**已作废的旧键**：随快速建网 R0–R6 一起废除） | `alignAutoNetwork`（**对齐自动建网**） | 新键优先，旧键回退 | **删除旧键** |
| `moduleSourceDirectory`（单值） | `moduleSourceDirectories`（有序列表） | 新键非空优先；否则旧键作为**首项** | **删除旧键** |
| `showLinkLines` → `showPortMarkers` | `showInfoOverlay`（**叠加信息层**） | 三级回退：`showInfoOverlay` → `showPortMarkers` → `showLinkLines` | 写新键；旧键作为**未知字段保留**（不删） |

- `showInfoOverlay` 的**旧配置兼容**：文件里显式写过旧键/新键的**仍按文件值生效**，只有「没写过」的（含全新安装）才落到默认 `false`；端口标记**常显**、不受该开关影响〔源: ADR-0045 D1〕。
- 旧语义已作废：R0「加入模块即自动连线」整体移除（改为对齐自动建网）；「连线层 / 口上标记」两次语义变更由 `showInfoOverlay` 承接。

### 2.3 外观相关设置 〔源: 主文档 §9.5〕

**机制**：只替换**角色 token 值**（Light/Dark 主题字典），视图一律用 `DynamicResource` 取色 ⇒ 改设置**不动任何视图**，模块窗口、弹窗、叠加层一并跟随。覆盖必须**直接改写主题字典中的键值**（资源查找顺序 = 主题字典 → 自身条目 → 合并字典），且每次应用前**恢复上一次覆盖**（快照 → 还原）以免污染内置 token；覆盖用**不可变画刷**（渲染线程会读）。

| 设置 | 落到的 token | 说明 |
|---|---|---|
| `accentColor` | `AccentPrimary`、`AccentSecondary`、`OverlaySelection`(α0.20)、`OverlayHighlight`(α0.12) | `AccentSecondary` = 主题色邻近色派生；**无用户输入** |
| `backgroundMode` / `backgroundColor` | `BgWorkspace`、`BgModule`、`BgChrome` | 三档背景色；`Theme` = 不覆盖（跟随主题） |
| `directionSendColor` / `directionReceiveColor` | `DirectionSend` / `DirectionReceive` | **仅用户显式填色时覆盖**；空 = 跟随主题默认（深浅两套各自的内置方向色都保住） |
| `uiFontFamily` / `dataFontFamily` | `FontUi` / `FontData`（**顶层键**，不在 `ThemeDictionaries` 里） | **界面字体 / 数据字体**（值可以是**回退列表**，逗号分隔、拉丁在前中文在后）；设置页的两个下拉框是**可编辑**的 ⇒ 既能从系统字体里挑，也能手输回退列表；候选表**头两条是默认的两组回退列表**（写回默认值时也选得中） |
| `theme` | `Application.RequestedThemeVariant` | `Dark`/`Light`/其他→`Default`（跟随系统） |

- **字体与颜色是同一条管线**（资源覆盖 → `{DynamicResource}`）：**唯一技术差别**是颜色写进 `ThemeDictionaries`（按主题变体分两套）、字体写进**顶层键字典**（深浅共用）⇒ 排查「改了没生效」时**先看落盘与回读**，别先怀疑机制不同。
- **2026-09 缺陷（已修 · `decisions.md` 7.54）——「字体下拉框为空」**：根因 = 下拉框**非编辑**且候选表里全是**单个系统字体名**，而设置值是**回退列表** ⇒ 匹配不到任何一项 ⇒ **显示为空**。修法 = ① 下拉框改**可编辑**并绑 `Text`（任何值都显示得出来）② 候选表补上两条默认回退列表 ③ 底部加**全局一键还原**按钮（见 §2.1）。
- **2026-09 缺陷（已修 · `decisions.md` 7.53）**：设置快照**漏拷** `UiFontFamily`/`DataFontFamily`，而快照是**读**与**写**两条路的必经之地 ⇒ 落盘写默认值、读回默认值、「生效」拿到的还是默认值（现象 = 「颜色能改、字体改不动也存不下」）。修法 = 补齐快照的两个字段 + 应用路径的回读块。**护栏 = 反射式全属性拷贝断言**（将来再漏一个字段会当场红）。
- **自绘层也必须跟字体**：叠层文字与连线文字与颜色**同一手法** —— 控件暴露数据字体，XAML 用 `{DynamicResource FontData}` 注入；字体变化时**清文字排版缓存**（缓存键不含字体）。**回归判据 = 断言来源键 `FontData`**，不是断言某个字体名。

- 主题色预设 **8 档**：蓝 `#2563EB` · 青 `#0891B2` · 绿 `#16A34A` · 橙 `#EA580C` · 红 `#DC2626` · 紫 `#7C3AED` · 粉 `#DB2777` · 灰 `#52525B`。
- 背景档位 → 三色：`LightGray` = `#E8EAED`/`#F7F8FA`/`#F1F2F5`；`DarkGray` = `#17181A`/`#202124`/`#1B1C1F`；`Custom` = 用户色 + 向白 +6%/+3% 的两级派生。**v1 无图片背景**。
- **语义边界**：`accentColor` 只表达**框架性交互**（选中/聚焦/活动/参考线）；方向色**独立驱动**「发送/接收」（消费者 = 端口标记箭头与边框、建网预览描边、叠加层流向箭头）；**模块内部特有的绘图与文本颜色由模块自己决定**（数据-颜色绑定归后续协议专项）〔源: ADR-0044 D1a/D7〕。
- 外壳尺寸：`shellAspect` 按**短边基准 396 DIP** 换算（`9:19.5` ≈ 396×858）；`shellFixedSize = false` 时可自由缩放，此时**最小尺寸 360×480 DIP**，比例仅作初值。

### 2.4 类型 → 颜色表（`typeColors`）〔源: ADR-0054〕

- 一行 = **一种数据类型身份**（键与 `PortView.TypeKey` / 色板 / 角色键**同源**）；值 = `#RRGGBB`；**缺省 = 不配置** ⇒ 该类型走**稳定哈希自动配色**（跨模块/跨进程/跨重启同色，不配置也能分辨类型）。
- **改色唯一入口**：侧边栏「交互」页底部「数据结构 · 颜色」表 ⇒ ① 色板（**唯一色彩来源**，端口标记窄色条与叠加层角色方块共用）② 落盘（`typeColors`，**缺省不写**）③ 界面重画（角色方块绘制期取色）。取色弹窗 = 8 档预设色片（与主题色同一套）+ 十六进制 + 恢复自动色。
- **纪律**：**只列现场真出现过的类型**（不发明条目）· **只呈现**（不参与建网/兼容/停流/投递/计量）· **不进组合件**。

### 2.5 快捷键（`hotkeys`）〔源: ADR-0036 D7〕

动作 = 固定目录（顺序即设置界面展示顺序）；缺失的动作用**内置默认绑定**；绑定为空串 = **不绑定**；作用域 = **应用内**（任一本应用窗口聚焦即生效）；**不实现系统级全局热键**；设置界面提供「恢复该项默认 / 全部恢复默认」，并检测绑定冲突。

| 动作标识 | 界面标题 | 默认绑定 |
|---|---|---|
| `openCatalog` | 打开模块清单 | `M` |
| `openIssues` | 打开 Issue | `I` |
| `openSettings` | 打开设置 | `S` |
| `openTopology` | 打开拓扑诊断 | `T` |
| `toggleMarkers` | 切换叠加信息层 | `L` |
| `toggleSnap` | 切换几何吸附 | `G` |
| `toggleLockAll` | 全部锁定 / 解锁 | `Ctrl+L` |
| `toggleAnchorFixed` | 固定 / 解锁端口锚点 | `Ctrl+P` |
| `toggleAppTopmost` | 应用整体置顶 | `Ctrl+T` |
| `raiseAllWindows` | 全部置前 | `Ctrl+R` |
| `showAllWindows` | 显示全部模块窗口 | `Ctrl+W` |

> `toggleAnchorFixed`（**G5 · C5-7**）与 `toggleLockAll` **不是一回事**：后者锁的是**模块窗口**（不可移动、不可缩放），
> 前者固定的是**端口锚点**（不可沿边拖动、不可换边）；用词按 `decisions.md` 7.14 一律「固定」。
> 它是**全局批量**入口；**单口**固定/解锁在标记内侧浮出的图标按钮上（见 `07` 端口标记表）。

绑定文本语法：`Ctrl` / `Shift` / `Alt` + 主键名（如 `Ctrl+Shift+L`、`M`）；只按修饰键不算绑定；非法/空 → 不绑定。

### 2.6 模块来源根（`moduleSourceDirectories`）〔源: ADR-0036 D1 + 主文档 §11.2〕

- **有序**根列表：启动与「立即重扫」**按顺序逐根扫描**；每根只扫**直接子目录**中含模块清单文件者；**先到者胜**（同 ID 同版本重复只记 Info）。
- 空列表 = 只用**内置包目录**（应用目录下 `modules\`，由构建产出）；内置目录**始终排在首位**（组合根拼接），**不可由用户移除**。
- 增删根**立即落盘并刷新诊断**；**改过代码的包需重启应用才生效**（框架**不实现热重载**）。

## 3. 变更路径 〔源: architecture/04b §5〕

```text
设置界面（FrameworkUi）→ Core.Api.UpdateSettings → SettingsService.Update
  → 校验（类型/范围，失败即整批拒绝、零副作用）→ 内存中的设置快照原子替换（Clone）
  → 即时应用到运行时（Carriers 选项 / 对齐自动建网）→ 通知相关组件
  → 合并写回 + 原子写盘（失败 → Issue，内存态保留并提示未持久化）
```

- 别名/一次性副作用：应用成功后 UI 侧再套用主题、重建快捷键绑定、套用窗口置顶状态、刷新外壳尺寸。
- **会话内视图开关 ≠ 设置**：工具栏上的「显示/交互」开关只改本次运行（**不写回设置**）；设置弹窗里的对应项是偏好，启动时生效。

## 4. 纪律：缺省不写 = 不产生死数据 〔源: ADR-0054 + ADR-0044 §4〕

| 纪律 | 现行实现 |
|---|---|
| **首次运行不生成 `settings.json`** | 缺失即用内存默认值（`DefaultsCreated`）；只有发生**首次变更**才写文件 ⇒ 没改过设置的用户不会多出一个死文件 |
| `typeColors` 只写**用户真正覆盖过**的条目（空键/空值直接跳过） | 未覆盖的类型不落盘 ⇒ 自动配色始终有效，配置文件不膨胀 |
| 方向色默认写**空串**而非某个具体色 | 空 = 跟随主题默认 ⇒ 深/浅两套主题各自的内置方向色都有效，不被浅色默认值「覆盖成死值」 |
| 反向教训：`accentColor` 默认**非空** | 其伴生色 `AccentSecondary` 因此**从不生效**（始终被 `accentColor` 派生值覆盖）——**已知历史问题**〔源: ADR-0044 §4〕；新增「跟随主题默认」的色项一律默认空串 |
| 旧键迁移后**删除**旧键（`autoNetworkEnabled`/`moduleSourceDirectory`） | 同一事实绝不留两个字段 |
| **未知字段保留** | 只更新已知字段；未识别内容原样写回（版本前进/回退皆无损） |
| 设置项必须**可在设置界面看到** | 禁止任何「隐藏的全局行为开关」 |
| **运行期状态切换不进设置项**（例：窗口置顶、叠加层开关、拖动分组等，**用户裁决**） | 它们**只在会话内生效**；只有**跨会话要记住的偏好**才落设置（现行实例见 §2）；工具栏的「显示/交互」开关同样只改本次运行（§3） |

> 对照现状：`showInfoOverlay`（叠加层开关）目前仍是**持久化设置键**（代码事实，见 §2 清单）——本纪律用于**新增设置项**的准入判定，不追溯改写既有键。

设置界面按**七类**组织（与代码的 7 个页签一致）：**常规**（应用行为：停止超时 / 输入队列容量）· **模块与来源**（来源根列表 + 逐包扫描诊断）· **窗口与交互**（应用整体置顶；拖动与吸附说明）· **外观与显示**（刷新率 / 吸附距离 / 主题 / 主题色 / 背景 / 发送色 / 接收色（含实时预览）/ 主窗口比例 / 叠加信息层）· **快捷键** · **日志与诊断** · **关于**（版本、用法速查、文件位置）。

## 5. 明确不做 〔源: architecture/04b §4（S-2）+ 主文档 §9.5 / §11.2 + ADR-0044/0045〕

- **不提供**「按模块类型的默认设置」（模块默认值由模块实现提供，用户在实例 Configuration 中覆盖）。
- **不提供**任何隐藏的全局行为开关；**不做**图片背景（背景只支持 跟随主题 / 浅灰 / 深灰 / 自定义纯色）。
- **不实现**系统级全局热键（未聚焦也响应）；**不实现**热重载（语义固定为「改代码 → 重建 → 重启应用」）。
- **不提供**单窗口置顶（只有「应用整体置顶」一种统一状态，避免「一部分被覆盖、一部分置顶」）。
- **不新增**任务栏相关设置项（模块窗口不进任务栏是固定行为）。
- 设置**不下发**给模块；**不进组合件**；不参与建网/兼容/判定语义（`typeColors` 只影响呈现）。

## 6. 落地缺口（设计 ↔ 代码） 〔源: 代码现状（以代码为准）〕

以下为**代码现状与设计不一致**处（正文一律按「以代码为现行事实」写）：**如实登记为落地缺口**，不在此拍板设计。

| # | 缺口 | 现状（代码为准） | 应有处置 |
|---|---|---|---|
| **G1** | `appTopmost` **属性存在但无读写方** | 属性存在（默认 `false`）、界面可切换且即时生效；`SettingsService` 的 JSON 映射**不含该键** ⇒ **不落盘** | **移除该属性，或改为运行期状态**（按 §4 纪律：运行期状态切换不进设置项） |
| **G2** | **日志能力未落地**（「日志文件位置」键不存在） | 代码**只有 `logLevel`**，**无「日志文件位置」键**；全仓无日志依赖、无文件 sink、无 `logs\`（另见 `10` §4.3 / §8） | 键清单**不含**该条；日志能力（sink + 文件位置 + 滚动）按 `10` §4.2 在 M1-10 / M2 落地 |
| **G3** | `diagnosticHintThreshold` 与 `logLevel` **当前无消费者** | 两项键在**设置文件里真实存在**（定义 / 校验 / 读写 / 界面齐全），但 `src/` 内**检索不到消费者** ⇒ 声明的「即时生效」尚未实现 | **保留键**并在 §2 标注「当前无消费者」；接入消费者后回写状态 |
| **G4** | 设置变更**未走 ChangeSet 同一入口** | `RuntimeServices.UpdateSettings` **直连** `SettingsService.Update`，不经 `ModuleRuntime.Apply(ChangeSet…)` ⇒ 与「**状态修改只有一条串行路径**」的约束**不符** | 接入统一入口，或由 ADR 明确「设置走独立入口」及其并发保证（**本轮不拍板设计**） |
| **G5** | `schemaVersion` **无迁移、非源生成** | 只有 `schemaVersion` 字段的读写，**未见迁移分支或版本门禁**；映射是**手工解析**，**非源生成** | 如实登记现状；迁移 / 门禁 / 源生成是否补做待定 |

**已按代码落定、不再作缺口的项**：背景档位是**两个键** —— 档位 `backgroundMode`（默认 `Theme`）+ 自定义色值 `backgroundColor`（默认 `#F3F4F6`，**仅 `backgroundMode = Custom` 时生效**）。
