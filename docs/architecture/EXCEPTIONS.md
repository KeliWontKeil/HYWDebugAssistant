# 架构例外登记

> **本文件是架构例外的唯一登记处。** 代码里那行 `// ARCH-EXCEPTION: <原因> · <复查条件>` 只是索引，不构成登记。
> 违反任何架构约束（依赖规则、分层、契约签名、工程纪律…）都必须显式申报并登记到本表；**禁止静默绕过**，缺登记视为门禁失败。

## 登记规则

1. 代码注释写 `// ARCH-EXCEPTION: <原因> · <复查条件>`，**并**在本表追加一行。
2. **追加式**：不删行。例外失效时把「状态」改成「已关闭（YYYY-MM-DD）」并写清关闭原因。
3. 每个里程碑收尾复查一次：过期的例外必须关闭或续期。
4. 单人项目由开发者自行登记，但必须在提交前完成。
5. 「临时」不是原因。写清为什么现在必须例外、什么条件下能撤销。

## 登记列

| 列 | 含义 |
|---|---|
| 日期 | 登记日期 |
| 约束 | 被例外的规则（如 AR-7 / 分层依赖 / 契约签名规则） |
| 位置 | 代码位置或范围（项目 / 文件） |
| 原因 | 为什么必须例外 |
| 复查条件 | 什么时点或事件下应关闭该例外 |
| 处置人 | 登记人 |
| 状态 | 生效 / 已关闭（YYYY-MM-DD） |
