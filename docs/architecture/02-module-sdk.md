## SDK 的定位与边界 〔源: architecture/03 §3.1 + ADR-0026 · ADR-0027 · ADR-0028〕

- SDK = **`HYWDebugAssistant.Sdk` 单一程序集**，是模块作者**唯一**可引用的框架程序集。
- **零框架依赖**：不引 `Infrastructure`，不引任何 UI 框架，不引其他框架项目；模块实现层只引 SDK。
- 承载三件事：① **声明载体**（特性与声明类型）· ② **实现基元**（模块接口与生命周期钩子）· ③ **框架服务面**（上下文、上报、配置读写）。
- **不含**：机制实现、契约兼容判定的实现（在 L2/L4 侧）、数据面投递类型、UI 类型。
- 边界纪律：SDK 的公开 API 必须有 XML 注释；**SDK 的破坏性变更等同契约变更，必须走 ADR**。

### 公开面的签名纪律（硬规则，两处来源同口径） 〔源: ADR-0041 D6/P30 + ADR-0050 R1〕

| 规则 | 内容 |
|---|---|
| 只增不改**看签名、不看语义** | **禁止**用**构造器可选参数**扩展声明面——那会改变方法签名，已编译模块各自带一份 SDK 副本 ⇒ 加载即 `MissingMethodException` |
| 新增可选声明的唯一方式 | **`init` 属性**或**新类型** |
| 连带要求 | **改 SDK 后必须重编全部模块包**（模块包与 SDK 版本耦合，纳入验收前检查） |

## 声明载体：C# 特性 + 反射 〔源: architecture/03 §3.2 + ADR-0028〕

Definition 六项声明与 manifest 附加项在技术上的映射：

| # | Definition 六项 | SDK 载体 | 说明 |
|---|---|---|---|
| ① | 身份与版本标识 | 模块特性上的**结构化三元组**（作者命名空间 / 模块名 / 版本） | 版本参与多版本共存与重锚诊断 |
| ② | 目录/用户元数据 | 特性属性：显示名、描述、可选标签 | 仅供 UI 目录展示；**不构成框架业务分类** |
| ③ | 对外契约声明 | **契约类型**（C# 类型即契约）+ 口成员声明（名称、方向两态、契约类型） | 见「口声明」与「契约」 |
| ④ | 可配置项声明 | **配置类型**（C# 类型） | 见「配置」 |
| ⑤ | 可选视图声明 | **视图声明**（预置控件组合） | 见「视图」；模块不提供 View 类型 |
| ⑥ | 宿主/生命周期能力声明 | 特性属性：是否参与数据活动、是否需要配置变更通知、活动承载需求 | 供 L2/L3 决定承载方式（不构成框架分类） |
| — | 实现入口（manifest） | 模块实现类型（实现模块入口接口） | 包加载时定位 |
| — | 依赖（manifest） | 特性声明其他模块 ID 三元组的依赖 | 缺失依赖 → Issue，**不静默降级** |
| — | 框架兼容范围（manifest） | 特性声明兼容的框架主版本区间 | 加载校验 |
| — | 可选资源引用（manifest） | 资源清单（图标等） | 物理形式 Gate |

**反射策略**：声明**仅在模块包加载/注册期读取一次**，读取后转为**不可变元数据**缓存；**运行期热路径零反射**（契约元数据在注册期解析成形）。

### 扩展声明面（同样只增不改） 〔源: ADR-0046 D2 · ADR-0050 B7 · ADR-0052 §11 · ADR-0049 §影响面〕

除 Definition 六项外，模块在 `OnRegistered` 期还通过模块声明接口（`IModuleDeclaration`）追加声明：

| 声明 | 作用 | 现行约束 |
|---|---|---|
| `DeclareDataType(DataTypeDeclaration)` | 声明数据类型身份（标识 + 版本 + 定长形状 + 传输语义 + 计量块 + 解码器 + 语义元数据） | 框架只持**机械镜像**、不解释语义；口用 `PortDeclaration.Type` 引用；引用未声明类型或重复声明**都报 Issue 并回退**（完整规则见《数据协议与类型》分册） |
| `DeclareRole(RoleDeclaration)` | 声明**功能分块**（1 种数据类型 + 输入口/输出口集合，口数不设上限） | 框架**只校验结构**（Id 唯一 / 类型可解析 / 口存在且方向相符 / 一口最多属一个角色 / **输入口与输出口同型** / 至少一个口），非法**报 Issue 并忽略该条**；>2 口只在 SDK 自检走**独立建议通道** `Advisories`（不进 `Problems`、运行期不报）；**框架不派生、不发明角色** |
| `DeclareFlow(FlowDeclaration)` | 声明角色 → 角色的内部处理顺序 | 框架**只存不解释**、不参与建网/兼容/停流/投递/计量，**不进组合件** |

角色、`m/n`、角色间连线**只呈现**：不参与任何框架判定，也不进组合件。

### 角色两侧同型（α）〔源: 用户 2026-09 裁定 · 主文档 §4.10 ③ · `decisions.md` 3.10〕

**一个角色的输入口与输出口承载同一种数据类型**（= 该角色的 `Type`）。ADR-0052 只裁了"一个角色只有一种数据类型"，本条裁的是它**没裁的那半** —— **两侧是否同型**。

| 项 | 现行 |
|---|---|
| **为什么** | 角色方块**填充 = 一种类型色**（`PacketTypePalette.For(role.TypeKey)`）⇒ 一个角色物理上**只能表达一种类型**；让两侧异型会让"这个方块是什么类型"失去答案 |
| **推论** | **类型转换 = 两个数据角色**（"收 A" 的角色 + "发 B" 的角色）+ `DeclareFlow` 表达先后 ⇒ 叠加层上是**两个方块**、各按自己的类型色 |
| **另一条推论** | 同一路输入要喂给两个角色 ⇒ **需要两个接收口**（"一个口最多属于一个角色"），由上游一个发送口按 **1→N 广播**（`05`）投递 |
| **校验落点** | ① **SDK 自检**：`ModuleContract.CheckRoles` ⇒ **`Problems`**（空 = 合法）；② **加载期**：`ModuleInstanceFactory.BuildRoles` ⇒ **Issue + 忽略该条**（与其余结构非法同处置） |
| **不校验的情形** | 口**未声明 `PortDeclaration.Type`**（旧模块形态）⇒ 无可比对象，**跳过不报**（"可声明 ≠ 必须声明"） |
| **模块作者怎么写** | 反例：`RoleDeclaration.Both("convert", typeA, "in", "out")`（`out` 是 typeB）⇒ **非法**；正例：`Input("recv", typeA, "in")` + `Output("send", typeB, "out")` + `DeclareFlow("recv","send")` |

#### 口 → 角色归属的完整性（B5）〔源: 用户裁定〕

「有数据口的模块**应当**声明角色」是 ADR-0052 的措辞（**应当，不是必须**）⇒ 归属完整性**只给建议、不是错误**：

| 情形 | 自检（`ModuleContract`） | 运行期 |
|---|---|---|
| 有数据口，但**零（有效）角色** | `Advisories` 一条（叠加层不会画任何功能块） | **不报** |
| 有角色，但**某口不属于任何角色** | `Advisories` 一条（点名那些口） | **不报** |
| 角色**结构非法**（Id 重复 / 类型不可解析 / 口不存在 / 方向不符 / 一口两角色 / **两侧异型** / 零口） | **`Problems`** | **Issue + 忽略该条** |

**为什么运行期不报**：与"口数 > 2 只给建议"同一口径（ADR-0052 Q3）—— 在自家正确模块的 Issue 中心报警，用户会以为模块写错了；且 ADR-0052 只要求"应当"，把建议升级为错误会与它矛盾。

## 标识：结构化三元组 〔源: architecture/03 §3.2 ① + ADR-0028 + architecture/12 §1.4〕

- 模块 ID = **作者命名空间 / 模块名 / 版本**（形如 `hyw/text-sender/1.0.0`）；**版本是 ID 的独立维度** ⇒ 同 ID 多版本共存注册，实例引用**创建时所选版本**。
- 口级端点 = **`实例ID.口名`**；连接锚定端口实例而非 Definition 的契约声明；重锚按三元组（含版本）匹配，版本不兼容 ⇒ **缺失态 + Issue**（可手动指定替代版本）。
- 可读、可治理、可 diff 是选它的理由（GUID 不可读、不利组合件 diff）。

## 口（端口）声明 〔源: architecture/03 §3.2.1 + 主文档 §5.4 + ADR-0005 · ADR-0009 · ADR-0022〕
| 项 | 现行约定 |
|---|---|
| **口 = 端口实例** | 口是模块实例上的**端口级端点**（Interface Instance）；Connection 两端**锚定端口**而非 Definition 的契约声明；多同型口由"命名/编号"区分 |
| **口名唯一性** | 口名 = **模块内唯一稳定名**（作者命名；多同型用「名 + 序号」）；由**加载期校验**（重复即**拒绝注册 + Issue**，**不静默改名**） |
| **方向两态** | 口只有**发送 / 接收**两态（撤销"双向"口类型）；**双向 = 两个口 + 两条单向网络**；网络严格单向 |
| **无特殊命令接口** | **不设**"命令接口 / 控制接口 / 状态接口"这类特殊口类型：一切内容经数据单元流 + 契约；命令/数据/事件是**契约的传递语义标注**，不是接口种类；模块状态走上报通道，不占数据口 |
| **契约引用形态** | 契约**一律具名引用**（随模块包/Definition）；**v1 不支持内联契约** |
| **元能力目录** | 平台提供**受控元能力目录**（可实例化口 / 可被连接 / 方向两态）；业务形状由作者契约描述、**不入目录** |
| **口级自动建网开关** | `PortDeclaration.ParticipatesInAutoNetwork`（bool，**默认 true**）**存在，但当前无任何消费者**（框架不按它决定是否参与自动建网）；**实现或删除待定**（记入**落地缺口**，见下） |

**口级"参与自动建网"开关 = 有声明、无消费者的落地缺口（非待裁）**〔源: `PortDeclaration.ParticipatesInAutoNetwork`（默认 `true`）〕：

- **现状**：`PortDeclaration.ParticipatesInAutoNetwork` **确实存在**（构造参数 + 属性，默认 `true`），**但框架从不读它** —— 现行建网只按**标签**（命名网络）与**几何**（未打标签口"接触且对齐"，`DockRule`）判定，参与与否由"**是否打了网络标签**"决定，没有按口级标志过滤的代码路径。
- **结论**：读它/不看它**不改变任何现行行为**，故**不是待裁**，而是**"有声明无消费者"的落地缺口** —— **实现（按标志过滤建网）或删除（从 SDK 移除该参数，走 `init` 属性兼容路径）待定**，记入落地缺口清单。
- **附带：注释里的失效引用**：该参数注释引用的"**R0–R6 快速建网**"是**失效引用** —— 该机制已由 **ADR-0037 D1 整体作废**（现行 = 命名网络 + 对齐网络两条）。**注释需在后续 bug 修复轮改正**（本轮只登记，不改 SDK 源码）。

## 实现基元：接口实现 + 六个钩子 〔源: architecture/03 §3.3 + C3-4 + architecture/04 §4.1〕

模块作者实现一组**接口**（**不继承框架基类**），框架只按接口调用。

- **必需接口**：模块入口接口（提供 ID/元数据读取与生命周期钩子的入口）。
- **可选接口**（按声明能力实现）：配置变更通知、活动承载回调（模块需要自发活动时）、上报扩展。

**六个生命周期钩子**（对齐框架状态机 `Registered → Active ⇄ Disabled → Removed`）：

| 钩子 | 触发时机（框架侧） | 模块应做 |
|---|---|---|
| `OnRegistered` | 实例创建、成员实例化完成后 | 建立内部结构；**不得**假定数据已在流动；**只在实例创建时触发一次**（增量重建**不重置**模块实例） |
| `OnActivated` | 进入 `Active`（加入即运行） | 开始业务活动（若需要） |
| `OnDisabled` | 进入 `Disabled`（保留实例/拓扑/配置、暂停数据流） | 内部处置**自决**（框架不替模块决定"是否断硬件"） |
| `OnEnabled` | `Disabled → Active` | 恢复业务活动 |
| `OnConfigurationChanged` | 配置更新（框架通知模块） | 应用新配置；热生效或请求重建**由模块自决** |
| `OnRemoved` | `Removed` 前 | **释放模块内部资源**（框架已先清连接/绑定与成员实例资源） |

- **不进钩子集的**：数据到达（属数据面调用路径）、业务状态上报（属服务面即时 API）。
- **异常纪律**：钩子与投递回调中的异常**不得逸出边界**——框架受控捕获并转 Issue。
- **自发活动**：模块**不得自建线程/定时器**；需要周期或事件驱动活动时，声明活动需求、由 L3 **承载调度**（可选接口 + 框架承载）。

## 契约：C# 类型即契约，且只定长 〔源: architecture/03 §3.4 + ADR-0008 · ADR-0028 · ADR-0051〕

契约 = 模块作者定义的 **C# 类型**，但**构成受限**：只能由平台提供的**形状原语目录**组合而成，框架在**加载期**反射校验成员类型。

| 契约能力层 | 内容 | 载体 |
|---|---|---|
| ① 传递语义标注 | 流 / 消息 / 事件 | 契约类型上的标注（作者声明）；跨语义**不判兼容**，需模块内部自行组帧 |
| ② 受控基础形状原语目录 | 平台提供、可扩展、作者只能组合 | SDK 侧只落一条硬约束：**只支持定长原语 + 结构组合，无变长**（字符串/序列由定长数组 + 长度字段自行表达）〔C3-5〕。**原语清单与各项上限以《数据协议与类型》分册为唯一落点**，本分册不复制 |
| ③ 组合与签名 | 成员序列（名称 + 原语类型 + 顺序）= 签名，是兼容判据锚点 | 兼容判定 = **形状完全一致**（逐字段结构比较，可完全计算）〔ADR-0051 修订：原「接收 ⊇ 发送」子集判定**已作废**〕 |

**边界（不得违反）**：

- 框架**不附加任何数据单元元信息**（时间戳/序号/来源）——需要者由模块**在自己的契约里声明字段**；
- 契约**不含单位/量纲语义**——单位属模块配置/显示层（语义元数据可随类型声明供展示，但**不参与任何框架判定**）；
- **不自动转换**：不兼容即不可连 + UI 明示差异，转换由用户显式插入转换模块。

**判定执行位置**：在 L2/L4 侧实现，**不在 SDK**；SDK 只提供契约的声明类型与元数据描述。吸附仅几何对齐，兼容判定发生在建立网络时。

**读取纪律（防御，长期保留）** 〔源: ADR-0051 D3 + architecture/18 §8.10〕：**到达的数据报长度 = 发送方的契约尺寸**（框架不投影、不补零、不截断）；接收方**按到达长度读**，用 SDK 的 `PayloadReader.TryCreate`（长度不足返回 `false` 不抛）；用**自己的**契约硬构造 `PayloadReader` 在长度不足时会抛异常，而**异常从投递回调逸出会让该实例的投递循环整体退出**（现场表现为"模块莫名不再收数"）——形状一致后这已不可能发生，但防御式读取不删。

## 配置：C# 类型 + 反射式序列化 + Schema 〔源: architecture/03 §3.5 + ADR-0035 + ADR-0041 D1/D2〕

| 项 | 现行落定值 |
|---|---|
| Schema 来源 | 框架**反射配置类型的公有可读写属性**生成字段；不支持的属性类型（复杂对象等）**不生成字段**，而非假装支持 |
| 可选标注 | **`[ConfigurationField("标题", Group=…, Minimum=…, Maximum=…, Step=…, Unit=…, Description=…)]`**；不标注时标题由属性名生成（`PeriodMs` → "Period Ms"）、控件由属性类型判定（布尔→开关 / 枚举→下拉 / 整型·实数→数值输入 / 字符串→文本） |
| 范围语义 | 范围与步长**只约束编辑界面**：框架**不据此裁剪**配置值（语义归模块）；特性参数只能是常量，故"未设置"用 `double.NaN` 表达 |
| 读即登记 | `IConfigurationAccess.Read<T>` **首次读即登记默认配置**（否则只读配置的模块保存时会整块丢配置，且无对象可生成表单）；配置集合的所有访问点**统一加锁** |
| 写回路径 | UI → `Core.Api.UpdateConfigurationField` → **JSON 中转产出新实例** → L4 变更入口（原子应用或整体拒绝、触发**一次**配置变更通知）；**不就地修改运行中的对象** |
| 未知字段保留 | 加载时未被当前配置类型识别的字段**必须保留**，再次保存时**原样写回**——实现 = 保留原始片段 + 合并写回（AC-4 无损往返） |
| 序列化取舍（v1） | **组合件信封零反射**（手工 JsonNode 映射）；**模块自有配置对象走反射式序列化**；配置 JSON 允许 `±Infinity/NaN` 命名浮点字面量、**枚举按名字**读写（旧数字枚举仍可读） |
| 归属 | **Instance 持有、随组合件保存**；Schema 在 Definition；配置界面由框架按 Schema 生成 |
| 还原语义 | **还原 = 用同类型的新默认实例替换**每个已登记配置，**不得** `Clear()`（清空会让"按登记对象生成"的表单失去数据来源） |

> **与"源生成"的差异已登记**：本章原定"配置类型 + 源生成器产出序列化代码"，**v1 未引入源生成器**（模块作者无需提供序列化上下文）；将来需要"编译期零反射"时统一替换（Schema 与序列化一并迁移）。分工是明确的：**声明（六项/成员/契约形状）与配置序列化 v1 都走反射**，反射只发生在**包加载期与配置读写路径**，不发生在数据面热路径。

## 视图：模块只声明，框架渲染 〔源: architecture/03 §3.6 + 03a §8 + ADR-0040 · ADR-0041 D6〕

**约束（不可协商）**：模块**不得提供任何 View 类型**，不得依赖 UI 框架；**视图全部由框架渲染**。

- 模块以**声明**描述视图：从**框架预置控件目录**中选取**控件**、组合、绑定到模块**可暴露的数据源**与配置项（不暴露内部对象引用）。
- **不声明视图的模块合法**，但它**仍然拥有自己的窗口**：窗口内至少显示模块名与状态，并由框架补上配置表单（无配置则说明原因）；**不存在"没有窗口的模块"**。
- **D 类（框架渲染类）不在模块声明范围**：Issue 标注与列表、口上标记与网络标识、流量/丢弃计数、模块状态徽标由框架渲染。
- **控件类型属 SDK 声明类型（即 `ViewElementKind`，现行 19 项）；视觉形态（颜色 / 字体 / 边框 / 悬停反馈）一律来自全局主题 —— 声明面没有任何外观键**。
- **声明写在哪里**〔源: `decisions.md` 7.60〕：模块**包内**的 **`view.json`**（与 `module.json` 并列；构建期「有它就拷进包」，**可选** —— 没有它的模块视图为空树，窗口照出）。**一个文件、两个顶层段**：**`frame`**（框架级个性化，只有几行：窗口尺寸 / 约束 · **网络标签默认位置**）与 **`sources` + `views`**（控件级完备声明：数据源登记 + 控件树）。声明里的 **`kind` 取 schema 的键名**（小驼峰，如 `textLog` / `commandButton` / `configurationEditor`），与 `ViewElementKind` 成员**一一对应**。
- **三件「唯一事实源」**〔源: `decisions.md` 7.60〕：① **树与语义** = 包内 `view.json`；② **默认值与约束** = 随框架程序集**嵌入**的 `view.schema.json`（逐键 `default` / `min` / `max` / `enum`；**代码零默认** —— 某键在 schema 里缺缺省值即判 schema 自身不完整，读取器报硬伤）；③ **外观** = **全局主题**（声明面**完全**没有颜色 / 字体键 —— 连「预留键」都不留：`frame` 段只有 `window` 与 `ports`；按模块的外观覆盖已明确**不做**）。
- **节点模型 = 4 容器 + 15 原子**：容器 = **`container`**（`layout` = `flow` / `grid` / `absolute`，`overflow` = `scroll` / `clip`）· **`group`** · **`tabs`** · **`collapsible`**；原子 = `numeric` · `curve` · `textLog` · `configurationEditor` · `commandButton` · `toggleSlider` · `toggleSwitch` · `textInput` · `fileSelector` + **6 个登记但尚未渲染**（`statusLight` · `table` · `hexView` · `gauge` · `image` · `enumSelector`：声明合法、报一条警告）。**声明面没有 `scroll` 这种 kind** —— 旧的独立滚动控件由容器的 `overflow` 表达（`ViewElementKind` 里的 `Scroll` 随载体切换一并删除，`Container = 19` 是声明面新增的排布容器成员）。**`padding` 缺省 0、`spacing` 缺省 2**。**容器的公共排布键**（`layout` / `overflow` / `padding` / `spacing` / `columnSpacing` / `rowSpacing`）**以 `container` 为基线**（schema 的 `containerBaseline.kind`）—— `group` / `tabs` / `collapsible` 是语义包装，**不重复声明**这些键（声明它们 = 硬伤）。
- **尺寸与位置**〔源: `decisions.md` 7.60〕：**每元素每轴一个尺寸对象** —— `width` / `height` = `{ "pixels" | "fill" | "adaptive", "min", "max" }`；**省略该轴 = 取 schema 的逐 kind 缺省**（宽度满宽；文本日志与多行输入的高度填满、其余随内容）⇒ 什么都不声明的模块拿到的是**与旧框架缺省一致的排布**。`absolute` 容器内两轴**必须显式 `pixels`**（配 `x` / `y` 定位，`scaleWithWindow` 缺省 `false`）；`grid` 容器内位置**必须显式** `column` + `row` 或 `"auto": true`（缺一个 / 两种写法混用 ⇒ **硬伤，整份忽略**），轨道写法 = `*`（等分）/ `N*`（权重）/ `auto`（按内容）/ `≥1` 数值（固定）。**越界的承担者 = `overflow: "scroll"` 的容器**（要滚动的绝对坐标内容放进它）。`feedbackSource` 把某输入源的结果搬到**本元素的角落信息区**；`showInlineResult: false` 关掉就地结果**文字行**（失败红框保留）。
- **绑定键按角色分名**：`data`（显示）/ `input`（用户写回）/ `command`（按钮触发）—— **每个控件只允许一个角色键**；名字必须先在 `sources` 里登记（**未登记 = 硬伤**；登记了没人用 = **警告**）。**命令不再有独立的命名命令表** ⇒ 命令**直接声明在按钮元素上**（名字 + 标题 + 图标）。
- **回退口径与门禁**：`version` 与 schema 的 `documentVersion` 不一致 · JSON 坏 · 任一条硬伤 ⇒ **整份忽略 + 一条 Issue**（不静默）；读取失败**不抛异常**。**打包门禁**校验包内**可选**的 `view.json`（能读、版本一致）。**不做**「用户在线调布局」、**不叠**用户覆盖层 ⇒ 也**不需要元素身份键机制**。**已知限制**：`tabs` 只渲染当前页（各页元素路径重合的旧限制随之消失 —— 路径键机制已整体删除）。

**目录规模与编号（以 SDK 声明面为准）**〔源: `ViewElementKind` 枚举（`Numeric=0` … `Collapsible=16`；**`Scroll=17` 已删除**；**末尾追加 `ToggleSwitch=18` 与 `Container=19`**）〕：

- **准确数量 = 19 项**：`ViewElementKind` 共 **19 个成员** = **15 个控件**（**A1–A8 数据呈现 8 项** + **B1–B7 交互控制 7 项**）+ **4 个容器控件**（**C1–C4**）。措辞口径见下条「控件（Control）——术语与 WinForms 对照」。
- **容器控件另算**：容器是枚举的**一等成员**（与控件同一枚举、可嵌套子控件），但在**分类上不与"控件"合并计数** ⇒ 现行表述 = "**15 个控件 + 4 个容器控件 = 19 项**"；旧表述"**18 个元素 + 4 个容器**"（`ADR-0028 §7` / `03a §8`）**不准确**（会读成 22 项），以上表（`03 §3.6`）与本条为准。
- **编号口径**：SDK 声明面用 **A/B/C 三类前缀 + 枚举序号**，逐项与上表 A1–A8 / B1–B7 / C1–C4 **完全一致**。`ADR-0040 D4` / `05 §5.20` 的 **"A10 开关 / A11 枚举选择 / `TextInput = 12`"** 是**连续编号**记法（把三类连排成 1–18），它与 SDK 的**枚举序号同值、与字母前缀不同**：`ToggleSlider` = **B3 · 序号 10**；`EnumSelector` = **B4 · 序号 11**；`TextInput` = **B5 · 序号 12**；`ToggleSwitch` = **B7 · 序号 18**（末尾追加，见下条）。
- **B7 `ToggleSwitch`（**2026-09 用户裁定新增**）**〔源: 用户"目前开关类的控件全部用的勾选框，我想添加一个开关式的滑块，更美观" · `decisions.md` 7.37 · `roadmap.md` §3 第 34 项 ⑤〕：**在枚举末尾追加**（`= 18`；其后又追加了 `Container = 19`）；**B3 `ToggleSlider` 的编号与语义不动**（仍属 CheckBox 形态；两者**语义相同、外观不同**）。
- **另一条轴不计入控件数**：数据源类型 `ViewDataSourceKind` 共 **6 项**（`Value / Sequence / RowSet / ByteBlock / Text / Frame`）——它描述"模块往里写什么"，与控件类型是两条轴。

### 控件（Control）——术语与 WinForms 对照 〔源: 用户 2026-09 裁定（术语标准化 · 沿用 WinForms 叫法）· `decisions.md` 7.37 · `roadmap.md` §3 第 34 项 ⑥〕

**命名规则（一个东西、两种称呼）**：**人类可读文本一律写「控件」**，容器类写「**容器控件**」；**代码里这棵树叫 `ViewNode`**（整份声明是 `ViewDocument`：节点的 `Kind` 是 schema 的**键名字符串**，渲染侧换算到 `ViewElementKind`；数据源类别用 `ViewDataSourceKind`）。⇒ **「控件」与 `ViewNode` 是同一物的两种称呼**：**人话 = 控件，代码 = 声明树里的 `ViewNode`**。容器控件同样是节点（靠 `children` 承载子节点）⇒ **本术语不新增任何 SDK 类型**。

- **旧类型名已随载体切换删除**（`decisions.md` 7.60，无兼容层）：`ViewElement` / `ViewDeclaration` / `ModuleViewLayout` 以及按路径打的几何补丁**整套不存在**；**保留**的是控件身份枚举 **`ViewElementKind`**（19 项；本轮载体切换中 `Scroll` 被删除、`Container` 新增，此后只增不减）与数据源类别 **`ViewDataSourceKind`**（6 项）。
- **一句话收敛**：文档中历史出现的「**元素**」「**视图元素**」「**构件**」与此处的「**控件**」**同义** —— 今后一律写「**控件**」/「**容器控件**」。

**WinForms 对照表**（左 = 本 SDK 的声明，右 = WinForms 叫法）：

| SDK 声明（`ViewElementKind`） | WinForms 叫法 | 备注 |
|---|---|---|
| `TextInput` | TextBox | 单行 / 多行（`Multiline`）由声明决定 |
| `TextLog` | RichTextBox（日志式只读） | 实际渲染是虚拟化只读行列表（见 `07`「A5 文本日志的"文本缓冲"口径」） |
| `CommandButton` | Button | 模块命令的触发点 |
| `ToggleSlider` | CheckBox | 勾选框形态（B3 原有语义） |
| `ToggleSwitch`（**新增**，枚举**追加在末尾**） | 开关滑块 | WinForms 无原生对应物，等价于 `CheckBox` 的"开关外观"；Avalonia 原生 `ToggleSwitch` 提供该外观 |
| `EnumSelector` | ComboBox | 枚举下拉 |
| `FileSelector` | **单个按钮**（文案 = 声明标题）+ 就地结果行（Open/SaveFileDialog 触发） | 弹窗在视图层，路径走输入通道；**2026-09 起不再有独立路径框**（见下条 B6 明细） |
| `Numeric` | Label（只读数值） | 数值展示（含单位标签） |
| `Gauge` | ProgressBar | 仪表/进度 |
| `Image` | PictureBox | 位图帧 |
| `HexView` / `Table` / `Curve` | 自绘（ListView / DataGridView / Chart 的等价物） | v1 目录内，实现时点见上条「v1 预置控件目录」 |
| `Group` / `TabPages` / `Collapsible` / `Container` | GroupBox / TabControl / Expander（Panel 自绘）/ Panel + ScrollViewer | **容器控件**（四者；滚动由 `container` 的 `overflow` 表达，不再是独立控件） |

**本表只对齐叫法、不改语义**：`ViewElementKind` 的成员名、序号、语义一律照旧（**变化仅三处**：末尾追加 `ToggleSwitch = 18`、`Scroll = 17` 随载体切换删除、末尾追加 `Container = 19` —— 见上条）。

### 视图的写入通道（人机操作三通道） 〔源: ADR-0040 D1–D4 + 05 §5.20〕

- 模块在视图声明里声明**命令**（名字 + 标题 + 图标）与**输入控件**；框架渲染按钮/输入框/开关。
- 人的操作**经变更入口投递**（`SendCommand` / `SubmitInput`），**在模块线程执行**（现行由模块在自己的活动体内消费，见「线程与投递」）；**不阻塞 UI、不跨线程直接调模块**；**未声明的命令/输入在变更校验阶段即被拒绝**（不静默）。
- 提交时机：**回车 / 失焦**提交输入（**不做逐字符写入**）；开关/滑块**只在松手时写入**（v1 不做"连续拖动即连续写入"）。
- 未知命令、执行抛异常 → 转 **Issue**，**不逸出**；重复点击**合并**（同命令已在待执行队列中则不再追加，语义 = "至少执行一次"）。
- **现行渲染子集 = schema 里 `rendered: true` 的 9 个原子**（`numeric` · `curve` · `textLog` · `configurationEditor` · `commandButton` · `toggleSlider` · `toggleSwitch` · `textInput` · `fileSelector`）+ **4 个容器 kind**（`container` · `group` · `tabs`（渲染**标签条** + 只渲染**当前页**）· `collapsible`；容器的边框与间距属框架固定项）；**6 个 `rendered: false` 的原子**（`statusLight` · `table` · `hexView` · `gauge` · `image` · `enumSelector`）**声明合法、但按"未渲染"占位**（声明即得一条警告，**不假装支持**）〔ADR-0040 D4/§5 · `05` §5.20 · `decisions.md` 7.60〕；控件编号以 SDK 声明面为准（见上条）。

- **B6 文件选择器（G4 · 2026-09）**〔源: 用户裁决"框架全做完再出模块页"· `roadmap.md` §3 第 12 项〕：**让用户挑路径**的输入控件（"保存文本 / 回放文件"这类需求）。

  | 项 | 约定 |
  |---|---|
  | **声明** | kind `fileSelector` + 数据源名（按角色键 `input`）；**三个 schema 键**：`fileMode`（`open`（缺省）/ `save` / `folder`）· `filter`（如 `*.txt` 或 `文本文件 (*.txt)\|*.txt`；空 = 不过滤）· `suggestedFileName`（**2026-09 只增**：保存对话框预填的默认文件名，如 `savetext1.txt`；打开模式忽略它） |
  | **值** | 产出一个**路径字符串** ⇒ 绑定到**文本型数据源**（`ViewDataSourceKind.Value`） |
  | **走哪条通道** | **与 B5 输入完全同一条**：用户选/存后经 `SubmitInput(实例, 源名, 路径)` 投递，模块在活动体里 `TryDequeueInput` 拿到 —— **模块不接触文件对话框 API**（弹窗与 `StorageProvider` 都属 UI） |
  | **渲染（2026-09 用户裁定改版 · `decisions.md` 7.53）** | **只有一个按钮**（文案 = 元素 `Title`）+ 其下一行**就地结果**；路径改在按钮的悬停提示里；落点确认由**模块**经输入反馈通道回投（模块才知道写盘成没成功） |
  | **收路径的前提** | 模块必须实现 `IActivitySource`（"无活动循环的模块不消费收件箱"，与 B5/B3 同一条限制） |
  | **修正** | 框架判定「哪些控件算输入控件」须计入 `FileSelector`（与 `TextInput`/`ToggleSlider`/`EnumSelector` 同列），否则声明了 B6 的模块收路径会被判「**模块未声明该输入**」而**拒绝** |
  | **输入反馈也适用于它**（2026-09） | 文件选择器与输入框**共用**输入反馈通道：模块回报成功/失败 ⇒ 按钮红框 + 结果行。**失败态与输入框同口径**（改边框颜色，不叠背景、不加图标） |
  | **只能人工验收的部分** | "**点那个按钮真的弹出系统文件对话框**"——无头环境没有真实对话框 ⇒ 该点归**人工验收**；自动化覆盖"渲染"与"提交被接受"两段 |
- **C2 标签页的声明结构与语义（G1 · 2026-09；**2026-09 修订见下条回读**）**〔源: 用户裁决"框架全做完再出模块页"· `roadmap.md` §3 第 12 项〕：kind `tabs` 的 `children` = **页节点序列**；**每个页节点的 `children` 才是该页内容**（页节点**自身没有子节点**时，把该页节点**本身**当内容 —— 两种写法都容忍，避免"切过去是空白页"）。页签标题取**页节点的 `title`**（空 ⇒ 回退为该页序号）。**只渲染当前页**。**切页仍不进组合件、不持久化**；**但"模块不感知"这半句已作废**（**2026-09 · `decisions.md` 7.28**）：选中页是**可被模块只读感知**的事实 —— 见下条「视图状态回读」。视觉取值见 `07`「模块窗口视觉规范」。
- **视图状态回读（2026-09 用户裁定"全部按推荐做" · `decisions.md` 7.28）**〔源: 用户"当前选中页似乎应该是一个**可被感知的属性**，这也有利于 **UI 整体简洁化**"〕：**框架把"视图状态"作为只读事实交给模块** —— 这是 Windows Forms 里"**控件属性即状态**"语义在本框架的落点（见下条对照表）。

  | 项 | 约定 |
  |---|---|
  | **可读的三样** | ① **某 `tabs` 的当前选中页** ② **某输入源的当前文本**（含用户**正在编辑、尚未提交**的内容）③ **某文本显示源当前保留的文本** |
  | **怎么读** | **拉取**：`Sdk` 只增 `IViewStateReader`，经 `IModuleContext.ViewState` 暴露；模块在**自身活动体**里读快照（与 `Inbox` 一样是"模块侧能力"，实现者需补实现）。**不做推送** —— 输入文本**逐键变化**，推进有界收件箱会被淹没 |
  | **怎么寻址** | 输入源 / 显示源用**数据源名**（已有）；容器（`tabs`）**没有数据源名** ⇒ 节点带一个可选的 **`stateKey`**（schema 公共键）。**不用 `title`** —— 那是给人看的展示文案，会被改文案的人无意改掉 |
  | **语义边界** | **只读**（模块不能改 UI 状态）· **快照**（最近一次框架写入的值）· **不进组合件、不持久化**（重启即丢 —— 与"开关不落盘"同一取向）· 未知/未声明 ⇒ `null` · **随实例移除清理** |
  | **为什么必须由框架持有** | 本框架的**控件表会在运行期重建**（切页 / 设置变更 / 重新声明）⇒ 状态若挂在**控件实例**上，重建即丢。**"不清空就一直在"要求状态独立于控件表** —— 这是与 WinForms 唯一必须显式不同的地方（WinForms 里控件实例活多久，状态就活多久） |
  | **它一次解决的问题** | 撤回"命令按钮关联输入源"（按钮 = 普通命令 + 回读）· 多标签消息（**一个按钮 + 页外共用控件**即可，UI 更简洁）· 转换器的"每方向一个按钮" · **读显示区文本做保存** · **切页不再丢未提交的编辑** |
  | **代价（已知情）** | 跨层新增面 5 处（`Sdk` / `Core` 状态存储 / `Hosting` 实现 / `Ui` 写入点 / 测试）；碰 `Sdk` 公开面 ⇒ **须跑一次 T3 + 重编全部模块**（`implementation/05` §2）—— 读数见 `roadmap.md` §6 |
- **与 WinForms 直觉的对照（2026-09 用户裁定：框架设计取向 · `decisions.md` 7.30）**：⇒ **语义一律向 WinForms 看齐，差异只有一处且必须显式**（差异来源 = WinForms 的窗口/控件/属性是**编译期确定**，而本应用是**运行期的声明和加载**）。

  | WinForms 里的东西 | 本框架的对应物 | 是否一致 |
  |---|---|---|
  | `new Form()` / `Controls.Add(...)` / 属性初值 | **加载期声明**：包内 `view.json` 的 `views[].root` 节点树（`children` 承载子节点）与 `sources[]`，模块加载时读一次 | **形似**：声明写的是"**有哪些控件、什么初值**"；差异 = **数据文件**而非代码，且是**加载期**而非编译期（插件式加载的必然） |
  | 控件**属性即状态**（`textBox.Text`、`checkBox.Checked`） | **读**：视图状态回读（上条）· **写**：`SubmitInput` / 命令（B3 开关也是提交 `true/false`） | **一致**：读得到、写得进；只是"写"走**通道**（跨线程、跨层）而不是直接赋值 |
  | 控件**存活期内持有自己的数据**（不清空就一直在） | **视图状态存储**持有（输入文本 / 选中页 / 显示缓冲） | **一致（本轮修的就是这条）** —— 状态**独立于控件表重建** ⇒ "切页 / 重新声明"不再丢内容 |
  | `textBox.Clear()` / `AppendText(...)` / `ScrollBars` | `clear` 之类的**命令** + 显示源**追加**样本 + 显示区**滚动回看** | **一致**：命令驱动清空、追加驱动增长、滚动回看 |
  | 事件（`Click` / `TextChanged`） | **命令** + **输入通道** + **回读** | **一致**：事件 → 命令；需要"当前值"时**回读**（不把值塞进事件参数） |
  | `Application.DoEvents()` / 消息泵 | **UI 刷新节拍**（60 Hz）+ 模块**活动体**（如 20 ms） | **形似**：两边各有节拍；**差异** = 框架不阻塞模块（缓冲满则丢旧并计数） |
  | 控件内存上限（无，靠内存兜底） | 显示缓冲**有容量上限**（防长跑 OOM） | **有意差异**：必须说清"到顶怎么办"（丢最旧 + 提示，见 `roadmap.md` §3 第 25 项） |
- **B5 文本输入的两种形态（G2 · 2026-09）**：schema 键 **`multiline`**（缺省 `false`）声明**多行**输入框。
  **提交键不属模块声明** —— 它是**应用级设置** `multilineSubmitKey`（三档：`CtrlEnter`（默认，回车换行 / Ctrl+Enter 提交 / 失焦不提交）· `Enter` · `None`），
  因为用户裁决"换行是极其常见的行为，且不同用户习惯不一样"（见《应用级设置》分册）。**单行输入行为不变**：回车 / 失焦一次提交（ADR-0040 D-5）。

- **多行输入框「不自动折行」是特性，不是限制**（**用户 2026-09 裁决**）：

  > 原文：**"该'限制'会带来一条显著优势：文本显示使用显式的换行符，不自动换行，换行代表文本结尾一定有一个换行符，
  > 可以保证发送信息的完整性，用户不用混淆'这里究竟是自动换行还是有换行符'……这对于上位机使用者来说是一个优点"**

  | 项 | 约定 |
  |---|---|
  | **所见即所发** | 多行输入框**不做视觉折行** ⇒ **画面上的每一个换行 ⟺ 文本里真的有一个换行符**。反之亦不允许出现"视觉折了行但文本里没有换行符"的歧义 |
  | **长行怎么办** | **横向滚动**，不折行（"文本框宽"不影响"文本内容"，正是保证上一条的手段） |
  | **框架不做规范化** | `SubmitInput(instanceId, source, text)` **原样投递**模块输入框里的文本 —— **不折 CRLF/LF、不去尾部换行、不追加换行**（框架不替模块决定内容的边界） |
  | **行尾用什么由模块定** | **`CR` / `LF` / `CRLF` 属模块语义**（模块自己的配置项），框架不猜、不统一 |
  | **与显示控件的分工** | **输入 = 所见即所发**（不折行）；**只读显示（A5 文本日志）可为便于阅读而折行** —— 两者语义不同，不得互相类推 |
  | **实现注记** | 不折行同时避免了自造 `IValueConverter`（本项目只用内置 `StringConverters`，且 `Ui` 的 VM 一律不引 Avalonia 类型）—— 但**这不是它成为特性的理由**，理由见上表第一行 |
- **网络标签（端口）的声明面：声明每个口的落点（G5 · 2026-09；载体见 `decisions.md` 7.60，端口边口径见 **7.61**）**〔源: 用户裁决"框架全做完再出模块页"· `roadmap.md` §3 第 12 项 / 第 57 项 · `decisions.md` 7.13/7.14/7.18/7.19〕：模块在 `view.json` 的 `frame.ports[]` 里给每个口**声明挂哪条边、在边的哪个位置**（**不参与**建网 / 兼容 / 停流 / 投递 / 计量 —— 纯呈现）。

  | 项 | 约定 |
  |---|---|
  | **声明口径** | `frame.ports[] = [{ "name": 口名, "edge": "left" / "right" / "top" / "bottom", "offset": 0…1（缺省 0.5）}]`；`name` 与 `edge` **都必填**。`edge` **没有 `auto`、没有框架惯例** —— 数据面登记的口必须在 `frame.ports[]` 里**各有一条**（缺一条 ⇒ 硬伤、整份忽略），`.json` 写什么就是什么（**2026-09 复裁**，见 `decisions.md` 7.61）。`name` 要与数据面登记的口名对得上（对不上 = 读取时一条提示）。**只此一项** —— `label` 与可拖动性**不是**声明项 |
  | **有效位置** | **用户拖动覆盖 > 包内声明的值**（**唯一解析**；呈现 / 建网判定 / UI 吸附三处共用）。用户覆盖随组合件保存（组合件的 `edge` 字段；用户**没拖过**时写 `auto` = **存储哨兵**、不是声明面的取值 ⇒ 解析时回落到声明值）。**它参与两件事**：① 呈现（标记贴哪条边、横排还是竖排）；② **建网判定** —— "接触且对齐"要求端口挂在**朝向接触面**的那条边上（**2026-09 增补**，见 `05` §2 的七条表）⇒ 用户拖动"可到任意边"因此**真正可用于建网**（发送口拖到下边缘 + 接收口拖到上边缘 ⇒ 上下相邻也能连） |
  | **可拖动性属框架固定项** | 标记几何（长 150 / 宽 20 / 端头留白）与**是否可拖动**都**不再由模块声明**（旧 `PortDeclaration.AnchorDraggable` 随载体切换删除）；用户的固定 / 解锁是**用户侧事实**（随组合件保存） |
  | **「固定」的层次** | 用户设置（拖动 / 单口按钮 / 全局快捷键，`decisions.md` 7.19）> 框架缺省：用户没设置过 ⇒ 用缺省（且 `locked` 字段**缺省不写**）；用户设过 ⇒ **覆盖**并落盘 |
  | **用户入口** | ① 标记**内侧空白带**里浮出的**图标按钮**（悬停该标记时淡入，点击 = 固定/解锁该口）② 全局快捷键 **Ctrl+P**（切换全部模块的所有口）。**模块不碰 UI**：两端都走 `Core.Api` 的锚点变更操作 |
  | **「固定」≠「锁定」** | 「固定」= 锚点不可拖动（模块拉伸时按比例重排 —— `Offset` 归一化天然如此）；「**锁定**」只属**模块窗口**（不可移动、不可缩放）。用词一律「固定」（`decisions.md` 7.14） |
  | **非强制开发约定** | **宽 > 高的模块建议把口放上下边、高 > 宽的放左右边** —— 只是约定，框架**不据此判定任何东西** |

- **B5 文本输入的"文本类型"与对齐（2026-09 · 用户裁定"不使用新控件而是扩展它"）**：给已有控件**加字段**，不新建控件（数值输入与文本输入走**同一条通道、同一套提交语义**，差别只在放行哪些字符 ⇒ 新建控件会让目录撑大而语义重复）。

  | 项 | 约定 |
  |---|---|
  | **声明** | schema 键 **`inputKind`**（`text`（缺省）/ `number` / **`hex`**（2026-09 只增，见 7.26））与 **`textAlign`**（`default`（缺省 = 框架惯例：左）/ `left` / `center` / `right`）—— 都是声明面键、缺省写在 schema 里 ⇒ **不声明即用缺省** |
  | **`Number` 做什么** | 输入框**只放行数字写法**：数字 · 一个小数点 · 首位负号（框架构造"插入后的文本"用 `^-?[0-9]*\.?[0-9]*$` 校验；`TextBox.invalid` 之外的**字符级拦截在隧道阶段**）。**允许中间态**（空 / `-` / `1.`），否则用户没法把数打完 |
  | **`Hex` 做什么** | 只放行十六进制写法：`0-9A-Fa-f` **+ 空白**（空格 / 换行 / 制表符）—— **空白只是排版**（"HEX 里的换行不是字符"），其余字符**根本不进框**（与 `Number` 同一手法）。**是否成对、长度奇偶、是否合法字节序列一律归模块**（输入反馈通道 ⇒ 红框）；**大小写不规范化**（原样投递，模块自己决定怎么看） |
  | **框架只判"格式"** | **范围 / 是否整数 / 业务合法性一律归模块**（模块用输入反馈通道回报 ⇒ 红框）—— 与"可声明 ≠ 可判定"同一纪律；**投递的仍是文本**（输入通道签名是 string）⇒ **不新增通道** |
  | **`Alignment` 由模块声明** | 对齐属**视觉组织**，框架不替模块限死（用户原话："如何对齐由模块自己去声明，有利于视觉组织"）。**当前消费方只有 B5**；其它控件声明了不生效（渲染子集逐步补齐） |
  | **单位不在控件上** | 输入框**不做框内单位后缀**（用户裁定："容易给人一种'这里单位可以改'的错觉"）⇒ 单位用**框外标签**呈现，来源 = 该输入源在 `view.json` 的 `sources[]` 里声明的 `unit`（模块不为此多声明字段） |
  | **当前不支持** | 科学计数法（`1e3`）：需要时再放宽（放宽属兼容扩展 —— 只增放行字符） |

- **渲染与投递的其余细节**见「线程与投递」与《UI 外壳与窗口》分册。

### 模块默认尺寸 〔源: ADR-0041 D6〕

`view.json` 的 **`frame.window`**（`width` / `height` / `minWidth` / `minHeight` / `maxWidth` / `maxHeight`，后两个可缺省）声明窗口尺寸与约束；**省略即取 schema 的缺省 = 320×220、最小 180×160**（上限缺省 = 无）。**框架地板 = schema 里 `window.minWidth` / `minHeight` 的缺省值**（180×160，由端口标记沿边长度推出）：声明的下限**只能抬高地板**，写小了由读取器**夹到地板并记一条 warning**（不是硬伤）；实例整份声明不可用（硬伤 / schema 加载失败）时宿主给按地板填好的兜底文档（`ViewDocument.Fallback`）⇒ 渲染侧不再夹、也不自带任何地板或默认尺寸字面量（`decisions.md` 7.63）。旧的 `ViewDeclaration.PreferredWidth` / `PreferredHeight` 已随载体切换删除（`decisions.md` 7.60）。**现行四个正式模块的声明值**见 `architecture/07`「模块窗口视觉规范」的默认尺寸行。

### 扩展性（C1-3 的三条硬后果） 〔源: 03a §2 + architecture/03 §3.6〕

- **没有"自定义视图"逃生口**：目录里没有的呈现形式，模块作者无法自己写——只能等框架升级或走 ADR 推翻"模块不得依赖 UI 框架"。
- **UI 表达力的增长路径只有框架版本升级**：第三方无法贡献 UI 控件（贡献 UI 控件必然要引用 UI 框架）。因此**初始目录的完整度比一般框架更关键**。
- **新增控件属兼容扩展；删除或改语义属破坏性变更（须 ADR）**。

## 框架服务面：模块如何与框架交互 〔源: architecture/03 §3.8 + §3.10.1 + §3.10.2 + ADR-0040〕

模块**不持有框架对象引用**，只通过框架在实例化时提供的**上下文**使用服务：

| 服务 | 用途 | 约束 |
|---|---|---|
| 上报：Issue | 模块发现的可呈现问题（归属对象 + 类别 + 描述） | **模块业务状态不入 Issue** |
| 上报：日志 | 模块诊断经框架汇集（可观测性） | 分级 + 来源；默认轻量不打扰 |
| 上报：业务状态 | 模块自报业务状态（框架只登记/呈现） | 框架**不解释业务语义** |
| **上报：输入处理结果**（G3） | 让"**处理失败**"在**对应输入控件**上可见（框架渲染失败态）——`SubmitInput` 的 `CommandResult` 只反映投递是否入队，**不反映模块处理结果** | 按**输入源名**（该节点的 **`input` 角色键** / `feedbackSource` 指到 `sources[]` 里的名字）定位；**只呈现**、不解释语义；**下一次提交即刷新**（框架在投递入队时清旧结果）；`Report` **不抛**；命令侧回显另按 `feedbackSource` + `showInlineResult`（缺省 `true`）声明 |
| 配置读写 | 读当前配置、写回配置 | 写回触发配置变更通知路径；还原 = 替换为同类型新默认实例 |
| 活动承载登记 | 声明模块需要被承载的活动 | 承载与调度在 L3 |
| 发送 API / 订阅写入 | 模块产出数据、写订阅缓冲供 UI 读 | 具体线程与缓冲规则见「线程与投递」 |
| 收件箱（`IModuleContext.Inbox`） | 接收命令与输入 | 见「线程与投递」 |

**方向纪律**：模块 → 框架为"上报/请求"；框架 → 模块为"生命周期钩子 + 投递回调"。模块**不得**反向查询其他模块是否存在、**不得持有其他模块实例**。

**关于"连接建立/拆除服务"**：连接（网络）的**建立/拆除由用户在 UI 声明、由 L4 执行**，**模块不参与、也不可见**——模块无法请求"把我和某个模块连起来"。正确理解：**数据通路由框架建立并保证直通，模块侧只需实现接收回调与发送 API**。

**成员统一路径的四阶段 → SDK 载体**：

| 阶段 | SDK 载体 | 框架侧动作 |
|---|---|---|
| ① 声明 | 特性 + 口/配置/视图声明类型 | 加载期反射读一次 → 不可变元数据 |
| ② 实例化 | 框架调用模块入口（构造 + 注册成员） | L2 创建实例与成员实例表（口实例 / 值槽 / 视图宿主） |
| ③ 存取·连接 | 上下文服务：配置读写、发送 API、订阅写入、上报 | L4 建网与绑定；L3 投递；UI 经订阅缓冲读取 |
| ④ 表现 | 视图声明（控件组合 + 数据源） | L5 按声明渲染；**口上标记与网络标签由框架绘制** |

**模块实现来源（v1）**：**原生代码（C#）是唯一实现来源**；**脚本 ❌**（v1 不引入脚本宿主，"脚本宿主可选"在 v1 **不实现**，未来引入须新 ADR）；**组合件作为模块实现来源 ❌**（组合件是**持久化/复用载体**，不是模块实现来源；未来若支持需新 ADR + 定义"组合件发布为模块"的装载语义）。

**安全一致性**：模块包的能力声明（网络/串口/文件）由 manifest 承载，加载时**透明提示**（不拦截）；**组合件永不自动执行代码**（加载组合件只重建声明结构）。

## 线程与投递（模块视角） 〔源: 04a §6 + architecture/04 §4.1 + ADR-0029 · ADR-0050 Q2 · ADR-0040 + 04a §5.2〕

**执行模型 = 每活跃模块实例一个框架分配的线程 + 有界队列**（用户裁决）。结构：

```text
每个 Active 的 Module Instance
  ├── 1 个专属线程（由 L3 创建/管理/回收；模块不自建线程）
  ├── N 个有界输入队列（每 (实例,口) 一条；容量与丢弃策略按口声明）
  ├── 1 个停止信号（框架设置 → 模块应尽快退出活动体）
  └── N 个订阅缓冲（供 UI 读取）
```

| 框架状态 | 线程 | 队列 |
|---|---|---|
| `Registered` | 无（**不占线程**） | 无 |
| `Active` | 分配并启动 | 接收投递（每口一条） |
| `Disabled` | **保留** | **停流**（投递暂停，绑定保留） |
| `Removed` | 请求退出 → 有界等待 → 回收 | 销毁（全部口的队列一起清空） |

模块侧必须遵守的约束：

- **模块不自建线程/定时器**；线程归模块使用 ⇒ **活动体内允许自由阻塞、循环、同步 IO**；阻塞只影响它自己（隔离语义）。
- **停止协议**：框架设置停止信号 → 有界等待（默认 5 s，可配置）；按时返回 = 正常回收；超时 ⇒ 记 Issue（"模块未在期限内停止活动"）+ 标记孤儿线程。**框架不假装能强杀模块**（.NET 无安全线程中止），超时后**不释放**队列/缓冲/池（交给 GC），仅释放已确认安全的外部资源；**模块内部资源由模块自己的 `OnRemoved` 释放**。
- **队列语义**：每 (实例,口) 一条（消除跨口队头阻塞）、默认**丢最旧保最新**、**v1 不做背压、绝不阻塞发送方**；丢弃与"停流未投递"**分账、不得混算**。
- **UI 从不调用模块代码**：模块写订阅缓冲，UI 按刷新节拍读；UI 慢只丢旧，永不阻塞模块。

### 人机操作（命令 / 输入 / 开关）的投递 〔源: 05 §5.20 + architecture/14 §9.2 + roadmap v1.21；对照 ADR-0040〕

**现行实现（已落地）**：命令与输入**一律投递到 `IModuleContext.Inbox`**（`IModuleInbox`：`TryDequeueCommand` / `TryDequeueInput`），由模块**在自己的活动体内消费**——框架**不跨线程调模块**；收件箱**有界（64）**、满则**丢最旧并计数**；投递成功/失败都进 `CommandResult`（Notice / Failures）→ 界面就地显示 + 状态栏提示。

**已登记限制（不是静默降级）**：**无活动循环的模块不消费收件箱**（投递入队、框架不代执行）；v1 的四个正式模块均为活动模块。

**口径（已裁定 · 收件箱拉取式为准）**：模块侧**唯一**的人机操作入口 = `IModuleContext.Inbox`（`IModuleInbox.TryDequeueCommand` / `TryDequeueInput`），由模块**在自己的活动体内取**；**框架不跨线程调模块**。**`IModule.OnCommand` / `IModule.OnInput`（推送式）作废** —— 模块作者**不需要、也不应**实现这两个回调。**ADR-0040 的推送式条款（D1/D2）已不适用**（实践已由收件箱取代；历史见归档）。

**仍然有效的语义（不因通道形态改变）**：① **命令合并** —— 同命令已在待执行队列中则不再追加，语义 = "**至少执行一次**"；② **失败转 Issue** —— 未知命令 / 执行抛异常 → **Issue**，**不逸出**、不静默；③ **输入一次提交** —— 回车 / 失焦提交（**不逐字符写入**），开关/滑块**只在松手时写入**。见「视图的写入通道」。

收件箱**容量 64**、满则 **丢最旧并计数**（`DroppedCount`）、`EnqueueCommand` **不做去重** ⇒ **"命令合并"这一条在实现侧尚未落地**（现行为"重复点击 = 重复入队，队列满则丢最旧"）。此项属**实现待补齐**，不改写本分册的设计语义。

### 接收模式：被动接收是现行推荐，主动接收有已知代价 〔源: 04a §5.2（裁决）+ §5.1〕

| 接收模式 | 实测（同两跳链 A→B、同契约、单单元） | 现行口径 |
|---|---|---|
| **被动接收**（模块只注册接收处理器，由**框架投递循环**驱动） | **893 ns** | **推荐形态**；**裁决 = 参考桩模块改用被动接收**（现行等价载体见 `09` §2 的判据载体表） |
| **主动接收 + 用停止信号当轮询间隔** | **15.70 ms** | 不采用：`IStopSignal.Wait` 的语义是"等**停止**信号"，被当成"等数据"用 ⇒ 每次空转等满超时，而 Windows 定时器分辨率 **15.6 ms**；把停止信号换成 `ManualResetEventSlim` **解决不了**（数据到达不会唤醒它） |
| **主动接收 + 自旋轮询** | **781 ns** | 快但**占一个核**；低频场景不值得 |

- 结论：**被动接收路径没有该问题**；主动接收在**连续流**下无影响，**低频**下退化到定时器粒度。
- **`WaitForData` 属后续 SDK 兼容扩展项，不是 v1 交付**（让主动接收也能微秒级且不占核；新增成员 + 回写本分册与《运行时机制》分册）。

## 模块包与发现 〔源: architecture/12 §1 + ADR-0036 D1–D4 + architecture/03 §3.7〕

| 项 | 现行约定 |
|---|---|
| 基数 | **1 个模块包 = 1 个 Module Definition = 1 个模块实现**（v1 强制，不允许一包多模块）；Registry 登记粒度 = 包粒度 |
| 物理形式 | 1 个包 = **1 个目录**：`module.json` + 实现程序集 + 依赖；目录内必须**同时**有 `module.json` 与 `entryAssembly` 指定的程序集 |
| 包从哪来 | **构建即归拢**：模块项目构建后自动归拢到 `artifacts\modules\<包名>\`（先清空该包目录再复制），框架 `App` 构建后再镜像到 `<应用输出>\modules\`——**作者不需要手工拷贝、不需要改任何脚本**（新增模块项目零改动，包名由项目属性推导） |
| 应用从哪找 | 设置项 **`moduleSourceDirectories`（有序根列表）**，默认只含 `<应用目录>\modules`；按顺序逐根扫描，每根只扫**直接子目录**中含 `module.json` 者；**不递归、不猜、不扫任意位置**（"用户可见的声明根"取代"任意位置"） |
| 重复时怎么办 | 同 ID 同版本：**先到者胜**（后者记 **Info**，不刷 Warning）；同 ID 不同版本：**共存**（目录按模块名聚合，默认取**最新版本**） |
| 显式加载 | 保留原有的"选择…加载"路径（声明根只是自动发现通道） |
| 重扫 | 启动自动扫描 + 界面「立即重扫」（`RescanModuleSources`）：**只发现新增包**；已载入程序集不可替换 |
| 诊断 | `GetModuleSources()`：每根的路径 · 扫到/跳过/失败计数 · 逐包结果（成功/失败原因）· "该包在本次启动后被重新构建"的提示；界面提供「打开目录」「立即重扫」 |
| 加载失败 | 失败 = Issue，且**不影响既有运行** |

**模块包生命周期的其余口径**：

- **更新**：新版本作为**新增注册项**（不覆盖旧版本）；既有实例**保持**原版本继续运行；用户可手动把实例切到新版本（版本迁移路径属后续 Gate）。
- **移除**：注销注册项；**已实例化的在用实例不强制卸载** → 进入**缺失态**（占位保留配置与网络成员 + Issue）；**程序集不主动卸载**。
- **重锚**：组合件记录实例的 ID 三元组（含版本），加载时按版本重锚；版本不兼容 → 缺失态 + Issue。

### 开发期行为：热重载**不做** 〔源: ADR-0036 D4 + architecture/12 §1.5〕

- **不实现热重载**（不做可卸载 `AssemblyLoadContext`，**不列入后续里程碑、也不留待办**）。固定语义：**改模块代码 → `dotnet build`（包自动归拢）→ 重启应用**。
- 唯一保留的便利：重扫时若包目录/文件的写入时间**晚于本进程启动时间** → 记一条 Info，并在模块清单标出"**该包在本次启动后重新构建，重启应用才生效**"（成本 = 一次时间比较，不引入任何重载机制）。

## 验收面：模块契约测试套件 T6 〔源: architecture/06 §T6 + ADR-0028 影响 + architecture/03 §3.10〕

- **T6 = 独立测试包**（`HYWDebugAssistant.Sdk.Testing`，以包分发以避免污染 SDK 的零依赖约束）：提供 `ModuleContract` 契约自检 + 模块级测试上下文；**提供且推荐（不强制）**。自检覆盖：**声明完整性 / 原语目录合法性 / 钩子实现 / 无跨模块引用**（含"故意写坏"的反例）；`ModuleContract` 的 `Problems` 语义是"**空 = 合法**"，建议走独立通道 `Advisories`。
- SDK 支撑的 AC 判据：**AC-1**（新模块零改动接入：作者只引 SDK，六项声明 + 入口接口足以接入）· **AC-2**（隔离/异常不逸出：钩子与回调异常纪律 + 上报通道）· **AC-4**（保存/加载无损往返：配置未知字段保留 + 契约具名引用）· **AC-5**（无隐藏耦合：不引其他模块与框架内部）· **AC-6**（对未知类型开放：契约 = 受控原语组合，新形状不改框架）。
