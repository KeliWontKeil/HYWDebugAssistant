# 03 数据协议与类型

> 网络/建网语义（建网两机制、口两态、多源 N:M、顺序等级、薄旁路头、计量四档与丢弃三类）见《网络语义》分册；本册只写**数据类型与协议本身**。
> 模块声明面的用法（特性/反射/钩子/结构化 ID）见《模块 SDK》分册；本节涉及的声明字段只写**数据类型相关**的部分。

## 1. 数据单元：一个单元 = 一个定长数据报 〔源: ADR-0046 D3/D7 + ADR-0050 D1 + 04a §3.1/§3.5/§6〕

| 项 | 定稿 |
|---|---|
| **形态** | **v1 只定长**：一个数据单元 = 一个**定长数据报**（长度 = 契约尺寸）。**不引入变长**，**不做分片** |
| **批量** | **批量 = 定长数组 `T[N]`**，**由类型声明**（`SamplesPerUnit`）；**不做框架自动合并**——自动合并会改变时序语义且难以调试 |
| **数组语义** | `f32[8]` 是"8 通道"还是"批量 8 个采样"由类型声明，**与计量块 `ChannelCount` 合并定义**（不设两处定义）——这是曲线/多通道显示**画对**的前提 |
| **物理表示** | **扁平池化定长缓冲**（跨线程、排队、丢弃、可零拷贝移交）+ **加载期特化访问**：为每个已注册契约生成①字段偏移表（供框架通用读写/兼容判定/诊断）②强类型访问器（供模块按类型读写，无反射、无装箱） |
| **尺寸何时已知** | 定长契约 ⇒ **每个单元的大小在加载期已知且恒定** —— 这是零拷贝切片、队列按字节计数、订阅缓冲按样本开槽的前提 |

### 1.1 数据面性能基线（实测 · 只记录、不设阈值 · 04a §5.1）

> 环境：i9-13980HX / Windows 11 24H2 / .NET 10.0.12 / Release；数据单元 = 参考模块的 **12 字节** `{seq: u64, value: f32}`。

| 项 | 实测（均值） |
|---|---|
| 同线程直调拷贝（基线） | **2.37 ns** |
| 池化缓冲 借 + 还（含归属断言） | **16.8 ns** |
| 纯队列 入队 + 出队 | **34.7 ns** |
| 一次完整投递（借 + 拷 + 入队 + 出队 + 归还） | **54.4 ns** |
| 三跳端到端·连续流 | **1.82 µs** |
| 吞吐·1 生产者 | **≈3.2 M 单元/秒** |
| **投递路径每单元分配** | **40 B/单元**（订阅写入路径 **0 B**）——`Rent` 每次 `new` 包装对象；用户裁决为"**池化包装对象**"，落地前**文档承诺以本实测为准**，完成后回写为 0 |

## 2. 解析三段式（边界写死） 〔源: ADR-0046 D1 + 主文档 §5.4.1 + 18 §8.8〕

| 段 | 归属 | 内容 |
|---|---|---|
| ① **声明期读取** | **框架必做** | 注册/实例化时**一次性**读取模块提供的元数据（端口、契约/类型引用、视图、能力、计量块、解码器）；销毁时注销。**运行期不重读**（热重载按既有"重扫/需重启"规则） |
| ② **传输期解析数据流** | **框架禁止** | 框架**不读数据内容**：投递按**绑定** + 仅校验**长度**（`payload.Length >= layout.SizeInBytes`）；**转发与建网用的是声明，不是包内标签** |
| ③ **呈现期解码** | **模块负责** | 把样本字节变成"可显示值"的解码器**由模块提供并注册**；**框架只回调**，不内建、不理解结构 |

**两条纪律**：① **框架永不内建业务解析器**；② **声明只在注册/实例化时读一次**。

**落地（现行）**：`DataTypeDeclaration.Decoder`（`SampleDecoder`，声明面在 `Sdk`）⇒ 数据源用 `ViewDataSource.Type` 引用类型 ⇒ 框架把**模块的解码器句柄**经 `SubscriptionSourceView.Decoder` 交给呈现层（框架只回调）。**唯一改造点已完成**：`Ui/Runtime/SampleCodec`（框架内建解码）**降级为参考实现**（只服务未声明类型的旧模块，登记为历史兼容路径）；`Sdk` 另提供 `PrimitiveSampleDecoder` 供模块直接注册。〔源: ADR-0046 §5 第③步 + 18 §8.8〕

**回归判据**：传输期**字节守恒**（投递字节 == 模块产出字节、单元数不变）；**通用路径不得调用内建解码器**（`SampleCodec` 不出现在框架路径，T1 + 静态检查）。〔源: ADR-0046 §6〕

## 3. 数据面边界：谁在数据面之外 〔源: ADR-0046 §4 + 17 §1〕

| 层 | 管什么 | **不管什么** | 必须携带 | 谁校验 | 允许的解析 |
|---|---|---|---|---|---|
| **传输 / 数据面** | 能不能传：尺寸完备性 + 投递 + 顺序 + 背压 + 丢弃 + 缓冲 | 数据"是什么" | **类型标识 + 版本 + 尺寸 + 传输语义 + 兼容声明** | 框架（机械：长度/尺寸/兼容） | 只有 ①② |
| **应用 / 模块语义** | 数据是什么、怎么解析、单位、量程、精度、建议采样率 | 传输细节 | 语义元数据 + 解码器 | **模块自己**（框架不解释） | 模块执行（框架只回调） |
| **呈现 / 框架 UI** | 拓扑 · 连接 · 数据角色 · 传输级指标 · 错误 | 应用语义 | —— | 框架 | 只读框架自有数据（计数、绑定、几何） |
| **模块自身 UI**（按声明渲染） | 该模块要让用户看的业务内容（数值/曲线/日志 + 单位） | —— | 视图声明（元素 + 数据源 + 单位） | 框架照声明画（**值由模块解码器产出**） | 调用模块注册的解码器 |

**三条推论**：① 尺寸属传输层、**语义不属传输层**（框架必须知道尺寸：零拷贝按偏移切片、队列按字节计数、订阅缓冲按样本开槽）；② 框架**无资格**判断"是否同一种量"（不懂单位/量纲）；③ 模块的**数据角色**由框架派生/由模块声明，**只用于呈现**——不参与建网、兼容、停流、投递、计量。〔源: 17 §2/§3.2 + ADR-0046 D8〕

## 4. 统计 vs 附加：框架对数据单元只统计、不附加 〔源: 主文档 §5.4.2 第一/三条 + ADR-0046 D4/D5 + ADR-0050 M4/Q6(c)〕

| 项 | 定稿 |
|---|---|
| **不附加** | 框架**不往数据单元附加任何元数据**（时间戳 / 序号 / 来源标识）：**投递字节 == 模块产出字节**（字节守恒），无每单元构造开销 |
| **包不自描述** | 数据包**不带类型标签**；框架按**声明**（端口 + 绑定）路由 |
| **框架侧只做统计** | 框架侧记录**投递计数 · 最后数据时间 · 间隔统计**（供速率/抖动）；**"序号" = 框架侧累计计数，不写入单元** |
| **模块要时序就自带** | 需要"采集时刻/序号"的模块 ⇒ **在自己的契约形状里声明字段**（如参考模块 `{seq:u64, value:f32}`）；框架可另记**接收时刻**用于自身统计 |
| **例外（仅多源网络）** | `DatagramHeader{源实例ID · 源口名 · 按源序号 · 接收时刻}` 随单元**旁路**携带（`InboundUnit.Header`，**不进 payload 字节流 ⇒ 字节守恒不变**）；**单源网络为 `null` ⇒ 零附加**（不构造、不入队、不读取）。**消费者 = 观测面**；**模块仍不通过它取来源**（要来源就自带字段）；头**不进契约**（兼容判定只看形状） |
| **来源的处置** | 数据面**不暴露来源**（"来源随接收回调提供"的旧口径已撤回）；要显示多源从**绑定模型**取 |

**读取纪律（防御，保留）**：**到达的数据报长度 = 发送方的契约尺寸**（框架**不投影、不补零、不截断**）；新兼容规则下这已**恒等于本口契约尺寸**，接收方仍应**按到达长度读**——SDK 提供 `PayloadReader.TryCreate(payload, layout, out reader)`（长度不足返回 `false`，不抛）；用**自己的**契约硬构造 `PayloadReader` 在长度不足时会抛异常，而**实测后果是该模块的投递循环整体退出**（只留一条写着"活动体异常"的 Issue，文案与真实原因不符，已知）。〔源: 主文档 §5.4.1 + ADR-0051 D3 + 18 §8.10〕

> 计量口径的**分档明细**（四档速率 / 三类丢弃 / 队列水位）与顺序保证等级归《网络语义》分册；本册只定"**框架侧只统计、不附加**"这条界线。

## 5. 契约形状 `ContractShape`（形状即契约） 〔源: 16 §1 + 主文档 §5.4.1 + 03 §C3-5 + ADR-0051 D1 + implementation/02 P48〕

- **形状 = 原语 / 定长数组 / 结构**（成员名 + 类型 + **顺序**），**定长**，有 `SizeInBytes`；`ContractShape.Describe()` 生成 `f32`、`{seq:u64, value:f32}` 这类**文本**（用于呈现，**不是类型身份**）。
- **形状的字母表（v1 原语目录，只能在目录内组合）**：定宽有符号整数 `i8/i16/i32/i64` · 定宽无符号整数 `u8/u16/u32/u64` · `f32/f64` · `bool` · **定长字节块**（长度 1–256）· **定长数组**（元素为上列原语，长度 1–256）· 上述的**结构组合（嵌套深度 ≤ 4）**；**无变长**（字符串/序列由定长数组 + 长度字段自行表达）。加载期由框架反射校验成员类型。
- **契约语言三层能力**：① 传递语义标注（流 / 消息 / 事件）② 受控基础形状原语目录 ③ 组合与签名——**成员序列（名称 + 原语类型 + 顺序）= 签名**；契约可**具名引用（类型注册表）或内联**。
- **"形状完全一致"的含义**：字段**名称** / **原语种类** / **数组与字节块长度** / **字段顺序** / **字段数量** 全同 ⇒ **尺寸必然相同**。
- **形状比较必须是结构比较**：形状是 record，但结构形状的**字段集合**在 record 默认相等里做的是**引用比较** ⇒ 必须用 **`ContractShape.AreSame`**（逐字段比较），否则"两个模块各自构造的同一形状"会被判不相等（**只有引用同一静态实例才连得上**——隐形陷阱，测试里恰好都引用同一实例所以全绿也没发现）。**通用规则**：值语义类型里含集合/数组/字典时 record 的 `==` 不可靠，需要值语义就自己写比较并配专门用例。
- **传递语义 `TransferSemantics` = `Stream` / `Message` / `Event`**（已有，属传输层，**参与兼容判定**：跨语义**不判兼容**，组帧由模块内部自理）。

## 6. 类型注册与机械镜像 〔源: ADR-0046 D2 + 18 §8.8/§8.9 + 17 §3.1〕

```
模块侧：类型定义 = 标识 + 版本 + 尺寸（定长形状） + 传输语义 + 计量块 + 解码器 + 语义元数据（展示用）
             ↓ 注册（声明期一次）
框架侧：类型注册表条目 = 标识 + 版本 + 尺寸 + 传输语义 + 兼容声明   ← 只做机械判定，不解释语义
```

| 项 | 定稿 |
|---|---|
| **声明方式** | `IModuleDeclaration.DeclareDataType(DataTypeDeclaration)`；口用 `PortDeclaration.Type` 引用（**`init` 属性 ⇒ 二进制兼容**）；数据源用 `ViewDataSource.Type` 引用类型 |
| **框架侧** | **机械镜像** = `ModuleInstance.DataTypes`，按**（标识, 版本）**索引；**不解释语义**（**可声明 ≠ 可判定**） |
| **跨模块复用** | 跨模块必须**引用同一标识**（可扩展性落点），而不是各自内联一份结构 |
| **旧模块（不填标识）** | 回退为**结构哈希**（向后兼容，旧模块零改动） |
| **引用未声明类型** | 报 Issue 并**回退结构比较** |
| **重复声明同（标识,版本）** | 报 Issue 并**忽略后者** |
| **驱动注册表而非"契约目录"** | 主文档 §5.4.1 的"契约可具名引用（契约目录）"即此注册表的细化落地 |
| **参考类型库** | `Sdk.Contracts.CommonDataTypes`：`hyw/*` 标准类型的**声明常量 + 形状 + 解码器**（`hyw/analog-sample@1` = `{seq:u64,value:f32}`、`hyw/f32@1`、`hyw/u64@1`），模块**直接声明**即可——避免各模块各写一遍导致"同标识不同形状"的**假不兼容**；**注册动作仍由模块自己做** |

**契约自检（`ModuleContract` 数据类型检查）**：标识/版本合法 · 同（标识,版本）不重复 · **口与数据源的引用必须能在本模块解析**（否则会静默回退结构比较） · 计量块自洽（`SamplesPerUnit`/`ChannelCount` > 0、`PayloadSizeInBytes` ≤ 契约尺寸）。〔源: 18 §8.9〕

## 7. 兼容规则：形状完全一致 〔源: ADR-0051 D1/D2/D3 + 主文档 §5.4.1 + 18 §8.8〕

| 情形 | 判定 |
|---|---|
| **双方都声明类型**：同标识 + **同版本** + **形状完全一致** | ✅ **兼容** |
| **同标识 + 不同版本** | ❌ **不兼容**（版本升级按**破坏性变更**处理）——请两侧升到同版本，或插入转换模块 |
| **不同标识** | ❌ **默认不兼容**（框架**无资格**判定二者是否同一种量——形状相同也不认）；用户**显式确认**后可强连，**此时仍要求形状完全一致** |
| **任一方未声明类型**（旧模块） | 只按**形状完全一致**判定 |

- **传递语义必须一致**（跨语义不判兼容）。
- **不自动转换**：不可连 + UI 明示差异；**转换 = 用户显式插入的转换模块**，框架只**提示差异**。
- **逐（源,宿）对判定**：形状不一致只排除**该对**（+ Issue），其余源照常；**同一宿口上永远只出现一种长度**。
- **显式确认的载体**：`ConnectNetworkOperation.AllowUnverifiedTypeMatch` → `Network.AllowUnverifiedTypeMatch`（**用户决定，不是派生事实**）⇒ 随组合件持久化（`allowUnverifiedTypeMatch`，只在该为 true 时写出，缺省 false），否则重载后连接会莫名失效。
- **为什么**（现行条款的成因，写实现/排查时需要知道）：旧的"接收 ⊇ 发送"（形状子集）允许接收方字段更多 ⇒ **到达数据报可能短于本口契约** ⇒ 接收方按自己契约整块读会抛 `数据单元过小`，而异常从投递回调逸出会使**该模块的投递循环整体退出**（现象 = "模块莫名不再收数"，Issue 却写"活动体异常"）。要求形状一致后，"**能连**"与"**能安全读**"重新成为同一件事。
- **作废项**（不得再作为实现依据）：`IsSubset`（接收 ⊇ 发送）· `IsTailAppendCompatible`（尾部追加 = 兼容）。

## 8. 类型身份、命名与演进 〔源: 16 Q7/Q8 + ADR-0046 D2/D6 + ADR-0051 D2 + 17 §3.1/§3.4 + 18 §8.10〕

| 项 | 定稿 |
|---|---|
| **命名空间** | **框架保留前缀（`hyw.`/`hyw/`）+ 包内声明**（前缀 = 包 ID）；重名 = 加载期拒绝/忽略并报 Issue（沿用"**不静默改名**"纪律）；UI 用**短名 + tooltip 全名** |
| **类型身份（`TypeKey`）** | 已声明类型 ⇒ **`标识@版本`**；未声明（旧模块）⇒ **结构描述 `ContractShape.Describe()`**。**不得**用呈现文本一律代替——那会把"**不同标识但同形状**"错误合并成一种量（ADR-0051 明确二者**不是同一种量**）。键由 `ModuleRuntime.DescribePortTypeKey` 给出，与**兼容判定的解析同一来源**；端口标记 / 角色 / 类型色板用**同一个键** |
| **版本号** | **仍必须声明**——它表达"**换了版本就不再是同一种数据报**"，而不是"可自动兼容的演进" |
| **演进规则** | 升级版本 = **破坏性变更**：改类型/删字段/改顺序/尾部追加**全都不兼容**；两侧同版本，或插入转换模块 |
| **易误读澄清** | `Sdk` 的"**只增不改**"纪律（P30）说的是**声明面扩展**（新增可选字段/新成员不破坏旧模块），**不是**"类型尾部加字段仍兼容"——后者**已作废** |
| **筛选/呈现的归属** | 类型身份 → 颜色/图例/检索的映射策略与覆盖表见《叠加层与视觉基线》分册；**键相同**是两册的共同前提 |

## 9. 单位与语义元数据：可声明、只展示、禁参与判定 〔源: 主文档 §5.4.2 第 2 条 + ADR-0046 §2 第 6 条/D2 + 16 Q2/Q5〕

| 项 | 定稿 |
|---|---|
| **契约不含单位/量纲语义** | 数据流保持简单、不过度精确化；**单位属模块配置/显示层**（轴标签与格式化由模块决定） |
| **语义元数据** | 单位（`°C`/`rpm`/`V`）· 量纲 · 有效范围（min/max）· 精度/分辨率 · 建议采样率 · 枚举值域 · 数组语义 · 显示格式提示——随类型声明，**全部可选**（模块作者写多少算多少），框架保证"**有就显示、无就留白**" |
| **红线** | 语义元数据**只透传/展示**，**禁止参与任何框架判定**（兼容判据只用标识/版本/形状/尺寸）——**可声明 ≠ 可判定** |
| **现状落点** | 配置字段有 `Unit`（`ConfigurationFieldAttribute`）、视图元素有 `Unit`（`ViewDeclaration`）；**端口契约没有 `Unit`** ⇒ 同一条数据"显示时有单位、契约里没单位" |
| **计量块（随类型声明，全可选、缺省有定义）** | `PayloadSizeInBytes`（业务数据字节数，缺省 = 契约尺寸）· `SamplesPerUnit`（缺省 1）· `ChannelCount`（与数组语义**合并定义**，缺省 1）· `NominalRateHz`（缺省空）——框架据此**机械计算**，零解析 |

## 10.1 `protocolVersion`：不引入 〔源: 用户裁定 + 16 Q14 + ADR-0046〕

**不引入协议版本字段**（进程内传递；如将来需要跨进程/远程，另立决定）。依据：数据面是**进程内**传递——数据单元从模块线程经 L3 队列投到宿口，**没有跨进程 / 网络协议**；`16` Q14 的"引入并写兼容细则"因**无承载、无 ADR 细则、无落地点**而不予落地。**术语澄清**：组合件的 `schemaVersion` 是**文件格式版本**（`ADR-0050 M11/R3`），与"协议版本"**同名不同物**，不因本条受影响。
