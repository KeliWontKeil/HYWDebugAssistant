# HYWDebugAssistant 架构法典

> 定位：面向工程人员的**模块化数据处理、通信与可视化工作台**。用户的操作模型是「选择模块 → 放入工作区 → 配置 → 拼接 → 即插即用」；用户不需要理解消息、通道、队列、订阅、路由、线程、运行时绑定等底层概念。
>
> 本文只描述**系统现在是什么样**。做什么归 `docs/TODO.md`，验收步骤归 `docs/ACCEPTANCE.md`，工作流与命令归 `docs/HOWTO.md`，代码风格归 `docs/STYLE.md`。

## 1 分层与项目结构

### 1.1 分层

层按**运行时角色**划分，不按命名空间划分。

| 层 | 名称 | 承担什么 |
|---|---|---|
| L0 | 横切支撑 | 中性技术能力：日志 sink、序列化、文件读写、诊断采集 |
| L1 | 契约层 | 模块作者与界面共同依赖的稳定抽象面：契约、声明面、数据类型 |
| L2 | 模块宿主层 | 模块包的发现、加载、校验、注册；实例世界；框架侧生命周期 |
| L3 | 数据面层 | 绑定的执行与投递、有界缓冲与丢弃、**模块活动的承载与调度**、流量计数 |
| L4 | 核心管理面 | 组合的解释与校验、变更的原子应用、增量重建、持久化、Issue 中心 |
| L5 | UI 构成层 | 外壳窗口、模块窗口、视觉层、口上标记渲染、管理视图 |
| L6 | 模块实现 | 业务功能单元，**不是框架的组成部分** |

L0 只对 L2 / L3 / L4 可见。

### 1.2 依赖方向

唯一允许的依赖链：

```
L6 模块实现  →  L1 契约（Sdk / Sdk.Ui / Sdk.AccessKit）
L2 模块宿主  →  { L1, L0 }
L3 数据面    →  { L1, L0 }
L4 核心管理  →  { L1, L2, L3, L0 }
L5 界面      →  { L1, Core.Api }
```

结构性事实：

- **L3 数据面没有任何指向 L2 / L4 / L5 的依赖** ⇒「Core 中转数据」「界面参与投递」在结构上无法成立。
- **L6 只依赖 L1**（`Sdk` / `Sdk.Ui` / `Sdk.AccessKit`）⇒ 模块不能自建活动载体、不能引用另一个模块、不能直接引用界面框架，也不能携带外部接入实现。
- 稳定抽象面单列为 `Core.Api`，界面只经它读取运行期事实；界面**不引用**核心管理面的内部。

### 1.3 项目与程序集

**项目清单即依赖边界**：同一层可由多个程序集构成（如 `Sdk` / `Sdk.Ui` / `Sdk.AccessKit`），但每条禁令都可以直接按「项目引用」检查，而不必从命名空间推断。

| 项目 | 层 | 允许直接引用 |
|---|---|---|
| `src/Sdk` | L1 | 无（零框架依赖） |
| `src/Sdk.Ui` | L1 界面契约/控件库 | `Sdk` |
| `src/Sdk.AccessKit` | L1 工具（模块侧外部接入骨架） | `Sdk` |
| `src/Sdk.Testing` | L1 工具 | `Sdk` |
| `src/Infrastructure` | L0 | 无 |
| `src/Hosting` | L2 | `Sdk` · `Infrastructure` |
| `src/DataPlane` | L3 | `Sdk` · `Infrastructure` |
| `src/Core` | L4 | `Sdk` · `Core.Api` · `Hosting` · `DataPlane` · `Infrastructure` |
| `src/Core.Api` | L1 公开面 | `Sdk` |
| `src/Ui` | L5 模块区 | `Sdk` · `Core.Api` |
| `src/FrameworkUi` | L5 外壳 | `Sdk` · `Core.Api` · `Ui` |
| `src/App` | 组合根 | 上述全部 + `Access` + `Sdk.AccessKit` |
| `src/Modules/Business/*` | L6 | 只允许 `Sdk` + `Sdk.Ui`（界面契约与控件库）+ `Sdk.AccessKit`（模块侧骨架） |
| `src/Access` | L3 外部接入实现（框架扩展） | 只允许 `Sdk`；**只有组合根引用**，适配器/参数类型/catalog 归框架侧 |

- 允许引用 Avalonia 的程序集**只有** `Sdk.Ui`、`Ui`、`FrameworkUi`、`App`；`Sdk`、`Core`、`Hosting`、`DataPlane` 不得出现界面框架依赖。模块经 `Sdk.Ui` 拿到控件，不直接引 Avalonia 包。
- 框架程序集**不得**引用任何模块程序集。
- 模块之间**不得**互相引用。
- `Access` 是**框架侧**的外部接入实现层（适配件、参数类型、内置 catalog）：**只有组合根引用它**；`Core` / `Hosting` / `DataPlane` / `Core.Api` / `Ui` / `FrameworkUi` 都不得引用。
- `Sdk.AccessKit` 是模块侧共用骨架（`ExternalAccessModule` / `AccessModuleSpec` / `RawBytesFraming`）：只引 `Sdk`，由宿主随附，**不随模块包分发**。
- `Sdk` 必须零依赖（包括不依赖 `Microsoft.Extensions.*`）。

`HYWDebugAssistant.slnx` 的登记内容以上表为准（框架项目 · 业务模块 · 测试项目；条目以解决方案文件为唯一来源，本文不抄）。业务模块为：文本发送器、HEX 发送器、数据监视器、HEX 字符串转换器，以及外部接入四模块（串口、TCP 客户端、TCP 服务端、UDP）。

### 1.4 模块包形态

- 一个模块包 = **一个目录**，其中 `module.json` 是包清单（身份与实现绑定），随后只有**模块自有**文件（模块 DLL、可选资源、模块私有第三方依赖）。**界面是模块自己的 XAML（编译进程序集），包内没有界面描述文件。**
- 宿主提供 `Sdk` / `Sdk.Ui` / `Sdk.AccessKit` / `Access` / 外部接入第三方依赖；模块包**不带这些宿主程序集**。
- 构建期把模块项目输出归拢到 `artifacts/modules/<Configuration>/<包名>/`（先清空该包目录再复制，避免新旧程序集混放），再由应用项目镜像到输出目录下的 `modules/`。
- 内置模块 = **预装的包，没有任何结构特权**：与外部导入包走同一条发现、加载、校验路径；区别只在存储位置（`modules/` vs `modules/external/`）与界面标注（内置 / 外部）。
- **外部模块不直接扫描**：用户在「模块清单」选择外部目录，框架校验后把包复制进 `modules/external/`，之后只扫描默认目录。
- 包名由项目属性推导，默认取项目名后缀 ⇒ 新增模块项目**零改动**。

### 1.5 唯一白名单：组合根

`src/App` 是**唯一**同时可见 L4 与 L5 的位置。它只做这几件事：

1. **装配**：构造核心构成（含模块注册表）、设置服务、运行期服务（同时以 `IRuntimeQuery` 与 `IRuntimeCommand` 两个面暴露）。
2. **装载**：读应用级设置（失败则用默认值 + Issue，**不阻断启动**），扫描固定默认模块目录（`modules/` + `modules/external/`）。
3. **显示**：创建外壳视图模型，显示外壳窗口；模块窗口由界面侧创建。

组合根里不放业务逻辑，也不放机制逻辑——一切机制都在 L4 之内。

装配序本身是语义：核心构成先于界面构成；界面只拿到查询面与命令面。

## 2 模块 SDK 与契约

### 2.1 模块是什么

模块是用户可感知的功能基本单元。它在实现上只有这几样东西：

- **入口接口**：模块实现接口，框架按接口调用，**不继承框架基类**。
- **声明入口**：在注册钩子里通过上下文声明数据类型、口、角色、内部处理顺序。
- **可选能力接口**：只声明"我需要自发活动"以及活动形式（周期 / 事件驱动），实现体内由框架在该实例的专属线程上调用。

模块不持有框架对象引用，只能经上下文使用上报能力、读写自身配置、登记活动。模块不能反向查询其他模块是否存在。

### 2.2 Definition：对外声明

声明面的项、键名与聚合成 Definition 的方式只在 SDK 的声明入口与模块定义类型里（`src/Sdk/Context/IModuleContext.cs`），本文只说明各项承担什么。

| 项 | 内容 |
|---|---|
| 身份与版本 | 作者 / 模块名 / 版本 |
| 元数据 | 显示名 / 说明（可用 `DisplayNameKey` / `DescriptionKey` 指向模块自己的文本表，见 §8.5）、可选预览图 |
| 接口 | 口（方向、形状、传递语义、是否参与自动建网） |
| 配置 | C# 配置类型 + 字段标注 |
| 视图 | 模块提供 `IModuleViewFactory`（XAML 视图）；声明来源是 `[ModuleDefinition(ViewFactory = …)]` |
| 外部接入 | 具名接入 + 标准标识；框架按标准目录解析适配器/参数类型并创建会话 |
| 生命周期能力 | 是否需要自发活动、活动形式 |

内置模块与外部模块**同形**：同一份声明面、同一条加载路径。

标识采用结构化字面量 `作者/模块名/语义版本`：段全小写、版本取语义化版本形式、段首不得为连字符、段不得为空；解析与校验只在 SDK 的模块标识实现里，失败即拒绝加载。**版本参与多版本共存**，也支撑连接锚定的诊断文本 `实例ID.口名`。

### 2.3 包、发现与加载

- **1 包 1 模块**：注册表的登记粒度是包。
- **发现**：只扫描固定默认目录 —— 程序目录下的 `modules/`（内置包）与 `modules/external/`（外部导入包）；每根只扫**直接子目录**中含 `module.json` 者；不递归、不猜、不扫任意位置。**不再有用户可配置的来源根列表**。
- **外部导入**：用户选择外部包目录（或包含多个包的上级目录）→ 校验 manifest / 同 ID 同版本冲突 → 复制进 `modules/external/<包名>` → 重扫默认目录。同 ID 同版本已存在时**拒绝导入**（不静默覆盖）；不同版本允许共存；同包内容相同则跳过。
- **重复包**：直接扫描时同标识同版本 ⇒ 先到者胜，后者记 Info；不同版本 ⇒ 都注册，按模块名聚合，默认取最新版本。
- **加载**：校验 manifest 完整性、框架兼容范围、依赖 ⇒ 注册 ⇒ 可实例化。只有结构/兼容/依赖/注册失败才记 Error，**不影响既有模块与正在运行的现场**。
- **重扫**：作用域限于固定默认目录，只发现新增/变化包；已载入的程序集不可替换。未变包不再产生 Issue。
- **来源标注**：包目录位于 `modules/external/` ⇒ 模块清单第二行标「外部」；`modules/` ⇒ 「内置」；需重启并入同一行。
- **重新加载**：保存当前工作区快照（`workspace/`）→ 重启应用 → 启动时恢复。工作区快照也用于正常关闭时的“保存退出”；不是组合件库。
- **移除**：从注册表注销；已被实例化的进入缺失态（占位 + Issue），**不强制卸载**正在使用的模块。
- **热重载不提供**：改动模块代码的语义固定为「重新构建 → 重启应用」。既不实现热重载，也不实现可卸载的加载上下文。

### 2.4 生命周期钩子

钩子按框架的生命周期契约固定（钩子名即 SDK 生命周期接口 `src/Sdk/Lifecycle/IModule.cs` 的成员），由框架在**该实例的专属线程**上调用，各自承担：

| 钩子 | 时机 | 语义 |
|---|---|---|
| `OnRegistered` | 实例创建、成员实例化完成 | 在此声明口、类型、角色、流；不得假定数据已在流动 |
| `OnActivated` | 进入 Active | 开始业务活动 |
| `OnDisabled` | 进入 Disabled | 暂停数据流；内部处置**自决**（是否断开硬件由模块决定） |
| `OnEnabled` | Disabled → Active | 恢复业务活动 |
| `OnConfigurationChanged` | 配置更新 | 热生效或请求重建由模块自决 |
| `OnRemoved` | 移除前 | 释放**模块内部**资源（框架已先清连接、绑定与成员资源） |

纪律：

- 钩子中的异常**不得逸出边界**，由框架受控捕获并转 Issue。
- 活动体可以阻塞、可以循环；但**外部 IO 归适配件**（框架驱动会话），模块不因外部 IO 自建活动体。活动体只承担非 IO 的周期活动与交互，必须响应停止信号。
- 模块**不得自建线程或定时器**。
- 上报接口本身不抛；框架自身代码不捕获自己。

### 2.5 口与类型引用

口是网络的端点，也是**唯一**的接口与建网单位。

- 口名在模块内唯一且稳定；重复即拒绝并记 Issue，**不静默改名**。
- 连接锚定为 `实例ID.口名`。
- 方向只有两态：发送、接收。双向 = 两个口 + 两条单向网络。
- 形状由 SDK 的原语组合给出，**尺寸由形状决定**（见 §3）。
- 口用**类型引用**（标识 + 版本）指向本模块已声明的数据类型；这是一项可声明、非必须的兼容扩展。不声明即回退到按形状判定。
- 类型引用用 `init` 属性而不是构造器参数（见 §2.8）。
- 口的**默认挂载边**由 `PortDeclaration.Edge` 声明（`Auto` = 按数据流惯例：发送右、接收左）；没有外部数据文件。

### 2.6 角色声明与两侧同型

角色 = **模块声明的功能分块**（「我有哪几块处理功能」），由模块在注册时声明，框架不派生、不发明。

| 字段 | 含义 |
|---|---|
| 标识 | 模块内唯一、稳定；重复即记 Issue 并忽略后者 |
| 功能名 | 呈现文本；为空则回退为类型短名 |
| 类型 | 该分块处理的数据类型引用，必须能在本模块解析；**一个角色只有一种类型** |
| 输入口集合 | 可为空 = 纯源分块 |
| 输出口集合 | 可为空 = 纯汇分块 |

**两侧同型**：一个角色的输入口与输出口承载**同一种数据类型**。违反 ⇒ 自检进 `Problems`、加载期记 Issue 并**忽略该条**；口未声明类型（旧模块形态）时不校验。

- 口数不设上限；口数超出「一个分块一进一出」的常规规模时，只在 SDK 自检的**独立建议通道**给一条可忽略的建议（建议文本明说「若是一件事则不必拆」；触发门槛只在 SDK 自检实现里），**不进 `Problems`、运行期不报**。
- 一个口**最多属于一个角色**；未归属任何角色的口合法，在叠加层里不表达。
- 口与角色不是同一个层级：口是数据接口的抽象（仍由端口标记表达），角色是模块内部功能的抽象（只由叠加层表达）。
- 类型转换 = **两个数据角色**（收 A 的角色 + 发 B 的角色）+ 一条内部流声明；叠加层上表现为两个方块、各按自己的类型色。
- 角色图标不做。

### 2.7 内部处理顺序声明

模块可声明一条「角色 → 角色」的处理顺序，表达分块之间的先后（如「融合 → 限幅」）。

- 两端角色必须已声明，否则记 Issue 并忽略该条。
- 不得自环；同一（起点，终点）不重复。
- **零声明即零线**：框架不猜——同类型的收发口之间没有必然关系，猜出来的线是虚假信息。
- 单分块模块完全没有可声明的边，因此参考模块通常零声明。

### 2.8 SDK 兼容纪律

- **只增不改，看签名不看语义**。语义上"只是加了个可选参数"仍会改变方法签名；宿主与模块共用同一份 SDK，版本不匹配时在加载期拒绝（不是运行到一半才抛 `MissingMethodException`）。
- **禁止用构造器可选参数扩展声明面**。新增可选声明一律用 `init` 属性或新类型。
- **改动 SDK 后必须重编全部模块**，并把它当作交付前的检查项。
- 外部接入的契约同样是**只增不改**：新增声明/存取/快照成员一律用默认实现或新类型；旧模块包因 SDK 契约版本不匹配在加载期被明确拒绝。
- 契约面的破坏性变更按契约变更处理。
- 配置读写与序列化用源生成，运行期热路径零反射：反射只用于加载期读一次声明。

### 2.9 报什么、不报什么

- 声明期能判定的结构问题（口名重复、角色类型不可解析、口方向不符、口不属于本模块、内部流自检失败）⇒ 加载期记 Issue 并忽略该条。
- 模块契约自检套件 `Sdk.Testing` 提供且推荐：只依赖 `Sdk`，模块作者在自己的测试项目里引用它即可自检接口、Schema、生命周期钩子与「无跨模块引用」。它**不进入产品程序集**。
- 「建议」与「问题」是两条通道：建议走独立的 `Advisories`，问题走 `Problems`。若把建议写进 `Problems`，自家参考模块的门禁用例会当场失败。
- 模块业务状态不属于 Issue（见 §4.6）。

### 2.10 计时纪律

- 模块的**周期/延时/等待**一律经 `IModuleContext.Timing`（`IModuleTiming`）；**不得自建 Timer、Thread.Sleep、DispatcherTimer、Task.Delay 或平台专有调度 API**。
- 框架侧只有一个进程级 `GlobalTimerService`：一个调度线程、一个平台高精度计时后端、多个模块等待者；模块线程只等待自己的信号。
- 1 ms 是 1000 Hz 的高精度档，不是“不能做”：Windows 使用高分辨率 waitable timer；其他平台走托管高精度回退（同一接口保留 timerfd / kqueue 后端位）。平台差异只存在于框架计时层，模块层零平台 API。
- 平台后端不可用时回退到托管等待/短自旋，并记录诊断；1 ms 回退可能占用一个核，必须如实告知，不静默假装精确。
- UI 刷新/动画由唯一 `UiFrameClock`（一个 `DispatcherTimer`）统一订阅，空闲停表；它是 UI 线程专用，不向模块暴露；模块不得使用 `DispatcherTimer`。
- 架构测试 AR-23 对模块包做源码扫描，禁止定时器/平台调度 API；外部接入适配器在框架侧，不参与模块源码扫描。

## 3 数据协议与类型

### 3.1 数据单元

- 一个数据单元 = **一个定长数据报**，长度等于发送口契约的尺寸。
- 数据包**不自描述**：不带类型标签，框架按声明路由。需要自描述的模块在自己的契约里带字段。
- v1 **只定长**：不提供变长载荷、不分片。
- **批量 = 定长数组**（`T[N]`）。框架不做自动合并——那会改变时序语义。
- 负载缓冲是池化的定长扁平缓冲，只含契约字段，**不含框架元信息**；形状元数据（字段偏移表）与强类型访问器在加载期生成。
- 接收侧约束：到达长度必须 ≥ 本口契约尺寸；长度不足时读取返回失败而**不抛异常**（防御式读取）。形状完全一致的前提下，长度恒等于契约尺寸。
- 取消类型标签与来源字段带来的两个直接后果：投递路径没有逐单元构造开销；同一宿口上永不出现两种长度。

### 3.2 解析三段式

| 阶段 | 谁做 | 内容 |
|---|---|---|
| 声明期读取 | **框架必做** | 注册 / 实例化时一次性读取端口、类型引用、视图声明、能力、计量块、解码器；销毁时注销；**运行期不重读** |
| 传输期解析数据流 | **框架禁止** | 框架不读数据内容；投递只按绑定走，外加长度校验 |
| 呈现期解码 | **模块负责** | 解码器由模块提供并随类型注册，框架只回调，不内建、不理解结构 |

框架内建的解码器只是参考实现。

### 3.3 数据类型声明

一条类型声明包含：标识 + 版本 + 形状（**尺寸的唯一来源**）+ 传递语义 + 计量块 + 解码器 + 语义元数据。

- **类型身份归模块，框架只持机械镜像**：标识、版本、尺寸、传递语义、兼容声明。框架做机械判定，不解释"这是什么量"。
- 类型按（标识，版本）索引；标识建议带模块前缀，因为**跨模块同名 = 同一类型**。
- 传递语义是枚举：流 / 消息 / 事件。**跨语义不判兼容**，需要时由模块内部组帧或插入转换模块。
- 解码器可选：不提供则呈现层显示「未声明解码器 + 字节数」，**不猜**。解码器必须是纯函数（同字节同结果、不抛、不分配），失败即失败，框架不按长度或原语推断。
- 语义元数据（单位、量程、精度等）**只用于展示**，禁止参与任何框架判定。
- 引用未声明的类型、重复声明同一（标识，版本）⇒ 记 Issue 并回退。

### 3.4 形状

形状 = 定长字节数 + 嵌套深度，形态如下：

| 形态 | 说明 |
|---|---|
| 原语 | `i8` `i16` `i32` `i64` `u8` `u16` `u32` `u64` `f32` `f64` `bool`；尺寸由原语本身表达 |
| 定长字节块 | 长度有上限（文本载荷按「一个 UDP 包量级」留量）；上限只在 SDK 形状类型的校验里 |
| 定长数组 | 元素必须是原语；长度上限只在 SDK 形状类型的校验里 |
| 结构组合 | 字段 = 名称 + 形状，字段名唯一，顺序即签名顺序；嵌套深度有上限，上限只在 SDK 形状类型的校验里 |

可读描述形如 `f32`、`u64`、`f32[N]`、`bytes[N]`、`{seq:u64, value:f32}`。

### 3.5 兼容判定

判定对象是**逐（源，宿）对**，不是整条网络。

判定顺序：

1. **传递语义必须一致**，否则不兼容。
2. **形状必须完全一致**：字段名称、原语种类、数组与字节块长度、字段顺序、字段数量全同 ⇒ 尺寸必然相同。
3. 双方都声明类型时再比类型身份：
   - 同标识 + 同版本 ⇒ 兼容；
   - **同标识 + 不同版本 ⇒ 不兼容**（版本升级按破坏性变更处理：把两侧升到同版本，或插入转换模块）；
   - **不同标识 ⇒ 默认不兼容**（框架无资格判定二者是否同一种量）；用户**显式确认**后可强连，**此时仍要求形状完全一致**，并产生一条必须让用户看到的说明。
4. 任一方未声明类型（旧模块形态）⇒ 只按第 2 条判定。

**形状相等必须逐字段结构比较**。这些形状是 record，但结构形状的字段集合在 record 默认相等里做的是**引用比较**——直接写 `==` 会把两个模块各自构造的同一形状判成不同（隐形陷阱：只有引用同一静态实例才连得上）。

**不自动转换**：不兼容即不可连并明示差异，转换由用户显式插入转换模块。合法但无意义的组合（例如两个发送口相接）方向决定其"连接存在但无数据流"，不在兼容判定里处理。

形状完全一致的收益是可安全读取：到达长度恒等于本口契约尺寸，接收方按自己的契约读不会越界，也就不会有异常从投递回调逸出、把该实例的投递循环整体带走。

### 3.6 计量块

随类型声明，全字段可选，每项都有明确缺省；缺省值只写在计量块类型里，本文不抄数值，只说明缺省语义：

| 字段 | 缺省语义 |
|---|---|
| 有效载荷字节数 | 未声明即按契约尺寸算 |
| 有效长度字段名 | 未声明即不逐单元读（按静态尺寸算） |
| 每单元样本数 | 未声明即按单元计，不换算样本 |
| 每样本通道数 | 未声明即不区分通道 |
| 标称速率 | 未声明即无标称值 |

**有效长度字段名**解决的是「定长契约里的变长载荷」（典型形态 = 一个顶层整型长度字段 + 一个定长字节块，尾部补零）：声明哪个顶层整型字段写着有效长度，框架逐单元小端读取并夹到 `[0, 契约尺寸]` 后累计，有效载荷档速率因此给出**真实**有效速率；声明了它则动态值优先。字段不存在、不是整型、或不是结构形状 ⇒ 契约自检明确报错，不静默。

速率按口径分档（档名即枚举成员，本文不抄各档数值）：

| 档 | 口径 |
|---|---|
| 单元速率 | 按**源**计，每个数据报一次，不受多播放大影响 |
| 搬运字节速率 | 按**宿**计，含自描述与对齐填充 |
| 有效载荷字节速率 | 业务数据字节 |
| 样本 / 通道样本速率 | 由每单元样本数与通道数换算 |

**丢弃只有一套词表、三条轴；一个事件只记一次**（词表 = `Sdk.Reporting.DropReason`，每条轴只回答自己那一侧的事实）：

| 轴（所有者） | 记录什么 | 不记录什么 |
|---|---|---|
| 队列轴（每 实例×接收口，`InboundBuffer`） | 满队挤旧 / 满队拒新 / 过期 / 停止清尾 / 模块内部丢弃；深度、峰值、饱和 | 无承载、载荷非法（没有队列可记） |
| 流轴（每 源→宿 绑定，`BindingDiagnostics`） | 停流未投递、队列满（与队列轴同一事件的两侧归属）、无承载、承载已停、载荷非法 | 模块内部丢弃（那不是网络事实） |
| 会话轴（每 外部接入，`ExternalAccessSession`） | 未打开发送被拒、写失败、会话接收队列满、适配件溢出、超长、过期 | 口队列的丢弃（由队列轴记） |

- **同一事件在队列轴与流轴各记一次**（一个回答「谁丢了」、一个回答「哪条流没送到」），**任何界面与任何合计只用一条轴，绝不跨轴相加**。
- **字节口径分三种**：队列轴 = 契约尺寸 × 单元数（界面按「单元」显示）、流轴 = 有效载荷字节、会话轴 = 实际有效字节；三者不混算。
- **停流未投递是合法状态**，不并入传输丢弃；**停止清尾**与**模块内部丢弃**各有独立原因，也不并入。
- 会话轴的合计由分项算出（`Dropped = 拒绝 + 写失败 + 接收侧`；接收侧 = 队列满 + 超长 + 适配件溢出 + 过期），不另存总数。
- **模块内部丢弃只能经上报口进入队列轴**；模块替框架声明「队列满了 / 写失败了」会被忽略（那两条事实框架自己看得见）。

纪律：计量块**只用于计量与呈现**，禁止参与建网、兼容等任何框架判定（可声明 ≠ 可判定）；界面只显示有定义的口径，不做差分估算；「是否掉速」= 实测与标称速率相比。

## 4 运行期机制

### 4.1 总流程

```
用户拼接 / 配置 → 组合声明 → L4 解释与校验 → 绑定（数据通路）→ 数据单元直通投递
```

- 数据单元按序**直通**：核心管理面不中转数据。
- **没有全局启停**：模块加入即运行，停止由生命周期状态承担。
- 变更 = 一次原子变更 → 增量重建受影响局部。
- 框架统一承载模块活动；模块的业务上下文独立于数据面。

### 4.2 生命周期

```
Registered → Active ⇄ Disabled → Removed
```

| 状态 | 语义 |
|---|---|
| `Registered` | 已加入（创建、初始化是转换过程）；**不占线程** |
| `Active` | 参与数据流（加入即运行） |
| `Disabled` | 保留实例、拓扑与配置，暂停数据流；**保留线程与队列**，只把绑定置为停流；通知模块，内部处置自决 |
| `Removed` | 已移除（停止、释放是过程）；**资源在此才回收** |

- **`Faulted` / `Recovering` 不是框架状态**——软件异常走异常报告。
- **移除不可逆**：重新加入 = 新实例；撤销由界面的撤销栈承担，复制配置属界面便利。
- **绑定独立于模块状态**，随连接存在：`Disabled` ⇒ 绑定保留停流（界面标注）；`Removed` ⇒ 级联销毁。业务状态变化不触碰绑定（表现为无数据）。
- 正交面：存在性（框架权威）· 活动面（框架权威）· 业务状态（模块自报，框架只登记与呈现）· 异常报告（模块产生，框架受控收集）。

### 4.3 线程与队列承载

- 每个 `Active` 实例 = 一个由 L3 分配的**专属线程** + 每（实例，口）一条有界输入队列 + 停止信号 + 若干订阅缓冲。
- 模块活动体允许阻塞（线程归它自己用，阻塞只影响自己），必须响应停止信号，**不得自建或自管线程**。
- **队列粒度 = 每（实例，口）一条有界 FIFO**，容量按口计；默认**丢最旧保最新**；**v1 不做背压，绝不阻塞发送方**。
- 入队结果分档，各自计数：接受 / 队列满挤旧 / 队列满拒新 / 无承载 / 已停止。「无承载」不记成「满队」，「承载已停」也不混进「无承载」。
- 每口一条队列同时消除跨口队头阻塞：一个满口不会堵住同实例其他口的数据流。多口之间按轮转公平调度。
- **投递按时间片回泵**：内层排空每处理一个单元前先查停止信号，最多连续占用线程一个片长，到点必回外层跑辅助工作源（命令 / 输入 / 会话泵 / 状态发布）。于是「某个口长期有货」不会再让控制面与接收侧被无限期排在后面。
- **积压可按滞留时长过期**：开启后，出队前判单元年龄，超过上限的整单元丢弃并记「过期」——迟到的实时数据不投给消费方。关闭（缺省）时行为与「把已收下的跑完」一致。
- **暂停即清尾**：实例进入 `Disabled` 时清空该实例各口队列（逐笔记「停止清尾」、缓冲归还池），恢复后不补发停用期间的陈旧积压。
- 记账补漏：丢旧策略下「新单元入队并挤掉旧单元」时，新单元记投递、被挤的旧单元记**队列满挤旧**——否则投递数会把从未被消费的单元算成成功。
- 承载参数（空闲等待、队列容量、满时策略、停止超时、饱和判据、滞留上限、外部写超时）的**唯一来源 = 数据面承载参数类型**（`src/DataPlane/Carriers/CarrierOptions.cs`），其用户可调部分来自应用级设置 `flow` 块（见 §4.10），测试与产品共用同一份缺省值，本文不抄数值。

### 4.4 停止协议

- 框架发停止信号 → **先清尾** → **有界等待**（等待上限 = 承载参数类型的停止超时缺省值，本文不抄数值）。
- **先清尾**：停止后队列里的单元已没有消费方，逐笔记「停止清尾」并把缓冲归还池，再等待线程退出；Join 成功后再清一次，兜住与生产者赛跑挤进来的单元。于是停止时长 ≈ 一个在途单元的处理时间，而不是整条积压的排空时间。
- 外部写必须有界（见 §4.9「写超时」）：否则「一个在途单元」也可能无限期不返回，停止的有界等待就失去意义。
- 超时 ⇒ 记 Issue + 标记该线程为孤儿线程，**不强杀线程、不卸载程序集**（.NET 没有安全的线程中止）；此时只放弃「清尾之后」挤进来的缓冲。
- 孤儿线程是**有意接受的边界**：此时「`Removed` 即资源已释放」对该线程不成立。
- 模块侧的义务是周期性检查停止信号并尽快返回。

### 4.5 变更与增量重建

- **单操作原子**：连接 / 断开 / 加入 / 移除 / 启用 / 停用等单个操作，要么完整应用、要么整体回滚一致，没有半状态。
- **复合 ChangeSet**：需要多步一起做（如替换模块并重连）时，由界面或命令层组装为一次复合变更。
- **两阶段**：
  - **Prepare**——整体校验规则、能力与契约，**可失败、零副作用**；
  - **Commit**——无失败点，先加后减。
- 变更入口**串行化**；任一步失败则**整体拒绝**。没有跨用户会话的全局事务或锁（单用户桌面 + 全在线场景不匹配）。
- **增量重建单位 = 绑定及其邻接数据面**：只重织受影响的连接与绑定衔接；**模块实例、配置与业务状态保留**（插拔线不重置模块）。删除、替换、配置结构变更才触达模块。
- 配置更新 = 框架通知模块，热生效或请求重建由模块自决。
- 配置 Schema 的字段写回也走同一条变更路径：按字段解析文本 → JSON 中转（序列化当前配置 → 覆盖一个属性 → 反序列化为**新实例**）→ 一次变更、原子应用或整体拒绝、触发一次配置变更通知。**绝不就地修改运行中的配置对象**，Prepare 阶段零副作用。
- 配置还原（界面的「还原」）语义是**用同类型的新默认实例替换**每个已登记配置，**不得清空集合**：清空会让按登记对象生成的 Schema 表单失去数据来源。

### 4.6 Issue 中心

统一模型 = 归属对象（实例 / 口 / 连接 / 配置项）+ 类别 + 来源（框架判定 / 模块报告）+ 描述与时间。

类别是枚举成员：Configuration Error · Composition Error · Interface Error · Module Error · Communication Error · Runtime Error · Presentation Error（成员即唯一来源）。

- 语义分两层：设计 / 变更问题（可判定、用户可修）与运行报告（运行期产生）。
- **模块业务状态不入 Issue**（属状态面）。
- **隔离与恢复 = 天然隔离 + 显式恢复**：框架不自动重试、不自动降级、不阻断上下游；隔离的实现保障是模块异常不逸出边界（框架在边界捕获并转 Issue）；恢复靠用户显式操作或模块自身内部恢复。标准恢复动作是「重建实例」（移除 + 加入的复合变更，由界面组装，框架只执行变更）。
- 呈现 = **对象标注 + 主从面板**（左侧列表扫描、右侧详情完整呈现）；**不阻止其他部分运行**。
- 面板操作：复制消息/详情、已读/未读、删除单条、清空全部。**已读仅本会话**（Issue 中心本身不持久化）；删除/清空只影响 Issue 列表与计数，不影响模块、网络或配置。
- 通知强度 = 默认轻量（标注、计数），**不弹窗打扰**；模块可声明「需要用户注意」级别，默认仍不打断。活动栏 Issue 徽标**只显示错误级 Issue 总数**；警告/信息只进 Issue 面板，不参与角标。
- **严重度口径**：Error = 框架内部故障、契约/声明错误、持久化损坏等真正需要红色角标的问题；Warning = 外部环境/对端状态（TCP 对端关闭、连接超时/被拒、串口不可用）、可恢复的运行失败；Info = 生命周期/诊断事实。外部接入失败一律走 Warning，并由 `ExternalAccessIssue` 单点映射。
- 异常边界：活动体入口整体包裹 ⇒ 记 Issue 并停止该模块活动；钩子逐个包裹；上报接口内部不抛。框架自身代码不捕获自己的异常。

### 4.7 可观测性

| 层 | 内容 | 呈现 |
|---|---|---|
| L1 框架诊断 | 加载 / 注册 / 建网 / 绑定 / 增量重建 / 变更事件，结构化日志 | 诊断面板 |
| L2 Issue 中心 | 对象标注 + 主从面板 + 过滤 + 已读 | 轻量计数 + 面板 |
| L3 模块日志与状态 | 模块自产日志经框架汇集，分级 / 来源 / 过滤 | 模块视图 + 汇总视图 |
| L4 数据流诊断 | 各档速率、**按原因丢弃（三轴分开）**、最后数据时间、队列深度/峰值/饱和、最近一次丢弃 | 口上 / 网络详情 / 模块状态行 |
| L5 性能监视 | CPU / 内存 / 线程 / GC 计数（约 1 Hz，只读） | 侧栏底部文本（默认开，设置可关） |

原则：默认轻量不打扰；L1 / L4 是排障主力；录波与回放属未来能力。

采集点在每一处绑定与每一条队列上：投递数、丢弃数（按原因）、最后数据时间、队列深度/峰值、饱和状态。队列压力由队列自己的**压力算法**给出（进/出压力段的判据、迟滞、段内丢弃都在一处），**是否饱和在读取时求值**，不需要定时器或后台线程。Issue 经**低频率锁**保护的可删集合汇集（支持用户删除单条/清空；Issue 不在数据热路径上）。

同一份事实只在一处生成、其余位置只做格式化：拓扑诊断与口标记悬停读查询面的队列/端口视图，模块状态行读会话快照与自己口上的流动状态，界面不自行差分或相加。

### 4.8 非功能基线

- **首要原则：数据实时性 > 界面呈现**。数据面绝不被界面阻塞（视图独立开关、丢帧不阻塞上游、框架统一承载活动）。
- 模块数量不设上限要求；Core 不随模块数量线性膨胀。
- 热点下沉的备案：极端热点可下沉为原生库，其余保持 C#，不整体换栈。
- 数值指标（界面刷新率、端到端延迟、内存、吞吐、连续运行时长）只作记录与对照，不设阈值。
- 行为护栏分两层：**安全护栏**（线程与内存安全、缓冲满丢旧、池化缓冲边界与归还保护；静默、快速、无热路径分支开销）+ **轻量提示**（「缓冲持续为满」「处理速度跟不上输入」「线程占用偏高」「未在期限内停止」等事实陈述；可见但不打扰，不预设问题场景）。
- **轻量提示是状态事实，不是 Issue**：只以文本出现在模块状态行 / 拓扑诊断 / 口标记悬停，**不进 Issue 面板、不弹窗、不改变界面配色、不阻断任何部分**；Issue 仍只收失败与结构问题。理由：Issue 是追加式事件列表（无自动清除），持续状态写进去只会刷屏或另造一套生命周期。
- **措辞按事实**：饱和只表示「深度达到阈值并持续」，**不等于已经丢过**（丢弃量另给分项）；两者不得互相冒充。
- 明确不做：速率上限、环检测、自连检测、阻断、给数据单元加跳数元信息。

### 4.9 外部接入

外部接入是**框架与模块之间的接触面**（外部标准 → 应用），与网络模型并列但**不入网**：口仍是唯一建网单位，外部接入不产生源/宿、不参与绑定与兼容判定。

| 概念 | 谁持有 / 实现 | 形态 |
|---|---|---|
| 声明 | 模块在注册钩子里交出：模块内唯一的名字 + 标准标识 | 与类型/口/角色同级，**声明期一次性** |
| 会话 | 框架按标准目录（catalog）创建并驱动 | 有生命周期、状态、计量；每会话一条有界队列 |
| 适配件 | 懂某个外部标准的实现件（**框架侧内置，随宿主**） | 开 / 关 / 读 / 写 / 就绪；协议词与第三方依赖只在这里 |
| 模块侧存取面 | 框架提供 | 双向数据（读/写）+ 打开/关闭请求 + 状态/计量快照 |

- **驱动**：会话的等待与推进在框架的实例循环里，模块不因外部 IO 建活动体。
- **实例循环**：一个“有活干”信号 + 多个工作源——口队列、外部接入会话、收件箱。没有活动体的模块由框架回调投递（数据/命令/输入）；有活动体的模块在自己的循环里用读取面，框架不投递回调。两种消费方式由“有没有活动体”唯一决定，不能同时存在两个消费者。
- **连接操作链**：用户在模块窗口点〔打开/关闭〕→ 模块只发起请求 → 框架执行并持有会话。配置变更、实例 `Disabled` / `Enabled` / `Removed` 也由框架驱动关闭、重开、恢复。
- **不自动重试**：打开失败、连接断开、写失败一律进入故障态并给出**结构化失败**（种类 + 端点 / 原始参数值 / 底层细节）；用户再次请求才会重开。适配件内部也不做退避重连。
- **交付面**：数据 = 每会话有界队列 + 可选回调；状态与计量 = 可读快照（不做事件面）。快照只含**事实**（状态、端点、结构化失败、计数），**不含任何面向用户的句子**；模块把事实翻译成自己的状态灯、文案与计数。快照的丢弃按来源分项（未打开发送被拒 / 写失败 / 接收队列满 / 适配件溢出 / 超长 / 过期）并给出接收队列深度与饱和，合计由分项算出，不另存总数。
- **文本归属**：外部接入的用户可见句子（连接中 / 已连接 / 失败原因 / 端点表述）只住在**模块自己的表**；框架表只放底层诊断（`access.diag.*`、`dataplane.access.*`），供 Issue 与异常细节。参数类型的显示文本同样随**声明该接入的模块**（不是参数类型所在的程序集）。
- **存活检查**：无连接语义的接入（串口）可实现 `IExternalAccessLiveness`；会话在实例线程按 250 ms 探活（不新增线程）。串口连续 2 次不在端口列表判 `DeviceLost`；读写异常再按"端口是否还在"区分 `DeviceLost` 与读写失败。
- **故障即释放**：适配件报告会话级故障后，由实例线程调用一次 `Close` 释放句柄（异常吞掉、不覆盖主故障），故障态与失败事实保留；适配件不得在自身的泵 / 事件线程关闭传输。
- **写超时**：单次外部写必须有界（来自应用级设置 `flow.externalWriteTimeoutMs`；会话在打开与参数变更时下发给实现该能力的适配件）。它是「停止时长可控」与「承载线程不被设备永久卡住」的前提；超时按写失败处理（Issue 语义不变），不自动重试。
- **计数与清零**：收 / 发 / 丢弃 / 被拒是**会话级累计**，打开与关闭都不清零；唯一归零路径是模块的清空计数命令 → `IExternalAccess.ClearCounters`（只清会话轴计数与接收队列账本，不清队列数据、活动连接数与故障态）。口队列的队列轴账本随实例生命周期，**不随清计数归零**（两个轴不互相冒充）。未打开发送被拒时 `RejectedUnits` 增长；此时空闲态的状态句整体换成单句「有 N 个发送单元因会话未打开被拒绝」，不弹窗，也不在基础状态句后追加。
- **断开语义**：TCP 客户端靠读循环感知对端关闭（`PeerClosed`）；TCP 服务端按连接处理；UDP 无连接语义；串口靠探活 + 读写故障，设备消失为 `DeviceLost`。四者都**不自动重连**。
- **参数**：标准 descriptor 给出的参数类型在实例创建时登记进配置快照 ⇒ 配置表单、持久化、还原默认值全部复用既有配置面，组合件格式不变；标题 / 说明 / 分组 / 选项按"声明该接入的模块"解析。
- **失败隔离**：适配件异常在框架边界捕获，转 Issue 并归属到会话；模块继续运行。
- **分层**：中性契约与标准标识在 `Sdk`；会话、队列、状态机、计数在 `DataPlane`；生命周期、配置登记、Issue 归属在 `Hosting` / `Core`；适配件、参数类型与内置 catalog 在 `Access`（框架侧，只有组合根引用）；模块侧共用骨架在 `Sdk.AccessKit`。

- **接收暂存（R7）**：串口 / TCP 的适配件暂存是**字节流**（默认 64 KB，可由 `flow.adapterBufferBytes` 调整）：驱动把长文本拆成几十个小块时合并，超过契约单元时按 1472 B 切片；会话一次 `Pump` 读到空（单轮上限 4096），不再"一次只取一个"；UDP 仍是一报一单元，目标不足时分片交付。
- **丢失提示（R7）**：状态行优先级 = 非打开态 → 接收丢失（最近 10 s）→ 发送丢失（最近 10 s）→ 接收饱和 → 发送饱和 → 连接句；接收句带本次打开以来的计数（`接收侧最近发生丢弃（本次打开以来 {0} 个单元）`）；发送句只陈述「发送侧最近发生丢弃」，写失败 / 积压清理 / 口队列丢弃不混成一个数，累计仍看 `drop` 读数。各模块同一事实的句子逐字一致。
- **通信参数（R7）**：`IExternalAccessTuning` 把暂存容量 / 关闭等待 / 丢失判定 / 探活节拍下发给适配件与会话；探活节拍由会话消费，余项由适配件消费。
- **全双工调度（R8）**：会话把阻塞写移出实例线程——`Write` 只把单元拷进**有界发送积压**（按字节，满时丢最旧并计数），由**每会话一个写泵线程**调用适配件 `Write`；实例线程只做接收投递、命令与状态。写泵故障经"待处理故障"交回实例线程 `Fail`；关闭/暂停/故障先中止在途写、再 `Join`（上限=关闭等待）、再清空积压（`DiscardedOnStop`）。这解决"回环 + 压力下实例线程被阻塞写占死"（实测过载清计数从 61 ms 降到 16 ms）。
- **发送积压**：容量 `flow.sendBacklogBytes`（默认 256 KB，对新建/重开会话生效），`maxBacklogAgeMs` 同样作用于它；挤旧/过期/清空分别记 `SendBacklogEvicted` / `Expired` / `DiscardedOnStop`，快照给出深度/字节/峰值/饱和与分项丢失；口队列（模块收件箱）与发送积压（设备写缓冲）分层，不跨轴相加。

- **唤醒纪律（R9）**：会话写泵**不再逐单元唤醒载体**（写/入队/发送计数都不发信号，只有失败/生命周期信号）；载体信号改为**计数信号**，不再用"二值信号 + SemaphoreFullException"合并——高频小数据下那条路径每个单元抛一次异常，是应用卡顿的根因之一；载体空闲等待放宽到 10 ms（数据与命令由信号立即唤醒，辅助工作/状态发布约 100 Hz）；DataMonitor 活动周期 10 ms。宿主兜底关闭与打开并发时，写泵线程可能"已挂上未 Start"，Join 按已退出处理。

### 4.10 参数治理（数据面）

**分界规则**（「能调」不等于「该调」）：

1. **框架设置** = 与具体模块 / 设备无关的机制参数，收在应用级设置的 `flow` 块（唯一类型 = `Core.Api.FlowSettings`），设置界面是专用的「通信」页：队列容量、满时策略、停止等待、饱和判定深度与持续、最大滞留时长、外部写超时、发送积压容量、探活节拍、适配件暂存容量、关闭等待、设备丢失判定。
2. **模块配置** = 对端 / 设备参数（地址、端口、波特率、连接超时），随组合件保存，不进应用设置。
3. **代码常量** = 机制不变量与内部调优：投递时间片、空闲等待、端口位图上限、会话关闭等待派生值、速率窗口、收件箱容量、显示 / 订阅容量。理由写在各类型注释里；它们不对用户暴露。

**生效时机只有两类，设置页必须能分辨**：

| 类别 | 参数 | 何时生效 |
|---|---|---|
| 对**新建对象**生效 | 队列容量、满时策略、外部写超时、发送积压容量 | 新建队列 / 新建或重开的会话；既有队列与既有会话保持自己的值，当前生效容量由拓扑诊断显示 |
| **立即生效** | 停止等待、饱和深度、饱和持续、最大滞留 | 下一拍作用于既有队列与会话（只改判据，不动队列内容与容量） |

**唯一方向**：设置 → 承载参数 → 队列 / 会话 / 适配件；不提供模块级覆盖（避免同一事实两个来源）。设置文件升级时旧根键折叠进 `flow` 并删除。

## 5 网络语义

### 5.1 数据面模型

**UDP 式数据报 + 发布订阅**：

| 性质 | 取值 |
|---|---|
| 连接 | 无连接：按声明建立绑定后即投递，无握手、无会话 |
| 可靠性 | best-effort：有界队列满即丢并计数，**不背压** |
| 顺序 | 同一（源，宿）对 **FIFO 强保证**；跨源仅按到达顺序，**不提供跨源时间序** |
| 数据单元 | 一个定长数据报 |
| 拓扑 | 多播（1→N）· 多发布者（N→1）· N:M |
| 端点 | 口；**无每包地址**，拓扑全部由声明派生 |
| 长度校验 | 到达长度 ≥ 契约尺寸 |
| 可观测 | 各档速率 + 各类丢弃 + 队列水位 |

**数据面不暴露来源**：应用需要来源就自带字段；观测面改从绑定模型取来源，因此框架不读数据也能显示多源。下游不应从数据面得知数据源身份。

**不换真 UDP socket**：进程内数据面就是上面的语义，保留零拷贝与对象模型。与真实设备通信由模块承担（模块能力声明里的网络与串口），框架数据面是**模块之间的织物**，两者不混淆。跨进程 / 跨机通信（同一语义契约的真 UDP / TCP / 共享内存）登记为未来能力。

### 5.2 网络模型

- **直连 = 匿名网络**；**标签同名 = 命名网络**。几何与连接解耦。
- 网络统一为一个模型：源集合 + 宿集合 + 契约引用 + 诊断计数 + 状态。**多源是一等组合**，框架不隐式仲裁。
- 接收策略**框架中立**：按到达顺序投递，不做优先级、时刻排序或去重。
- 合并与仲裁由**模块**承担（例如融合器：两个输入口 + 一个输出口，策略为最新 / 优先 / 平均，来源用口区分，融合结果可再发布）。**框架永不仲裁**。

### 5.3 口的两态与严格单向

- 方向严格单向；双向 = 两个口 + 两条单向网络。
- 两个发送口相接 ⇒ **连接存在但无数据流**（由方向判定，不是兼容问题）。
- 宿口多路输入合法：多条网络可以喂同一个宿口（交织为一条流，要求逐对契约兼容）；宿若需区分来源，自带字段或改用多口。

### 5.4 源集合的两态与停流判定

| 概念 | 定义 |
|---|---|
| 在场的源 | 已锚定、可投递的来源 |
| 悬空的源声明 | 声明了但未锚定的来源（方向 = 发送） |
| 「声明的源」 | 上述两者的并集，是**持久化与展示的事实源** |

- **停流是派生量**：当且仅当在场源数为零。它不单独存。
- **部分源未锚定不是停流**：其余源照常投递，只为该源记一条 Issue。
- 全部源未锚定 ⇒ 停流（保留声明）；无源或无宿 ⇒ 未建网（等待）。
- 在场源为空是**合法状态**，读取方必须先看停流标志再读来源集合。
- 计算与上报分离：「字面量 → 网络」只有**唯一**实现，加载与重锚共用（因此重锚不可能把多源网络打回单源）；停流 Issue 同一事实只有一个归属者。
- 网络的**身份键用声明的源集合**，两条都停流的网络不会因「在场源为空」而撞成同一个键。

### 5.5 建网机制

**一条权威推导**：每次变更提交、载入组合件、解析占位时都重算一次派生网络，但**按差量落地**——身份与在场成员都相同的网络**原地保留**（不拆不建），只移除真的消失的、只新增真的出现的。全拆重建会在两步之间留下一个"网络还在、绑定已空"的窗口，模块线程恰在此刻发送就会**静默丢单元**；原地保留同时让绑定上的投递 / 丢弃计数与速率计不被每次提交清零。用户显式建立的网络与组合件里载入的网络一律不动，用户意图优先。派生网络带自动生成标记，拖开即自动断开。

| 机制 | 条件 |
|---|---|
| 命名网络 | 端口**网络标签同名即连**；标签本身即网络名 |
| 对齐网络 | 双方**均未打标签**、两模块**接触且标记对齐** ⇒ 自动连上，名为匿名（直连） |

对齐判定的完整条件（建网行为与界面预览**共用同一实现**）：

- **接触**：相邻边间隙在接触容差以内（贴合后为零）。
- **接触面重叠**：沿接触边的投影必须真正重叠（排除边缘数值巧合）。
- **标记对齐**：两端口标记中心沿接触面的距离在标记对齐容差以内。
- **方向**：发送口 ↔ 接收口。
- **契约**：形状完全一致（不兼容即忽略，不自动转换）。
- **标签**：双方均未打标签。打标签的口只参与命名网络，两种机制不混用。

两个容差的唯一来源 = 建网判定类型（`src/Core/Composition/DockRule.cs`），本文不抄数值；建网判定与拖动预览读的就是这一份。

**拖动中预览**：界面用临时布局向 L4 询问「现在松手会连上什么」，高亮标记并把提示送到状态栏；**实际建网只发生在布局提交之后**。吸附是界面行为，建网是网络行为。

自动建网总开关是一个应用级设置项；口上还有「是否参与自动建网」的声明位。

### 5.6 多对多与逐对判定

- 源集合是列表，绑定按网络建立，**投递逐（源，宿）对**进行。这样保持零拷贝与字节守恒。
- **兼容逐（源，宿）对判定**：只排除不兼容的那一对并记 Issue，其余源照常投递，**网络不整条拒绝**。
- 几何不自动合并：接触对齐的两个口仍各自按源口建网，避免误连。
- 同一（源，宿）对内的多个口对按对角聚合；宿侧多条网络 → 对端有 N 个不同实例就画 N 条线。

### 5.7 队列与旁路头

- 队列粒度 = 每（实例，口）一条有界 FIFO，容量按口计；多口轮转公平调度。
- 入队结果分档：接受 / 队列满 / 无承载 / 已停止（各自计数）。
- **薄旁路头只在多源网络携带**：内含源实例标识、源口名、**按源序号**、接收时刻（单调计数）。
  - 它**随数据单元旁路携带、不进 payload 字节流**，字节守恒不变。
  - **单源网络传空 ⇒ 零附加**：不构造、不入队、不读取。
  - 序号按源从 1 递增，由「每个数据报一次、不受多播放大」的发布计数提供，同时它就是**单元速率（按源计）的分母**。
  - 消费者是**观测面**（诊断）；模块仍然不通过它取来源。

### 5.8 持久化形态

- 网络记录持久化**源列表**（而不是单个源）+ 内嵌版本号；旧组合件必须可读入并迁移。
- 每条网络记录：标签（匿名则为空）、源列表、宿列表、契约引用、是否用户显式建立、是否允许未验证的类型强连。
- 运行态（队列内容、计量计数、绑定对象）与绑定**不随件**。

### 5.9 呈现口径

- 网络标签即网络名，显示在端口标记上；标记**常驻**显示该口参与通路的**有效载荷**字节速率（未入网 `---`；已连接但上一秒无数据 ⇒ `0.00 B/s`，与“没连接”可区分），与叠加层开关解耦。**速率按源计（多宿不放大）；投递/搬运字节按宿计（一条绑定 N 个宿即 N 份）；界面显示的速率只取前者。**
- 叠加层里端口标记**沉到遮罩之下**（做减法，而不是给它加降权样式）。
- 拓扑诊断采用**网络列表 + 单网络诊断详情**：左列表只放状态/网络名/源→宿数，右侧显示诊断结论、链路、源指标表与宿成员；**速率只在源指标表出现一次**，不做网络级汇总；原始 `实例.口名` 只进 tooltip/复制文本。异常网络置顶并默认选中；不画自由节点图。多源网络在叠加层上表现为「多生产者 → 一消费者」，不同源各自一条线，不在界面上合并。

## 6 UI 外壳与窗口

### 6.1 表现形态：拼图式多窗口

- **一模块一窗口**：默认形态是每个模块一个**无边框顶层窗口**（`SystemDecorations=None`，`ShowInTaskbar=false`），背景即桌面，没有工作区背景。
- 外壳主窗口是**拼图的起始点**。
- **模块 ≠ 窗口**：模块不强制等于窗口，窗口只是默认承载形态；框架渲染模块视图，模块不提供 View 类型（见 §2.2）。
- 应用内窗口层级分三带：**固定底带 = 外壳**；**浮动带 = 模块窗口与功能面板（模块清单 / Issue / 设置 / 拓扑）**，同一带按**最近激活**排序 —— 点模块可抬到模型化设置窗之上，点设置窗可回到模块之上；**固定顶带 = 模态弹窗（确认 / 消息 / 重命名 / 关闭询问等）**，永远在最上，打开时禁用低带窗口、关闭后恢复。模块窗口的属主是外壳窗口，外壳永远在模块窗口之下；最小化外壳时模块窗口随之最小化，恢复时一并恢复。
- 任务栏与 Alt+Tab **只出现外壳一项**（写死，不设开关）。
- 应用整体相对其他应用只有两种统一状态，由应用级开关切换：**普通**（任一本应用窗口被激活就把**低带**窗口一并抬到最前，不抢焦点、保持浮动带最近激活顺序；其他应用被激活则整体下沉）与**全体置顶**（外壳 + 模块窗口 + 弹窗一起置前，新窗口按当前状态继承）。**禁止混合状态**。应用内浮动带顺序与这一应用级状态是两个层次，前者不受后者影响。
- 组抬升需要少量平台互操作（取窗口句柄后调整置前次序），只落在界面层，不进入 L1–L4；非 Windows 平台降级为不做组抬升，其余行为不变。输入控件的下拉/弹出层用 `Popup.Topmost` 保证打开时可见，不参与窗口带排序。
- 组抬升需要少量平台互操作（取窗口句柄后调整置前次序），只落在界面层，不进入 L1–L4；非 Windows 平台降级为不做组抬升，其余行为不变。

### 6.2 外壳结构

- **A 区 活动栏**：竖向图标按钮（宽度 = 外壳布局 token），图标化、选中态用可变色滑块；顶部菜单不做，各动作由活动栏入口、侧边页面与弹窗承担。
- **B 区 侧边界面**：竖向排列的常驻页面。**模块清单**与**交互**是常驻页面；**设置**、**拓扑诊断**、**Issue**、**帮助与关于**是弹窗。
- **底部状态栏**：保留 Issue 总数/错误数；活动栏 Issue 徽标只显示**错误级 Issue 总数**（无错误隐藏；警告/信息不显示）。
- 外壳尺寸由设置驱动：比例档位是一组固定选项（选项集合与各自的比例只在设置定义与外壳常量里，本文不抄）与「固定尺寸」开关（缺省开）。固定时窗口不可缩放、尺寸由所选比例推导；关闭时可自由缩放，比例仅作初值。相关常量集中在一处，换比例只改一处。
- 设置弹窗按内容自适应：内容定尺寸 + 宽高上限 + 内容区滚动，不固定大小。设置页「左分类固定宽 + 右页面留白、条目与字段行高、分组标题字重」的规格集中在设置页样式 token 里，本文不抄数值。
- 模块清单每行 = 72×40 预览（共享 `previewTile` 样式；图片居中裁切，无图显示占位字形）+ 名称 + 来源标注（内置 / 外部；需重启并入同一行）；描述在悬停提示里。组合列表复用同一套预览与行结构。

### 6.3 模块窗口形态

- **整块模块、无标题栏**：整块窗口矩形即模块矩形，与建网判定的几何基准一致。
- 边框覆盖整个窗口周界：常规为细线；**选中态在所有选中模块上叠加 2px 半透明选择框**（不带角点，贴客户区外沿、覆盖 Frame 外框，不留白圈）；锚点另有按钮簇与手柄。
- **交互带**：边中点与角点用于缩放，其余区域用于拖动（厚度 = 窗口几何常量）。
- **缩放手柄是固定尺寸的方块**（尺寸只在窗口几何常量里），**只属于锚点**（多选里第一个选中的模块）；其余选中项只有选择框、没有手柄。
- **按钮簇固定在右上角、纯图标**，每个按钮本身有面（与普通按钮同源：圆角、1px 边、hover/pressed/focus），悬停或选中时整簇淡入；命中区与图标尺寸由样式 token 给出。动作为：**壁纸 / 还原 / 锁定 / 隐藏 / 关闭**（壁纸是带 `MenuFlyout` 的图标按钮）。
  - 没有「暂停 / 启用」按钮：模块生命周期由框架权威判定，数据面没有"暂停"语义。
  - **还原**弹确认，选项为：只还原默认尺寸（位置保持）／尺寸和配置都还原／取消。
  - **锁定**的含义：① 不可拖动、缩放；② **不参与拖动组、不随壳体移动**；③ **仍可被选中**（组合范围可包含它），只是不显示缩放手柄。
- 模块名与运行状态以内容区顶部一行轻量文本呈现；状态点与状态文本在**左下角**（弱化色小字号，字号 = 样式 token）。
- **普通点击 = 选中并置顶整个拼接组**（组 = §6.4 的连通分量，锚点 = 被点者；隐藏/占位成员不入组，锁定成员入组）；Shift+点击加入/移出选择集（不改变锚点，不扩组）；Ctrl+拖动仍是独立拖动；点击外壳或其他窗口清除选中。组合页的勾选**不**联动组。
- **一次指针动作 = 一次动作**：输入控件的"提交"只在 Enter / 显式提交时发生，**失焦只结束编辑、不提交**（内容随时由逐键写入的视图状态承载）；被拒绝的动作**撤销并遗忘**，不得作为"意图"跨帧保存后自动生效——否则表现为"报错之后补上参数，它自己就执行了"。
- 模块默认尺寸由 `[ModuleDefinition(WindowWidth/WindowHeight)]` 给出；未声明则由框架地板兜底。**模块尺寸与端口位置只来自代码声明。**
- 窗口最小尺寸的地板由端口标记几何推出（`PortMarkerMetrics.MinWindowExtent`；窗口比标记短会把它裁掉一截），模块声明的最小尺寸**只能抬高**地板；窗口模型构造时夹到有效区间。
- 模块窗口底色可混入极轻比例的主色。

### 6.4 吸附与拼接

- **吸附 = 参照线模型**：一切吸附都是把「被拖模块外框的某个锚点」吸到「某条参照线」上。
- 被拖模块提供的锚点：X 轴 = 左边缘 / 中心 / 右边缘 / 上下边上每个口的归一化位置；Y 轴 = 上边缘 / 中心 / 下边缘 / 左右边上每个口的归一化位置。
- 参照线只有两个来源：其他模块的外框（边 + 中心线）· 其他模块的端口（每个口一条线，**轴由它所在的边决定**）· 外壳（**只提供右边缘一条竖线**，并入同一张线表，不是特殊通道）。
- **候选级别由「线类别 + 交叉轴条件」派生**：贴合（最高）· 端口锚点 · 中心线 · 边缘对齐（最低）。同轴且在去重容差内的多条候选只保留级别最高的一条（该容差只在吸附实现里）。
- 手感参数是设置项：**吸附距离**的缺省值与取值范围只在设置定义里；对齐类容差 = 吸附距离，贴合类容差 = 吸附距离的固定倍数（倍率常量只在吸附实现里）；不设额外的"释放带"。
- **拖动中实时吸附**，离开容差带立即跟手；**不做松手吸附**，**不做网格吸附**。
- **拼接 = 由位置派生的关系**：只保存位置；"是否拼为一组"由边缘贴合（容差判定）派生为**连通分量**；组不是容器，没有布局树、没有停靠槽位、没有标签页堆叠。
- **排版块 = 一种常规模块**：无端口、无功能、只能改大小，与功能模块同级同机制，不引入新概念。
- 外壳纳入拼图：外壳是拼图里的一个节点，与模块之间**只有单侧吸附**（只提供右边缘，"左边缘贴外壳右边缘 + 竖向重叠"），移动外壳时平移整个贴壳平铺组，没拼上的模块留在原处。
- **几何单位：模型位置与尺寸是 DIP，每个窗口另有自己的 `Scale`**。物理投影 = `(X*Scale, Y*Scale, Width*Scale, Height*Scale)`；吸附、成组、建网接触判定、叠加层连线都在**物理像素空间**比较，DIP 只在各窗口边界换算。这样同一拼接组里不同缩放的窗口才能保持物理贴合，而尺寸（DIP）不随屏变。参照线与辅助线按"被拖窗口的 DIP"比较，跨窗时先把对方物理矩形 ÷ 本窗 `Scale`（单一换算函数）。
- **窗口落位：位置与尺寸由同一个整数像素矩形推出**。模型四数是 DIP，按该窗口的 `Scale` 投影后把四条边各自取整成物理像素；窗口位置取 `left/top`、尺寸取 `(right-left)/缩放`（再给一个亚像素偏置抵消平台取整差）。这样模型里相邻的两块在任何缩放/跨屏下公共边都是同一个整数像素 —— 分别对位置和尺寸取整会让 `round(x·s)+round(w·s) ≠ round((x+w)·s)`，表现为拼接处偶发 1px 缝。回写只发生在无布局记录的首次且以一个设备像素为容差。
- 落盘只改内存 + 防抖合并提交；布局格式是 DIP + 可选 `scale`（旧文件缺省按读取时屏缩放），"跟随"只是贴壳时的行为，不是相对坐标存储。

### 6.5 端口标记标准件

- 尺寸 = 跨轴宽（即预留带厚度）× 沿边长度，**与模块外边框完全重合**；尺寸与固定槽位的唯一来源 = 几何度量类型（`src/Ui/Geometry/PortMarkerMetrics.cs`），本文不抄数值，也不进样式 token。
- 内容 = **固定槽位**（数值右对齐、固定小数位，空值 `---`，信息变化不引起排版抖动）：

| 槽位 | 内容 |
|---|---|
| ① 类型窄色条 | 颜色 = 类型身份色（宽度 = 几何度量） |
| ② 网络名 | 优先占用剩余宽度（空间不足先裁速率，因名字是网络身份信息）；取值三态 = 标签名 / 已连但无标签「（直连）」/ 未连「无网络」 |
| ③ 方向箭头 | 定宽列（列宽 = 几何度量），按边取向外 / 向内：发送口向外、接收口向内 |
| ④ 连接指示灯 | 定尺寸方块（尺寸 = 几何度量），贴到标记端部 |

- 标记上**不写连接状态文本，也不写类型文本**：连接状态由指示灯的颜色与形状双重编码承担；类型只在悬停提示里给出。
- 悬停提示：`口名（方向）` / 状态 / `类型：X` / 网络名 · 对端 · 投递 · 丢弃 · 流量；提示行**不含**"上次操作"（提交结果送状态栏）。
- 双击标记填写 / 清除网络名；编辑弹窗只放标题、输入框与按钮，多句提示收进标题右侧的 `?` 帮助浮层，失败原因仍在弹窗内就地显示。
- 标记**常驻**显示通路速率（字号比名称小一号），与叠加层开关解耦。
- 标记内元素的字号与尺寸集中在样式 token 里（本文不抄数值）；标记整体尺寸只在几何度量类型里。
- 竖排分支整体旋转（旋转量只在标记绘制常量里），因此"色条在最前、灯在最末"在屏幕上表现为灯在上端、色条在下端。

## 7 叠加层与视觉基线

### 7.1 叠加层语义与开关

叠加信息层是**调试与观测层**，不是编辑层。

- **默认关闭**，快捷键 **`L`** 切换；设置页与快捷键入口共用同一状态源。
- 外观 = **灰玻璃**：一层半透明深色遮罩压在模块内容上，其上文字一律用浅色墨水（遮罩是深的，因此两套主题共用同一套叠层墨水）。**遮罩浓度是样式 token，浅 / 深两套主题共用同一值**（本文不抄数值）。不做背景模糊，不进设置项。
- 遮罩 `IsHitTestVisible=false`、覆盖整窗；叠加层**不参与命中**，不自绘任何文字控件，全部走绘制上下文。
- 层级（自下而上）：**内容 → 遮罩 → 端口标记 → 连线层 → 运行指示 / 按钮簇**。端口标记**沉到遮罩之下**（被灰玻璃压暗），连线跨过标记直达对端。
- 虚线相位由**一个共享时钟**驱动（节拍 = 时钟常量，只在时钟实现里）：一个定时器 + 弱引用订阅；叠加层关闭时退订，无订阅者时停表。
- 坐标系纪律：叠加层控件的绘制单位是 **DIP**；模型位置/尺寸也是 DIP，按本窗 `Scale` 做物理投影。跨窗/跨缩放时先算**物理中心差**，再 ÷ 本窗 `Scale` 回到局部 DIP（`ResolvePeerAnchor` / `ResolvePeerCenter` 是唯一换算点），别处不许再乘除缩放。画布用负边距抵消窗口边框线宽，使画布正好等于窗口客户区，两窗拼接处两段严丝合缝。
- **身份用外部语义，不用实例 ID**：左上信息区 = **模块展示名 + 现场连续编号**（不显示 `text-sender-1` 这类底层标识）。编号按当前 `Modules` 顺序、以展示名分组现场重算：关闭一个实例后剩余实例重排，新实例补到当前数量之后，不保留关闭实例的旧全局编号。

### 7.2 信息维度

同一份框架诊断被**两个不同的对象**表达，不能因为底层同源就当作一个维度：

| 维度 | 画在哪 | 内容 |
|---|---|---|
| 角色维度 | **角色方块**（及其周围的纯文字） | 这块功能自己在跑多快 |
| 通路维度 | **端口标记**（网络标签） | 这条网络在跑多快 |

### 7.3 角色方块

- 一个模块的方块数 = 该实例声明的数据角色数；同类型的发送角色与接收角色**各一个方块**。
- 方块尺寸：宽度随文本自适应、**夹在几何常量给出的上下限之间**，块高统一（具体数值只在角色方块布局常量里）。宽度估算必须是**确定性纯函数**（CJK 字宽取字号、拉丁字宽取字号的固定比例、留固定余量；系数只在宽度估算函数里）——宽度同时被**两端**用来算连线锚点，一旦依赖渲染期排版，字体或主题差异会让两侧不一致而线错位。
- 方块内两行：第一行 **功能名**（为空则类型短名），第二行 **`m/n`**。
- **填充 = 类型色**（按类型身份，跨模块一致）；**左侧接口边 = 接收方向色、右侧接口边 = 发送方向色**（一个方块可同时有两种颜色的边）。方向小箭头与边框同色。
- **刻痕只在某一侧口数多于一个时画**（单口是常态，不加噪）；类型长文本不进方块（靠颜色与悬停）。
- 摆放 = **单列竖直堆叠、居中**，按声明顺序；放不下则只画得下的 + 底部 **`+K`**（如实报出未画数量）。方块 v1 不参与命中。
- **自回环**（同实例、同角色）画成方块外侧的环线 + `↻` 标记；判据只看呈现身份（对端实例/角色 = 本实例/本角色），**不读**网络类型、口数、命名/显式连接。自环不画"未拼接"断口、不标对端名。
- `m/n` 的定义：`m` = 本角色**输入侧连接的对端角色数**，`n` = 输出侧同定义；去重键 =（对端实例，对端角色），因此同一对端角色的多个口连到本角色仍算 **1**。**没有该方向的口 ⇒ `--`**（与该方向是否连上无关）；**有口但没连 ⇒ `0`**（两者含义不同，必须区分）。`m/n` 由框架从网络成员关系**派生**，模块不得自报。
- **角色自身信息画在方块周围 / 上方的纯文字**（不画文本框），三行：

| 行 | 内容 |
|---|---|
| ① | 该角色**自身**速率（无流量 `---`），主色大字 |
| ② | 投递 … · 丢弃 …（丢弃 = 传输丢弃，停流未投递不混算） |
| ③ | 类型语义 · 标称速率（未声明则不占位） |

位置默认在方块上方（居中，与方块留固定间隙，间隙值只在布局常量里），上方放不下自动改到下方，一律留在留白以内。聚合口径 = **产出侧优先**：有输出口就聚合它的**输出侧各口所承载的绑定**，纯汇分块才聚合**输入侧各口**；**同一绑定只计一次**（多宿/多口不放大）；**不把入 / 出两侧相加**（那是多条通路的和，会被读成"总吞吐"）。速率按源计，多宿不放大。

### 7.4 连线

- 一条线 = **两角色方块中心的连线**（纯函数算出的唯一一条线段），每个窗口只画**这条线段与自己窗口矩形的交集**，并且画出来的那段落在**本端方块之外**。因此视觉上从方块中心方向出发，又不会在方块里留一道淡线、也不横穿方块。
- **两侧严格共线**：两端用同一套角色布局与同一个线段函数，所以相邻拼接时两段正好接上，看起来是一根连续的线；未拼接时各自止于自己的边界，缺的那段恰好是两窗之间的空隙（"看起来缺一段"可接受，"两根错位的线"绝不出现）；窗口重叠时两段仍共线。
- **虚线沿数据流方向流动**：线的几何恒按数据流方向绘制，两侧取**同一个负偏移 ÷ 线宽**。偏移量的语义是实测约定——**偏移增大时虚线图案整体朝几何起点移动，且单位是笔宽的倍数**（不是 DIP），取负才能让图案从起点向终点前进；除以线宽才能让速度不随线宽变化。发送侧表现为向外流动，接收侧表现为向内流动。
- **箭头画在指向本模块的那一端**（发送 ⇒ 朝窗外；接收 ⇒ 朝本端方块）。
- **断口与对端名画在窗口边界那一端**：未拼接时画一段竖杠断口 + 对端名，拼接时不加任何标记。线上**不写任何文字**（网络名与条数都不写）。
- 一条网络的不同源是**不同的对端角色** ⇒ 各自一条线，不在界面上合并。
- 对端角色不可用时按回退链逐级降级、绝不猜：① 对端角色方块中心 →（未装入 / 对端没有该角色 / 占位实例）② 对端窗口中心 →（对端不在现场）③ 沿本端接口边方向出窗。
- 类型转换表现为两个方块 + 两条线，各按自己的类型色。

### 7.5 类型颜色表

- 位置：侧边栏**交互页**的「数据结构 · 颜色」分区（带帮助问号 + 空态 + 列表）。**只作图例，不做指标面板**。
- 一行 = **一种数据类型身份**（`标识@v版本`；未声明类型的模块按结构描述）。列 = 色块 / 类型身份（等宽字体、超长省略、悬停给全文）/ 形状文本 / 用在（N 个口 · M 个角色）。
- 颜色来源两级：① 用户覆盖色；② 否则**稳定哈希自动色**（同标识恒同色，跨模块、跨进程、跨重启一致）⇒ 不配置也能分辨类型。
- 色板是**唯一**的色彩来源：端口标记的窄色条与角色方块的填充共用它，改一处两处同步。改色**只影响呈现**，不参与建网 / 兼容 / 停流 / 投递 / 计量，**不进组合件**。
- 表里只列**现场真出现过的类型身份**（来自各实例的端口类型身份与角色类型身份）；"声明了但没用上"的类型不列。空态是一句事实。
- 键与端口标记、角色方块用的键同源（类型身份），**不用呈现文本**作键：不同标识即使形状相同也是不同的量。
- 持久化为应用级设置里的一个类型身份 → 颜色映射；**缺省不写任何条目**（不配置 = 自动配色，不产生死数据）。
- 落盘入口唯一：改色 → 设置色板覆盖 → 写设置 → 让界面重画。刷新时**就地改值、不重建集合**——重建会让正在打开的弹窗与悬停目标被销毁，表现为鼠标指到色块上不停闪烁。
- 类型颜色是**一套全局颜色**，由用户自己改、与主题色解耦（换主题不改用户已选的类型色）；只有调色板的推荐色与主题同一套。

### 7.6 配色与字号纪律

- **方向语义色与主题色完全解耦**：方向色有自己的内置默认值（浅 / 深两套各一份），主题色只表达"选中 / 聚焦 / 活动"等框架性交互语义。
  - 浅 / 深两套主题各有一份内置默认方向色（发送 / 接收各一），默认刻意避开红绿对（色盲友好）；色值只在视觉 token 里，本文不抄。
  - 设置项默认空串 = 跟随主题内置默认值；**不做任何校验或提示**（个性化内容不干预用户立场）。
  - 一致化范围 = 箭头 + 标记框 + 叠加层流向箭头 + "即将建网"描边（同一方向色，仅以线宽分档区分）。
- 主题色只管"模块共有元素 / 框架性颜色"；模块私有绘图配色由模块自己决定。
- **颜色设置准入判据**：① 该语义在多处出现 ② 用户改色后仍能靠形状或位置读懂（双重编码）③ 两个颜色同屏同时出现且需要区分。全部为"是"才开设置项；用户可调的颜色总数宜少（设计取向，不是框架强制的上限）—— 它约束的是"**为某个语义再开一个专项控件**"。**「主题色板」是另一回事**：它不新增语义，只把已经存在的相对色**逐项可覆盖**；**一个主题方案对应一份色板**，设置页一次只显示当前方案的一列，不再并排浅/深两栏。主题色 / 发送 / 接收 / 语义状态都是普通 token，统一进色板；编辑内置方案会自动复制为自定义方案，方案随「应用 / 确认」落盘。
- **主题 ≠ 字体 / 数据颜色 / 窗口行为**：字体是全局显示偏好，不随方案切换；数据结构颜色是交互页的全局身份映射，不随主题；窗口比例、置顶、吸附、刷新率是行为设置，不进主题方案。主题的唯一边界 = 色板 token。
- 取色统一为**一个调色板窗口**：左侧取色器（光谱页 + 分量页＝RGB·HSV 滑块 + 十六进制输入 + 当前色预览条）+ 右侧常驻一组推荐色（条目 = `Core.Api/ThemePresets.cs` 的推荐色目录，本文不抄）；不带透明度；去掉控件自带的色板页签与强调色增减块，使推荐色只有一个来源。全应用只有这一种选色交互（**色板里任意一格** + 交互页的类型颜色块）。
  - 调色板窗口的模板必须显式挂载样式，否则**不报错、什么都不画**——窗口只剩标题、提示与按钮。
  - 布局纪律：标题只由窗口标题栏给（窗口内不重复）；提示文字整行独占并自动换行；按钮单独一行右对齐；窗口按内容定尺寸。
  - 调用方自己解释「恢复」：类型色 = 移除覆盖；色板里的格 = 清掉那一格的覆盖（回到跟随）。
- 视觉 token 是**唯一来源**：主题切换只替换 token 值，视图里的取色方式不变（动态资源自动刷新，模块窗口、弹窗、叠加层一并跟随）。色板覆盖：背景、模块底、外壳底、边框与文字的层级、主色与辅色、方向语义色（发送 / 接收）、语义色（正常 / 警告 / 错误 / 空闲）、选中与高亮叠层、叠加层遮罩与叠层墨水分级、内部结构线色、按钮面与边、开关与页签等专有键。**键表、分组与"谁跟随谁"以 `Styles/palette.json` 为准，本文不抄**。
- 字号与尺寸 token：控件高与字号、缩放手柄、交互带、端口标记各字号、箭头、灯、色条宽、模块圆角全部落在视觉 token 里，本文不抄数值（圆角必须用圆角类型，写成数值会在运行期抛类型转换异常）。
- 字体：界面与数据**各是一条"西文 + 中文"的轴**（默认 `Segoe UI` + `Microsoft YaHei UI` / `Cascadia Mono` + `宋体`），用户可分别设置；**不引字体包**。
- **模块表面的文字墨色只有三档**：值（读数/输入内容）用 `TextPrimary`；字段标题、区标题、读数标题用 `TextSecondary`；说明/提示用 `TextMuted`（错误用 `SemanticError`）。**单位不是控件的概念、也没有"单位槽"**：静态单位（`ms` / `条` / `个`）就是视图里一个普通标签；字节计数的 B/KB/MB 是值文本的一部分（`ByteQuantity` 唯一实现）。标签与值各占自己的矩形，基线由各自的单行文本保证；不再把单位塞进读数的第三列。图标是**显式 SVG**（框架 `resources/icons/<owner>/`、模块包内 `resources/icons/<owner>/`；`icons.json` → `.svg`，见 §8.6），界面经 `IconButton` / `Glyph` / `ModuleButton.Icon` 的 `Icon` 取；填充色跟随 `Foreground`，**不手绘几何**。
- **主题壁纸**：主窗口壁纸属于主题方案（系统内置浅色/深色默认无；樱色是编译期 seed 投放的**普通自定义方案**，带受管壁纸）；模块壁纸属于实例 presentation，随组合件/工作区。所有壁纸居中裁切、直接使用原图并叠主题色 veil；遮罩浓度属于当前主题方案。图片选择统一走应用内全局裁切器。
- 内部处理关系线用细实线 + 中性低对比色 + 小箭头，端点落在角色方块边缘，**不走方向色渐变、不参与流动相位**——否则会被误读成"这里也有数据在流"。

### 7.7 模块界面：代码声明 + XAML + 控件库

**唯一事实源只有两份，各管各的：**

| 事实 | 唯一落点 | 例子 |
|---|---|---|
| 窗口尺寸 / 端口边与偏移 / 显示源 / 输入源 / 命令 / 配置字段 | 模块代码（`[ModuleDefinition]` + `OnRegistered` 的 `Declaration`） | `WindowWidth=400` · `PortDeclaration.Edge` · `DeclareDisplaySource("rxCount", …)` |
| 布局与控件组合（含每个元素的坐标） | 模块自己的 XAML（`Views/*.axaml`）——**坐标全部内联在这一个文件里**（唯一视图事实源、预览器直接看它、编辑点只有一处） | `<ui:ModuleLabel … Classes="caption right" Canvas.Left="0" Canvas.Top="0" Width="56" Height="24" Field="{x:Static views:SerialViewKeys.PortName}" />` + `<ui:ModuleConfigField … Canvas.Left="60" … Width="100" … />` |

**坐标归模块、框架不持坐标**：模块视图用 `Canvas` + 显式矩形（`Canvas.Left/Top` + `Width/Height`）摆放固定控件，坐标**只写在视图的 `.axaml` 里**；框架只提供控件、主题与"内容区多大"（`Ui/Geometry/ModuleSurfaceMetrics`），**不在框架里写任何模块控件坐标**，也不替模块做自动排布、不要求同一个视图里各行的数字必须相同（每一行怎么摆是该视图自己的决定）。模块之间**没有代码耦合**：相似模块各写各的坐标，不共享常量类。

**没有界面描述文件。** 不写 `view.json`、`view.schema.json`、控件目录或 kind 派发表；一份界面事实只能有一个家。AR-20 / AR-21 / AR-22 是它的可执行检查。

**键必须经 `x:Static` 引用模块常量**：`Source` / `Field` / `CommandName` / `StateKey` / `Icon` 写字符串字面量在编译期完全合法，但写错只会在运行期变成空白或"点了没反应"；常量拼错则是编译错误。配置字段名用 `nameof(ConfigType.Property)` 锁到配置类型；外壳的 `IconButton` / `Glyph.Icon` 用 `ShellIcons` 常量（分类/锚点这类随状态变化的值允许绑定）。

**控件库（Sdk.Ui）只放标准控件承载不了的行为**：提交时机、页签状态、配置字段编辑器、数值显示、状态灯角色、日志跟随尾部、运行期外观通道。纯外观差异改主题；纯布局在 XAML 里摆；不要为"看起来不同"新建 kind / 描述表。**控件不承载标题**：字段标题、读数标题、区标题、单位都是独立的标签控件（`ModuleLabel`），由视图分别摆放 —— 标题若长在控件里，它的文本宽度就会替视图决定邻居还能剩多宽。**图标按钮**：模块用 `ModuleButton.Icon`（键 → 模块包 `resources/icons/<程序集简名>/` 的 SVG；视图给矩形、`ToolTip` 说明用途），外壳用 `Ui.IconButton` / `Ui.Glyph`（键 → Ui 表）；图标是**显式 SVG**（见 §8.6），`Icon` 控件跟随 `Foreground`，按钮与普通按钮同面（`ButtonChrome` 五态）；视图里不画 `Path`、不写码位；不引入图标包。

**视觉结构也只在主题里**：需要自绘的 `ui:Module*` 控件在 `Sdk.Ui/Themes/Controls.axaml` 有一个 `ControlTheme`（`PART_*` 命名部件），C# 控件只取部件、管行为；控件构造函数里不许 `new Grid` / `new TextBlock` / `new Ellipse`（AR-21）。`ModuleButton` 用应用级 `ButtonChrome`，`ModuleTabs` 用 `TabControl` 主题。**布尔一律用 `ModuleToggle`**（同一套轨道 + 圆钮模板；输入源与配置字段共用），不再让配置表单用勾选框、视图用另一种开关；配置字段的文本/枚举用 `TextBox` / `ComboBox`，**编辑器只在自己的矩形里排版，不画标题**。

**视图必须填满内容区**：`ModuleViewHost`（`Horizontal/VerticalContentAlignment=Stretch`）与 `ModuleView`（同样的内容对齐）是这条的唯一落点。模块 XAML **不写外圈 margin**：预留带与描边由 `Ui/Views/ModuleSurfaceView` 从 `Ui/Geometry/ModuleSurfaceMetrics` 取，端口标记与运行指示叠在预留带里；否则标记会压住模块自己的控件，且 `*` 行列拿不到余量、最右读数被裁。

**文本面只有一个 `ModuleTextSurface`**：`Mode=Input` 时用 `TextBox` 叶子（光标、编辑选择、提交），`Mode=Display` 或 `IsReadOnly=true` 时用 `IncrementalTextView` 叶子（只读、可跨行选择/复制，没有编辑器光标）。`IncrementalTextView` 按“逻辑行 + 视觉行”缓存 `TextLayout`：追加只布局新增行/最后一个视觉行，只绘制可见行；完整回看、自动折行、选择/复制、`↵` 与跟随尾部都保留，刷新仍跟随全局节拍（没有新内容时零工作）。超长单行按 512 字符分块布局，但**上一块的最后一个视觉行必须拼到下一块前面再布局**，否则块边界会硬断，拉宽后出现没有规律的长短行。**滚动偏移由外层 `ScrollViewer` 负责**：控件在内容坐标里绘制与命中，`Render`/`HitTest` 不得再减/加 `ScrollViewer.Offset`；双重偏移会让滚到尾后只剩空白、新文本错位。两种叶子共用同一个模板、`PART_Frame`、`PART_ErrorRing`、数据刷新与只读策略；`NewlineMarkOverlay` 现在只服务可编辑 `TextBox`，只读面的 `↵` 由增量控件按真实换行绘制。`↵` **只标数据里真实的换行字符**，自动折行与通道换行不标。边框只有 `BorderDefault` 一种；**声明只读（`Display` / `IsReadOnly`）才换叶子**，运行期只读（外观通道）**不换叶子**、只停止编辑（光标隐藏、仍可选中复制），框与圈不变；选择背景两者都是 `OverlaySelection`。错误圈是模板里的 `PART_ErrorRing` 叠加层，画在焦点/选择边框之上，选中不会盖掉红框。多行输入的换行与提交时机在 `ModuleTextSurface` 一处。

**预览器自包含**：模块视图基类 `ModuleView` 在**设计时**补上 `Sdk.Ui/Themes/Controls.axaml` 与一份设计时 token；宿主未挂控件主题时只补**同一份**控件主题，不加载设计时 token。运行时 App 已挂主题则不重复。模块 XAML 另带 `d:DesignWidth/Height` 与 `x:DataType`，预览器才能看到真实尺寸与模板（这两个值只在预览器里生效，运行期读不到；它们的规则是"等于内容区尺寸"）。IDE 里打开模块 `Views/*.axaml` 时，预览器目标选 `HYWDebugAssistant.PreviewHost`（`tools/PreviewHost`，引用全部模块的可执行宿主）；类库本身不能作为预览目标。预览宿主显式置 `ModuleView.IsPreviewHost`，设计主题/设计时上下文由"谁在预览"决定，不依赖外部一定设置了 `Design.IsDesignMode`。带配置字段的模块视图可用 `[ModuleViewDesignData(typeof(…Config))]` 指定模块自有配置类型；外部接入的参数类型在框架侧，则用 `[ModuleViewDesignData(ExternalAccessStandardIds.Xxx)]`，由预览宿主把标准标识映射到配置类型。`DesignModuleViewContext` 从同一份 `[ConfigurationField]` / `[ConfigurationChoice]` 标注反射出标题、编辑器与选项，预览器里的左侧参数区才不是空的；它的 `ReadLatest` / `ReadText` 还给**样例值**，于是预览里读数和标签本来就有墨迹。

**预览里的空标签有占位框**：`ModuleLabel` / `ModuleNumeric` 的模板带 `PART_Placeholder`（虚线框，不参与布局），只在"预览环境 + 文本为空"时显示 —— 完全透明、没有内容的标签也有一个框，排版时才看得见。产品运行不显示。

**页签观感与内容拉伸**：`ModuleTabs` 用自定义 `TabItem` 的 `ControlTheme`：**直角**标签、选中 = 淡主题色底 + 2px 主题色下沿，未选中透明 + 次文字；页头文字不因选中改字号/字重；整组页签由 `ModuleTabs` 的 1px 外框圈住，明确“这组页签管哪块内容”。主题必须通过 `TabControl.ItemContainerTheme` 的**本地值**挂上——Fluent 的 `TabControl` 主题会给容器设自己的 `TabItem` 主题，外部 `TabItem` 样式或 `TabItem.Theme` 会被它盖掉，表现为“只有选中底色生效、内边距/下沿全不变”。下沿放在 `Padding` 外的模板根层，才会横过整个页签而不是只横过文字。`TabControl` 的 `ContentPresenter` 必须 `Horizontal/VerticalContentAlignment=Stretch`，否则页内容按 desired width 收缩，上下两个页签里的文本框会看起来不一样大。

**视图契约**：每个模块一个 `IModuleViewFactory`，由 `[ModuleDefinition(ViewFactory = typeof(…))]` 指到。框架每帧只做一次遍历：`ModuleElement.Refresh` + `ApplyAppearance`；页签等不能继承 `ModuleElement` 的控件实现 `IModuleViewElement`。

**运行期外观通道**：模块经 `IViewAppearanceAccess` 按源名设边框色/角色/文字色/字号/只读；落点唯一是 `ModuleElement.ApplyAppearance`。运行期只读只改编辑态（`IsReadOnly`、不进 Tab 序、隐藏光标），**不换控件、不改边框**，也不用 `IsEnabled=false`；声明只读（`Display` / `IsReadOnly`）才换文本叶子。角色词 → token 的映射只在宿主色板（`Ui/Theming/PaletteManifest`）；控件不认色值，也没有第二张映射表。

旧声明键到控件属性的映射（迁移参考，不是新词汇表）：

| 旧键 | 现在 |
|---|---|
| `data` / `input` | `ModuleElement.Source` / `ModuleTextSurface.Source` |
| `field` | `ModuleConfigField.Field`（编辑器）+ `ModuleLabel.Field`（标题，两者各自一条矩形） |
| `command` | `ModuleButton.CommandName` |
| `stateKey` | `ModuleTabs.StateKey` |
| `unit` | 普通标签（静态单位）或值文本的一部分（字节计数）；**没有控件级单位属性** |
| `title` | 一个 `ModuleLabel`（`Text` / `Source` / `Field` 三种来源，视图只用一条） |
| `multiline` / `readonly` | `ModuleTextSurface.Multiline` / `IsReadOnly` |
| `fontSize` / `textColor` / 角色词 | 主题样式或运行期外观通道；不写进视图 |

### 7.8 主题分层与合并顺序

| 层 | 文件 | 内容 |
|---|---|---|
| 1 token | `Ui/Styles/Tokens.axaml` | 浅/深两套色板与角色 token（**唯一的色值来源**） |
| 2 应用壳 | `Ui/Styles/Controls.axaml` · `ButtonChrome.axaml` | 全局控件高/字号、按钮五态 |
| 3 Fluent 桥接 | `Ui/Styles/FluentBridge.axaml` | 模板自带颜色的 token 化（按钮 / 滚动条 / 列表 / 浮层 / 提示；输入控件改由第 5 层画） |
| 4 模块控件库 | `Sdk.Ui/Themes/Controls.axaml` | `ui\|Module*` 的尺寸/类样式；**只引 token，不写色值** |
| 5 输入 chrome | `Ui/Styles/InputChrome.axaml` | `TextBox` / `ComboBox` / `ComboBoxItem` 的框、焦点圈、错误圈与候选项底色（宿主与模块共用，**唯一来源**） |

`App.axaml` 的合并顺序固定为 **FluentTheme → Ui/Controls → ButtonChrome → FluentBridge → Sdk.Ui/Controls → InputChrome**；后加者赢。控件库不自带色值，依赖宿主 token —— 宿主是唯一色源，换主题/用户改色不需要改控件代码；输入控件的绘制只在 `InputChrome` 一处，`FluentBridge` 与模块主题都不许再写它们的边框/底色。**chrome 不写尺寸，但必须清掉外来主题的尺寸下限**：Fluent 的 `TextBox` 主题带 `MinWidth=64`（`TextControlThemeMinWidth`），只覆盖 Template 清不掉它 —— 48 宽（内容 46）的间隔框会被撑到 64，右对齐文本的末位就跑到框外；因此 `InputChrome` 显式 `MinWidth=0`，文本面内层编辑器再用 `Height=NaN / MinHeight=0` 由视图矩形拉伸。

**状态只改颜色与叠加层，不改几何**：悬停不得加粗（只改颜色）；焦点/选中用 2px **叠加圈**表达，不改边框厚度（输入框与文本面同一口径，聚焦不得让文字位移）；标红用 `PART_ErrorRing` 叠加圈，不靠改内层边框厚度，因此不会被焦点/选择盖住。字号与窗口内容内缩不随状态变。按钮/页签/输入控件的**外观**由主题统一；视图里的固定控件（配置字段、按钮、开关、读数、标签）显式给绝对坐标与尺寸，只有文本面交给星号布局。

### 7.9 内容放不下与布局纪律

- **固定控件的布局走绝对坐标**：配置字段、按钮、开关、读数、标签在 `Canvas` 上用 `Canvas.Left/Top` + 显式宽高摆放；它们不参与流式拉伸，窗口变宽时位置不漂。坐标以**内容区左上角**为原点，内容区尺寸的唯一算法是 `ModuleSurfaceMetrics`（窗口 − 描边 − 预留带），视图的 `d:DesignWidth/Height` 与它一致。
- **坐标只有一个主人**：视图给每个元素一条矩形；控件只在自己的矩形里排版，**不外扩、不带"让外部墨迹偏移"的边距、外尺寸不随内容变**（放不下就显式截断）。坐标全部内联在视图的 `.axaml`（预览器看到的就是它，编辑点只有一处）；框架不持坐标、不替模块排布，也不要求同一视图里各行的数字相同。
- **标签与编辑器各一条矩形**：字段 = 一个 `ModuleLabel`（`Field` 取配置元数据）+ 一个 `ModuleConfigField`（只有编辑器）；宽度不够时**加宽标签的矩形或删字**，不再有"标签换行/堆叠"这种由控件内部决定的形态。
- **读数 = 标题标签 + 值**：值的单位若为静态（`条` / `个`）就是第三个普通标签；三者要"标题 + 值 + 单位"整体紧排时，放进一个**声明矩形**里靠右的横向 `StackPanel`（组内相对、组矩形绝对），右缘不随数字宽度漂。
- **只有大文本面自适应**：页签内容、日志、转换器的输入/索引区放在 `Grid` 的星号行列里随窗口伸缩；转换器每半区是一个页签控件，**结果文字面放在选中页内容内部**：页签头固定（Auto），页内容内部用 `*,*` 等分输入与结果。页签头因此完全不参与输入/结果的等分，输入文字区与结果文字区像素级同高，上下对应区也同高，底部结果不会被裁掉；不再用代码按实测头高调整行高。HEX 输入/结果的 `ShowNewlineMarks=False`：HEX 里的换行只是格式，不显示 `↵`；字符串输入/结果仍按真实换行标记。
- **文本装不下时先动文字，不动坐标**：① 预留够（按最长标题给矩形）② 字号档位（标签 11，说明 10）③ 换行（仅正文类）④ 显式省略号 + 悬停全文（标签与值默认 `CharacterEllipsis`；状态行这类长度不受控的文本**必须**声明截断，不许静默硬切）。构建期用例按真实字体量宽：静态标签装不下即失败，动态标签必须声明截断。
- 窗口尺寸是**初始/最小尺寸**；固定控件不随窗口重排，文本面吃余量。内容放不下由控件内部滚动处理。
- 控件自己负责"值没变就不碰视觉"：刷新不得重建控件对象（否则悬停/焦点/滚动位置会丢）。
- 自绘几何（曲线、灯、滑块）仍遵守"一个量化点、同一坐标系、设备像素取整、先问 NaN"的旧纪律；这些行为住在控件里，不回到声明面。

### 7.10 提示与帮助

- **按长度分三层**：短语（≤十几个字）直接显示；**一句解释挂标签的 tooltip**（控件本身只放"怎么用"）；**多句/教程进帮助入口**——**页面级**帮助（讲整页怎么用）放在**页面顶行右侧**、**列表框之外**（放进某个列表的框里会让人以为它是那个控件的帮助），分区级帮助放在分区标题行右侧并保持 X 对齐，正文在弹出层里（可滚动/可换行），不就地展开。
- **常驻提示只留必要的一句**：列表的"双击做什么"不收进界面常驻文字，而是并入帮助正文（或空状态）；界面上的常驻行只放状态与必要说明。
- **悬停提示始终不透明**：它跟着指针走、会叠在各种界面之上，半透明会让文字对比度变低——这与"控件表面不透明度"是两回事（控件不会互相堆叠）。所以提示层的底色必须取**不参与 `surfaceOpacity` 乘算**的 token（`surface` 标记的底色会被乘成半透明）。
- **帮助与 tooltip 不重复**：帮助讲"这一区怎么用"，tooltip 讲"这个控件做什么"；同一行只留一个 tooltip（挂标签），搜索框的 `PlaceholderText` 只放示例词，不承担说明。
- **列表：条目根部一个提示**（标题 + 简述，指针落在行内任意位置都出同一个提示）；列表容器**不挂**提示，"双击做什么"用一句常驻说明或空状态表达。
- **条目根必须参与命中**：容器行为透明背景的布局元素（如 `Grid` 无 `Background`）在空白处不命中，指针会落到祖先容器上——挂提示的条目根要显式 `Background="Transparent"`，否则会出现"必须指到文字上才看得到提示"。
- **状态行共用一条**：错误与提示用同一行标签，错误才带红框；提示（如"间隔过小可能不准"）不带红、不阻断操作。

**文案口径（两类读者）**

- **给用户看的**（控件、状态、提示、帮助）：短句，只回答"做什么、结果怎样"；不出现内部概念（契约、承载、订阅、视图状态、落盘、口径）和代码名（类名、方法名、§ 编号）；括号只放单位、示例与可选项。帮助讲"这一区怎么用"，不再复述控件 tooltip。
- **给排障者/模块作者看的**（Issue、异常、声明校验）：动作 + 原因 + 关键值（标识、路径、端口、字节数），异常消息原样附在末尾；保留"已忽略 / 已丢弃 / 未保存"这类结果，不写教学式长句，不引用文档章节。
- **能生成的不写死**：数量、路径、当前快捷键、从设置解析出的绑定都从数据生成；文本表只存格式与说明（例：快捷键清单由 `HotkeyService` 按当前绑定生成，表里只放作用域与用法）。
- **术语统一**：端口、连接、发送端/接收端、模块包、方案（主题）、工作区；不混用"口 / 接口 / 通道"，也不在用户文本里用"源 / 宿"（那是拓扑页的排障词）。

## 8 应用设置

### 8.1 组合、模块数据与框架数据

- **组合件 = 一次保存的模块组合关系**：模块集合 + 连接 + 配置 + 位置 + 活动面。它不是运行时实体、不是库、也不是文档；保存与加载都是**一次性动作**，没有“当前组合文件”、没有脏标记、没有最近列表。
- **加载 = 加载一批模块**：与单独加入模块同构；实例 ID 与当前现场冲突时只重映射冲突项，标签/网络名/配置/位置原样保留；同名标签仍按命名网络语义并入同一张网。
- **组合页**：顶部搜索可用组合；“可用组合”列表占主要高度（预览占位 + 名称 + 模块数/缺模块标注），**框内 `加载 / 删除 / 重命名 / 更换封面` 针对当前选中组合**；`导入组合… / 重新扫描` 放在框下（针对整个可用组合区）；“已选模块”固定较矮并内部滚动（名称 + 移出；无运行状态）；组合名一行，`保存组合` 与 `另存为…` 同一行；提示与状态共用一个紧凑 footer。选中模块的主入口仍是模块窗口；`全选现场` 可把隐藏/占位模块加入范围。加载 = 追加一批模块；不是库。
- **组合删除/重命名**：都只操作默认目录下的组合件包（旧扁平 `.json` 兼容）。删除确认后执行，不影响当前现场已加载模块；重命名只改包目录名，目标已存在则拒绝。外部路径/目录拒绝；失败进 Issue。
- **操作反馈**：两页共用固定 18px 的 `operationStatus` / `operationHint` 单行区（省略 + ToolTip）；状态只显示短句，完整路径/逐条失败进 ToolTip 与 Issue 中心。信息出现/消失不得改变列表尺寸。
- **组合导入**：外部组合件包（或旧扁平 `.json`）先只读检查，通过后复制进 `composites/`；包连同封面与 `assets/` 一起复制，同名内容相同则复用，不同则唯一命名；外部文件不直接加载。
- **按功能分根**（路径只从路径解析器取，目录按需创建）：每个顶层目录 = 一个功能在磁盘上的家，包含关系与界面一致：

```
<程序目录>/modules/            模块（内置包）
<程序目录>/modules/external/   外部导入模块包（来源标注为「外部」）
<程序目录>/composites/         组合（用户组合件包默认目录；外部导入复制到这里）
  <组合名>/composite.json      组合文档
  <组合名>/cover.png           可选封面（固定名）
  <组合名>/assets/             可选模块壁纸资产
<程序目录>/settings/           设置
  settings.json                应用级设置（主题选择 / 跟随系统 / 已投放 / 字体 / 其余行为项）
  appearance/themes/<id>/      一个主题 = 一个文件夹（theme.json + 同目录壁纸）
<程序目录>/workspace/          工作区
  workspace.json               当前工作区快照
  restart.json                 一次性重启恢复快照
  assets/                      工作区资产（模块壁纸等）
<程序目录>/logs/               日志（本轮只预留）
<程序目录>/resources/seeds/    出厂种子（程序层只读；与目标目录同构，只有投放器读）
```

- 模块只扫描上述两个默认模块目录；不再有用户可配置的来源根。组合只扫描 `composites/`。工作区只由框架读写，不进入组合列表。
- 应用级设置与组合件**完全分离**：设置不随组合件保存，组合件是用户文件，不写进 `settings/`。
- **模块持久化统一进组合件**：模块需要跨会话保留的参数/状态放进实例 Configuration，随组合件保存；单个模块也可以保存为一个组合件。框架**不提供**模块自有设置文件、模块数据目录或静默写模块数据。用户显式选择路径导出的数据（如把显示内容保存到文件）不属于框架持久化。
- 应用级设置**不提供按模块类型的默认值**——模块默认值由模块实现提供。
- **工作区快照**：关闭主窗口时按设置执行「每次询问 / 保存并退出 / 不保存退出」；询问弹窗可勾选「下次不再提醒」。保存后下次启动恢复全部模块、配置、用户输入、位置、壁纸与外壳位置。选择不保存只丢弃本次未保存修改，不删除上次快照。应用设置仍由设置三键独立保存。
- **外壳几何**：有工作区快照时，外壳位置与尺寸按快照**原样恢复**，不按当前比例设置重算；比例与尺寸固定是应用级偏好，只在无工作区或用户显式改比例时参与。比例档只有 `9:19.5`（默认）/ `9:16`，不提供宽体档；窗口几何由 `ShellGeometryPlanner` 规划、`MainWindow` 唯一落地，设置页只编辑草稿。
- **主题表面材质**：`SurfaceOpacity` / `WallpaperVeilOpacity` 属于**每个主题**（主题文件夹里的清单），内置/自定义默认 **0.70 / 0.55**；`SurfaceOpacity` 只乘到 `palette.json` 中标记 `surface` 的背景 token（外壳底色、按钮面、开关轨道），文字、图标、边框、窗口底色不参与。它是主题的表面透明度，不是控件整体 `Opacity`，也不是全局设置。
- **退出策略**：`WorkspaceExitBehavior` 持久化在 settings.json；策略写入失败记 **Error**，不能当作成功。
- **退出的单一出口**：主窗设 `ClosingBehavior=OwnerWindowOnly` —— 主窗先决定，取消时子窗一个都不关；模块窗的视图摘除只绑定在 `Closed`（取消关闭时子窗的 `Closing` 根本不会到），管理器记住 `Closed` 并移除，避免对已关闭窗口再 `Show`。询问 / 保存 / 记住策略 / 关模块窗 / 放行外壳 / 收尾都在 `ShellExitCoordinator` 一处，主窗 `Closing` 只做“取消 + 请求”。收尾（窗口管理器与服务容器）只在 `Exit` 执行一次；`ShutdownRequested` 不拆任何东西（平台请求会取消一回合、静默保存后放行）。
- 用户数据路径只有一处来源：文件名不得散落在别处；不做版本迁移（旧 `data/` 位置不搬家、不提示）。

### 8.2 设置分类

设置弹窗按分类组织（左分类、右页面、**三键：取消 / 应用 / 确认**）；每类管什么见下表，而键名、类型、缺省值与取值范围只在**设置定义**（`src/Core/Api/ApplicationSettings.cs`）里，本文不抄：

| 分类 | 内容 |
|---|---|
| 常规 | **语言**（跟随系统 / 中文；当前只提供中文，切换后重启完全生效）、停止超时、输入队列容量、对齐自动建网、UI 刷新率、性能监视开关、日志级别、诊断提示阈值 |
| 外观 | 顺序固定为 **字体 → 主题方案 → 壁纸 → 色板**；**主题方案**（跟随系统 / 内置浅色 / 内置深色 / 自定义主题卡；樱色是出厂种子投放的普通自定义主题）；跟随系统时用**两个下拉框**分别选浅色 / 深色模式方案；**壁纸**含当前主题的主窗口壁纸（只影响外壳，模块壁纸不变）与**该主题的**壁纸遮罩浓度、控件表面不透明度；**色板**最后；字体四项（界面/数据 × 西文/中文）全局、不随主题 |
| 窗口与交互 | 应用整体置顶、叠加信息层开关、吸附距离、主窗口比例 / 尺寸固定、**关闭主窗口行为**、多行输入提交键 |
| 存储 | **只读路径**（设置 / 模块 / 组合 / 工作区 / 日志 五个功能根）+ 打开目录；不新增写入型设置 |
| 快捷键 | 动作清单 + 当前绑定 + 修改 / 重置 / 冲突检测 |
| 关于 | 版本、构建配置、依赖许可摘要、用法与快捷键速查 |

**设置提交语义**：设置弹窗内的**全部可编辑项**（含叠加信息层、应用置顶、快捷键、性能监视）都是草稿；只有「应用 / 确认」提交，取消不改变运行时。交互页的直接开关是另一种入口：立即生效并立即写入设置文件，打开设置页时按当前已落盘值显示；两处共享同一份设置文件，但“表单提交”和“直接动作”的语义不混用。

**功能与设置分家**：外部模块导入 / 重扫 / 包清单在**模块清单**弹窗；Issue / 拓扑诊断 / 日志查看是独立功能。设置页不再承载这两类页签；日志级别与诊断提示阈值并入「常规」；**模块来源根设置已移除**。

**字体**：`appearance.fonts.ui` / `appearance.fonts.data` 各是 `{ latin, cjk }` 两个字段（v5）——一个字段就是一个字体，组合规则只在 `FontFamilySetting.Compose()` 一处（`西文, 中文`）。默认值只在 `AppearanceSettings` 定义；`Tokens.axaml` / `DesignTokens.axaml` 是首帧/预览兜底，必须与默认值逐字一致（资源审计第⑧段）。v4 的回退列表字符串读时折叠、写侧只留新形状。设置页的「应用 / 确认」必须把四个字段写进外观草稿再落盘。

**主题覆盖面**：

| 项目 | 是否属于主题 | 说明 |
|---|---|---|
| 背景 / 边框 / 文字 / 主题色 / 方向 / 语义 / 叠加层 / 模块控件表面 | **是**（按方案） | 色板 token；外观页统一编辑 |
| Fluent 控件颜色（按钮 / 输入 / 下拉 / 滚动条 / 列表 / 浮层 / ToolTip） | **是**（经 token 桥接） | `FluentBridge.axaml` |
| 界面字体 / 数据字体 | **否** | 全局显示偏好；换方案不改字体 |
| 数据结构（类型身份）颜色 | **否** | 交互页的全局身份映射；跨主题稳定 |
| 窗口比例 / 尺寸 / 置顶 / 吸附 / 叠加开关 / 刷新率 | **否** | 行为设置 |
| 模块导入 / Issue / 拓扑 / 日志查看 | **否，且不是设置** | 各自功能入口 |
| 模块私有绘图配色 | **否** | 模块自管 |
| 控件密度 / 圆角 / 图标集 | 未来候选，本轮不做 | 不新增设置项 |

主要键与全部缺省值、取值范围一律以**设置定义**为唯一来源，本文不抄（名称即持久化键；持久化文件形态与兼容纪律见 §8.3）。

### 8.3 持久化与迁移纪律

- **文本 JSON** + 内嵌版本号 + **未知字段逐层保留并合并写回** + 原子写（临时文件 + 替换）。
- 缺失或损坏 ⇒ 用内置默认值 + 一条 Issue，**不阻断启动**；不可解析时拒绝并保护原文件（受限解析：白名单字段 + 大小与深度上限，**拒绝而非猜测**；两个上限只写在持久化读取实现里，本文不抄数值）。
- **未来版本**：设置/组合件文件版本高于本应用 ⇒ 拒绝写回并保护原文件；设置使用默认值 + Warning。
- **组合件**：1 包目录 = 1 组合关系（`composite.json` + 可选 `cover.png` / `assets/`）；**运行态与绑定不随件**；随件内容 = 配置 / 视图状态 / 每实例壁纸 / 拓扑 / 布局 / 活动面。加载 = 实例化 → 恢复配置与视图状态 → 重建成员 → 按 `实例ID.口名` 重锚；冲突实例 ID 只重映射冲突项，标签/网络名/位置不动。
- **布局加载顺序**：UI 新建窗口时必须**先读取并消费已保存 Layout**；只有完全没有布局的新实例才使用错位摆放并回写初始尺寸。禁止“先按错位建窗、再应用布局”——窗口 `Opened` 时的初始布局回写会覆盖文件位置。
- **自动摆放**：新模块按现有模块的**真实下沿 + 间距**向下让位，不按候选声明高度整块跳过；组合件加载时保持组内相对位置——空现场恢复文件绝对位置，非空现场若整组与现有模块相交则整组平移到空闲处，单个模块组合与普通新模块同路径。
- **预览图/封面**：模块包内固定文件名 `preview.png`；组合包内固定 `cover.png`（旧扁平件 `<组合同名>.preview.png`）。图片居中裁切；缺失显示占位字形。模块不提供应用内预览设置入口，组合由用户「更换封面」经全局图片裁切器写入。
- **模块持久化**：Configuration、声明为持久化的输入（`DeclareInput(InputDeclaration)`）、当前页/折叠态与模块壁纸随组合件/工作区保存；不另设模块数据目录或模块设置文件。连续发送、外部连接打开意图、文件选择路径与显示缓冲不持久化。
- **配置「读即登记」**：模块首次读取配置时登记一份默认值，后续读返回同一对象，写覆盖。若只读不改的模块不登记，保存组合件时整块配置会丢失，无损往返形同虚设，配置表单也失去数据来源。配置字典由模块线程与管理线程共同访问 ⇒ 访问点纳入同一把锁，快照按加锁复制。
- 配置 JSON 允许命名浮点字面量（无穷与 NaN）；枚举按名字读写（仍能加载早期的数字形式）。
- **应用级设置**在 `settings/settings.json`；热键、外观、类型颜色等都属于它。设置项更名时保留旧键的兼容读取；**旧键只读不写**（读时折叠进新形状，写侧删掉它）。模块来源根键已移除，不再读写。
- **外观块 v5**：`appearance { theme, systemLightScheme, systemDarkScheme, seeded[], fonts{ ui{latin,cjk}, data{latin,cjk} } }`。**主题内容不再内联**：每个主题是 `settings/appearance/themes/<id>/theme.json` 加同目录壁纸，`theme` 与"跟随系统"两项只是**选择**（内置 `light` / `dark` 是代码里的色板，永远只读、不落盘）。`seeded` 记"投放过哪些出厂单元"（相对程序目录），用户删除后由它阻止复活。跟随系统的两个方案必须是同基类型；非法/缺失回落内置。旧版本文件不做内联主题迁移（见 §8.1 与 §9.5 的兼容口径）。
- **同一语义的设置只保留一处状态**，其他界面做委托；禁止各存一份再"同步"（那从结构上保证漂移）。
- 快捷键：作用域 = 应用内任一窗口聚焦即生效；作用是可见、可改、可重置，冲突即时提示，空值 = 不绑定；**不做系统级全局热键**；清单以设置页为准。

### 8.4 资源与出厂种子

- **分开放**：只读的出厂种子住 `resources/seeds/`（投放）；可写的用户数据住 `settings/` `workspace/` `logs/`；随包走的资产住包内 `assets/`（模块壁纸）与组合包内的 `cover.png` / `assets/`；**框架程序资源**（框架的界面文本 `resources/i18n/`、图标 `resources/icons/`、种子）就地读、只读；**模块自有资源**在模块包内 `resources/`（`module.json` 声明，模块自己持有；框架不读、不审计其 kind）。发布包只含程序文件、内置模块包与框架 `resources/`（`seeds/`、`i18n/`、`icons/`）。
- **种子与目标目录同构**：`resources/seeds/settings/appearance/themes/<id>/` 就是一个主题文件夹；投放 = 把它按相对路径合并进程序目录。于是"出厂主题"与"用户主题"是**同一种东西**，运行期没有特殊分支。
- **投放规则**：单文件在目标不存在时才复制（出厂设置基线用这一条）；**叶子目录 = 一个投放单元**，目标目录不存在才整目录复制，并把相对路径记进 `appearance.seeded`；已在 `seeded` 的单元不再投放（用户删了不复活）；只做整单元投放，不改写已存在的内容；失败 ⇒ 一条 Warning、不记 `seeded`、撤掉本次半成品（下次启动重试）。没有 `resources/seeds/` 是合法状态（不报 Issue）。
- **默认设置不入库**：发布时由程序自身 `--emit-default-settings` 从代码默认值生成到导出的种子目录——代码默认值是唯一来源，避免仓库里出现第二份默认值。
- **壁纸跟着主题走**：壁纸是主题文件夹的一部分（不再是单独的内容寻址仓库）；导出/搬走一个主题 = 复制一个文件夹。
- **构建只写入 `resources/`**：`settings/` `workspace/` `logs/` 只在运行期出现；构建不往用户目录写任何东西。

### 8.5 界面文本（文本包）

- **文本是数据，不是代码**：每份表是 `resources/i18n/<程序集简名>/<culture>.json`（可选分片 `<culture>.<area>.json`），随程序目录发布、可直接查看与替换；**不编译进 DLL**。`resources/` 下三个子树各有访问模式：`seeds/` = 投放（复制进用户目录），`i18n/` = 就地读（只读），`icons/` = 就地读（只读，见 §8.6）。
- **拥有者目录（两套根）**：框架程序集的表住 `<程序目录>/resources/i18n/<程序集简名>/`；模块的表住**模块包内** `resources/i18n/<程序集简名>/`（模块目录下，`module.json` 的 `resources` 声明）。模块 owner 只读模块根、框架 owner 只读框架根，**互不回退**；找不到表 ⇒ 该拥有者的键显示 `⟦键⟧` 并报一次诊断；缺键只显示标记（框架表由审计在构建期拦，模块表运行时诊断）。
- **模块自带文本**：模块包 = `module.json` + 实现程序集 + `resources/i18n/` + `resources/icons/`（+ 可选 `preview.png` / `assets/`）；模块自有资源包在 `module.json` 的 `resources` 里声明，模块只依赖 `Sdk` 的通用 `IResourceAccess` 读自定义 kind。模块声明的展示文本用**键**而不是字面量（`DisplayNameKey` / `DescriptionKey` / `TitleKey` / `GroupKey`），解析优先级 = 键 → 字面量 → 类型/属性名；外部接入的参数类型在框架侧，但它的显示文本归**声明该接入的模块**。
- **文本归属**：文本属于**它在界面上所描述的那个对象的拥有者**——模块标题/说明、角色名、命令标题、视图按钮与单位、模块状态句在模块包；框架控件文案在 `Sdk.Ui`；框架诊断在 Core / Hosting / DataPlane / Ui / FrameworkUi；配置字段标题/说明/分组/选项随**声明该配置（接入）的模块程序集**（外部接入四标准的参数类型在 `Access`，文本却在四个模块的表里——用户看到的是模块，文本就归模块）。
- **跨层显示文本**：外部接入快照只给**事实**——状态、端点（`ExternalAccessEndpoint`）、结构化失败（`ExternalAccessFailure`：种类 + 端点 + 原始参数值 + 底层细节）、计数。模块按失败**种类**从自己的表选句子；消费方不解析文本、不据此分支。框架侧只保留底层诊断文本（异常细节 / Issue 原因），不生成"面向用户的接入句子"。
- **语言**：`uiLanguage` 设置（跟随系统 / 具体语言），`TextCatalog.Apply` 只改 UI 文化、不动数值格式；回退链 精确 → 语言中立 → 中文简体 → 可见标记。加一种语言 = 在该拥有者的目录里加一份表（框架与各模块各自加）。
- **XAML 通道**：`{loc:Tr <键>}`（标记扩展住在 `Sdk.Ui`，外壳与模块共用）。外壳引用 `Sdk.Ui` 只允许这个扩展——`FrameworkUi` 的 XAML 里映射到 `Sdk.Ui` 的命名空间前缀只许叫 `loc`，由架构用例守。
- **诊断文本同样进表**：Issue / 校验 / 保存失败等经界面显示的文案都走表（按键取值、参数走 `{0}`）。**不进表的三类**：加载器自身在表不可用时的引导期诊断、面向模块作者/开发者的契约层与测试套件文案、设计时样例数据——名单与理由登记在资源审计脚本里；个别行用 `// i18n-exempt: <理由>` 标注，审计会打印清单供复核。
- **门**：资源审计检查"可本地化层零中文"、表结构（版本/语言/键格式/无重复/占位符一致）、`{loc:Tr}` 键存在、无死键、**测试不以文案为判据**、种子包合法；框架 `resources/` 只含框架 owner；模块 `resources/` 走 §8.6 的 ③d/模块包校验（不以框架表规则审模块）。产物校验按文件集与哈希比对框架 `resources/` 全树。

### 8.6 界面图标（图标包）与模块自有资源

- **图标是显式文件**：每个图标一个 `.svg`；框架的 17 个用 **Fluent UI MDL2**（`@fluentui/react-icons-mdl2` / `microsoft/fluentui` v8，MIT，`viewBox 2048`，旧观感），模块的 4 个 `refresh.svg` 用 **Fluent UI System Icons**（20px filled，MIT，与 24×20 小按钮适配）——两套都是 MIT，`THIRD_PARTY_NOTICES` 分别列明。一个拥有者一份 `icons.json` 清单 `{ "schemaVersion": 1, "entries": { "icon.shell.reset": "shell/reset.svg" } }`。框架的清单住 `<程序目录>/resources/icons/<程序集简名>/`，模块的清单住**模块包内** `resources/icons/<程序集简名>/`；随程序目录/模块包发布，不编译进 DLL。
- **框架 vs 模块（两套根，互不回退）**：`resources/` 是**模块共有框架**的资源根（框架自己的文本/图标/种子）；模块的 `resources/` 是**模块自有资源包**（`module.json` 的 `resources` 声明）。`ResourceLayout` 判定 owner：模块拥有的 owner 只查模块包内 `resources/<kind>/<owner>`（缺了就是 null，绝不回退框架根）；框架 owner 只查框架根（显式根 → 产物 `resources/<kind>` → 仓库根，逐级找 owner 目录）。框架的 `resources/` 不出现模块 owner，模块的 `resources/` 不以框架 kind 规则审计。
- **取用**：`IconCatalog.TryGet(owner, key, out IconAsset)`（只读数据：路径字符串 + viewBox；`Sdk` 零依赖，不引 Avalonia）；`Icon` 控件（`Sdk.Ui`）在界面层合成几何并跟随 `Foreground`；缺键/缺表显示键名 + 诊断；`ResourceLayout` 提供根/显式根/代号/目录，`UseRoot` 供测试/预览；缓存按 (owner, 代号)。
- **界面控件**：模块 `ModuleButton.Icon`，外壳 `Ui.IconButton` / `Ui.Glyph`（`Glyph : Sdk.Ui.Icon` 薄子类）；`Icon` 是键（外壳 StyledProperty 可绑定，模块 `x:Static`）；图标按钮与普通按钮**同面**（`ButtonChrome` 的面/边/hover/pressed/focus/disabled），活动栏保持导航式（hover/active/pressed + railMark）；视图里不出现 `<Path>` / `<PathIcon>` / 硬编码码位。
- **模块自定义资源**：图片/字体/其它 kind 放模块自己的 `resources/<kind>/`，由 `Sdk` 的 `IResourceAccess`（模块上下文，`TryOpen(kind, relativePath)`，只读、相对、不越界）读；模块只依赖这个接口，不需要新增框架 `ResourceKinds`、不改框架审计、不引框架包。标准 `i18n`/`icons` 仍由 `TextCatalog`/`IconCatalog` 读模块自己的根。
- **外部修改/失败**：程序目录的 `resources/` 与模块包的 `resources/` 可直接替换，重启生效；缺清单/坏 SVG/缺键 ⇒ 键名 + 诊断；模块表不做框架级 schema 校验（坏表运行时诊断），模块资源包由 `module.json` 清单 + `verify-module-packages` 校验（目录存在、相对、不越界、无未声明目录）。
- **许可**：`resources/icons/LICENSE`（MIT 全文，Microsoft 版权）+ 仓库根 `THIRD_PARTY_NOTICES.md`（两套：Fluent UI MDL2 的框架 17 / Fluent UI System Icons 的模块 refresh；各自来源/版本/版权行）；`package-release` 随 `resources/` 带出。
- **门**：资源审计只审框架 `resources/`（框架文本/图标表、种子、`{loc:Tr}` 键、死键）；模块 `resources/` 走 ③d（清单/目录/文件/越界）与模块包校验；`src/` 禁硬编码字形；模块视图禁 `<Path>`/`PathIcon`、`Icon` 必须 `x:Static`。
- **边界**：SVG 只支持 `viewBox` + `<path d>` + `fill-rule`（`transform`/`<use>`/`<g>` 跳过并诊断）；框架的 MDL2 用 2048 画布、默认 nonzero（不写 `fill-rule`），模块 refresh 用 Fluent 2 的 20px；多色图标、任意字体资产未做（G69）；模块表没有框架级 schema 校验（运行期诊断）。

## 9 测试、门禁与交付

### 9.1 架构规则集

规则集以 `AR-n` 编号（编号即规则项的名字，出现在测试名与报告里），由独立的架构测试项目承载，该项目**不引用任何产品项目**（只读它们的产物）。

| 组 | 规则 |
|---|---|
| 项目清单 | AR-0：产品项目清单必须与七层结构一致（穷举，模块前缀除外） |
| 依赖（程序集引用） | AR-1 模块只引 `Sdk` / `Sdk.Ui` / `Sdk.AccessKit` · AR-2 模块不得互引 · AR-3 数据面不得反向依赖宿主 / 核心 / 界面 · AR-4 宿主只引契约与横切 · AR-5 核心的允许集合（并**加强**：允许引用界面框架的程序集只有 `Ui` / `FrameworkUi` / `App`）· AR-6 公开面只引契约 · AR-7 界面两级的允许集合 · AR-8 外壳层允许集合（含 `Sdk.Ui`，但**只许 `loc:` 前缀引用它**——外壳不得顺手用模块控件库）· AR-9 契约零依赖 · AR-10 横切零依赖 · AR-11 唯一白名单 = 组合根 · AR-12 框架不得引用模块；`Access` 只允许被 `App` 引用 |
| 命名空间与词汇 | AR-13 核心 / 宿主 / 数据面不得出现具体业务词汇（禁令词表含串口、波特率、电机、绘图、总线协议等）· AR-14 命名空间须与项目名加目录一致 |
| 第三方 | AR-15 排除清单（诊断支持包、加速包、商业控件、中介者与对象映射库、断言与模拟库、日志门面等一律不得引用） |
| 公开面 | AR-16 公开签名不得出现框架内部类型 |
| 用户数据 | AR-17 用户数据路径只有一处来源（文件名只允许出现在路径解析器里） |
| 模块几何 | AR-18 模块尺寸与端口位置只能来自代码声明 |
| 注释 | AR-19 源码注释只承载"为什么 / 不变量 / 坑"，不得携带日期、决定编号、用户原话、实测读数与当前坐标/尺寸/像素值 |
| 界面唯一性 | AR-20 界面描述文件禁止复活（无 `view.json` / `view.schema.json`）· AR-21 `Sdk.Ui` 只许控件/契约/主题 · AR-22 模块 XAML 的绑定键只许 `{x:Static}` 常量 |
| 模块计时 | AR-23 模块包不得自建 Timer / Thread.Sleep / DispatcherTimer / Task.Delay / 平台专有调度 API |
| 包边界 | AR-24 模块包不得含宿主提供程序集（`Sdk*` / `Sdk.Ui*` / `Sdk.AccessKit*` / `Access*` / Avalonia / 外部接入第三方依赖） |

执行方式：

- 依赖类规则**同时**按两条路径检查：程序集引用（覆盖间接依赖）与项目文件的引用项（覆盖"引了但暂时没用"）。
- 源码类规则按源码扫描。
- 用到的程序集按当前构建配置定位；**目标程序集缺失即失败**，不跳过——否则改名之后整类规则会静默失效。
- `Access` 作为框架侧外部接入实现参与 AR-0 的项目清单；它**只进入组合根的允许集合**，`Core` / `Hosting` / `DataPlane` / `Core.Api` / `Ui` / `FrameworkUi` 引用它即判红。
- 判定口径（架构能力）：框架程序集**引用集不变** + 既有测试全绿 + 新模块功能测试通过；不做中间语言或二进制基线比对。

### 9.2 测试分层

| 层 | 内容 | 承载项目 |
|---|---|---|
| T1 | 架构能力判据：新增模块核心零改动 · 状态变化不外溢且不影响无关模块 · 组合与配置在线生效 · 保存加载无损往返 · 无隐藏耦合 · 对未知类型开放 | 判据测试项目 |
| T2 | 契约与兼容：表驱动的合法 / 非法矩阵 + 建网各情形 | 主测试项目 |
| T3 | 核心机制：注册表、生命周期状态机、变更原子性、增量重建、资源释放无泄漏 | 主测试项目 |
| T4 | 持久化：组合件往返、版本迁移、缺失模块与损坏处理、未知字段保真 | 主测试项目 |
| T5 | 故障注入：异常不外溢、慢消费者丢帧、停止超时路径 | 主测试项目 |
| T6 | 模块契约自检套件（提供且推荐） | `Sdk.Testing`（模块作者侧） |
| T7 | 用户手工验收（须交付手工验收清单） | 用户 |
| T8 | 界面自动化 | **v1 不做** |

- 判据由**正式模块**承载，参考桩模块不承载契约判据；参考组合由业务模块（见 §1.3）与测试内桩模块构成，桩模块与第三方模块**同引用面、同加载路径**，判据才具保真度。
- 资源释放验证以计数断言为主（活动线程、队列、池计数归零），关键点辅以弱引用断言。
- 渲染快照作为独立测试项目在**真实渲染栈**下把窗口画成 PNG 供目视复核。两点设计取舍：必须独立进程（无头绘制模式是进程级配置，与主测试项目的空绘制会话同进程会互相破坏）；刻意不引用应用项目（引用它会在构建时重拷输出，应用一开着快照就不可用），改为在自己的快照宿主里复刻同一批资源路径。
- 表驱动优先；界面层与纯几何 / 视图模型的判据分开承载（纯函数可单独断言）。
- **测试不以文案为判据**：断言键 / 结构（类别、对象路径、计数、顺序、编码往返），不写死界面文案与诊断措辞；测试里出现的文案字面量由资源与文本审计第⑦段在门禁期拦下。机器契约（键、JSON 属性名、模块标识 / 版本、文件名、枚举线值）不受此限。

### 9.3 验证层级与完整门禁

验证层级按 **T0 → T1 → T2 → T3** 逐层递进：T0 构建 · T1 单类 / 单项目测试 · T2 相关项目集合 · T3 完整门禁。按改动范围选最小必要的一层，完整门禁在里程碑收尾时跑。

完整门禁的顺序与内容：

1. **文档审计**
2. **颜色口径审计**
3. **资源与文本审计**
4. **注释布局数值审计**（注释不得写当前坐标 / 尺寸 / 像素值）
5. **还原**
6. **构建**（0 警告 0 错误）
7. **模块包校验** · **资源包校验**
8. **许可审计**
9. **全部测试**（含架构规则）

基准测试不进常规门禁，按需单独运行。

### 9.4 依赖与许可

- **中央包管理**：版本集中在一处声明，工程只引用不写版本，避免漂移；配依赖锁文件保证可复现。
- 主要依赖：Avalonia（含桌面、Fluent 主题、数据网格、取色控件、无头、Skia 后端，同版本）· `CommunityToolkit.Mvvm` · `Microsoft.Extensions.DependencyInjection`（**仅组合根使用**）· 测试侧 `Microsoft.NET.Test.Sdk` / `xunit` / `xunit.runner.visualstudio` / `Shouldly` / `NSubstitute` / `coverlet.collector` · `BenchmarkDotNet`。版本只在中央包管理里声明，本文不抄。
- 不引无头测试框架专用的 xUnit 适配包（它依赖的 xunit 主版本与本工程所用不一致，会出现同一特性存在于两个程序集的编译错误）；无头会话改用带独立调度线程、不绑定测试框架的会话 API。
- **许可纪律**：只允许 MIT / Apache-2.0 / BSD 一类宽松许可；**禁止 GPL / LGPL 与任何需要采购的商业授权**。构建期许可审计覆盖**直接与传递依赖**，出现受限许可即失败。无许可声明与强制遥测的包一律不得引入。
- 日志后端为极简自研（日志抽象 + 自研文件 sink），不引第三方日志门面。
- 模块加载用运行时内置的加载上下文。

### 9.5 交付形态

- v1 交付为**便携包**：没有安装程序与卸载程序，没有自动更新通道，升级 = 手动替换。
- 允许**多开**（不做单实例限制）；设置文件并发写采用「直接覆写、最后写入获胜」。
- 产品自身**不上报任何数据**，没有隐私或遥测声明。
- 界面文本走**文本包**（`resources/i18n/<程序集简名>/<culture>.json` 文件，随包发布、可就地查看与替换；`{loc:Tr}` 取用，见 §8.5）；图标走**图标包**（框架 `resources/icons/<程序集简名>/icons.json` → `.svg`；模块包 `resources/icons/`；`IconButton` / `Glyph` / `ModuleButton.Icon` 取用，见 §8.6）；本轮只提供中文，语言设置点已就位（加语言 = 加一份表 + 重编）。不做无障碍支持，不做诊断包导出，首次运行引导 v1 不做。
- 数据导出与打印属模块自身能力。
- 跨平台能力天然具备（运行时 + 界面框架），但**不为跨平台牺牲性能**；Windows 是首要目标，平台相关适配只落在界面层。
- 组合件**永不自动执行任何代码**（加载只重建声明结构）；模块包加载是显式的用户信任决策，加载前显示来源与签名状态，包声明的能力（网络 / 串口 / 文件）在加载时提示但不拦截；不做进程级沙箱、不做权限拦截系统、不做强制签名。
- 模块包只带**模块自有**文件与模块私有第三方依赖；`Sdk` / `Sdk.Ui` / `Sdk.AccessKit` / `Access` / 外部接入第三方依赖由宿主提供。缺失宿主/私有依赖记 Issue，**不静默降级**。
- **发布包只含程序层**：程序文件 + `modules/`（内置包，各带自己的 `resources/i18n`/`resources/icons`）+ 框架 `resources/`（出厂种子 `seeds/`、界面文本 `i18n/` 与界面图标 `icons/`；种子里的设置基线由 `--emit-default-settings` 生成）。用户目录（`settings/` `workspace/` `logs/` `composites/`）与 `modules/external/` 一律不进发布；构建也不往用户目录写东西。
