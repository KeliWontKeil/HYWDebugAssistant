# HYWDebugAssistant 架构法典

> 定位：面向工程人员的**模块化数据处理、通信与可视化工作台**。用户的操作模型是「选择模块 → 放入工作区 → 配置 → 拼接 → 即插即用」；用户不需要理解消息、通道、队列、订阅、路由、线程、运行时绑定等底层概念。
>
> 本文只描述**系统现在是什么样**。做什么归 `docs/TODO.md`，验收步骤归 `docs/ACCEPTANCE.md`，工作流与命令归 `docs/HOWTO.md`，代码风格归 `docs/STYLE.md`。

## 1 分层与项目结构

### 1.1 分层

层按**运行时角色**划分，不按命名空间划分。

| 层 | 名称 | 承担什么 |
|---|---|---|
| L0 | 横切支撑 | 中性技术能力：日志 sink、序列化、文件读写、诊断采集 |
| L1 | 契约层 | 模块作者与界面共同依赖的稳定抽象面：契约、声明面、数据类型 |
| L2 | 模块宿主层 | 模块包的发现、加载、校验、注册；实例世界；框架侧生命周期 |
| L3 | 数据面层 | 绑定的执行与投递、有界缓冲与丢弃、**模块活动的承载与调度**、流量计数 |
| L4 | 核心管理面 | 组合的解释与校验、变更的原子应用、增量重建、持久化、Issue 中心 |
| L5 | UI 构成层 | 外壳窗口、模块窗口、视觉层、口上标记渲染、管理视图 |
| L6 | 模块实现 | 业务功能单元，**不是框架的组成部分** |

L0 只对 L2 / L3 / L4 可见。

### 1.2 依赖方向

唯一允许的依赖链：

```
L6 模块实现  →  L1 契约
L2 模块宿主  →  { L1, L0 }
L3 数据面    →  { L1, L0 }
L4 核心管理  →  { L1, L2, L3, L0 }
L5 界面      →  { L1, Core.Api }
```

结构性事实：

- **L3 数据面没有任何指向 L2 / L4 / L5 的依赖** ⇒「Core 中转数据」「界面参与投递」在结构上无法成立。
- **L6 只依赖 L1** ⇒ 模块不能自建活动载体、不能引用另一个模块、不能引用界面框架。
- 稳定抽象面单列为 `Core.Api`，界面只经它读取运行期事实；界面**不引用**核心管理面的内部。

### 1.3 项目与程序集

**一个层即一个程序集**，因此上面每一条禁令都可以直接按「项目引用」检查，而不必从命名空间推断。

| 项目 | 层 | 允许直接引用 |
|---|---|---|
| `src/Sdk` | L1 | 无（零框架依赖） |
| `src/Sdk.Testing` | L1 工具 | `Sdk` |
| `src/Infrastructure` | L0 | 无 |
| `src/Hosting` | L2 | `Sdk` · `Infrastructure` |
| `src/DataPlane` | L3 | `Sdk` · `Infrastructure` |
| `src/Core` | L4 | `Sdk` · `Core.Api` · `Hosting` · `DataPlane` · `Infrastructure` |
| `src/Core.Api` | L1 公开面 | `Sdk` |
| `src/Ui` | L5 模块区 | `Sdk` · `Core.Api` |
| `src/FrameworkUi` | L5 外壳 | `Sdk` · `Core.Api` · `Ui` |
| `src/App` | 组合根 | 上述全部 |
| `src/Modules/Business/*` | L6 | 只允许 `Sdk` + `Sdk.Ui`（界面契约与控件库） |

- 允许引用 Avalonia 的程序集**只有** `Sdk.Ui`、`Ui`、`FrameworkUi`、`App`；`Sdk`、`Core`、`Hosting`、`DataPlane` 不得出现界面框架依赖。模块经 `Sdk.Ui` 拿到控件，不直接引 Avalonia 包。
- 框架程序集**不得**引用任何模块程序集。
- 模块之间**不得**互相引用。
- `Sdk` 必须零依赖（包括不依赖 `Microsoft.Extensions.*`）。

`HYWDebugAssistant.slnx` 的登记内容以上表为准（框架项目 · 业务模块 · 测试项目；条目以解决方案文件为唯一来源，本文不抄）。业务模块为：文本发送器、HEX 发送器、数据监视器、HEX 字符串转换器。

### 1.4 模块包形态

- 一个模块包 = **一个目录**，其中 `module.json` 是包清单（身份与实现绑定），程序集随后。**界面是模块自己的 XAML（编译进程序集），包内没有界面描述文件。**
- 构建期把模块项目输出归拢到 `artifacts/modules/<包名>/`（先清空该包目录再复制，避免新旧程序集混放），再由应用项目镜像到输出目录下的 `modules/`。
- 内置模块 = **预装的包，没有任何结构特权**：与第三方包走同一条发现、加载、校验路径，只是来源目录固定在程序目录下并排在来源列表首位。
- 包名由项目属性推导，默认取项目名后缀 ⇒ 新增模块项目**零改动**。

### 1.5 唯一白名单：组合根

`src/App` 是**唯一**同时可见 L4 与 L5 的位置。它只做这几件事：

1. **装配**：构造核心构成（含模块注册表）、设置服务、运行期服务（同时以 `IRuntimeQuery` 与 `IRuntimeCommand` 两个面暴露）。
2. **装载**：读应用级设置（失败则用默认值 + Issue，**不阻断启动**），扫描模块来源目录。
3. **显示**：创建外壳视图模型，显示外壳窗口；模块窗口由界面侧创建。

组合根里不放业务逻辑，也不放机制逻辑——一切机制都在 L4 之内。

装配序本身是语义：核心构成先于界面构成；界面只拿到查询面与命令面。

## 2 模块 SDK 与契约

### 2.1 模块是什么

模块是用户可感知的功能基本单元。它在实现上只有这几样东西：

- **入口接口**：模块实现接口，框架按接口调用，**不继承框架基类**。
- **声明入口**：在注册钩子里通过上下文声明数据类型、口、角色、内部处理顺序。
- **可选能力接口**：只声明"我需要自发活动"以及活动形式（周期 / 事件驱动），实现体内由框架在该实例的专属线程上调用。

模块不持有框架对象引用，只能经上下文使用上报能力、读写自身配置、登记活动。模块不能反向查询其他模块是否存在。

### 2.2 Definition：对外声明

声明面的项、键名与聚合成 Definition 的方式只在 SDK 的声明入口与模块定义类型里（`src/Sdk/Context/IModuleContext.cs`），本文只说明各项承担什么。

| 项 | 内容 |
|---|---|
| 身份与版本 | 作者 / 模块名 / 版本 |
| 元数据 | 显示名、说明、可选预览图 |
| 接口 | 口（方向、形状、传递语义、是否参与自动建网） |
| 配置 | C# 配置类型 + 字段标注 |
| 视图 | 模块提供 `IModuleViewFactory`（XAML 视图）；声明来源是 `[ModuleDefinition(ViewFactory = …)]` |
| 生命周期能力 | 是否需要自发活动、活动形式 |

内置模块与外部模块**同形**：同一份声明面、同一条加载路径。

标识采用结构化字面量 `作者/模块名/语义版本`：段全小写、版本取语义化版本形式、段首不得为连字符、段不得为空；解析与校验只在 SDK 的模块标识实现里，失败即拒绝加载。**版本参与多版本共存**，也支撑连接锚定的诊断文本 `实例ID.口名`。

### 2.3 包、发现与加载

- **1 包 1 模块**：注册表的登记粒度是包。
- **发现**：应用级设置持一份**有序的声明根列表**，默认值为「程序目录下的 `modules`」。扫描规则是按顺序逐根扫描，每根只扫**直接子目录**中含 `module.json` 者；不递归、不猜、不扫任意位置。
- 内置根固定在列表首位，**不可移除、不出现在可编辑列表里**；启动与「重新加载」共用同一条根解析，因此用户没有配置任何来源根时重扫也不会把列表清空。
- **重复包**：同标识同版本 ⇒ 先到者胜，后者记一条信息；同标识不同版本 ⇒ 都注册，按模块名聚合，默认取最新版本。
- **加载**：校验 manifest 完整性、框架兼容范围、依赖 ⇒ 注册 ⇒ 可实例化。失败只记 Issue，**不影响既有模块与正在运行的现场**。
- **重扫**：作用域限于声明根，只发现新增包；已载入的程序集不可替换。重扫时若包文件写入时间晚于本进程启动时间，记一条信息并在模块清单里标出「重启应用后生效」。
- **移除**：从注册表注销；已被实例化的进入缺失态（占位 + Issue），**不强制卸载**正在使用的模块。
- **热重载不提供**：改动模块代码的语义固定为「重新构建 → 重启应用」。既不实现热重载，也不实现可卸载的加载上下文。

### 2.4 生命周期钩子

钩子按框架的生命周期契约固定（钩子名即 SDK 生命周期接口 `src/Sdk/Lifecycle/IModule.cs` 的成员），由框架在**该实例的专属线程**上调用，各自承担：

| 钩子 | 时机 | 语义 |
|---|---|---|
| `OnRegistered` | 实例创建、成员实例化完成 | 在此声明口、类型、角色、流；不得假定数据已在流动 |
| `OnActivated` | 进入 Active | 开始业务活动 |
| `OnDisabled` | 进入 Disabled | 暂停数据流；内部处置**自决**（是否断开硬件由模块决定） |
| `OnEnabled` | Disabled → Active | 恢复业务活动 |
| `OnConfigurationChanged` | 配置更新 | 热生效或请求重建由模块自决 |
| `OnRemoved` | 移除前 | 释放**模块内部**资源（框架已先清连接、绑定与成员资源） |

纪律：

- 钩子中的异常**不得逸出边界**，由框架受控捕获并转 Issue。
- 活动体可以阻塞、可以循环、可以做同步 IO——写「读硬件 → 处理 → 投递」的同步循环是允许的写法；但必须响应停止信号。
- 模块**不得自建线程或定时器**。
- 上报接口本身不抛；框架自身代码不捕获自己。

### 2.5 口与类型引用

口是网络的端点，也是**唯一**的接口与建网单位。

- 口名在模块内唯一且稳定；重复即拒绝并记 Issue，**不静默改名**。
- 连接锚定为 `实例ID.口名`。
- 方向只有两态：发送、接收。双向 = 两个口 + 两条单向网络。
- 形状由 SDK 的原语组合给出，**尺寸由形状决定**（见 §3）。
- 口用**类型引用**（标识 + 版本）指向本模块已声明的数据类型；这是一项可声明、非必须的兼容扩展。不声明即回退到按形状判定。
- 类型引用用 `init` 属性而不是构造器参数（见 §2.8）。
- 口的**默认挂载边**由 `PortDeclaration.Edge` 声明（`Auto` = 按数据流惯例：发送右、接收左）；没有外部数据文件。

### 2.6 角色声明与两侧同型

角色 = **模块声明的功能分块**（「我有哪几块处理功能」），由模块在注册时声明，框架不派生、不发明。

| 字段 | 含义 |
|---|---|
| 标识 | 模块内唯一、稳定；重复即记 Issue 并忽略后者 |
| 功能名 | 呈现文本；为空则回退为类型短名 |
| 类型 | 该分块处理的数据类型引用，必须能在本模块解析；**一个角色只有一种类型** |
| 输入口集合 | 可为空 = 纯源分块 |
| 输出口集合 | 可为空 = 纯汇分块 |

**两侧同型**：一个角色的输入口与输出口承载**同一种数据类型**。违反 ⇒ 自检进 `Problems`、加载期记 Issue 并**忽略该条**；口未声明类型（旧模块形态）时不校验。

- 口数不设上限；口数超出「一个分块一进一出」的常规规模时，只在 SDK 自检的**独立建议通道**给一条可忽略的建议（建议文本明说「若是一件事则不必拆」；触发门槛只在 SDK 自检实现里），**不进 `Problems`、运行期不报**。
- 一个口**最多属于一个角色**；未归属任何角色的口合法，在叠加层里不表达。
- 口与角色不是同一个层级：口是数据接口的抽象（仍由端口标记表达），角色是模块内部功能的抽象（只由叠加层表达）。
- 类型转换 = **两个数据角色**（收 A 的角色 + 发 B 的角色）+ 一条内部流声明；叠加层上表现为两个方块、各按自己的类型色。
- 角色图标不做。

### 2.7 内部处理顺序声明

模块可声明一条「角色 → 角色」的处理顺序，表达分块之间的先后（如「融合 → 限幅」）。

- 两端角色必须已声明，否则记 Issue 并忽略该条。
- 不得自环；同一（起点，终点）不重复。
- **零声明即零线**：框架不猜——同类型的收发口之间没有必然关系，猜出来的线是虚假信息。
- 单分块模块完全没有可声明的边，因此参考模块通常零声明。

### 2.8 SDK 兼容纪律

- **只增不改，看签名不看语义**。语义上"只是加了个可选参数"仍会改变方法签名；模块各自带一份 SDK 副本，于是加载即抛 `MissingMethodException`。
- **禁止用构造器可选参数扩展声明面**。新增可选声明一律用 `init` 属性或新类型。
- **改动 SDK 后必须重编全部模块**，并把它当作交付前的检查项。
- 契约面的破坏性变更按契约变更处理。
- 配置读写与序列化用源生成，运行期热路径零反射：反射只用于加载期读一次声明。

### 2.9 报什么、不报什么

- 声明期能判定的结构问题（口名重复、角色类型不可解析、口方向不符、口不属于本模块、内部流自检失败）⇒ 加载期记 Issue 并忽略该条。
- 模块契约自检套件 `Sdk.Testing` 提供且推荐：只依赖 `Sdk`，模块作者在自己的测试项目里引用它即可自检接口、Schema、生命周期钩子与「无跨模块引用」。它**不进入产品程序集**。
- 「建议」与「问题」是两条通道：建议走独立的 `Advisories`，问题走 `Problems`。若把建议写进 `Problems`，自家参考模块的门禁用例会当场失败。
- 模块业务状态不属于 Issue（见 §4.6）。

## 3 数据协议与类型

### 3.1 数据单元

- 一个数据单元 = **一个定长数据报**，长度等于发送口契约的尺寸。
- 数据包**不自描述**：不带类型标签，框架按声明路由。需要自描述的模块在自己的契约里带字段。
- v1 **只定长**：不提供变长载荷、不分片。
- **批量 = 定长数组**（`T[N]`）。框架不做自动合并——那会改变时序语义。
- 负载缓冲是池化的定长扁平缓冲，只含契约字段，**不含框架元信息**；形状元数据（字段偏移表）与强类型访问器在加载期生成。
- 接收侧约束：到达长度必须 ≥ 本口契约尺寸；长度不足时读取返回失败而**不抛异常**（防御式读取）。形状完全一致的前提下，长度恒等于契约尺寸。
- 取消类型标签与来源字段带来的两个直接后果：投递路径没有逐单元构造开销；同一宿口上永不出现两种长度。

### 3.2 解析三段式

| 阶段 | 谁做 | 内容 |
|---|---|---|
| 声明期读取 | **框架必做** | 注册 / 实例化时一次性读取端口、类型引用、视图声明、能力、计量块、解码器；销毁时注销；**运行期不重读** |
| 传输期解析数据流 | **框架禁止** | 框架不读数据内容；投递只按绑定走，外加长度校验 |
| 呈现期解码 | **模块负责** | 解码器由模块提供并随类型注册，框架只回调，不内建、不理解结构 |

框架内建的解码器只是参考实现。

### 3.3 数据类型声明

一条类型声明包含：标识 + 版本 + 形状（**尺寸的唯一来源**）+ 传递语义 + 计量块 + 解码器 + 语义元数据。

- **类型身份归模块，框架只持机械镜像**：标识、版本、尺寸、传递语义、兼容声明。框架做机械判定，不解释"这是什么量"。
- 类型按（标识，版本）索引；标识建议带模块前缀，因为**跨模块同名 = 同一类型**。
- 传递语义是枚举：流 / 消息 / 事件。**跨语义不判兼容**，需要时由模块内部组帧或插入转换模块。
- 解码器可选：不提供则呈现层显示「未声明解码器 + 字节数」，**不猜**。解码器必须是纯函数（同字节同结果、不抛、不分配），失败即失败，框架不按长度或原语推断。
- 语义元数据（单位、量程、精度等）**只用于展示**，禁止参与任何框架判定。
- 引用未声明的类型、重复声明同一（标识，版本）⇒ 记 Issue 并回退。

### 3.4 形状

形状 = 定长字节数 + 嵌套深度，形态如下：

| 形态 | 说明 |
|---|---|
| 原语 | `i8` `i16` `i32` `i64` `u8` `u16` `u32` `u64` `f32` `f64` `bool`；尺寸由原语本身表达 |
| 定长字节块 | 长度有上限（文本载荷按「一个 UDP 包量级」留量）；上限只在 SDK 形状类型的校验里 |
| 定长数组 | 元素必须是原语；长度上限只在 SDK 形状类型的校验里 |
| 结构组合 | 字段 = 名称 + 形状，字段名唯一，顺序即签名顺序；嵌套深度有上限，上限只在 SDK 形状类型的校验里 |

可读描述形如 `f32`、`u64`、`f32[N]`、`bytes[N]`、`{seq:u64, value:f32}`。

### 3.5 兼容判定

判定对象是**逐（源，宿）对**，不是整条网络。

判定顺序：

1. **传递语义必须一致**，否则不兼容。
2. **形状必须完全一致**：字段名称、原语种类、数组与字节块长度、字段顺序、字段数量全同 ⇒ 尺寸必然相同。
3. 双方都声明类型时再比类型身份：
   - 同标识 + 同版本 ⇒ 兼容；
   - **同标识 + 不同版本 ⇒ 不兼容**（版本升级按破坏性变更处理：把两侧升到同版本，或插入转换模块）；
   - **不同标识 ⇒ 默认不兼容**（框架无资格判定二者是否同一种量）；用户**显式确认**后可强连，**此时仍要求形状完全一致**，并产生一条必须让用户看到的说明。
4. 任一方未声明类型（旧模块形态）⇒ 只按第 2 条判定。

**形状相等必须逐字段结构比较**。这些形状是 record，但结构形状的字段集合在 record 默认相等里做的是**引用比较**——直接写 `==` 会把两个模块各自构造的同一形状判成不同（隐形陷阱：只有引用同一静态实例才连得上）。

**不自动转换**：不兼容即不可连并明示差异，转换由用户显式插入转换模块。合法但无意义的组合（例如两个发送口相接）方向决定其"连接存在但无数据流"，不在兼容判定里处理。

形状完全一致的收益是可安全读取：到达长度恒等于本口契约尺寸，接收方按自己的契约读不会越界，也就不会有异常从投递回调逸出、把该实例的投递循环整体带走。

### 3.6 计量块

随类型声明，全字段可选，每项都有明确缺省；缺省值只写在计量块类型里，本文不抄数值，只说明缺省语义：

| 字段 | 缺省语义 |
|---|---|
| 有效载荷字节数 | 未声明即按契约尺寸算 |
| 有效长度字段名 | 未声明即不逐单元读（按静态尺寸算） |
| 每单元样本数 | 未声明即按单元计，不换算样本 |
| 每样本通道数 | 未声明即不区分通道 |
| 标称速率 | 未声明即无标称值 |

**有效长度字段名**解决的是「定长契约里的变长载荷」（典型形态 = 一个顶层整型长度字段 + 一个定长字节块，尾部补零）：声明哪个顶层整型字段写着有效长度，框架逐单元小端读取并夹到 `[0, 契约尺寸]` 后累计，有效载荷档速率因此给出**真实**有效速率；声明了它则动态值优先。字段不存在、不是整型、或不是结构形状 ⇒ 契约自检明确报错，不静默。

速率按口径分档（档名即枚举成员，本文不抄各档数值）：

| 档 | 口径 |
|---|---|
| 单元速率 | 按**源**计，每个数据报一次，不受多播放大影响 |
| 搬运字节速率 | 按**宿**计，含自描述与对齐填充 |
| 有效载荷字节速率 | 业务数据字节 |
| 样本 / 通道样本速率 | 由每单元样本数与通道数换算 |

丢弃按类分开记，不混算：

| 类 | 内容 |
|---|---|
| 停流未投递 | **合法状态**，不与其他丢弃混算 |
| 传输丢弃 | 队列满 + 无承载 + 载荷非法 |
| 模块内部丢弃 | 模块自己丢的（由模块上报） |

纪律：计量块**只用于计量与呈现**，禁止参与建网、兼容等任何框架判定（可声明 ≠ 可判定）；界面只显示有定义的口径，不做差分估算；「是否掉速」= 实测与标称速率相比。

## 4 运行期机制

### 4.1 总流程

```
用户拼接 / 配置 → 组合声明 → L4 解释与校验 → 绑定（数据通路）→ 数据单元直通投递
```

- 数据单元按序**直通**：核心管理面不中转数据。
- **没有全局启停**：模块加入即运行，停止由生命周期状态承担。
- 变更 = 一次原子变更 → 增量重建受影响局部。
- 框架统一承载模块活动；模块的业务上下文独立于数据面。

### 4.2 生命周期

```
Registered → Active ⇄ Disabled → Removed
```

| 状态 | 语义 |
|---|---|
| `Registered` | 已加入（创建、初始化是转换过程）；**不占线程** |
| `Active` | 参与数据流（加入即运行） |
| `Disabled` | 保留实例、拓扑与配置，暂停数据流；**保留线程与队列**，只把绑定置为停流；通知模块，内部处置自决 |
| `Removed` | 已移除（停止、释放是过程）；**资源在此才回收** |

- **`Faulted` / `Recovering` 不是框架状态**——软件异常走异常报告。
- **移除不可逆**：重新加入 = 新实例；撤销由界面的撤销栈承担，复制配置属界面便利。
- **绑定独立于模块状态**，随连接存在：`Disabled` ⇒ 绑定保留停流（界面标注）；`Removed` ⇒ 级联销毁。业务状态变化不触碰绑定（表现为无数据）。
- 正交面：存在性（框架权威）· 活动面（框架权威）· 业务状态（模块自报，框架只登记与呈现）· 异常报告（模块产生，框架受控收集）。

### 4.3 线程与队列承载

- 每个 `Active` 实例 = 一个由 L3 分配的**专属线程** + 每（实例，口）一条有界输入队列 + 停止信号 + 若干订阅缓冲。
- 模块活动体允许阻塞（线程归它自己用，阻塞只影响自己），必须响应停止信号，**不得自建或自管线程**。
- **队列粒度 = 每（实例，口）一条有界 FIFO**，容量按口计；默认**丢最旧保最新**；**v1 不做背压，绝不阻塞发送方**。
- 入队结果分档，各自计数：接受 / 队列满 / 无承载 / 已停止。「无承载」不记成「满队」。
- 每口一条队列同时消除跨口队头阻塞：一个满口不会堵住同实例其他口的数据流。多口之间按轮转公平调度。
- 记账补漏：丢旧策略下「新单元入队并挤掉旧单元」时，新单元记投递、被挤的旧单元记**队列满丢弃**——否则投递数会把从未被消费的单元算成成功。
- 承载参数（空闲等待、队列容量、满时策略、停止超时）的**唯一来源 = 数据面承载参数类型**（`src/DataPlane/Carriers/CarrierOptions.cs`），测试与产品共用同一份缺省值，本文不抄数值。

### 4.4 停止协议

- 框架发停止信号 → **有界等待**（等待上限 = 承载参数类型的停止超时缺省值，本文不抄数值）。
- 超时 ⇒ 记 Issue + 标记该线程为孤儿线程，**不强杀线程、不卸载程序集**（.NET 没有安全的线程中止）。
- 孤儿线程是**有意接受的边界**：此时「`Removed` 即资源已释放」对该线程不成立。
- 模块侧的义务是周期性检查停止信号并尽快返回。

### 4.5 变更与增量重建

- **单操作原子**：连接 / 断开 / 加入 / 移除 / 启用 / 停用等单个操作，要么完整应用、要么整体回滚一致，没有半状态。
- **复合 ChangeSet**：需要多步一起做（如替换模块并重连）时，由界面或命令层组装为一次复合变更。
- **两阶段**：
  - **Prepare**——整体校验规则、能力与契约，**可失败、零副作用**；
  - **Commit**——无失败点，先加后减。
- 变更入口**串行化**；任一步失败则**整体拒绝**。没有跨用户会话的全局事务或锁（单用户桌面 + 全在线场景不匹配）。
- **增量重建单位 = 绑定及其邻接数据面**：只重织受影响的连接与绑定衔接；**模块实例、配置与业务状态保留**（插拔线不重置模块）。删除、替换、配置结构变更才触达模块。
- 配置更新 = 框架通知模块，热生效或请求重建由模块自决。
- 配置 Schema 的字段写回也走同一条变更路径：按字段解析文本 → JSON 中转（序列化当前配置 → 覆盖一个属性 → 反序列化为**新实例**）→ 一次变更、原子应用或整体拒绝、触发一次配置变更通知。**绝不就地修改运行中的配置对象**，Prepare 阶段零副作用。
- 配置还原（界面的「还原」）语义是**用同类型的新默认实例替换**每个已登记配置，**不得清空集合**：清空会让按登记对象生成的 Schema 表单失去数据来源。

### 4.6 Issue 中心

统一模型 = 归属对象（实例 / 口 / 连接 / 配置项）+ 类别 + 来源（框架判定 / 模块报告）+ 描述与时间。

类别是枚举成员：Configuration Error · Composition Error · Interface Error · Module Error · Communication Error · Runtime Error · Presentation Error（成员即唯一来源）。

- 语义分两层：设计 / 变更问题（可判定、用户可修）与运行报告（运行期产生）。
- **模块业务状态不入 Issue**（属状态面）。
- **隔离与恢复 = 天然隔离 + 显式恢复**：框架不自动重试、不自动降级、不阻断上下游；隔离的实现保障是模块异常不逸出边界（框架在边界捕获并转 Issue）；恢复靠用户显式操作或模块自身内部恢复。标准恢复动作是「重建实例」（移除 + 加入的复合变更，由界面组装，框架只执行变更）。
- 呈现 = **对象标注 + 汇总列表**；**不阻止其他部分运行**。
- 通知强度 = 默认轻量（标注、计数），**不弹窗打扰**；模块可声明「需要用户注意」级别，默认仍不打断。
- 异常边界：活动体入口整体包裹 ⇒ 记 Issue 并停止该模块活动；钩子逐个包裹；上报接口内部不抛。框架自身代码不捕获自己的异常。

### 4.7 可观测性

| 层 | 内容 | 呈现 |
|---|---|---|
| L1 框架诊断 | 加载 / 注册 / 建网 / 绑定 / 增量重建 / 变更事件，结构化日志 | 诊断面板 |
| L2 Issue 中心 | 对象标注 + 汇总列表 + 过滤 | 轻量计数 + 面板 |
| L3 模块日志与状态 | 模块自产日志经框架汇集，分级 / 来源 / 过滤 | 模块视图 + 汇总视图 |
| L4 数据流诊断 | 各档速率、各类丢弃、最后数据时间、队列水位 | 口上 / 网络详情 |
| L5 性能监视 | CPU / 内存 / 模块活动统计 | v1 不做 |

原则：默认轻量不打扰；L1 / L4 是排障主力；录波与回放属未来能力。

采集点在每一处绑定与每一条队列上：投递数、丢弃数（按原因）、最后数据时间、队列深度。Issue 经无锁并发队列汇集。

### 4.8 非功能基线

- **首要原则：数据实时性 > 界面呈现**。数据面绝不被界面阻塞（视图独立开关、丢帧不阻塞上游、框架统一承载活动）。
- 模块数量不设上限要求；Core 不随模块数量线性膨胀。
- 热点下沉的备案：极端热点可下沉为原生库，其余保持 C#，不整体换栈。
- 数值指标（界面刷新率、端到端延迟、内存、吞吐、连续运行时长）只作记录与对照，不设阈值。
- 行为护栏分两层：**安全护栏**（线程与内存安全、缓冲满丢旧、池化缓冲边界与归还保护；静默、快速、无热路径分支开销）+ **轻量提示**（「缓冲持续为满」「处理速度跟不上输入」「线程占用偏高」「未在期限内停止」等事实陈述；可见但不打扰，不预设问题场景）。
- 明确不做：速率上限、环检测、自连检测、阻断、给数据单元加跳数元信息。

## 5 网络语义

### 5.1 数据面模型

**UDP 式数据报 + 发布订阅**：

| 性质 | 取值 |
|---|---|
| 连接 | 无连接：按声明建立绑定后即投递，无握手、无会话 |
| 可靠性 | best-effort：有界队列满即丢并计数，**不背压** |
| 顺序 | 同一（源，宿）对 **FIFO 强保证**；跨源仅按到达顺序，**不提供跨源时间序** |
| 数据单元 | 一个定长数据报 |
| 拓扑 | 多播（1→N）· 多发布者（N→1）· N:M |
| 端点 | 口；**无每包地址**，拓扑全部由声明派生 |
| 长度校验 | 到达长度 ≥ 契约尺寸 |
| 可观测 | 各档速率 + 各类丢弃 + 队列水位 |

**数据面不暴露来源**：应用需要来源就自带字段；观测面改从绑定模型取来源，因此框架不读数据也能显示多源。下游不应从数据面得知数据源身份。

**不换真 UDP socket**：进程内数据面就是上面的语义，保留零拷贝与对象模型。与真实设备通信由模块承担（模块能力声明里的网络与串口），框架数据面是**模块之间的织物**，两者不混淆。跨进程 / 跨机通信（同一语义契约的真 UDP / TCP / 共享内存）登记为未来能力。

### 5.2 网络模型

- **直连 = 匿名网络**；**标签同名 = 命名网络**。几何与连接解耦。
- 网络统一为一个模型：源集合 + 宿集合 + 契约引用 + 诊断计数 + 状态。**多源是一等组合**，框架不隐式仲裁。
- 接收策略**框架中立**：按到达顺序投递，不做优先级、时刻排序或去重。
- 合并与仲裁由**模块**承担（例如融合器：两个输入口 + 一个输出口，策略为最新 / 优先 / 平均，来源用口区分，融合结果可再发布）。**框架永不仲裁**。

### 5.3 口的两态与严格单向

- 方向严格单向；双向 = 两个口 + 两条单向网络。
- 两个发送口相接 ⇒ **连接存在但无数据流**（由方向判定，不是兼容问题）。
- 宿口多路输入合法：多条网络可以喂同一个宿口（交织为一条流，要求逐对契约兼容）；宿若需区分来源，自带字段或改用多口。

### 5.4 源集合的两态与停流判定

| 概念 | 定义 |
|---|---|
| 在场的源 | 已锚定、可投递的来源 |
| 悬空的源声明 | 声明了但未锚定的来源（方向 = 发送） |
| 「声明的源」 | 上述两者的并集，是**持久化与展示的事实源** |

- **停流是派生量**：当且仅当在场源数为零。它不单独存。
- **部分源未锚定不是停流**：其余源照常投递，只为该源记一条 Issue。
- 全部源未锚定 ⇒ 停流（保留声明）；无源或无宿 ⇒ 未建网（等待）。
- 在场源为空是**合法状态**，读取方必须先看停流标志再读来源集合。
- 计算与上报分离：「字面量 → 网络」只有**唯一**实现，加载与重锚共用（因此重锚不可能把多源网络打回单源）；停流 Issue 同一事实只有一个归属者。
- 网络的**身份键用声明的源集合**，两条都停流的网络不会因「在场源为空」而撞成同一个键。

### 5.5 建网机制

**一条权威推导**：每次变更提交、载入组合件、解析占位时都重算一次派生网络，但**按差量落地**——身份与在场成员都相同的网络**原地保留**（不拆不建），只移除真的消失的、只新增真的出现的。全拆重建会在两步之间留下一个"网络还在、绑定已空"的窗口，模块线程恰在此刻发送就会**静默丢单元**；原地保留同时让绑定上的投递 / 丢弃计数与速率计不被每次提交清零。用户显式建立的网络与组合件里载入的网络一律不动，用户意图优先。派生网络带自动生成标记，拖开即自动断开。

| 机制 | 条件 |
|---|---|
| 命名网络 | 端口**网络标签同名即连**；标签本身即网络名 |
| 对齐网络 | 双方**均未打标签**、两模块**接触且标记对齐** ⇒ 自动连上，名为匿名（直连） |

对齐判定的完整条件（建网行为与界面预览**共用同一实现**）：

- **接触**：相邻边间隙在接触容差以内（贴合后为零）。
- **接触面重叠**：沿接触边的投影必须真正重叠（排除边缘数值巧合）。
- **标记对齐**：两端口标记中心沿接触面的距离在标记对齐容差以内。
- **方向**：发送口 ↔ 接收口。
- **契约**：形状完全一致（不兼容即忽略，不自动转换）。
- **标签**：双方均未打标签。打标签的口只参与命名网络，两种机制不混用。

两个容差的唯一来源 = 建网判定类型（`src/Core/Composition/DockRule.cs`），本文不抄数值；建网判定与拖动预览读的就是这一份。

**拖动中预览**：界面用临时布局向 L4 询问「现在松手会连上什么」，高亮标记并把提示送到状态栏；**实际建网只发生在布局提交之后**。吸附是界面行为，建网是网络行为。

自动建网总开关是一个应用级设置项；口上还有「是否参与自动建网」的声明位。

### 5.6 多对多与逐对判定

- 源集合是列表，绑定按网络建立，**投递逐（源，宿）对**进行。这样保持零拷贝与字节守恒。
- **兼容逐（源，宿）对判定**：只排除不兼容的那一对并记 Issue，其余源照常投递，**网络不整条拒绝**。
- 几何不自动合并：接触对齐的两个口仍各自按源口建网，避免误连。
- 同一（源，宿）对内的多个口对按对角聚合；宿侧多条网络 → 对端有 N 个不同实例就画 N 条线。

### 5.7 队列与旁路头

- 队列粒度 = 每（实例，口）一条有界 FIFO，容量按口计；多口轮转公平调度。
- 入队结果分档：接受 / 队列满 / 无承载 / 已停止（各自计数）。
- **薄旁路头只在多源网络携带**：内含源实例标识、源口名、**按源序号**、接收时刻（单调计数）。
  - 它**随数据单元旁路携带、不进 payload 字节流**，字节守恒不变。
  - **单源网络传空 ⇒ 零附加**：不构造、不入队、不读取。
  - 序号按源从 1 递增，由「每个数据报一次、不受多播放大」的发布计数提供，同时它就是**单元速率（按源计）的分母**。
  - 消费者是**观测面**（诊断）；模块仍然不通过它取来源。

### 5.8 持久化形态

- 网络记录持久化**源列表**（而不是单个源）+ 内嵌版本号；旧组合件必须可读入并迁移。
- 每条网络记录：标签（匿名则为空）、源列表、宿列表、契约引用、是否用户显式建立、是否允许未验证的类型强连。
- 运行态（队列内容、计量计数、绑定对象）与绑定**不随件**。

### 5.9 呈现口径

- 网络标签即网络名，显示在端口标记上；标记**常驻**显示该口参与通路的**有效载荷**字节速率（未入网 `---`；已连接但上一秒无数据 ⇒ `0.00 B/s`，与“没连接”可区分），与叠加层开关解耦。**速率按源计（多宿不放大）；投递/搬运字节按宿计（一条绑定 N 个宿即 N 份）；界面显示的速率只取前者。**
- 叠加层里端口标记**沉到遮罩之下**（做减法，而不是给它加降权样式）。
- 拓扑诊断显示源列表与每源状态；多源网络在叠加层上表现为「多生产者 → 一消费者」，不同源各自一条线，不在界面上合并。

## 6 UI 外壳与窗口

### 6.1 表现形态：拼图式多窗口

- **一模块一窗口**：默认形态是每个模块一个**无边框顶层窗口**（`SystemDecorations=None`，`ShowInTaskbar=false`），背景即桌面，没有工作区背景。
- 外壳主窗口是**拼图的起始点**。
- **模块 ≠ 窗口**：模块不强制等于窗口，窗口只是默认承载形态；框架渲染模块视图，模块不提供 View 类型（见 §2.2）。
- 应用内窗口层级自上而下：**弹窗 > 模块窗口 > 外壳**。模块窗口的属主是外壳窗口，外壳永远在模块窗口之下；最小化外壳时模块窗口随之最小化，恢复时一并恢复。
- 任务栏与 Alt+Tab **只出现外壳一项**（写死，不设开关）。
- 应用整体相对其他应用只有两种统一状态，由应用级开关切换：**普通**（任一本应用窗口被激活就把本应用其余窗口一并抬到最前，不抢焦点、保持内部次序；其他应用被激活则整体下沉）与**全体置顶**（外壳 + 模块窗口 + 弹窗一起置前，新窗口按当前状态继承）。**禁止混合状态**。应用内的"弹窗 > 模块窗口 > 外壳"与这一应用级状态是两个层次，前者不受后者影响。
- 组抬升需要少量平台互操作（取窗口句柄后调整置前次序），只落在界面层，不进入 L1–L4；非 Windows 平台降级为不做组抬升，其余行为不变。

### 6.2 外壳结构

- **A 区 活动栏**：竖向图标按钮（宽度 = 外壳布局 token），图标化、选中态用可变色滑块；顶部菜单不做，各动作由活动栏入口、侧边页面与弹窗承担。
- **B 区 侧边界面**：竖向排列的常驻页面。**模块清单**与**交互**是常驻页面；**设置**、**拓扑诊断**、**Issue**、**帮助与关于**是弹窗。
- **底部状态栏**：保留 Issue 计数（可点）。
- 外壳尺寸由设置驱动：比例档位是一组固定选项（选项集合与各自的比例只在设置定义与外壳常量里，本文不抄）与「固定尺寸」开关（缺省开）。固定时窗口不可缩放、尺寸由所选比例推导；关闭时可自由缩放，比例仅作初值。相关常量集中在一处，换比例只改一处。
- 设置弹窗按内容自适应：内容定尺寸 + 宽高上限 + 内容区滚动，不固定大小。设置页「左分类固定宽 + 右页面留白、条目与字段行高、分组标题字重」的规格集中在设置页样式 token 里，本文不抄数值。
- 模块清单每行 = 缩略图占位 + 名称 + 版本 + 来源 +「加入现场」（占位尺寸 = 清单行样式 token）；包内可声明可选预览图相对路径，缺字段即无图。

### 6.3 模块窗口形态

- **整块模块、无标题栏**：整块窗口矩形即模块矩形，与建网判定的几何基准一致。
- 边框覆盖整个窗口周界：常规为细线，选中态用主色加粗（线宽 = 窗口样式 token）。
- **交互带**：边中点与角点用于缩放，其余区域用于拖动（厚度 = 窗口几何常量）。
- **缩放手柄是固定尺寸的方块**（尺寸只在窗口几何常量里），**仅选中时可命中**（命中可见性随选中态切换，因此"手柄置顶"与"端口标记可点"不再互斥）。
- **按钮簇固定在右上角、纯图标**，悬停或选中时淡入；命中区与图标尺寸由样式 token 给出。动作为：**还原 / 锁定 / 隐藏 / 关闭**。
  - 没有「暂停 / 启用」按钮：模块生命周期由框架权威判定，数据面没有"暂停"语义。
  - **还原**弹确认，选项为：只还原默认尺寸（位置保持）／尺寸和配置都还原／取消。
  - **锁定**的含义：① 不可拖动、缩放、选中；② **不参与拖动组、不随壳体移动**。
- 模块名与运行状态以内容区顶部一行轻量文本呈现；状态点与状态文本在**左下角**（弱化色小字号，字号 = 样式 token）。
- 点击外壳或其他窗口清除选中。
- 模块默认尺寸由 `[ModuleDefinition(WindowWidth/WindowHeight)]` 给出；未声明则由框架地板兜底。**模块尺寸与端口位置只来自代码声明。**
- 窗口最小尺寸的地板由端口标记几何推出（`PortMarkerMetrics.MinWindowExtent`；窗口比标记短会把它裁掉一截），模块声明的最小尺寸**只能抬高**地板；窗口模型构造时夹到有效区间。
- 模块窗口底色可混入极轻比例的主色。

### 6.4 吸附与拼接

- **吸附 = 参照线模型**：一切吸附都是把「被拖模块外框的某个锚点」吸到「某条参照线」上。
- 被拖模块提供的锚点：X 轴 = 左边缘 / 中心 / 右边缘 / 上下边上每个口的归一化位置；Y 轴 = 上边缘 / 中心 / 下边缘 / 左右边上每个口的归一化位置。
- 参照线只有两个来源：其他模块的外框（边 + 中心线）· 其他模块的端口（每个口一条线，**轴由它所在的边决定**）· 外壳（**只提供右边缘一条竖线**，并入同一张线表，不是特殊通道）。
- **候选级别由「线类别 + 交叉轴条件」派生**：贴合（最高）· 端口锚点 · 中心线 · 边缘对齐（最低）。同轴且在去重容差内的多条候选只保留级别最高的一条（该容差只在吸附实现里）。
- 手感参数是设置项：**吸附距离**的缺省值与取值范围只在设置定义里；对齐类容差 = 吸附距离，贴合类容差 = 吸附距离的固定倍数（倍率常量只在吸附实现里）；不设额外的"释放带"。
- **拖动中实时吸附**，离开容差带立即跟手；**不做松手吸附**，**不做网格吸附**。
- **拼接 = 由位置派生的关系**：只保存位置；"是否拼为一组"由边缘贴合（容差判定）派生为**连通分量**；组不是容器，没有布局树、没有停靠槽位、没有标签页堆叠。
- **排版块 = 一种常规模块**：无端口、无功能、只能改大小，与功能模块同级同机制，不引入新概念。
- 外壳纳入拼图：外壳是拼图里的一个节点，与模块之间**只有单侧吸附**（只提供右边缘，"左边缘贴外壳右边缘 + 竖向重叠"），移动外壳时平移整个贴壳平铺组，没拼上的模块留在原处。
- **几何单位：一律"屏幕坐标、整 DIP"**（模型、参照线、辅助线同单位；DIP → 物理像素只在窗口边界换算一次，见 §7 的窗口落位）。参照线与辅助线的**绘制侧**只许"把本窗口客户区原点也换成 DIP 再相减"，**不得再乘除缩放** —— 把"线 − 原点"这个差整体再除一次缩放，等于把线自己的坐标缩了一遍，位置会按 `(1/缩放 − 1)` 偏移且越靠屏幕右下越偏（实测：125% 屏上中线对齐的那根线跑高上百像素）。
- 落盘只改内存 + 防抖合并提交；布局格式是**整数 DIP**，"跟随"只是贴壳时的行为，不是相对坐标存储。

### 6.5 端口标记标准件

- 尺寸 = 跨轴宽（即预留带厚度）× 沿边长度，**与模块外边框完全重合**；尺寸与固定槽位的唯一来源 = 几何度量类型（`src/Ui/Geometry/PortMarkerMetrics.cs`），本文不抄数值，也不进样式 token。
- 内容 = **固定槽位**（数值右对齐、固定小数位，空值 `---`，信息变化不引起排版抖动）：

| 槽位 | 内容 |
|---|---|
| ① 类型窄色条 | 颜色 = 类型身份色（宽度 = 几何度量） |
| ② 网络名 | 优先占用剩余宽度（空间不足先裁速率，因名字是网络身份信息）；取值三态 = 标签名 / 已连但无标签「（直连）」/ 未连「无网络」 |
| ③ 方向箭头 | 定宽列（列宽 = 几何度量），按边取向外 / 向内：发送口向外、接收口向内 |
| ④ 连接指示灯 | 定尺寸方块（尺寸 = 几何度量），贴到标记端部 |

- 标记上**不写连接状态文本，也不写类型文本**：连接状态由指示灯的颜色与形状双重编码承担；类型只在悬停提示里给出。
- 悬停提示：`口名（方向）` / 状态 / `类型：X` / 网络名 · 对端 · 投递 · 丢弃 · 流量；提示行**不含**"上次操作"（提交结果送状态栏）。
- 双击标记填写 / 清除网络名；编辑弹窗只放标题、输入框与按钮，多句提示收进标题右侧的 `?` 帮助浮层，失败原因仍在弹窗内就地显示。
- 标记**常驻**显示通路速率（字号比名称小一号），与叠加层开关解耦。
- 标记内元素的字号与尺寸集中在样式 token 里（本文不抄数值）；标记整体尺寸只在几何度量类型里。
- 竖排分支整体旋转（旋转量只在标记绘制常量里），因此"色条在最前、灯在最末"在屏幕上表现为灯在上端、色条在下端。

## 7 叠加层与视觉基线

### 7.1 叠加层语义与开关

叠加信息层是**调试与观测层**，不是编辑层。

- **默认关闭**，快捷键 **`L`** 切换；设置页与快捷键入口共用同一状态源。
- 外观 = **灰玻璃**：一层半透明深色遮罩压在模块内容上，其上文字一律用浅色墨水（遮罩是深的，因此两套主题共用同一套叠层墨水）。**遮罩浓度是样式 token，浅 / 深两套主题共用同一值**（本文不抄数值）。不做背景模糊，不进设置项。
- 遮罩 `IsHitTestVisible=false`、覆盖整窗；叠加层**不参与命中**，不自绘任何文字控件，全部走绘制上下文。
- 层级（自下而上）：**内容 → 遮罩 → 端口标记 → 连线层 → 运行指示 / 按钮簇**。端口标记**沉到遮罩之下**（被灰玻璃压暗），连线跨过标记直达对端。
- 虚线相位由**一个共享时钟**驱动（节拍 = 时钟常量，只在时钟实现里）：一个定时器 + 弱引用订阅；叠加层关闭时退订，无订阅者时停表。
- 坐标系纪律：叠加层几何**一律用 DIP**。模型几何（位置与尺寸）的单位是物理像素，叠加层控件的绘制单位是 DIP，非默认缩放时两者差一个缩放因子——把像素增量当 DIP 用会让**完全水平或垂直的线也错位**。换算只发生在画布尺寸与一个换算函数两处，别处不许再乘除缩放。画布用负边距抵消窗口边框线宽，使画布正好等于窗口客户区，两窗拼接处两段严丝合缝。
- **身份用外部语义，不用实例 ID**：左上信息区 = **模块展示名 + 现场连续编号**（不显示 `text-sender-1` 这类底层标识）。编号按当前 `Modules` 顺序、以展示名分组现场重算：关闭一个实例后剩余实例重排，新实例补到当前数量之后，不保留关闭实例的旧全局编号。

### 7.2 信息维度

同一份框架诊断被**两个不同的对象**表达，不能因为底层同源就当作一个维度：

| 维度 | 画在哪 | 内容 |
|---|---|---|
| 角色维度 | **角色方块**（及其周围的纯文字） | 这块功能自己在跑多快 |
| 通路维度 | **端口标记**（网络标签） | 这条网络在跑多快 |

### 7.3 角色方块

- 一个模块的方块数 = 该实例声明的数据角色数；同类型的发送角色与接收角色**各一个方块**。
- 方块尺寸：宽度随文本自适应、**夹在几何常量给出的上下限之间**，块高统一（具体数值只在角色方块布局常量里）。宽度估算必须是**确定性纯函数**（CJK 字宽取字号、拉丁字宽取字号的固定比例、留固定余量；系数只在宽度估算函数里）——宽度同时被**两端**用来算连线锚点，一旦依赖渲染期排版，字体或主题差异会让两侧不一致而线错位。
- 方块内两行：第一行 **功能名**（为空则类型短名），第二行 **`m/n`**。
- **填充 = 类型色**（按类型身份，跨模块一致）；**左侧接口边 = 接收方向色、右侧接口边 = 发送方向色**（一个方块可同时有两种颜色的边）。方向小箭头与边框同色。
- **刻痕只在某一侧口数多于一个时画**（单口是常态，不加噪）；类型长文本不进方块（靠颜色与悬停）。
- 摆放 = **单列竖直堆叠、居中**，按声明顺序；放不下则只画得下的 + 底部 **`+K`**（如实报出未画数量）。方块 v1 不参与命中。
- `m/n` 的定义：`m` = 本角色**输入侧连接的对端角色数**，`n` = 输出侧同定义；去重键 =（对端实例，对端角色），因此同一对端角色的多个口连到本角色仍算 **1**。**没有该方向的口 ⇒ `--`**（与该方向是否连上无关）；**有口但没连 ⇒ `0`**（两者含义不同，必须区分）。`m/n` 由框架从网络成员关系**派生**，模块不得自报。
- **角色自身信息画在方块周围 / 上方的纯文字**（不画文本框），三行：

| 行 | 内容 |
|---|---|
| ① | 该角色**自身**速率（无流量 `---`），主色大字 |
| ② | 投递 … · 丢弃 …（丢弃 = 传输丢弃，停流未投递不混算） |
| ③ | 类型语义 · 标称速率（未声明则不占位） |

位置默认在方块上方（居中，与方块留固定间隙，间隙值只在布局常量里），上方放不下自动改到下方，一律留在留白以内。聚合口径 = **产出侧优先**：有输出口就聚合它的**输出侧各口所承载的绑定**，纯汇分块才聚合**输入侧各口**；**同一绑定只计一次**（多宿/多口不放大）；**不把入 / 出两侧相加**（那是多条通路的和，会被读成"总吞吐"）。速率按源计，多宿不放大。

### 7.4 连线

- 一条线 = **两角色方块中心的连线**（纯函数算出的唯一一条线段），每个窗口只画**这条线段与自己窗口矩形的交集**，并且画出来的那段落在**本端方块之外**。因此视觉上从方块中心方向出发，又不会在方块里留一道淡线、也不横穿方块。
- **两侧严格共线**：两端用同一套角色布局与同一个线段函数，所以相邻拼接时两段正好接上，看起来是一根连续的线；未拼接时各自止于自己的边界，缺的那段恰好是两窗之间的空隙（"看起来缺一段"可接受，"两根错位的线"绝不出现）；窗口重叠时两段仍共线。
- **虚线沿数据流方向流动**：线的几何恒按数据流方向绘制，两侧取**同一个负偏移 ÷ 线宽**。偏移量的语义是实测约定——**偏移增大时虚线图案整体朝几何起点移动，且单位是笔宽的倍数**（不是 DIP），取负才能让图案从起点向终点前进；除以线宽才能让速度不随线宽变化。发送侧表现为向外流动，接收侧表现为向内流动。
- **箭头画在指向本模块的那一端**（发送 ⇒ 朝窗外；接收 ⇒ 朝本端方块）。
- **断口与对端名画在窗口边界那一端**：未拼接时画一段竖杠断口 + 对端名，拼接时不加任何标记。线上**不写任何文字**（网络名与条数都不写）。
- 一条网络的不同源是**不同的对端角色** ⇒ 各自一条线，不在界面上合并。
- 对端角色不可用时按回退链逐级降级、绝不猜：① 对端角色方块中心 →（未装入 / 对端没有该角色 / 占位实例）② 对端窗口中心 →（对端不在现场）③ 沿本端接口边方向出窗。
- 类型转换表现为两个方块 + 两条线，各按自己的类型色。

### 7.5 类型颜色表

- 位置：侧边栏**交互页**的「数据结构 · 颜色」分区（带帮助问号 + 空态 + 列表）。**只作图例，不做指标面板**。
- 一行 = **一种数据类型身份**（`标识@v版本`；未声明类型的模块按结构描述）。列 = 色块 / 类型身份（等宽字体、超长省略、悬停给全文）/ 形状文本 / 用在（N 个口 · M 个角色）。
- 颜色来源两级：① 用户覆盖色；② 否则**稳定哈希自动色**（同标识恒同色，跨模块、跨进程、跨重启一致）⇒ 不配置也能分辨类型。
- 色板是**唯一**的色彩来源：端口标记的窄色条与角色方块的填充共用它，改一处两处同步。改色**只影响呈现**，不参与建网 / 兼容 / 停流 / 投递 / 计量，**不进组合件**。
- 表里只列**现场真出现过的类型身份**（来自各实例的端口类型身份与角色类型身份）；"声明了但没用上"的类型不列。空态是一句事实。
- 键与端口标记、角色方块用的键同源（类型身份），**不用呈现文本**作键：不同标识即使形状相同也是不同的量。
- 持久化为应用级设置里的一个类型身份 → 颜色映射；**缺省不写任何条目**（不配置 = 自动配色，不产生死数据）。
- 落盘入口唯一：改色 → 设置色板覆盖 → 写设置 → 让界面重画。刷新时**就地改值、不重建集合**——重建会让正在打开的弹窗与悬停目标被销毁，表现为鼠标指到色块上不停闪烁。
- 类型颜色是**一套全局颜色**，由用户自己改、与主题色解耦（换主题不改用户已选的类型色）；只有调色板的推荐色与主题同一套。

### 7.6 配色与字号纪律

- **方向语义色与主题色完全解耦**：方向色有自己的内置默认值（浅 / 深两套各一份），主题色只表达"选中 / 聚焦 / 活动"等框架性交互语义。
  - 浅 / 深两套主题各有一份内置默认方向色（发送 / 接收各一），默认刻意避开红绿对（色盲友好）；色值只在视觉 token 里，本文不抄。
  - 设置项默认空串 = 跟随主题内置默认值；**不做任何校验或提示**（个性化内容不干预用户立场）。
  - 一致化范围 = 箭头 + 标记框 + 叠加层流向箭头 + "即将建网"描边（同一方向色，仅以线宽分档区分）。
- 主题色只管"模块共有元素 / 框架性颜色"；模块私有绘图配色由模块自己决定。
- **颜色设置准入判据**：① 该语义在多处出现 ② 用户改色后仍能靠形状或位置读懂（双重编码）③ 两个颜色同屏同时出现且需要区分。全部为"是"才开设置项；用户可调的颜色总数宜少（设计取向，不是框架强制的上限）—— 它约束的是"**为某个语义再开一个专项控件**"。**「主题色板」是另一回事**：它不新增语义，只把已经存在的相对色**逐项可覆盖**（浅 / 深两套各自一个值），用于"把整体观感换成我要的那一套"；每一支都有"跟随内置"这一档可退，面板默认只展开常用分区。
- 取色统一为**一个调色板窗口**：左侧取色器（光谱页 + 分量页＝RGB·HSV 滑块 + 十六进制输入 + 当前色预览条）+ 右侧常驻一组推荐色（条目 = `Core.Api/ThemePresets.cs` 的推荐色目录，本文不抄）；不带透明度；去掉控件自带的色板页签与强调色增减块，使推荐色只有一个来源。全应用只有这一种选色交互（**色板里任意一格** + 交互页的类型颜色块）。
  - 调色板窗口的模板必须显式挂载样式，否则**不报错、什么都不画**——窗口只剩标题、提示与按钮。
  - 布局纪律：标题只由窗口标题栏给（窗口内不重复）；提示文字整行独占并自动换行；按钮单独一行右对齐；窗口按内容定尺寸。
  - 调用方自己解释「恢复」：类型色 = 移除覆盖；色板里的格 = 清掉那一格的覆盖（回到跟随）。
- 视觉 token 是**唯一来源**：主题切换只替换 token 值，视图里的取色方式不变（动态资源自动刷新，模块窗口、弹窗、叠加层一并跟随）。色板覆盖：背景、模块底、外壳底、边框与文字的层级、主色与辅色、方向语义色（发送 / 接收）、语义色（正常 / 警告 / 错误 / 空闲）、选中与高亮叠层、叠加层遮罩与叠层墨水分级、内部结构线色、按钮面与边、开关与页签等专有键。**键表、分组与"谁跟随谁"以 `Styles/palette.json` 为准，本文不抄**。
- 字号与尺寸 token：控件高与字号、缩放手柄、交互带、端口标记各字号、箭头、灯、色条宽、模块圆角全部落在视觉 token 里，本文不抄数值（圆角必须用圆角类型，写成数值会在运行期抛类型转换异常）。
- 字体：界面用系统 UI 字体（含中文回退），数据区用系统等宽字体（Cascadia Mono / Consolas 回退链）——**不引字体包**。图标用系统图标字体（Segoe Fluent Icons / Segoe MDL2 Assets），字形码位集中为一组字符串 token，**不手绘几何、零依赖**。
- 不做图片背景；不做主题联动校验或对比度提示。
- 内部处理关系线用细实线 + 中性低对比色 + 小箭头，端点落在角色方块边缘，**不走方向色渐变、不参与流动相位**——否则会被误读成"这里也有数据在流"。

### 7.7 模块界面：代码声明 + XAML + 控件库

**唯一事实源只有两份，各管各的：**

| 事实 | 唯一落点 | 例子 |
|---|---|---|
| 窗口尺寸 / 端口边与偏移 / 显示源 / 输入源 / 命令 / 配置字段 | 模块代码（`[ModuleDefinition]` + `OnRegistered` 的 `Declaration`） | `WindowWidth=400` · `PortDeclaration.Edge` · `DeclareDisplaySource("rxCount", …)` |
| 布局与控件组合 | 模块自己的 XAML（`Views/*.axaml`） | `<ui:ModuleNumeric Source="{x:Static views:SerialViewKeys.RxCount}" …/>` |

**没有界面描述文件。** 不写 `view.json`、`view.schema.json`、控件目录或 kind 派发表；一份界面事实只能有一个家。AR-20 / AR-21 / AR-22 是它的可执行检查。

**键必须经 `x:Static` 引用模块常量**：`Source` / `Field` / `CommandName` / `StateKey` 写字符串字面量在编译期完全合法，但写错只会在运行期变成空白或"点了没反应"；常量拼错则是编译错误。配置字段名用 `nameof(ConfigType.Property)` 锁到配置类型。

**控件库（Sdk.Ui）只放标准控件承载不了的行为**：提交时机、页签状态、配置字段编辑器、读数/单位、状态灯角色、日志跟随尾部、运行期外观通道。纯外观差异改主题；纯布局在 XAML 里摆；不要为"看起来不同"新建 kind / 描述表。

**视觉结构也只在主题里**：需要自绘的 `ui:Module*` 控件在 `Sdk.Ui/Themes/Controls.axaml` 有一个 `ControlTheme`（`PART_*` 命名部件），C# 控件只取部件、管行为；控件构造函数里不许 `new Grid` / `new TextBlock` / `new Ellipse`（AR-21）。`ModuleButton` 用应用级 `ButtonChrome`，`ModuleTabs` 用 `TabControl` 主题。**布尔一律用 `ModuleToggle`**（同一套轨道 + 圆钮模板；输入源与配置字段共用），不再让配置表单用勾选框、视图用另一种开关；配置字段的文本/枚举用 `TextBox` / `ComboBox`，标题与行结构在模板里。

**视图必须填满内容区**：`ModuleViewHost`（`Horizontal/VerticalContentAlignment=Stretch`）与 `ModuleView`（同样的内容对齐）是这条的唯一落点。模块 XAML **不写外圈 margin**：内容预留带由 `Ui/Views/ModuleSurfaceView` 从 `Ui/Styles/ModuleMetrics.axaml` 取（左/上/右/下 = 20/22/20/24），端口标记与运行指示叠在预留带里；否则标记会压住模块自己的控件，且 `*` 行列拿不到余量、最右读数被裁。

**文本面只有一个 `ModuleTextSurface`**：`Mode=Input` 时用 `TextBox` 叶子（光标、编辑选择、提交），`Mode=Display` 或 `IsReadOnly=true` 时用 `IncrementalTextView` 叶子（只读、可跨行选择/复制，没有编辑器光标）。`IncrementalTextView` 按“逻辑行 + 视觉行”缓存 `TextLayout`：追加只布局新增行/最后一个视觉行，只绘制可见行；完整回看、自动折行、选择/复制、`↵` 与跟随尾部都保留，刷新仍跟随全局节拍（没有新内容时零工作）。超长单行按 512 字符分块布局，但**上一块的最后一个视觉行必须拼到下一块前面再布局**，否则块边界会硬断，拉宽后出现没有规律的长短行。**滚动偏移由外层 `ScrollViewer` 负责**：控件在内容坐标里绘制与命中，`Render`/`HitTest` 不得再减/加 `ScrollViewer.Offset`；双重偏移会让滚到尾后只剩空白、新文本错位。两种叶子共用同一个模板、`PART_Frame`、`PART_ErrorRing`、数据刷新与只读策略；`NewlineMarkOverlay` 现在只服务可编辑 `TextBox`，只读面的 `↵` 由增量控件按真实换行绘制。`↵` **只标数据里真实的换行字符**，自动折行与通道换行不标。可编辑边框用 `SurfaceTextFrameEditableBrush`，只读用 `BorderDefault`；选择背景两者都是 `OverlaySelection`。错误圈是模板里的 `PART_ErrorRing` 叠加层，画在焦点/选择边框之上，选中不会盖掉红框。多行输入的换行与提交时机在 `ModuleTextSurface` 一处。

**预览器自包含**：模块视图基类 `ModuleView` 在**设计时**补上 `Sdk.Ui/Themes/Controls.axaml` 与一份设计时 token；宿主未挂控件主题时只补**同一份**控件主题，不加载设计时 token。运行时 App 已挂主题则不重复。模块 XAML 另带 `d:DesignWidth/Height` 与 `x:DataType`，预览器才能看到真实尺寸与模板。IDE 里打开模块 `Views/*.axaml` 时，预览器目标选 `HYWDebugAssistant.PreviewHost`（`tools/PreviewHost`，引用全部模块的可执行宿主）；类库本身不能作为预览目标。预览宿主显式置 `ModuleView.IsPreviewHost`，设计主题/设计时上下文由"谁在预览"决定，不依赖外部一定设置了 `Design.IsDesignMode`。带配置字段的模块视图再用 `[ModuleViewDesignData(typeof(…Config))]` 指定配置类型：`DesignModuleViewContext` 从同一份 `[ConfigurationField]` / `[ConfigurationChoice]` 标注反射出标题、编辑器与选项，预览器里的左侧参数区才不是空的。

**页签观感与内容拉伸**：`ModuleTabs` 用自定义 `TabItem` 的 `ControlTheme`：**直角**标签、选中 = 淡主题色底 + 2px 主题色下沿，未选中透明 + 次文字；页头文字不因选中改字号/字重；整组页签由 `ModuleTabs` 的 1px 外框圈住，明确“这组页签管哪块内容”。主题必须通过 `TabControl.ItemContainerTheme` 的**本地值**挂上——Fluent 的 `TabControl` 主题会给容器设自己的 `TabItem` 主题，外部 `TabItem` 样式或 `TabItem.Theme` 会被它盖掉，表现为“只有选中底色生效、内边距/下沿全不变”。下沿放在 `Padding` 外的模板根层，才会横过整个页签而不是只横过文字。`TabControl` 的 `ContentPresenter` 必须 `Horizontal/VerticalContentAlignment=Stretch`，否则页内容按 desired width 收缩，上下两个页签里的文本框会看起来不一样大。

**视图契约**：每个模块一个 `IModuleViewFactory`，由 `[ModuleDefinition(ViewFactory = typeof(…))]` 指到。框架每帧只做一次遍历：`ModuleElement.Refresh` + `ApplyAppearance`；页签等不能继承 `ModuleElement` 的控件实现 `IModuleViewElement`。

**运行期外观通道**：模块经 `IViewAppearanceAccess` 按源名设边框色/角色/文字色/字号/只读；落点唯一是 `ModuleElement.ApplyAppearance`。只读用编辑器的只读态，不用 `IsEnabled=false`。角色词 → token 的映射只在宿主色板（`Ui/Theming/PaletteManifest`）；控件不认色值，也没有第二张映射表。

旧声明键到控件属性的映射（迁移参考，不是新词汇表）：

| 旧键 | 现在 |
|---|---|
| `data` / `input` | `ModuleElement.Source` / `ModuleTextSurface.Source` |
| `field` | `ModuleConfigField.Field` |
| `command` | `ModuleButton.CommandName` |
| `stateKey` | `ModuleTabs.StateKey` |
| `unit` | `ModuleNumeric.Unit` |
| `title` | `ModuleNumeric.Title`，或 XAML 里一个 `TextBlock`（`Classes="module-title"`） |
| `multiline` / `readonly` | `ModuleTextSurface.Multiline` / `IsReadOnly` |
| `fontSize` / `textColor` / 角色词 | 主题样式或运行期外观通道；不写进视图 |

### 7.8 主题分层与合并顺序

| 层 | 文件 | 内容 |
|---|---|---|
| 1 token | `Ui/Styles/Tokens.axaml` | 浅/深两套色板与角色 token（**唯一的色值来源**） |
| 2 应用壳 | `Ui/Styles/Controls.axaml` · `ButtonChrome.axaml` | 全局控件高/字号、按钮五态 |
| 3 Fluent 桥接 | `Ui/Styles/FluentBridge.axaml` | 模板自带颜色的 token 化 |
| 4 模块控件库 | `Sdk.Ui/Themes/Controls.axaml` | `ui\|Module*` 的尺寸/类样式；**只引 token，不写色值** |

`App.axaml` 的合并顺序固定为 **FluentTheme → Ui/Controls → ButtonChrome → FluentBridge → Sdk.Ui/Controls**；后加者赢。控件库不自带色值，依赖宿主 token —— 宿主是唯一色源，换主题/用户改色不需要改控件代码。

**状态只改颜色与叠加层，不改几何**：悬停不得加粗（只改颜色）；焦点/选中才允许 2px 边框；标红用 `PART_ErrorRing` 叠加圈，不靠改内层边框厚度，因此不会被焦点/选择盖住。字号与窗口内容内缩不随状态变。按钮/页签的**外观**由主题统一；视图里的固定控件（配置字段、按钮、开关、读数、状态、单位）显式给绝对坐标与尺寸，只有文本面交给星号布局。

### 7.9 内容放不下与布局纪律

- **固定控件的布局走绝对坐标**：配置字段、按钮、开关、读数、状态与单位在 `Canvas` 上用 `Canvas.Left/Top` + 显式宽高摆放；它们不参与流式拉伸，窗口变宽时位置不漂。坐标以**内容区左上角**为原点，`ModuleView` 的 `d:DesignWidth/Height` 与内容区一致。
- **只有大文本面自适应**：页签内容、日志、转换器的输入/索引区放在 `Grid` 的星号行列里随窗口伸缩；转换器每半区是一个页签控件，**结果文字面放在选中页内容内部**：页签头固定（Auto），页内容内部用 `*,*` 等分输入与结果。页签头因此完全不参与输入/结果的等分，输入文字区与结果文字区像素级同高，上下对应区也同高，底部结果不会被裁掉；不再用代码按实测头高调整行高。HEX 输入/结果的 `ShowNewlineMarks=False`：HEX 里的换行只是格式，不显示 `↵`；字符串输入/结果仍按真实换行标记。
- 窗口尺寸是**初始/最小尺寸**；固定控件不随窗口重排，文本面吃余量。内容放不下由内容区滚动或控件内部滚动处理。
- 控件自己负责"值没变就不碰视觉"：刷新不得重建控件对象（否则悬停/焦点/滚动位置会丢）。
- 自绘几何（曲线、灯、滑块）仍遵守"一个量化点、同一坐标系、设备像素取整、先问 NaN"的旧纪律；这些行为住在控件里，不回到声明面。

## 8 应用设置

### 8.1 与组合件的边界

- 应用级设置与组合件**完全分离**：独立文件、独立生命周期、Core 持有、**不下发模块**（模块只接收自身配置）。
- 位置：程序目录下的 `data/settings.json`（便携语义——不引入用户漫游目录，**所有需要持久化的数据全部进 `data/`**，备份或搬走就是拷这一个目录）。
- 持久化内容：**组合件**（`data/composites/`，1 文件 = 1 组合件）· **应用级设置**（`data/settings.json`）· 会话快照。
- 用户数据路径只有一处来源：路径由路径解析器统一给出，文件名不得散落在别处；目录按需创建，不预先建；不做版本迁移（旧位置的文件不搬家、不提示）。
- 应用级设置**不提供按模块类型的默认值**——模块默认值由模块实现提供。

### 8.2 设置分类

设置弹窗按分类组织（左分类、右页面、即时生效）；每类管什么见下表，而键名、类型、缺省值与取值范围只在**设置定义**（`src/Core/Api/ApplicationSettings.cs`）里，本文不抄：

| 分类 | 内容 |
|---|---|
| 常规 | 启动行为、便携目录说明 |
| 模块与来源 | 来源根列表增删排序 + 填入工程默认值 + 立即重扫 + 每根诊断 + 包清单（内置 / 第三方） |
| 窗口与交互 | 吸附开关与容差、整组拖动与临时停用吸附的修饰键、锁定语义说明、应用整体置顶开关 |
| 外观与显示 | 界面刷新率、端口标记与叠加层开关、**主题**（选哪套 / 跟随系统）、**字体两项**、**主题色板**（全部相对色逐项可改 + 分组 / 全局恢复 + 背景预设这类动作）、主窗口比例与尺寸固定 |
| 快捷键 | 动作清单 + 当前绑定 + 修改 / 重置 / 冲突检测 |
| 日志与诊断 | 日志级别、诊断提示阈值、Issue 上限与保留 |
| 关于 | 版本、构建配置、依赖许可摘要、用法与快捷键速查 |

主要键与全部缺省值、取值范围一律以**设置定义**为唯一来源，本文不抄（名称即持久化键；持久化文件形态与兼容纪律见 §8.3）。

### 8.3 持久化与迁移纪律

- **文本 JSON** + 内嵌版本号 + **未知字段逐层保留并合并写回** + 原子写（临时文件 + 替换）。
- 缺失或损坏 ⇒ 用内置默认值 + 一条 Issue，**不阻断启动**；不可解析时拒绝并保护原文件（受限解析：白名单字段 + 大小与深度上限，**拒绝而非猜测**；两个上限只写在持久化读取实现里，本文不抄数值）。
- 组合件：1 文件 = 1 组合件；**运行态与绑定不随件**；随件内容 = 配置 / 拓扑 / 布局 / 活动面。
- 加载组合件的流程 = 实例化 → 恢复配置 → 重建成员 → 按 `实例ID.口名` 重锚。
- **配置「读即登记」**：模块首次读取配置时登记一份默认值，后续读返回同一对象，写覆盖。若只读不改的模块不登记，保存组合件时整块配置会丢失，无损往返形同虚设，配置表单也失去数据来源。配置字典由模块线程与管理线程共同访问 ⇒ 访问点纳入同一把锁，快照按加锁复制。
- 配置 JSON 允许命名浮点字面量（无穷与 NaN）；枚举按名字读写（仍能加载早期的数字形式）。
- 设置项更名时保留旧键的兼容读取；**旧键只读不写**（读时折叠进新形状，写侧删掉它）—— 留着旧键就是"两个来源"，下次读到时又得判谁优先。
- **同一语义的设置只保留一处状态**，其他界面做委托；禁止各存一份再"同步"（那从结构上保证漂移）。
- 快捷键：作用域 = 应用内任一窗口聚焦即生效；作用是可见、可改、可重置，冲突即时提示，空值 = 不绑定；**不做系统级全局热键**；清单以设置页为准。

## 9 测试、门禁与交付

### 9.1 架构规则集

规则集以 `AR-n` 编号（编号即规则项的名字，出现在测试名与报告里），由独立的架构测试项目承载，该项目**不引用任何产品项目**（只读它们的产物）。

| 组 | 规则 |
|---|---|
| 项目清单 | AR-0：产品项目清单必须与七层结构一致（穷举，模块前缀除外） |
| 依赖（程序集引用） | AR-1 模块只引 `Sdk` · AR-2 模块不得互引 · AR-3 数据面不得反向依赖宿主 / 核心 / 界面 · AR-4 宿主只引契约与横切 · AR-5 核心的允许集合（并**加强**：允许引用界面框架的程序集只有 `Ui` / `FrameworkUi` / `App`）· AR-6 公开面只引契约 · AR-7 / AR-8 界面两级的允许集合 · AR-9 契约零依赖 · AR-10 横切零依赖 · AR-11 唯一白名单 = 组合根 · AR-12 框架不得引用模块 |
| 命名空间与词汇 | AR-13 核心 / 宿主 / 数据面不得出现具体业务词汇（禁令词表含串口、波特率、电机、绘图、总线协议等）· AR-14 命名空间须与项目名加目录一致 |
| 第三方 | AR-15 排除清单（诊断支持包、加速包、商业控件、中介者与对象映射库、断言与模拟库、日志门面等一律不得引用） |
| 公开面 | AR-16 公开签名不得出现框架内部类型 |
| 用户数据 | AR-17 用户数据路径只有一处来源（文件名只允许出现在路径解析器里） |
| 模块几何 | AR-18 模块尺寸与端口位置只能来自代码声明 |
| 注释 | AR-19 源码注释只承载"为什么 / 不变量 / 坑"，不得携带日期、决定编号、用户原话与实测读数 |
| 界面唯一性 | AR-20 界面描述文件禁止复活（无 `view.json` / `view.schema.json`）· AR-21 `Sdk.Ui` 只许控件/契约/主题 · AR-22 模块 XAML 的绑定键只许 `{x:Static}` 常量 |

执行方式：

- 依赖类规则**同时**按两条路径检查：程序集引用（覆盖间接依赖）与项目文件的引用项（覆盖"引了但暂时没用"）。
- 源码类规则按源码扫描。
- 用到的程序集按当前构建配置定位；**目标程序集缺失即失败**，不跳过——否则改名之后整类规则会静默失效。
- 判定口径（架构能力）：框架程序集**引用集不变** + 既有测试全绿 + 新模块功能测试通过；不做中间语言或二进制基线比对。

### 9.2 测试分层

| 层 | 内容 | 承载项目 |
|---|---|---|
| T1 | 架构能力判据：新增模块核心零改动 · 状态变化不外溢且不影响无关模块 · 组合与配置在线生效 · 保存加载无损往返 · 无隐藏耦合 · 对未知类型开放 | 判据测试项目 |
| T2 | 契约与兼容：表驱动的合法 / 非法矩阵 + 建网各情形 | 主测试项目 |
| T3 | 核心机制：注册表、生命周期状态机、变更原子性、增量重建、资源释放无泄漏 | 主测试项目 |
| T4 | 持久化：组合件往返、版本迁移、缺失模块与损坏处理、未知字段保真 | 主测试项目 |
| T5 | 故障注入：异常不外溢、慢消费者丢帧、停止超时路径 | 主测试项目 |
| T6 | 模块契约自检套件（提供且推荐） | `Sdk.Testing`（模块作者侧） |
| T7 | 用户手工验收（须交付手工验收清单） | 用户 |
| T8 | 界面自动化 | **v1 不做** |

- 判据由**正式模块**承载，参考桩模块不承载契约判据；参考组合由业务模块（见 §1.3）与测试内桩模块构成，桩模块与第三方模块**同引用面、同加载路径**，判据才具保真度。
- 资源释放验证以计数断言为主（活动线程、队列、池计数归零），关键点辅以弱引用断言。
- 渲染快照作为独立测试项目在**真实渲染栈**下把窗口画成 PNG 供目视复核。两点设计取舍：必须独立进程（无头绘制模式是进程级配置，与主测试项目的空绘制会话同进程会互相破坏）；刻意不引用应用项目（引用它会在构建时重拷输出，应用一开着快照就不可用），改为在自己的快照宿主里复刻同一批资源路径。
- 表驱动优先；界面层与纯几何 / 视图模型的判据分开承载（纯函数可单独断言）。

### 9.3 验证层级与完整门禁

验证层级按 **T0 → T1 → T2 → T3** 逐层递进：T0 构建 · T1 单类 / 单项目测试 · T2 相关项目集合 · T3 完整门禁。按改动范围选最小必要的一层，完整门禁在里程碑收尾时跑。

完整门禁的顺序与内容：

1. **文档审计**
2. **还原**
3. **构建**（0 警告 0 错误）
4. **模块包校验**（包目录与构建产物一致）
5. **许可审计**
6. **全部测试**（含架构规则）

基准测试不进常规门禁，按需单独运行。

### 9.4 依赖与许可

- **中央包管理**：版本集中在一处声明，工程只引用不写版本，避免漂移；配依赖锁文件保证可复现。
- 主要依赖：Avalonia（含桌面、Fluent 主题、数据网格、取色控件、无头、Skia 后端，同版本）· `CommunityToolkit.Mvvm` · `Microsoft.Extensions.DependencyInjection`（**仅组合根使用**）· 测试侧 `Microsoft.NET.Test.Sdk` / `xunit` / `xunit.runner.visualstudio` / `Shouldly` / `NSubstitute` / `coverlet.collector` · `BenchmarkDotNet`。版本只在中央包管理里声明，本文不抄。
- 不引无头测试框架专用的 xUnit 适配包（它依赖的 xunit 主版本与本工程所用不一致，会出现同一特性存在于两个程序集的编译错误）；无头会话改用带独立调度线程、不绑定测试框架的会话 API。
- **许可纪律**：只允许 MIT / Apache-2.0 / BSD 一类宽松许可；**禁止 GPL / LGPL 与任何需要采购的商业授权**。构建期许可审计覆盖**直接与传递依赖**，出现受限许可即失败。无许可声明与强制遥测的包一律不得引入。
- 日志后端为极简自研（日志抽象 + 自研文件 sink），不引第三方日志门面。
- 模块加载用运行时内置的加载上下文。

### 9.5 交付形态

- v1 交付为**便携包**：没有安装程序与卸载程序，没有自动更新通道，升级 = 手动替换。
- 允许**多开**（不做单实例限制）；设置文件并发写采用「直接覆写、最后写入获胜」。
- 产品自身**不上报任何数据**，没有隐私或遥测声明。
- 不做国际化与多语言，不做无障碍支持，不做诊断包导出，首次运行引导 v1 不做。
- 数据导出与打印属模块自身能力。
- 跨平台能力天然具备（运行时 + 界面框架），但**不为跨平台牺牲性能**；Windows 是首要目标，平台相关适配只落在界面层。
- 组合件**永不自动执行任何代码**（加载只重建声明结构）；模块包加载是显式的用户信任决策，加载前显示来源与签名状态，包声明的能力（网络 / 串口 / 文件）在加载时提示但不拦截；不做进程级沙箱、不做权限拦截系统、不做强制签名。
- 模块包自带全部依赖，缺失依赖记 Issue，**不静默降级**。
