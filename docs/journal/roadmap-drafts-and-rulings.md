### 3.1 控件布局机制 —— 草案与裁决结果（对应第 53 项；**布局口径已由 `decisions.md` **7.60** 取代，接续落地见第 59 项**）

> **取代说明**：本节所列的**载体**（包内 `view.json`）、`Flow`/`Absolute` 模式、路径键与逐元素尺寸补丁等**布局口径**，一律以顶层设计（`decisions.md` **7.60**）为准，冲突处作废、无兼容层。**`### 3.2 分层保存机制` 不在被取代范围内、仍然有效。**

> **已裁**：**§A → A2**（包内描述文件 `view.json`，**不叠用户覆盖层**）· **§B → B2**（每容器可选 `Flow | Absolute`，`ScaleWithWindow` 默认 false）· **§C 全部转为待评估 Gate** —— 其中 **C-6 已再裁 = ②让 `Group`/`Collapsible`/`Scroll` 变成真容器**（配套 **R1 默认真渲染 + 填满性透传 + 页节点按 `TabPage` 语义**；选项①③ 未采纳），**已随第 53 项实施完毕**（`decisions.md` **7.56**）。以下表格保留为裁决理由的记录。

> **后续追加（第 55 项 / `decisions.md` 7.57）**：布局模型在 `Flow | Absolute` 之外**再增 `grid`** —— `columns`/`rows` 轨道支持 `*`·`N*`·`auto`·`≥1 数值`，元素可给 `column`/`row`/`columnSpan`/`rowSpan`/`align`/`verticalAlign`，`width`/`height` 由「仅绝对坐标必填」放宽为**任意模式下可选（声明即固定尺寸）**；动机 = 试点模块（数据显示器）要求「**表格式排列、按钮同尺寸、列左对齐**」（§B2 的「两种机制」**扩为三种**）。同一批还给**角落结果**（`feedbackSource`/`showInlineResult`）与「有 `view.json` 就拷进包」的构建规则。

> **后续追加（第 56 项 / `decisions.md` 7.58）**：元素尺寸**由扁平数值收紧为「每轴一个对象」** —— `{ "adaptive" | "fill" | "pixels", "min", "max" }`，优先级 `adaptive` > `fill` > `pixels` 且**必须显式选一条**（用户原话：「**不能静默声明，避免多个事实源**」），`min`/`max` **允许为空**；**未声明 = 框架缺省**（宽度满宽、日志/多行输入高度填满）⇒ 老模块逐像素不变。**`grid` 位置也收紧为必须显式**（写全 `column` + `row`，或写 `"auto": true`；缺一个或两种写法混用 = **硬伤整份忽略**）。**尺寸来源唯一**：模板里「命令按钮按内容宽 / 文件选择器撑满」两处自决已删 ⇒ 同一个声明不再出两种像素。窗口**默认/最小/最大尺寸**与**网络标签的默认边/位置**同一批改由 `view.json` 声明（`window` / `ports` 两段，`decisions.md` **7.60**）。

> **更早冻住的前置语义**（用户 2026-09）：布局是**开发模块阶段定好的**，框架**不提供**「像端口锚点那样的在线可调机制」（端口锚点是**通信/排版设施**，不是控件）；布局用**描述性文件或代码里的人**、只在**加载时声明**一次。

**§A 声明载体**（布局描述放哪）

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A1 只用代码**（`ViewElement` 加 `init` 属性 / 挂一个布局记录） | 编译期检查；与现有声明风格一致；**单一事实源**（模块代码）；无解析/版本/文件管理成本 | 改布局要**改代码 + 重编模块包**（改 SDK 还要重编**全部**包）；**用户无法调**（只能模块作者调） |
| **A2 包内描述文件**（模块包目录放 `view.json`，与 `module.json` 并列；MSBuild 从模块工程拷进包） | 结构（代码）与布局（文件）分离；**改布局不动 C#**；手改/工具化容易；可校验可回退；与 `module.json` 同一套既有打包路径 | 新增一种格式（要版本、校验、坏文件回退）；「模块包 = 声明唯一来源」需要写明**谁赢**；打包/导出脚本要带上它 |
| **A3 两者共存**（代码默认 + 文件覆盖） | 最灵活（开发期文件里试、发布时固化到代码） | **两个事实源**（与「减少事实源」的取向冲突）⇒ 优先级/冲突/报 Issue 都要定；成本最高 |

> **推荐 A2**：它拿到最实用的收益（调布局不必重编 C#），又不引入双源。**注意**：包内文件是**构建产物**（每次构建先删再拷）⇒ 改布局的正确姿势 = 改**模块工程里的源文件**再构建；若想「不构建就试」，需要**再叠一层用户覆盖**（= 变 A3），这一点单列为命题 A-3。

**§B 布局模型**（元素怎么摆）

| 选项 | 优点 | 缺点 |
|---|---|---|
| **B1 纯流式 + 元素级尺寸/拉伸**（保持单列；新增 宽/高/最小高/间距/对齐/**是否填满剩余**） | 与现面板一致，改动可控；直接解决「调不了大小/自适应」 | **做不了两列并排/左右分组**（用户明确提到想要位置控制） |
| **B2 每容器可选 `Flow \| Absolute`**（推荐）：容器（模块根 / `Group` / `TabPages` 的页 / `Collapsible`）声明模式；`Flow` 内 = B1 那套；`Absolute` 内元素给 `X/Y/宽/高`（DIP，相对容器客户区）+ **`ScaleWithWindow`（默认 false）**；未声明 = `Flow`（旧模块逐像素不变） | **两种机制并存**（直答用户之问）；多数控件用流式、少数（固定点/装饰/并排）用绝对；`ScaleWithWindow=false` 默认满足「部分控件不需要缩放」；超出客户区由**容器滚动**承担 ⇒ 与「不许撑大窗口」不冲突 | 实现量最大：面板要支持两种排布；**`Group/Collapsible/Scroll` 今天展平不画**，要先把它们变成**真容器**（独立一笔成本）；嵌套/越界/最小尺寸策略要定 |
| **B3 纯绝对坐标**（全局 x/y/w/h） | 最自由直观 | 窗口一缩放就乱（与「可缩放窗口 + 不抖动」冲突）；旧模块要么补坐标、要么走流式兜底 ⇒ 又回到双模；维护成本高 |

> **推荐 B2**（已采纳），且**第一批只把 `Group` 变成真容器**（`TabPages` 的页顺带可用），模块根默认仍是 `Flow`。**实施时扩为三类一起做**（`Group` + `Collapsible` + `Scroll`），因为三者的容器化是**同一处管线改动**（容器分支 + 三个模板）—— 分两轮反而要动两次同一段代码；`Collapsible`/`Scroll` 在 `src`/`tests` 里**0 处构造** ⇒ 一起做的「旧模块会不会变样」风险为零。

| # | 命题 | 候选 | 备注 |

### 3.2 分层保存机制 —— 草案与裁决结果（对应第 54 项）

> **已裁**：**P4 只程序目录**（便携，不引入 `%AppData%`）· **P5 引入统一分层**（一个路径解析器）· **P6 用户数据收进 `<程序目录>\data\`** · **P7 隐式目录表**（默认目录 + 最近列表；选别处只记引用、不复制不搬动）· **P8 不补备份**（「减少事实源数量，降低上下文污染」）。**§E 全部转为待评估 Gate**；**E-1（旧 `exe\settings.json` 自动搬家）已由用户定案 = 不做**（2026-09）⇒ 旧文件留在原地、新目录从空开始。**§F 是 bug 级**，已随本轮落地修掉（见下）。

### 3.3 顶层设计：界面声明面收敛为「三件唯一事实源」（对应第 59 项）

**裁决**：`decisions.md` **7.60**（依据用户 `m03520` 的 Q1–Q8 与 `m04188` 的 C-1…C-15；完全取代 7.55 的 P1–P3 / 7.56 / 7.57 / 7.58 的布局口径，无兼容层）。

- **三件唯一事实源**：① 控件树与语义 = 包内 `view.json`（`frame` 段 = 框架级个性化那几行；`sources` + `views` 段 = 控件级完备声明；**一个文件两个顶层段**，不是两个文件：两个文件会造出两个事实源、两条加载路径、两条错误通道）② 所有默认值与约束 = 随框架程序集嵌入的 `view.schema.json`（**代码零默认** —— 任何键在 schema 里缺缺省值即判 schema 自身不完整）③ 外观 = 全局主题（声明面**完全**没有颜色/字体键 —— 连「预留键」都不留：`frame` 段只有 `window` 与 `ports`；按模块的外观覆盖明确**不做**，长期保持全局主题唯一）。
- **节点模型**：4 容器（`container` 带 `layout` = flow / grid / absolute 与 `overflow`；`group` / `tabs` / `collapsible`）+ 15 原子；旧独立 `scroll` 并进容器的 `overflow`；绑定键按角色分名（`data` / `input` / `command`，每 kind 只允许一个）；命名的命令表取消 ⇒ 命令直接声明在按钮元素上；6 个原子**登记但不渲染**（声明合法 + 警告，既不拒载也不静默）。
- **不进声明面但必须显式登记**：网络标签的标记几何与可拖动性（只声明 `edge` + `offset`，`edge` 必填、**无框架惯例**；有效位置 = 用户拖动 > 声明值）· 框架共有外壳 14 组（关闭菜单栏、模块运行状态、内容留白、容器边框、间距、填满判定、拖动期纪律等）· 全局外观本身（数据类型自动配色与用户配色属设置数据，登记为主题护栏的例外）。
