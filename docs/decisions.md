## 3. 架构例外登记（ARCH-EXCEPTION 决策日志）

> **用途**：登记所有架构约束例外与"实现期必须落定但未在设计中固定"的决策。
> **规则**（`docs/implementation/01-coding-style-and-dev-conventions.md` §8）：
> 1. 违反任一约束须显式申报：代码注释 `// ARCH-EXCEPTION: <原因> · <复查条件>` **并**登记到本文件；
> 2. **禁止静默绕过**；缺登记视为门禁失败；
> 3. **本文件是例外的唯一登记处**——代码注释只是索引，不构成登记；
> 4. 追加式（不删行，状态改为「已关闭」并注明日期）；
> 5. 每个里程碑收尾（M1/M2/M3…）复查一次：过期例外须关闭或续期。
> **谁能登记**：单人项目由开发者自行登记，但必须在提交前完成。

### 3.1 登记格式

| 列 | 含义 |
|---|---|
| 日期 | 登记日期 |
| 约束 | 被例外的规则编号（如 AR-7 / `implementation/01` §3 / ADR-0026 C1-4） |
| 位置 | 代码位置或范围（文件/项目） |
| 原因 | 为什么必须例外（不写"临时"这类无信息量的话） |
| 复查条件 | 什么情况下应关闭该例外（时点或事件） |
| 处置人 | 登记人 |
| 状态 | 生效 / 已关闭（YYYY-MM-DD） |
