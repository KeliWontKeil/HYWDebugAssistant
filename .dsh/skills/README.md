| 技能 | 一句话 | 何时用 |
|---|---|---|
| `layered-verification-and-minimal-test-strategy` | 用"编译→单类测试→单测试项目→完整门禁"的分层验证，按改动范围选最小必要的一层；并以"人工可感知优先 + 测试面越小越好"决定什么才配变成一条测试，禁止"改一个验证一个"的测试漩涡。… | ①任何"改了就想跑全量，或者干脆不想跑"的仓库；②改动天然分成"纯表现层"与"连带逻辑"两类时；③要写"验证结论"或向人报告"已通过"时；④发现自己在为"让测试变绿"而写测试、而不是为了让功能正确而写代码时（测试漩涡）；⑤测试面需要一次性破坏性重整时。 |
| `human-ai-collaborative-design-review` | 在"人类领域专家逐条裁决、AI 负责扩散与落地"的长周期设计或大改造中，用固定的推进节奏、裁决边界与文档治理把需求→设计→裁决→落地→验证推到底，并把返工压到方向性返工之前。… | ①从零设计或大改造一个平台/系统，且验收事实源是文档而非代码；②与"懂领域、不熟悉形式化建模"的专家逐条确认设计；③用户… |
| `batched-file-edit-discipline` | 把"一个文件一次改完"变成硬纪律：先把该文件所有待改点找齐，再一次落盘（整文件重写或少量大块替换），禁止对同一文件连续做逐行 +1/−1 微改；同批多个文件各自也只改一次，校验放在最后一次性做。 | ①用 AI 批量编辑文档或源码时；②一次任务里同一个文件要改 3 处以上时；③发现自己在"改一行→跑一次校验→再改一行"地循环时；④上下文/额度/耗时被反复重读同一文件吃掉时。 |
