# 选层决策表与交付前自检

## 一、选层决策（照表勾一条）

```
本次改动落在哪一类？
├─ 只有样式 / 文案 / 间距 / 颜色 / 布局字面值
│    → T0 编译 + 跑起来看。不跑测试、不跑门禁。
│    （若同时改了视图模型/命令/数据结构 → 按下一类处理）
├─ 视图模型 / 命令 / 数据结构 / 校验逻辑
│    → T0 + T1（只跑受影响的那个测试类）
│    → 一个增量收尾时补 T2
├─ 契约 / 公开面 / 文件格式 / 设置项增减 / 依赖清单 / 架构规则
│    → 必须 T3
├─ 机制类（并发 / 缓冲 / 生命周期 / 持久化 / 调度）
│    → 必须 T3 + 组合级验证（端到端真实链路）
└─ 以上都不是，或说不清
     → 按最高风险处理：T3
```

**三个强制 T3 的时点**（与改动类型无关）：
1. 要把东西交给人类手工验证之前；
2. 一个步骤/里程碑宣布完成时（写状态回写之前）；
3. 改了"验收事实源相关"的东西（公开面 / 契约 / 文件格式 / 架构规则 / 依赖）。

**例外**：若当前阶段有明确裁决"暂不跑全量门禁"，必须以**带恢复触发条件**的形式记录下来（"直到 X 就绪后恢复"），并在报告里如实说明"本轮未跑 T3"。

**两条成本闸门（与选层同等重要）**：
1. **同一改动、同一层只跑一次**：不为了"确认一下"重复跑；改动集合变了就按新集合重新选层。
2. **并行工作单元不跑全量**：子代理/并行分支只做"改动工程编译 + 受影响的那一个测试类"；**T2/T3 由主流程按批次跑一次**。

**新增用例的准入（三条同时满足才加）**：拦得住一类已发生过的缺陷 · 不与既有用例重复断言同一事实 · 断言来源/一致性/边界而非钉住字面值。达不到就写成临时探针，定位完即删。

## 二、交付前自检（逐项勾）

- [ ] 我跑了哪一层？→ 写进报告，**没有**把局部说成全量。
- [ ] 若改了库项目又只重编了测试项目：**确认改动的项目已先编译**（否则测试跑的是旧产物）。
- [ ] 我改了行为 → 有能复现原缺陷的回归断言吗？没有就补一条。
- [ ] 我改了用户可见行为 → 手工验收清单同步了吗？（预期写成"人能观察到的现象"）
- [ ] 我用了临时探针/临时脚本 → 删了吗？或转正为断言了吗？
- [ ] 我碰到规则报错 → 确认是真违规还是误报？误报登记了吗（不是改规则）？
- [ ] 有未做到的事 → 显式登记了吗（不是"记得就行"）？
- [ ] 报告里给出可复现的验证步骤了吗（命令 + 前置 + 预期）？

## 三、常见误判速查

| 现象 | 错误结论 | 正确动作 |
|---|---|---|
| 过滤词跑出 0 个测试 | "失败了" 或 "通过了" | 单列一类：**未匹配**；换词或跑整项目 |
| 单独跑绿、一起跑红 | "测试不稳定" | 查**共享可变状态**：静态/单例/全局字典/线程亲和对象/进程级配置 |
| 断言偶发失败（差一点点的固定值） | "环境噪声，加个容差" | 改断言形式（改成与次数无关），而不是放宽阈值 |
| 判据全绿但用户说还有问题 | "决策层没问题 → 没问题了" | 只能下"这一层被排除"的结论，**接着找差异在哪一层** |
| 改了代码但现象没变 | "改动无效，重新想方案" | 先确认**改动真的被加载**（重编/缓存/是否有第二条实现路径） |
| 规则/测试报错 | "规则太严，关掉" | 先判真违规 vs 误报；误报走例外登记 |
| 为了让门禁跑通而停掉用户的实例 | "反正要跑门禁" | 先问；或用不碰输出的应急模式 |
| 关键约束只写在文档里 | "文档写了就算约束" | 必须有可执行检查（检索/构建/测试/规则），否则不算 |
