# 分层可读文档的结构与写作

## 何时使用

- 要从零建立或重做一个项目的文档体系。
- 现有文档是几份不断变长的汇编，读者找不到入口、同一事实多处出现。
- 需要让人和 AI 都能按结构找到事实，而不是全文搜索。

## 核心主张

文档是产品的一部分：有读者分层、有页面边界、有事实归属。结构决定可读性，长度与措辞不是主要问题。

## 做法

### 1. 先定读者层级，再定页面

按"读者是谁、来做什么"分层，而不是按代码目录。常见五级：

| 级别 | 读者 | 内容 |
|---|---|---|
| 第一次接触 | 想试用 | 安装、跑通、界面速览 |
| 日常使用 | 按任务操作 | 任务指南、排障 |
| 进阶使用 | 想理解机制 | 概念解释 |
| 扩展作者 | 写插件或模块 | 开发指南、接口面 |
| 维护者 | 改框架 | 约束、门禁、发布 |

默认路径不得要求读者先读架构；专业事实放在明确的"深入"与"参考"层。

### 2. 页面类型固定，内容随之收敛

| 类型 | 只回答 |
|---|---|
| 层首页 | 这层适合谁、现状、去哪 |
| 教程 | 完成什么、前置、步骤、结果 |
| 任务指南 | 什么场景、怎么做、怎么验证 |
| 解释 | 解决什么问题、机制、边界 |
| 开发 | 目标、步骤、约束、验证 |
| 参考 | 速查表或清单，能生成就不手写 |

模板放在代码库内，复制后删减；模板是起点，不是八股校验。

### 3. 一个主题只有一个家

- 同一事实只写一处；其他页面只放一句指向它的链接。
- 解释也属于事实：不要换个说法再讲一遍，链接过去。
- 数值、版本号、清单类事实由构建注入或由源生成，不在正文手写。
- 判断归属的方法：问"读者会到哪里找这件事"，那页就是家。

### 4. 用结构代替门禁

文字质量、篇幅、是否重复解释无法可靠地机械判断。可以机械保证的是：页面存在、导航完整、链接可达、生成内容与源一致。把这些做成构建检查，其余交给模板、评审与写作规则。

### 5. 目录即层级，导航即目录的投影

- 目录名表达读者层级，页面路径稳定，标题可改。
- 新增页面只增加文件与一行导航，不改脚本。
- 语言分目录，默认语言在根，其他语言加前缀；中英文路径一一对应。

### 6. 语气与篇幅

- 专业书面语；步骤用动词开头；不用口语、拟人、感叹号。
- 一页回答一个问题；能一页说清就不拆。规格表、矩阵类事实允许同页，用二级标题分段；不要为了行数强行拆分不可拆的事实。
- 先写做什么、怎么做，再写为什么。

### 7. 历史与临时内容不进正文

- 历史材料单独存放，不进站点，不被现行页面引用为依据。
- 临时状态、验收清单、未定稿设计保留为纯文本文件，与站点分离。
- 被取代的表述直接删除或归档，不让新旧两种说法并排。

## 自检

- [ ] 第一次来的读者能否在十分钟内找到入口并跑通一件事？
- [ ] 每个页面是否只回答一个问题，且标题就是这个问题的答案？
- [ ] 同一事实是否只有一页在讲，其余位置是链接？
- [ ] 参考类内容是否由源生成，而不是手抄？
- [ ] 新增页面是否只需要加文件和导航？
- [ ] 站点里是否混进了历史材料或未定稿设计？
